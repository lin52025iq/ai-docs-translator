本指南介绍为文档命名以及组织单个文档内内容的最佳实践，帮助你定义自己的文档结构。

要全面了解如何选择文档名称，请参阅我们的[授权指南](/collaboration/getting-started/authenticate#authorize-per-document)，因为文档命名对访问控制也起着至关重要的作用。

## 设计文档名称

Tiptap Collaboration 使用文档名称来支持协作会话。文档名称是唯一标识符，可将用户关联到同一文档。理论上，它可以是任意字符串。

下面的示例使用实体名称与唯一 ID 组合，这在 CMS 应用中很常见；你也可以根据应用需求采用任何命名约定。

需要时会自动创建新文档；你只需向 provider 提供一个字符串标识符。

```typescript
const documentName = 'article.123'
```

这种命名格式便于轻松拆分出关键细节：

```typescript
const documentName = 'article.123'

// Splitting the document name into separate parts
const [entityType, entityID] = documentName.split('.')

console.log(entityType) // Output: "article"
console.log(entityID) // Output: "123"
```

## 使用片段管理嵌套文档

Yjs 的片段非常适合处理包含不同部分的复杂文档。如果你想嵌套文档，例如将博客文章拆分为单独的 `title` 和 `content` 部分，就可以使用片段。

使用片段时，你可以使用一个 Y.Doc 实例（例如一个文档），并使用不同的编辑器处理其中各个部分。

例如，下面是一个博客文章的设置：

```typescript
const ydoc = new Y.Doc()

// Title editor
const titleEditor = new Editor({
  extensions: [
    Collaboration.configure({
      document: this.ydoc,
      field: 'title',
    }),
  ],
})

// Content editor
const bodyEditor = new Editor({
  extensions: [
    Collaboration.configure({
      document: this.ydoc,
      field: 'content',
    }),
  ],
})
```

对于包含嵌套片段的复杂设置，你可以直接使用原始 Y.js 片段，绕过 `document` 和 `field` 设置。

```typescript
// a raw Y.js fragment
Collaboration.configure({
  fragment: ydoc.getXmlFragment('custom'),
})
```

要充分了解文档命名如何影响 Tiptap Collaboration 中的访问控制，请务必参阅我们的[授权指南](/collaboration/getting-started/authenticate)。
