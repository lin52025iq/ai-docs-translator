要在移动或多平台应用中运行 Tiptap，可以在 WebView 中渲染编辑器，并通过原生代码驱动它。本指南介绍一种简单协议，用于连接多平台应用与运行在 WebView 中的 Tiptap 编辑器实例。基于 JSON 的协议允许应用发送和接收各种命令或事件，可在包括 iOS、Android、React Native 和 Flutter 在内的任何平台上使用。

本指南及其参考仓库仅用于演示用法，并非我们承诺维护的产品。请根据需要复制相关部分，并自行在应用中维护。

## 工作原理

WebView 负责渲染编辑器；原生代码负责渲染周边界面（工具栏、菜单），并通过 JSON 消息与编辑器双向通信，消息分为三类：

- **命令** 从应用发送到编辑器。每条命令都带有一个 `id`，编辑器会返回一条包含该 `id` 的响应，以便你将异步结果（例如“把文档发给我”）与请求对应起来。
- **事件** 从编辑器发送到应用。事件不带 `id`，也不需要回复；它们是通知，例如选区移动或内容更改。
- **宿主请求** 从编辑器发送到应用，与事件不同，这类请求会等待回复。编辑器会请求只有原生端才能完成的操作，例如上传粘贴的图片；应用则返回一条通过 `id` 关联的回复。

这些协议命令不同于 Tiptap 自身的编辑器命令（`toggleBold`、`setContent` 等）：两者都称为“命令”，因此本指南将编辑器自身的命令称为“Tiptap 命令”。

该协议与平台无关：所有平台使用相同的编辑器包和消息，只有传输 JSON 的方式因平台而异。


本指南其余部分将介绍相同的架构，帮助你将其构建到自己的应用中。

## 设置编辑器

将编辑器构建为单个、自包含的 HTML 文件（例如使用 [vite-plugin-singlefile](https://www.npmjs.com/package/vite-plugin-singlefile)），并从设备文件系统将其加载到 WebView 中，以便离线使用。最快的入门方式是复制参考仓库中的 [`web/`](https://github.com/ueberdosis/tiptap-mobile-bridge/tree/main/web) 项目，并修改扩展列表，使其与 Web 编辑器一致。保持 Schema 一致正是关键，这样文档在应用中的呈现效果就会与网页上完全相同。

在编辑器旁边添加一个小型桥接层：原生端通过一个入口发送命令，并通过 `send` 辅助函数回传消息。宿主发送的第一条命令 `init` 会创建编辑器，因此应用可以通过传入文档内容来打开已保存的文档：

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'

let editor = null

// The native side calls this to send a command in.
window.tiptapBridge = {
  handleCommand: (json) => onCommand(JSON.parse(json)),
}

// Post a message out to the native side (see "Connect your native app").
function send(message) {
  // e.g. window.flutter_inappwebview.callHandler('tiptapBridge', JSON.stringify(message))
}

function onCommand(command) {
  // `init` is the first command: create the editor with the host's content.
  if (command.name === 'init') {
    editor = new Editor({
      element: document.querySelector('#editor'),
      extensions: [StarterKit], // use the same extensions as your web editor
      content: command.params?.content ?? '<p>Hello from Tiptap 👋</p>',
      editable: command.params?.editable !== false,
    })
    // register your event forwarders here (see "Receive any event" and "Drive a native toolbar")
    send({ type: 'response', id: command.id, ok: true })
    return
  }

  // The commands below run against the editor created here.
}
```

`content` 可以是 HTML 字符串或 ProseMirror JSON：传入已保存的文档即可打开它；设置 `editable: false` 可创建只读视图。之后若要切换文档（例如从 API 获取文档后），发送一条 `setContent` 命令，调用 `editor.commands.setContent(content)` 即可。

## 执行任意命令

你不需要为每个 Tiptap 命令都创建一个桥接方法。发送通用的 `exec` 命令，附上 Tiptap 命令名称及其参数，然后在编辑器的[命令链](/editor/api/commands)上执行。将 `exec` 分支添加到上一步的 `onCommand` 中：

```json
{
  "type": "command",
  "id": "1",
  "name": "exec",
  "params": { "command": "toggleHeading", "args": [{ "level": 2 }] }
}
```

```js
// inside onCommand(command), after the init branch:
if (command.name === 'exec') {
  const { command: name, args = [] } = command.params
  if (typeof editor.commands[name] !== 'function') {
    const error = { code: 'UNKNOWN_COMMAND', message: `no such command: ${name}` }
    send({ type: 'response', id: command.id, ok: false, error })
    return
  }
  const executed = editor
    .chain()
    .focus()
    [name](...args)
    .run()
  send({ type: 'response', id: command.id, ok: true, result: { executed } })
}
```

`args` 在 JSON 中以位置参数数组的形式编码，并展开后传给命令。因此，`{ "args": [{ "level": 2 }] }` 会调用 `toggleHeading({ level: 2 })`，而 `{ "args": ["left"] }` 会调用 `setTextAlign('left')`。

响应包含一个 `ok` 标记。上面的处理程序会对未知命令名称返回 `ok: false` 和 `error: { code, message }`；实际应用中也应捕获命令抛出的异常，并以相同方式回复，避免宿主一直等待一个永远不会到来的响应。每次都要检查响应中的 `ok`，不要默认操作一定成功。

## 接收任意事件

编辑器会[触发事件](/editor/api/events)，例如 `focus`、`blur`、`update`、`selectionUpdate` 和 `transaction`。让应用订阅所需的事件，然后将每个事件转发为 JSON 消息。跟踪订阅情况，并在创建编辑器时注册转发器（在 `init` 分支中，紧接着 `editor = new Editor(...)` 之后）：

```js
const subscriptions = new Set()

// Add a subscribe branch to onCommand so the host can opt into events:
if (command.name === 'subscribe') {
  subscriptions.add(command.params.event)
  send({ type: 'response', id: command.id, ok: true })
}

// Register the forwarders once, when the editor is created in the init branch:
for (const name of ['focus', 'blur', 'update', 'selectionUpdate', 'transaction']) {
  editor.on(name, () => {
    if (subscriptions.has(name)) {
      send({ type: 'event', name, payload: project(name) })
    }
  })
}
```

原始事件负载包含实时对象（`Editor`、`Transaction`），无法通过 JSON 边界传输，因此应改为转发简化后的数据。对于文档和选区事件，返回选区信息；对于 `focus` 和 `blur`，则返回空对象：

```js
function project(name) {
  if (name === 'update' || name === 'selectionUpdate' || name === 'transaction') {
    const { from, to, empty } = editor.state.selection
    return { selection: { from, to, empty } }
  }
  return {} // focus, blur
}
```

参考 [`PROTOCOL.md`](https://github.com/ueberdosis/tiptap-mobile-bridge/blob/main/PROTOCOL.md) 列出了所有转发事件及其投影后的负载。若要在内容更改后获取完整文档，可发送一条命令，返回 `editor.getJSON()` 或 `editor.getHTML()`：

```js
// getJSON / getHTML are commands like any other: run, then reply with the document
if (command.name === 'getJSON') {
  send({ type: 'response', id: command.id, ok: true, result: editor.getJSON() })
}
```

## 驱动原生工具栏

原生工具栏需要知道哪些按钮处于激活状态（例如选区是否为粗体），以及哪些按钮可用（例如当前选区是否可以切换为标题）。在选区更改时计算这些状态，并通过 `selectionChanged` 事件发送；但只针对你实际呈现的命令执行，切勿遍历所有命令（见下方警告）：

```js
// one entry per button your toolbar renders
function toolbarState() {
  return {
    bold: { isActive: editor.isActive('bold'), canExec: editor.can().toggleBold() },
    italic: { isActive: editor.isActive('italic'), canExec: editor.can().toggleItalic() },
    // nodes pass attributes, e.g. editor.isActive('heading', { level: 2 })
  }
}

// register alongside the other forwarders when you create the editor:
editor.on('selectionUpdate', () => {
  const { from, to, empty } = editor.state.selection
  send({
    type: 'event',
    name: 'selectionChanged',
    payload: { selection: { from, to, empty }, commandStates: toolbarState() },
  })
})
```

应用读取这个映射，以突出显示已激活的按钮，并禁用不可用的按钮。参考实现会在每次选区更改时发送 `selectionChanged`（无需订阅），并对发送操作进行防抖处理。详情请参阅 [`PROTOCOL.md`](https://github.com/ueberdosis/tiptap-mobile-bridge/blob/main/PROTOCOL.md)。

<Callout title="要构建原生工具栏？不要探测所有命令" variant="warning">
  要点亮工具栏按钮，你需要知道每个按钮的激活和启用状态。只读取你实际呈现的命令状态（`editor.isActive('bold')`、`editor.can().toggleBold()`）。切勿对*所有*命令循环调用 `editor.can()`。某些命令在试运行时并非无副作用（例如 `blur` 会安排在下一帧执行实际的失焦操作），因此每次按键都探测所有命令可能会在用户输入时抢走焦点。
</Callout>

## 向宿主请求数据

有些操作只有原生端才能完成：上传粘贴的图片、解析提及对象、选择文件。对于这些操作，编辑器会发送一个**宿主请求**并等待回复，与命令一样使用 `id` 进行关联，但方向相反。为每个请求设置超时，避免宿主一直不回复导致编辑器无限等待：

```js
const pending = new Map()
let nextRequestId = 1

// Ask the host to do something, and await its reply.
function hostRequest(name, params) {
  const id = `r${nextRequestId++}`
  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => {
      pending.delete(id)
      reject(new Error(`host request timed out: ${name}`))
    }, 30000)
    pending.set(id, { resolve, reject, timer })
    send({ type: 'hostRequest', id, name, params })
  })
}

// The native side delivers the host's answer here.
window.tiptapBridge.handleReply = (json) => {
  const { id, ok, result, error } = JSON.parse(json)
  const entry = pending.get(id)
  if (!entry) return
  clearTimeout(entry.timer)
  pending.delete(id)
  ok ? entry.resolve(result) : entry.reject(error)
}
```

例如，拦截粘贴的图片，将其交给宿主处理，然后插入宿主返回的 URL：

```js
const url = await hostRequest('uploadImage', { dataUrl })
editor.chain().focus().setImage({ src: url }).run()
```

在参考仓库的 [`main.ts`](https://github.com/ueberdosis/tiptap-mobile-bridge/blob/main/web/src/main.ts) 中，完整展示了如何将粘贴的文件读取为 data URL，并通过 Tiptap 的 `handlePaste` 阻止默认粘贴行为。

## 连接原生应用

应用始终以相同方式发送命令：在 WebView 中执行 `window.tiptapBridge.handleCommand("<json>")`，并通过平台自身的通道接收消息。在编辑器端，检测可用的通道，并通过它调用 `send`。根据你的技术栈，使用对应的章节。使用 Flutter 时，同一宿主可同时服务 iOS 和 Android，因此只需参考 Flutter 章节。每个宿主只需一个或两个小文件即可复制：[`tiptap_bridge.dart`](https://github.com/ueberdosis/tiptap-mobile-bridge/blob/main/flutter_example/lib/tiptap_bridge.dart)（Flutter）、[`TiptapBridge.swift`](https://github.com/ueberdosis/tiptap-mobile-bridge/blob/main/ios_example/TiptapBridgeExample/TiptapBridge.swift)（iOS）、[`TiptapBridge.kt`](https://github.com/ueberdosis/tiptap-mobile-bridge/blob/main/android_example/app/src/main/java/dev/tiptap/mobilebridge/example/TiptapBridge.kt)（Android），以及 [`TiptapBridge.ts`](https://github.com/ueberdosis/tiptap-mobile-bridge/blob/main/react_native_example/src/TiptapBridge.ts) 和 [`EditorWebView.tsx`](https://github.com/ueberdosis/tiptap-mobile-bridge/blob/main/react_native_example/src/EditorWebView.tsx)（React Native）。

### Flutter

使用 [`flutter_inappwebview`](https://pub.dev/packages/flutter_inappwebview) 时，为发出的消息注册处理程序，并通过执行 JavaScript 发送传入命令。应用按 `id` 保存待处理命令的映射，并在收到相应响应时逐一处理：

```dart
final _pending = <String, Completer<Object?>>{};
int _nextId = 1;

// inbound: app to editor. Returns a future that completes with the response.
Future<Object?> send(String name, [Map<String, dynamic>? params]) {
  final id = '${_nextId++}';
  final completer = Completer<Object?>();
  _pending[id] = completer; // resolved when the response with this id arrives
  final command = {'type': 'command', 'id': id, 'name': name, if (params != null) 'params': params};
  // double-encode so the JSON is a valid JS string argument
  controller.evaluateJavascript(
    source: 'window.tiptapBridge.handleCommand(${jsonEncode(jsonEncode(command))})',
  );
  return completer.future;
}

// outbound: editor to app. Route responses, events, and host requests.
controller.addJavaScriptHandler(
  handlerName: 'tiptapBridge',
  callback: (args) {
    final message = jsonDecode(args.first as String) as Map<String, dynamic>;
    if (message['type'] == 'response') {
      final completer = _pending.remove(message['id']);
      message['ok'] == true
          ? completer?.complete(message['result'])
          : completer?.completeError(message['error']);
    }
    // 'event' and 'hostRequest' are handled here too (see tiptap_bridge.dart)
  },
);
```

### iOS（`WKWebView`）

为发出的消息添加脚本消息处理程序，并通过执行 JavaScript 发送传入命令：

```swift
// outbound: the editor calls window.webkit.messageHandlers.tiptapBridge.postMessage(json)
config.userContentController.add(self, name: "tiptapBridge")

// inbound
webView.evaluateJavaScript("window.tiptapBridge.handleCommand(\(jsStringLiteral))")
```

只有在 `window.tiptapBridge` 存在后才能发送第一条命令。`WKWebView` 的 `didFinish` 可能会在编辑器模块安装该对象之前触发，因此请先轮询确认对象已就绪，再发送第一条命令（轮询循环示例见 [`EditorWebView.swift`](https://github.com/ueberdosis/tiptap-mobile-bridge/blob/main/ios_example/TiptapBridgeExample/EditorWebView.swift)）。

### Android（`WebView`）

为发出的消息公开一个 `@JavascriptInterface`，并通过调用 `evaluateJavascript` 发送传入命令：

```kotlin
// outbound: the editor calls window.AndroidTiptapBridge.postMessage(json)
webView.addJavascriptInterface(object {
  @JavascriptInterface fun postMessage(json: String) = bridge.handle(json)
}, "AndroidTiptapBridge")

// inbound
webView.evaluateJavascript("window.tiptapBridge.handleCommand(${JSONObject.quote(json)})", null)
```

`@JavascriptInterface` 回调会在后台线程中执行，因此必须将所有 WebView 调用转回主线程，因为 WebView 不是线程安全的。这是 Flutter 和 iOS 宿主不需要考虑的问题。与 iOS 一样，只有在 `window.tiptapBridge` 存在后才能发送第一条命令：编辑器模块可能会在页面加载完成后才安装该对象，因此请在发送 `init` 前轮询确认对象已就绪（示例见 [`EditorWebView.kt`](https://github.com/ueberdosis/tiptap-mobile-bridge/blob/main/android_example/app/src/main/java/dev/tiptap/mobilebridge/example/EditorWebView.kt)）。

### React Native（`react-native-webview`）

使用 `injectJavaScript` 发送传入命令，并通过 `onMessage` 属性接收发出的消息：

```tsx
// outbound: the editor calls window.ReactNativeWebView.postMessage(json), delivered to the onMessage
// prop, which MUST be set, or react-native-webview never injects window.ReactNativeWebView and the
// editor can't detect the platform.
function EditorWebView() {
  return (
    <WebView
      source={{ html }}
      originWhitelist={['*']}
      onMessage={(e) => bridge.handleMessage(e.nativeEvent.data)}
    />
  )
}

// inbound
webviewRef.current?.injectJavaScript(`window.tiptapBridge.handleCommand(${jsStringLiteral}); true;`)
```

React Native 有三点需要注意：`injectJavaScript` 不返回任何内容（与 `evaluateJavaScript` 不同，它既不报告成功，也不报告错误），因此桥接层会为每条命令设置超时时间，以确保调用方不会一直等待；注入的脚本必须以 `true;` 结尾。请将包作为内嵌 HTML 加载（使用 `source={{ html }}` 和 `originWhitelist={['*']}`），因为 react-native-webview 在发布版本中无法加载本地文件。与 iOS 和 Android 一样，发送第一条命令前请先轮询确认 `window.tiptapBridge` 已就绪（见 [`EditorWebView.tsx`](https://github.com/ueberdosis/tiptap-mobile-bridge/blob/main/react_native_example/src/EditorWebView.tsx)）。桥接层与框架无关，因此相同代码也可用于 Expo，只需替换图片选择器即可。

## 已知限制

编辑器运行在 WebView 中，因此也会受到一些移动 WebView 限制的影响。发布前值得了解以下几点：

### 光标可能被键盘遮挡

屏幕键盘打开时，光标或选区可能会被键盘遮挡，因为 WebView 不一定会自动滚动选区，使其进入可视区域。这是 WebView 层面的行为，并非桥接层所能控制。通常的处理方式是监听 `window.visualViewport` 尺寸变化，并将光标滚动到可视区域，同时与原生端的键盘内边距配合（例如 Flutter 中的 `MediaQuery.viewInsets`）。但要让它在不同设备和键盘上都可靠运行，需要进行充分测试。本参考实现未处理此问题。

### 编辑器不会自动扩展以适应内容高度

WebView 的高度由原生布局决定，而编辑器不会报告自身内容高度，因此 WebView 不会自动调整大小以适应内容。对于全屏编辑器（内容在 WebView 内滚动）来说，这没有问题；但开箱即用的方案不支持行内自动扩展的编辑器（例如聊天输入框）。如需实现此功能，可在 WebView 中测量内容高度（例如使用 `ResizeObserver`），并通过桥接层发送该高度，以便原生端调整 WebView 大小。

### 回车键会在表格单元格内插入换行

移动键盘没有 Tab 键，且参考实现保留了表格的默认行为，因此在表格单元格中按回车会在当前单元格内插入换行，而不是移动到下一个单元格。若要在移动设备上实现单元格导航，需要自行接入，例如使用键盘映射或工具栏按钮来执行 `goToNextCell` / `goToPreviousCell` 命令。

## 安全

请像对待其他用户输入一样处理来自编辑器的内容。`setContent` 和你加载的 HTML 都会按照编辑器的 Schema 解析，无法识别的标签和属性会被移除；但这不能替代在服务器上存储或渲染不可信内容之前进行验证和清理。

也要将桥接层本身视为信任边界。执行操作之前，请验证每条传入消息；只将可信且随应用打包的编辑器 HTML 加载到 WebView 中，切勿加载远程或不可信页面。保持原生接口范围精简：通过明确的白名单公开宿主请求，而不是提供宽泛的原生 API，这样编辑器就只能请求你允许的特定操作。
