## 将编辑器内容复制到文本框时，为什么会出现很多换行？

在 Tiptap 中，剪贴板文本序列化器默认会在段落之间插入两个换行符（就像 Markdown 中的做法一样）。

因此，粘贴的内容会是这样：

```text
This is a paragraph.

This is another paragraph.
```

但你可能希望它看起来是这样（段落之间没有多余的换行）：

```text
This is a paragraph.
This is another paragraph.
```

要实现这一点，你需要将 `clipboardTextSerializer` 改为使用一个换行符，而不是两个。

例如：

```js
new Editor({
  // other options
  coreExtensionOptions: {
    clipboardTextSerializer: {
      blockSeparator: '\n',
    },
  },
})
```

这样剪贴板序列化器就会在块之间使用一个换行符作为分隔符。

## 拖放功能无法正常工作

`react-dnd` 或 `react-beautiful-dnd` 等库可能会通过全局注册来干扰 Tiptap 的拖放功能。
如果你正在使用这些库，可能需要禁用它们（或者至少限制它们监听的元素范围），才能让编辑器的拖放功能正常工作。

## 为什么同时需要 `parseHTML` 和 `renderHTML`

可以将 `parseHTML` 和 `renderHTML` 看作是相反的操作：

- `parseHTML`：HTML -> JSON，接收 HTML 表示并将其解析为 JSON。
- `renderHTML`：JSON -> HTML，接收 JSON 表示并将其输出为 HTML，以便在编辑器中渲染。

正因如此，Tiptap 才能灵活地表示内容。你可以将内容定义为 JSON，再将其渲染为 HTML；也可以将内容定义为 HTML，再将其解析为 JSON。

此外，`parseHTML` 和 `renderHTML` 也会在不同场景下使用：
`renderHTML` 用于_复制事件_，因为从编辑器复制的内容需要序列化为 HTML，才能放入剪贴板。
`parseHTML` 用于_粘贴事件_，因为剪贴板中的 HTML 需要解析为 JSON。

首次渲染时，如果内容定义为 JSON，就会完全跳过 `parseHTML`，它只会用于粘贴操作。
而 `renderHTML` 方法则决定内容在编辑器中以何种 HTML 形式呈现。

可以在编辑器视图中通过节点视图和标记视图覆盖 `renderHTML`，从而自定义节点和标记的渲染方式。

## 我想用 Tiptap 编辑 HTML 内容

Tiptap 基于 ProseMirror。它并不是一个可以处理任意 HTML 的编辑器，而是一个富文本编辑器，需要完全掌控正在编辑的 HTML，才能对其进行修改。ProseMirror 会尝试解析内容，使其符合一个 schema（该 schema 根据你指定为 Tiptap 扩展的节点和标记生成）。这意味着不符合 schema 的内容将会丢失。这是一种权衡：ProseMirror 可以接受相当多的 HTML 内容，并将其解析为结构化格式，但无法可靠地处理任意 HTML（对输入宽容，对输出严格）。

一个常见的情况是尝试嵌套不同类型的标记，例如：`<span class="my-class"><span style="color: red">editable text</span></span>`。这两个标记不能这样嵌套。为遵守标记不能相互包裹的规则，ProseMirror 会尝试修正内容，并移除其中一个标记。要解决这个问题，输入编辑器的 HTML 应该使用带有多个属性的单个元素，例如：`<span class="my-class" style="color: red">editable text</span>`。这样，ProseMirror 就能正确地将其解析为要应用于文本的两个标记。

ProseMirror 没有提供配置这种行为的方法，因为解析任意 HTML 本身已经足够复杂。根据你要解析的 HTML 来源，可以：

- 使用默认行为，丢弃未知内容
- 尝试使用自定义 HTML 解析器自行解析 HTML，并使其符合 ProseMirror 的预期格式（例如合并 span）

## React 上下文无法在 NodeView 中使用

要在 NodeView 中使用 React 上下文，需要用上下文提供程序包装 `EditorContent` 组件。在 nodeview 中，NodeView 组件应该能够访问该上下文。

```jsx
import React from 'react'
import { EditorContent } from '@tiptap/react'

const TiptapEditor = ({ editor }) => {
  return (
    <MyContext.Provider value={{ foo: 'bar' }}>
      <EditorContent editor={editor} />
    </MyContext.Provider>
  )
}
```

## 使用 React Node View 时为什么会出现额外的 div？

出现这些 div 的原因是，ProseMirror 期望节点视图能够同步生成，而 React 只能异步渲染。因此，我们会先插入一个元素，再让 React 异步渲染到该元素中。这就导致 DOM 中出现了一个包裹用的 div。

类似地，使用 `NodeViewContent` 时也会有一个由 React 创建的元素，然后 ProseMirror 会在该元素中渲染内容。这个元素是 React 和 ProseMirror 之间的交接点，必须存在，因为 React 默认会清空渲染目标中的内容，而我们需要避免 React 销毁 ProseMirror 正要用于渲染富文本的元素。

总而言之，由于 React 的工作方式，没有可靠的方法可以移除这些中间元素。你只能使用 JS NodeView API 或 Vue，因为它们的渲染方式更合理。
