我们致力于让所有人都能无障碍地使用 Tiptap。但作为一款无头编辑器，我们并不提供界面，因此需要由你来确保编辑器具备无障碍访问能力。以下是一些可供参考的指南。

## 指南

以下是一些帮助你实现编辑器无障碍访问的指南，并未涵盖所有方面：

### 键盘无障碍

确保可以通过键盘使用编辑器的所有功能，包括在编辑器中导航、选择文本、使用菜单和其他编辑器功能。
从上方的演示可以看到，你可以通过以下方式使用键盘在编辑器中导航：

- 按 `Tab` 将焦点移至编辑器内
- 按 `Alt + F10` 将焦点移至编辑器工具栏
  - 使用方向键在工具栏中导航
  - 按 `Enter` 选择菜单项
  - 按 `Tab` 或 `Esc` 返回编辑器内容
- 按 `Shift + 方向键` 选择文本
  - 按 `Tab` 移至文本选择菜单
  - 按 `Enter` 选择菜单项
  - 按 `Tab` 或 `Esc` 返回编辑器内容
- 按 `Enter` 新建段落
  - 按 `Tab` 移至插入内容菜单
    - 使用方向键在工具栏中导航
    - 按 `Enter` 选择菜单项并插入内容
    - 按 `Tab` 或 `Esc` 返回编辑器内容
- 其他编辑器键盘快捷键请参阅[键盘快捷键](/editor/core-concepts/keyboard-shortcuts)

### 语义化标记与 ARIA 角色

所有默认的 Tiptap 扩展都会生成语义化标记。这意味着编辑器生成的 HTML 易于屏幕阅读器理解。

为了进一步帮助屏幕阅读器，你的编辑器和菜单应提供恰当的 ARIA 角色。例如：

- 编辑器应设置 `role="textbox"`
- 工具栏应设置 `role="toolbar"`
- 菜单应设置 `role="menu"`
- 菜单项应设置 `role="menuitem"`

### 界面

界面需要具有明确的对比度，并提供足够大的可点击区域。目前我们不提供界面，因此这些都需要由你负责。

### 注意事项

在实现无障碍访问时，我们发现了一些值得注意的问题：

#### VoiceOver 会连接不同块级元素中的单词

在 macOS 上使用 VoiceOver 时，请注意它可能会将不同块级元素中的单词连接起来。这可能会让依赖屏幕阅读器的用户遇到意料之外的朗读体验。

例如，考虑以下 HTML 结构：

```html
<h1>Heading</h1>
<p>Paragraph</p>
```

VoiceOver 会将其读作“HeadingParagraph”，而不是“Heading Paragraph”（请注意其中的空格）。要解决此问题，可以在每个块级元素后添加一个零宽空格：

```css
.tiptap {
  h1::after,
  h2::after,
  h3::after,
  h4::after,
  h5::after,
  h6::after,
  p::after {
    content: '\200B';
  }
}
```

#### 键盘陷阱

键盘陷阱是指用户无法使用键盘离开某个元素的情况。如果你有可以通过键盘打开的模态框或菜单，这可能会造成问题。请确保用户始终可以离开这些元素。

### 写作辅助（可选）

可选的写作辅助功能可以帮助用户以符合语义规范的方式撰写内容，例如指出标题级别使用不当之处。如果核心开发者提供此类辅助功能，我们就能帮助改进许多应用中的内容。
