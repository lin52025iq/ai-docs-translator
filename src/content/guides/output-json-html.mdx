## 导出

### 选项 1：JSON

JSON 可能更便于遍历，例如查找提及内容；而且它也更接近 Tiptap 底层使用的格式。无论如何，如果你想用 JSON 存储内容，我们提供了一个获取 JSON 格式内容的方法：

```js
const json = editor.getJSON()
```

你可以将其存储在数据库中（或发送到 API），并在初始化时还原文档：

```js
new Editor({
  content: {
    type: 'doc',
    content: [
      // …
    ],
  },
})
```

如果需要等待某些操作完成，也可以稍后通过编辑器实例设置内容：

```js
editor.commands.setContent({
  type: 'doc',
  content: [
    // …
  ],
})
```

### 选项 2：HTML

HTML 可以轻松地在其他地方渲染，例如电子邮件中，而且应用广泛，因此以后切换编辑器可能会更方便。每个编辑器实例都提供了一个方法，用于获取当前文档的 HTML：

```js
const html = editor.getHTML()
```

然后可以在初始化时用它来还原文档：

```js
new Editor({
  content: `<p>Example Text</p>`,
})
```

如果你想稍后还原内容（例如 API 调用完成后），也可以这样做：

```js
editor.commands.setContent(`<p>Example Text</p>`)
```

### 选项 3：Y.js

我们的编辑器对 Y.js 提供一流的支持。借助它，可以轻松实现[实时协作、离线编辑或跨设备同步](/collaboration/getting-started/overview)等功能。

Y.js 会在内部保存所有更改的历史记录。这些记录可以存储在浏览器或服务器上，也可以与其他已连接的客户端同步，甚至可以保存在 U 盘上。但需要注意的是，Y.js 需要这些已存储的更改记录。仅有一个简单的 JSON 文档不足以合并更改。

当然，你可以导入现有的 JSON 文档以开始使用，也可以从 Y.js 导出 JSON；但这更像是一种导入/导出格式，而不是唯一的数据源。在上述场景中使用 Y.js 时，这一点很重要。

话虽如此，Y.js 确实非常出色，而且我们即将推出一个出色的后端，让这一切变得轻而易举。

### Markdown

Tiptap 已支持 Markdown（包括 GitHub Flavored Markdown）的导入、导出和 REST API 转换。你可以：

- **导入 `.md` 或 GFM** 文件到 Tiptap 编辑器，并将其转换为 Tiptap JSON
- **将** Tiptap JSON **导出**为标准 Markdown 或 GFM，从而将编辑器内容保存或分享为 `.md` 文件。
- 通过我们的转换 REST API 发送或获取 `.md` 内容，实现**服务端集成**（无需编辑器）。

请参阅 [Markdown 转换](/conversion/import/markdown/rest-api)，了解如何处理其他 Markdown 功能，以及编辑器内工作流和服务端用法的示例。

**Tiptap v3 将进一步增强 Markdown 支持。**我们致力于让 Markdown 更加可靠，并更便于集成到高级（AI）使用场景中。

如果你想将 ProseMirror JSON 转换为 Markdown，可以使用 `@tiptap/static-renderer` 包。它可以将 ProseMirror JSON 转换为 Markdown。更多信息和示例，请参阅其[文档](/editor/api/utilities/static-renderer)。

## 监听更改

如果你想在用户编辑时持续保存更新后的内容，可以[监听事件](/editor/api/events)。示例如下：

```js
const editor = new Editor({
  // intial content
  content: `<p>Example Content</p>`,

  // triggered on every change
  onUpdate: ({ editor }) => {
    const json = editor.getJSON()
    // send the content to an API here
  },
})
```

### 选项 3：静态渲染器

从 ProseMirror JSON 生成 HTML、React 元素或 Markdown

如果你想以静态方式渲染内容，例如用于博客文章，可以使用 `@tiptap/static-renderer` 包。它可以将 ProseMirror JSON 转换为 HTML、React 元素或 Markdown。

## 迁移

### 从 Draft.js 迁移

如果你要从 Draft.js 迁移到 Tiptap，内容可能已经以 JSON 格式存储。这很好，因为 Tiptap 可以通过 [draft-js-to-tiptap 包](https://github.com/ueberdosis/draft-js-to-tiptap)处理这些内容。更多信息和示例，请参阅其[文档](https://github.com/ueberdosis/draft-js-to-tiptap/blob/main/README.md)。

### 其他情况

如果要将现有内容迁移到 Tiptap，我们建议先将现有输出转换为 HTML。这可能是将初始内容导入 Tiptap 的最佳格式，因为 ProseMirror 会确保内容没有问题。即使其中包含不被允许的标签或属性（具体取决于你的配置），Tiptap 也会直接将其静默丢弃。

我们接下来会介绍一些相关场景来帮助你完成迁移。例如，我们提供了一个 PHP 包，可将 HTML 转换为兼容的 JSON 结构：[ueberdosis/prosemirror-to-html](https://github.com/ueberdosis/html-to-prosemirror)。

## 安全

出于安全考虑，没有理由必须选择其中一种格式。如果有人想向你的服务器发送恶意内容，内容是 JSON 还是 HTML 并不重要。即使你没有使用 Tiptap，情况也是如此。你应始终验证用户输入。
