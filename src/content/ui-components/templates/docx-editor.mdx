**DOCX 编辑器模板**是一款分页式 Word 风格文档编辑器。与连续画布编辑器不同，它会将内容呈现在独立页面上，并支持真实页边距、可编辑页眉和页脚、脚注、手动分页符以及可配置的页面格式；随后可导出忠实还原内容的 `.docx` 文件，并在编辑器旁显示实时 Word 预览。

该模板基于 [Tiptap Pages](/pages/getting-started/overview) 扩展和 [Conversion](/conversion/getting-started/overview) DOCX/PDF 导出器构建，并通过 [Tiptap Collaboration](/collaboration/getting-started/overview) 提供实时协作功能。

## 概述

该模板将多个 Tiptap Pro 扩展整合为一套文档编辑体验：

- **[Pages](/pages/getting-started/overview)** — 分页、页面格式（大小、方向、页边距）、页眉和页脚、脚注及缩放。
- **[Convert / Export DOCX](/conversion/export/docx/editor-extension)** — 在浏览器中将编辑器文档转换为真正的 Word `.docx` 文件。
- **[Export PDF](/conversion/export/pdf/editor-extension)** — 通过 Tiptap Conversion API 生成并排显示的 Word 预览。
- **[Collaboration](/collaboration/getting-started/overview)** — 对正文、页眉、页脚和脚注进行实时多人协作编辑。

此外，模板还提供 Word 风格工具栏、文档设置侧边栏、可编辑的页眉/页脚浮层，以及一些小型兼容性处理，让 Pages 的交互体验更加自然。

## 安装

你需要拥有有效订阅或试用资格的 Tiptap 账户。请前往 [cloud.tiptap.dev/register](https://cloud.tiptap.dev/register) 创建账户。

### 用于现有项目

```bash
npx @tiptap/cli@latest add docx
```

### 用于新项目

```bash
npx @tiptap/cli@latest init docx
```

此模板需要进行样式和配置设置。

### 样式

我们不限定样式框架，因此你需要根据自己的项目配置进行集成。请遵循[样式设置指南](/ui-components/getting-started/style)，确保编辑器正常显示。

模板附带 SCSS，因此请确保项目中已将 `sass`（以及 `sass-embedded`）作为开发依赖安装。

### 环境变量

DOCX 编辑器使用两项云服务：**Collaboration**（用于实时编辑）和 **Conversion**（用于 PDF/Word 预览）。请为以下变量提供相应值。

**Collaboration**

- `NEXT_PUBLIC_TIPTAP_COLLAB_APP_ID` — 你的 Collaboration（文档服务器）App ID。
- `NEXT_PUBLIC_TIPTAP_COLLAB_TOKEN` — 用于访问 Collaboration 服务的 JWT。
- `NEXT_PUBLIC_TIPTAP_COLLAB_DOC_PREFIX` — _(可选)_ 添加到每个文档名称前的前缀。
- `NEXT_PUBLIC_USE_JWT_TOKEN_API_ENDPOINT` — _(生产环境)_ 一个返回新签名 JWT 的 API 端点，可替代发送静态令牌到客户端的做法。

**Conversion（PDF / Word 预览）**

- `NEXT_PUBLIC_TIPTAP_CONVERSION_APP_ID` — 你的 Conversion App ID（在客户端读取并传递给 PDF 导出器）。
- `TIPTAP_CONVERSION_SECRET` — _(仅限服务器端)_ Conversion 密钥，`/api/convert/token` 路由使用该密钥为预览签发有效期较短（10 分钟）的 JWT。

带 `NEXT_PUBLIC_` 前缀的变量必须可在客户端访问。请根据所用框架添加相应前缀：

- [Next.js](/ui-components/install/next)：`NEXT_PUBLIC_`。例如：`NEXT_PUBLIC_TIPTAP_COLLAB_APP_ID`。
- [Vite + React](/ui-components/install/vite)：`VITE_`。例如：`VITE_TIPTAP_COLLAB_APP_ID`。
- 其他框架：遵循框架的规则，并将变量值接入 `tiptap-collab-utils.ts`。

<Callout title="生成 JWT" variant="info">
  如需快速上手，可以使用 Tiptap Cloud 账户中的示例 JWT，并将其存入令牌环境变量。示例 JWT 的有效期较短，不应在生产环境中使用。生产环境中，请实现一个在服务器端生成 JWT 的 API 端点。请参阅 [JWT 身份验证](/guides/authentication)完整指南。
</Callout>

如果未配置 Collaboration，编辑器会显示设置提示，要求你填写 App ID 和令牌（或 JWT 端点）。你也可以在 URL 后追加 `?noCollab=1`，以便在本地测试时停用协作功能。

## 用法

渲染 `PageDocxEditor` 组件。每份文档对应一个协作房间，因此请为每份文档传入唯一的 `room` ID。

```tsx
import { PageDocxEditor } from '@/components/tiptap-templates/page-docx/components/page-docx-editor'
import initialContent from '@/components/tiptap-templates/page-docx/data/content.json'

export default function App() {
  return <PageDocxEditor room="contract-123" initialContent={initialContent} />
}
```

### 路由

模板附带一个与演示版运行方式相同的页面：访问 `/docx` 会重定向到 `/docx/<room-id>`，并生成一个新的房间 ID；`[slug]` 路由则会渲染该房间的编辑器，同时预加载字体选择器使用的 Google Fonts。每个房间都是一份单独保存的协作文档。

### Props

导出的 `PageDocxEditor` 组件接受以下属性：

| Prop              | Type              | Description                                                                                                                                                                               |
| ----------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `room`            | `string`          | Collaboration 房间 ID。每份文档都应使用唯一房间；如果省略，则会创建随机房间。                                                                                      |
| `initialContent`  | `JSONContent`     | 首次打开房间时写入文档的 Tiptap JSON。模板附带一个 NDA 示例。初始化过程会进行保护，避免重复写入。                                       |
| `invertMenu`      | `boolean`         | 将工具栏显示在屏幕底部而非顶部。也可以通过 `?menu=invert` 查询参数切换。默认值为 `false`。                                     |
| `settingsStorage` | `SettingsStorage` | 侧边栏 UI 设置（页面格式、页眉/页脚设置、预览开关）的持久化后端。默认使用 localStorage 适配器。请参阅[设置持久化](#settings-persistence)。 |

## 功能

一款功能齐全的分页式文档编辑器，配有 Word 风格工具栏、文档设置和实时导出功能。

- **分页**：内容会在真实页面间流动，并可配置页面大小、方向和页边距。
- **页眉和页脚**：可按文档编辑，支持首页和奇偶页使用不同内容、调整与页面边缘的距离，以及动态页码字段。
- **脚注**：提供类似 Word 的脚注功能——正文中显示引用，脚注内容位于每页页脚上方的专用区域，并在自动编号的浮层中编辑。
- **手动分页符**：插入分页符后会占用当前页剩余空间，并将后续内容移到下一页，效果与 Word 完全一致。
- **文档设置**：页面大小（20 多种预设及自定义选项）、方向、页边距、单位、页间距和页面背景色。
- **缩放和适合页面**：提供 40%–200% 的预设缩放比例，以及根据可用宽度缩放页面的自动适合页面模式。
- **字体系列**：可分类、可搜索的字体选择器。默认字体为 Carlito（一种与 Calibri 度量兼容的字体），导出时也会嵌入该字体。
- **有序列表编号**：提供八种编号方案（十进制、字母、罗马数字、嵌套等），确保屏幕显示与导出文档一致。
- **富文本格式**：标题、粗体/斜体/删除线/代码、文字颜色、链接、行内图片、项目符号列表、行距、文字对齐和字号。
- **DOCX 导出**：一键下载真正的 `.docx` 文件，全程在浏览器中生成。
- **实时 Word 预览**：并排显示文档的 PDF 渲染效果，呈现 Word 的排版结果，并可按需刷新。
- **实时协作**：多人实时编辑正文、页眉、页脚和脚注，并显示协作者光标。
- **深色和浅色模式**：开箱即用，完整支持主题样式。
- **响应式设计**：适配移动设备，支持全屏预览模式；工具栏内容溢出时，会将额外控件折叠到菜单中。

### 分页和页面格式

页面几何布局由 Pages 扩展管理，并可通过文档设置侧边栏配置。你可以设置：

- **页面大小** — A4、A5、A6、JIS B5、US Letter、US Legal、Executive、明信片、信封等；还可以选择 **Custom**，明确指定宽度和高度。
- **方向** — 纵向或横向。
- **页边距** — 上、下、左、右边距；还可选择“链接页边距”，让四个边距保持一致。
- **单位** — `cm`、`in`、`mm` 或 `px`；所有输入值都会根据所选单位重新格式化。
- **页间距** — 编辑器画布中页面之间的距离。
- **页面背景色** — 默认透明，并提供一组预设颜色。

侧边栏中设置的选项会应用到实时编辑器；反过来，通过 Pages 扩展进行的更改（包括协作者发起的远程更改）也会同步回侧边栏和持久化设置。

### 页眉和页脚

双击任意页眉或页脚区域，或在侧边栏中打开 **页眉和页脚** 标签，即可在覆盖于当前页面上的浮层中编辑。示例文档附带一个页眉（文档标题和徽标）以及一个页脚（标签、“Confidential”和 `{page} of {pages}` 字段），这些内容均使用表格排版。

支持的选项：

- **首页不同** — 为第 1 页设置独立的页眉/页脚。
- **奇偶页不同** — 奇数页和偶数页交替使用不同的页眉/页脚，适合书籍版式。
- **距页面边缘的距离** — 设置页眉距页面顶部、页脚距页面底部的距离，单位与文档一致（限制在 Word 的范围内，默认约为 1.25 cm）。
- **页码** — 插入当前页码或总页数字段。这些字段在编辑器中显示为 `{page}` / `{pages}` 标记，导出后会成为实时 Word 字段。

由于 Pages 会为每种变体（默认 / 首页 / 奇数页 / 偶数页）分别维护一个内部编辑器，侧边栏提供了一个小型分页控件，用于切换当前文档中可用的变体。

### 脚注

脚注是 Pages 扩展的一项功能。从工具栏（或使用键盘快捷键）插入脚注后，正文中会出现带编号的引用，同时脚注内容会在浮层编辑器中打开；渲染后的脚注则显示在所在页面页脚上方的专用区域中。导出时，DOCX 导出器会自动将其提取为真正的 Word 脚注。

### 分页符

手动分页符前始终会保留一个空段落，并将光标放到分页符后的段落中——这与 Word 处理手动分页符的方式一致。从末尾空段落按退格键时，会逐个删除相邻的分页符，然后才恢复正常编辑行为。可通过工具栏或 `Mod-Enter` 插入分页符。

### 缩放

缩放控件提供 40% 至 200% 的预设比例，以及 **适合页面** 操作。默认情况下，编辑器处于自动模式，会将页面缩小以适应可用列宽，并在视口变宽时放大至 100%；选择预设比例后，则会切换到固定的手动缩放。缩放值通过 `--zoom` CSS 变量发布，因此通过门户渲染的浮层（如页眉/页脚编辑器）也能保持一致的缩放比例。

### 导出和预览

- **DOCX 导出**：通过 Export DOCX 扩展在浏览器中生成 `.docx` 文件并下载，无需与服务器往返传输。页面大小、页边距（包括页眉/页脚扩展部分）、背景色、有序列表编号和页码字段都会写入文档；同时会嵌入 Carlito 字体，并将编辑器 CSS 变量颜色规范化为固定的十六进制值，确保文件在不同环境中的外观一致。
- **Word 预览**：按需将同一份文档渲染为 PDF，并在编辑器旁显示（移动设备上则全屏显示）。预览通过 Tiptap Conversion API 生成，使用 `/api/convert/token` 路由提供的短时令牌，再由 `react-pdf` 渲染。打开预览或页面布局发生变化时，预览会刷新；文档有未保存更改时，也可以通过 **更新预览** 按钮手动刷新。

### 实时协作

正文绑定到一个 `TiptapCollabProvider` 文档；每种页眉/页脚变体和脚注内容则通过各自的协作字段同步。只有正文会显示协作者光标（内部编辑器会有意转发内容同步，但不转发光标，以避免共享 provider 中出现重复光标）。每个房间只会初始化一次默认页眉/页脚框架和正文初始内容，并且会等待 provider 同步完成后再执行，因此用户重新进入房间时，已编辑的内容会得到保留。

### 设置持久化

侧边栏 UI 设置（页面格式、页眉/页脚设置和预览开关）会按房间持久化。默认情况下，这些设置会以房间专属键名存储在 `localStorage` 中。你可以通过 `settingsStorage` 属性和 `SettingsStorage` 适配器接口替换后端：

```ts
interface SettingsStorage {
  get<T = unknown>(key: string): T | null
  set<T = unknown>(key: string, value: T): void
  remove(key: string): void
}
```

传入 `noopStorage` 可完全停用持久化；也可以实现该接口，将设置保存到自己的后端（例如按文档 ID 建立索引的数据库）。

## 组件构成

该模板基于一组共享的 Tiptap UI 组件，组合了自有组件、钩子和库。

### 模板组件

- `page-docx-editor` — 根组件：负责协作设置、编辑器实例、布局和副作用。
- `page-docx-main-toolbar` — Word 风格工具栏，支持溢出处理。
- `page-docx-header-footer-overlay` — 悬停在页眉/页脚区域时显示的浮动“编辑”操作。
- `page-docx-pdf-preview` — `react-pdf` Word 预览窗格。
- `page-docx-loading-overlay`、`floating`、`theme-toggle` — 辅助 UI。
- `sidebar/*` — 文档和页眉/页脚设置面板、页脚分页控件及设置面板基础组件。
- `zoom-dropdown-menu`、`font-family-combobox`、`numbering-format-dropdown-menu` — 专用工具栏控件。

### 钩子

- `use-page-editor-state` — 从 Pages 存储中获取页面状态（当前编辑器类型、页数、当前页、页眉/页脚标记）。
- `use-zoom`、`use-auto-export`、`use-page-docx-export`、`use-page-docx-insert-actions` — 分别处理缩放、未保存状态追踪、DOCX/PDF 导出操作，以及工具栏插入操作（脚注 / 分页符 / 图片）。
- `use-overlay-focus`、`use-overlay-labels`、`use-mobile-typography-guard` — 浮层行为和布局辅助功能。实时跟踪元素矩形的功能来自共享的 `use-bounding-rect` 钩子。

### 库

- `page-docx-utils`、`page-docx-pages` — 单位和转换、页面格式辅助功能以及设置同步。
- `page-docx-export`、`page-docx-export-colors`、`page-docx-fonts` — 导出布局/样式、颜色规范化和字体注册表。
- `settings-storage`、`settings-storage-context` — 可插拔的持久化适配器及其 React 上下文。

### 扩展和兼容性处理

- `extensions/extension-page-token-highlight` — 行内 `{page}` / `{pages}` 页码节点及其 DOCX 适配器。
- `workaround/page-break`、`workaround/header-footer`、`workaround/footnote` — 小型且注释详尽的补丁，让 Pages 的交互（光标定位、浮层焦点和滚动、脚注滚动到可视区域）表现得像桌面文字处理器一样。
