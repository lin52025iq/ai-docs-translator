ConvertKit 覆盖了大多数 DOCX 内容的 schema。如果转换器生成的节点或属性（例如自定义 mark、较少见的属性或特定领域的块级内容）无法由 ConvertKit 渲染，你可以使用标准的 Tiptap `extend()` 模式自行接入。本指南通过两个完整示例说明如何操作：扩展现有扩展以呈现被忽略的属性，以及添加自定义节点并将导入的内容映射到该节点。

## 基本思路

Conversion 服务会尽可能提取源文档中的内容，并输出包含相应节点、mark 和属性的 Tiptap JSON。ConvertKit 注册的扩展可以渲染其中大部分内容，但并非全部。遇到缺失内容时，你有三种处理方式：

1. **扩展现有扩展**，以渲染转换器已生成、但 ConvertKit 未处理的属性。
2. **向 schema 添加自定义节点或 mark**，并告知导入器将 DOCX 结构映射到该节点或 mark。
3. **告知导出器如何序列化**自定义节点并将其写回 DOCX，从而实现往返转换。

通常，缺失的行内属性使用第 1 种方式；新增块级结构则需要结合使用第 2 和第 3 种方式。

## 示例 1：渲染导入的字符间距

转换器会将字符间距提取为带有 `letterSpacing` 属性的 `textStyle` mark。ConvertKit 会注册 `TextStyle`（通过其内置的 `TextStyleKit`），但没有将 `letterSpacing` 声明为其属性之一，因此该值虽然存在于 JSON 中，却不会应用到渲染后的 DOM。

扩展 `TextStyle`，声明该属性并将其输出为行内 CSS：

```ts
import { Extension } from '@tiptap/core'
import { TextStyle } from '@tiptap/extension-text-style'

const TextStyleWithLetterSpacing = TextStyle.extend({
  addAttributes() {
    return {
      ...this.parent?.(),
      letterSpacing: {
        default: null,
        parseHTML: (element) => element.style.letterSpacing || null,
        renderHTML: (attributes) => {
          if (!attributes.letterSpacing) return {}
          return { style: `letter-spacing: ${attributes.letterSpacing}` }
        },
      },
    }
  },
})
```

禁用 ConvertKit 默认的 `textStyleKit` 插槽，并注册扩展后的版本：

```ts
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'

const editor = new Editor({
  extensions: [
    ConvertKit.configure({ textStyleKit: false }),
    TextStyleWithLetterSpacing,
    // ... your other extensions
  ],
})
```

现在，导入的文档中原有的字符间距会在渲染时生效。对于转换器能够提取、但 ConvertKit 默认不呈现的其他属性，也可以采用相同的模式。请参阅其余的[功能支持矩阵](/conversion/getting-started/feature-support-matrix)。

<Callout title="何时扩展而不是替换" variant="info">
  扩展现有扩展可以保留其余行为，还能通过 <code>...this.parent?.()</code> 展开原有属性。若完全替换它（从头创建自己的 Mark），则需要重新实现 ConvertKit 为往返转换所依赖的解析规则，这通常不值得。
</Callout>

## 示例 2：自定义提示块

假设你的编辑器中有一个 `callout` 节点（带图标和颜色样式的块），并且希望导入的 DOCX 引用块映射到它，而不是默认的 `blockquote`。需要三步：定义自定义节点、将导入内容映射到该节点，并定义如何将其导出回 DOCX。

### 定义节点

```ts
import { Node, mergeAttributes } from '@tiptap/core'

const Callout = Node.create({
  name: 'callout',
  group: 'block',
  content: 'block+',
  defining: true,

  addAttributes() {
    return {
      tone: { default: 'info' },
    }
  },

  parseHTML() {
    return [{ tag: 'aside[data-callout]' }]
  },

  renderHTML({ HTMLAttributes }) {
    return ['aside', mergeAttributes(HTMLAttributes, { 'data-callout': '' }), 0]
  },
})
```

### 导入时将 DOCX 引用块映射为提示块

`ImportDocx` 接受一个 `prosemirrorNodes` 映射，用于在导入过程中重写传入的节点类型。设置该映射，将引用块发送到你的 `callout` 节点：

```ts
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

ImportDocx.configure({
  token: 'YOUR_JWT',
  prosemirrorNodes: {
    blockquote: 'callout',
  },
})
```

导入的 DOCX 引用块现在会作为 `callout` 节点进入编辑器，并保留其中的行内内容。

### 导出时将提示块序列化回 DOCX

要实现往返转换，`ExportDocx` 必须知道如何写出自定义节点。传入一个 `customNodes` 项，其 `type` 与 Tiptap 节点名称相同，且 `render(node)` 函数返回一个或多个文档对象：

<Callout variant="warning" title="请使用 Docx 构建这些对象，不要直接导入 docx">
  `@tiptap-pro/extension-export-docx` 会将文档库重新导出为 `Docx`，导出器识别的是这个版本。如果改用你自己安装的 `docx` 中的 `new Paragraph()` 构建结果，导出时该结果会被丢弃。只有构造函数有此要求：`BorderStyle` 和 `WidthType` 等枚举是普通字符串，两种方式都可以使用。
</Callout>

```ts
import { Docx, ExportDocx } from '@tiptap-pro/extension-export-docx'

ExportDocx.configure({
  customNodes: [
    {
      type: 'callout', // matches the Tiptap node name
      render: (node) => {
        // 为简化示例，展平提示块的文本内容。
        // 对于更丰富的提示块，可遍历 node.content 并生成多个 Paragraph
        // （返回 Paragraph[]），或按设计返回合适的结构。
        const text = (node.content ?? [])
          .flatMap((child) => child.content ?? [])
          .map((leaf) => leaf.text ?? '')
          .join('')

        return new Docx.Paragraph({
          children: [new Docx.TextRun({ text, bold: true })],
        })
      },
    },
  ],
  onCompleteExport: (result) => {
    /* ... */
  },
})
```

`render` 函数接收 Tiptap 节点，并且必须返回以下类型之一：`Paragraph`、`Paragraph[]`、`Table`、`TextRun`、`ExternalHyperlink`、`InternalHyperlink`、`Bookmark` 或 `null`（返回 `null` 会在导出时丢弃该节点）。完整 API 和更复杂的示例请参阅[自定义节点导出](/conversion/export/docx/custom-nodes)。

## 预期情况

- 超出 ConvertKit 的支持范围后，自定义 mark/节点的工作就需要由你负责。我们提供了扩展接口；具体的渲染和序列化逻辑取决于应用。
- 通过在 `ConvertKit.configure({…})` 中将相应插槽设为 `false`，可以逐个替换 ConvertKit 内置的扩展。
- 为确保往返保真，导入映射和导出序列化应当对称。如果导入时将 blockquote 映射为 callout，就应定义 callout 如何在导出时写回 DOCX。

## 不支持的功能

- Schema 迁移工具。没有自动方法可以将已有存储内容从旧节点类型升级为新的自定义节点；你需要自行编写一次性转换程序。
- 超出转换器现有能力的属性提取。如果源 DOCX 包含转换器无法解析的功能（例如多栏节属性、某些 SmartArt 图形），那么无论编辑器端扩展如何编写，都无法将其提取出来。
