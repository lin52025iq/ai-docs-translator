本指南将带你从空项目开始，逐步完成 DOCX 的导入和导出。我们会使用 ConvertKit 配置编辑器，添加文件输入框，通过 Conversion 服务上传 DOCX，并将文档往返转换为 DOCX。第 6 步会介绍如何在此基础上叠加 [Pages 扩展](/pages/getting-started/overview)，以实现分页编辑器。

## 前置条件

- 拥有 Tiptap 账户，并开通 [Pro 方案或试用版](https://cloud.tiptap.dev/v2?trial=true)。
- 有权访问 [Tiptap 的私有 npm registry](/guides/pro-extensions)。
- 拥有用于签署 Convert 令牌的环境密钥对。请参阅[身份验证](/authentication)。

## 1. 安装 Conversion 套件

```bash
npm install @tiptap-pro/extension-convert-kit \\
            @tiptap-pro/extension-import-docx \\
            @tiptap-pro/extension-export-docx
```

<Callout title="为什么始终使用 ConvertKit" variant="info">
  ConvertKit 是 Conversion 的标准编辑器套件。它会注册 DOCX 感知型 schema（段落间距、图片裁剪、表格单元格格式），以匹配导入服务生成、导出服务使用的数据。不要用 `StarterKit` 替代；否则往返转换时会丢失这些属性。
</Callout>

## 2. 使用 ConvertKit 配置编辑器

```ts
import { Editor } from '@tiptap/core'
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'
import { ImportDocx } from '@tiptap-pro/extension-import-docx'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [
    ConvertKit,
    ImportDocx.configure({
      token: 'YOUR_JWT', // 在服务端生成
    }),
    ExportDocx.configure({
      onCompleteExport: (result) => {
        // 在第 5 步中补充此处
      },
    }),
  ],
})
```

<Callout title="签署令牌" variant="warning">
  始终在服务器上签署令牌。切勿在浏览器代码中暴露签名密钥。请参阅[身份验证](/authentication)，了解如何签署令牌；有关 Convert 令牌所需的操作，请参阅 [Conversion 安装指南](/conversion/getting-started/install)。
</Callout>

## 3. 配置 DOCX 导入

在页面中添加文件输入框，并将选中的文件传给编辑器的 `import` 命令：

```html
<input type="file" id="docx-input" accept=".docx" />
```

```ts
const input = document.querySelector<HTMLInputElement>('#docx-input')!

input.addEventListener('change', () => {
  const file = input.files?.[0]
  if (!file) return

  editor.chain().focus().importDocx({ file }).run()
})
```

这就是完整流程。转换服务接收 DOCX，返回 Tiptap JSON，编辑器再使用 ConvertKit 的 schema 渲染内容。

## 4. 自行处理导入结果

默认情况下，导入会替换编辑器中的内容。若要验证或转换内容，或呈现错误信息，请传入 `onImport` 回调：

```ts
editor
  .chain()
  .focus()
  .importDocx({
    file,
    onImport(context) {
      if (context.error) {
        console.error('导入失败：', context.error)
        return
      }

      // 可在此检查或转换 `context.content`。若要直接使用，请调用 setEditorContent()。
      // 若要替换为自定义转换结果，请使用 editor.commands.setContent()。
      context.setEditorContent()
    },
  })
  .run()
```

`content` 对象是纯 Tiptap JSON。记录它是查看转换器实际生成内容的最快方式；当某项功能的渲染结果不符合预期时，这会很有帮助。

## 5. 配置 DOCX 导出

在 `onCompleteExport` 回调中添加触发下载的代码：

```ts
ExportDocx.configure({
  onCompleteExport: (result) => {
    const blob = new Blob([result], {
      type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
    })
    const url = URL.createObjectURL(blob)
    const a = document.createElement('a')
    a.href = url
    a.download = 'document.docx'
    a.click()
    URL.revokeObjectURL(url)
  },
  exportType: 'blob', // 默认值；此处明确写出以便说明
})
```

通过按钮触发导出：

```ts
document.querySelector('#export')!.addEventListener('click', () => {
  editor.commands.exportDocx()
})
```

DOCX 导出在**客户端**执行：无需令牌，也不会调用 API。转换由扩展本身完成。

<Callout title="往返转换不会逐字节一致" variant="info">
  目前，少数功能（下标/上标标记、段落行高、浮动表格）在往返转换时还不够完善。完整列表请参阅[功能支持矩阵](/conversion/getting-started/feature-support-matrix)。不要指望 DOCX → 编辑 → DOCX 的流程能逐字节还原原始文件。
</Callout>

## 6. （可选）添加 Pages 以实现分页渲染

如果希望编辑器看起来像真正的文档，包含分页边界、页眉和页脚以及页面格式，可以在相同配置的基础上添加 [Pages 扩展](/pages/getting-started/overview)和 PagesTableKit：

```bash
npm install @tiptap-pro/extension-pages-tablekit @tiptap-pro/extension-pages
```

```ts
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'
import { TableKit }   from '@tiptap-pro/extension-pages-tablekit'
import { Pages }      from '@tiptap-pro/extension-pages'
import { ImportDocx } from '@tiptap-pro/extension-import-docx'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    ConvertKit.configure({ table: false }), // 禁用 ConvertKit 的表格
    TableKit,                                // 改用适合分页的表格
    Pages.configure({
      pageFormat: 'A4',
      header: '我的文档',
      footer: '第 {page} 页，共 {total} 页',
    }),
    ImportDocx.configure({ token: 'YOUR_JWT' }),
    ExportDocx.configure({ onCompleteExport: /* ... */ }),
  ],
})
```

与第 2 步相比，改动如下：

- 禁用 ConvertKit 的表格（`{ table: false }`）；ConvertKit 内置的表格不适合分页。
- 添加来自 `extension-pages-tablekit` 的 `TableKit`。
- 添加 `Pages.configure({...})`。

现在，导入的文档会应用其页眉、页脚和页面格式进行渲染。导出流程不变：`editor.commands.exportDocx()` 仍然可用，导出的 DOCX 也会保留 Pages 覆加的页眉和页脚。

<Callout title="Pages 的重要限制" variant="warning">
  发布前请阅读 [Pages 限制说明](/pages/core-concepts/limitations#oversized-non-splittable-blocks-cause-an-infinite-layout-loop)。高于页面高度的表格及其他不可拆分块可能导致布局陷入无限循环。
</Callout>

## 预期行为

- **导入始终通过服务完成。** 即使是很小的 DOCX，也会发送到 Conversion 服务进行解析。该服务需要经过签署的 JWT。
- **导出在本地完成。** DOCX 导出在浏览器中运行；无需身份验证，也不会发起网络请求。
- **往返转换确实会产生偏差。** 对照矩阵中无法往返转换的功能（下标标记、行高）做好规划：可以在编辑器 schema 中避免使用这些功能，也可以接受转换偏差。

## 非预期行为

- **不支持 OCR 或扫描版 PDF 处理。** Conversion 处理的是结构化文档，而不是页面位图输入。
- **此配置不包含实时协作。** 如需多人编辑，请配合使用 Tiptap Collaboration 产品。若与 Pages 搭配使用，请参阅 [在 Pages 中添加协作功能](/pages/guides/collaboration-with-pages)。
- **不支持异步任务控制。** 服务会对每个请求同步响应。处理超大型文档时，请在客户端规划超时设置。
