将 DOCX 文件导入编辑器时，文档结构会保留，但视觉呈现会发生变化。本指南将说明原因、可用的样式信息，以及如何控制这些样式。

如需快速了解各阶段支持哪些功能，请参阅[支持的功能](/conversion/getting-started/feature-support-matrix)矩阵。如需了解各项功能的详细信息，包括提取的属性和所需扩展，请参阅[内容参考](/conversion/content-types/overview)页面。

## 为什么 Word 样式不会随文档转换

Tiptap 是无头编辑器。它会转换文档结构（节点、标记、属性），但不会应用 Word 的视觉主题。Word 文档使用分层样式系统：文档主题、命名样式定义（例如“标题 2”）以及针对单个文本片段的直接格式覆盖。转换服务会转换结构含义（“这是一个标题 2”），但不会转换视觉呈现（“标题 2 使用 Aptos Light、13pt、蓝色”）。

编辑器使用你的 CSS 渲染内容。编辑器中的 `<h2>` 会按样式表对 `h2` 的定义显示，而不是按 Word 对“标题 2”的定义显示。

## 保留哪些样式

转换服务会从 DOCX 中提取两类样式信息：

### 行内格式（文本节点上的标记）

这些信息以标记的形式存储在各个文本节点上，标准 Tiptap 扩展会自动将其渲染为 `<span>` 元素上的行内 `style` 属性：

| 样式 | 标记属性 | 所需扩展 | HTML 输出 |
| --- | --- | --- | --- |
| 文本颜色 | `textStyle.color` | Color | `style="color: #FF0000"` |
| 字体系列 | `textStyle.fontFamily` | FontFamily | `style="font-family: Courier New"` |
| 字号 | `textStyle.fontSize` | FontSize | `style="font-size: 14px"` |
| 背景颜色 | `textStyle.backgroundColor` | BackgroundColor | `style="background-color: #FFFF00"` |
| 突出显示 | `highlight.color` | Highlight (`multicolor: true`) | `<mark style="background-color: yellow">` |
| 字符间距 | `textStyle.letterSpacing` | [需要扩展 TextStyle](#扩展扩展以支持未支持的属性) | `style="letter-spacing: 2px"` |
| 粗体、斜体、下划线、删除线 | 单独的标记 | ConvertKit（内置） | `<strong>`、`<em>`、`<u>`、`<s>` |

行高未列在此表中，因为 Word 将行距存储在段落上，而不是文本片段上。导入器始终会将其作为段落节点属性输出；请参阅下文的块级格式部分。

如果安装了这些扩展（推荐的扩展组合请参阅 [ConvertKit](/conversion/import/docx/convertkit)），行内格式会自动渲染，无需额外 CSS。

### 块级格式（段落和标题节点上的属性）

这些信息以属性的形式存储在 `paragraph` 和 `heading` 节点上。它们是否会渲染，取决于你安装了哪些扩展。

| 样式 | 节点属性 | 格式 | 使用标准扩展时 | 使用 [ConvertKit](/conversion/import/docx/convertkit) 时 |
| --- | --- | --- | --- | --- |
| 文本对齐 | `textAlign` | `"left"`、`"center"`、`"right"`、`"justify"` | 需要 `TextAlign` | 已渲染（包含 TextAlign） |
| 段前间距 | `spacingBefore` | 数值（像素） | 不渲染 | `margin-top: Npx` |
| 段后间距 | `spacingAfter` | 数值（像素） | 不渲染 | `margin-bottom: Npx` |
| 左缩进 | `indent` | 数值（像素） | 不渲染 | `padding-left: Npx` |
| 右缩进 | `indentRight` | 数值（像素） | 不渲染 | `padding-right: Npx` |
| 首行缩进 | `firstLineIndent` | 数值（像素） | 不渲染 | `text-indent: Npx`（负值表示悬挂缩进） |
| 行高 | `lineHeight` | 字符串（例如 `"1.5"`、`"24px"`） | 不渲染 | `line-height: <value>` |
| 字号（段落标记） | `fontSize` | 字符串（例如 `"11pt"`） | 不渲染（标记级的 `textStyle.fontSize` 会由 `FontSize` 渲染） | `font-size: <value>`（用于间隔段落） |
| 上下文间距 | `contextualSpacing` | 布尔值 | 不渲染 | `data-contextual-spacing="true"` + 注入的 CSS 规则，用于取消相邻上下文间距段落之间的边距 |
| 与下段同页 | `keepNext` | 布尔值 | 不渲染 | 保留在 JSON 中以供导出，不输出 CSS |
| 段中各行同页 | `keepLines` | 布尔值 | 不渲染 | 保留在 JSON 中以供导出，不输出 CSS |

列表项中的段落，其 `indent` 和 `firstLineIndent` 的读取方式有所不同。如果列表指定了编辑器中已注册的编号格式，这两个属性会定位整个列表项（包括标记和文本），而不是为列表项中的段落添加内边距。如果列表没有已注册的格式，则会像表格所述，将它们渲染为段落上的 `padding-left` 和 `text-indent`。请参阅[单个列表项的缩进](/conversion/export/docx/ordered-list-numbering#indents-on-a-single-item)。

<Callout variant="warning" title="架构验证会移除无法识别的属性">
  调用 `setEditorContent()` 时，ProseMirror 会根据编辑器的架构验证内容。节点规范中未定义的属性会被移除。`context.content` 中的原始 JSON 仍包含所有属性，但内容载入编辑器后，这些属性就会丢失。若要保留这些属性，请安装 [ConvertKit](/conversion/import/docx/convertkit)（它会扩展架构以支持上述所有属性），或自行扩展节点架构。
</Callout>

## 设置编辑器样式以近似 Word 的效果

即使没有保留所有段落属性，也可以通过 CSS 让编辑器的外观接近 Word。

### 基本标题样式

Word 的默认标题样式使用特定字体、字号和颜色。你可以在编辑器中近似这些样式：

```css
.tiptap h1 {
  font-family: 'Aptos Light', sans-serif;
  font-size: 16pt;
  font-weight: bold;
  color: #2E74B5;
  margin-top: 12pt;
  margin-bottom: 6pt;
  line-height: 1.15;
}

.tiptap h2 {
  font-family: 'Aptos Light', sans-serif;
  font-size: 14pt;
  font-weight: bold;
  color: #2E74B5;
  margin-top: 12pt;
  margin-bottom: 6pt;
  line-height: 1.15;
}

.tiptap h3 {
  font-family: 'Aptos', sans-serif;
  font-size: 13pt;
  font-weight: bold;
  color: #2E74B5;
  margin-top: 12pt;
  margin-bottom: 6pt;
  line-height: 1.15;
}
```

### 正文

Word 默认的“正文”样式使用 Aptos 11pt 字体、段后间距 10pt 和 1.15 倍行高：

```css
.tiptap p {
  font-family: 'Aptos', sans-serif;
  font-size: 11pt;
  margin-top: 0;
  margin-bottom: 10pt;
  line-height: 1.15;
}
```

### 表格

Word 表格通常使用细边框且没有单元格内边距。编辑器的默认表格样式可能有所不同：

```css
.tiptap table {
  border-collapse: collapse;
  width: 100%;
}

.tiptap td,
.tiptap th {
  border: 1px solid #d0d0d0;
  padding: 4px 8px;
  vertical-align: top;
}

.tiptap th {
  font-weight: bold;
  background-color: #f5f5f5;
}
```

### 列表

Word 对嵌套列表使用特定的缩进。可以通过以下 CSS 进行匹配：

```css
.tiptap ul,
.tiptap ol {
  padding-left: 24px;
  margin-top: 0;
  margin-bottom: 2pt;
}

.tiptap li {
  line-height: 1.15;
}

.tiptap li > ul,
.tiptap li > ol {
  margin-top: 0;
  margin-bottom: 0;
}
```

## 让导出样式与编辑器样式保持一致

导出扩展在写入 DOCX 文件时会应用自己的默认样式。这些默认样式（正文使用 Aptos 11pt，标题使用特定字号和颜色）可能与用户在编辑器中看到的样式不一致。为确保导入、编辑和导出时的外观一致，请让编辑器 CSS 与导出的 `styleOverrides` 保持一致：

```ts
ExportDocx.configure({
  styleOverrides: {
    paragraphStyles: [
      {
        id: 'Normal',
        name: 'Normal',
        run: { font: 'Aptos', size: 22 }, // 11pt in half-points
        paragraph: {
          spacing: { after: 200, line: 276 }, // 10pt after, 1.15 line height
        },
      },
      {
        id: 'Heading1',
        name: 'Heading 1',
        basedOn: 'Normal',
        next: 'Normal',
        run: { font: 'Aptos Light', size: 32, bold: true, color: '2E74B5' },
        paragraph: {
          spacing: { before: 240, after: 120, line: 276 },
        },
      },
    ],
  },
})
```

如果编辑器 CSS 使用了不同字体或字号，请相应更新导出的 `styleOverrides`，使导出的 DOCX 与用户编辑时看到的效果一致。

## 扩展扩展以支持未支持的属性

[ConvertKit](/conversion/import/docx/convertkit) 已为 `Paragraph`、`Heading`、`Image` 和表格扩展组扩展了 Convert API 生成的 DOCX 专用属性。如果使用 ConvertKit，上表中的段落和标题属性会自动渲染；你无需自行编写扩展。

以下模式适用于 ConvertKit 未涵盖的属性（典型例子是 `textStyle.letterSpacing`，Convert API 会提取该属性，但没有内置扩展会渲染它），也适用于不使用 ConvertKit、需要自行实现的编辑器。

<Callout title="路线图" variant="hint">
  将剩余的文本样式属性（从 `letterSpacing` 开始）加入 ConvertKit 内置的 `TextStyleKit` 已列入路线图，未来版本将开箱即用。在此之前，你可以自行扩展 `TextStyle`（如下所示），无需等待上游改动，即可立即实现相同的渲染效果。
</Callout>

```ts
import { TextStyle } from '@tiptap/extension-text-style'

const TextStyleWithLetterSpacing = TextStyle.extend({
  addAttributes() {
    return {
      ...this.parent?.(),
      letterSpacing: {
        default: null,
        parseHTML: (element) => element.style.letterSpacing || null,
        renderHTML: (attributes) => {
          if (!attributes.letterSpacing) return {}
          return { style: `letter-spacing: ${attributes.letterSpacing}` }
        },
      },
    }
  },
})
```

然后禁用内置的 `TextStyle`，并将扩展后的版本与 ConvertKit 一起添加：

```ts
ConvertKit.configure({
  textStyleKit: { textStyle: false },
}),
TextStyleWithLetterSpacing,
```

同样的模式适用于转换器会输出、但没有扩展负责渲染的其他属性。有关扩展现有扩展的完整机制，请参阅[自定义扩展指南](/editor/extensions/custom-extensions/extend-existing)。

## 加载前拦截内容

如果你想在内容进入编辑器前转换或提取样式数据，请使用 `onImport` 回调，而不是自动调用 `setEditorContent()`：

```ts
editor.chain().importDocx({
  file,
  onImport(context) {
    if (context.error) {
      console.error(context.error)
      return
    }

    // context.content has the raw JSON with ALL attributes
    // You can inspect, transform, or extract styling data here
    const doc = context.content

    // Example: log all paragraph spacing values
    function walkNodes(nodes) {
      for (const node of nodes) {
        if (node.type === 'paragraph' && node.attrs) {
          console.log('Spacing:', node.attrs.spacingBefore, node.attrs.spacingAfter)
        }
        if (node.content) walkNodes(node.content)
      }
    }
    walkNodes(doc.content || [])

    // Then load into editor (this triggers schema validation)
    context.setEditorContent()
  },
}).run()
```

## 自动导入样式

如果你不想手动编写 CSS 来近似 Word 的外观，可以使用实验性的 [CSS 注入](/conversion/import/docx/css-injection)功能。该功能会提取导入文档的命名样式目录（`Heading1`、`Normal`、`Quote` 等），并将其作为 CSS 对象返回，或以带作用域的 `<style>` 标签注入页面。无需为每个文档手动编写 CSS，效果也会更接近源文档在 Word 中的呈现。

CSS 注入涵盖 16 个选择器（块级：`p`、`h1`–`h6`、`blockquote`、`ul li`、`ol li`；行内：`strong`、`em`、`u`、`s`、`a`、`code`）和 11 种排版属性（`fontSize`、`color`、`fontFamily`、`fontWeight`、`fontStyle`、`textDecoration`、`backgroundColor`、`textAlign`、`marginTop`、`marginBottom`、`lineHeight`）。单个文本片段上的行内覆盖和任意选择器不在支持范围内；完整的注意事项列表请参阅该页面。

这两项功能可以结合使用：ConvertKit 可确保导入的节点属性通过编辑器架构验证并正确渲染，CSS 注入则将文档的排版样式目录作为层叠 CSS 引入。在这两项功能都无法满足需求时，本指南前面介绍的手写 CSS 方法仍然适用。
