本指南介绍当遇到问题时我们自己会使用的工具和方法：导入失败、内容未按预期呈现、Conversion 服务返回 HTTP 错误，或者分页编辑器突然停止响应。指南按你遇到问题时可能会搜索的内容进行组织。

## 转换警告和错误

每次导入都会在内容旁返回一个 `logs` 对象，其中包含 `warn` 和 `error` 数组。警告表示有内容未能写入文档；当文档中缺少内容时，这是首先要检查的地方。

```json
{
  "content": {
    /* Tiptap JSON */
  },
  "logs": {
    "warn": [
      {
        "message": "Image skipped: No imageUploadConfig was provided, so images cannot be imported.",
        "fileName": "image1.gif"
      }
    ],
    "error": [
      {
        "message": "Image upload failed: General error",
        "fileName": "image1.gif",
        "url": "https://your-image-upload-endpoint.com",
        "error": "Unable to connect. Is the computer able to access the url?",
        "context": "uploadImage general error"
      }
    ]
  }
}
```

这些日志会通过 `context` 传递到 `onImport` 回调中，因此你可以记录日志，或将其展示给上传文件的用户：

```ts
editor
  .chain()
  .importDocx({
    file,
    onImport(context) {
      for (const warning of context.logs.warn) {
        console.warn(warning.message)
      }

      context.setEditorContent()
    },
  })
  .run()
```

## 插入前检查转换后的内容

要了解转换器实际生成了什么，最快的方法是在 `onImport` 回调中记录 `context.content`：

```ts
editor
  .chain()
  .import({
    file,
    onImport(context) {
      console.log('Imported content:', JSON.stringify(context.content, null, 2))
      context.setEditorContent()
    },
  })
  .run()
```

`context.content` 中的每个节点都包含其类型和属性。如果某项功能的呈现结果不符合预期，首先查看这里对应的节点。它可以告诉你转换器是丢弃了该功能、将其映射为其他节点，还是传递了编辑器架构无法呈现的属性。

## 确认编辑器扩展

导入的内容无法呈现时，最常见的原因是编辑器架构中缺少某个扩展。可以在运行时查看已注册的扩展：

```ts
console.log(editor.extensionManager.extensions.map((e) => e.name))
```

如果使用 `ConvertKit`，你应该能看到段落、标题、图像、表格扩展以及标准标记。如果缺少某项，请检查是否确实注册了 ConvertKit，以及是否误将 `ConvertKit.configure({…})` 中所需的位置设为 `false`。

## 常见 HTTP 响应

发送到服务的转换请求会返回少数几种响应。每种响应都有明确的原因和相应的处理方式。

| 状态 | 含义 | 处理方式 |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `401`  | 缺少 JWT 或 JWT 无效。 | 在服务器端重新生成令牌。 |
| `403`  | 你的应用无权执行此操作。最常见的情况是：所用格式不在当前套餐范围内，或在云端套餐中使用了 `customFonts`。 | 查看[定价页面](https://tiptap.dev/pricing)，了解各套餐支持的格式。PDF 中使用自定义字体需要企业版套餐或本地部署。 |
| `5xx`  | 暂时性的服务器端错误。 | 使用指数退避策略重试。如果问题持续存在，请提交支持工单。 |

围绕这三种情况设计错误处理即可；无需针对每种情况编写细致的分支逻辑。

## Pages 无限循环情形

当 Pages 编辑器停止响应时，**首先要检查这一点**。编辑器会变得无响应，滚动停止，CPU 占用飙升，并且控制台会反复出现 Pages 警告。

**原因。** 不可拆分的块（表格行、图形、定位容器以及大多数 BFC 元素）比页面还高。Pages 无法将它放置在任何页面上（当前页放不下，下一页也一样），因此布局会不断将其向后移动，始终无法稳定下来。

**请从内容入手修复，而不是修改扩展配置：**

1. 在问题块上使用 `max-height: var(--page-max-height)` 限制高度。
2. 将过高的内容拆分成相邻的小块（长表格 → 多个较小的表格；高图形 → 多个较小的图形）。
3. 对于从 DOCX 导入的表格，如果行内容高度有上限，请将 `heightRule: "atLeast"` 改为 `"exact"`。
4. 如果内容原本是按大于目标页面的纸张尺寸制作的，请选择更大的页面格式。

有关详细说明，请参阅[限制]( /pages/core-concepts/limitations#oversized-non-splittable-blocks-cause-an-infinite-layout-loop)；有关表格的具体处理方式，请参阅 [PagesTableKit 已知问题](/pages/guides/pages-tablekit#known-issues)。

<Callout title="将警告视为信号" variant="warning">
  导入用户提供的 DOCX 的生产代码应明确处理 Pages 警告：拒绝该文档并告知用户，或在插入前以编程方式拆分过高的行。不要仅依赖警告来保证编辑器仍可使用。
</Callout>

## 确认 Pages 是否自动应用了导入的页眉和页脚

将 DOCX 导入已注册 Pages 扩展的编辑器时，Word 文档中的页眉和页脚内容会自动应用。要确认这一点，请读取已发布的存储：

```ts
const { pages } = editor.storage
console.log({
  default: pages.headerHTML,
  firstPage: pages.headerFirstPageHTML,
  oddPages: pages.headerOddHTML,
  evenPages: pages.headerEvenHTML,
})
```

页脚也有对应的 `footer*HTML` 属性。在导入器填充内容或用户打开内联编辑器并编辑内容之前，每个属性的值都是 `null`。

如果你确认 DOCX 中包含页眉和页脚，但导入后这些值仍为 `null`，可能有以下两个原因：

- **未注册 Pages 扩展。** 只有在存在 Pages 扩展时，ImportDocx 才会自动应用这些内容。
- **DOCX 实际上并未包含页眉和页脚。** Word 可能存储了模板，但并未将其写入文档。请检查上面的日志，确认转换器提取到了哪些内容。

## 架构不匹配警告

当导入内容使用了编辑器无法呈现的节点类型时，ProseMirror 会对未知节点发出警告，并回退为丢弃或改写该节点。可以通过以下两种方式解决：

1. **添加缺少的扩展。** ConvertKit 涵盖了大多数情况；如果你禁用了某个扩展，或使用自定义 kit，请重新添加该扩展。
2. **将不受支持的节点映射为受支持的节点。** ImportDocx 接受 `prosemirrorNodes` 和 `prosemirrorMarks` 选项，可在导入期间重写节点类型。请参阅[自定义节点映射](/conversion/import/docx/custom-node-mapping)和[自定义标记映射](/conversion/import/docx/custom-mark-mapping)。

对于架构中没有对应类型的节点（例如脚注引用），请参阅[自定义扩展指南](/conversion/getting-started/guides/custom-extensions)。
