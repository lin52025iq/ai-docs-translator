带有[修订跟踪](/tracked-changes/getting-started/overview)建议的文本会导出为真正的 Word 修订，因此会显示在 Word 的审阅窗格中，并可在那里接受或拒绝。

## 工作原理

无需配置。如果导出的内容中包含建议，它们就会转换为修订：

```ts
editor.chain().exportDocx().run()
```

| 标记类型           | 转换为             |
| ------------------ | ------------------ |
| `add`              | Word 插入修订      |
| `delete`           | Word 删除修订      |
| `replaceInsertion` | 编辑中的插入部分   |
| `replaceDeletion`  | 编辑中的删除部分   |

这些值直接对应建议标记本身。修订跟踪查询 API 会将后两项合并报告为一个 `replace` 建议，因此在查询结果中会看到 `replace`，而这里则会看到这两个部分。

替换会写成先删除、紧接着再插入，这是 Word 表示文本替换的方式。导入的文档只会包含 `add` 和 `delete`，因此这两个部分来自在编辑器中进行的编辑。

## 节点类型更改

如果文档包含待处理的[节点类型建议](/tracked-changes/usage/advanced-usage#node-type-changes)，例如将段落转换为标题，DOCX 导出会拒绝处理。导出修订跟踪内容前，请先接受或拒绝这些提议。

## 整块内容

当建议涵盖整个节点时，例如 [Compare](/compare/guides/tracked-changes) 为新增或删除的段落生成的建议，或编辑器为插入的图像生成的建议，导出结果会按照 Word 跟踪修订的方式处理。节点内部的内容会成为修订，而节点本身会标记为已插入或已删除。因此，在 Word 中接受或拒绝时，会删除或还原整个内容，不会留下空行。

这适用于段落、标题、引用块、列表和列表项、任务项、表格行和单元格、图像以及水平线。针对容器（如列表或表格单元格）的建议会作用于其中的所有内容。

针对链接的建议会同时保留链接和修订，与 Word 编写跟踪链接的方式一致。

## 作者和日期

每条修订都会带有审阅者姓名和时间戳，这些信息取自建议：

- 姓名取自 `userMetadata.name`。如果没有该值，则使用 `userId`；如果也没有，则使用 `anonymous`。
- 日期取自 `createdAt`。如果建议没有可用的时间戳，则会使用固定的占位日期，因为 Word 不接受日期为空的修订。

在 Word 中打开文件后，这些信息会显示在审阅窗格中，并按审阅者分组，效果与直接在 Word 中进行编辑完全相同。

## 不会导出的内容（正在完善中）

以下情况都会导出内容本身，因此文档在 Word 中仍可正常阅读。缺少的是某项内容属于跟踪修订的记录。

- **格式建议。** 记录文本已设为粗体的建议不会写成 Word 格式修订。格式本身会导出，因此文本显示正常，但不会显示为跟踪修订。
- **任务项的复选框。** 带有跟踪修订的任务项文本会作为修订导出，但复选框不会，因为 Word 不允许在修订中包含复选框控件。在 Word 中接受删除后，空复选框仍会保留。
- **重叠建议的一种堆叠顺序。** 当删除和插入作用于同一段文本时，如果一位审阅者删除了另一位审阅者插入的内容，导出结果会将两条修订嵌套，因此 Word 会显示两位作者。相反的堆叠顺序则只会写入删除修订。

## 往返转换

从 Word 导入并设置 [`trackedChanges: 'preserve'`](/conversion/import/docx/tracked-changes) 的文档，再次导出后会保留修订以及每位审阅者的姓名和日期。

有一点会有所不同：Word 会为每段文本分别写入一条修订记录，导出时也会如此。因此，跨越不同格式文本的单条建议会被写成多条相邻修订，而不是一条。Word 会在审阅窗格中将它们重新组合，因此读者看到的更改内容仍然相同。

<Callout variant="info" title="在 Word 中接受更改与在 Tiptap 中接受效果相同">
  在 Word 中接受所有更改后得到的文本，与使用 `trackedChanges: 'accept'` 导入同一文件得到的文本相同；拒绝所有更改则与 `trackedChanges: 'reject'` 的效果相同。例外是[不会导出的内容](#what-is-not-exported-work-in-progress)中列出的情况：修订不会写入，因此无法接受或拒绝。
</Callout>
