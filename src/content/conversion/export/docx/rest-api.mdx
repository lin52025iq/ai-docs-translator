DOCX 导出 API 可将 Tiptap JSON 文档转换为 `.docx`（Microsoft Word）文件。它使用与[编辑器扩展](/conversion/export/docx/editor-extension)相同的转换库，对标准内容生成等效的 DOCX 输出。

REST API 支持[样式覆盖](/conversion/export/docx/styles)、[通过 DSL 渲染自定义节点](/conversion/export/docx/custom-nodes-dsl)、页面大小和边距、页眉/页脚、评论线程以及元素级覆盖（`tableOverrides`、`paragraphOverrides`、`textRunOverrides`、`tableCellOverrides`、`imageOverrides`）。它不接受 JavaScript 函数选项。若要使用基于函数的自定义节点 API，请使用[编辑器扩展](/conversion/export/docx/editor-extension)，该扩展也可在服务器端运行。

</Callout>

## 导出 DOCX

`POST /v2/convert/export/docx`

`/v2/convert/export/docx` 端点可将 Tiptap 文档转换为 `DOCX` 格式。用户可以向此端点发送 `POST` 请求，并使用各种参数自定义转换过程中对不同文档元素的处理方式。

<Callout title="导出自定义选项支持情况" variant="info">
  `/v2/convert/export/docx` 端点接受[样式覆盖](/conversion/export/docx/styles)、
  页面大小/边距、页眉/页脚、五种元素级覆盖（`tableOverrides`、
  `paragraphOverrides`、`textRunOverrides`、`tableCellOverrides`、`imageOverrides`），以及
  [通过 JSON DSL 渲染自定义节点](/conversion/export/docx/custom-nodes-dsl)。它不接受
  JavaScript 函数选项。若要使用基于函数的自定义节点 API，请使用[编辑器
  扩展](/conversion/export/docx/editor-extension)或[服务器端导出
  指南](/conversion/export/docx/editor-extension#server-side-export)。
</Callout>

### 示例（cURL）

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"attrs\":{\"textAlign\":\"left\"},\"content\":[{\"type\":\"text\",\"text\":\"Welcome to this demonstration of our editor ability to export a wide array of formatting options to DOCX, ensuring that your content retains its intended appearance in Word.\"}]}]}",
      "exportType": "blob"
    }'
```

<Callout title="需要订阅" variant="warning">
  此端点需要有效的 Tiptap 订阅。详情请查看我们的[定价页面](https://tiptap.dev/pricing)。
</Callout>

### 必需的请求头

| 名称 | 说明 |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |

| `Content-Type`  | 必须为 `application/json` |

| `styleOverrides` | `Object` | 样式覆盖 | `{}` |
| `pageSize` | `Object` | 页面大小配置 | `undefined` |
| `pageMargins` | `Object` | 页面边距配置 | `undefined` |
| `headers` | `Object` | 页眉配置 | `undefined` |
| `footers` | `Object` | 页脚配置 | `undefined` |
| `tableOverrides` | `Object` | 表格级渲染覆盖 | `undefined` |
| `paragraphOverrides` | `Object` | 段落级渲染覆盖 | `undefined` |
| `textRunOverrides` | `Object` | 文本运行渲染覆盖 | `undefined` |
| `tableCellOverrides` | `Object` | 表格单元格渲染覆盖 | `undefined` |
| `imageOverrides` | `Object` | 图像渲染覆盖 | `undefined` |
| `headerFooterOverrides` | `Object` | 仅应用于页眉/页脚内容的逐字段覆盖（与元素覆盖使用相同的五个键）。请参阅[元素覆盖](#element-overrides)。 | `undefined` |
| `customNodeDsl` | `Object` | [自定义节点 DSL](/conversion/export/docx/custom-nodes-dsl) 规则 | `undefined` |
| `placeholders` | `Object \| false` | 可选的 `{ page?, total? }` 重命名映射，与 `Pages.configure({ placeholders })` 对应，可将各页眉或页脚位置中重命名的标记（如 `{p}` / `{pages}`）转换为动态 `PAGE` / `NUMPAGES` 字段。传入 `false` 可完全禁用替换（导出的 `.docx` 中会保留字面文本 `{page}` / `{total}`）。请参阅[自定义标记名称](#custom-token-names-placeholders)。 | `undefined` |
| `comments` | `Object` | 要嵌入为原生 Word 评论的评论线程：`{ threads: [...] }`。每个线程包含其消息、作者、日期和解决状态，并锚定到文档的 `inlineThread` / `blockThread` 标记。请参阅[评论](#comments)。 | `undefined` |
| `footnotes` | `Object` | 按注释 ID 索引的脚注正文。每个值都是 Tiptap JSON 文档。请参阅[脚注和尾注](#footnotes-and-endnotes)。 | `undefined` |
| `endnotes` | `Object` | 按注释 ID 索引的尾注正文，结构与 `footnotes` 相同。请参阅[脚注和尾注](#footnotes-and-endnotes)。 | `undefined` |

#### 页面大小配置

`pageSize` 对象可用于自定义导出 DOCX 文档的尺寸：

| 属性 | 类型 | 说明 | 默认值 |
| -------- | -------- | ---------------------------------------------------------------------------------------------------- | ---------- |
| `width` | `string` | 页面宽度。必须是正数，后接有效单位（cm、in、pt、pc、mm、px）。 | `"21.0cm"` |
| `height` | `string` | 页面高度。必须是正数，后接有效单位（cm、in、pt、pc、mm、px）。 | `"29.7cm"` |

**自定义页面大小的 cURL 示例：**

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"Document with custom page size\"}]}]}",
      "exportType": "blob",
      "pageSize": {"width": "21.0cm", "height": "29.7cm"}
    }'
```

| `right` | `string` | 页面右边距。必须是正数，后接有效单位（cm、in、pt、pc、mm、px）。 | `"1.0cm"` |

**自定义页面边距的 cURL 示例：**

#### 页眉和页脚

`headers` 和 `footers` 对象可用于配置导出 DOCX 的页眉和页脚选项。

##### 页眉配置

`headers` 对象可用于自定义导出 DOCX 文档的页眉：

| 属性 | 类型 | 说明 |
| -------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `evenAndOddHeaders` | `boolean` | 是否为奇数页和偶数页使用不同的页眉 |
| `differentFirstPage` | `boolean` | 是否为首页使用不同的页眉。设为 `true` 时，第一页使用 `first` 值，而不是 `default`。 |
| `default` | `string \| Object` | 每页的标准默认页眉；启用 `evenAndOddHeaders` 选项时，则用作奇数页页眉。接受纯文本、字符串化的 Tiptap JSONContent 或 Tiptap JSONContent 对象。 |
| `first` | `string \| Object` | 首页页眉。仅当 `differentFirstPage` 设为 `true` 时使用。接受纯文本、字符串化的 Tiptap JSONContent 或 Tiptap JSONContent 对象。 |
| `even` | `string \| Object` | 启用 `evenAndOddHeaders` 选项时的偶数页页眉。接受纯文本、字符串化的 Tiptap JSONContent 或 Tiptap JSONContent 对象。 |

<Callout title="可接受的位置值">
  每个页眉值可以采用以下三种形式之一：

- **纯文本字符串。**生成简单的无样式页眉。
- **字符串化的 Tiptap JSONContent。**支持粗体、斜体和链接等富文本格式。使用 `JSON.stringify(yourHeaderDoc)` 生成。
- **Tiptap JSONContent 对象。**同样支持富文本内容，可作为嵌套 JSON 对象直接放入请求体，无需字符串化。

在 JSON 请求体中，对象必须包含 `type` 字段；如果格式无效，则会返回 `400 Bad Request`。

</Callout>

**自定义页眉的 cURL 示例：**

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"Document with custom headers\"}]}]}",
      "exportType": "blob",
      "headers": {"evenAndOddHeaders": true, "default": "Default Header", "first": "First Page Header", "even": "Even Page Header"}
    }'
```

#### 页脚配置

`footers` 对象可用于自定义导出 DOCX 文档的页脚：

| 属性 | 类型 | 说明 |
| -------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `evenAndOddFooters` | `boolean` | 是否为奇数页和偶数页使用不同的页脚 |
| `differentFirstPage` | `boolean` | 是否为首页使用不同的页脚。设为 `true` 时，第一页使用 `first` 值，而不是 `default`。 |
| `default` | `string \| Object` | 每页的标准默认页脚；启用 `evenAndOddFooters` 选项时，则用作奇数页页脚。接受纯文本、字符串化的 Tiptap JSONContent 或 Tiptap JSONContent 对象。 |
| `first` | `string \| Object` | 首页页脚。仅当 `differentFirstPage` 设为 `true` 时使用。接受纯文本、字符串化的 Tiptap JSONContent 或 Tiptap JSONContent 对象。 |
| `even` | `string \| Object` | 启用 `evenAndOddFooters` 选项时的偶数页页脚。接受纯文本、字符串化的 Tiptap JSONContent 或 Tiptap JSONContent 对象。 |

<Callout title="可接受的位置值">
  每个页脚值与页眉值一样，可以采用三种形式之一：纯文本字符串、字符串化的 Tiptap JSONContent 或 Tiptap JSONContent 对象。在 JSON 请求体中，对象必须包含 `type` 字段；如果格式无效，则会返回 `400 Bad Request`。
</Callout>

<Callout title="`{page}` / `{total}` 标记会转换为动态 Word 字段" variant="info">
  REST API 会将页眉/页脚中的 `{page}`、`{total}` 以及同义标记 `{numpages}` 转换为导出 `.docx` 中的动态 Word `PAGE` / `NUMPAGES` 字段。所有位置值形式均支持此功能：纯文本字符串、字符串化的 Tiptap JSON 或 Tiptap JSON 对象。若要使用 `{p}` / `{pages}` 等自定义标记名称，必须传入可选的 `placeholders` 重命名映射。请参阅下文的[自定义标记名称](#custom-token-names-placeholders)。传入 `"placeholders": false` 可将标记作为字面文本写入。
</Callout>

#### 自定义标记名称（`placeholders`）

如果编辑器通过 [`Pages.configure({ placeholders })`](/pages/core-concepts/page-header-footer#renaming-or-disabling-placeholders) 重命名了内置标记，请将相同的重命名映射传递给 REST API，以确保传输格式一致。传输字段的名称和结构与编辑器选项相同：

```json
{
  "doc": "{\"type\":\"doc\",\"content\":[]}",
  "footers": { "default": "{p} of {pages}" },
  "placeholders": { "page": "p", "total": "pages" }
}
```

如果未提供映射，服务会默认识别 `{page}`、`{total}` 和 `{numpages}`（Word 对总页数字段的写法；保留此同义标记是为了让直接调用 REST API 的用户能够匹配 `/import/docx` 的输出）。重命名 `total` 后，`{numpages}` 同义标记也会失效，因此未更新的标记将按字面文本显示；重命名规则严格执行。传入 `"placeholders": false` 可禁用所有位置的替换，使所有 `{page}` / `{total}` 文本都按原样写入，而不生成动态字段。

**自定义页脚的 cURL 示例：**

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"Document with custom footers\"}]}]}",
      "exportType": "blob",
      "footers": {"evenAndOddFooters": true, "default": "Default Footer", "first": "First Page Footer", "even": "Even Page Footer"}
    }'
```

### 评论

传入 `comments` 对象，可将评论线程作为原生 Word 评论嵌入导出的 `.docx`。每个线程通过文档自身的评论标记锚定到对应文本：`inlineThread` 标记的 `data-thread-id` 与线程 `id` 相匹配，或使用 `blockThread` 节点。`comments` 字段提供线程正文、作者、日期和解决状态。

其结构与编辑器的导出扩展一致：

| 字段 | 类型 | 说明 |
| ---------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `threads` | `Array` | 要嵌入的评论线程。 |
| `threads[].id` | `String` | 线程 ID。必须与 `doc` 中对应 `inlineThread` / `blockThread` 的 `data-thread-id` 相匹配。 |
| `threads[].resolvedAt` | `String \| null` | 设置后，该线程会以已解决状态导出。 |
| `threads[].comments` | `Array` | 线程中的消息，先列根消息，再按顺序列出回复。 |
| `comments[].id` | `String` | 消息 ID。 |
| `comments[].content` | `String \| Object` | 消息正文，可以是纯文本或 Tiptap JSON。 |
| `comments[].data` | `Object` | 可选元数据：`author`、`initials`、`dateIso`、`dateUtc` 以及往返转换标识（`originalWId`、`originalDurableId`）。 |

如果省略此字段，导出结果中不会包含评论，因此不会影响现有请求。

**包含评论线程的 cURL 示例：**

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"Reviewed text\",\"marks\":[{\"type\":\"inlineThread\",\"attrs\":{\"data-thread-id\":\"T1\"}}]}]}]}",
      "exportType": "blob",
      "comments": {
        "threads": [
          {
            "id": "T1",
            "resolvedAt": null,
            "comments": [
              {
                "id": "c1",
                "content": "Please cite a source.",
                "data": { "author": "Ada Lovelace", "initials": "AL", "dateIso": "2026-01-01T00:00:00.000Z" }
              }
            ]
          }
        ]
      }
    }'
```

### 脚注和尾注

传入 `footnotes` 和 `endnotes` 可导出 Word 脚注和尾注。两者都是以注释 ID 为键的对象，每个值都是 `
