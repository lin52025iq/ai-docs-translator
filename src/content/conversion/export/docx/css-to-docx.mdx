## 功能说明

通常，将 Tiptap 导出为 DOCX 时，会读取文档的**节点和标记属性**，并将其以内联方式写入每个段落、文本片段和单元格。生成的 DOCX 文件中，每个元素都带有自己的 `fontSize`、`color` 和间距副本：内容冗长、重复冗余，视觉效果虽相同，但结构欠佳。

此功能让你可以继续以编辑器的**样式表**作为唯一事实来源。你可以提供 CSS 规则（显式指定，或让我们从浏览器中提取），导出时我们会将这些规则编译为 DOCX **样式定义**：这是 Word 用作自身事实来源的命名条目。导出的 DOCX 会包含规范的样式目录，Word 用户只需编辑一次，就能更改所有使用相应样式的段落外观。

配合[导入时注入 CSS](/conversion/import/docx/css-injection)，你就可以往返转换文档的*样式层*，并使其与*内容层*相互独立。

## 工作原理

分为三个步骤：

1. **收集 CSS。** 导出器会从两个可能的来源读取样式（可以任选其一，也可以同时使用）：
   - 传入 `configure()` 的显式 `styles` 对象
   - 浏览器当前的样式表（如果设置了 `extractFromDocument: true`），范围限定为编辑器根节点
2. **编译每个选择器。** 编译器会在固定映射表中查找每个选择器（与导入端的 16 个选择器相同），将每个 CSS 属性转换为对应的 DOCX 属性，并舍弃无法映射的属性。
3. **合并到样式目录。** 编译后的 DOCX 样式片段会合并到导出选项的样式目录中，然后交给 DOCX 写入器处理。

```ts
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

ExportDocx.configure({
  cssStyles: {
    styles: {
      h1: { fontSize: '32px', fontWeight: 'bold', color: '#1a1a1a' },
      p:  { fontSize: '16px', lineHeight: 1.5, marginTop: '0pt', marginBottom: '8pt' },
      blockquote: { fontStyle: 'italic', color: '#555' },
    },
    // Optional: also pick up rules from the live browser stylesheets
    extractFromDocument: true,
    // Optional: base for rem/em resolution
    baseFontSize: 16,
  },
})
```

当 `extractFromDocument: true` 时，导出器会遍历 `document.styleSheets`，选取选择器与编辑器根节点作用域内的 16 个选择器映射表匹配的规则，并将其与显式提供的 `styles` 合并。**显式样式在每个属性上优先。**

## 支持的功能

**选择器（16 个）：**与导入端相同。

`p`、`h1`–`h6`、`blockquote`、`ul li`、`ol li`、`strong`、`em`、`u`、`s`、`a`、`code`

**CSS 属性。**每个选择器可以包含以下任意子集。未列出的属性会在导出时跳过，并通过 `console.warn` 发出警告。

- `fontSize`：转换为半磅（DOCX `w:sz`）
- `color`：映射为 DOCX `w:color`（十六进制）
- `fontFamily`：映射为 DOCX `w:rFonts`
- `fontWeight`：`bold` 会启用 `w:b`
- `fontStyle`：`italic` 会启用 `w:i`
- `textDecoration`：`underline` → `w:u`，`line-through` → `w:strike`
- `backgroundColor`：映射为 DOCX `w:shd` 填充色
- `letterSpacing`：导出时支持（导入时不提取）
- `textAlign`：映射为 DOCX `w:jc`（`justify` → DOCX `both`）
- `marginTop` / `marginBottom`：映射为 `w:spacing` 的 `before` / `after`（单位为 twip）
- `lineHeight`：无单位值 → 自动行距规则（比例）；`Npt` → 固定值；`Npx` → 转换后使用

**单位转换。**编译器接受 `px`、`pt`、`rem`、`em`。`rem` 和 `em` 会根据 `baseFontSize` 进行解析（默认为 `16`）。其他单位（`%`、`vh`、`ch` 等）无法识别，相应属性会被跳过。

**列表合并。**`ul li` 和 `ol li` 都会映射到 DOCX 的 `ListParagraph` 样式。如果两者都有定义，其属性会合并；对于同一属性，后出现的条目优先。

## 不支持的功能

<Callout variant="warning" title="以下限制是有意设定的">
这些并非错误，而是此功能明确记录的边界。如果你的工作流程依赖以下任何一项，此功能就不适合你的需求。
</Callout>

- **跨域样式表。**浏览器安全机制会阻止访问来自其他源的样式表中的 `.cssRules`。`extractFromDocument` 会静默跳过这些样式表。如果你的主题托管在 CDN 上，请改为通过 `styles` 显式传入规则。
- **伪类、伪元素和媒体查询。**`a:hover`、`p::first-line`、`@media (min-width: …)`：这些都无法映射到 DOCX，会被舍弃。
- **CSS 变量和 `calc()`。**编译器读取的是声明值，而不是计算值，因此不会解析 `var(--brand)` 或 `calc(100% - 2rem)`。传入样式前，请先解析这些值。
- **任意选择器。**选择器映射表仅包含这 16 个选择器。`.prose p` 或 `article h1` 之类的后代选择器，只有在*移除作用域后*与映射表中的选择器完全匹配时才会被解析，否则会被舍弃。
- **层叠和优先级。**编译器会将每个选择器压平为一组属性。如果同一选择器在不同优先级下存在冲突规则，只有编译后的结果会写入 DOCX，不会保留层叠关系。
- **计算样式继承。**浏览器提取器直接读取 `document.styleSheets`，不会遍历 DOM 或计算继承值。如果某个属性在浏览器中是继承的，但未在目标选择器上声明，就不会被导出。

## 预期结果

- 生成的 DOCX 文件包含规范的 `styles.xml`，Word 用户可以在一个位置集中编辑样式。
- 每个匹配的选择器恰好对应一个 DOCX 样式条目，且只包含成功映射的属性。其余属性要么从显式 `styles` 覆盖项合并，要么通过 `console.warn` 警告后跳过。
- 行为具有确定性：给定相同的输入（`styles` 对象和 DOM 样式表），导出结果的字节内容可比较。
- 可安全地在服务器端使用：如果 `document` 未定义（Node、SSR），`extractFromDocument` 将不执行任何操作，不会抛出错误，也不会注入任何内容。

## 不应期待的结果

- **与导入端完全往返一致。**某些 CSS → DOCX 转换会有损（例如：`line-height: 1.5` → 自动行距规则；但重新导入该 DOCX 时，行高会以无单位倍率的形式输出，如果 Word 对存储值进行了规范化，该值可能不再恰好等于 `1.5`）。
- **行内标记属性在往返转换后保留。**导出时，每个选择器都接受全部 12 个属性，包括 `strong`、`em`、`u`、`s`、`a`、`code`。但导入时，对应的 [CSS 注入](/conversion/import/docx/css-injection)会将这些行内标记选择器限制为仅保留其特征属性（例如，`strong` 保留 `fontWeight`，`em` 保留 `fontStyle`，`code` 保留 `fontFamily`/`color`/`fontSize`/`backgroundColor`）。为避免通过优先级覆盖父级块样式，超出这些范围的设置在重新导入时会被舍弃。例如，若要让 `strong` 的颜色在往返转换后保留，请改为在父级选择器（`p`、`h1`）上设置颜色。
- **感知媒体查询的导出。**DOCX 不支持媒体查询。如果响应式 CSS 在移动端和桌面端不同，导出时会采用调用 `configure()` 时匹配的规则（通常是桌面端规则）。
- **与浏览器渲染完全一致的视觉效果。**DOCX 渲染引擎（Word、LibreOffice、Google Docs）对样式的解析方式与浏览器不同。行距、字距和段落间距可能略有差异。
- **自动转换主题。**颜色、字体和字号会一对一映射，但 Word“主题”（强调色、字体搭配）不会转换。如果要使用 Word 主题，必须直接在导出选项中进行设置。

## 配置参考

```ts
ExportDocx.configure({
  cssStyles: {
    // Either: explicit object of selectors → CSS declarations
    styles?: {
      p?: { fontSize?: string; color?: string; /* … */ },
      h1?: { /* … */ },
      // …any of the 16 selectors
    },

    // Or: extract from the browser's live stylesheets
    extractFromDocument?: boolean,  // default: false

    // Base size for resolving rem / em
    baseFontSize?: number,  // default: 16
  },
})
```
