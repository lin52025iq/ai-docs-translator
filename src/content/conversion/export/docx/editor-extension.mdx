使用 Tiptap 的 `@tiptap-pro/extension-export-docx` 将编辑器内容导出为 `.docx` 文件。由于 `exportDocx` 函数具有同构特性，此扩展可在任何 JavaScript 环境中使用，包括服务器端应用程序。

你也可以通过 [REST API](/conversion/export/docx/rest-api) 导出。两种方式使用相同的转换库，主要区别如下：

|                       | 编辑器扩展                                                                                                                                                                                                                                                                                     | REST API                                                                                      |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 运行位置               | 你的应用（客户端或服务器端）                                                                                                                                                                                                                                                                     | Tiptap 云                                                                                  |
| 自定义节点渲染         | 通过 [`customNodes`](/conversion/export/docx/custom-nodes) 支持                                                                                                                                                                                                                                  | 通过 [`customNodeDsl`](/conversion/export/docx/custom-nodes-dsl) 支持*                   |
| 元素覆盖               | [`paragraphOverrides`、`textRunOverrides`、`tableOverrides`、`tableRowOverrides`、`tableCellOverrides`、`imageOverrides`](/conversion/export/docx/styles#element-overrides)，以及用于页眉/页脚范围覆盖的 [`headerFooterOverrides`](/conversion/export/docx/styles#headerfooteroverrides) | 与静态对象相同的字段，但不包括 `tableRowOverrides`*                                   |
| 样式覆盖               | 支持                                                                                                                                                                                                                                                                                            | 支持                                                                                     |
| 页眉和页脚             | docx.js 对象，或从 Pages 自动提取                                                                                                                                                                                                                                                         | 纯文本、序列化为字符串的 JSON，或 JSON 对象                                                |
| 脚注                   | 从 [Pages 脚注](/pages/core-concepts/footnotes) 自动提取，或通过 `footnotes` 选项提供                                                                                                                                                                                        | 通过 [`footnotes` 字段](/conversion/export/docx/rest-api#footnotes-and-endnotes)提供 |
| 尾注                   | 从 [Pages 尾注](/pages/core-concepts/endnotes) 自动提取，或通过 `endnotes` 选项提供                                                                                                                                                                                           | 通过 [`endnotes` 字段](/conversion/export/docx/rest-api#footnotes-and-endnotes)提供  |

\* REST API 不接受 `customNodes` 渲染函数或 `tableRowOverrides`。在验证过程中，请求中的这些字段会被移除，导出时则使用默认值。如果需要其中任一功能，请使用编辑器扩展。

如果要在没有编辑器的情况下从服务器导出，请选择 REST API。如果需要 `customNodes` 渲染函数、基于函数的覆盖、`tableRowOverrides` 或对输出的完全控制，请使用编辑器扩展。

默认情况下，扩展会将 Tiptap 节点映射为 DOCX 元素。如果内容包含自定义节点，请配置其[导出行为](/conversion/export/docx/custom-nodes)，确保它们得到正确转换。

## 安装 DOCX 导出扩展

Conversion 扩展发布在 Tiptap 的私有 npm registry 中。按照[私有 registry 指南](/guides/pro-extensions)集成这些扩展。

完成后，即可安装并导入 **Export DOCX** 扩展包：

```bash
npm i @tiptap-pro/extension-export-docx
```

使用导出扩展不需要 Tiptap Conversion 凭据，因为转换会直接在扩展中完成。

```js
import { ExportDocx } from '@tiptap-pro/extension-export-docx'
```

## 配置扩展

可以将 `ExportDocxOptions`（`object`）作为参数传入 `configure` 方法，并通过以下属性配置 `ExportDocx` 扩展：

```ts
// Import the ExportDocx extension
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    // Other extensions ...
    ExportDocx.configure({
      onCompleteExport: (result: string | Buffer<ArrayBufferLike> | Blob | Stream) => void, // required
      exportType: 'blob', // optional. Default: 'blob'
      customNodes: [], // optional. Default: []
      styleOverrides: {}, // optional. Default: {}
      paragraphOverrides: {}, // optional. Default: {}
      textRunOverrides: {}, // optional. Default: {}
      tableOverrides: {}, // optional. Default: {}
      tableRowOverrides: {}, // optional. Default: {}
      repeatTableHeaderRows: false, // optional. Default: false
      tableCellOverrides: {}, // optional. Default: {}
      imageOverrides: {}, // optional. Default: {}
      onWarning: undefined, // optional. Default: undefined
      onImageError: 'skip', // optional. Default: 'skip'
      numberingFormats: undefined, // optional. Default: undefined
      headerFooterOverrides: undefined, // optional. Default: undefined
      fonts: undefined, // optional. Default: undefined
      embedFonts: false, // optional. Default: false
      token: undefined, // optional. Default: undefined
      endpoint: undefined, // optional. Default: undefined
      region: 'eu', // optional. 'eu' or 'us'. Default: 'eu'
    }),
    // Other extensions ...
  ],
  // Other editor settings ...
})
```

| headerFooterOverrides | 仅适用于页眉/页脚内容的逐字段覆盖；它们会完全替换页眉和页脚中对应的正文全局覆盖。仅适用于从 [Pages 扩展](/pages/getting-started/overview)自动提取的页眉/页脚。[查看 `headerFooterOverrides`](/conversion/export/docx/styles#headerfooteroverrides)                                                                          | `undefined`                         |

## 导出 DOCX 文件

安装扩展后，即可将编辑器内容转换为 `.docx`。

在开始查看示例之前，先来看看编辑器命令中 `exportDocx` 方法的签名：

```ts
/**
 * Export the current document as a .docx file
 *
 * Notes: 'buffer' and 'stream' export types are only available in the server environment
 * as they use the Node Buffer and Stream APIs respectively
 *
 * @param onCompleteExport - Callback function to handle the exported file
 * @param options - Export options
 * @param customNodes - Custom node definitions to ensure proper conversion
 * @param styleOverrides - Custom styles to apply to the exported document
 * @example editor.commands.exportDocx((result) => {}, { exportType: 'buffer' }, [])
 *
 */
exportDocx: (options?: ExportDocxOptions) =>
  Promise<string | Buffer<ArrayBufferLike> | Blob | Stream>
```

```js
      onWarning: undefined, // optional. Default: undefined
      onImageError: 'skip', // optional. Default: 'skip'
      headerFooterOverrides: undefined, // optional. Default: undefined
      fonts: undefined, // optional. Default: undefined
      embedFonts: false, // optional. Default: false
      token: undefined, // optional. Default: undefined
      endpoint: undefined, // optional. Default: undefined
      region: 'eu', // optional. 'eu' or 'us'. Default: 'eu'
    }),
    // Other extensions ...
  ],
  // Other editor settings ...
})

// Declare some functions that will call the exportDocx method from your editor

function handleExportDocx() {
  // Call your editor's exportDocx method
  editor
    .chain()
    // Method call without any overrides
    // It will take the configuration set in the configure method
    .exportDocx()
    .run()
}

function handleExportDocxBuffer() {
  // Call your editor's exportDocx method
  editor
    .chain()
    // Call your editor's exportDocx method
    .exportDocx({
      // Override the onCompleteExport callback to handle the override exported type
      onCompleteExport: (result: Buffer) => {

      },
      // Override the export type
      exportType: 'Buffer',
    })

handleExportDocx()
handleExportDocxBuffer()
```

### 工作原理

上述示例完全在浏览器中运行。由于我们没有覆盖 `exportType`，它会使用默认值 `blob`，因此 ExportDocx 扩展会生成 DOCX Blob。随后，我们以编程方式下载文件。你可以调整此逻辑，例如将 Blob 发送到服务器，而不是下载。

| Parameter        | 说明                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| onCompleteExport | 转换完成后，转换结果会作为回调函数唯一的参数传入；在此例中，它是一个 `Blob`，因为我们在 `options` 参数的 `exportType` 中指定了此类型。你可以根据需要处理它，例如像上面的示例那样提示用户下载文件。 |
| exportType       | 使用默认值 `blob`，因此转换会返回 `Blob`。                                                                                                                                                                                                                                                                                                                              |
| customNodes      | 由于没有提供自定义节点，因此不需要提供任何自定义节点映射。                                                                                                                                                                                                                                                                                                           |
| styleOverrides   | 我们没有提供样式覆盖，因此会按照 Microsoft Word 的常见默认规范设置默认 `DOCX` 样式，并将其应用于导出的文档。                                                                                                                                                                                            |

## 服务器端导出

对于需要生成复杂文档或希望减小客户端打包体积的应用，你可以在服务器上导出 `.docx` 文件。

为此，需要从 `@tiptap-pro/extension-export-docx` 包导入 `exportDocx` 函数，将 Tiptap JSON 内容传入该函数，并将转换结果返回给客户端。

先来看看 `exportDocx` 函数的签名：

```ts
/**
 * Export the current document as a .docx file
 *
 * Notes: 'buffer' and 'stream' export types are only available in the server environment
 * as they use the Node Buffer and Stream APIs respectively
 *
 * @param options.document - The JSON representation of the document
 * @param options.exportType - The type of export to perform
 * @param options.customNodes - Custom node definitions
 * @param options.styleOverrides - Style overrides for the exported document
 * @param options.paragraphOverrides - Base defaults for all paragraphs
 * @param options.textRunOverrides - Base defaults for all text runs
 * @param options.tableOverrides - Table-level property overrides
 * @param options.tableRowOverrides - Base defaults for all table rows
 * @param options.tableCellOverrides - Base defaults for all table cells
 * @param options.imageOverrides - Image property overrides
 * @param options.onWarning - Called for each image the export skipped
 * @param options.onImageError - 'skip' (default) or 'throw'
 * @example exportDocx({ document: editor.getJSON(), exportType: 'blob', customNodes: [], styleOverrides: {} })
 */
async function exportDocx({
  document,
  exportType,
  customNodes,
  styleOverrides,
  paragraphOverrides,
  textRunOverrides,
  tableOverrides,
  tableRowOverrides,
  tableCellOverrides,
  imageOverrides,
  onWarning,
  onImageError,
}: ExportDocxOptions) {}
```

`exportDocx` 函数会返回一个已转换为任意格式的 `docx` 文档，供你使用。

下面是在服务器端使用 `Express` 和 `@tiptap-pro/extension-export-docx` 的简单示例：

```ts
import { exportDocx } from '@tiptap-pro/extension-export-docx'
import express from 'express'

const app = express()

app.post('/export-docx', async (req, res) => {
  try {
    // Get Tiptap JSON content from the request or from your database
    const { content } = req.body

    // Convert Tiptap JSON to DOCX
    const docxBuffer = await exportDocx({ document: content })

    // Send as a downloadable file
    res.setHeader(
      'Content-Type',
      'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
    )
    res.setHeader('Content-Disposition', 'attachment; filename="document.docx"')
    res.send(docxBuffer)
  } catch (error) {
    res.status(500).json({ error: error.message })
  }
})
```

## 无法导出的图像

导出时会根据每张图像的 `src` 获取图像。有些图像无法使用：URL 返回 404、主机没有响应，或者图像格式不受 DOCX 支持。Word 会将粘贴的图表和公式写为 EMF，因此从 Word 导入的文档通常会包含这种格式。

默认情况下，导出会跳过无法使用的图像并继续处理，因此一张损坏的图片不会导致整个文件导出失败。如果该图像是段落中的唯一内容，段落也会一并移除，不会留下空行。

传入 `onWarning`，即可了解哪些图像被跳过：

```js
ExportDocx.configure({
  onCompleteExport: result => saveAs(result, 'export.docx'),
  onWarning: warning => {
    console.log(warning.code, warning.src)
  },
})
```

每条警告都包含以下字段：

| Field         | 说明                                                                       |
| ------------- | --------------------------------------------------------------------------------- |
| `code`        | `image-missing-src`、`image-request-failed`、`image-fetch-failed` 或 `image-unsupported-type` |
| `message`     | 易于阅读的摘要，可安全地写入日志                                                     |
| `src`         | 如果节点包含图像 URL，则为该 URL                                              |
| `status`      | 主机返回错误时的 HTTP 状态码                                 |
| `contentType` | 格式不受支持时检测到的类型                                       |

如果没有设置 `onWarning`，被跳过的图像会通过 `console.warn` 报告。`onWarning` 内部抛出的异常会被忽略，因此处理程序中的错误不会导致导出失败。

如需让导出失败，请设置 `onImageError: 'throw'`。抛出的错误可能是 `ImageMissingSrcError`、`ImageRequestError`、`ImageFetchError` 或 `UnsupportedImageTypeError`；这些错误均从包中导出，且都继承自 `ImageConversionError`：

```js
import { ImageConversionError } from '@tiptap-pro/extension-export-docx'

try {
  await exportDocx({ document, onImageError: 'throw' })
} catch (error) {
  if (error instanceof ImageConversionError) {
    console.log(`Could not use ${error.src}: ${error.code}`)
  }
}
```

<Callout title="不会解析相对图像 URL" variant="hint">
  导出时会直接使用存储的 `src`。相对 URL（例如 `/img/chart.png`）没有可用于解析的来源，因此会报告 `image-request-failed` 并跳过。请存储导出器可以访问的绝对 URL。
</Callout>

## 节点属性推断

DOCX 导出会自动遵循编辑器设置的节点级属性，而不是始终从头计算值。这意味着，调整过大小的图像、修改过的表格列以及其他编辑器级自定义设置都会保留在导出的文档中。

| 功能                                   | 说明                                                                                                                                                                                               |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **图像 `width`/`height`**                | 如果在编辑器中调整了图像大小，则使用用户设置的尺寸。优先级：`imageOverrides.transformation` > `node.attrs.width/height` > 固有尺寸                              |
| **图像 `alt` 文本**                      | 映射到 docx 的 `altText` 属性，作为无障碍元数据                                                                                                                                          |
| **表格单元格 `colwidth`**                 | 编辑器调整列宽后，每个单元格的像素数组会生成精确的导出列宽。对于流式表格，各列会保持其比例                                                        |
| **表格单元格 `rowspan`**                  | 跨多行的单元格可以正确导出                                                                                                                                                       |
| **表格 `width`**                         | 显式设置了 `width` 的表格会按固定宽度导出；未设置宽度的表格会按全宽（流式）导出，以适应页面                                                                  |
| **表格边框**                         | 会导出表格自身的边框（外边缘以及内部横向和纵向网格）；无边框表格仍保持无边框                                                                     |
| **表格单元格 `background`**               | 导出为单元格底纹                                                                                                                                                                                 |
| **表格单元格边框**                    | 会导出单元格各边的边框（`width` / `style` / `color`）；与表格边框不同的单元格边框会保留为覆盖                                                                     |
| **表格单元格 `verticalAlign`**            | `top` / `middle` / `bottom` 会导出为单元格垂直对齐方式                                                                                                                                      |
| **表格行 `height` / `heightRule`**     | 会导出行高；`exact` 会按该高度裁切，`atLeast` 会将其视为最小高度                                                                                                                     |
| **表格单元格边距**                    | 表格节点上的 `cellMarginTop` / `cellMarginRight` / `cellMarginBottom` / `cellMarginLeft` 会导出为表格的单元格边距。未设置这些属性的表格会使用 Word 默认值                          |
| **段落 `textAlign: 'justify'`**      | 会正确映射为 `AlignmentType.JUSTIFIED`（此前会回退为左对齐）                                                                                                                 |
| **文本运行 `backgroundColor`**            | `textStyle` 标记中的 `backgroundColor` 会导出为纯色字符底纹                                                                                                                                    |
| **段落/标题 `lineHeight`**        | 比例行高（无单位倍数，如 `1.5`，或百分比，如 `150%`）会写为相对行高，并随字体大小缩放。固定的 `px`/`pt` 行高会写为精确行高                                                 |
| **段落/标题间距**             | `spacingBefore` 和 `spacingAfter` 会写为段前和段后间距                                                                                                                        |
| **段落/标题缩进**         | `indent`、`indentRight` 和 `firstLineIndent` 会分别写为左缩进、右缩进和首行缩进；负的 `firstLineIndent` 会变为悬挂缩进                                              |
| **段落/标题 `contextualSpacing`** | 导出时会取消相邻同样式段落之间的间距                                                                                                                            |
| **段落/标题 `keepNext` / `keepLines`** | 会写为 Word 的“与下段同页”和“段中不分页”分页提示                                                                                                                            |

## 预期效果

- **无需身份验证。** 导出完全在浏览器中运行（或在使用相同包的 Node.js 服务器上运行）。无需令牌，也不会调用 API。
- **同时支持浏览器和服务器端环境**，使用的是同一个包。上方的服务器端示例展示了 Node.js 用法；浏览器端是默认方式。
- **同步返回结果。** `onCompleteExport` 回调会直接接收导出的文件，具体类型取决于 `exportType`，可以是 `Blob`、`Buffer`、`Stream` 或 `string`。

## 不应期待的效果

- **往返后完全一致。** 导入 DOCX、编辑后再导出，并不会得到字节完全相同的文件。目前导入时会提取少数属性（制表位以及固定的 `px`/`pt` 行高），但导出时不会写入。完整列表请参阅[功能支持矩阵](/conversion/getting-started/feature-support-matrix)。
- **与 Word 像素级一致。** 我们致力于在支持的功能范围内实现视觉效果忠实的往返转换；与 Word 渲染引擎绝对一致不在目标范围内。
- **编辑器中的页面布局。** DOCX 导出会保留你在导出选项中配置的页眉、页脚和页面格式设置，但不会根据屏幕上的分页推断页面边界。因此，需要基于分页的导出时，请搭配 [Pages 扩展](/pages/getting-started/overview)使用。
