除非字体**嵌入**文档本身，否则 Word 只能显示读者设备上已安装的字体。`@tiptap-pro/extension-export-docx` 可以嵌入内容中使用的字体，让导出的 `.docx` 在任何地方看起来都一样，即使设备上没有安装这些字体也不例外。

有两种方式可以实现：

- **[手动](#manual-embedding)**：通过 `fonts` 选项提供字体数据。控制全面、无需依赖网络，也可在服务器上使用。
- **[自动](#automatic-embedding)**：设置 `embedFonts: true`，导出时便会自动检测、获取并嵌入文档所用的字体。仅限浏览器。

<Callout title="只嵌入常规字形">
  DOCX 字体嵌入会为每个字体系列嵌入常规（直立、字重 400）字形。Word 会据此合成粗体和斜体，因此无需（也无法通过此 API）嵌入单独的粗体或斜体字体文件。
</Callout>

## 手动嵌入

传入一个 `fonts` 数组，每个字体系列对应一项，其中包含其原始 TTF 或 OTF 字节。字体会以混淆形式写入文档包（根据 OOXML 规范，路径为 `word/fonts/font<N>.odttf`），并关联到所有使用匹配字体系列名称的文本运行。

```ts
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

// In the browser: fetch the font and hand its ArrayBuffer straight to the export.
const data = await fetch('/fonts/PlayfairDisplay-Regular.ttf').then((response) =>
  response.arrayBuffer(),
)

editor
  .chain()
  .exportDocx({
    fonts: [{ name: 'Playfair Display', data }],
  })
  .run()
```

在服务器上，请改为将文件读入 `Buffer`：

```ts
import { readFile } from 'node:fs/promises'
import { exportDocx } from '@tiptap-pro/extension-export-docx'

const data = await readFile('./fonts/PlayfairDisplay-Regular.ttf')

await exportDocx({
  document: editorJSON,
  exportType: 'buffer',
  customNodes: [],
  styleOverrides: {},
  fonts: [{ name: 'Playfair Display', data }],
})
```

### `DocxFontDefinition`

```ts
interface DocxFontDefinition {
  name: string
  data: Buffer | Uint8Array | ArrayBuffer
  characterSet?: DocxFontCharacterSet
}
```

| 字段           | 说明                                                                                                                                                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `name`         | 字体系列名称。**必须与**内容中使用的字体名称完全匹配：`textStyle` 标记的 `fontFamily` 中的第一个字体系列（去除引号，因此 `\'"Playfair Display", serif\'` 会解析为 `Playfair Display`），或通过 `styleOverrides` / `textRunOverrides` 设置的 `font`。如果名称不匹配，系统会静默回退到替代字体。 |
| `data`         | 原始 **TTF 或 OTF** 字节。接受 Node `Buffer`、`Uint8Array` 或 `ArrayBuffer`（因此 `await fetch(url).then((r) => r.arrayBuffer())` 可直接在浏览器中使用）。此处不接受 WOFF/WOFF2 数据；有关 WOFF2 转换，请参阅[自动嵌入](#automatic-embedding)。 |
| `characterSet` | 可选的 Word 字符集代码，会作为 `<w:charset>` 写入字体表。普通拉丁字体可不设置。请使用重新导出的 `CharacterSet` 常量作为值（例如 `CharacterSet.GREEK`）。                                                                                                                                         |

## 自动嵌入

设置 `embedFonts: true` 后，导出过程会自动收集文档引用的所有字体系列、查找各字体文件，并在需要时将其转换为可嵌入的格式后嵌入，无需为每次导出单独处理字体。

```ts
ExportDocx.configure({
  embedFonts: true,
  // token is only used when a font needs WOFF2 → TTF conversion
  token: 'your-jwt',
  region: 'eu', // optional. 'eu' or 'us'
  onCompleteExport: (blob) => {
    /* download blob */
  },
})
```

### 工作原理

1. **检测**：收集 `textStyle` 的 `fontFamily` 标记、[CSS 样式](/conversion/export/docx/css-to-docx)和文本运行级样式覆盖中使用的字体系列。通用关键字（`serif`、`monospace` 等）以及已通过 `fonts` 传入的字体系列会被跳过。
2. **定位**：从页面中可读取的 `@font-face` 规则查找各字体文件，并选取常规字形。如果一个字体系列拆分为多个语言子集（Google Fonts 和许多自托管方案都如此），系统会选择覆盖文档实际字符的子集：拉丁文文档嵌入拉丁字形，西里尔文文档嵌入西里尔字形，依此类推。如果字体系列没有可读取的规则（Google Fonts `<link>` 通常如此，因为 JavaScript 无法读取跨域样式表），则会改用 [Google Fonts](https://fonts.google.com) 查询。
3. **转换**：`TTF`/`OTF` 文件会直接嵌入。`WOFF2` 文件会通过 Convert Service 的 `POST /fonts/convert` 端点转换为 TTF（此步骤需要具有 `Convert:Fonts` 权限的令牌）。
4. **嵌入**：转换后的字体会以与通过手动 `fonts` 选项传入时相同的方式嵌入。同名字体中，手动提供的字体始终优先于自动解析的字体。

### 要求和凭证

- **仅限浏览器。** 自动嵌入会读取 `document.styleSheets`，因此在服务器环境中不会执行任何操作。在服务器端请使用手动 `fonts` 选项。
- **只有转换 WOFF2 时才需要令牌。** 自托管的 `TTF`/`OTF` 字体无需调用 Convert Service 即可嵌入。WOFF2 字体（包括从 Google Fonts 解析出的所有字体）需要具有 `Convert:Fonts` 权限的令牌，才能调用[转换端点](#convert-service-endpoint)。
- 用于提供 WOFF2 → TTF 转换功能的 `endpoint` 必须由 **Convert Service ≥ v2.25.0** 提供支持。

<Callout title="嵌入不会导致导出失败">
  每种字体都会独立解析。如果某种字体无法找到、获取或转换（或者 WOFF2 字体缺少凭证），导出过程会针对该字体系列记录一条 `console.warn`，然后继续。受影响的文本会回退到 Word 的字体替代机制，效果与未嵌入时相同；导出本身始终会成功。
</Callout>

<Callout title="同一字体用于多种文字系统">
  一个 DOCX 文件中的每个字体系列只会嵌入一个文件。如果同一文档中**同一个**字体系列用于多种文字系统的文本（例如拉丁文和西里尔文），系统会嵌入覆盖文本最多的子集，其他文字系统中的文本则会回退到 Word 的字体替代机制。若要让此类字体系列完整覆盖所有字符，请提供一个完整（非子集）字体文件：将其作为单个 `@font-face` 自托管，或通过手动 [`fonts`](#manual-embedding) 选项传入。每个字体系列仅用于一种文字系统时不受影响。
</Callout>

### 选项

| 参数         | 说明                                                                                              | 默认值      |
| ------------ | ------------------------------------------------------------------------------------------------- | ----------- |
| `embedFonts` | 启用自动检测和嵌入。仅限浏览器。                                                                  | `false`     |
| `token`      | Tiptap Convert JWT，以 `Authorization` bearer token 形式发送。仅在需要转换 WOFF2 字体时才必需。   | `undefined` |
| `endpoint`   | 用于 WOFF2 → TTF 转换的 Tiptap Convert REST 端点基址。设置后会覆盖 `region`。                     | `undefined` |
| `region`     | 未设置 `endpoint` 时，用于 WOFF2 → TTF 转换的 Tiptap Cloud 区域；可选值为 `'eu'` 或 `'us'`。      | `'eu'`      |

## 让编辑器与导出结果一致

若要让编辑器预览与嵌入字体后的输出一致，请使用 `@font-face` 规则在页面中加载同一字体（自动嵌入也会读取此规则来定位自托管字体）：

```css
@font-face {
  font-family: 'Playfair Display';
  src: url('/fonts/PlayfairDisplay-Regular.ttf') format('truetype');
  font-weight: 400 900;
  font-style: normal;
  font-display: swap;
}
```

然后使用 `fontFamily` 标记将该字体系列应用于内容；编辑器和导出过程都会根据其清理后的名称关联字体：

```ts
editor.chain().focus().setFontFamily('Playfair Display').run()
```

## Convert Service 端点

自动嵌入中的 WOFF2 转换由 REST 端点提供支持，你也可以直接调用该端点：

`POST {endpoint}/fonts/convert`

- **请求正文：** `multipart/form-data`，包含 `file` 字段（字体二进制数据）以及可选的 `fontFamily` 字段。
- **响应：** 返回可嵌入字体，格式为 `font/ttf`。上传 TTF/OTF 文件时会原样返回；上传 WOFF2 文件时会转换为 TTF。
- **身份验证：** 使用与其他转换端点相同的 `Authorization: Bearer <token>` 标头。令牌需要具有 `Convert:Fonts` 权限。

从 Convert Service v2.25.0 起，Tiptap Cloud 和本地部署均可使用此功能。
