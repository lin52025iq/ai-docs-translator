[基于函数的自定义节点 API](/conversion/export/docx/custom-nodes)允许你编写简短的 JavaScript 函数，将任意 Tiptap 自定义节点渲染为 DOCX。这种方式在编辑器扩展中运行良好，但函数无法通过 HTTP 传输，因此过去的 [DOCX REST API](/conversion/export/docx/rest-api) 完全无法渲染自定义节点。

**`customNodeDsl`** 选项弥补了这一缺口。它是一种轻量、可序列化的 JSON 语言，用于描述自定义节点应如何渲染为 DOCX。同一份 JSON 可用于两种场景：在浏览器中将它传给 `ExportDocx.configure({ customNodeDsl })`，或在 REST 请求体中将它作为 `customNodeDsl` 字段传入。

## 何时使用

| 你的需求……                                                                                              | 使用                                                                       |
| --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 在浏览器中调用 `editor.exportDocx()` 时渲染自定义节点，并充分利用 JavaScript 的灵活性。 | [函数 API](/conversion/export/docx/custom-nodes)（`customNodes`）。 |
| 调用任意导出 REST 端点（docx、pdf、odt、epub、doc）时渲染自定义节点。                                         | **`customNodeDsl`**（本文）。                                          |
| 在浏览器应用和服务器端渲染之间共享同一套自定义节点导出逻辑。                | **`customNodeDsl`**（本文）。                                          |
| 在两种场景中以单一事实来源渲染同一个自定义节点。                                 | **`customNodeDsl`**（本文）。                                          |

编辑器扩展中可以同时使用这两种 API。如果同一种节点类型同时出现在 `customNodes` 和 `customNodeDsl` 中，则以函数定义为准，并且每次导出只会发出一条 `console.warn`。现有基于函数 API 的用户不会看到行为变化。

## 第一个示例

将自定义的 `hintbox` 块节点渲染为 DOCX 中带样式的段落：

```ts
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

ExportDocx.configure({
  customNodeDsl: {
    dslVersion: '1.0',
    nodes: [
      {
        type: 'hintbox',
        nodeKind: 'block',
        render: {
          emit: {
            element: 'Paragraph',
            props: { style: 'Hintbox' },
            children: { $children: { as: 'inline', marks: 'default' } },
          },
        },
      },
    ],
  },
})
```

通过 REST 使用同一份 JSON：

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"hintbox\",\"content\":[{\"type\":\"text\",\"text\":\"hi\"}]}]}",
      "exportType": "blob",
      "customNodeDsl": {
        "dslVersion": "1.0",
        "nodes": [
          {
            "type": "hintbox",
            "nodeKind": "block",
            "render": {
              "emit": {
                "element": "Paragraph",
                "props": { "style": "Hintbox" },
                "children": { "$children": { "as": "inline", "marks": "default" } }
              }
            }
          }
        ]
      }
    }'
```

`Hintbox` 段落样式本身通过 [styleOverrides](/conversion/export/docx/styles) 声明，方式与为函数 API 声明样式完全相同。

## 顶层文档

```jsonc
{
  "dslVersion": "1.0",
  "nodes": [
    /* CustomNodeRule, … */
  ],
}
```

| 字段         | 类型               | 说明                                                                                                                                    |
| ------------ | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `dslVersion` | `"1.0"`            | 必须是精确的字面值。其他值都会导致 `DOCX_DSL_UNKNOWN_VERSION` 错误。                                                       |
| `nodes`      | `CustomNodeRule[]` | 必填。每种 ProseMirror 节点类型对应一条规则。最多 128 条。若 `type` 值重复，则会导致 `DOCX_DSL_DUPLICATE_NODE_TYPE` 错误。 |

以下根级键**为未来版本保留**，目前出现时会报错 `DOCX_DSL_RESERVED_SHAPE`，而不会被静默忽略：`requiresStyles`、`contributedStyles`、`externalRefs`、`limits`。这样可以确保未来启用相关功能时安全无虞：今天可以通过编译的载荷，明天仍会以完全相同的方式通过编译。

---

## CustomNodeRule

单条规则描述一种 ProseMirror 节点类型：

```jsonc
{
  "type": "hintbox",
  "nodeKind": "block",
  "render": {
    /* RenderProgram */
  },
}
```

| 字段       | 类型                            | 默认值   | 说明                                                                                             |
| ---------- | ------------------------------- | -------- | -------------------------------------------------------------------------------------------------- |
| `type`     | `string`                        | 必填     | 此规则匹配的 PM 节点类型（例如 `"hintbox"`、`"mention"`）。                                |
| `nodeKind` | `"block" \| "inline" \| "auto"` | `"auto"` | 源 PM 节点声明的种类。`"auto"` 会让验证器根据规则的 emit 结构推断种类。 |
| `render`   | `RenderProgram \| null`         | 必填     | 要渲染的内容。`null` 会丢弃匹配的 PM 节点及其**所有后代**。                     |

如果要让包装节点不输出任何内容，同时让子节点照常渲染，请使用 `render: { emit: { "$children": { "as": "block" } } }`，而不要使用 `render: null`。

---

## RenderProgram

```jsonc
{
  "emit": /* RenderNode | RenderNode[] | null */
}
```

`RenderProgram` 至少必须声明 `emit`。既没有 `emit`、也没有（保留的）`contribute` 字段的程序会报错 `DOCX_DSL_INVALID_SHAPE`。

`emit: null` 表示此 PM 节点不渲染任何内容，但**不会**丢弃后代节点。若要彻底丢弃后代节点，请在规则本身设置 `render: null`。

---

## RenderNodes

`emit` 下的每个条目（以及 `ElementNode` 的子项）都是一个 `RenderNode`。共有七种结构形式，均通过结构本身区分；传输格式中没有 `kind` 标签：

| 结构                      | 判别方式        | 含义                                                   |
| ------------------------ | --------------- | --------------------------------------------------------- |
| `null`                   | 字面值          | 此处不渲染任何内容。                                      |
| array                    | 原生 JS 数组    | 隐式片段；按顺序渲染每一项。            |
| `{ "element": …, … }`    | `element` 键     | 通过适配器注册表构造 docx.js 元素。         |
| `{ "$children": { … } }` | `$children` 键 | 遍历 PM 节点的子内容并分发每个子节点。 |
| `{ "$text": …, … }`      | `$text` 键     | 便捷地输出单个文本运行。               |
| `{ "$fragment": [ … ] }` | `$fragment` 键 | 显式定义由同级渲染节点组成的片段。                |
| `{ "$if": { … } }`       | `$if` 键       | 结构性条件判断。                                   |
| `{ "$switch": { … } }`   | `$switch` 键   | 结构性多路条件判断。                         |

如果对象混用了两个以 `$` 开头的键（例如 `{ "$text": …, "$children": … }`），就会报错 `DOCX_DSL_INVALID_SHAPE`。只能选择一个。

### ElementNode

最常见的结构用于实例化 docx.js 元素：

```jsonc
{
  "element": "Paragraph",
  "props": { "style": "Hintbox" },
  "children": { "$children": { "as": "inline", "marks": "default" } },
  "applyMarks": "node",
  "inheritOverrides": true,
}
```

| 字段               | 类型                         | 默认值      | 说明                                                                                                                                                |
| ------------------ | ---------------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `element`          | `ElementName`                | 必填        | 可用元素之一（参见[元素目录](#element-catalog)）。                                                                                 |
| `props`            | `Record<string, ValueExpr>`  | `{}`        | 元素属性。每个值都可以是字面值或任意[值表达式](#value-expressions)。未知 prop 键会因不符合元素的 prop 架构而报错。 |
| `children`         | `RenderNode \| RenderNode[]` | `undefined` | 子渲染节点。允许的内容由元素适配器决定（参见[包含关系](#containment)）。                                                      |
| `applyMarks`       | `ApplyMarksPolicy`           | `undefined` | 仅适用于行内元素。将规则自身的 PM 节点 marks 合并到文本运行中。参见 [Marks](#marks-system)。                                               |
| `inheritOverrides` | `boolean`                    | `true`      | 若为 `false`，则仅对此元素跳过全局 `*Overrides` 配置（例如 `paragraphOverrides`）。                                                       |

### `$children`

遍历 `node.content`，并通过标准转换器分发每个子节点：

```jsonc
{ "$children": { "as": "inline", "marks": "default" } }
```

| 字段                    | 类型                                                 | 默认值      | 说明                                                                                                                                                                                  |
| ----------------------- | ---------------------------------------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `as`                    | `"block" \| "inline" \| "table-row" \| "table-cell"` | 必填        | 预期的子节点种类。会根据父元素的 `childKind` 进行验证。不匹配时会报错 `DOCX_DSL_INVALID_CONTEXT`。                                                                  |
| `marks`                 | `MarkPolicy`                                         | `"default"` | 仅当 `as: "inline"` 时有效。如何映射文本子节点上的 marks。参见 [Marks](#marks-system)。                                                                                               |
| `wrapInlineInParagraph` | `boolean`                                            | `false`     | 仅当 `as: "block"` 时有效。为 `true` 时，会将连续的行内子节点缓存在默认 `Paragraph` 中，而不是报错。适用于接收纯行内内容的表格单元格。 |

### `$text`

便捷地输出单个文本运行：

```jsonc
{ "$text": { "$ref": "node.attrs.label" }, "marks": "default", "default": "(unnamed)" }
```

| 字段      | 类型                  | 默认值      | 说明                                                                |
| --------- | --------------------- | ----------- | -------------------------------------------------------------------------- |
| `$text`   | `ValueExpr`           | 必填        | 解析为字符串。非字符串值会通过 `String()` 转换。              |
| `marks`   | `"default" \| "none"` | `"default"` | `"default"` 会运行标准 marks 处理流程；`"none"` 则跳过。            |
| `default` | `string`              | `undefined` | 解析结果为 `""`、`null` 或 `undefined` 时使用的替代字符串。 |

`{ "$text": e }` 且 `marks: "default"`，等效于应用标准 marks 处理流程的 `{ "element": "TextRun", "props": { "text": e } }`，但写法更简洁。

### `$fragment`

显式定义由同级渲染节点组成的片段。直接使用数组也能达到相同效果：

```jsonc
{ "$fragment": [ /* RenderNode, … */ ] }
// 或等效地：
[ /* RenderNode, … */ ]
```

### `$if`

结构性条件判断：

```jsonc
{
  "$if": {
    "test": { "$ref": "node.attrs.featured" },
    "then": { "element": "Paragraph", "props": { "style": "Featured" } },
    "else": null,
  },
}
```

| 字段   | 类型         | 默认值 | 说明                                                                                    |
| ------ | ------------ | -------- | ---------------------------------------------------------------------------------------------- |
| `test` | `ValueExpr`  | 必填 | 转换为布尔值。`false`、`null`、`undefined`、`0`、`""` 为假；其他值均为真。 |
| `then` | `RenderNode` | 必填 | `test` 为真时渲染的分支。                                                         |
| `else` | `RenderNode` | `null`   | `test` 为假时渲染的分支。                                                          |

### `$switch`

多路条件判断。查找时会与 `cases` 键进行精确匹配；不支持正则表达式或 glob 匹配：

```jsonc
{
  "$switch": {
    "on": { "$ref": "node.attrs.variant" },
    "cases": {
      "warning": { "element": "Paragraph", "props": { "style": "CalloutWarning" } },
      "info": { "element": "Paragraph", "props": { "style": "CalloutInfo" } },
    },
    "default": { "element": "Paragraph", "props": { "style": "Callout" } },
  },
}
```

运行时 `on` 必须解析为字符串；非字符串会报错 `DOCX_DSL_RUNTIME_TYPE_MISMATCH`。`default` 是没有匹配项时使用的回退值；若省略，则默认为 `null`（不渲染）。

`$switch` **也可用作值表达式**。参见[值形式的 `$switch`](#value-form-switch)。

## 元素目录

DSL 内置了一组封闭的受支持元素。添加新元素属于版本变更。未知名称会报错 `DOCX_DSL_UNKNOWN_ELEMENT`。

| 元素                | 种类         | 允许用于          | 子项种类                | 备注                                                                                                                                                    |
| ------------------- | ------------ | --------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Paragraph`         | `block`      | document, block | `inline`                | 标准文本块。                                                                                                                                     |
| `TextRun`           | `inline`     | inline          | （叶节点）              | 标准文本运行。                                                                                                                                       |
| `ExternalHyperlink` | `inline`     | inline          | `inline`（仅限 TextRun） | 将一个或多个 `TextRun` 包装为超链接。                                                                                                             |
| `Table`             | `block`      | document, block | `table-row`             | 子项会填入 `rows`，而非 `children`。                                                                                                                |
| `TableRow`          | `table-row`  | table-row       | `table-cell`            | 表格的一行。                                                                                                                                      |
| `TableCell`         | `table-cell` | table-cell      | `block`                 | 表格的一格；包含块级内容。                                                                                                               |
| `PageBreak`         | `block`      | document, block | （叶节点）              | 输出一个包含 docx 分页符运行的段落。若要在段落内添加行内分页符，请使用 `{ "element": "TextRun", "props": { "break": 1 } }`。 |

`ImageRun` **不属于 v1**。图像数据只能通过内置的 `image` PM 节点流入：你的 DSL 规则可以使用 `$children` 将其子项传递进去，但 DSL 本身不会生成图像字节。这是 REST 场景下的一项安全保证。

### 包含关系

验证器会在编译时拒绝所有非法的父子组合，并提供出错节点的准确 `dslPath`。

| 父级槽位 ↓ \ 子级种类 → | block |               inline                | table-row | table-cell |
| ---------------------------- | :---: | :---------------------------------: | :-------: | :--------: |
| 文档主体                |   ✓   |                                     |           |            |
| `Paragraph.children`         |       |                  ✓                  |           |            |
| `ExternalHyperlink.children` |       |          ✓（仅限 TextRun）           |           |            |
| `Table.rows`                 |       |                                     |     ✓     |            |
| `TableRow.children`          |       |                                     |           |     ✓      |
| `TableCell.children`         |   ✓   |（仅限启用 `wrapInlineInParagraph`） |           |            |

不匹配示例：

```jsonc
{
  "error": "Element \"Paragraph\" cannot appear in \"inline\" slot.",
  "code": "DOCX_DSL_INVALID_CONTEXT",
  "dslPath": "nodes[1].render.emit.children[0]",
}
```

### 元素属性

每个元素的 `props` 都会根据严格的架构进行验证。未知键会报错 `DOCX_DSL_INVALID_PROP`。

#### Paragraph

```jsonc
{
  "style": "Hintbox",
  "alignment": "left" | "center" | "right" | "justified" | "justify" | "both",
  "heading": "heading1" | "heading2" | "heading3" | "heading4" | "heading5" | "heading6",
  "spacing":  { "before": 120, "after": 120, "line": 240, "lineRule": "auto" | "exact" | "atLeast" },
  "numbering":{ "reference": "bullet-list" | "ordered-list", "level": 0, "instance": 1 },
  "indent":   { "left": 360, "right": 0, "firstLine": 360, "hanging": 0 },
  "pageBreakBefore": false
}
```

Spacing 和 indent 的单位是 **twip**（1 twip = 1/20 点）。如果想用更直观的单位表示，可以使用 `$unit` 辅助函数（`pointsToTwips`、`inchesToTwips` 等）。

#### TextRun

```jsonc
{
  "text": "hello",
  "bold": true,
  "italics": true,
  "underline": true,
  "underline": { "type": "single" | "double" | "thick" | "dotted" | "dash" | "wave", "color": "4F46E5" },
  "strike": true,
  "doubleStrike": true,
  "superScript": true,
  "subScript": true,
  "size": 24,
  "color": "1F2937",
  "font": "Inter",
  "highlight": "yellow",
  "shading": { "type": "solid" | "clear", "fill": "F3F4F6", "color": "1F2937" },
  "break": 1,
  "style": "InlineCode"
}
```

`size` 的单位是 **半点**（因此 12pt 的文本运行对应 `size: 24`）。`color`、shading 的 `fill` 和 `color`，以及 underline 的 `color`，都必须是**不带 `#` 的 6 位十六进制字符串**（如果数据带有 `#` 前缀，请使用 `hexNoHash` 转换或 `normalizeColor` 单位）。

#### ExternalHyperlink

```jsonc
{ "link": "https://tiptap.dev" }
```

`link` 为必填值，且必须以 `http`、`https`、`mailto` 或 `tel` 之一开头。其他协议会在编译时被拒绝。链接长度上限为 2048 个字符。

`ExternalHyperlink` 至少需要一个 `TextRun` 子项；空超链接会在运行时因 `DOCX_DSL_INVALID_CONTEXT` 而被拒绝。

#### Table

```jsonc
{
  "width":   { "size": 100, "type": "pct" | "auto" | "dxa" | "nil" },
  "layout":  "fixed" | "autofit",
  "columnWidths": [2400, 2400, 2400],
  "margins": { "top": 100, "bottom": 100, "left": 120, "right": 120 },
  "borders": {
    "top":              { "style": "single", "size": 4, "color": "B8D8FF" },
    "bottom":           { "style": "single", "size": 4, "color": "B8D8FF" },
    "left":             { "style": "single", "size": 4, "color": "B8D8FF" },
    "right":            { "style": "single", "size": 4, "color": "B8D8FF" },
    "insideHorizontal": { "style": "single", "size": 4, "color": "B8D8FF" },
    "insideVertical":   { "style": "single", "size": 4, "color": "B8D8FF" }
  }
}
```

`Table` 的子项会填入 docx.js 的 `rows` 参数，因此无需自行编写 `rows`。表格至少需要一行（空表格会在运行时被拒绝）。

#### TableRow

```jsonc
{
  "tableHeader": false,
  "cantSplit":   false,
  "height":      { "value": 480, "rule": "auto" | "exact" | "atLeast" }
}
```

每行至少需要一个单元格。

#### TableCell

```jsonc
{
  "width":         { "size": 50, "type": "pct" | "auto" | "dxa" | "nil" },
  "columnSpan":    1,
  "rowSpan":       1,
  "shading":       { "type": "solid" | "clear", "fill": "FFF1CC", "color": "1F2937" },
  "borders":       { "top": …, "bottom": …, "left": …, "right": … },
  "margins":       { "top": 100, "bottom": 100, "left": 120, "right": 120 },
  "verticalAlign": "top" | "center" | "bottom"
}
```

#### PageBreak

```jsonc
{}
```

`PageBreak` 不接受任何 props。它会输出一个块级段落，其中包含 docx 分页符运行。

## 值表达式

凡是可以接受 prop 值（或 `$text` 值、`$if.test`、`$switch.on` 等）的地方，都可以传入字面值，**或**以下类型化值表达式之一。不是表达式的值（字符串、数字、布尔值、`null`、数组、普通对象）会原样传递。普通对象会递归遍历，因此 `spacing` 等嵌套结构的任意叶节点都可以包含表达式。

表达式语言**刻意保持精简**。它不提供字符串拼接运算符（请使用 `$template`）、数组索引（请使用精确的属性路径）、`eval` 或通用计算功能。以下五种基本表达式足以满足实际自定义节点渲染器的需求。

### `$ref`：读取 PM 节点属性

```jsonc
{
  "$ref": "node.attrs.color",
  "default": "4F46E5",
  "transform": "hexNoHash",
}
```

| 字段        | 类型                               | 默认值      | 说明                                                                                             |
| ----------- | ---------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------ |
| `$ref`      | `string`                           | 必填        | 点分隔路径。仅允许标识符片段（`/^[a-zA-Z_][a-zA-Z0-9_]*$/`）；不允许数组索引或通配符。 |
| `default`   | `ValueExpr`                        | `undefined` | 路径解析为 `null` 或 `undefined` 时使用的替代值。                                            |
| `transform` | `TransformName \| TransformName[]` | `undefined` | 解析后应用的一个或多个白名单后处理器。                                      |

允许的路径：

| 路径               | 返回值                                                                                        |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| `node`             | 整个 PM 节点对象。                                                                      |
| `node.type`        | PM 节点类型名称。                                                                         |
| `node.attrs`       | 整个 attrs 对象。                                                                        |
| `node.attrs.<key>` | 指定属性（仅支持一层，因此 v1 不允许 `node.attrs.style.color`）。 |
| `node.text`        | PM 节点的 `text` 字段（仅对文本节点有意义）。                                   |
| `node.textContent` | 所有后代文本节点的拼接结果，等同于 ProseMirror 的 `node.textContent`。   |

其他路径会被拒绝：

- `node.content`、`node.marks` → `DOCX_DSL_INVALID_REF`（v1 没有遍历模型）。
- `loop.*`、`$parent`、`$siblings`、`$depth`、`$root` → `DOCX_DSL_RESERVED_SHAPE`（为未来版本保留）。
- 路径中任何位置出现 `__proto__`、`prototype`、`constructor` 片段 → `DOCX_DSL_INVALID_REF`（防止原型污染）。
- 解析结果为函数 → `DOCX_DSL_INVALID_REF`。

### `$template`：字符串插值

```jsonc
{ "$template": "@{node.attrs.label}" }
```

始终返回字符串。替换使用 `{path}`（路径语法与 `$ref` 相同）。`{{` 和 `}}` 用于转义字面花括号。解析后的长度不得超过 `maxTemplateLength`（默认值为 2000）；超出限制时会在运行时报错 `DOCX_DSL_RESOURCE_LIMIT`。

### `$op`：类型化计算

```jsonc
{ "$op": "mul", "args": [{ "$ref": "node.attrs.size" }, 2] }
```

| 运算符                             | 参数个数       | 说明                                                            |
| ---------------------------------- | -------------- | ---------------------------------------------------------------- |
| `add`、`mul`                       | ≥ 2（可变参数） | 数值运算。混用类型会报错。                                   |
| `sub`、`div`                       | 必须为 2 个      | 数值运算。                                                         |
| `eq`、`ne`、`lt`、`le`、`gt`、`ge` | 必须为 2 个      | 两侧必须是相同的基本类型（数字或字符串）。 |
| `and`、`or`                        | ≥ 2            | 根据真值进行短路求值。                                  |
| `not`                              | 必须为 1 个      | 布尔运算。                                                         |
| `coalesce`                         | ≥ 2            | 返回第一个非 `null`、非 `undefined` 的参数。          |

没有 `concat` 运算符；字符串请使用 `$template`。也不会进行隐式数值转换，因此 `{ "$op": "add", "args": ["3", 1] }` 会报错 `DOCX_DSL_RUNTIME_TYPE_MISMATCH`。

### `$unit`：单位／类型转换辅助函数

```jsonc
{ "$unit": "pointsToTwips", "value": 12 }
```

调用固定列表中的辅助函数。结果类型与对应辅助函数的签名一致。

| 单位                      | 输入                                  | 输出                                   |
| ------------------------- | ------------------------------------- | ---------------------------------------- |
| `pixelsToHalfPoints`      | number（px）                          | number（半点）                     |
| `pixelsToPoints`          | number（px）                          | number（点）                          |
| `pointsToHalfPoints`      | number（pt）                          | number（半点）                     |
| `pointsToTwips`           | number（pt）                          | number（twip）                           |
| `lineHeightToDocx`        | number（倍数）                        | number（docx 行距值）                 |
| `universalMeasureToTwips` | 字符串 `"1.5cm"`／`"10pt"`／… 或 number | number（twip）                           |
| `normalizeColor`          | string（任意 CSS 颜色）               | 不带 `#` 的 6 位十六进制字符串，或 `null` |
| `inchesToTwips`           | number（in）                          | number（twip）                           |
| `cmToTwips`               | number（cm）                          | number（twip）                           |
| `mmToTwips`               | number（mm）                          | number（twip）                           |

这些辅助函数与基于函数的 `customNodes` API 使用的函数相同。DSL 作者也可以使用它们，以确保传输格式与编辑器扩展的运行时语义完全一致。

### 值形式的 `$switch`

`$switch` **也可以用作值表达式**，适用于根据属性选择 prop 值：

```jsonc
{
  "color": {
    "$switch": {
      "on": { "$ref": "node.attrs.variant" },
      "cases": { "warning": "F59E0B", "info": "0EA5E9" },
      "default": "1F2937",
    },
  },
}
```

验证器会根据外围上下文判断采用值形式还是结构性渲染树形式。在 `props` 中，它是值表达式；在 `RenderNode` 槽位中，它采用结构形式。

### 转换

在 `$ref` 解析后应用（如果路径不存在，则应用于 `default`）：

| 转换                     | 行为                                                                                              |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| `hexNoHash`              | 去除开头的 `#`；剩余内容必须匹配 `/^[0-9A-Fa-f]{6}$/`。非字符串或无效十六进制值会被拒绝。 |
| `lower`、`upper`、`trim` | 标准字符串操作。非字符串值会被拒绝。                                                              |
| `parseIntStrict`         | `parseInt(value, 10)`；结果为 `NaN` 时拒绝。                                                                 |
| `parseFloatStrict`       | `parseFloat(value)`；结果为 `NaN` 时拒绝。                                                                   |
| `boolean`                | 严格模式：接受 `true`／`false`、`"true"`／`"false"`（不区分大小写）。其他值均拒绝。       |
| `nullableString`         | 空字符串或仅含空白字符的字符串 → `null`；否则返回去除首尾空白的字符串。                                           |

`hexNoHash` **不是** CSS 颜色标准化器（无法识别 `rgb()`、命名颜色、`#abc` 简写等）。如果需要这些功能，请使用 `{ "$unit": "normalizeColor", "value": … }`。

### 真值规则

适用于 `$if.test` 以及布尔运算符 `and`／`or`／`not`／`coalesce`：

| 假值                                    | 真值          |
| --------------------------------------- | --------------- |
| `false`、`null`、`undefined`、`0`、`""` | 其他所有值 |

除上述明确规则外，不会进行隐式类型转换。

## Marks 系统

Marks（`bold`、`italic`、`underline`、`strike`、`code`、`subscript`、`superscript`、`textStyle`、`highlight`、`link`）是 DOCX 文本运行级格式的重要来源。DSL 提供两个 marks 钩子：

1. `$children` 和 `$text` 上的 **`MarkPolicy`** 控制标准处理流程如何映射**文本子节点**上的 marks。
2. 行内元素（`TextRun`、`ExternalHyperlink`）上的 **`applyMarks`** 控制如何将**规则自身** PM 节点上的 marks 合并到输出的文本运行中。

### `MarkPolicy`（用于 `$children`／`$text`）

```jsonc
"marks": "default"           // 标准 Tiptap mark 映射（默认）
"marks": "none"              // 忽略所有 marks
"marks": "node"              // 使用规则自身 PM 节点的 marks，而非每个子节点的 marks
"marks": {
  "mode": "default" | "node",
  "overrides": {
    "bold":   { "props": { "color": "DC2626" }, "replace": false },
    "italic": { "replace": true }
  },
  "disable": ["highlight"]
}
```

| 字段                        | 默认值                    | 说明                                                                                               |
| --------------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------- |
| `mode`                      | 必填（对象形式） | `"default"` 运行标准 marks 处理流程；`"node"` 则针对规则自身 PM 节点的 marks 运行。       |
| `overrides[<mark>].props`   | `{}`                      | 存在此 mark 时应用的额外 `TextRun` props。                                                 |
| `overrides[<mark>].replace` | `false`                   | 为 `true` 时，停用此 mark 的标准映射，仅应用覆盖项 `props`。             |
| `disable`                   | `[]`                      | 完全跳过的 marks。不会运行其标准映射，也会忽略任何匹配的 `overrides` 条目。                   |

`$children: { as: "inline" }` 和 `$text` 默认使用 `MarkPolicy: "default"`：也就是普通文本运行所采用的相同标准处理流程。

### `applyMarks`（用于行内元素）

`applyMarks` 与 `MarkPolicy` 不同：它始终使用**规则自身** PM 节点上的 marks（即自定义节点本身的 marks），而不是子节点的 marks。因此唯一有效的 `mode` 是 `"node"`：

```jsonc
"applyMarks": "node"
"applyMarks": {
  "mode": "node",
  "overrides": { "underline": { "props": { "color": "EA580C" } } },
  "disable": ["highlight"]
}
```

`'default'` 和 `'none'` 在 `applyMarks` 中会被有意拒绝；它们只对子节点 marks 有意义。

省略 `applyMarks` 时，会**忽略**规则 PM 节点上的 marks。大多数带有显式样式的行内自定义节点都适合使用此默认设置：自行设置颜色和字体，并让外层 marks 不再生效。

### 覆盖优先级

如果多个层级要设置同一属性，则以下有序列表中靠后的设置优先：

```
1. docx 基础默认值
2. 根据 cssStyles 推导的样式               （实验性的 cssStyles 选项）
3. styleOverrides                         （命名 DOCX 样式）
4. 全局 *Overrides 选项              （paragraphOverrides、textRunOverrides 等）
5. Tiptap 内置节点／mark 映射      （标准处理流程）
6. DSL 子节点处理流程的 mark 覆盖      （MarkPolicy.overrides[<mark>]）
7. 行内元素上的 DSL applyMarks props
8. 显式 DSL 元素 props
```

在 `ElementNode` 上设置 `inheritOverrides: false`，可仅对此元素跳过第 4 层。例如，可以让某个提示框段落不采用 `paragraphOverrides`，而不影响其他段落。

嵌套对象（`spacing`、`borders`、`shading`）会在每一层**整体替换**，不会深度合并。如果设置 `spacing: { before: 120 }`，而底层的 `paragraphOverrides` 包含 `spacing: { line: 240 }`，最终结果只有 `{ before: 120 }`。这与现有扩展选项的约定一致。

### Hintbox（块级、自定义样式、标准子节点）

```jsonc
{
  "type": "hintbox",
```

### Mention（行内、模板文本、继承 marks）

```jsonc

  "type": "mention",
  "nodeKind": "inline",
  "render": {
    "emit": {
      "element": "TextRun",

        "text": { "$template": "@{node.attrs.label}" },
```

粗体 mention 会渲染为 `new TextRun({ text: '@alice', color: '4472C4', bold: true })`。

## 与函数 API 的冲突策略

编辑器扩展同时配置 `customNodes` 和 `customNodeDsl` 时：

| 场景                                               | 结果                                                                            |
| ------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 两者中存在相同的 `type`                               | 函数优先。每次导出时，针对每种冲突类型发出一条 `console.warn`。 |
| 类型只存在于 `customNodes`                        | 由函数渲染。                                                                  |
| 类型只存在于 `customNodeDsl.nodes`                | 由 DSL 渲染。                                                                       |
| 两者都不存在该类型                                   | 保持现有的 “Custom node not found” 行为；节点会被丢弃，并在控制台输出错误。  |
| `customNodeDsl.nodes` **内部**存在重复 `type` | 编译错误：`DOCX_DSL_DUPLICATE_NODE_TYPE`。                                     |

约定如下：不了解 DSL 的用户升级 package 版本时，无需修改代码，输出也会完全相同。添加 `customNodeDsl` 只会**增加**规则，绝不会覆盖现有的基于函数的自定义节点。

REST 场景完全不接受函数 API，只接受 `customNodeDsl`。

## 资源限制

公共 REST 场景中的 DSL 是不可信的 JSON。编译时和运行时都会强制执行资源上限。正常的自定义节点程序不应触及这些限制。

| 限制                  | 默认值 | 说明                                                                           |
| --------------------- | ------- | ------------------------------------------------------------------------------------- |
| `maxRules`            | 128     | 单个 DSL 文档中节点规则的最大数量。                                |
| `maxRenderDepth`      | 32      | 渲染树编译和运行时遍历过程中的最大递归深度。             |
| `maxRenderNodes`      | 1024    | 单个程序中编译后的渲染节点最大数量。                               |
| `maxValueDepth`       | 16      | 值表达式内部的最大递归深度（`$ref` 默认值、`$op` 参数等）。 |
| `maxStringLength`     | 10 000  | 求值后字符串 prop 的最大长度。                                     |
| `maxTemplateLength`   | 2 000   | 替换后 `$template` 结果的最大长度。                            |
| `maxOpArgs`           | 32      | 任意单个 `$op` 的最大参数数量。                                          |
| `maxTableRows`        | 1 024   | `Table` 可输出的 `TableRow` 子项最大数量。                             |
| `maxTableCellsPerRow` | 64      | 单个 `TableRow` 可输出的 `TableCell` 子项最大数量。                  |

### 在编辑器扩展中调整限制

将 `customNodeDslLimits?: Partial<CustomNodeDslLimits>` 与 `customNodeDsl` 一同传入：

```ts
ExportDocx.configure({
  customNodeDsl,
  customNodeDslLimits: {
    maxRules: 256,
    maxRenderDepth: 48,
  },
})
```

传输格式本身**没有** `limits` 字段。若出现保留的根级键 `limits`，会报错 `DOCX_DSL_RESERVED_SHAPE`，防止客户端载荷绕过服务器管理员设置的限制。

## 错误

每个错误都包含稳定的 `code`，以及指向出错 JSON 的 `dslPath`。运行时错误还会包含 `nodePath`（指向 PM 文档中的路径）和 `nodeType`。

```jsonc
{
  "error": "Expected TextRun.size to be number, got string.",
  "code": "DOCX_DSL_INVALID_PROP",
  "dslPath": "nodes[2].render.emit.props.size",
  "nodePath": "doc.content[4].content[2]",
  "nodeType": "mention",
}
```

### 错误代码

| 代码                             | 触发条件                                                                                                                         |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `DOCX_DSL_UNKNOWN_VERSION`       | 存在 `dslVersion`，但其值不是 `"1.0"`。                                                                                     |
| `DOCX_DSL_INVALID_SHAPE`         | JSON 不符合预期结构（缺少必填字段或类型错误）。                                             |
| `DOCX_DSL_DUPLICATE_NODE_TYPE`   | `nodes` 中有两条规则声明了相同的 `type`。                                                                                |
| `DOCX_DSL_UNKNOWN_ELEMENT`       | `element` 不在 v1 目录中。                                                                                          |
| `DOCX_DSL_UNKNOWN_OPERATION`     | `$op` 不在封闭列表中。                                                                                             |
| `DOCX_DSL_RESERVED_SHAPE`        | 载荷中出现了为未来版本保留的键。                                                                  |
| `DOCX_DSL_INVALID_PROP`          | 元素 prop 不符合其架构（未知键或类型错误）。                                                                  |
| `DOCX_DSL_INVALID_ENUM`          | 枚举 prop 收到的值不在封闭列表中。                                                                       |
| `DOCX_DSL_INVALID_REF`           | `$ref` 路径格式错误、指向允许根节点之外，或包含禁止的片段。                                     |
| `DOCX_DSL_INVALID_TEMPLATE`      | `$template` 格式错误（例如花括号不匹配）。                                                                              |
| `DOCX_DSL_INVALID_UNIT`          | `$unit` 名称不在封闭列表中。                                                                                      |
| `DOCX_DSL_INVALID_TRANSFORM`     | `transform` 名称不在封闭列表中。                                                                                  |
| `DOCX_DSL_INVALID_CONTEXT`       | 渲染节点所在槽位不允许其元素种类（包含关系违规）。                                        |
| `DOCX_DSL_INVALID_OP_ARITY`      | `$op` 收到的参数数量不正确。                                                                           |
| `DOCX_DSL_RUNTIME_TYPE_MISMATCH` | 值表达式结果在运行时不符合预期类型（例如 `$switch.on` 解析为数字）。                |
| `DOCX_DSL_RESOURCE_LIMIT`        | 超出可配置的限制（深度、节点数、字符串长度等）。                                                       |
| `DOCX_DSL_RENDER_FAILED`         | 适配器的 `instantiate` 步骤抛出异常；通常表示与 docx.js 不兼容，并会提供出错的 `dslPath`。 |

### HTTP 状态码映射（REST）

| 类别                                     | 状态码                                             |
| ---------------------------------------- | -------------------------------------------------- |
| 编译错误（由验证器捕获） | `400`                                              |
| 运行时错误（渲染期间捕获）  | `422`                                              |
| 编译时超出资源限制        | `400`                                              |
| 运行时超出资源限制        | `422`                                              |
| docx.js 本身发生故障（少见）              | `422`（现有的 `FAILED_TO_EXPORT_DOCX_FILE` 路径） |

### 行为矩阵（REST）

| 场景                                                           | HTTP  | 响应体代码                  |
| --------------------------------------------------------------- | ----- | -------------------------- |
| 未提供 `customNodeDsl` 字段                                        | `200` | DOCX 响应不变    |
| `customNodeDsl` 有效，所有规则均成功渲染                         | `200` | DOCX                       |
| 缺少 `dslVersion`                                            | `400` | `DOCX_DSL_INVALID_SHAPE`   |
| `dslVersion` 错误                                              | `400` | `DOCX_DSL_UNKNOWN_VERSION` |
| `customNodeDsl.nodes` 超出 `maxRules`                        | `400` | `DOCX_DSL_RESOURCE_LIMIT`  |
| 出现保留的根级键（`requiresStyles` 等）                      | `400` | `DOCX_DSL_RESERVED_SHAPE`  |
| 包含关系无效                                             | `400` | `DOCX_DSL_INVALID_CONTEXT` |
| 元素名称未知                                            | `400` | `DOCX_DSL_UNKNOWN_ELEMENT` |
| `$ref` 路径无效                                             | `400` | `DOCX_DSL_INVALID_REF`     |
| 必需属性解析为 `undefined`，导致 prop 架构验证失败 | `422` | `DOCX_DSL_INVALID_PROP`    |
| 运行时超出深度限制                                   | `422` | `DOCX_DSL_RESOURCE_LIMIT`  |

DSL 采用**快速失败**策略：任何错误都会中止导出，不生成部分结果。静默生成不完整的输出会产生无效 DOCX，比明确报错更难排查。

## 安全模型

REST 场景接受经过身份验证的客户端提交的任意 `customNodeDsl`。DSL 的设计确保任何有效输入组合都无法访问 docx.js 内部、宿主文件系统或网络。

| 威胁                                                                      | 缓解措施                                                                                                              |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 任意代码执行                                                   | 不使用 `eval`、`Function` 或动态导入。适配器／运算符／单位／转换器均采用封闭白名单。                        |
| 访问 PM 节点之外的属性                                            | `$ref` 解析器只遍历 `node.*`；不支持数组索引或原型遍历。                                              |
| 通过 `__proto__`／`prototype`／`constructor` 片段进行原型污染 | 路径片段保护机制会以 `DOCX_DSL_INVALID_REF` 拒绝这些路径。                                                            |
| 通过深层嵌套导致 OOM                                                       | 编译时以及每次递归调用时都会强制执行 `maxRenderDepth: 32`。                                                        |
| 通过大型载荷导致 OOM                                                     | 限制 `maxRules`、`maxRenderNodes`、`maxStringLength`、`maxTemplateLength`。                                              |
| 通过表格导致 OOM                                                             | 限制 `maxTableRows: 1024`、`maxTableCellsPerRow: 64`。                                                                        |
| `$template` 解析导致二次方级耗时                                   | 限制解析结果长度 `maxTemplateLength`；运算符参数列表限制为 `maxOpArgs: 32`。                                       |
| DOCX 输出格式错误                                                      | 每个元素的 Zod prop 架构会在编译时捕获大多数问题；传给 docx.js 构造函数前还会检查运行时值的类型。 |
| 未授权的媒体获取                                                 | DSL 没有 `ImageRun.data` 字段；图像数据只能通过内置的 `image` PM 节点传入。                       |
| 恶意 URL                                                             | `ExternalHyperlink.link` 仅允许 `http`、`https`、`mailto`、`tel`。                                            |

## REST API 补充说明

每个导出 REST 端点（`/export/docx`、`/export/pdf`、`/export/odt`、`/export/epub`、`/export/doc`）都接受 DSL。它与现有的 `styleOverrides`、`pageSize`、`pageMargins`、`headers` 和 `footers` 字段同级。有关请求头、响应结构以及其余请求体架构，请参阅 [REST API 参考](/conversion/export/docx/rest-api)。

| 请求体字段      | 类型                                              | 默认值      | 说明               |
| --------------- | ------------------------------------------------- | ----------- | ------------------------- |
| `customNodeDsl` | `Object`（[`CustomNodeDsl`](#top-level-document)） | `undefined` | 自定义节点渲染规则。 |

如果请求采用 `multipart/form-data`（该端点的表单形式），则 `customNodeDsl` 会作为**经过 JSON 序列化的值**放在同名表单字段中，与 `styleOverrides` 完全相同。服务会解析该值，并将结果转发到导出流程。

## 本文刻意不涵盖的内容

以下是**明确的边界**，并非缺陷：

- **遍历数组属性。** v1 中没有 `$each`。该结构已保留（`DOCX_DSL_RESERVED_SHAPE`），以便将来添加时不破坏当前可编译的载荷。在此之前，可以在父级（块节点）中输出变长集合，并使用 `$children` 分发集合项。
- **跨规则读取属性。** 子规则无法读取其父规则的 PM 节点。可通过父规则上的 `$children: { as: "inline", marks: "node" }` 传递父级 marks 给子文本运行，作为变通方式。
- **自由形式表达式。** DSL 并非图灵完备，也不嵌入 Jexl、JSONata 或 `eval`。所有操作均为类型化操作，并受到限制。
- **生成图像数据。** 图像字节不会来自 DSL，而是来自内置的 `image` PM 节点。
- **文档级样式贡献。** DSL 描述的是_节点_如何渲染。命名样式仍通过 [`styleOverrides`](/conversion/export/docx/styles) 定义。保留的根级键 `requiresStyles` 和 `contributedStyles` 为未来功能预留了接口。
- **在不同版本之间修改 `dslVersion` 载荷。** `dslVersion: "1.0"` 是精确的字面值。未来的次版本会以增量方式添加（新增可选字段、新操作），并继续接受不作修改的 v1.0 载荷。主版本升级则需要显式迁移。
