DSL 构建器是编写[自定义节点 DSL](/conversion/export/docx/custom-nodes-dsl)时更符合 **TypeScript 使用习惯**的方式。它是一个小巧、流畅且不可变的 API，编译后生成线缆格式所需的**相同 JSON**：每个链式方法都会返回一个新的构建器，任意链上的 `.toJSON()` 都会生成 DSL 编译器可接受的字面载荷。

你将获得：

- **自动补全所有元素属性。** `paragraph({ … })` 会提示 `style`、`alignment`、`spacing`、`border`、`shading` 等属性，这些正是 DSL 编译器会验证的字段。不必再从文档中猜测属性名。
- **编译时容器安全检查。** `paragraph().children(childrenBlock())` 会产生 TypeScript 错误：段落只接受行内子项。`table().rows(paragraph())` 也会报错：`Table.rows` 要求 `TableRow` 构建器。这些错误会在编辑时而非运行时出现。
- **必需属性检查。** `externalHyperlink({})` 会产生 TypeScript 错误：线缆格式要求提供 `link` 属性，构建器类型会强制执行这一要求。
- **兼容线缆格式。** 输出与手写 JSON 完全相同。同一载荷可用于编辑器、Node.js 服务器，也可作为 [Conversion REST API](/conversion/export/docx/rest-api) 中的 `customNodeDsl` 字段。

## 安装与导入

构建器通过子路径导入提供，与 DOCX 导出流程的其余部分位于同一个程序包中：

```bash
npm i @tiptap-pro/extension-export-docx@^0.18.0
```

```ts
// 主入口：运行时导出器和可配置扩展。
import { ExportDocx, exportDocx } from '@tiptap-pro/extension-export-docx'

// 构建器子路径：支持 tree-shaking。完全不用 DSL 的用户
// 无需承担它带来的开销。
import {
  docxNode,
  paragraph,
  textRun,
  externalHyperlink,
  table,
  tableRow,
  tableCell,
  pageBreak,
  childrenInline,
  childrenBlock,
  childrenTableRow,
  childrenTableCell,
  iff,
  switch_,
  fragment,
  textOp,
  ref,
  template,
  op,
  unit,
  switchValue,
  marks,
} from '@tiptap-pro/extension-export-docx/dsl'
```

此子路径别名适用于 **Vite、Next.js、Webpack 5+、esbuild、Rollup 以及所有现代打包器**。较旧的工具链可能需要显式支持 `exports` 字段的解析器。

## 何时使用构建器

| 使用场景                                                                     | 选择                                                                                                      |
| ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 使用 TypeScript 编写 DOCX 规则，并需要自动补全和重构支持。                    | **构建器。**                                                                                             |
| 将 DSL 作为 JSON 请求体发送到 `POST /v2/convert/export/docx`。                | [JSON DSL](/conversion/export/docx/custom-nodes-dsl)：直接从 JSON 文件传入 `customNodeDsl`。             |
| 在编辑器扩展中需要完整的 JavaScript（闭包、IO 等）。                          | 基于函数的[自定义节点 API](/conversion/export/docx/custom-nodes)。                                         |
| 从配置服务动态加载规则。                                                      | JSON DSL（反序列化配置并传入）。                                                                          |

构建器会生成 JSON，因此你可以混合使用这两种方式：在设计时构建，将 `.toJSON()` 保存到磁盘，再把 JSON 发送到服务器；也可以在运行时读取 JSON 并直接传给 `exportDocx`。无论选择哪种方式，都不会受到限制。

## 快速开始

下面用 12 行代码编写一条 `hintbox` 规则，将其渲染为带样式的 DOCX 段落：

```ts
import { ExportDocx } from '@tiptap-pro/extension-export-docx'
import { childrenInline, docxNode, paragraph } from '@tiptap-pro/extension-export-docx/dsl'

ExportDocx.configure({
  customNodeDsl: {
    dslVersion: '1.0',
    nodes: [
      docxNode('hintbox')
        .block()
        .emit(
          paragraph({ style: 'Hintbox' }) //
            .children(childrenInline({ marks: 'default' })),
        )
        .toJSON(),
    ],
  },
})
```

这与 [JSON DSL 快速入门示例](/conversion/export/docx/custom-nodes-dsl#a-first-example)使用的是同一载荷。在线缆中传输的字节完全相同，区别仅在于编写方式。

## 顶层构建器：`docxNode`

`docxNode(type)` 会为一种 ProseMirror 节点类型创建规则。调用链必须以 `emit(...)`、`emitNothing()` 或 `drop()` 中的**且仅一个**结束。在选择策略之前调用 `toJSON()` 会抛出错误。

```ts
docxNode('hintbox') // ┐
  .block() //          │  可选：显式声明 nodeKind
  .emit(paragraph()) //│  指定替代 PM 节点的渲染内容
  .toJSON() //         ┘  字面形式的 CustomNodeRule JSON
```

| 方法              | 效果                                                                                                      |
| ----------------- | --------------------------------------------------------------------------------------------------------- |
| `.block()`        | 将规则标记为块级（供验证器执行容器检查）。                                                                |
| `.inline()`       | 将规则标记为行内级。                                                                                      |
| `.auto()`         | 由验证器根据 emit 结构推断类型（默认值）。                                                                |
| `.emit(node)`     | 将匹配的 PM 节点渲染为 `node`。接受单个渲染节点构建器、字面形式的 `RenderNode` 或数组。                    |
| `.emitNothing()`  | `emit: null`：不为此 PM 节点输出内容，但仍遍历其后代节点。                                                |
| `.drop()`         | `render: null`：丢弃匹配的 PM 节点及其**所有后代节点**。                                                  |
| `.toJSON()`       | 将调用链转换为线缆格式的 `CustomNodeRule` JSON。                                                          |

每个方法都会返回一个**新的构建器**，因此可以复用部分调用链，不必担心别名问题：

```ts
const base = docxNode('mention').inline()
const withColor = base.emit(textRun({ color: '4472C4' }))
const dropped = base.drop()
// `base` 未发生变化。
```

## 元素工厂

v1 目录中的每种元素都有一个工厂。每个工厂都会返回可链式调用的构建器，其 `.toJSON()` 会生成线缆格式的 [`ElementNode`](/conversion/export/docx/custom-nodes-dsl#elementnode)。

### `paragraph(props?)`

接受行内子项的块级元素。

```ts
paragraph({
  style: 'Hintbox',
  alignment: 'center',
  spacing: { before: 240, after: 240, line: 240, lineRule: 'auto' },
  border: {
    top: { style: 'single', size: 4, color: 'B8D8FF', space: 5 },
    bottom: { style: 'single', size: 4, color: 'B8D8FF', space: 5 },
    left: { style: 'single', size: 4, color: 'B8D8FF', space: 5 },
    right: { style: 'single', size: 4, color: 'B8D8FF', space: 5 },
  },
  shading: { type: 'clear', fill: 'E6F3FF' },
}).children(childrenInline({ marks: 'default' }))
```

| 方法                       | 用途                                                                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `.children(spec)`          | 设置行内子项（`ChildrenInlineBuilder`、单个渲染节点构建器或数组）。块级子项会在编译时触发错误。                                      |
| `.inheritOverrides(value)` | 设为 `false` 时，此段落跳过全局 `paragraphOverrides` 配置。默认值为 `true`。                                                       |
| `.toJSON()`                | 生成线缆格式的 `ElementNode`。                                                                                                     |

对应规范：[Paragraph 元素属性架构](/conversion/export/docx/custom-nodes-dsl#paragraph)。

`border` 和 `shading` 属性让自定义节点可以直接在 DSL 元素上携带装饰样式（方框、提示框、信息框），无需定义命名的 `styleOverrides` 样式。请参阅下文的[直接表达装饰样式](#express-decoration-inline)。

### `textRun(props?)`

行内叶节点，不带 `children`。使用 `applyMarks` 继承规则中 PM 节点的标记。

```ts
textRun({
  text: template('@{node.attrs.label}'),
  color: '4472C4',
  size: 24, // 半磅
  highlight: 'cyan',
  style: 'Hyperlink', // 往返转换时用于标识身份
}).applyMarks('node')
```

| 方法                       | 用途                                                                                                                                                                                                  |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.applyMarks(policy)`      | `'node'`（继承规则中 PM 节点的标记）或 `marks('node')...` 构建器（用于精细控制）。此处会有意拒绝 `'default'` 和 `'none'`（请参阅[标记策略](#mark-policies)）。 |
| `.inheritOverrides(value)` | 设为 `false` 时，此文本运行跳过 `textRunOverrides`。默认值为 `true`。                                                                                                                                 |
| `.toJSON()`                | 生成线缆格式的 `ElementNode`。                                                                                                                                                                        |

对应规范：[TextRun 元素属性架构](/conversion/export/docx/custom-nodes-dsl#textrun)。

### `externalHyperlink(props)`

行内元素，包裹一个或多个 `TextRun` 子项。类型层面要求必须提供 `link` 属性，因此 `externalHyperlink({})` 会产生 TypeScript 错误。

```ts
externalHyperlink({ link: ref('node.attrs.href') }).children([
  textRun({ text: ref('node.attrs.label'), style: 'Hyperlink' }) //
    .applyMarks('node'),
])
```

链接值还会在运行时验证，必须以 `http`、`https`、`mailto` 或 `tel` 开头（长度上限为 2048 个字符）。其他协议会在编译时因 `DOCX_DSL_INVALID_PROP` 而被拒绝。

### `table(props?)` / `tableRow(props?)` / `tableCell(props?)`

`table()` 通过 `.rows(...)`（或等价的 `.children([row, row, ...])`）接受 `TableRow` 构建器。`tableRow()` 通过 `.children([cell, cell, ...])` 接受 `TableCell` 构建器。`tableCell()` 接受块级内容（段落、嵌套表格）或 `childrenBlock()`。

```ts
table({
  width: { size: 100, type: 'pct' },
  borders: {
    top: { style: 'single', size: 4, color: 'B8D8FF' },
    bottom: { style: 'single', size: 4, color: 'B8D8FF' },
    left: { style: 'single', size: 4, color: 'B8D8FF' },
    right: { style: 'single', size: 4, color: 'B8D8FF' },
  },
}).rows(
  tableRow().children([
    tableCell({
      shading: { type: 'clear', fill: 'FFF1CC' },
      verticalAlign: 'top',
    }).children([paragraph().children(childrenInline({ marks: 'default' }))]),
  ]),
)
```

在线缆格式中，`Table` 的子项会在内部映射到 docx 的 `rows` 构造函数参数，因此你无需自行编写 `rows: ...`。

### `pageBreak()`

叶节点工厂：输出一个包含 docx 分页运行的块级段落。若要在段落内插入行内分页符，请改用 `textRun({ break: 1 })`。

```ts
docxNode('explicitPageBreak').block().emit(pageBreak()).toJSON()
```

## 子项辅助函数

在元素的 `.children(...)` 中，你可以传入：

- **渲染节点构建器的显式数组**（`[paragraph(), table(), ...]`）。
- **`childrenX()` 委托**，让运行时遍历 PM 节点的 `content` 数组，并通过标准转换器分派每个子项。

| 辅助函数               | 用于                                                                 | 线缆格式                                                             |
| ---------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `childrenInline(opts?)` | `paragraph().children(...)`、`externalHyperlink().children(...)`   | `{ "$children": { "as": "inline", "marks"?: ... } }`            |
| `childrenBlock(opts?)`  | `tableCell().children(...)`                                          | `{ "$children": { "as": "block", "wrapInlineInParagraph"?: bool } }` |
| `childrenTableRow()`    | `table().children(...)`（`.rows(...)` 的同义写法）                   | `{ "$children": { "as": "table-row" } }`                         |
| `childrenTableCell()`   | `tableRow().children(...)`                                           | `{ "$children": { "as": "table-cell" } }`                        |

```ts
// 行内标记策略：对每个文本子项运行标准标记处理流程。
paragraph({ style: 'Body' }).children(childrenInline({ marks: 'default' }))

// 块级委托并包装行内内容：将独立的行内子项收集到默认段落中，
// 从而确保表格单元格中始终只有块级内容。
tableCell().children(childrenBlock({ wrapInlineInParagraph: true }))
```

`childrenInline()` 接受 `marks` 选项，其值可以是 `MarkPolicy`（`'default'`、`'none'`、`'node'`）或 `marks(...)` 构建器链（请参阅[标记策略](#mark-policies)）。

## 渲染树基元

除了元素之外，还有四种渲染树结构可用于组合动态输出。

### `iff({ test, then, else? })`

结构性条件。`else` 默认为 `null`（不输出内容）。

```ts
iff({
  test: ref('node.attrs.featured'),
  then: paragraph({ style: 'Featured' }).children(childrenInline({ marks: 'default' })),
  else: paragraph().children(childrenInline({ marks: 'default' })),
})
```

`test` 会依据 v1 真值规则转换为布尔值：`false`、`null`、`undefined`、`0`、`""` 为假，其余值为真。

### `switch_({ on, cases, default? })`

多路条件。通过与 `cases` 的键进行精确匹配来查找分支。`on` 在运行时必须解析为字符串。

```ts
switch_({
  on: ref('node.attrs.variant'),
  cases: {
    warning: paragraph({ style: 'CalloutWarning' }),
    info: paragraph({ style: 'CalloutInfo' }),
  },
  default: paragraph({ style: 'Callout' }),
})
```

末尾的下划线是因为 `switch` 在 JavaScript 中属于保留字。另有用于选择属性值的**值形式** `switchValue(...)`（请参阅下文的[值表达式](#value-expressions)）。

### `fragment(...children)`

输出多个同级渲染节点。向元素的 `.children([...])` 传入普通数组也能实现相同效果；当整个 emit 都是由多个片段组成时，可使用 `fragment`。

```ts
docxNode('keyValue')
  .block()
  .emit(
    fragment(
      paragraph({ style: 'Key' }).children([textRun({ text: ref('node.attrs.key') })]),
      paragraph({ style: 'Value' }).children(childrenInline({ marks: 'default' })),
    ),
  )
  .toJSON()
```

### `textOp(value, opts?)`

便捷函数，可根据值表达式输出单个文本运行。在 v1 中，它等价于应用标记策略后的 `{ element: 'TextRun', props: { text: value } }`，但写起来更简洁。

```ts
textOp(template('@{node.attrs.label}'))
textOp(ref('node.attrs.title'), { default: '(untitled)', marks: 'none' })
```

## 值表达式

凡是可以接受属性值（或 `$text`、`$if.test`、`$switch.on`、`$op.args`）的位置，都可以传入字面值**或**以下类型化表达式之一。

### `ref(path, opts?)`

从源 PM 节点读取值。允许的路径：`node`、`node.type`、`node.attrs`、`node.attrs.<key>`、`node.text`、`node.textContent`。其他路径会因 [`DOCX_DSL_INVALID_REF`](/conversion/export/docx/custom-nodes-dsl#error-codes) 被拒绝。

```ts
ref('node.attrs.color')
ref('node.attrs.color', { default: '4472C4', transform: 'hexNoHash' })
ref('node.textContent')
```

`transform` 选项接受单个 `TransformName` 或数组。请参阅 JSON DSL 参考页面中的[转换表](/conversion/export/docx/custom-nodes-dsl#transforms)。

### `template(s)`

字符串插值，始终返回字符串。替换项使用 `{path}`（路径语法与 `ref` 相同）；`{{` 和 `}}` 用于转义字面大括号。

```ts
template('@{node.attrs.label}') //        →  '@alice'
template('size: {node.attrs.size}px') //  →  'size: 24px'
template('{{escaped}} braces') //          →  '{escaped} braces'
```

解析后的长度上限为 `maxTemplateLength`（默认值为 2,000）。超出上限时，运行时会因 `DOCX_DSL_RESOURCE_LIMIT` 而拒绝。

### `op(name, ...args)`

类型化计算。操作集合固定，且每种操作都有严格的参数数量要求（请参阅[op 参数数量表](/conversion/export/docx/custom-nodes-dsl#op---typed-compute)）。

```ts
op('mul', ref('node.attrs.size'), 2)
op('coalesce', ref('node.attrs.color'), ref('node.attrs.fallbackColor'), '000000')
op('and', ref('node.attrs.visible'), op('not', ref('node.attrs.hidden')))
```

没有 `concat` 操作；字符串请使用 `template(...)`。不会进行隐式数值转换，因此 `op('add', '3', 1)` 会被拒绝。

### `unit(name, value)`

用于调用固定列表中的单位/类型转换辅助函数，这些函数与转换器内部使用的函数相同。结果类型与对应辅助函数的签名一致。

```ts
unit('pixelsToHalfPoints', 16) //                          →  24（半磅）
unit('pointsToTwips', 12) //                               →  240（缇）
unit('normalizeColor', ref('node.attrs.backgroundColor')) //→  '4F46E5'
```

完整列表：[unit 分派表](/conversion/export/docx/custom-nodes-dsl#unit---unit--coercion-helper)。

### `switchValue({ on, cases, default? })`

`$switch` 的值形式：按字符串匹配选择属性值（而非渲染节点）。

```ts
paragraph({
  style: switchValue({
    on: ref('node.attrs.variant'),
    cases: { warning: 'CalloutWarning', info: 'CalloutInfo' },
    default: 'Callout',
  }),
})
```

验证器会根据外围上下文选择值形式或渲染树形式：`switchValue` 只能用于属性值中，而 `switch_` 只能用于 `RenderNode` 插槽中。

## 标记策略

`marks(mode)` 构建器会创建可链式调用的 [`MarkPolicy`](/conversion/export/docx/custom-nodes-dsl#marks-system) 对象。当你需要比字符串简写更精细的控制时，它会很有用。

```ts
import { childrenInline, marks } from '@tiptap-pro/extension-export-docx/dsl'

childrenInline({
  marks: marks('default') //
    .disable('bold', 'italic')
    .overrides({
      underline: { props: { color: 'EA580C' } },
      highlight: { replace: true, props: { color: 'FFE066' } },
    }),
})
```

| 方法                                               | 用途                                                                                                                                               |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `marks(mode)`                                      | 开始构建。`mode` 为 `'default'`（针对子项自身的标记使用标准处理流程）或 `'node'`（使用规则中 PM 节点的标记）。                                       |
| `.disable(...marks)`                               | 完全跳过这些标记。它们不会执行标准映射，任何匹配的 `overrides` 条目也会被忽略。                                                                     |
| `.overrides({ markType: { props?, replace? } })`   | 针对单个标记进行调整。`replace: true` 会阻止该标记的标准映射；`props` 会合并到其上。                                                                 |
| `.toJSON()`                                        | 转换为线缆格式的 `MarkPolicyObject`。容器辅助函数会替你调用此方法。                                                                                 |

### `applyMarks` 的适用范围更窄

`textRun().applyMarks(...)` 和 `externalHyperlink().applyMarks(...)` **仅**接受 `'node'` 或 `marks('node')...` 构建器。线缆格式会拒绝此处的 `'default'` 和 `'none'`，因为它们只适用于子项标记。

构建器会在运行时强制执行此规则：如果向 `applyMarks` 传入 `marks('default')`，它会抛出一条有用的错误消息，而不是生成之后会被 DSL 编译器拒绝的载荷。

```ts
textRun().applyMarks('node') //                       ✓
textRun().applyMarks(marks('node').disable('code')) // ✓
textRun().applyMarks(marks('default')) //              ✗ 构建时抛出错误
```

## 类型系统保证

构建器的 TypeScript 接口会在编辑时执行运行时本来会检测到的所有容器规则。以下情况都会产生编译错误：

```ts
// 段落仅接受行内子项。
paragraph().children(childrenBlock())
//                  ^^^^^^^^^^^^^^^^
// Type 'ChildrenBlockBuilder' is not assignable to type 'ParagraphChildSpec'.

// Table.rows 要求传入 TableRow 构建器。
table().rows(paragraph())
//           ^^^^^^^^^^^
// Type 'ParagraphBuilder' is not assignable to type 'TableRowBuilder'.

// TableRow 的子项必须是 TableCell 构建器。
tableRow().children([tableRow()])
//                   ^^^^^^^^^^
// Type 'TableRowBuilder' is not assignable to type 'TableCellBuilder'.

// TableCell 的子项必须是块级内容；不接受行内子项委托。
tableCell().children(childrenInline())
//                   ^^^^^^^^^^^^^^^^

// TextRun 是叶节点，没有子项。
textRun({ text: 'hi' }).children
//                       ^^^^^^^^
// Property 'children' does not exist on type 'TextRunBuilder'.

// externalHyperlink.link 是必需属性。
externalHyperlink({})
//                ^^
// Property 'link' is missing in type '{}' but required in type 'ExternalHyperlinkProps'.

// applyMarks 不接受 'default' / 'none'。
textRun().applyMarks('default')
//                   ^^^^^^^^^
// Argument of type '"default"' is not assignable to parameter of type 'ApplyMarksPolicy | MarkPolicyBuilder'.
```

这些规则与运行时的 [`DOCX_DSL_INVALID_CONTEXT`](/conversion/export/docx/custom-nodes-dsl#error-codes) 相对应：约束相同，只是更早提示。

## 直接表达装饰样式

使用 `styleOverrides` 的常见模式是：先声明一个带边框和底纹的命名段落样式 `Hintbox`，然后在 DSL 规则中通过 `style: 'Hintbox'` 引用它。现在，`paragraph()` 构建器直接提供了 `border` 和 `shading` 属性，因此可以将装饰样式直接写在元素上，无需 `styleOverrides` 配置块。

命名样式标签仍有用途：**用于往返转换时标识身份**。无论 `Hintbox` 是否在 `styles.xml` 中声明，DOCX 写入器都会输出 `<w:pStyle w:val="Hintbox"/>`。导入端会读取该 pStyle，以重建匹配的自定义节点。

```ts
docxNode('hintbox')
  .block()
  .emit(
    paragraph({
      // 往返转换时用于标识身份。
      style: 'Hintbox',
      // 在此处设置装饰样式；无需 styleOverrides。
      spacing: { before: 240, after: 240 },
      border: {
        top: { style: 'single', size: 1, color: 'B8D8FF', space: 5 },
        bottom: { style: 'single', size: 1, color: 'B8D8FF', space: 5 },
        left: { style: 'single', size: 1, color: 'B8D8FF', space: 5 },
        right: { style: 'single', size: 1, color: 'B8D8FF', space: 5 },
      },
      // `clear` 底纹会让 `fill` 透出并作为背景色。
      // `solid` 会绘制 100% 覆盖率的前景色（默认 `auto` → 黑色），
      // 并完全遮住填充色。请参阅下文的 OOXML 陷阱。
      shading: { type: 'clear', fill: 'E6F3FF' },
    }).children(childrenInline({ marks: 'default' })),
  )
  .toJSON()
```

这与 [`cssStyles.extractFromDocument`](/conversion/export/docx/css-to-docx) 配合使用非常自然：由 CSS 处理标题、正文字体、列表等通用选择器；由 DSL 处理与自定义节点类型相关的内容。

<Callout variant="warning" title="OOXML 陷阱：`solid` 底纹会绘制前景色">
  在 OOXML 中，`w:val="solid"` 的 `<w:shd>` 会以 100% 覆盖率绘制**前景色**。`fill` 属性是*背景色*（位于前景色下方）。如果未设置 `color`，前景色默认为 `auto`，Word 会将其渲染为**黑色**，从而完全遮住 `fill`。若要设置段落背景色，请使用 **`type: 'clear'`**（空图案，让 `fill` 透出）。JSON DSL 中也存在同样的问题；这是 OOXML 语义所致，并非构建器缺陷。
</Callout>

## 示例详解

以下示例与 [JSON DSL 参考页面](/conversion/export/docx/custom-nodes-dsl#putting-it-together--worked-examples)中的五个示例相同，只是通过此构建器编写。

### Hintbox：带行内装饰的块级段落

```ts
docxNode('hintbox')
  .block()
  .emit(
    paragraph({
      style: 'Hintbox',
      spacing: { before: 240, after: 240 },
      border: {
        top: { style: 'single', size: 1, color: 'B8D8FF', space: 5 },
        bottom: { style: 'single', size: 1, color: 'B8D8FF', space: 5 },
        left: { style: 'single', size: 1, color: 'B8D8FF', space: 5 },
        right: { style: 'single', size: 1, color: 'B8D8FF', space: 5 },
      },
      shading: { type: 'clear', fill: 'E6F3FF' },
    }).children(childrenInline({ marks: 'default' })),
  )
  .toJSON()
```

### Mention：包含模板文本并继承标记的行内 TextRun

```ts
docxNode('mention')
  .inline()
  .emit(
    textRun({
      text: template('@{node.attrs.label}'),
      color: ref('node.attrs.color', { default: '4472C4', transform: 'hexNoHash' }),
    }).applyMarks('node'),
  )
  .toJSON()
```

粗体 mention 会渲染为 `new TextRun({ text: '@alice', color: '4472C4', bold: true })`。

### Callout：由属性控制底纹并切换样式的单元格表格

```ts
docxNode('calloutBox')
  .block()
  .emit(
    table({
      width: { size: 100, type: 'pct' },
      borders: {
        top: { style: 'single', size: 4, color: 'B8D8FF' },
        bottom: { style: 'single', size: 4, color: 'B8D8FF' },
        left: { style: 'single', size: 4, color: 'B8D8FF' },
        right: { style: 'single', size: 4, color: 'B8D8FF' },
      },
    }).rows(
      tableRow().children([
        tableCell({
          shading: {
            type: 'clear',
            fill: unit('normalizeColor', ref('node.attrs.backgroundColor', { default: 'E6F3FF' })),
          },
          margins: {
            top: unit('pointsToTwips', 8),
            bottom: unit('pointsToTwips', 8),
            left: unit('pointsToTwips', 10),
            right: unit('pointsToTwips', 10),
          },
        }).children([
          paragraph({
            style: switchValue({
              on: ref('node.attrs.variant'),
              cases: { warning: 'CalloutWarning', info: 'CalloutInfo' },
              default: 'Callout',
            }),
          }).children(childrenInline({ marks: 'default' })),
        ]),
      ]),
    ),
  )
  .toJSON()
```

### 代码块：抑制冲突子项标记的段落

```ts
docxNode('codeBlock')
  .block()
  .emit(
    paragraph({ style: 'Code' }).children(
      childrenInline({ marks: marks('default').disable('bold', 'italic') }),
    ),
  )
  .toJSON()
```

### 自定义链接：包裹 TextRun 的行内 ExternalHyperlink

```ts
docxNode('customLink')
  .inline()
  .emit(
    externalHyperlink({ link: ref('node.attrs.href') }).children([
      textRun({ text: ref('node.attrs.label'), style: 'Hyperlink' }) //
        .applyMarks('node'),
    ]),
  )
  .toJSON()
```

## 并排对比：构建器与手写 JSON

构建器生成的 JSON 在线缆格式上等价。以下是同一条 hintbox 规则的两种写法：

**构建器**

```ts
docxNode('hintbox')
  .block()
  .emit(
    paragraph({ style: 'Hintbox' }) //
      .children(childrenInline({ marks: 'default' })),
  )
  .toJSON()
```

**JSON**

```jsonc
{
  "type": "hintbox",
  "nodeKind": "block",
  "render": {
    "emit": {
      "element": "Paragraph",
      "props": { "style": "Hintbox" },
      "children": { "$children": { "as": "inline", "marks": "default" } },
    },
  },
}
```

`builder.toJSON()` 与手写对象深度相等，且已通过程序包自带的一致性测试验证。根据你的编写环境选择合适的方式即可；线缆格式相同。

## 与 `cssStyles` 组合使用

构建器与 [`cssStyles`](/conversion/export/docx/css-to-docx) 配合使用，有助于清晰划分职责：

- **CSS** 描述编辑器样式表中已有的通用选择器样式（标题、段落、列表、引用块）。
- **DSL** 描述自定义节点的渲染：任何需要 Tiptap 节点类型、且无法通过通用 CSS 选择器表达的内容。

```ts
ExportDocx.configure({
  cssStyles: {
    extractFromDocument: true, // 从当前样式表中提取 .tiptap 规则
    baseFontSize: 16,
  },
  customNodeDsl: {
    dslVersion: '1.0',
    nodes: [
      docxNode('hintbox')
        .block()
        .emit(
          paragraph({
            style: 'Hintbox', // 往返转换时用于标识身份
            border: { top: { style: 'single', size: 1, color: 'B8D8FF', space: 5 } /* ... */ },
            shading: { type: 'clear', fill: 'E6F3FF' },
          }).children(childrenInline({ marks: 'default' })),
        )
        .toJSON(),
    ],
  },
})
```

使用这种方式可以完全移除 `styleOverrides` 配置块。随附的 `ExportDocxCustomNodeDslBuilder` 示例正是采用这种模式。

## 冲突策略与运行时错误

构建器只是一个轻量的编写层，因此 [JSON DSL 参考页面](/conversion/export/docx/custom-nodes-dsl#errors)所述的所有运行时约束同样适用：

- 如果基于函数的 [`customNodes`](/conversion/export/docx/custom-nodes) 与此 API 中出现相同的 `type`，则以前者为准（每次导出调用中，每个冲突类型只记录一次警告）。
- DSL 错误会返回[结构化封装](/conversion/export/docx/custom-nodes-dsl#error-responses-rest)，其中包含 `code`、`dslPath`，以及（针对运行时错误）`nodePath` 和 `nodeType`。
- [资源上限](/conversion/export/docx/custom-nodes-dsl#resource-limits)会在编译时和运行时强制执行；可通过 `exportDocx` 上的 `customNodeDslLimits` 调整，也可通过 REST 端的 `DOCX_DSL_MAX_*` 环境变量调整。

构建器自身只增加**一项**运行时检查：向 `applyMarks` 传入 `marks('default')` 构建器时，会抛出清晰的错误，而不是生成之后会因 `DOCX_DSL_INVALID_SHAPE` 而失败的载荷。其他所有内容都会直接交由标准 DSL 编译器处理。

## TypeScript 参考

所有构建器、辅助函数和属性结构接口都从 `@tiptap-pro/extension-export-docx/dsl` 导出，可直接复用：

```ts
import type {
  // 顶层规则
  CustomNodeRuleBuilder,

  // 元素构建器
  ParagraphBuilder,
  TextRunBuilder,
  ExternalHyperlinkBuilder,
  TableBuilder,
  TableRowBuilder,
  TableCellBuilder,

  // 子项辅助函数
  ChildrenInlineBuilder,
  ChildrenBlockBuilder,
  ChildrenTableRowBuilder,
  ChildrenTableCellBuilder,

  // 渲染节点抽象
  RenderNodeBuilder,

  // 标记策略链
  MarkPolicyBuilder,

  // 各元素的属性接口
  ParagraphProps,
  TextRunProps,
  ExternalHyperlinkProps,
  TableProps,
  TableRowProps,
  TableCellProps,

  // 共享结构
  BorderSide,
  Prop,
} from '@tiptap-pro/extension-export-docx/dsl'
```

`Prop<T>` 是一个辅助类型，让每个叶属性都可以接受字面值（`number`、`string` 等）或 `ValueExpr`（`ref(...)`、`template(...)`、`op(...)` 等）。
