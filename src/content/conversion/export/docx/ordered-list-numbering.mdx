`@tiptap-pro/extension-export-docx` 接受可选的**编号格式定义**注册表，其中包括多级标记样式、标记文本、对齐方式、缩进和字体。每个列表通过最外层 `<ol>` 或 `<ul>` 上的属性选择格式。具有匹配 ID 的列表会按相应定义导出；未指定 ID 的列表则保留其列表类型的默认层级。

如果某格式的各级使用 `baseStyle: 'bullet'`，它描述的是字形层级而非计数器，因此同一注册表也可定义装饰性项目符号。参阅[项目符号层级](#bullet-ladders)。

此功能默认关闭。未提供 `numberingFormats` 的使用者不会看到任何行为变化。

## 提供的内容

| 导出项                                                                         | 程序包                              | 用途                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------ | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OrderedListNumbering`                                                         | `@tiptap-pro/extension-convert-kit` | Tiptap 扩展，为 `orderedList` 和 `bulletList` 添加 `numberingFormat` 属性，并提供 `setOrderedListNumberingFormat(id)`、`toggleOrderedListWithFormat(format?)`、`setBulletListNumberingFormat(id)`、`toggleBulletListWithFormat(format?)` 和 `registerNumberingFormats(formats)` 命令；还通过 `editor.storage.orderedListNumbering` 跟踪光标所在位置各列表类型的活动格式。由 `ConvertKit` 注册（通过 `orderedListNumbering: true` 或包含 `defaultFormat` / `defaultBulletFormat` / `formats` 的选项对象启用）。在粘贴、JSON、协同同步和程序化编辑时强制只在最外层列表设置编号。 |

| `NumberingFormatDefinition`、`NumberingLevelDefinition`、`NumberingMarkerFont` | `@tiptap-pro/extension-convert-kit` | 预览类型。导出器提供了更严格、可供两个程序包共同使用的类型。                                                                                                                                                                                                                                                   |
| `ExportDocx.configure({ numberingFormats })`                                   | `@tiptap-pro/extension-export-docx` | 将注册表传给导出器，以便 `.docx` 文件包含匹配的定义。                                                                                                                                                                                                                                                        |
| `LevelFormat`、`IRunOptions`、`PositiveUniversalMeasure`                       | `@tiptap-pro/extension-export-docx` | 从 `docx` 重新导出，因此无需额外添加一个依赖项。                                                                                                                                                                                                                                                                             |

## 快速开始

```ts
import { Editor } from '@tiptap/core'
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'
import {
  ExportDocx,
  LevelFormat,
  type NumberingFormatDefinition,
} from '@tiptap-pro/extension-export-docx'

// 1. 定义注册表：唯一事实来源，供下文两处使用。
const MY_FORMATS: NumberingFormatDefinition[] = [
  {
    id: 'decimal-paren',
    levels: [
      { baseStyle: LevelFormat.DECIMAL, textTemplate: '%1)' },
      { baseStyle: LevelFormat.LOWER_LETTER, textTemplate: '%2)' },
      { baseStyle: LevelFormat.LOWER_ROMAN, textTemplate: '%3)' },
    ],
  },
  {
    id: 'outline',
    levels: [
      { baseStyle: LevelFormat.DECIMAL, textTemplate: '%1.' },
      { baseStyle: LevelFormat.DECIMAL, textTemplate: '%1.%2.' },
      { baseStyle: LevelFormat.DECIMAL, textTemplate: '%1.%2.%3.' },
    ],
  },
]

// 2. 通过 ConvertKit 启用。传入 `formats` 会生成编辑器预览 CSS
//    并自动注入；使用同一注册表配置 ExportDocx，确保
//    .docx 文件包含匹配的定义。
const editor = new Editor({
  extensions: [
    ConvertKit.configure({
      // 默认关闭，因此不使用自定义编号的用户可以保持干净的
      // orderedList 架构。传入选项对象（或 `true`）即可启用。
      orderedListNumbering: { formats: MY_FORMATS },
    }),
    ExportDocx.configure({
      numberingFormats: MY_FORMATS,
      onCompleteExport: (blob) => {
        /* download blob */
      },
    }),
  ],
})

// 3. 在当前选区以选定格式开始编号列表
//    （若已位于列表中，则使用 setOrderedListNumberingFormat 更改其格式）。
editor.chain().focus().toggleOrderedListWithFormat('outline').run()
```

更希望自行管理样式表？省略 `formats`，改为注入 [`generateNumberingFormatCss`](#generatenumberingformatcssformats-options) 生成的 CSS。两种方式产生的标记相同。

## 启用有序列表编号

[`@tiptap-pro/extension-convert-kit`](/conversion/import/docx/convertkit) 随附 `OrderedListNumbering`，但**默认关闭**，以便不使用自定义编号的用户保持干净的 `orderedList` 架构。通过 `ConvertKit` 启用：

```ts
ConvertKit.configure({ orderedListNumbering: true })
```

<Callout variant="warning" title="项目符号列表的存储 JSON 会新增属性">
  启用此功能后，`bulletList` 和 `orderedList` 都会注册 `numberingFormat`，因此现在对于未指定格式的项目符号列表，`editor.getJSON()` 会写入 `attrs: { numberingFormat: null }`；此前则完全没有 `attrs`。有序列表一直以来都是这种形式，渲染后的 HTML 也不会改变：未指定格式的列表仍是普通的 `<ul>`。存储的 JSON、协作文档以及逐字节比较项目符号列表的快照测试都会看到这个新键。
</Callout>

要配置三项内容，请传入选项对象而不是 `true`：

```ts
ConvertKit.configure({
  orderedListNumbering: {
    // 新建有序列表使用的格式 ID。默认为 `null`（普通的 `1. 2. 3.`）。
    defaultFormat: 'outline',
    // 新建项目符号列表使用的默认格式。
    defaultBulletFormat: 'arrows',
    // 与传给 ExportDocx 的定义相同。提供后，
    // 系统会根据它们生成编辑器预览 CSS 并自动注入，
    // 无需额外配置，屏幕上显示的标记就会与导出内容一致。
    formats: MY_FORMATS,
  },
})
```

| 选项                  | 默认值 | 说明                                                                                                                                                                                                                                                                                                                                              |
| --------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `defaultFormat`       | `null`  | 应用于新建**有序**列表的编号格式 ID（即 `numberingFormat` 属性的默认值）。只有最外层列表会设置格式；嵌套的有序列表不设置格式。 |
| `defaultBulletFormat` | `null`  | 新建**项目符号**列表的默认格式。两者相互独立，因此任何一个默认值都不会应用到另一种列表。 |
| `formats`             | `null`  | 用于生成并注入编辑器预览 CSS 的编号格式定义；传入的数组与 `ExportDocx.configure({ numberingFormats })` 相同。配置了相同格式的编辑器会共用一个预览样式表，格式不同的编辑器则使用各自的样式表，因此每个编辑器始终显示正确的标记；只有在使用共享样式表的最后一个编辑器销毁后，样式表才会被移除。 |

在此处传入 `formats`，等同于调用 [`generateNumberingFormatCss`](#generatenumberingformatcssformats-options) 并自行注入结果；请根据你的设置选择合适的方式。

## 应用格式

`setOrderedListNumberingFormat(id)` 命令会在当前选区所属的最外层有序列表祖先上设置 `numberingFormat` 属性。传入 `null` 可清除该属性（此时列表会以普通的 `1. 2. 3.` 导出）。

```ts
editor.chain().focus().setOrderedListNumberingFormat('decimal-paren').run()
editor.chain().focus().setOrderedListNumberingFormat(null).run()
```

如果选区不在有序列表中，命令会返回 `false`；如果选区与该有序列表之间隔着其他类型的列表，也会返回 `false`，因为该列表会终止层级链。要判断此命令是否能找到列表，请使用 `editor.can().setOrderedListNumberingFormat(null)`，而不要使用 `editor.isActive('orderedList')`：只有在上述特定情况下，两者的结果才会不同，并且只有 `can()` 的结果与命令实际行为一致。

### 以指定格式开始新列表

`setOrderedListNumberingFormat` 只会作用于选区**已经位于其中**的列表。要从非列表选区开始指定格式的编号列表，请使用 `toggleOrderedListWithFormat(format?)`。此命令会一次性创建有序列表并应用格式，非常适合用于“选择格式并开始编号列表”的工具栏按钮：

```ts
// 从段落开始：创建有序列表并设置其格式。
editor.chain().focus().toggleOrderedListWithFormat('outline').run()

// 省略格式参数，使用已配置的 `defaultFormat` 开始列表。
editor.chain().focus().toggleOrderedListWithFormat().run()
```

如果选区已经位于有序列表中，该命令会切换关闭列表，行为与 `toggleOrderedList` 一致。链式调用 `toggleOrderedList().setOrderedListNumberingFormat(format)` 也能达到相同结果；单个命令只是更方便，并且也能处理切换关闭的情况。

省略参数和传入 `null` 并不相同。省略参数时，新列表会采用已配置的 `defaultFormat`；传入 `null` 时，新列表完全不使用任何格式。

这两个命令的 `editor.can()` 检查目标不同，因此工具栏需要兼顾二者。`toggleOrderedListWithFormat` 的判断方式与普通切换命令相同：在普通段落中会返回 `true`，因为它可以创建列表；如果按钮的用途是“以此格式开始列表”，就应在这种情况下禁用它。`setOrderedListNumberingFormat` 判断的是是否已有列表可供更改，因此在同一段落中会返回 `false`。应根据 setter 的判断结果选择要运行的命令，而不是据此禁用按钮：

```ts
// 一个“应用此格式”按钮，无论当前所处位置如何都能正确工作。
if (editor.can().setOrderedListNumberingFormat(null)) {
  editor.chain().focus().setOrderedListNumberingFormat(id).run()
} else {
  editor.chain().focus().toggleOrderedListWithFormat(id).run()
}
```

<Callout variant="warning" title="切换命令会越过另一种类型的列表">
  对 **set** 命令而言，另一种类型的列表会终止层级链；但 **toggle** 命令不会，它仍会将此处视为非列表位置并执行创建分支。如果选区位于嵌套在 `<ol>` 中的 `<ul>` 内，`toggleOrderedListWithFormat` 会将该内层 `<ul>` 转为 `<ol>`，随后把格式写入外层 `<ol>`，也就是用户并未编辑的列表。如果该处是任务列表，命令会将任务列表展平，并把其项目提升到外层 `<ol>` 中，导致复选框丢失。在这两种位置，toggle 自身的 `can()` 都会返回 `true`，因此无法发出警告；由于 setter 返回 `false`，上面的分支也会在此调用 toggle。如果工具栏需要避免改动任务列表，就必须自行检查 `editor.isActive('taskList')`。
</Callout>

### 项目符号列表

项目符号列表也有一组对应命令，作用于最外层的 `bulletList` 祖先：

```ts
editor.chain().focus().setBulletListNumberingFormat('arrows').run()
editor.chain().focus().toggleBulletListWithFormat('arrows').run()
```

上述内容同样适用于项目符号列表的这组命令，只需将 `defaultFormat` 替换为 `defaultBulletFormat`。在以下四种位置，`setBulletListNumberingFormat` 都会返回 `false`：任何列表之外、有序列表内部、任务列表内部，以及只有越过上述两种列表之一才能到达的项目符号列表内部。任务列表不是项目符号列表，因此它会像有序列表一样终止层级链。请根据 `editor.can().setBulletListNumberingFormat(null)` 的结果进行分支；与前述有序列表命令一样，它在上述四种位置都会返回 `false`。

`toggleBulletListWithFormat` 的作用范围与对应的有序列表命令相同：在任务列表内部调用时，会将整个任务列表转换为普通项目符号列表，导致复选框丢失。

### 编辑器运行后添加格式

创建编辑器时只会读取一次 `formats`。若注册表在编辑器启动后才可用（通常是从 DOCX 文件中重建的注册表），请通过 `registerNumberingFormats(formats)` 注册。此命令会按 ID 合并注册表并刷新注入的预览样式表，因此文档中已有的列表会立即显示对应标记：

```ts
editor.commands.registerNumberingFormats(formatsFromTheImport)
```

按 ID 合并意味着重复调用也是安全的：重新注册某个 ID 会替换该条目，而不是再添加一条，因此重复导入同一文件也只会保留一份定义。以同样方式替换在 `formats` 中配置的 ID，因此导入文档可以覆盖同名的自定义格式。

扩展的 storage 中包含完整注册表，即已配置的格式和此后注册的所有格式。将它传给导出器即可完成往返：

```ts
ExportDocx.configure({ numberingFormats: editor.storage.orderedListNumbering.numberingFormats })
```

如果启用了 `orderedListNumbering`，`ImportDocx` 扩展会自动调用 `registerNumberingFormats`，因此导入的文档无需额外配置即可显示自身标记。如果以其他方式加载内容，则需要自行调用该命令。

### 读取活动格式

要在工具栏中反映活动格式，请从扩展的 storage 中读取；选区或文档发生变化时，该值会保持同步：

```ts
const activeOrdered = editor.storage.orderedListNumbering.activeNumberingFormat
const activeBullet = editor.storage.orderedListNumbering.activeBulletNumberingFormat
// 格式 ID；如果选区不在对应类型的列表中，则为 `null`
```

每个字段都会反映对应命令将要作用的对象，因此一次只会设置其中一个：如果选区位于嵌套在有序列表中的项目符号列表内，项目符号字段会返回该列表，而有序列表字段则为 `null`。

## `NumberingFormatDefinition`

```ts
interface NumberingFormatDefinition {
  id: string
  levels: NumberingLevelDefinition[]
}
```

| 字段     | 类型                         | 说明                                                                                                                            |
| -------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `id`     | `string`                     | 在 `numberingFormats[]` 中必须唯一。序列化到指定此 ID 的最外层 `orderedList` 或 `bulletList` 的 `numberingFormat` 属性中。 |
| `levels` | `NumberingLevelDefinition[]` | 每个嵌套深度对应一项。数组不能为空。当列表嵌套深度超过数组长度时，深度 `N` 会重复使用 `levels[N % levels.length]`。 |

## `NumberingLevelDefinition`

```ts
interface NumberingLevelDefinition {
  baseStyle: NumberingBaseStyle
  textTemplate: string
  startAt?: number
  alignment?: 'left' | 'center' | 'right'
  numberIndent?: number | string
  textIndent?: number | string
  markerFont?: NumberingMarkerFont
  suffix?: 'tab' | 'space' | 'nothing'
  isLegalNumbering?: boolean
  linkedStyle?: string
}
```

ConvertKit 的类型接受普通字符串，因此该程序包不会引入 `docx` 依赖。若要让 ConvertKit 和 `ExportDocx` 共用一个注册表，请从 `@tiptap-pro/extension-export-docx` 导入 `NumberingFormatDefinition`。其更严格的类型可供两个程序包共同使用。`LevelFormat.DECIMAL` 和字符串 `'decimal'` 都会选择十进制编号。

| 字段              | 默认值                  | 说明                                                                                                                                                                                                                                                               |
| -------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `baseStyle`    | （必填）               | 计数器字形，或表示[项目符号层级](#bullet-ladders)的字面值 `'bullet'`。除此之外，它等同于对应的 docx [`LevelFormat`](https://docx.js.org/api/enums/LevelFormat.html) 值。拉丁字母/数字样式（`'decimal'`、`'decimalZero'`、`'upperLetter'`、`'lowerLetter'`、`'upperRoman'`、`'lowerRoman'`、`'none'`）以及许多区域性样式（例如 `'hebrew1'`、`'thaiNumbers'`、`'hindiNumbers'`、`'japaneseCounting'`、`'koreanDigital'`、`'chineseCounting'`、`'ideographDigital'`）都会映射到对应的 CSS 计数器样式，因此预览会显示其原生字形。对于没有忠实 CSS 等效项的样式（例如 `'chicago'`、`'ordinal'`、`'cardinalText'`）以及任何无法识别的字符串，**仅在编辑器预览中**会回退为 `decimal`；导出的 `.docx` 始终会保留你设置的确切 `LevelFormat`。 |
| `textTemplate` | （必填）               | 使用 Word 的 `<w:lvlText>` 语法定义标记文本（见下文）。对于 `'bullet'` 层级，此值就是字形本身。                                                                                                                                             |
| `startAt`      | `1`                      | 初始计数值。                                                                                                                                                                                                                                                    |
| `alignment`    | `'left'`                 | 标记相对于 `numberIndent` 的对齐方式。参阅[标记对齐](#marker-alignment)。                                                                                                                                                                           |
| `numberIndent` | Word 的每级默认值 | 从页边距到标记的距离。可以是 twips 数值，也可以是 docx 风格的尺寸字符串（`'0.63cm'`、`'0.25in'`、`'18pt'`）。                                                                                                                                              |
| `textIndent`   | Word 的每级默认值 | 从页边距到正文文本的距离。应大于 `numberIndent`。单个列表项目可以位于其他位置；参阅[单个项目的缩进](#indents-on-a-single-item)。                                                                                   |
| `markerFont`   | 无                     | 仅应用于标记的文本运行格式（见下文的 [`NumberingMarkerFont`](#numberingmarkerfont)）。此设置会保留在 DOCX 导出中，并反映在编辑器预览的 `generateNumberingFormatCss` 中。对于 `'bullet'` 层级，`font` 是 Word 符号字体项目符号所需的字体。                  |
| `suffix`       | `'tab'`                  | Word 的“编号之后”（`w:suff`）。制表符会将标记填充至 `textIndent`；`'space'` 会在标记后插入一个不换行空格，`'nothing'` 则不插入空格，因此正文会紧跟在标记之后。编辑器预览也会遵循此设置。 |
| `isLegalNumbering` | `false`              | Word 的“法律样式编号”（`w:isLgl`）：指向罗马数字或字母层级的 `%N` 会改用阿拉伯数字显示，因此 `Article IV.2` 会变成 `Article 4.2`。阿拉伯数字层级仍保留其计数格式，所以 `decimalZero` 仍会补零（`01.1` 而非 `1.1`）；不计数的层级仍不会显示任何内容。编辑器预览也会遵循此设置。 |
| `linkedStyle`  | 无                     | Word 的“将级别链接到样式”（`w:pStyle`）：该样式的段落会按此级别编号。值为样式 ID，例如 `'Heading1'`。含有链接级别的格式在**整个文档中属于同一个列表**，因此这些列表会接续编号而不是重新开始。仅影响导出；编辑器预览没有对应功能。 |

## `NumberingMarkerFont`

```ts
interface NumberingMarkerFont {
  font?: string | { name: string }
  size?: number | string
  bold?: boolean
  italics?: boolean
  color?: string
  underline?: unknown
}
```

| 字段       | 说明                                                                               |
| ----------- | ----------------------------------------------------------------------------------------- |
| `font`      | 字体系列名称，或 docx 风格的 `{ name }` 对象。                                      |
| `size`      | docx 半磅数值（例如 `28` = 14pt），或 docx 尺寸字符串，例如 `'14pt'`。 |
| `bold`      | 设置为 `true` 可将标记显示为粗体。                                                     |
| `italics`   | 设置为 `true` 可将标记显示为斜体。                                                   |
| `color`     | 十六进制颜色，可带或不带前导 `#`。                                                   |
| `underline` | 任何真值都会在预览中应用 `text-decoration: underline`。                     |

`generateNumberingFormatCss` 会读取上述字段。若要让标记字体同时用于 `ExportDocx`，请使用导出器的 `NumberingMarkerFont`。它还接受只影响导出文档的其他文本运行选项。

```ts
import { Docx, type NumberingMarkerFont } from '@tiptap-pro/extension-export-docx'

const markerFont: NumberingMarkerFont = {
  color: 'AA3344',
  underline: { type: Docx.UnderlineType.SINGLE, color: '336699' },
}
```

`color` 和 `underline.color` 都使用字符串。原生 [`IRunOptions`](https://docx.js.org/api/interfaces/IRunOptions.html) 也接受主题颜色对象，例如 `{ theme: 'accent1' }`；因此，共享标记字体的类型标注应使用 `NumberingMarkerFont` 而非 `IRunOptions`。

## `textTemplate` 语法

- `%1` 到 `%9` 引用按 1 起始编号的嵌套深度上的计数器。因此，无论 `textTemplate` 属于哪一级，`%1` 始终表示“最外层级别的计数器”。
- 其他所有字符都会按字面显示。
- `%` 后面跟着非数字的情况（例如 `"50%"`）会原样保留。
- 如果 `%N` 指向不计数的层级、`'bullet'` 层级或 `'none'` 层级，则不会显示任何内容。

若要让每级显示自身的计数器，请按级别递增使用 `%N`。若要让某级包含父级计数器（法律样式大纲），请将它们串联起来：在第 1 级使用 `'%1.%2.'` 会显示 `'1.1.'`。

| 第 N 级使用的模板       | 显示示例           |
| ------------------------- | -------------------------- |
| 第 0 级的 `'%1.'`        | `1.`                       |
| 第 1 级的 `'%2.'`        | `1.`（第 1 级的计数器） |
| 第 1 级的 `'%1.%2.'`     | `1.1.`                     |
| 第 2 级的 `'%1.%2.%3.'`  | `1.1.1.`                   |
| 第 0 级的 `'Article %1'` | `Article 1`                |
| 第 0 级的 `'§ %1 —'`     | `§ 1 —`                    |
| 第 2 级的 `'(%3)'`       | `(1)`                      |

## 项目符号层级

Word 会使用 `w:lvlText` 中的字形绘制项目符号，因此箭头、菱形或星号会由文档指定，而不是由读者所用的 Word 决定。若某格式的各级使用 `baseStyle: 'bullet'`，该格式就描述了这样的层级；`bulletList` 可通过同一个 `numberingFormat` 属性选择该格式：

```ts
numberingFormats: [
  {
    id: 'arrows',
    levels: [
      { baseStyle: 'bullet', textTemplate: '➔' },
      { baseStyle: 'bullet', textTemplate: '◆' },
    ],
  },
]
// { type: 'bulletList', attrs: { numberingFormat: 'arrows' }, content: [...] }
```

在 `'bullet'` 层级中，`textTemplate` 就是字形本身，而 `markerFont.font` 用于指定绘制字形的字体，这是 Word 符号字体项目符号所需的设置。层级上的其他设置（包括缩进）都与计数器层级的工作方式相同。只有精确值 `bullet` 才会将层级标记为项目符号层级；其他所有 `baseStyle` 值仍表示计数器层级。

项目符号层级不进行计数，因此指向该层级的 `%N` 不会显示任何内容。在项目符号层级上，`'Item %1:'` 会在 Word 和预览中都显示为 `Item :`。`'none'` 的行为相同，`isLegalNumbering` 也不会改变这一点：法律样式编号可以将计数器改为阿拉伯数字，但不能为没有计数器的层级添加计数器。

格式不与列表类型绑定。它会应用于任何指定它的列表，就像 Word 的 `numId` 无论列表外观如何都会指向某个定义一样。因此，将字形层级应用于 `<ol>` 会显示字形，将计数器层级应用于 `<ul>` 则会进行计数。`generateNumberingFormatCss` 会在 `ul` 和 `ol` 上同样查找此属性，因此预览与导出两者都会一致。

嵌套在同类型列表中的列表会在自己的深度使用外层列表的层级，因此一个多级列表会使用同一个定义。

### 任务列表

任务列表会渲染为 `ul`，但它不是项目符号层级的一部分。检查清单会保留其复选框，嵌套在其中的项目符号列表也会保留自身的 `numberingFormat`。

检查清单也会终止层级链，与另一种类型的列表完全相同。命令和 `active…` storage 字段都会在此停止，因此只有越过检查清单才能到达的项目符号列表会重新成为最外层列表，并拥有自己的格式。

<Callout variant="info" title="两侧对嵌套深度的计算方式不同">
  编辑器预览只会通过**同类型**列表计算嵌套深度，而导出时会计算**所有**外层列表。因此，位于检查清单或另一种类型列表下方的列表，在屏幕上会显示其格式的第一级，而在 Word 中则会显示更深一级。请将多级层级放在同一种列表中，以避免这种差异。
</Callout>

## 架构约定：每种类型的最外层列表

`numberingFormat` 属性应放在每种类型的**最外层**列表上。一个定义会为整个多级列表声明所有嵌套级别。`OrderedListNumbering` 会在解析时强制执行此约定：如果粘贴的 HTML 在嵌套于另一个 `<ol>` 中的 `<ol>` 上，或嵌套于另一个 `<ul>` 中的 `<ul>` 上带有 `data-numbering-format`，该属性就会被移除。

另一种类型的列表会开始自己的层级链，同时也会**终止**当前链：通过 `<ol>` 到达的 `<ul>` 会重新成为最外层列表，因此即使它整体又嵌套在另一个 `<ul>` 中，也可以保留自己的格式。命令和 `active…` storage 字段也会在此边界停止，因此每个命令都会作用于导出和预览实际绘制的列表。

同一个最外层列表下的所有嵌套级别共用一个计数器范围；父级递增时，子级会重新开始计数，这与 Word 的行为完全一致。

## 循环规则

`levels.length` 决定循环周期。当列表嵌套深度超过 `levels.length - 1` 时，DOCX 导出和编辑器预览 CSS 都会让深度 `N` 重复使用 `levels[N % levels.length]`。若要覆盖 Word 的全部嵌套深度而不循环，请提供九个级别；如果更深层级可以自然重复较浅层级的条目，则可以提供更少的级别。

## 默认值与 Word 标准一致

未设置 `numberIndent` / `textIndent` 时，导出器和 CSS 辅助函数都会输出 Word 的标准多级列表默认值：

| 深度 | `textIndent`   | `numberIndent` | 悬挂缩进 |
| ----- | -------------- | -------------- | ------- |
| 0     | `720` (0.50″)  | `360` (0.25″)  | `360`   |
| 1     | `1140` (0.79″) | `780` (0.54″)  | `360`   |
| 2     | `1440` (1.00″) | `1080` (0.75″) | `360`   |
| 3     | `1740` (1.21″) | `1380` (0.96″) | `360`   |
| 4     | `2040` (1.42″) | `1680` (1.17″) | `360`   |
| 5     | `2340` (1.63″) | `1980` (1.38″) | `360`   |
| 6     | `2640` (1.83″) | `2280` (1.58″) | `360`   |
| 7     | `2940` (2.04″) | `2580` (1.79″) | `360`   |
| 8     | `3240` (2.25″) | `2880` (2.00″) | `360`   |

## 标记对齐

`alignment` 指定标记相对于 `numberIndent`（即该级为标记设定的位置）的对齐方式。Word 会让标记相对于这个位置对齐，编辑器预览也是如此。

| `alignment`        | 标记位置                                                                                    |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| `'left'`（默认） | 从 `numberIndent` 开始向右延伸。                                                             |
| `'right'`          | 在 `numberIndent` 处结束并向左延伸，因此不同宽度的标记会按右边缘对齐。   |
| `'center'`         | 以 `numberIndent` 为中心，左右各占一半宽度。                                                       |

无论选择哪种对齐方式，正文都位于 `textIndent` 处，因此右对齐标记与正文之间的间距会比相同宽度的左对齐标记更大。在 `'left'` 和 `'center'` 对齐方式下，如果标记宽于该间距，就会将该项目的正文进一步向右推；而右对齐标记会向 `numberIndent` 之前的空隙延伸，不会移动正文。无论哪种情况，都只有该项目的正文会移动：嵌套在项目中的列表仍会从其自身级别指定的位置开始。

```ts
// 罗马数字递增时宽度会变大。右对齐会使句点位于同一列，正文则位于另一列。
levels: [{ baseStyle: LevelFormat.UPPER_ROMAN, textTemplate: '%1.', alignment: 'right' }]
```

将 `suffix` 设为 `'space'` 或 `'nothing'` 会移除标记的填充列，因此在 `'left'` 和 `'center'` 对齐方式下，正文会紧跟标记，而不再等待到 `textIndent`。与 `'right'` 配合时，标记仍会在 `numberIndent` 处结束，正文也会从该位置开始。

<Callout variant="info" title="导入的格式不包含对齐方式">
  DOCX 导入返回的注册表不会报告源文档使用的对齐方式，因此，即使 Word 中的层级是右对齐的，导入后也会以左对齐方式绘制。请在代码中定义格式时设置 `alignment`。
</Callout>

## 单个项目的缩进

某个级别会设置属于该级的所有项目，但单个项目也可以位于其他位置。如果列表项目中的段落带有 `indent` 属性，该项目的标记和正文文本都会随之移动，并且该项目不再应用级别的 `textIndent`。同一段落上的负 `firstLineIndent` 会设置该项目标记与正文之间的间距，取代级别中 `numberIndent` 到 `textIndent` 的距离。列表项目中的标题也会以相同方式处理。

```ts
// 此项目比其级别设定的位置更靠右，标记与正文之间间隔 24px。
{
  type: 'listItem',
  content: [
    {
      type: 'paragraph',
      attrs: { indent: 96, firstLineIndent: -24 },
      content: [{ type: 'text', text: 'Positioned by the item, not by the level' }],
    },
  ],
}
```

导入的文档会依赖此行为。导入时，会将每个列表段落在 Word 中自身的缩进写入段落节点的 `indent` 和 `firstLineIndent`（参阅 [ConvertKit](/conversion/import/docx/convertkit)），因此项目会位于源文档中的位置，而不是按层级设置的位置排列。

适用条件和限制：

- 仅当列表指定了编辑器已知的格式时才会应用此功能；格式可以来自 `formats`，也可以来自 [`registerNumberingFormats`](#adding-formats-after-the-editor-is-running)。如果列表没有指定格式，就不会有任何内容为项目定位，因此段落会像列表外的段落一样，将缩进渲染为自身的 `padding-left` 和 `text-indent`。关闭 `orderedListNumbering` 时也会如此。
- 任务列表不属于编号层级，因此检查清单中的项目会在段落上保留缩进。
- **正值** `firstLineIndent` 是普通的首行缩进，而非标记间距。它会保留在段落上，使项目正文首行缩进。
- `indentRight` 不受影响。列表会设置项目左边缘的位置，而非右边缘。
- 含有多个块的列表项目会依据第一个块确定位置。后续块会与它对齐，且不会自行渲染缩进。
- 这些属性会保留在节点上，因此 `ExportDocx` 会按原样导出缩进，DOCX 往返转换后也会保留该设置。
- 编辑器会定位项目，并使用行内样式清除段落自身的 `padding-left` 和 `text-indent`。若要覆盖该段落上的此行为，需要在自己的规则中使用 `!important`。

## `generateNumberingFormatCss(formats, options?)`

返回 CSS 文本，如何注入由你决定（例如 `<style>` 标签、CSS-in-JS 层，或由构建流程提供的样式表）。该函数是纯函数，不依赖其他程序包，可在启动时或注册表发生变化时安全调用。

```ts
generateNumberingFormatCss(formats, {
  scope: '.tiptap.ProseMirror', // default
  maxDepth: 9, // default
})
```

| 选项       | 默认值                 | 说明                                                                                                                                                  |
| ---------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `scope`    | `'.tiptap.ProseMirror'` | CSS 选择器前缀，用于限定所有生成规则的作用范围。传入空字符串可生成不限定范围的输出（适合在 Shadow DOM 或自定义 CSS 层中注入）。 |
| `maxDepth` | `9`                     | 要生成规则的最大嵌套深度。值越小，样式表越精简。                                                                           |

生成的 CSS 会定位每个列表标记及正文文本，使其与 Word 渲染时的绝对位置一致，包括每个嵌套深度的阶梯式缩进。规则会设置列表及其各个项目的左边距和内边距，因此格式化列表内部 `ul`、`ol` 或 `li` 上由你定义的低优先级规则会被这些规则覆盖；垂直间距则由你自行处理。如果需要为主题（深色模式、RTL、字体缩放）覆盖设置，请用自己的选择器或作用域包裹输出，并利用层叠规则。

列表项目需要设置 `box-sizing: border-box`。项目规则会组合使用百分比宽度和内边距；若未设置此项，位于其级别右侧的项目会超出列表右边缘。ConvertKit 的 CSS 重置样式会在 `.tiptap` 内设置此项，默认作用域下无需额外处理；如果在其他位置注入此 CSS，请自行添加。

每种格式都会同时生成 `ul[data-numbering-format="…"]` 和 `ol[data-numbering-format="…"]` 规则，因为格式适用于任何指定它的列表。每条层级链随后会通过自身元素（`ul:not([data-type="taskList"])` 或 `ol`）上的 `> li >` 进入下一深度，因此检查清单会保留复选框，层级链也会在遇到另一种类型的列表时停止，而不会穿过它继续延伸。

## 解析规则

- ID 匹配时，多级列表的每个级别（包括所有同类型嵌套列表）都会使用对应定义进行渲染。
- ID 不匹配时（输入错误、缺少属性、`numberingFormats` 为空），列表会保留该类型的默认层级：有序列表显示普通的 `1. 2. 3.`，项目符号列表显示内置字形层级。
- 引用同一格式的同级多级列表会分别重新开始计数，每个列表都从自身的 `startAt` 开始。但任何级别含有 `linkedStyle` 的格式例外：它在整个文档中属于同一个列表，因此各处列表会接续编号。

## 已知限制

导出器有意不建模的 Word 功能：

| 功能                                    | 解决方法 / 适用范围                                                                    |
| ------------------------------------------ | ------------------------------------------------------------------------------------- |
| 按级别重新开始计数（Word 的“在第 N 级之后重新开始列表”，`w:lvlRestart`） | 始终使用 Word 的默认行为（父级递增时子级重新开始）。 |
| 图片项目符号（`w:lvlPicBulletId`）       | 改用 `markerFont.font` 指定符号字体。                                  |
| 在不同列表之间继续编号 | 每个列表都会从自己的 `startAt` 开始计数。                                      |
| 单个项目的标记覆盖（为某一项设置不同字形或计数值） | 使用单独的列表从不同计数值开始。如果只是要调整项目的位置，请参阅[单个项目的缩进](#indents-on-a-single-item)。 |
| DOCX → 编辑器导入                       | 由 `@tiptap-pro/extension-import-docx` 处理；它会将重建的格式传给编辑器。参阅[编辑器运行后添加格式](#adding-formats-after-the-editor-is-running)。 |
