DOCX 导入服务会从导入的文档中提取脚注和尾注内容。不过，这些数据只能通过 [REST API](/conversion/import/docx/rest-api) 获取。[编辑器扩展](/conversion/import/docx/editor-extension) 不会在 `onImport` 回调中提供脚注或尾注。目前没有用于渲染脚注的编辑器扩展，也不支持导出。

## 支持概览

| | 导入 | 编辑器 | 导出 |
| --- | --- | --- | --- |
| 脚注 | 仅限 REST API（不包含在扩展回调中） | 无扩展 | 开发中 |
| 尾注 | 仅限 REST API（不包含在扩展回调中） | 无扩展 | 开发中 |

## 导入

脚注和尾注数据只能通过 [REST API](/conversion/import/docx/rest-api) 获取。[编辑器扩展](/conversion/import/docx/editor-extension) 会调用同一个 API，但不会在 `onImport` 回调中包含这些数据。

REST API 会从 DOCX 中提取脚注和尾注，并在响应中以 `footnotes` 和 `endnotes` 字段返回，按注释 ID 编索引。正文中的行内引用会表示为带有 `noteId` 属性的 `footnoteReference` 和 `endnoteReference` 节点。

<Callout variant="warning" title="扩展不会提供脚注/尾注数据">
  如需访问脚注和尾注数据，请直接使用 [REST API](/conversion/import/docx/rest-api)。正文中的 `footnoteReference` 和 `endnoteReference` 节点需要通过[自定义扩展](/editor/extensions/custom-extensions/extend-existing)才能在编辑器中渲染。有关处理策略，请参阅[无效 schema 指南](/guides/invalid-schema)。
</Callout>

如果直接使用 REST API，每个脚注和尾注的值都是一个 Tiptap JSON 文档（`{ type: "doc", content: [...] }`）。如何使用这些数据由你决定。你可以将注释作为编号列表追加到文档末尾，在自定义侧边栏中渲染，或存储起来以供日后使用。

## 编辑器

Tiptap 和 Tiptap Pro 均没有脚注或尾注扩展。编辑器 schema 没有内置的节点类型或标记类型来表示脚注引用或脚注内容。

若要在编辑器中渲染脚注，你需要构建一个自定义扩展来处理 `footnoteReference` 和 `endnoteReference` 节点类型，并提供用于显示注释内容的界面。

## 导出

[编辑器扩展](/conversion/export/docx/editor-extension)和 [REST API](/conversion/export/docx/rest-api) 均不会导出脚注或尾注。目前无法在导出的 DOCX 文件中生成脚注或尾注。

## 替代方案

如果你的工作流需要在编辑器和导出的文档中包含类似脚注的内容，可以考虑以下替代方案：

- **行内括号注释**：将脚注内容转换为正文中的括号注释。这样可以完整保留往返转换的内容。
- **尾注部分**：在文档末尾追加一个手动维护的“注释”部分，使用常规段落和编号文本。
- **自定义处理**：使用导入回调提取脚注数据，将其与文档一同存储，并在自定义导出步骤中重新注入。
