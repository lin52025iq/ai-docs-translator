DOCX 文档中的图片会在导入时提取、在编辑器中渲染，并在导出时重新嵌入。Image 扩展不包含在 StarterKit 中，必须单独安装。

## 所需内容

- **扩展（推荐）：** [`ConvertKit`](/conversion/import/docx/convertkit)。它的自定义 Image 在基础 Image 扩展的基础上声明了 `cropTop`、`cropBottom`、`cropLeft`、`cropRight`，因此 DOCX 裁剪元数据可以通过 schema 验证并保留下来。
- **扩展（最低要求）：** `@tiptap/extension-image`（不包含在 StarterKit 中）。基础扩展会渲染 `src`、`alt`、`title`、`width`、`height`。在此配置下，DOCX 裁剪属性会在 schema 验证时被丢弃。
- **配置：** 无论使用哪种扩展配置，都需要在导入扩展或 REST API 请求中通过 `imageUploadConfig` 配置图片上传端点。

<Callout title="导入时必须配置 imageUploadConfig" variant="warning">
  导入 DOCX 时，图片会从文件中提取为二进制 Blob。如果没有 `imageUploadConfig`，生成的 `src` 值将无法解析，图片也会显示为损坏状态。必须提供上传端点，以便转换器将每张图片 POST 到该端点，并将内部引用替换为真实 URL。
</Callout>

## 支持概览

| 功能 | 导入 | 编辑器 | 导出 | 备注 |
| --- | --- | --- | --- | --- |
| 行内图片 | 支持 | 支持 | 支持 | 导入时需要配置 imageUploadConfig |
| 浮动/环绕图片 | 部分支持 | 不支持 | 不支持 | 锚定图片会被转换，但不会跟踪环绕类型。所有图片都会变为行内图片。背景/水印图片（`behindDoc`）会被跳过。 |
| 图片尺寸 | 支持 | 支持 | 支持 | 从 EMU 值提取宽度和高度，并作为像素属性传递给图片节点。导出时会读取 width/height 属性。 |
| 替代文本 | 支持 | 支持 | 支持 | 导入时会从 `wp:docPr` 提取 `descr` 和 `title`。编辑器节点中的 alt 会在导出时映射为 DOCX 替代文本。 |
| 格式（PNG、JPEG、GIF、BMP、SVG） | 支持 | 支持 | 支持 | |
| EMF/WMF | 支持（导入） | 取决于浏览器 | 不支持（导出） | Windows 矢量格式可能无法往返转换 |
| 图片裁剪 | 支持 | ConvertKit 会保留属性；视觉裁剪需要 CSS | 不支持 | `cropTop`、`cropBottom`、`cropLeft`、`cropRight` 会作为属性提取（百分比值） |
| 图片缩放 | 不适用 | 支持 | 支持 | 缩放后的尺寸可正确导出 |

## 导入

使用[编辑器扩展](/conversion/import/docx/editor-extension)或 [REST API](/conversion/import/docx/rest-api)导入图片。两者都接受 `imageUploadConfig`，并生成相同的输出。转换服务会在这两种方式下处理图片上传。

导入 DOCX 时，每张嵌入的图片都会从 ZIP 存档中提取为 Blob。如果提供了 `imageUploadConfig`，转换器会将每个 Blob POST 到你的上传端点，并将内部引用替换为服务器返回的 URL。

```ts
ImportDocx.configure({
  token: 'your-jwt',
  imageUploadConfig: {
    url: 'https://your-api.example.com/upload',
  },
})
```

如果没有此配置，导入图片的 `src` 值将无法解析。

如果源图片在 Word 中应用了裁剪，裁剪值会作为 `cropTop`、`cropBottom`、`cropLeft` 和 `cropRight` 属性提取（取值为 0 到 100 的百分比）。[ConvertKit](/conversion/import/docx/convertkit) 的自定义 Image 会接受这些属性，并在渲染的 `<img>` 元素上输出为 `data-crop-top`、`data-crop-bottom`、`data-crop-left`、`data-crop-right`。该软件包不包含用于将这些 data 属性转换为视觉裁剪效果的 CSS。若要实现实际裁剪，请添加读取这些属性的 CSS（例如使用 `clip-path`，或使用带有 `overflow: hidden` 的包装元素并设置负的 `object-position`）。如果不使用 ConvertKit，这些值会在 schema 验证时被丢弃。导出时不会保留裁剪值。

<Callout title="尚未完全支持浮动图片" variant="info">
  DOCX 文档中的图片通常会设置文字环绕（四周型、紧密型、衬于文字下方等）。导入时会转换锚定图片，但不会跟踪环绕类型。无论原始定位方式如何，所有图片都会作为行内节点插入。背景或水印图片（`behindDoc`）会被完全跳过。
</Callout>

## 在编辑器中渲染

[`Image`](/editor/extensions/nodes/image) 扩展会添加一个带有 `src`、`alt`、`title`、`width` 和 `height` 属性的 `image` 节点，并将其渲染为标准 `<img>` 标签。它不包含在 StarterKit 中。

```bash
npm install @tiptap/extension-image
```

```ts
import Image from '@tiptap/extension-image'

const editor = new Editor({
  extensions: [
    StarterKit,
    Image.configure({ inline: true }),
  ],
})
```

若要启用拖动缩放控点，请传入 `resize` 选项：

```ts
Image.configure({
  inline: true,
  resize: { enabled: true },
})
```

如果没有 Image 扩展，schema 将无法识别导入的图片节点。有关处理方法，请参阅[无效 schema 指南](/guides/invalid-schema)。

## 导出

使用[编辑器扩展](/conversion/export/docx/editor-extension)或 [REST API](/conversion/export/docx/rest-api)导出图片。该扩展支持通过 [`imageOverrides`](/conversion/export/docx/styles#element-overrides) 自定义输出中的图片默认设置。REST API 不接受图片覆盖设置。

导出时，会获取每个图片节点的 `src` URL，并将二进制数据嵌入 DOCX。支持导出的格式：PNG、JPG、JPEG、GIF、BMP 和 SVG。

如果节点具有 `width` 和 `height` 属性（单位为像素），这些值会转换为磅（1px = 0.75pt）。如果未设置尺寸，导出器会自动检测图片的固有尺寸。如果检测失败，图片默认尺寸为 800x400 像素。

图片节点上的 `alt` 属性会映射到 DOCX 图片的替代文本字段。

### 无法获取图片时

如果图片 URL 返回 404、主机无响应，或图片格式不受支持，该图片会从文档中移除，但文档的其余部分仍会正常导出。如果该图片是其所在段落中唯一的内容，该段落也会被删除，因此不会留下空行。

常见情况是 EMF：Word 会将其用于粘贴的图表和公式，而 DOCX 导出无法嵌入这种格式。

传入 `onWarning` 可查看哪些图片被跳过；也可以设置 `onImageError: 'throw'`，在此情况下让导出失败。请参阅[无法导出的图片](/conversion/export/docx/editor-extension#images-that-cannot-be-exported)。
