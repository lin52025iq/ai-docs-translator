Word 文档使用样式系统，每个段落和文本片段都会引用一个命名样式。转换流程会将已知的段落样式名称解析为对应的 Tiptap 样式，其他样式则会回退为普通段落。`basedOn` 继承链仅用于解析文本片段级别的格式。

无论通过[编辑器扩展](/conversion/import/docx/editor-extension)还是 [REST API](/conversion/import/docx/rest-api) 导入，样式解析的工作方式都相同。导出时，两种方式都支持通过 [`styleOverrides`](/conversion/export/docx/styles) 自定义文档级样式定义。此外，扩展还支持[元素覆盖](/conversion/export/docx/styles#element-overrides)，以便逐个控制元素；REST API 不支持此功能。

## 可识别的段落样式

导入服务可以识别以下段落样式名称（匹配时不区分大小写）。当段落的规范样式名称与其中一项匹配时，会将其转换为对应的 Tiptap 节点：

| Word 样式名称 | Tiptap 节点 | 说明 |
| --- | --- | --- |
| `heading 1` 至 `heading 9`（正则表达式 `/^heading\s*\d+$/i`） | `heading`（级别 1 至 9） | 参见[标题](/conversion/content-types/text-and-formatting/headings) |
| `quote`（精确匹配，不区分大小写） | `blockquote` | 参见[块级元素](/conversion/content-types/structures-and-media/block-elements) |
| 其他所有样式 | `paragraph` | 参见[段落](/conversion/content-types/text-and-formatting/paragraphs) |

## 样式继承

Word 样式可以继承其他样式，类似于类继承。自定义样式“Company Heading”可能基于“Heading 2”，而“Heading 2”又基于“Normal”，由此形成一条父样式链。

导入时，转换器会沿着这条继承链，收集各级祖先样式中的文本格式（字体、字号、粗体、斜体、颜色）。但这条继承链不会用于决定段落转换成哪种节点。节点类型只取决于段落自身的样式名称是否符合已知模式（标题正则表达式或“Quote”）。

这意味着，即使“Company Heading”继承了“Heading 2”的标题格式，使用该样式的段落仍会转换为普通段落节点。要让转换器生成标题，样式名称本身必须符合标题模式（例如“Heading 2”）。

## 字符样式

Word 还支持应用于单个文本片段的字符样式。导入时不会保留字符样式名称。相反，解析时已将解析出的格式（粗体、斜体、颜色、字号等）反映在文本片段的 CSS 属性中，并映射到 Tiptap 标记。

这意味着，如果应用了“Strong”样式的文本片段解析后为粗体，就会生成 `bold` 标记，因为其格式包含 `font-weight: bold`。“Strong”样式名称本身会被舍弃。

如果渲染器不支持自定义字符样式中的非标准格式（小型大写字母、字间距、文本效果），这些格式就会丢失。

## 编辑器

Tiptap 没有样式扩展。编辑器也没有 Word 段落样式或字符样式的概念。每种内容类型都有自己的扩展（Heading、Blockquote、CodeBlock、Paragraph），格式则通过标记处理。

如需将文档中命名样式的排版效果（即 `Heading 1`、`Normal`、`Quote` 等样式的视觉定义）作为级联 CSS 引入编辑器，而非作为逐节点属性，请使用实验性的 [CSS 注入](/conversion/import/docx/css-injection)功能。该功能会提取样式目录，并将其注入为带作用域的 `<style>` 标签，或以 `cssStyles` 对象的形式提供给你。此功能涵盖的 16 个选择器和 11 项属性（仅限排版；不包括单侧边框和字间距）在该页面中有详细说明。

## 导出

每种 Tiptap 节点类型都映射到固定的 Word 样式：

| Tiptap 节点 | 导出的 Word 样式 |
| --- | --- |
| `paragraph` | Normal |
| `heading`（级别 1 至 6） | Heading 1 至 Heading 6 |
| `blockquote` 子节点 | Quote |
| 列表项 | List Paragraph |

原始文档中的自定义样式不会在往返转换中保留。以“Legal Disclaimer”样式导入的段落，导出时会变为“Normal”。

| Heading 1 | Aptos Light | 16pt | 粗体，颜色 #2E74B5 |
| Heading 2 | Aptos Light | 14pt | 粗体，颜色 #2E74B5 |
| Heading 3 | Aptos | 13pt | 粗体，颜色 #2E74B5 |
| Heading 4 | Aptos | 12pt | 粗体，颜色 #2E74B5 |
| Heading 5 | Aptos | 11pt | 粗体，颜色 #2E74B5 |

| Subtitle | Aptos Light | 16pt | 斜体，灰色，居中 |

### 自定义导出样式

使用 `styleOverrides` 覆盖任意默认样式或添加新样式。覆盖项会与默认值进行深度合并：`id` 相同的项会递归合并，新的 `id` 则会追加。

```ts
ExportDocx.configure({
  styleOverrides: {
    paragraphStyles: [
      {
        id: 'Normal',
        name: 'Normal',
        run: {
          font: 'Calibri',
          size: 24,        // half-points (24 = 12pt)
        },
        paragraph: {
          spacing: {
            after: 200,    // twips (200 = 10pt)
            line: 276,     // 240ths of a line (276 = 1.15)
          },
        },
      },
    ],
  },
})
```

<Callout title="样式定义中的单位" variant="info">
  字号以半磅为单位（24 = 12pt）。间距值以 twip 为单位（20 twip = 1pt）。行距以行的 240 分之一为单位（240 = 单倍行距，276 = 1.15）。这些单位来自 `docx` 库，与 OOXML 规范一致。
</Callout>
