Word 中的页眉和页脚用于在每页顶部和底部显示重复内容。导入 API 会从 DOCX 文件中提取页眉和页脚内容；安装 [Pages 扩展](/pages/getting-started/overview) 后，扩展可以自动将这些内容应用到编辑器中。导出扩展则会将它们写回 DOCX。

## 所需内容

- **扩展：** 导入使用 `@tiptap-pro/extension-import-docx`，导出使用 `@tiptap-pro/extension-export-docx`
- **在编辑器中渲染：** [`Pages`](/editor/extensions/functionality/pages) 扩展，用于编辑页眉/页脚以及自动应用导入的页眉/页脚

## 导入

使用[编辑器扩展](/conversion/import/docx/editor-extension)或 [REST API](/conversion/import/docx/rest-api) 导入页眉和页脚。两者返回相同的页眉/页脚数据。安装 [Pages 扩展](/editor/extensions/functionality/pages) 后，编辑器扩展还会自动将页眉和页脚应用到编辑器中。REST API 则返回原始数据，供你自行处理。

DOCX 导入服务会从源文档中提取页眉和页脚内容。响应中最多包含六个有内容的字段（另有两个始终为 null 的占位字段），涵盖页眉和页脚的默认、首页以及奇偶页变体。

安装 [Pages 扩展](/editor/extensions/functionality/pages) 后，使用编辑器扩展时，导入的页眉和页脚会通过 `setEditorContent()` 自动应用到编辑器中。未安装 Pages 扩展时，页眉/页脚数据仍可通过 `onImport` 回调获取，以便手动处理。

### 可用字段

| 字段              | 说明                                                               |
| ----------------- | ------------------------------------------------------------------ |
| `header`          | 默认页眉内容                                                       |
| `footer`          | 默认页脚内容                                                       |
| `headerFirstPage` | 首页页眉（在 Word 中启用“首页不同”时）                             |
| `footerFirstPage` | 首页页脚                                                           |
| `headerOdd`       | 始终为 `null`（见下方说明）                                         |
| `footerOdd`       | 始终为 `null`（见下方说明）                                         |
| `headerEven`      | 偶数页页眉                                                         |
| `footerEven`      | 偶数页页脚                                                         |

每个字段都包含有效的 Tiptap JSON；如果源文档中没有对应变体，则为 `null`。

<Callout variant="info" title="奇数页页眉会返回在默认字段中">
  Word 的 OOXML 模型使用三种页眉类型：`default`、`first` 和 `even`。在 Word 中启用“奇偶页不同”时，奇数页显示的是 **default** 页眉。API 与此一致：

- `header` / `footer` 包含 **默认**（奇数页）内容。
- `headerEven` / `footerEven` 包含偶数页内容。
- `headerFirstPage` / `footerFirstPage` 包含首页内容。
- `headerOdd` / `footerOdd` 始终为 `null`。它们仅为保持响应结构对称而保留。

要获取奇数页页眉，请读取 `context.header`（而不是 `context.headerOdd`）。如果源文档只引用首页和偶数页页眉，却没有默认页眉，响应中就不会有奇数页内容：导入器无法生成源文档中不存在的内容。

</Callout>

<Callout variant="info" title="自动应用需要 Pages 扩展">
  未安装 Pages 扩展时，导入扩展仍会在回调中返回页眉/页脚数据，但无法自动将其应用到编辑器。你可以通过
  `onImport` 回调获取这些数据，并在自己的代码中处理。
</Callout>

<Callout variant="info" title="`PAGE` 和 `NUMPAGES` 字段会作为 `{page}` / `{numpages}` 标记导入">
  安装 Pages 扩展后，Word 的 `PAGE` 和 `NUMPAGES` 字段代码默认会转换为规范的文本标记：`PAGE` 对应 `{page}`，`NUMPAGES` 对应 `{numpages}`。Pages 扩展可原生渲染 `{page}`，因此 Word 页眉中的“第 5 页，共 12 页”会导入为“第 {page} 页，共 {numpages} 页”，并立即显示实时页码。若要让 `{numpages}` 也实时渲染，请配置 `Pages.configure({ placeholders: { total: 'numpages' } })`。在 `importDocx` 命令中传入 `placeholders: false`，即可禁用转换，改为导入缓存的显示值（例如字面文本“第 5 页，共 12 页”）。其他字段代码（如 `DATE` 和 `AUTHOR`）仍会以缓存的显示值导入。请参阅 [DOCX 导入 → 页码字段](/conversion/import/docx/editor-extension#page-number-fields)。
</Callout>

## 编辑器

[Pages 扩展](/editor/extensions/functionality/pages)可在分页布局中全面支持页眉和页脚。如需完整的设置和配置说明，请参阅[页面页眉和页脚指南](/pages/core-concepts/page-header-footer)。

Pages 扩展支持三种与 Word 行为一致的页眉/页脚模式：

- **默认：** 每页使用相同的页眉和页脚
- **首页不同：** 首页使用单独的页眉/页脚
- **奇偶页不同：** 奇数页和偶数页使用不同的页眉/页脚

页码通过占位符渲染：`{page}` 表示当前页，`{total}` 表示总页数。Pages 扩展会在编辑器渲染每一页时替换这些占位符；导出时，[`ExportDocx` 编辑器扩展](/conversion/export/docx/editor-extension)会将它们输出为实时的 `PAGE` / `NUMPAGES` 字段，因此导出的文档会在 Word 中显示真实页码。REST API 导出端点也会输出相同的实时字段。请参阅下方的[导出](#export)部分。

导入后，用户可以双击导入的页眉或页脚进行编辑。Pages 扩展通过 `editor.storage.pages` 提供当前活动的浮层编辑器，并提供 `headerEditorOn` / `headerEditorOff`（以及 `footerEditorOn` / `footerEditorOff`）事件订阅辅助函数，可用于同步工具栏或响应焦点变化。请参阅页面页眉和页脚指南中的[活动编辑器状态](/pages/core-concepts/page-header-footer#active-editor-state)。

## 导出

使用[编辑器扩展](/conversion/export/docx/editor-extension)或 [REST API](/conversion/export/docx/rest-api) 导出页眉和页脚。两者都支持默认、首页和奇偶页变体。扩展接受 `docx.js` 的 Header/Footer 对象，或自动从 Pages 扩展中提取内容。REST API 接受纯文本字符串、序列化为字符串的 Tiptap JSON，或 Tiptap JSON 对象。

对于 PDF 导出，扩展接受的插槽值类型更丰富（纯文本、序列化为字符串的 JSONContent、JSONContent 对象、`docx.Header`/`Footer` 实例，以及按需构建页眉的异步工厂函数）。完整列表请参阅 [PDF 页眉和页脚指南](/conversion/export/pdf/headers-footers)。

同时安装 Pages 扩展和导出扩展时，页眉/页脚内容会自动从 Pages 扩展存储中提取，无需额外配置。

未安装 Pages 扩展时，可以通过导出选项手动提供页眉和页脚：

```ts
import { Docx } from '@tiptap-pro/extension-export-docx'

ExportDocx.configure({
  headers: {
    default: new Docx.Header({
      children: [new Docx.Paragraph({ text: 'My Document' })],
    }),
  },
  footers: {
    default: new Docx.Footer({
      children: [new Docx.Paragraph({ text: 'Confidential' })],
    }),
  },
})
```

页眉和页脚均支持 `default`、`first` 和 `even` 变体。提供相应变体时，`differentFirstPage` 和 `evenAndOddHeaders` 标志会自动设置。

显式设置的页眉/页脚选项优先于从 Pages 扩展自动提取的内容。

<Callout variant="info" title="`{page}` 和 `{total}` 会渲染为实时 DOCX 页码字段">
  页眉或页脚包含 `{page}` 或 `{total}` 时，[`ExportDocx` 编辑器
  扩展](/conversion/export/docx/editor-extension)会将每个标记输出为实时的 `PAGE` /
  `NUMPAGES` 字段，因此 Word 显示的是当前页码和总页数，而不是字面标记字符串。这适用于从 Pages 扩展自动提取的页眉和页脚，也适用于传入 `placeholders` 选项的直接 `convertHeader` / `convertFooter` 调用。[REST
  API](/conversion/export/docx/rest-api) 会在所有页眉和页脚插槽形式中转换相同的标记，也接受 `{numpages}` 作为 `{total}` 的同义标记。对于更复杂的构造（例如超出单纯标记的“第 X 页，共 Y 页”格式），也可以手动提供 `Docx.Header` /
  `Docx.Footer` 实例，并使用 `Docx.PageNumber.CURRENT` / `Docx.PageNumber.TOTAL_PAGES`。
</Callout>

### 往返转换

安装 Pages 扩展后，页眉和页脚可以完整经历从导入到导出的往返转换。导入扩展会提取并应用页眉/页脚内容，导出扩展则会将其写回 DOCX。通过 Pages 扩展在编辑器中创建的内容，或通过导出配置提供的内容，也会正确出现在导出的 DOCX 中。

页码往返转换需要满足一个条件。`{page}` 无需配置。使用默认 Pages 配置时，导入会将总页数写为 `{numpages}`，但 Pages 和导出扩展期望的是 `{total}`。配置 `Pages.configure({ placeholders: { total: 'numpages' } })`，即可让总页数在编辑器中渲染，并再次作为实时的 `NUMPAGES` 字段导出。否则，`{numpages}` 在这两处都会保留为字面文本。
