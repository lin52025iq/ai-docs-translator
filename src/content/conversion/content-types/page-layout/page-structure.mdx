页面结构涵盖控制内容如何跨页流动的元素：分页符、分节、页面大小、页边距和页码。分页符可以在转换流程中往返保留。其他页面结构属性仅部分受支持。

## 所需内容

- **扩展：** `@tiptap-pro/extension-pagebreak`（不包含在 StarterKit 中），以及用于分页布局的 [`Pages`](/pages/getting-started/overview)
- **导出选项：** 在导出扩展或 REST API 中设置 `pageSize` 和 `pageMargins`
- **集成方式：** 通过[编辑器扩展](/conversion/import/docx/editor-extension)和 [REST API](/conversion/import/docx/rest-api) 导入和导出的效果相同。两种导出方式都接受 `pageSize` 和 `pageMargins`。

## 支持情况一览

| 功能 | 导入 | 编辑器 | 导出 |
| --- | --- | --- | --- |
| 分页符 | 支持 | 支持（PageBreak） | 支持 |
| 页面大小 | 不支持 | 支持（[Pages](/pages/getting-started/overview)） | 支持（可配置） |
| 页边距 | 不支持 | 支持（Pages） | 支持（可配置） |
| 分节 | 部分支持（提取并应用分栏配置） | 不支持 | 仅支持单个分节 |
| 页码 | 支持（PAGE/NUMPAGES → `{page}`/`{numpages}` 标记，见[下文](#page-numbers)） | 支持（通过页眉/页脚） | 支持。编辑器扩展和 REST API 会在页眉/页脚中将 `{page}`/`{total}` 标记输出为动态 `PAGE`/`NUMPAGES` 字段。REST API 也接受 `{numpages}`。 |
| 分栏 | 导入时支持（创建 columns/column 节点） | 不支持 | 不支持 |

## 分页符

分页符可以在整个转换流程中完整往返保留。详情请参阅专门介绍[分页符](/conversion/content-types/page-layout/page-breaks)的页面。

## 页面大小和页边距

DOCX 中的页面大小和页边距不会被导入。解析器会从分节属性中读取这些值，但 Tiptap 渲染器会将其丢弃。

[Pages 扩展](/pages/getting-started/overview)提供可配置页面大小和页边距的分页布局。配置详情请参阅[页面格式指南](/pages/core-concepts/page-format)。

导出扩展接受 `pageSize` 和 `pageMargins` 选项：

```ts
ExportDocx.configure({
  pageSize: {
    width: '21.0cm',
    height: '29.7cm',
  },
  pageMargins: {
    top: '2.54cm',
    bottom: '2.54cm',
    left: '3.17cm',
    right: '3.17cm',
  },
})
```

值可使用 CSS 样式的单位：`cm`、`in`、`pt`、`pc`、`mm`、`px`。默认值会生成采用 Word 标准页边距的 A4 页面。

<Callout variant="info" title="Pages 与导出之间不会自动同步">
  导出扩展不会自动从 Pages 扩展读取页面大小或页边距。如果编辑器使用自定义页面格式，请在导出配置中传入相应的值。
</Callout>

## 分节

Word 文档可以包含多个分节，每个分节都有自己的页面布局属性（大小、方向、页边距、分栏、页眉/页脚）。转换流程对分节的支持有限：

- **导入：** 使用分节边界检测多栏布局。多栏分节会被包装为 `columns`/`column` Tiptap 节点。其他分节级属性（大小、方向、页边距）会被解析，但不会应用。
- **编辑器：** Tiptap 没有分节概念，但可以原生渲染分栏节点。
- **导出：** 只生成单个分节。无法创建混合纵向/横向页面或包含多个分节的文档。

## 页码

Word 中的页码是页眉和页脚中的字段代码（`PAGE`、`NUMPAGES`）。安装 Pages 扩展后，导入时会将这些代码转换为规范文本标记（`PAGE` 对应 `{page}`，`NUMPAGES` 对应 `{numpages}`）；也可以选择显式启用：在[编辑器命令](/conversion/import/docx/editor-extension#page-number-fields)中设置 `placeholders: true`（或 `{ page?, total? }`），或在 [REST API](/conversion/import/docx/rest-api#page-number-fields) 中使用 `placeholders={}` 表单字段。导出时，[编辑器扩展](/conversion/export/docx/editor-extension)会将页眉/页脚内容中的 `{page}` / `{total}` 标记输出为动态 `PAGE` / `NUMPAGES` 字段，以便 Word 在打印或重新分页时重新计算。REST API 导出也会执行相同的转换；传入 `placeholders: false` 可将标记保留为普通文本。

Pages 扩展默认识别 `{page}` 和 `{total}`，但**不**识别 `{numpages}`。若要在导入后让 Word 的 `NUMPAGES` 字段在编辑器预览中动态显示，请配置 `Pages.configure({ placeholders: { total: 'numpages' } })`。请参阅 [DOCX 导入 → 页码字段](/conversion/import/docx/editor-extension#page-number-fields)。

## 往返转换支持情况

| 功能 | 是否可往返转换？ | 说明 |
| --- | --- | --- |
| 分页符 | 是 | 需要 `@tiptap-pro/extension-pagebreak` |
| 页面大小 | 否 | 分别为编辑器（Pages）和导出单独配置 |
| 页边距 | 否 | 分别为编辑器（Pages）和导出单独配置 |
| 分节 | 部分支持 | 分栏配置会保留；其他分节属性不会保留 |
| 页码 | 是 | Word `PAGE` / `NUMPAGES` ↔ `{page}` / `{numpages}`（Pages 中总页数的规范名称是 `{total}`；配置 `placeholders: { total: 'numpages' }` 即可进行转换）。REST API 导出时无需此设置即可识别 `{numpages}`。 |
| 分栏 | 部分支持 | 导入时会创建分栏节点；导出时尚不会将其写回 |
