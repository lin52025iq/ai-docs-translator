字体族和字号是通过 `textStyle` 标记传递的行内文本样式属性。其模式与[文本颜色和高亮](/conversion/content-types/text-and-formatting/text-color-highlight)相同：以 TextStyle 为基础，再叠加特定扩展。

## 所需内容

- **扩展：** [`ConvertKit`](/conversion/import/docx/convertkit)。其捆绑的 `TextStyleKit` 在一个扩展中提供 `TextStyle`、`Color`、`BackgroundColor`、`FontFamily`、`FontSize` 和 `LineHeight`。
- **配置：** 无需配置。

```ts
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'

new Editor({ extensions: [ConvertKit] })
```

<Callout title="请勿使用已弃用的独立字号包" variant="warning">
  请勿单独安装 `@tiptap/extension-font-size`，也不要分别引入
  `@tiptap/extension-font-family` 和 `@tiptap/extension-font-size`。所有功能都已包含在
  `TextStyleKit` 中，并由 ConvertKit 自动注册。
</Callout>

## 支持概览

|                | 导入                                      | 编辑器                                                                  | 导出                      |
| -------------- | ------------------------------------------- | ----------------------------------------------------------------------- | --------------------------- |
| 字体族         | 支持（`textStyle.fontFamily`）              | 支持（FontFamily）                                                      | 支持（仅保留第一个字体）    |
| 字号           | 支持（`textStyle.fontSize`，单位为 px）     | 支持（FontSize）                                                        | 支持（px、pt、rem、em）     |
| 字间距         | 支持（`textStyle.letterSpacing`，单位为 px）| 需扩展 TextStyle（ConvertKit / TextStyleKit 未捆绑此功能）              | 不支持                      |

## 导入

可通过[编辑器扩展](/conversion/import/docx/editor-extension)或 [REST API](/conversion/import/docx/rest-api)导入字体族和字号。两者产生的输出完全相同。

转换服务会读取 `<w:rFonts>` 的 `w:ascii` 属性；如果没有 `w:ascii`，则使用 `w:hAnsi`。原始属性值会原样存储在 `textStyle.fontFamily` 中（例如 `"Courier New"`）。

字号取自 `<w:sz>`，单位为半磅，并使用 ConvertKit 的 OOXML 注册表中的 `halfPointsToPixels` 转换为像素：

```ts
import { halfPointsToPixels } from '@tiptap-pro/extension-convert-kit/ooxml-registry'

halfPointsToPixels(24) // 12pt -> 16px
```

请使用此辅助函数，而不要自行编写换算公式，这样得到的值才能与导入器完全一致。结果会通过 `Math.round()` 四舍五入到最接近的整数像素。12pt（16px）、14pt（19px）和 18pt（24px）等常见字号都能准确转换。结果会存储在 `textStyle.fontSize` 中（例如 `"16px"`）。

文本运行中的 `<w:spacing>` 也会提取字间距（从 twip 转换为像素），并存储在 `textStyle.letterSpacing` 中。ConvertKit 捆绑的 `TextStyleKit` 和 [CSS 注入](/conversion/import/docx/css-injection)都不会渲染此属性。字间距是典型的“已提取但默认不渲染”的情况。若要在编辑器中显示它，请为 `TextStyle` 扩展 `letterSpacing` 属性，并使其在 `renderHTML` 中输出 `style="letter-spacing: ..."`。[设置转换后内容的样式](/conversion/getting-started/guides/styling-converted-content#extending-extensions-for-unsupported-attributes)指南提供了可直接复制粘贴的示例。导出时不会保留字间距。

## 编辑器渲染

[`FontFamily`](/editor/extensions/functionality/fontfamily) 和 [`FontSize`](/editor/extensions/functionality/fontsize) 都依赖于 [`TextStyle`](/editor/extensions/marks/text-style)。这三者都包含在 `TextStyleKit` 中，并由 ConvertKit 自动注册：

```bash
npm install @tiptap-pro/extension-convert-kit
```

字体族会在 `<span>` 元素上渲染为 `style="font-family: ..."`，字号则渲染为 `style="font-size: ..."`。如果禁用了 `ConvertKit.configure({ textStyleKit: false })`，则架构无法识别导入的属性。请参阅[无效架构指南](/guides/invalid-schema)了解如何处理。

## 导出

可通过[编辑器扩展](/conversion/export/docx/editor-extension)或 [REST API](/conversion/export/docx/rest-api)导出字体族和字号。两者对字体族和字号的处理方式完全相同。

导出时会清理字体族值：移除引号，并且对于以逗号分隔的值，仅使用第一个字体。由于导入时只会产生单个字体名称，因此往返转换的值会原样保留。

<Callout title="字体回退列表会被合并" variant="info">
  DOCX 不支持 CSS 样式的字体回退列表。如果编辑器内容包含手动设置的值，例如
  `"Arial, Helvetica, sans-serif"`，导出器会选取第一个字体名称（`Arial`），
  并丢弃其余名称。从 DOCX 导入的值已经是单个字体名称，不受影响。
</Callout>

字号会根据单位进行处理。没有单位的值或带 `px` 单位的值会被视为像素，并使用 `pixelsToHalfPoints` 转换为半磅：

```ts
import { pixelsToHalfPoints } from '@tiptap-pro/extension-convert-kit/ooxml-registry'

pixelsToHalfPoints(16) // 16px -> 24 half-points (12pt)
```

带有单位的值会按其单位处理，而不会被视为像素：

- `pt` 会直接映射为磅，因此 `12pt` 导出后仍为 12pt（24 个半磅）。
- `rem` 和 `em` 会以 16px 为基准进行换算（例如 `1rem` 为 16px）。

不带单位的数字仍按像素处理，因此从 DOCX 导入的内容（其中 `textStyle.fontSize` 以 px 存储）往返转换后不会改变。

从 DOCX 导入的值在导出时会得到相同的半磅值，前提是原始半磅值能够转换为整数像素。如果导入时 `Math.round()` 改变了像素值（例如 14pt 转换为 18.67px 后四舍五入为 19px），导出的半磅值就会与原值不同（19px 会导出为 28.5 个半磅，而原值为 28）。无法解析的字号会被跳过，并在控制台输出警告。
