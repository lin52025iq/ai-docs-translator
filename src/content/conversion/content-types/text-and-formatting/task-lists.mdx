Word 复选框列表会转换为 Tiptap 的 `taskList` 和 `taskItem` 节点，并在导入和导出时保留勾选状态。导入此功能需显式启用，因为不包含这些任务节点的编辑器无法渲染它们。

## 所需内容

- **扩展：**[`ConvertKit`](/conversion/import/docx/convertkit) 内置 `TaskList` 和 `TaskItem`。`TaskItem` 配置了 `nested: true`，以确保导入的嵌套列表有效。
- **配置：**编辑器扩展会为你处理此配置。使用 REST API 时，请传入 `taskLists: "import"`。

## 支持概览

|                       | 导入             | 编辑器                 | 导出    |
| --------------------- | ---------------- | ---------------------- | ------- |
| 复选框列表            | 支持，需显式启用 | 支持（ConvertKit）     | 支持    |
| 勾选状态              | 支持             | 支持                   | 支持    |
| 嵌套复选框列表        | 支持             | 支持                   | 支持    |

列表以外的复选框仍按现有方式处理。导出的复选框在 Word 中仍可交互。下文将分别介绍这两种情况。

## 导入

通过[编辑器扩展](/conversion/import/docx/editor-extension)或 [REST API](/conversion/import/docx/rest-api)启用此功能。

```js
ImportDocx.configure({
  token: 'your-jwt',
  // 'auto' is the default: it imports task lists when your editor can render
  // them, and leaves them as bullet lists when it cannot.
  taskLists: 'auto',
})
```

`auto` 会检查编辑器架构中是否同时包含 `taskList` 和 `taskItem`。使用 `ConvertKit` 时，这两个节点始终存在，因此 `auto` 会导入任务列表。传入 `'import'` 可强制导入；传入 `'ignore'` 则会保留原有行为，将复选框列表导入为项目符号列表或编号列表。

<Callout title="REST API 默认忽略" variant="info">
  编辑器扩展能够获知你的架构，因此默认值可以是 `auto`。直接调用 REST API 时无法获知架构，所以 `taskLists` 在那里默认设为 `"ignore"`。传入 `taskLists: "import"` 即可获取任务节点。
</Callout>

### 可识别的复选框

Word 有多种表示复选框的方式，其中三种可以转换：

- **字形项目符号。**在文档的编号设置中，将方框字符用作列表项目符号，例如 Wingdings `U+F06F` 或 Unicode 投票方框 `U+2610`。这是实际文档中最常见的复选框列表。勾选状态由字形决定，因此使用已勾选方框绘制的列表会作为已勾选项导入。
- **内容控件。**`w14:checkbox` 控件，这是现代版 Word 插入的复选框，也是 Tiptap 导出的格式。勾选状态由控件决定。
- **旧式表单域。**较早版本 Word 中的表单域复选框。状态取自表单域；如果当前值缺失，则使用其默认值。

只有当复选框是段落中**唯一**的复选框，并且位于文本**之前**时，才会转换为任务项。这样可以区分清单和表单。例如 `Yes ☐ No ☐` 这样的行，或位于句子之后的复选框，仍按现有方式导入。

像 Wingdings `U+F0FC`（✔）这样的勾号字形不会被视为复选框。这类符号是实际文档中最常见的装饰性项目符号；若将其识别为复选框，普通列表和表格中的勾号就会被误转为清单。

<Callout title="编号列表包含复选框时，编号会丢失" variant="warning">
  如果编号列表中的每一项都以一个复选框开头，该列表会作为任务列表导入，因此编号会丢失。对于清单而言，复选框比编号更有意义；但如果需要保留编号，请使用 `taskLists: 'ignore'` 导入。
</Callout>

## 编辑器渲染

`TaskList` 和 `TaskItem` 来自 [`ConvertKit`](/conversion/import/docx/convertkit)，无需额外安装。有关各自的选项和命令，请参阅 [`TaskList`](/editor/extensions/nodes/task-list) 和 [`TaskItem`](/editor/extensions/nodes/task-item) 扩展页面。

任务列表会渲染为 `<ul data-type="taskList">`，其中包含 `<li data-type="taskItem" data-checked="true|false">`。每个任务项都包含一个放置复选框的 `<label>`，以及一个放置该项内容的 `<div>`。

`ConvertKit` 内置了这些节点的布局，因此复选框会与项目符号的位置对齐，项目文本也会与项目符号和编号列表的文本对齐。无需添加 CSS，即可让清单的外观与导出的文档一致。

### 自定义外观

请设置数据属性的样式，而不要替换布局，以保留 `ConvertKit` 设置的对齐方式：

```css
/* A ticked item */
.tiptap ul[data-type='taskList'] li[data-checked='true'] > div > p {
  color: #6b7280;
  text-decoration: line-through;
}

/* The checkbox itself */
.tiptap ul[data-type='taskList'] li > label input {
  accent-color: #7c3aed;
}
```

如需完全关闭这些节点，或为它们传入自定义选项：

```js
ConvertKit.configure({
  taskList: false,
  taskItem: false,
})
```

## 导出

通过[编辑器扩展](/conversion/export/docx/editor-extension)或 [REST API](/conversion/export/docx/rest-api)导出。两者的行为相同。

任务项会导出为 Word 复选框内容控件，后接该项文本。该控件在 Word 中仍可交互，因此读者可以勾选或取消勾选，并能看到你导出时的勾选状态。

列表项使用 Word 的“列表段落”样式并采用悬挂缩进，因此复选框列表在文档中的缩进与项目符号列表或编号列表相同，各行之间的间距也一致。

嵌套任务列表导出时会使用 Word 嵌套列表的更深缩进。如果任务项包含多个块，复选框会放在第一个块前，其余块也会相应缩进，但不会再出现第二个复选框。

## 往返转换

Word 复选框列表导入后再导出，仍会变回 Word 复选框列表，且勾选状态保持不变。反向转换也是如此：在编辑器中创建任务列表，导出后再导入，其列表项及状态都会保留。

导出时始终会写入内容控件，而不是大多数现有 Word 文档使用的字形项目符号样式。两种格式都能正确导入，因此以字形项目符号形式导入的文档，导出时会变为内容控件。
