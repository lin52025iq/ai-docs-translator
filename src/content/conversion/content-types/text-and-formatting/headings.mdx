在 Word 中，标题是应用了标题样式的段落（Heading 1 到 Heading 9）。Tiptap 将其表示为带有 `level` 属性的 `heading` 节点。

## 所需内容

- **扩展：** [`ConvertKit`](/conversion/import/docx/convertkit)。其中的自定义 Heading 与自定义 Paragraph 类似：间距、缩进、行高、字号和上下文间距均以行内 CSS 渲染。它还内置了 `TextAlign`，并已针对 `['paragraph', 'heading']` 预先配置。
- **配置：** 无需配置。

<Callout title="标题级别可往返转换；视觉样式需要 ConvertKit 或 CSS 注入" variant="hint">
  在任何配置下，标题级别（1 到 6）和对齐方式都可以往返转换。每个标题的属性（间距、缩进、行高以及标题标记上的字号）由 ConvertKit 的自定义 Heading 渲染。Word 样式库中命名样式的排版（例如“Heading 1 为 Aptos Light、16pt、蓝色”）则是另一回事：编辑器使用你的 CSS 渲染标题，而非 Word 主题。若要将样式库作为有作用域的 CSS 引入，请使用实验性的 [CSS 注入](/conversion/import/docx/css-injection)功能。
</Callout>

## 支持概览

| | 导入 | 编辑器（使用 ConvertKit） | 导出 |
| --- | --- | --- | --- |
| 标题级别 1 到 6 | 支持 | 支持 | 支持 |
| Title 和 Subtitle 样式 | 导入为段落（继承样式链中的字体和间距） | 渲染为视觉上类似标题的段落 | 导出为段落 |
| 标题级别 7 到 9 | 在 JSON 中生成 `level: 7`、`8` 或 `9` 的标题节点 | 渲染为 `<h1>`，因为标准 Heading 扩展的 `levels` 选项仅支持 1–6；级别会保留在 JSON 属性中，但标签会被转换。配置 `Heading.configure({ levels: [1,2,3,4,5,6,7,8,9] })`（或覆盖 ConvertKit 的 `heading` 插槽）即可渲染实际标签。 | 在 Word 端导出为 `<h1>`，除非你的编辑器 schema 支持更高级别 |
| 自定义标题样式 | 映射到最接近的标准级别 | 样式名称丢失 | 应用通用标题样式 |
| 文本对齐 | 支持 | 支持（TextAlign） | 支持 |
| 行内格式 | 支持 | 支持 | 支持 |
| 标题编号 | 转换为 indent 属性 | 渲染缩进（`padding-left`）；不会生成编号符号 | 不保留 |
| 每个标题的间距 / 缩进 / 行高 | 转换为属性 | 支持 | 支持（仅支持比例行高；负数首行缩进会转换为悬挂缩进） |
| 每个标题的字号 | 转换为属性 | 支持 | 应用导出默认值 |
| 命名样式排版（主题） | 可通过 [CSS 注入](/conversion/import/docx/css-injection)使用样式库 | 通过注入的 CSS 渲染 | 应用导出默认值 |

## 导入

使用[编辑器扩展](/conversion/import/docx/editor-extension)或 [REST API](/conversion/import/docx/rest-api)导入标题。两者生成的标题输出相同。

转换服务会检测规范名称匹配 `Heading 1` 到 `Heading 9` 的 Word 标题样式（不区分大小写，空格可有可无），并生成具有相应级别的 `heading` 节点。自定义样式名称会被丢弃；仅保留解析出的级别。

**Title 和 Subtitle 不会映射为标题。** 导入器只会检测符合 `Heading N` 模式的样式，因此 Word 中应用了 `Title` 或 `Subtitle` 样式的段落会导入为 `paragraph` 节点。这些样式的字体、字号和间距会沿 `basedOn` 链传递为运行级标记（`textStyle.fontSize`、`textStyle.fontFamily` 等）以及段落级属性，因此导入结果*看起来*像标题，尽管它并不是标题节点。输出不会保留原始样式名称，因此开发者无法仅凭 JSON 判断哪些段落原来是 `Title`，哪些是 `Normal`。如果你的应用需要让 Title/Subtitle 具有 `<h1>`/`<h2>` 语义，目前的解决方法是在导入前预处理 DOCX 文件（例如使用 docx 编辑器），将这些样式重命名为 `Heading 1` 和 `Heading 2`。

转换服务会按以下结构输出标题节点：

```json
{
  "type": "heading",
  "attrs": {
    "level": 2,
    "textAlign": "center"
  },
  "content": [
    {
      "type": "text",
      "text": "My Heading",
      "marks": [
        { "type": "bold", "attrs": {} }
      ]
    }
  ]
}
```

<Callout variant="warning" title="标题级别 7–9 会渲染为 h1">
  Word 支持 1 到 9 级标题，导入转换器也能识别全部九个级别。`Heading` 扩展的默认 `levels` 选项为 `[1,2,3,4,5,6]`；当节点级别不在允许列表中时，其 `renderHTML` 会回退到 `levels[0]`（即 `1`）。因此，导入的 7、8、9 级标题默认会在编辑器中渲染为 `<h1>`。级别值会保留在节点 JSON 的 `attrs.level` 中，因此数据不会丢失；只有渲染出的标签会被转换。若要渲染实际的 `<h7>`–`<h9>` 标签（或你想要的任何标签映射），请将完整级别范围传给 `Heading.configure`：

```ts
ConvertKit.configure({
  heading: { levels: [1, 2, 3, 4, 5, 6, 7, 8, 9] },
})
```
</Callout>

### 保留的内容

- 标题级别（JSON 中为 1 到 9；若不扩展 `levels` 选项，级别 7 到 9 会渲染为 `<h1>`）
- 标题中的行内格式（粗体、斜体、颜色和字体，作为子文本节点上的标记）
- 文本对齐（作为 `textAlign` 属性）
- 段落前后间距（作为 `spacingBefore` 和 `spacingAfter` 属性；由 ConvertKit 的自定义 Heading 渲染为 `margin-top` / `margin-bottom`）

### 丢失的内容

标准 `Heading` 扩展的 schema 只定义了 `level`。安装 ConvertKit 后，自定义 Heading 还会渲染 `spacingBefore`、`spacingAfter`、`lineHeight`、`fontSize`、`indent`、`indentRight`、`firstLineIndent` 和 `contextualSpacing`，并在 JSON 中保留 `keepNext` 和 `keepLines`。不使用 ConvertKit 时，调用 `setEditorContent()` 会剥除这些属性。

无论编辑器如何配置，以下内容仍会丢失：

- **每个标题的边框和背景。** 导入器不会提取这些内容。
- **Word 的命名样式排版。** 编辑器中的 Heading 1 会呈现为 CSS 为 `<h1>` 定义的样式，而不是 Word 的“Heading 1”主题样式。若要引入样式库，请使用 [CSS 注入](/conversion/import/docx/css-injection)。
- **标题编号符号。** Word 编号（例如“1.2.3”）会在标题上生成 `indent` 属性。ConvertKit 会渲染缩进，但导入器和编辑器都不会生成编号前缀本身。

如需处理与 schema 不匹配的内容，请参阅[无效 schema 指南](/guides/invalid-schema)；如需扩展扩展以支持 ConvertKit 未覆盖的属性，请参阅[设置转换后内容的样式](/conversion/getting-started/guides/styling-converted-content)指南。

## 编辑器渲染

[`Heading`](/editor/extensions/nodes/heading) 扩展由 [`ConvertKit`](/conversion/import/docx/convertkit) 注册，并根据 `level` 属性将标题节点渲染为 `<h1>` 到 `<h6>` HTML 标签。ConvertKit 会替换为自定义 Heading，以呈现 DOCX 相关属性（间距、缩进、行高、字号和上下文间距）。

### 内置文本对齐

ConvertKit 还会注册 `TextAlign`，并预先将其配置为适用于 `['paragraph', 'heading']`，因此导入的 DOCX 标题中的 `textAlign` 属性会自动渲染。如果禁用了内置的 `textAlign` 插槽，该属性仍会保留在 JSON 中，但不会应用。请参阅[无效 schema 指南](/guides/invalid-schema)。

### 与 Word 的视觉差异

编辑器使用你的 CSS 样式渲染标题，而不是 Word 的主题样式。Word 中的 Heading 2（通常为 Aptos Light、13pt、蓝色）在编辑器中的显示会有所不同，除非你将 `h2` 设置为匹配的样式。文档结构会保留。视觉效果由你通过编辑器 CSS 控制。有关如何管理样式，请参阅[设置转换后内容的样式](/conversion/getting-started/guides/styling-converted-content)指南。

## 导出

使用[编辑器扩展](/conversion/export/docx/editor-extension)或 [REST API](/conversion/export/docx/rest-api)导出标题。该扩展支持 [`paragraphOverrides` 和 `textRunOverrides`](/conversion/export/docx/styles#element-overrides)，可精细控制标题段落和文本运行的默认样式。REST API 不接受元素覆盖。若要通过 REST API 自定义标题样式，请使用 [`styleOverrides`](/conversion/export/docx/styles) 重新定义标题文档样式。

导出转换器会将 `heading` 节点转换为具有相应标题样式的 DOCX 段落。文本对齐方式（`left`、`center`、`right`、`justify`）会正确导出。

**级别映射：** `level: 1` → Word Heading 1，`level: 2` → Word Heading 2，以此类推，最高到级别 6。

### 自定义导出的标题样式

导出时会为每个标题级别应用特定的默认样式：Aptos Light 字体、蓝色（#2E74B5）以及各级别对应的字号。如果导出的文档要用于企业模板或品牌，这些默认值很可能不符合要求。可通过 `styleOverrides` 自定义：

```ts
ExportDocx.configure({
  styleOverrides: {
    paragraphStyles: [
      {
        id: 'Heading1',
        name: 'Heading 1',
        run: {
          font: 'Arial',
          size: 32,        // half-points (32 = 16pt)
          bold: true,
          color: '000000',
        },
        paragraph: {
          spacing: {
            before: 240,   // twips (240 = 12pt)
            after: 120,    // twips (120 = 6pt)
          },
        },
      },
    ],
  },
})
```

### 往返转换的内容

居中对齐且包含粗体彩色文本的 Heading 2，经过完整的导入 → 编辑 → 导出流程后仍会保留。标题级别、对齐方式和行内格式都会保留。

发生变化的是：导出的标题将使用导出时的默认样式（或覆盖后的样式），而不是原始 DOCX 的主题样式。字体、字号、间距和颜色由导出配置决定，不会从原始文档中继承。
