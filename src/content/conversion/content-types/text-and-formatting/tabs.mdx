Word 文档使用制表符在段落中对齐、缩进和排列内容。Tiptap 和 HTML 没有原生的制表位概念，因此导入时会将制表符转换为空格。

## 所需内容

- **扩展：** 无需其他扩展。制表符内容会转换为纯文本。
- **配置：** 无。

## 支持情况概览

| | 导入 | 编辑器 | 导出 |
| --- | --- | --- | --- |
| 制表符（段落中间） | 转换为四个空格 | 纯文本（空格） | 空格仍保留为空格 |
| 制表符（段落开头） | 在 JSON 中转换为四个空格；在编辑器中视觉上会折叠 | 默认不可见（见下文） | 空格仍保留为空格 |
| 制表位位置 | 不保留 | 不支持 | 不支持 |

## 导入

使用[编辑器扩展](/conversion/import/docx/editor-extension)或 [REST API](/conversion/import/docx/rest-api) 导入制表符。两者对制表符的处理方式相同。

导入转换器在文本运行中遇到 `<w:tab/>` 元素时，会将其替换为四个空格字符。Word 的制表位位置（在段落或样式属性中定义的左对齐、居中、右对齐、小数点对齐和竖线制表位）不会被提取或保留。

转换与位置无关：段落开头和段落中间的制表符都会在 JSON 中转换为四个空格。由于浏览器渲染空白字符的方式不同，最终的视觉效果也会有所差异（见下文“编辑器渲染”）。

## 编辑器渲染

导入时，制表符会转换为空格，因此编辑器接收到的是普通文本内容。Tiptap 中没有制表位或制表符的概念。

<Callout title="段落开头的空格默认不可见" variant="info">
  制表符转换成的四个空格会保存在 JSON 中，并原样传递给编辑器，但在默认的 `white-space: normal` 设置下，浏览器会折叠连续的空白字符。因此，段落开头的制表符渲染出来就像一个贴着段落左边缘的空格，视觉上仿佛制表符被删除了。这是 HTML 的标准空白字符处理规则，并非导入时进行了修剪。句子中间的制表符也会折叠为一个空格；由于两侧都有文字，通常不会影响阅读。

  若要保留视觉上的缩进，可以在编辑器的段落样式中设置 `white-space: pre-wrap`，或者在将内容载入编辑器之前，在 `onImport` 回调中将开头的空格转换为不换行空格（` `）。
</Callout>

## 导出

导出的 DOCX 中，空格仍然是空格。空格不会转换回制表符。原先在 Word 中使用制表符的内容，导出后会以空格呈现。
