DOCX 导入 API 可将 `.docx` 文件转换为 Tiptap 的 JSON 格式。它使用与[编辑器扩展](/conversion/import/docx/editor-extension)相同的转换服务，因此生成的内容完全一致。

如果你需要在服务器端处理文件、访问脚注或尾注数据（扩展不会提供这些数据），或者需要未经架构筛选的原始 JSON，那么 REST API 是更好的选择。如果你希望内容直接加载到 Tiptap 编辑器，并自动应用页眉和页脚，请改用[编辑器扩展](/conversion/import/docx/editor-extension)。

## 导入 DOCX

`POST /v2/convert/import/docx`

`/v2/convert/import/docx` 端点可将 `docx` 文件转换为 Tiptap 的 JSON 格式。用户可以向此端点发送 `POST` 请求，并使用各种参数自定义转换过程中对不同文档元素的处理方式。

### 示例（cURL）

```bash
curl -X POST "https://api.tiptap.dev/v2/convert/import/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -F "file=@/path/to/your/file.docx" \
    -F 'imageUploadConfig={"url":"https://your-image-upload-endpoint.com","headers":{"Authorization":"Bearer your-upload-token"}}' \
    -F "prosemirrorNodes={\"nodeKey\":\"nodeValue\"}" \
    -F "prosemirrorMarks={\"markKey\":\"markValue\"}"
```

<Callout title="需要订阅" variant="warning">
  此端点需要有效的 Tiptap 订阅。详情请参阅我们的[定价页面](https://tiptap.dev/pricing)。
</Callout>

### 必需的请求头

| 名称            | 说明                                                                       |
| --------------- | -------------------------------------------------------------------------- |
| `Authorization` | 用于验证请求的 JWT 令牌。例如：`Bearer your-jwt-token`                     |

### 请求正文

| 名称                | 类型                   | 说明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `file`              | `File`                 | 要转换的文件                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `imageUploadConfig` | `JSON string`          | 配置图片上传的 JSON 对象。包含必填的 `url`，以及可选的 `headers`、`method` 和 `queryParams`。完整架构请参阅[编辑器扩展文档](/conversion/import/docx/editor-extension#image-upload-configuration)。                                                                                                                                                                                                                                                                                                                                                         |
| `prosemirrorNodes`  | `Object string`        | 转换时使用的自定义节点映射，[了解详情](/conversion/import/docx/custom-node-mapping)。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `prosemirrorMarks`  | `Object string`        | 转换时使用的自定义标记映射，[了解详情](/conversion/import/docx/custom-mark-mapping)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `extractCssStyles`  | `"true" \| "false"`    | **实验性功能。**设为 `"true"` 时，响应中会包含 `cssStyles` 字段，其中包含转换为 CSS 兼容键值对的 DOCX 样式目录。默认值为 `"false"`。有关输出格式和注意事项，请参阅 [CSS 样式提取](#css-style-extraction-experimental)。                                                                                                                                                                                                                                                                                                                                 |
| `placeholders`      | `JSON string`          | 启用后，可将页眉和页脚中的 Word `PAGE` / `NUMPAGES` 域代码转换为规范的 `{page}` / `{numpages}` 文本标记。发送 `{}`（空对象）可使用线格式默认值启用；发送 `{ "page"?: string, "total"?: string }` 可通过重命名映射启用（例如，`{"total":"pages"}` 会使 `NUMPAGES` 转换为 `{pages}`）；发送 `false` 可明确禁用。省略此参数（默认行为）时，Word 缓存的显示值会保留为纯文本。此选项与编辑器的 `Pages.configure({ placeholders })` 选项一致；编辑器扩展会自动将其转发到此处。请参阅[页码域](#page-number-fields)。 |
| `documentName`      | `String`               | 目标 Tiptap Collaboration 文档名称。若请求令牌具有该文档的 `Documents:Write` 权限，服务会将导入的评论串与 Document Server 同步，使其在导入时即可生效。请参阅[响应中的评论](#comments-in-the-response)。可选；如果令牌没有此权限，或环境中没有 Document Server，则忽略此参数。                                                                                                                                                                                                                                        |
| `taskLists`         | `"import" \| "ignore"` | 是否将 Word 复选框列表转换为 `taskList` / `taskItem` 节点。默认值为 `"ignore"`，即将其作为项目符号列表或编号列表导入。如果编辑器注册了任务节点，请发送 `"import"`。请参阅[任务列表](/conversion/content-types/text-and-formatting/task-lists)。                                                                                                                                                                                                                                                                                                                             |
| `trackedChanges`    | `String`               | 如何处理 Word 插入和删除的内容：`preserve` 将其保留为建议，`accept` 应用更改，`reject` 丢弃更改。默认值为 `accept`。请参阅[修订](/conversion/import/docx/tracked-changes)。                                                                                                                                                                                                                                                                                                                                                                                    |

### 响应中的警告和错误

每个响应都会在 `data` 旁附带一个 `logs` 对象，其中包含 `warn` 和 `error` 数组。警告表示某些内容未能导入文档，因此值得告知上传文件的用户。

```js
{
  "data": {
    "content": {
        // Tiptap JSON
    }
  },
  "logs": {
    "warn": [
      {
        "message": "Image skipped: No imageUploadConfig was provided, so images cannot be imported.",
        "fileName": "image1.gif"
      }
    ],
    "error": [
      {
        "message": "Image upload failed: General error",
        "fileName": "image1.gif",
        "url": "https://your-image-upload-endpoint.com",
        "error": "Unable to connect. Is the computer able to access the url?",
        "context": "uploadImage general error"
      }
    ]
  }
}
```

## 响应中的页眉和页脚

导入 API 会从 `.docx` 文件中提取页眉和页脚。如果文档包含页眉或页脚内容，响应的 `data` 对象中会包含其他字段。

### 响应字段

| 字段              | 类型             | 说明                                                                   |
| ----------------- | ---------------- | ---------------------------------------------------------------------- |
| `content`         | `Object`         | 以 Tiptap JSON 表示的文档主体                                           |
| `header`          | `Object \| null` | 以 Tiptap JSON 表示的默认页眉内容                                       |
| `footer`          | `Object \| null` | 以 Tiptap JSON 表示的默认页脚内容                                       |
| `headerFirstPage` | `Object \| null` | 首页页眉（在 Word 中启用“首页不同”时）                                  |
| `footerFirstPage` | `Object \| null` | 首页页脚（在 Word 中启用“首页不同”时）                                  |
| `headerOdd`       | `Object \| null` | 奇数页页眉（在 Word 中启用“奇偶页不同”时）                              |
| `footerOdd`       | `Object \| null` | 奇数页页脚（在 Word 中启用“奇偶页不同”时）                              |
| `headerEven`      | `Object \| null` | 偶数页页眉（在 Word 中启用“奇偶页不同”时）                              |
| `footerEven`      | `Object \| null` | 偶数页页脚（在 Word 中启用“奇偶页不同”时）                              |

### 响应示例

```json
{
  "data": {
    "content": {
      "type": "doc",
      "content": [
        {
          "type": "paragraph",
          "content": [{ "type": "text", "text": "Document body content..." }]
        }
      ]
    },
    "header": {
      "type": "doc",
      "content": [
        {
          "type": "paragraph",
          "content": [{ "type": "text", "text": "Default Header" }]
        }
      ]
    },
    "footer": {
      "type": "doc",
      "content": [
        {
          "type": "paragraph",
          "content": [
            { "type": "text", "text": "Page " },
            { "type": "text", "text": "{page}" },
            { "type": "text", "text": " of " },
            { "type": "text", "text": "{numpages}" }
          ]
        }
      ]
    },
    "headerFirstPage": {
      "type": "doc",
      "content": [
        {
          "type": "paragraph",
          "content": [
            {
              "type": "text",
              "text": "Title Page Header",
              "marks": [{ "type": "bold" }]
            }
          ]
        }
      ]
    },
    "footerFirstPage": null,
    "headerOdd": null,
    "footerOdd": null,
    "headerEven": null,
    "footerEven": null
  }
}
```

字段值为 `null` 表示文档未在相应的页眉或页脚位置定义内容。

### 页码域

默认情况下，页眉和页脚中的 Word `PAGE` 和 `NUMPAGES` 域代码会作为 Word 上次打开文档时存储的缓存显示值导入（例如字面文本 `1`）。在请求中传入 `placeholders={}`，即可将这些域转换为规范的文本标记：`PAGE` 对应 `{page}`，`NUMPAGES` 对应 `{numpages}`。识别到域指令后，缓存的数字值会被丢弃。

服务可识别以下三种格式的域：

- Word 常见的格式：域的每个部分都位于单独的 run 中。
- 整个域打包在单个 run 中。Tiptap 自己导出 DOCX 时会采用这种格式，因此将 Tiptap 导出的文件重新导入后，页码会恢复为标记。
- 页码被包裹在块级内容控件中，这是 Word 的“插入”→“页码”库添加页码的方式。

服务不会转换以简单 `w:fldSimple` 域形式编写的 `PAGE` 或 `NUMPAGES` 域，并会丢弃其缓存值。这适用于任何 `placeholders` 值，包括 `false`；`false` 会使其他格式中的缓存数字保留为纯文本。

```bash
curl -X POST "https://api.tiptap.dev/v2/convert/import/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -F "file=@/path/to/your/file.docx" \
    -F "placeholders={}"
```

下游使用方（例如 [Pages 扩展](/pages/getting-started/overview)）会根据自身配置识别的标记名称替换 `{page}` 和 `{numpages}`。若要使线格式与自定义标记注册表匹配，请将 `placeholders` 作为包含 `page` 和/或 `total` 键的 JSON 对象传入：

```bash
curl -X POST "https://api.tiptap.dev/v2/convert/import/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -F "file=@/path/to/your/file.docx" \
    -F 'placeholders={"page":"page","total":"total"}'
```

上例将 `NUMPAGES` 映射为 `{total}`（Pages 中总页数字段的默认名称），因此编辑器预览无需任何配置即可原生替换。线格式字段与 `Pages.configure({ placeholders })` 直接对应；安装 Pages 扩展后，[编辑器扩展](/conversion/import/docx/editor-extension)会自动将其转发到此处。

## 响应中的脚注和尾注

导入 API 会从 `.docx` 文件中提取脚注和尾注。如果文档包含脚注或尾注内容，响应的 `data` 对象中会包含其他字段。

### 响应字段

| 字段        | 类型     | 说明                                                                                                       |
| ----------- | -------- | ---------------------------------------------------------------------------------------------------------- |
| `footnotes` | `Object` | 以脚注 ID 为键的对象，每个值都是一个 Tiptap JSON 文档（`{ type: "doc", content: [...] }`）                 |
| `endnotes`  | `Object` | 以尾注 ID 为键的对象，每个值都是一个 Tiptap JSON 文档（`{ type: "doc", content: [...] }`）                 |

没有脚注或尾注的文档会返回空对象（`{}`），因此不会影响现有集成。

文档主体中的行内引用会表示为 `footnoteReference` 和 `endnoteReference` 节点；每个节点都带有 `noteId` 属性，用于关联 `footnotes` 或 `endnotes` 中对应的条目。

### 响应示例

```json
{
  "data": {
    "content": {
      "type": "doc",
      "content": [
        {
          "type": "paragraph",
          "content": [
            { "type": "text", "text": "This sentence has a footnote" },
            { "type": "footnoteReference", "attrs": { "noteId": "1" } },
            { "type": "text", "text": " and an endnote" },
            { "type": "endnoteReference", "attrs": { "noteId": "1" } },
            { "type": "text", "text": "." }
          ]
        }
      ]
    },
    "footnotes": {
      "1": {
        "type": "doc",
        "content": [
          {
            "type": "paragraph",
            "content": [{ "type": "text", "text": "This is the footnote content." }]
          }
        ]
      }
    },
    "endnotes": {
      "1": {
        "type": "doc",
        "content": [
          {
            "type": "paragraph",
            "content": [{ "type": "text", "text": "This is the endnote content." }]
          }
        ]
      }
    },
    "header": null,
    "footer": null,
    "headerFirstPage": null,
    "footerFirstPage": null,
    "headerOdd": null,
    "footerOdd": null,
    "headerEven": null,
    "footerEven": null
  }
}
```

## 响应中的页面布局和列表编号

另外两个字段用于描述整个文档，而不是文档内容。

| 字段               | 类型    | 说明                                                                                                                                                                |
| ------------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pageLayout`       | `Object` | 从文档节属性中读取的纸张大小、方向和页边距。值以 twip 为单位。请参阅[应用页面布局](#applying-the-page-layout)。                                                      |
| `numberingFormats` | `Array`  | 文档中有序列表和项目符号列表所使用的编号定义。每个列表节点都有一个 `numberingFormat` 属性，用于指明此处对应的条目。                                                    |

如果文档没有可报告的内容，则不会返回这两个字段。

在编辑器中注册 `numberingFormats`，以便列表保留其编号；并将其传递给导出器，以便往返转换时保留编号。[列表编号和项目符号](/conversion/export/docx/ordered-list-numbering)页面介绍了完整流程。

### 应用页面布局

`pageLayout` 报告的是 Word 中的页面设置，而不是 [Pages 扩展](/pages/getting-started/overview)所需的格式，因此使用前需要先进行转换：

```json
{
  "width": 12240,
  "height": 15840,
  "orientation": "portrait",
  "margins": {
    "top": 1440,
    "right": 1440,
    "bottom": 1440,
    "left": 1440,
    "header": 720,
    "footer": 720
  }
}
```

所有尺寸均以 twip 为单位，而 Pages 的 `setPageFormat` 需要像素值和 `id`。请使用 ConvertKit 的 OOXML 注册表中的 `twipsToPixels`，而不是自行编写转换逻辑，这样计算结果才能与转换服务使用的数值一致：

```ts
import { twipsToPixels } from '@tiptap-pro/extension-convert-kit/ooxml-registry'

// 没有节属性的文档中不会包含此字段。
if (pageLayout) {
  editor.commands.setPageFormat({
    id: 'docx-import',
    width: twipsToPixels(pageLayout.width),
    height: twipsToPixels(pageLayout.height),
    margins: {
      top: twipsToPixels(pageLayout.margins.top),
      right: twipsToPixels(pageLayout.margins.right),
      bottom: twipsToPixels(pageLayout.margins.bottom),
      left: twipsToPixels(pageLayout.margins.left),
    },
  })
}
```

`header` 和 `footer` 页边距没有对应的 `setPageFormat` 参数，因此请将它们省略。

<Callout variant="info" title="使用共享的单位转换辅助函数">
  OOXML 注册表导出了转换流程两端共用的单位转换函数，包括
  `twipsToPixels`、`pixelsToTwips`、`halfPointsToPixels`、`emuToPixels` 和 `twipsToPoints`，以及
  `TWIPS_PER_PIXEL` 等常量。使用这些函数可确保数值与导入器和导出器完全一致。自行编写计算逻辑，通常会导致文档往返转换后略有偏差。
</Callout>

注册 Pages 扩展后，[编辑器扩展](/conversion/import/docx/editor-extension)会自动为你完成此转换，因此只有使用 REST 接口时才需要手动转换。

## 响应中的评论

导入 API 会从 `.docx` 文件中提取评论串。如果文档包含评论，响应的 `data` 对象中会包含 `commentThreads` 数组。文档主体包含 `inlineThread` 标记（以及 `blockThread` 节点），其中的 `data-thread-id` 与各评论串的 `id` 相对应，因此你可以将评论串关联回其批注的文本。

### 响应字段

| 字段                         | 类型      | 说明                                                                                                     |
| ---------------------------- | --------- | -------------------------------------------------------------------------------------------------------- |
| `commentThreads`             | `Array`   | 每个评论串对应一个条目。文档没有评论时，该数组为空或省略。                                                |
| `commentThreads[].id`        | `String`  | 评论串 ID。与 `content` 中该评论串的 `inlineThread` / `blockThread` 上的 `data-thread-id` 相对应。       |
| `commentThreads[].durableId` | `String`  | Word 稳定的持久 ID（如果存在）。                                                                         |
| `commentThreads[].resolved`  | `Boolean` | 评论串是否已解决。                                                                                       |
| `commentThreads[].messages`  | `Array`   | 评论串中的消息，先列出根消息，再按日期升序列出回复。                                                      |
| `messages[].wId`             | `String`  | 评论原始 DOCX `w:id`。                                                                                   |
| `messages[].id`              | `String`  | Document Server 生成的评论 ID。仅在同步后存在（见下文）。                                                 |
| `messages[].durableId`       | `String`  | 规范化后的持久 ID（如果存在）。                                                                           |
| `messages[].body`            | `Object`  | 以 Tiptap JSON 表示的消息正文。                                                                           |
| `messages[].data`            | `Object`  | 作者和日期元数据：`author`、`initials?`、`providerId?`、`userId?`、`dateIso?`、`dateUtc?`。               |

没有评论的文档会返回空的 `commentThreads` 数组，因此不会影响现有集成。`/import/docx` 和通用的 `/import` 都会返回相同的数据。

### 与 Document Server 同步

默认情况下，返回的评论串和消息 ID 均源自 DOCX；评论串的 `id` 与 `content` 中的 `data-thread-id` 标记相对应，因此客户端可以自行持久化评论串。

如果要让服务将导入的评论与 Document Server 同步，请在令牌对该文档拥有 `Documents:Write` 权限的请求中传入 `documentName`：服务会在 Document Server 中创建或更新评论串，然后将返回的 `commentThreads` 和正文标记中的 ID 都替换为服务器生成的 ID。这样导入后评论即可生效，并且会填充 `messages[].id`。如果未提供 `documentName`、令牌没有 `Documents:Write` 权限，或环境中没有 Document Server，则会跳过同步，并原样返回 DOCX 中生成的 ID。

### 响应示例

```json
{
  "data": {
    "content": {
      "type": "doc",
      "content": [
        {
          "type": "paragraph",
          "content": [
            {
              "type": "text",
              "text": "Reviewed text",
              "marks": [{ "type": "inlineThread", "attrs": { "data-thread-id": "abc123" } }]
            }
          ]
        }
      ]
    },
    "commentThreads": [
      {
        "id": "abc123",
        "resolved": false,
        "messages": [
          {
            "wId": "0",
            "body": {
              "type": "doc",
              "content": [
                {
                  "type": "paragraph",
                  "content": [{ "type": "text", "text": "Please cite a source." }]
                }
              ]
            },
            "data": {
              "author": "Ada Lovelace",
              "initials": "AL",
              "dateIso": "2026-01-01T10:30:00Z",
              "dateUtc": "2026-01-01T10:30:00Z"
            }
          }
        ]
      }
    ]
  }
}
```

## CSS 样式提取（实验性功能）

<Callout title="实验性功能" variant="warning">
  `extractCssStyles` 为可选的实验性功能。响应格式可能会在不另行通知的情况下发生变化。如果你依赖此功能，请固定使用确切的客户端版本，并阅读 [CSS 注入文档](/conversion/import/docx/css-injection)，了解支持的选择器、CSS 属性和已知限制的完整列表。
</Callout>

在请求中传入 `extractCssStyles=true`，即可在响应中包含 `cssStyles` 字段。该字段包含从 DOCX 默认样式目录转换而来的 CSS 兼容键值对，并以 CSS 选择器为键。

### 请求

```bash
curl -X POST "https://api.tiptap.dev/v2/convert/import/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -F "file=@/path/to/your/file.docx" \
    -F "extractCssStyles=true"
```

### 响应字段

| 字段        | 类型     | 说明                                                                                                                                                                                                                                             |
| ----------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `cssStyles` | `Object` | 以 CSS 选择器为键的对象，每个值都是一个 CSS 属性对象。文档中没有可提取的默认样式时，该对象为空（`{}`）。如果未设置 `extractCssStyles` 或其值为 `"false"`，则响应中完全不会包含此字段。 |

### 支持的选择器

提取器会将 DOCX 命名样式映射到以下固定的 CSS 选择器。未匹配此映射的样式不会转换。

`p`、`h1`、`h2`、`h3`、`h4`、`h5`、`h6`、`blockquote`、`ul li`、`ol li`、`strong`、`em`、`u`、`s`、`a`、`code`

### 支持的 CSS 属性

根据 DOCX 样式的定义，每个上述选择器都可以包含以下属性的任意子集。

`color`、`fontSize`、`fontFamily`、`fontWeight`、`fontStyle`、`textDecoration`、`backgroundColor`、`textAlign`、`marginTop`、`marginBottom`、`lineHeight`

### 响应示例

```json
{
  "data": {
    "content": {
      "type": "doc",
      "content": [
        {
          "type": "paragraph",
          "content": [{ "type": "text", "text": "Document body..." }]
        }
      ]
    },
    "cssStyles": {
      "p": {
        "fontSize": "16px",
        "fontFamily": "Calibri",
        "lineHeight": 1.15,
        "marginBottom": "8pt"
      },
      "h1": {
        "fontSize": "28px",
        "fontWeight": "bold",
        "color": "#1F3864",
        "marginTop": "24pt",
        "marginBottom": "6pt"
      },
      "a": {
        "color": "#0563C1",
        "textDecoration": "underline"
      },
      "blockquote": {
        "fontStyle": "italic",
        "color": "#595959"
      }
    }
  }
}
```

关于输出的说明：

- **值为字符串或数字。**基于像素的属性（`fontSize`）会以 `"Npx"` 字符串形式输出；以点为单位的间距（`marginTop`、`marginBottom`）会以 `"Npt"` 形式输出；无单位的倍率（`auto` 行距规则下的 `lineHeight`）会以纯数字形式输出。
- **会解析样式继承关系。**子级 DOCX 样式会包含从父级继承的所有内容（通过 `basedOn`）；输出会展平处理，无需遍历继承链。
- **支持本地化文档。**非英文 Word 版本中的命名样式会在输出前映射回其规范选择器。
- **字段缺失表示“未定义”。**只有至少提取到一个属性时才会出现对应选择器。如果 DOCX 没有样式目录（或所有命名样式都不在 16 个选择器的映射范围内），`cssStyles` 将为 `{}`。

### 自定义节点和标记映射

你可以在请求正文中分别通过 `prosemirrorNodes` 和 `prosemirrorMarks` 指定映射，从而覆盖导入时使用的默认 `node/mark` 类型。如果编辑器使用自定义 `nodes/marks`，并且你希望导入的 `JSON` 使用这些类型，就需要提供相应映射。

每个条目中，键是默认类型名称，值是你希望导入的 JSON 中使用的名称。例如，如果你的架构将段落称为 `textBlock`，请在请求正文中发送 `"{\"paragraph\":\"textBlock\"}"`，导入的每个段落都会使用 `textBlock`。

你也可以调整标题、列表、粗体或斜体等标记，以及更多类型。名称区分大小写，请严格按照下文所列的名称填写。

</Callout>

#### 将 Word 样式映射到标记

`prosemirrorMarks` 还接受第二种条目。如果键是 Word 字符样式的名称，而不是上述标记之一，那么使用该样式的每个 run 都会获得你指定的标记。例如，`"{\"Strong\":\"bold\"}"` 表示所有应用了 `Strong` 样式的 run 都会获得 `bold` 标记。

通过这种方式，你可以将自定义 Word 样式导入架构。完整操作说明请参阅[自定义标记映射](/conversion/import/docx/custom-mark-mapping)。
