您导入的某些文档可能包含需要在转换后的文档中保留的图像。

<Callout title="注意" variant="info">
    Tiptap 不提供图像上传服务。您需要自行实现服务器来处理图像上传。
</Callout>

## 导入图像

如果导入的 DOCX 文件包含图像，只有提供图像上传配置，转换服务才能将这些图像包含在生成的 Tiptap JSON 中。

使用 `imageUploadConfig` 选项指定您服务器上的端点，转换服务会在导入过程中将图像上传到该端点。

```js
 import { Editor } from '@tiptap/core'
 import { ImportDocx } from '@tiptap-pro/extension-import-docx'

 const editor = new Editor({
   // ... other editor options,
   extensions: [
     ImportDocx.configure({
       token: '<your-jwt>',
       imageUploadConfig: {
         url: 'https://your-server.com/upload-image',
       },
     })
   ]
 })
 ```
在此配置中，`imageUploadConfig.url` 设置为您服务器上用于接收图像文件的端点。如果未提供此配置，导入器会从文档中移除图像。

触发导入时，转换服务会将每张嵌入的图像上传到您指定的 URL。

### 经过身份验证的图像上传

如果您的上传端点需要身份验证或自定义标头，可以直接进行配置：

```js
ImportDocx.configure({
  token: '<your-jwt>',
  imageUploadConfig: {
    url: 'https://your-server.com/upload-image',
    headers: {
      Authorization: 'Bearer your-upload-token',
    },
    method: 'PUT',
    queryParams: {
      bucket: 'my-bucket',
    },
  },
})
```

有关所有可用选项，请参阅[图像上传配置](/conversion/import/docx/editor-extension#image-upload-configuration)参考文档。

如果上传标头中包含短期有效的令牌，请改为将 `imageUploadConfig` 传递给 `importDocx` 命令，这样每次导入都会发送新的令牌。请参阅[每次导入时传入新令牌](/conversion/import/docx/editor-extension#pass-a-fresh-token-on-each-import)。

### 回调处理流程
您可以使用任何 Web 框架或云函数实现此端点。需要完成的关键步骤如下：

1. **接收文件：**读取原始请求正文，并从 `File-Name` 标头获取文件名。请参阅[请求的格式](#what-the-request-looks-like)。
2. **存储图像：**将图像保存到可通过 URL 访问的位置，例如 AWS S3 存储桶、Cloudinary 等存储服务，或您服务器上的公共文件夹。为保存的文件生成公共 URL。
3. **返回 URL：**发送 `2xx` 响应，并在 JSON 正文中包含图像的绝对 URL。例如：`{ "url": "https://my-cdn.com/uploads/unique-image-name.png" }`。请参阅[响应必须包含的内容](#what-the-response-must-contain)。

随后，Tiptap 转换服务会获取该 URL，并将其作为图像节点的 `src` 插入 Tiptap JSON。

### 请求的格式

每张图像都会收到一个请求，图像本身就是请求正文中的原始数据。

| 部分           | 值                                                                        |
| -------------- | ---------------------------------------------------------------------------- |
| Method         | `POST`，或您配置的 `method`                                       |
| Body           | 图像原始字节数据。不是 `multipart/form-data`，也没有 `file` 字段 |
| `Content-Type` | 图像的 MIME 类型，例如 `image/png`                              |
| `File-Name`    | 图像的文件名，例如 `image1.png`                              |

因此，请将正文读取为 blob 或 buffer，而不是表单数据。

有两点需要注意：

- **您配置的 `headers` 和 `queryParams` 也会随请求发送**，因此可用于身份验证。`Content-Type` 和 `File-Name` 由转换服务设置，您无法用自己的值替换它们。
- **`File-Name` 来自 DOCX 文件内部**。Word 会将图片命名为 `image1`、`image2` 等，并在每个文档中从 1 重新开始编号。因此，不同导入中的文件可能同名，这个名称只能作为标签，不能作为唯一键。如果使用它来构造存储键，请添加每个文档独有的信息，以区分不同的导入。

您的端点应在 10 秒内响应。响应较慢会导致该图像上传失败。最多可同时进行三次上传，因此端点需要能够处理并发请求。

文档中的所有图像都会被发送，无论其类型是什么。对于 `png`、`jpeg`、`gif`、`bmp`、`tiff`、`webp`、`svg`、`emf` 和 `wmf`，`Content-Type` 根据文件扩展名设置。其他类型会以 `application/octet-stream` 发送，因此请自行决定要保留哪些类型。单张图像的大小和文档中的图像数量均不受限制。

### 响应必须包含的内容

响应状态码为 `2xx`，且 JSON 正文中包含一个字符串类型的 `url`：

```json
{ "url": "https://my-cdn.com/uploads/unique-image-name.png" }
```

`url` 必须是包含主机名的绝对 `http` 或 `https` URL。该值会按您返回的内容原样使用：除了值两侧的空白字符外，不会重新编码或规范化，因此签名 URL 仍能通过验证。

#### 相对 URL 会被拒绝，不会解析

像 `/uploads/image1.png` 这样的路径会被拒绝。转换在我们的服务器上运行，而不是在您的页面中运行，因此没有可用于解析相对 URL 的来源地址；如果猜测一个地址，可能会得到一个悄悄指向错误位置的 URL。请自行返回完整 URL。出于同样的原因，像 `//my-cdn.com/image1.png` 这样的协议相对值也会被拒绝。

#### URL 无法使用时

系统会跳过该图像，其余文档仍会正常导入。上传失败、超时或返回的内容不是 JSON 时，也会发生同样的情况。失败的上传不会重试，也不会导致导入失败。

无论哪种情况，导入的[详细输出](/conversion/import/docx/editor-extension#verbose-output)中都会出现一条指出文件名的消息。如果端点已响应，但其 `url` 无法使用，该消息还会附带以下原因之一：

| 原因                                                                                   | 常见原因                                                                                        |
| ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 响应中不包含 `url` 字段                                               | JSON 中没有 `url` 键，使用了 `location` 或 `src` 等其他键，或将 `url` 设为 `null` |
| `url` 字段不是字符串                                                         | `url` 的值是数字或对象                                                                    |
| `url` 字段为空                                                                | `url` 的值为 `""` 或仅包含空白字符                                                                    |
| URL 中包含空格或控制字符，因此无法按原样使用              | 值中含有未编码的空格或换行符。请在返回前进行百分号编码                    |
| URL 是相对地址；由于处理发生在服务器端，因此没有可供解析的页面 | 类似 `/uploads/image1.png` 的路径，或类似 `//my-cdn.com/image1.png` 的协议相对地址               |
| URL 不是格式正确的绝对 http(s) URL                                        | 缺少斜杠，例如 `https:/my-cdn.com/image1.png`，或完全没有主机名                             |
| 只能使用 http 和 https URL                                                     | 使用了 `s3://` 或 `data:` 等方案                                                                  |

记录的 URL 会在查询字符串之前截断，因此签名 URL 中的令牌不会写入日志。

### 重要注意事项
- **可公开访问：**您提供的端点 URL 必须能从互联网访问，因为 Tiptap 云服务会调用该端点。它不能是 localhost，也不能位于防火墙后。同样，返回的图像 URL 也应可公开访问（或至少能供所有需要查看文档的人访问）。
- **正确的响应格式：**您的端点必须返回一个 JSON 对象，其中包含 `url` 字段，且该字段的值为绝对 `http` 或 `https` URL。其他任何响应都会导致该图像被跳过，详细输出中会显示原因。请参阅[响应必须包含的内容](#what-the-response-must-contain)。
- **安全性：**Tiptap 不限制您使用哪个端点。您可以通过 `imageUploadConfig` 选项传递自定义标头（例如 `Authorization: Bearer ...`）和查询参数进行身份验证。转换服务会在上传图像时转发这些内容。请在您自己的服务端实现必要的身份验证（例如，验证请求标头中的 Bearer 令牌或 API 密钥）。
- **图像持久性：**您返回的 URL 会继续用于编辑器的内容中。例如，导入后，编辑器会包含 `src: "https://my-cdn.com/uploads/unique-image-name.png"` 的图像节点。之后导出或查看该内容的任何人都会尝试加载该 URL。请确保图像在这些 URL 下持续可用（不要立即删除）。

### 服务器实现示例
此示例展示了一个简单的服务器实现，它接收图像上传，并将图像上传到通过环境变量配置的 S3 存储桶。

```ts
 import { serve } from '@hono/node-server'
 import { Hono } from 'hono'
 import { Upload } from '@aws-sdk/lib-storage'
 import { S3Client } from '@aws-sdk/client-s3'

 const {
   AWS_ACCESS_KEY_ID,
   AWS_SECRET_ACCESS_KEY,
   AWS_REGION,
   AWS_S3_BUCKET,
   PORT = '3011',
   AWS_ENDPOINT,
   AWS_FORCE_STYLE,
 } = process.env

 if (!AWS_ACCESS_KEY_ID || !AWS_SECRET_ACCESS_KEY || !AWS_S3_BUCKET) {
   console.error('Please provide AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, and AWS_S3_BUCKET')
   process.exit(1)
 }

 const s3 = new S3Client({
   credentials: {
     accessKeyId: AWS_ACCESS_KEY_ID,
     secretAccessKey: AWS_SECRET_ACCESS_KEY,
   },

   region: AWS_REGION,
   endpoint: AWS_ENDPOINT,
   forcePathStyle: AWS_FORCE_STYLE === 'true',
 })

 const app = new Hono() as Hono<any>

 app.post('/upload', async (c) => {
   const file = await c.req.blob()
   const filename = c.req.header('File-Name')
   const fileType = c.req.header('Content-Type')
   // Word restarts at image1 in every document, so add something unique
   // when building the storage key.
   const key = `${crypto.randomUUID()}-${filename}`

   if (!file) {
     return c.json({ error: 'No file uploaded' }, 400)
   }

   try {
     const data = await new Upload({
       client: s3,
       params: {
         Bucket: AWS_S3_BUCKET,
         Key: key,
         Body: file,
         ContentType: fileType,
       },
     }).done()

     return c.json({ url: data.Location })
   } catch (error) {
     console.error(error)
     return c.json({ error: 'Failed to upload file' }, 500)
   }
 })

 serve({
   fetch: app.fetch,
   port: Number(PORT) || 3000,
 })
```

下面是一个使用 bun 且无需依赖项的实现：

```ts
 const s3Client = new Bun.S3Client({
   accessKeyId: process.env.AWS_ACCESS_KEY_ID,
   secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
   region: process.env.AWS_REGION,
   bucket: process.env.AWS_BUCKET,
   endpoint: process.env.AWS_ENDPOINT,
 })

 Bun.serve({
   port: 8081,
   async fetch(req) {
     const url = new URL(req.url)

     // Handle file uploads on the /upload endpoint
     if (url.pathname === '/upload') {

       const file = await req.blob()
       const filename = req.headers.get('File-Name')!
       const fileType = req.headers.get('Content-Type')!
       // Word restarts at image1 in every document, so add something unique
       // when building the storage key.
       const key = `${crypto.randomUUID()}-${filename}`

       if (!file) {
         return new Response(JSON.stringify({ error: 'No file uploaded' }), {
           status: 400,
           headers: {
             'content-type': 'application/json',
           },
         })
       }

       try {
         // Store under our own key, with the type from the request
         const s3File = s3Client.file(key, { type: fileType })
         // Write the file to S3
         await s3File.write(file)

         return new Response(
           JSON.stringify({
             // Send the URL of the uploaded file back to the client to insert it into the editor
             url: new Response(s3File).headers.get('location'),
           }),
           {
             headers: {
               'content-type': 'application/json',
             },
           },
         )
       } catch (error) {
         return new Response(
           JSON.stringify({
             error: error instanceof Error ? error.message : 'Failed to upload file',
           }),
           {
             status: 500,
             headers: {
               'content-type': 'application/json',
             },
           },
         )
       }
     }

     return new Response(JSON.stringify({ error: 'Not found' }), {
       status: 404,
     })
   },
 })
```
