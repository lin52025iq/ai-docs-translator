经过审阅的 Word 文档会记录是谁插入或删除了哪些内容。导入时，你可以决定如何处理这些记录：将其保留为可在编辑器中审阅的建议、接受修订，或拒绝修订。

## 选择模式

| 模式       | 效果                                                                      |
| ---------- | ------------------------------------------------------------------------- |
| `preserve` | 将插入和删除转换为建议，并保留原作者和日期                                |
| `accept`   | 将插入转换为普通文本，并移除已删除内容                                    |
| `reject`   | 将已删除内容恢复为普通文本，并移除插入内容                                |
| `auto`     | 仅适用于编辑器扩展。根据编辑器的 schema 选择 `preserve` 或 `accept`        |

## 使用编辑器扩展

`ImportDocx` 接受 `trackedChanges` 选项，默认值为 `auto`：

```ts
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

const editor = new Editor({
  extensions: [
    ImportDocx.configure({
      token: 'your-jwt',
      trackedChanges: 'auto',
    }),
  ],
})
```

你也可以针对每次导入单独指定模式，该设置优先于已配置的值：

```ts
editor.commands.importDocx({ file, trackedChanges: 'preserve' })
```

### `auto` 的作用

`auto` 会检查编辑器 schema 中是否存在修订用的 `suggestion` 标记。如果存在，模式就设为 `preserve`；如果不存在，则设为 `accept`。如果你通过 `prosemirrorMarks` 重命名了该标记，`auto` 会查找你指定的名称。

这是因为编辑器会丢弃 schema 不认识的标记，但保留标记所附着的文本。因此，如果编辑器无法呈现建议，却要求使用 `preserve`，每处删除都会变回普通内容，从而悄无声息地撤销审阅者的修改。`auto` 可以避免这种情况，因此除非你明确知道要使用哪种模式，否则请保留默认设置。

<Callout variant="info" title="保留建议需要修订扩展">
  注册 [`@tiptap-pro/extension-tracked-changes`](/tracked-changes/getting-started/overview)，以保留导入的修订标记。否则，请使用 `accept` 或 `reject`，让文档以普通文本的形式导入。
</Callout>

## 使用 REST API

将 `trackedChanges` 作为表单字段发送。它接受 `preserve`、`accept` 和 `reject`，默认值为 `accept`。

```bash
curl -X POST https://api.tiptap.dev/v2/convert/import/docx \
  -H "Authorization: Bearer <your-jwt>" \
  -F "file=@reviewed.docx" \
  -F "trackedChanges=preserve"
```

默认值设为 `accept` 而不是 `preserve`，这样未发送该字段的调用方仍会收到普通内容，也不会收到编辑器无法呈现的建议标记。

## 保留的建议是什么样的

带有修订的文本会获得一个 `suggestion` 标记：

```json
{
  "type": "text",
  "text": "brave ",
  "marks": [
    {
      "type": "suggestion",
      "attrs": {
        "id": "docx-suggestion-1",
        "type": "add",
        "userId": "ada lovelace",
        "createdAt": "2026-07-27T10:00:00Z",
        "updatedAt": "2026-07-27T10:00:00Z",
        "userMetadata": { "name": "Ada Lovelace" }
      }
    }
  ]
}
```

插入的 `type` 为 `add`，删除的 `type` 为 `delete`。替换内容（即审阅者用一段文本替换另一段文本）会以先删除、后插入的形式导入。

Word 仅通过显示名称识别审阅者，因此 `userMetadata.name` 保存该名称，`userId` 则由该名称生成：去除首尾空白、合并连续空白并转换为小写。因此，显示名称相同的审阅者会使用相同的 `userId`。没有作者的修订，其 `userId` 为 `anonymous`，`userMetadata` 为 `null`。

Word 会为每段文本分别写入一条记录，因此一次编辑常常会被拆分成多条。同一作者、类型相同且彼此相邻的记录会合并为一个建议，这样跨越不同格式的修订仍是一个可审阅的整体，而不会被拆成多个。

插入或删除的图像及其他独立内容不会使用标记，而是通过节点属性携带相同信息：`suggestionId`、`suggestionType`、`suggestionUserId`、`suggestionCreatedAt`、`suggestionUpdatedAt` 和 `suggestionUserMetadata`。

## 建议的保留范围

建议会保留在文档正文中，包括表格单元格内的内容。

页眉、页脚、批注和脚注与正文分开编辑，`preserve` 不会作用于这些部分。导入时，这些部分的修订会直接应用，因此页眉中的删除会以已删除文本的形式导入，而不是作为建议。其内容不会丢失。

这是有意为之。这些部分通常使用不包含 `suggestion` 标记的 schema；若在其中保留建议，标记会被移除而文本仍保留，导致删除内容变成实际内容。目前，即使为页眉和页脚编辑器配置修订扩展，也不会改变导入行为。

## 尚未导入的内容（正在开发）

以下两种情况会完整导入文本，只缺少修订记录：

- **段落拆分和合并。** Word 会将这些修订记录在段落标记上，而不是文本上；它们在经过审阅的文档中很常见。段落本身会正确导入，但不会保留段落拆分本身是一次修订这一信息。
- **格式更改**，例如开启修订后将某个词设为粗体。格式会导入，但不会保留它是一次修订这一信息。

移动操作则有所不同，建议你在自己的文档中检查：

- **移动文本**，即审阅者移动了一段文本。Word 会将移动操作写成两部分：源位置和目标位置；目前两部分都无法识别。在依赖移动操作的处理结果之前，请先检查移动过的段落。

## 往返同步

导出来自 Word 的建议时，会将其写回为 Word 插入和删除，并保留作者和日期。请参阅[导出修订](/conversion/export/docx/tracked-changes)。

在 Tiptap 中接受所有修订，结果与在 Word 中接受所有修订相同；拒绝修订也是如此。例外是导出无法写入的情况，包括图像和其他独立内容上的建议。这些建议会以节点属性的形式导入，导出时则作为普通内容写回。请参阅[尚未导出的内容](/conversion/export/docx/tracked-changes#what-is-not-exported-work-in-progress)。
