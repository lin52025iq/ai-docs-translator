## 功能简介

DOCX 文件包含标准 Tiptap 扩展无法识别的格式元数据：以 twips 为单位的段落间距、表格行高规则、图像裁剪百分比、单元格垂直对齐方式以及各边框宽度。如果使用原生 Tiptap 渲染 DOCX 内容，这些信息就会丢失或渲染错误。

**ConvertKit 是一个扩展，可将编辑器配置为处理从 DOCX 导入的内容。** 添加它即可获得：

- 32 个内置扩展，已配置好，可处理 Convert API 生成的所有内容。
- 自定义的 Paragraph、Heading、Image、Table、TableRow、TableCell 和 TableHeader 扩展，可接受 DOCX 专用属性。
- 创建编辑器时注入一小段 CSS 重置样式，用于规范浏览器默认行为，从而准确呈现 DOCX 间距值。
- 每个内置扩展都可以单独配置或禁用。

## 安装

```bash
npm i @tiptap-pro/extension-convert-kit@^0.1.0
```

## 工作原理

主要由三部分组成：

1. **一组预配置的扩展。** ConvertKit 会注册一组精选的 Tiptap 扩展（用于标记和列表的基础扩展，以及支持 DOCX 的段落、标题、图像和表格自定义覆盖扩展）。你可以在 `ConvertKit.configure({…})` 中为任意选项传入 `false`，以排除相应扩展。
2. **架构节点上的 DOCX 属性。** 支持 DOCX 的覆盖扩展会扩展相应的基础扩展，并声明其他属性（段落间距、图像裁剪、表格单元格属性）。转换服务会生成这些属性；ConvertKit 的节点负责渲染它们。
3. **作用域限定的 CSS 重置样式。** ConvertKit 会注入一小段 CSS 重置样式，规范浏览器对段落边距、表格行高、单元格垂直对齐和精确行高的默认处理，从而准确呈现 DOCX 间距值。销毁编辑器时会移除这段样式。

```ts
import { Editor } from '@tiptap/core'
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'

const editor = new Editor({
  extensions: [ConvertKit],
})
```

自定义或禁用特定子扩展：

```ts
new Editor({
  extensions: [
    ConvertKit.configure({
      heading: { levels: [1, 2, 3] }, // only allow H1–H3
      codeBlock: false, // drop the code-block node entirely
      table: false, // swap for a different table stack
    }),
  ],
})
```

## 支持的功能

### 内置扩展

ConvertKit 在单个 `@tiptap-pro/extension-convert-kit` 包中提供 **32** 个扩展。下表供你参考，帮助了解编辑器架构中包含哪些扩展；你无需单独安装或注册它们。

| 类别 | 扩展 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 核心 | `Document`、`Text`、`Paragraph`_、`Heading`_ |
| 标记 | `Bold`、`Italic`、`Underline`、`Strike`、`Code`、`Link` |
| 块 | `Blockquote`、`HorizontalRule`、`HardBreak`、`CodeBlock`、`PageBreak` |
| 列表 | `BulletList`、`OrderedList`、`ListItem`、`ListKeymap`、`TaskList`、`TaskItem`、`OrderedListNumbering`† |
| 媒体 | `Image`\* |
| 样式 | `TextStyleKit`（`TextStyle`、`Color`、`BackgroundColor`、`FontFamily`、`FontSize`、`LineHeight`）、`TextAlign`、`Highlight`（多色）、`Superscript`、`Subscript` |
| UI 辅助 | `Dropcursor`、`Gapcursor` |
| 历史记录 | `UndoRedo` |
| 表格 | `ConvertTableKit`（Table*、TableRow*、TableCell*、TableHeader*） |

标有 `*` 的扩展是自定义的、支持 DOCX 的 Tiptap 基础扩展覆盖版本。它们增加的内容详见下一节。标有 `†` 的扩展虽已内置，但**默认关闭**：可通过同名配置选项启用（参见[配置参考](#配置参考)）。

ConvertKit 还导出了与 `OrderedListNumbering` 配套的辅助函数和类型，用于在编辑器预览中渲染：`generateNumberingFormatCss`、`GenerateNumberingFormatCssOptions`、`NumberingFormatDefinition`、`NumberingLevelDefinition`、`NumberingBaseStyle` 和 `NumberingMarkerFont`。端到端操作指南请参阅[列表编号和项目符号](/conversion/export/docx/ordered-list-numbering)。

### 在 Tiptap 基础扩展之上添加的属性

| 扩展 | 新增属性 | 来源 |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Paragraph` | `spacingBefore`、`spacingAfter`、`lineHeight`、`fontSize`、`indent`、`indentRight`、`firstLineIndent`、`contextualSpacing`、`keepNext`、`keepLines` | 段落标记上的 DOCX `w:pPr` + `w:rPr` |
| `Heading` | 与 `Paragraph` 相同 | 段落标记上的 DOCX `w:pPr` + `w:rPr` |
| `Image` | `cropTop`、`cropBottom`、`cropLeft`、`cropRight` | 图形对象上的 DOCX `a:srcRect` |
| `Table` | `width`、`indent`、各边表格边框（上/下/左/右边框及内部水平和垂直网格的 `width` / `style` / `color`）、`cellMarginTop`、`cellMarginRight`、`cellMarginBottom`、`cellMarginLeft`（默认 `cellMinWidth: 1`，而 Tiptap 默认为 `25`） | DOCX `w:tblW`、`w:tblInd`、`w:tblGrid`、`w:tblBorders`、`w:tblCellMar` |
| `TableRow` | `height`、`heightRule`（`exact` / `atLeast`） | DOCX `w:trHeight` + `w:hRule` |
| `TableCell` / `TableHeader` | `background`、`verticalAlign`、各边边框（上/下/左/右边框的 `width` / `style` / `color`） | DOCX `w:tcPr` |
| `OrderedListNumbering`† | `numberingFormat`，用于 `orderedList` 和 `bulletList` | `ExportDocx` 编号格式注册表；仅处理每种列表最外层的列表。参见[列表编号和项目符号](/conversion/export/docx/ordered-list-numbering)。 |

### CSS 重置样式规范的内容

该重置样式限定在 `.tiptap` 作用域内，并调整了几个可能导致浏览器默认样式与 DOCX 间距不一致的部分：

- **段落间距。** 将段落及其 `*` 后代元素的上下边距设为零，使 DOCX 中定义的间距值（包含各自的段前和段后值）能够准确呈现，而不会叠加浏览器默认边距。
- **表格行高和单元格内边距。** 收紧默认值，确保声明了特定行高的表格能够按指定高度渲染。
- **精确行高会裁切溢出内容。** 对于 `heightRule: "exact"` 的行，通过单元格内部包装元素裁切内容；超出声明行高的内容会被隐藏，与 Word 的行为一致。
- **尾随换行符伪影。** 将 ProseMirror 尾随换行符的边距和内边距设为零，以免在段落末尾引入多余空白。

如果需要覆盖其中任何规则，请在 `.tiptap` 内设置自己的选择器；你的规则优先于重置样式。

### 细微但重要的默认设置

- Table 的 `cellMinWidth: 1`。Tiptap 的默认值为 `25`，会将 DOCX 中用作布局的狭窄间隔列（宽 1–15 px）扩展成明显的空隙。ConvertKit 将最小宽度限制为 `1` px。
- `textAlign` 配置为 `types: ['paragraph', 'heading']`，确保 DOCX 段落对齐方式同时应用于这两种块。
- `highlight` 配置为 `multicolor: true`，因此 DOCX `w:highlight` 颜色会原样保留。

## 无法实现的功能

<Callout variant="warning" title="这些是有意设定的限制">
  这些并非错误，而是此功能明确记录的边界。如果你的工作流依赖以下任何功能，那么此功能并不适合你。
</Callout>

- **浮动表格。** DOCX `w:tblpPr`（相对于锚点定位并带有文字环绕的表格）会渲染为普通的内联堆叠表格。转换器会丢弃定位元数据。这是有意为之；浮动布局的保真度不在支持范围内。
- **负表格缩进。** 小于零的 `w:tblInd` 值会保留在 `attrs.indent` 中，但渲染时会限制为 `0`。Word 会将负缩进渲染到纸张装订线区域；浏览器没有装订线，因此渲染负缩进会把表格推到页面边缘之外。
- **精确行高时的内容溢出。** 对于 `heightRule: "exact"` 的行，溢出内容会通过 `.cell-content` 包装元素的 `overflow: hidden` 裁切。超出声明高度的内容不可见。
- **表格宽度超出容器。** 对于声明的 `width` 超出容器宽度的表格，会使用 `max-width: 100%` 渲染。声明的宽度保留在 `attrs.width` 中，但视觉上会限制在容器范围内。
- **多页布局。** ConvertKit 不会分页。如果你需要跨页表格、实际页面容器，或在视觉上遵循页眉/页脚及分页符，请将 ConvertKit 与 [Pages 扩展](/pages/getting-started/overview)搭配使用，并使用 [PagesTableKit](/pages/guides/pages-tablekit) 提供表格扩展。
- **脚注、尾注和批注。** 不会渲染。转换器会将它们输出为段落或直接丢弃；ConvertKit 不会添加脚注或批注 UI。

## 使用时的预期

- 编辑器挂载期间会应用一小段作用域限定的 CSS 重置样式。同一页面上由 ConvertKit 驱动的多个编辑器会共用这段样式：只插入一次，并且只有在最后一个编辑器销毁时才会移除。
- 在整个应用中一致地渲染从 DOCX 导入的内容。非零 DOCX 裁剪值的图像会实际裁剪；列宽缩小时，`heightRule: "atLeast"` 的行会垂直扩展；`verticalAlign: "center"` 的单元格会将内容垂直居中。
- **列表缩进作用于列表项，而不是段落。** 启用 `orderedListNumbering` 后，导入列表段落的 `indent` 会移动整个列表项（包括标记和文本），而不是给列表项内的段落添加内边距。这样导入的列表项就会位于 Word 中的原始位置，不会在每个嵌套层级上逐渐偏离自己的标记。有关适用条件以及哪些内容仍作用于段落，请参阅[缩进单个列表项](/conversion/export/docx/ordered-list-numbering#indents-on-a-single-item)。
- 与 Tiptap Pro 扩展生态系统的其他部分完全兼容。`@tiptap-pro/extension-import-docx` 和 `@tiptap-pro/extension-export-docx` 是自然搭配；如果需要分页，可在此基础上叠加 `@tiptap-pro/extension-pages-tablekit`。
- **默认排版较紧凑。** CSS 重置样式会将段落边距设为零，并应用较紧凑的行高。如果你用 ConvertKit 处理的内容并非从 DOCX 导入，请在此基础上叠加自己的排版规则。这种重置是有意设计的，并非我们认为视觉效果已打磨完善的默认样式。

## 不应期待的功能

- **超出节点属性层面的 DOCX 保真度。** ConvertKit 会接入 Convert API 生成的属性。如果转换器无法解析某项 DOCX 功能，ConvertKit 也无法渲染它。
- **表格自动调整大小手柄。** ConvertKit 的 Table 扩展继承自 `@tiptap/extension-table`，支持标准的调整大小行为，但默认的 `cellMinWidth: 1` 意味着手柄可以将列拖动到仅 1 px 宽，通常不适合手动编辑。混合处理 DOCX 导入和手动编辑时，请覆盖 `table.cellMinWidth`。

## ConvertKit 未涵盖的内容

ConvertKit 会将 Convert API 生成的所有功能作为 Tiptap 节点和标记处理。部分导入的 DOCX 内容不在此范围内，仍需在应用层处理：

- **脚注和尾注引用。** [导入 REST API](/conversion/import/docx/rest-api) 会返回脚注和尾注数据，但[编辑器扩展](/conversion/import/docx/editor-extension)不会提供这些数据，并且没有 Tiptap 扩展可渲染脚注标记或注释。参见[脚注和尾注](/conversion/content-types/structures-and-media/footnotes-endnotes)。
- **多栏布局。** 导入时会为多栏分节生成 `columns` 和 `column` 节点，但没有编辑器扩展可以渲染这些节点。参见[页面结构](/conversion/content-types/page-layout/page-structure)。
- **目录。** 会导入为 `tableOfContents` 节点。除非添加自定义扩展，否则会渲染为普通内容。参见[支持的功能](/conversion/getting-started/feature-support-matrix)。
- **Word 样式。** 导入时会使用样式名称进行结构检测（标题、引用块、代码块），但不会应用文档样式目录中定义的视觉样式。可将 ConvertKit 与 [CSS 注入](/conversion/import/docx/css-injection)搭配使用，以保留样式目录中的样式；也可参阅 [Word 样式](/conversion/content-types/structures-and-media/word-styles)。
- **数学公式。** Convert API 不会解析 OMML。参见[数学公式](/conversion/content-types/structures-and-media/math-equations)。
- **字符间距。** Convert API 会将字符间距提取为各个文本运行标记上的 `textStyle.letterSpacing`，但内置的 `TextStyleKit` 未声明 `letterSpacing` 属性，因此渲染时会丢弃该值。[CSS 注入](/conversion/import/docx/css-injection)也不会提取此属性（只有导出端编译支持它）。若要渲染导入的字符间距，请扩展 `TextStyle`，添加 `letterSpacing` 属性，并在 `renderHTML` 中输出 `style="letter-spacing: …"`。参见[字体系列和字号](/conversion/content-types/text-and-formatting/font-family-size)。
- **页面布局。** 页面大小、边距、页眉和页脚属于文档级设置。ConvertKit 负责渲染内容；如需分页布局，请将它与 [Pages 扩展](/pages/getting-started/overview)搭配使用。

有关如何扩展 ConvertKit 的内置扩展，以及如何使用 CSS 设置转换后内容的样式，请参阅[转换后内容的样式设置](/conversion/getting-started/guides/styling-converted-content)指南。

## 配置参考

所有键均为可选项。传入 `false` 可排除某个扩展。传入部分选项对象可将其转发给底层扩展的 `configure()`。除下方特别说明外，各键的默认值均为 `{}`。

```ts
ConvertKit.configure({
  document: Record<string, never> | false,
  text: Record<string, never> | false,
  paragraph: Partial<ParagraphOptions> | false,
  heading: Partial<HeadingOptions> | false,
  blockquote: Partial<BlockquoteOptions> | false,
  bold: Partial<BoldOptions> | false,
  italic: Partial<ItalicOptions> | false,
  underline: Partial<UnderlineOptions> | false,
  strike: Partial<StrikeOptions> | false,
  code: Partial<CodeOptions> | false,
  link: Partial<LinkOptions> | false,
  bulletList: Partial<BulletListOptions> | false,
  orderedList: Partial<OrderedListOptions> | false,
  listItem: Partial<ListItemOptions> | false,
  listKeymap: Partial<ListKeymapOptions> | false,
  taskList: Partial<TaskListOptions> | false,
  taskItem: Partial<TaskItemOptions> | false,
  orderedListNumbering: boolean | Partial<OrderedListNumberingOptions>, // default: false; opt in with `true`, or an options object (`defaultFormat`, `defaultBulletFormat`, `formats`)
  hardBreak: Partial<HardBreakOptions> | false,
  horizontalRule: Partial<HorizontalRuleOptions> | false,
  dropcursor: Partial<DropcursorOptions> | false,
  gapcursor: Record<string, never> | false,
  codeBlock: Partial<CodeBlockOptions> | false,
  image: Partial<ImageOptions> | false,
  textStyleKit: Partial<TextStyleKitOptions> | false,
  textAlign: Partial<TextAlignOptions> | false, // default: { types: ['paragraph', 'heading'] }
  highlight: Partial<HighlightOptions> | false, // default: { multicolor: true }
  superscript: Partial<SuperscriptExtensionOptions> | false,
  subscript: Partial<SubscriptExtensionOptions> | false,
  pageBreak: Partial<PageBreakOptions> | false,
  table: Partial<ConvertTableKitOptions> | false,
})
```

<Callout variant="warning" title="启用 `orderedListNumbering` 会改变项目符号列表的 JSON">
  `numberingFormat` 属性会同时注册到 `bulletList` 和 `orderedList` 上。因此启用此选项后，对于未指定格式的项目符号列表，`editor.getJSON()` 会写入 `attrs: { numberingFormat: null }`；此前不会写入任何 `attrs`。这与有序列表一直以来的表现一致，渲染出的 HTML 不会改变：未指定格式的列表仍然是普通的 `<ul>`。逐字节比较项目符号列表的已存储 JSON、协作文档和快照测试会发现这个新键。
</Callout>
