## 快速开始

```bash
npm install pele@1.6.0
```

```ts
import { Diagrams } from '@tiptap-pro/extension-diagrams'
import { peleDiagramRenderer } from '@tiptap-pro/extension-diagrams/pele'
import PeleWorker from '@tiptap-pro/extension-diagrams/pele-worker?worker'

Diagrams.configure({
  diagramRenderers: [peleDiagramRenderer({ worker: () => new PeleWorker() })],
})
```

`pele` 是可选的 peer 依赖，版本固定为 1.6.0。它的标记会随版本更新而变化，而图表编辑功能会读取这些标记。

Worker 的入口是 `@tiptap-pro/extension-diagrams/pele-worker`。使用打包工具的 Worker 导入方式加载它。`?worker` 是 Vite 的写法。

只有 Worker 会加载 Pele 并注册 25 种 [Mermaid 类型](/diagrams/flow-diagrams/overview#mermaid-kinds)。页面只会加载入口 `@tiptap-pro/extension-diagrams/pele`。`PELE_DIAGRAM_KINDS` 列出所有类型。`peleDrawsDiagram(source)` 是渲染器的 `draws` 函数。

## 选项

| 选项     | 类型                   | 说明                                                                                   |
| -------- | ---------------------- | -------------------------------------------------------------------------------------- |
| `worker` | `() => PeleWorkerPort` | 必填。为第一个图表启动一次 Worker。`Worker` 属于 `PeleWorkerPort` 类型。                 |
| `id`     | `string`               | 默认值：`'pele'`                                                                        |
| `label`  | `string`               | 默认值：`'Mermaid (Pele)'`                                                              |

## 与 mermaid.js 对比

两者的文档中存储相同的 Mermaid 源码，区别仅在于绘制方式。对于 `mermaid` 格式，只需注册其中一个，因为每种格式的第一个图表渲染器会负责绘制。

|                             | mermaid.js                                | Pele                                   |
| --------------------------- | ----------------------------------------- | -------------------------------------- |
| 绘制位置                    | 沙盒 iframe                               | Web Worker                             |
| 压缩后体积                  | 约 980 kB                                 | 约 205 kB，位于 Worker 中              |
| 类型                        | 列表中的所有类型                          | 相同                                   |
| 连线                        | 曲线                                      | 直线、直角线                           |
| journey                     | 时间线下方显示人脸                        | 将分数绘制为一条线                     |
| mindmap                     | 放射状                                    | 向两侧延伸的树形结构                   |
| 在图表中编辑文本            | 双击，适用于所有包含文本的类型            | 相同                                   |
| 拖动形状                    | 流程图                                    | 相同                                   |
| 在服务器上运行              | 需要浏览器                                | 可在 Node 中运行，使用 `renderPeleDiagram` |

## 绘制方式

- **源代码中的链接和图像**会被忽略。`click … href` 和 `@{ img: … }` 都不会绘制任何内容。
- **颜色**来自 `--tt-flow-diagram-*` 自定义属性，与 mermaid.js 相同。Pele 会将这些颜色写入 SVG。`toPeleVariables(theme)` 列出了对应关系。
- **图表**会像其他图表一样显示在 `<img>` 中。
- **不使用 `foreignObject`。**标签是 SVG 文本，因此导出 PNG、WebP 和 Word 时无需额外处理。
- **无法解析的源代码**会显示错误状态和 Pele 提供的错误消息。
- **Worker 运行失败时**，所有等待它处理的图表都会被拒绝。下一个图表会启动新的 Worker。

## 在服务器上运行

入口 `@tiptap-pro/extension-diagrams/pele-render` 可在没有页面的情况下绘制图表，可在 Node 或自建 Worker 中运行：

```ts
import { defaultDiagramTheme } from '@tiptap-pro/extension-diagrams/core'
import { renderPeleDiagram } from '@tiptap-pro/extension-diagrams/pele-render'

const { svg, width, height } = renderPeleDiagram({
  format: 'mermaid',
  source: 'flowchart LR\n  A --> B',
  theme: defaultDiagramTheme,
})
```

没有 canvas 时，文本宽度会根据 Pele 内置的字体度量计算。因此，图表可能比在浏览器中宽或窄几像素。

Word 需要在 SVG 旁边提供 PNG。可以使用 resvg 等栅格化工具将 SVG 转换为 PNG。

## 在图表中编辑

`peleDiagramEditing` 会在 Pele 的 SVG 中查找文本和形状，就像 `mermaidDiagramEditing` 对 mermaid.js 所做的那样。请参阅[在图表中编辑](/diagrams/renderers/custom-diagrams#editing-in-the-diagram)。

- **双击**会打开与 mermaid.js 相同的文本。请参阅[双击时可编辑的内容](/diagrams/flow-diagrams/editing#what-a-double-click-edits)。
- **拖动流程图中的形状**会存储与使用 mermaid.js 拖动时相同的偏移量。
- **移动形状的边**会以直线连接边界。箭头会随之转向，连线文本则位于中间。
- **其他所有内容都会保留 Pele 绘制时的位置**，包括子图的边框。Pele 不会重新布局图表。
