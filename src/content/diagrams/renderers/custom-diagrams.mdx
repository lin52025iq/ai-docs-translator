## 快速开始

此图表渲染器会将 Mermaid 源文本发送到你托管的渲染服务：

```ts
import type { DiagramRenderer } from '@tiptap-pro/extension-diagrams'

export function serviceDiagramRenderer(endpoint: string): DiagramRenderer {
  return {
    id: 'mermaid-service',
    label: 'Mermaid (service)',
    formats: ['mermaid'],
    async render({ source, theme, raster }) {
      const response = await fetch(endpoint, {
        method: 'POST',
        headers: { 'content-type': 'application/json' },
        body: JSON.stringify({ source, theme, htmlLabels: !raster }),
      })
      if (!response.ok) throw new Error(`The diagram service answered ${response.status}`)
      const svg = await response.text()
      const root = new DOMParser().parseFromString(svg, 'image/svg+xml').documentElement
      const width = Number.parseFloat(root.getAttribute('width') ?? '') || 600
      const height = Number.parseFloat(root.getAttribute('height') ?? '') || 400
      return { svg, width, height }
    },
  }
}
```

```ts
Diagrams.configure({
  diagramRenderers: [serviceDiagramRenderer('https://diagrams.example.com/mermaid/svg')],
})
```

## 成员

| 成员      | 类型                                         | 说明                                                                                                                             |
| --------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `id`      | `string`                                     | 指定渲染器的名称                                                                                                                  |
| `label`   | `string`                                     | 可选。用于菜单                                                                                                                    |
| `formats` | `readonly FlowDiagramFormat[]`               | 渲染器可绘制的图表格式                                                                                                            |
| `draws`   | `(source: string) => boolean`                | 可选。指定是否绘制此源文本，例如只绘制某些 Mermaid 类型。不提供时，所有源文本都会绘制                                              |
| `rules`   | `RendererRules`                              | 可选。参见[渲染器规则](/diagrams/renderers/custom#rules-of-your-renderer)                                                        |
| `render`  | `(input) => Promise<{ svg, width, height }>` | 绘制源文本，详见下文                                                                                                              |
| `editing` | `DiagramEditing`                             | 可选。在 SVG 中查找文本和形状，参见[编辑图表](/diagrams/renderers/custom-diagrams#editing-in-the-diagram)                        |

## 哪个渲染器会绘制图表

扩展会选择第一个已注册的图表渲染器：其 `formats` 包含该图表的格式，并且其 `draws` 不会拒绝该源文本。对于空源文本，会直接交给该格式的第一个图表渲染器，不会调用 `draws`。

如果没有渲染器能绘制某种类型，图表会显示 [`unavailable`](/diagrams/api-reference/options#unavailable) 返回的内容，原因是 `'unsupported-kind'`。源文本会保留在文档中。与图表渲染器不同，拒绝绘制的图表渲染器之后也不会再绘制该图表。

### 自定义格式

只要某个已注册的图表渲染器在 `formats` 中列出该格式，`insertFlowDiagram` 和 `updateFlowDiagram` 就可以接受这种格式。无需进行其他注册。

- **格式的 id** 最多 64 个字符，只能包含字母、数字、`_` 和 `-`。
- **源文本** 会原样存储，最多 1,000,000 个字符。
- **没有已注册的图表渲染器能够绘制的格式**会原样保留在文档中，并在每次保存后继续存在。图表会显示 `unavailable` 返回的内容。

## render 接收什么

| 输入     | 类型                | 说明                                                                                                                               |
| -------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `format` | `FlowDiagramFormat` | `mermaid`、`drawio`、`bpmn` 或自定义格式，且必须是该渲染器 `formats` 中的格式                                                     |
| `source` | `string`            | 图表源文本，与文档中的存储内容一致                                                                                                  |
| `theme`  | `DiagramTheme`      | 解析后的颜色和字体，取自 `--tt-flow-diagram-*` 自定义属性（[图表](/diagrams/api-reference/selectors#diagrams)）                     |
| `raster` | `boolean`           | 当 SVG 将转换为 PNG、WebP、JPEG 或 Word 中的图像时为 `true`                                                                         |

当 `raster` 为 `true` 时，请将标签写为 SVG 文本。SVG 不得包含 `foreignObject`，因为浏览器不允许 canvas 导出此类对象。

## render 返回什么

`render` 返回 `{ svg, width, height }`。`svg` 是独立的 SVG 字符串，包含 `width` 和 `height`。`width` 和 `height` 是表示绘图像素尺寸的数字。

## 编辑图表

用户可以双击图表中的文本进行编辑，也可以拖动形状来移动它。参见[编辑图表](/diagrams/flow-diagrams/editing)。只有渲染器知道 SVG 中的文本和形状所在的位置，因此它会通过 `editing` 将这些信息告知扩展。`editing` 中的每个函数都会接收 `render` 返回的 SVG 字符串以及图表源文本。

| 成员            | 签名                                              | 未提供时的行为                                                                    |
| --------------- | ------------------------------------------------- | --------------------------------------------------------------------------------- |
| `labelAt`       | `(svg, point, source) => DiagramLabelHit \| null` | 双击不会打开任何内容                                                               |
| `nodeAt`        | `(svg, point, source) => DiagramNodeHit \| null`  | 无法拖动形状                                                                        |
| `movePositions` | `(svg, positions, source) => string \| null`      | 无法拖动形状。存储的偏移量不会绘制出来，但仍会保留在文档中                          |

- **`point`** 使用 SVG 自身的单位，通过其 `viewBox` 确定。
- **`DiagramLabelHit`** 的结构为 `{ target, label, box }`。`target` 指定源文本中的文本位置，例如 `{ kind: 'node', id: 'A' }`。扩展会在该位置写入新文本。
- **`DiagramNodeHit`** 的结构为 `{ id, label, box }`。`id` 是源文本中该形状的 id。
- **`movePositions`** 会返回一个 SVG，其中每个形状都根据其偏移量移动；如果没有形状移动，则返回 `null`。
- 对于渲染器无法处理的图表类型，请**返回 `null`**。

使用 mermaid.js 绘图的渲染器可以复用内置的 `editing`：

```ts
import { mermaidDiagramEditing } from '@tiptap-pro/extension-diagrams/mermaid'

const renderer = { id: 'my-mermaid', formats: ['mermaid'], render, editing: mermaidDiagramEditing }
```

## 确保网页安全

编辑器会在 `<img>` 中显示 SVG，因此 SVG 中的脚本和外部资源都不会在网页中运行或加载。

切勿在网页中执行源文本。请像内置渲染器一样，在服务器或沙盒化的 iframe 中进行渲染。仅解析文本且不需要 DOM 的库也可以改用 Web Worker 绘图，如 [Pele 渲染器](/diagrams/renderers/pele)所示。
