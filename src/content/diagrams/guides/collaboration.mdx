## 在哪里注册 Diagrams

在每个打开共享文档的地方注册 `Diagrams`：

- 在每个编辑器中
- 在只读查看器中
- 在代理中
- 在协作服务器上

如果遗漏某个客户端，它会从共享文档中删除所有图表和示意图，除非它设置了
`enableContentCheck: true`。请参阅[不含 Diagrams 的客户端](#不含-diagrams-的客户端)。

## 两个人同时修改一张图表

图表将其数据、Chart Spec 和 Renderer 分别存储为独立属性。共享文档会分别合并每个属性：

- **同时修改不同属性**时，两项修改都会保留。例如，一个人修改标题，另一个人修改单元格。
- **同时修改数据**时，只会保留其中一项。例如，两个人修改同一张图表中的不同单元格。数据是一个属性，因此后到的修改会覆盖另一项。
- **撤销**只会撤销你自己的修改，即使其他人已经修改了图表也是如此。

示意图也遵循相同规则。其源数据是一个属性。

## 不含 Diagrams 的客户端

如果客户端的 schema 中没有 `chart` 或 `flowDiagram` 节点，或者将 `chart: false` 或
`flowDiagram: false` 设为禁用状态，就无法构建这些节点。之后会发生什么，取决于编辑器选项
[`enableContentCheck`](/guides/invalid-schema#for-collaborative-editing)：

| `enableContentCheck` | 共享文档                                                                                     | 该客户端                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `false`（默认值）    | 删除该客户端无法构建的图表或示意图。删除操作会同步到所有其他客户端                           | 加载文档时删除这些内容                                                                    |
| `true`               | 保持不变。其他所有人仍可保留自己的图表和示意图                                               | 显示文档的其余部分，但无法编辑、不发送任何内容，并触发 `contentError`                      |

`enableContentCheck: true` 需要 `@tiptap/extension-collaboration` 3.33.0 和 `@tiptap/y-tiptap`
3.2.0 或更高版本。在较旧版本中，无论哪种情况，客户端都会删除这些图表或示意图。只有
`@tiptap/y-tiptap` 3.0.10 和 3.0.11 的行为不同：它们会将编辑器设为只读，并可能显示空白或过时的文档。

对于任何可能未注册 `Diagrams` 的客户端（例如应用的旧版本），都应设置 `enableContentCheck: true`。当文档包含该客户端无法构建的图表或示意图时，该客户端会暂停运行。还应设置 `onContentError`，因为默认处理程序会抛出错误。请参阅[无效 schema 的处理](/guides/invalid-schema#for-collaborative-editing)。

## 不显示任何内容的客户端

不绘制任何内容的客户端可以注册 `Diagrams`，但不配置 Renderer 或 Diagram Renderer。它不需要 DOM 或图表库，并会原样保留所有图表和示意图。

```ts
import { getSchema } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Diagrams } from '@tiptap-pro/extension-diagrams'

const extensions = [StarterKit, Diagrams.configure({ renderers: [] })]
const schema = getSchema(extensions)
```

没有 Renderer 的编辑器会将每个图表或示意图显示为此处无法绘制，或显示为
[`unavailable`](/diagrams/api-reference/options#unavailable) 返回的内容。其数据不会被更改。

## 拒绝不含 Diagrams 的客户端

如果你无法控制的客户端也能连接，可以让服务器拒绝未声明 `Diagrams` 的客户端。例如，使用 Hocuspocus 时，客户端会在连接中添加一个参数。服务器会在加载文档前检查该参数：

```ts
// client
const provider = new HocuspocusProvider({
  url: 'wss://collaboration.example.com?schema=diagram-1',
  name: 'document-id',
})

// server
const server = new Hocuspocus({
  async onConnect({ requestParameters }) {
    if (requestParameters.get('schema') !== 'diagram-1') {
      throw new Error('This document needs the Diagrams extension.')
    }
  },
})
```

## 版本混用

较新版本的 `@tiptap-pro/extension-diagrams` 可能会存储旧版客户端不认识的图表属性。旧版客户端会保留该属性，直到它修改图表，此时该属性就会丢失。在使用较新版本新增的功能之前，请先将所有客户端更新到相同版本。
