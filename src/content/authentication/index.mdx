Tiptap 服务使用 JWT（JSON Web Token）进行身份验证和授权。你可以在自己的服务器上生成并签署令牌，然后将其传递给 Tiptap 服务。每个令牌都会标识你的环境、列出它可以访问的服务，以及它获准对你的资源执行的操作。

<Callout title="仍在使用 App ID 和各服务独立密钥？" variant="hint">
  如果你使用 App ID 和各服务独立密钥进行身份验证，请参阅[迁移到新的身份验证方式](/authentication/migrate)。旧配置记录在[旧版身份验证](/authentication/legacy)中，并且仍可继续使用。
</Callout>

## 工作原理

1. 在 Tiptap 控制面板中创建一对非对称密钥。
2. 服务器使用私钥签署 JWT。
3. 客户端连接 Tiptap 服务（AI、Convert、Documents）时传递 JWT。
4. Tiptap 使用公钥验证令牌签名，并检查你的订阅。

## 令牌控制的内容

单个 JWT 包含请求所需的一切信息：它可以访问哪些服务、获准执行哪些操作，以及这些操作针对哪些资源。

- **一个令牌，多个服务。** 单个 JWT 可通过 `aud` 声明授权访问 AI、Convert 和 Documents 的任意组合。
- **跨服务工作流。** AI 服务可以在同一个令牌下操作你的文档，无需进行服务间的额外配置。
- **令牌中包含权限。** 通过 `action`、`resource` 和可选约束，明确声明允许执行的操作。
- **轮换密钥时零停机。** 每个环境可以同时启用多个密钥对，并在无需切换窗口的情况下停用旧密钥。

## 声明参考

每个 JWT 都必须包含以下注册声明：

| 声明 | 类型 | 必需 | 说明 |
|-------|------|----------|-------------|
| `iss` | `string` | 是 | 你的环境哈希 ID（来自 Tiptap 控制面板） |
| `aud` | `string \| string[]` | 是 | 此令牌可访问的服务：`"AI"`、`"Convert"`、`"Documents"` |
| `iat` | `number` | 否 | 签发时间戳（纪元秒数） |
| `exp` | `number` | 是 | 过期时间戳（纪元秒数） |
| `sub` | `string` | 否 | 用户标识符（用于审计日志和跟踪） |
| `permissions` | `Permission[]` | 否 | 此令牌获准执行的操作。省略此项表示不授予任何特定操作权限。 |

## 签署令牌

### 非对称密钥对 (ES256) — 默认方式

在控制面板中创建密钥后，你会获得一个 ECDSA 私钥（P-256）。使用私钥签署令牌。Tiptap 只存储公钥，并用它来验证令牌。私钥始终保留在你的服务器上。

```typescript
import { SignJWT, importPKCS8 } from 'jose'

const privateKey = await importPKCS8(process.env.TIPTAP_PRIVATE_KEY, 'ES256')

const jwt = await new SignJWT({
  permissions: [
    { action: 'Documents:Read', resource: '*' },
  ],
})
  .setProtectedHeader({ alg: 'ES256' })
  .setIssuer('your-environment-hash-id')
  .setAudience(['Documents'])
  .setIssuedAt()
  .setExpirationTime('30m')
  .sign(privateKey)
```

### 其他语言

JWT 是一种标准的 [RFC 7519](https://datatracker.ietf.org/doc/html/rfc7519) 令牌。任何支持 ES256 的 JWT 库都可以签署令牌。无论使用哪种语言，负载结构都相同。

**Python**（PyJWT；使用 ES256 时需要 `pyjwt[crypto]`）：

```python
import jwt, time

with open("private_key.pem", "rb") as f:
    private_key = f.read()

payload = {
    "iss": "your-environment-hash-id",
    "aud": ["AI", "Documents"],
    "iat": int(time.time()),
    "exp": int(time.time()) + 1800,
    "permissions": [
        {"action": "Documents:Read", "resource": "*"}
    ]
}

token = jwt.encode(payload, private_key, algorithm="ES256")
```

**PHP**（firebase/php-jwt）：

```php
use Firebase\JWT\JWT;

$privateKey = file_get_contents('private_key.pem');

$payload = [
    'iss' => 'your-environment-hash-id',
    'aud' => ['AI', 'Documents'],
    'iat' => time(),
    'exp' => time() + 1800,
    'permissions' => [
        ['action' => 'Documents:Read', 'resource' => '*'],
    ],
];

$token = JWT::encode($payload, $privateKey, 'ES256');
```

## 权限

权限定义令牌获准执行的操作。权限是可选的，但不含权限的令牌只能验证请求身份，不会授予任何特定操作权限。

每项权限都包含 **action** 和 **resource**（两者均为必填项），以及可选的 **constraints**：

```json
{
  "permissions": [
    {
      "action": "Documents:Read",
      "resource": "*",
      "constraints": { "prefix": "team1_" }
    }
  ]
}
```

### 操作

操作采用 `Service:Operation` 格式。每个 Tiptap 服务都有自己的操作：

| 服务 | 操作 |
|---------|---------|
| Documents | `Documents:Read`、`Documents:Write`、`Documents:Comment` |
| Documents REST API | `Documents:Api:All` 授予对 Document Server REST API 的完整访问权限。|
| Convert | `Convert:Import:Docx`、`Convert:Export:Docx`、`Convert:Import:Markdown`、`Convert:Export:Markdown`、`Convert:Export:Doc`、`Convert:Export:Odt`、`Convert:Export:Epub`、`Convert:Export:Pdf`、`Convert:Fonts` |
| AI | `AI:Generation`、`AI:Toolkit` |

`Documents:Write` 隐含 `Documents:Read` 和 `Documents:Comment` 的权限——授予写入权限时会自动授予另外两项，因此无需单独列出。

`Documents:Api:All` 授予对 Document Server 所有 API 端点的访问权限，包括托管设置。此权限与其他 `Documents:*` 操作不同；后者用于通过协作连接授权文档操作。请将携带此权限的令牌视为管理员凭据。将其保留在服务器端，严格限制有效期，切勿与客户端共享。

`Convert:*` 操作按文件格式 **和** 操作类型（`Import` 或 `Export`）限定范围。令牌只需包含实际执行操作所需的权限——例如，仅导出 PDF 的令牌需要 `Convert:Export:Pdf`。目前只有 DOCX 和 Markdown 支持导入和导出；Doc、ODT、EPUB 和 PDF 仅支持导出。`Convert:Fonts` 不限定范围，适用于 `/fonts/*` 路由。

`AI:Generation` 涵盖文本生成、建议和智能体端点。`AI:Toolkit` 涵盖工具包端点。两项权限互不隐含。目前 AI 操作不按资源限定范围，因此 AI 权限请使用 `"resource": "*"`。

操作名称不区分大小写——`"Documents:Read"` 和 `"documents:read"` 等效。资源和约束值（`prefix`、`suffix`、`in`）区分大小写，因为它们可能引用具有外部意义的标识符。请在自己的代码中统一大小写格式。

### 资源

每项权限都必须包含 `resource` 字段。该字段控制权限适用的资源：

| 值 | 含义 | 示例 |
|-------|---------|---------|
| `"*"` | **通配符** — 匹配所有内容 | `{ "action": "Documents:Read", "resource": "*" }` |
| `"*"` + 约束 | **筛选通配符** — 匹配符合约束的资源 | `{ "action": "Documents:Read", "resource": "*", "constraints": { "prefix": "team_" } }` |
| `"doc_42"` | **指定资源** — 仅匹配此精确资源 | `{ "action": "Documents:Write", "resource": "doc_42" }` |

关键规则：

- 使用 `"*"` 表示通配访问。不带约束的通配符会匹配 **所有内容**。
- 指定资源只匹配该精确资源。

### 约束

约束可以在资源匹配的基础上添加细粒度筛选。如果你想允许访问某一类资源，而不是逐一列出每项资源，约束会很有用。

```json
{
  "action": "Documents:Read",
  "resource": "*",
  "constraints": { "prefix": "team1_" }
}
```

这会授予对名称以 `"team1_"` 开头的所有文档的读取权限。

**可用的约束字段：**

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `prefix` | `string` | 资源名称必须以此值开头 |
| `suffix` | `string` | 资源名称必须以此值结尾 |
| `in` | `string[]` | 资源名称必须是这些精确值之一 |

**单个约束中的字段组合**采用 AND 逻辑（必须全部满足）：

```json
{ "prefix": "team1_", "suffix": "_published" }
```

匹配 `"team1_report_published"`，但不匹配 `"team1_report_draft"`。

**约束数组**采用 OR 逻辑（满足其中一项即可）：

```json
[
  { "prefix": "team1_" },
  { "prefix": "team2_" }
]
```

匹配 `"team1_doc"` 或 `"team2_doc"`。

**规则：**

- `constraints` 字段不能为空。每项约束必须至少声明 `prefix`、`suffix` 或 `in` 中的一项；约束数组也必须至少包含一项。如果不需要筛选，请完全省略此字段。
- `in` 不能与同一约束对象中的 `prefix` 或 `suffix` 组合使用。请改为在数组中使用不同的约束。
- `prefix` 和 `suffix` 必须是非空字符串。
- `in` 必须是非空字符串数组。

## 跨服务操作

某些操作会跨越服务边界。Document Server 存储你的文档，其他服务则对文档执行操作。例如，通过 Convert 服务导入 DOCX 时，文档及其评论会写入 Document Server。当操作以这种方式读取或写入文档时，令牌需要同时包含发起操作的权限和相应的 `Documents` 操作权限。

将带评论的 DOCX 导入并存储为文档的令牌需要同时包含以下权限：

```json
{
  "permissions": [
    { "action": "Convert:Import:Docx", "resource": "*" },
    { "action": "Documents:Write", "resource": "*" }
  ]
}
```

`resource` 由你自行定义。每个服务的文档都会说明该服务执行哪些跨服务操作，以及这些操作需要哪些权限。

## 示例

### 访问所有服务的完整权限

```json
{
  "iss": "env_abc123",
  "aud": ["AI", "Convert", "Documents"],
  "iat": 1722344565,
  "exp": 1722344865,
  "permissions": [
    { "action": "AI:Generation", "resource": "*" },
    { "action": "AI:Toolkit", "resource": "*" },
    { "action": "Documents:Write", "resource": "*" },
    { "action": "Convert:Import:Docx", "resource": "*" },
    { "action": "Convert:Export:Docx", "resource": "*" },
    { "action": "Convert:Import:Markdown", "resource": "*" },
    { "action": "Convert:Export:Markdown", "resource": "*" },
    { "action": "Convert:Export:Doc", "resource": "*" },
    { "action": "Convert:Export:Odt", "resource": "*" },
    { "action": "Convert:Export:Epub", "resource": "*" },
    { "action": "Convert:Export:Pdf", "resource": "*" },
    { "action": "Convert:Fonts", "resource": "*" }
  ]
}
```

`Documents:Write` 隐含读取和评论权限，因此只需一项 Documents 权限。

### 对特定文档的只读访问权限

```json
{
  "permissions": [
    {
      "action": "Documents:Read",
      "resource": "*",
      "constraints": {
        "in": ["document_a", "document_b"]
      }
    }
  ]
}
```

### 仅访问 AI

授予令牌所需的 AI 功能。以下示例允许访问生成和工具包端点：

```json
{
  "aud": ["AI"],
  "permissions": [
    { "action": "AI:Generation", "resource": "*" },
    { "action": "AI:Toolkit", "resource": "*" }
  ]
}
```

### 文档转换

仅授予令牌实际使用的格式和操作方向权限。以下示例导入 DOCX 并导出 PDF：

```json
{
  "aud": ["Convert"],
  "permissions": [
    { "action": "Convert:Import:Docx", "resource": "*" },
    { "action": "Convert:Export:Pdf", "resource": "*" }
  ]
}
```

### 按文档前缀限定范围

允许读取和评论属于特定团队的文档：

```json
{
  "permissions": [
    {
      "action": "Documents:Read",
      "resource": "*",
      "constraints": { "prefix": "team-sales_" }
    },
    {
      "action": "Documents:Comment",
      "resource": "*",
      "constraints": { "prefix": "team-sales_" }
    }
  ]
}
```

### 对单个文档的写入权限

```json
{
  "permissions": [
    { "action": "Documents:Write", "resource": "meeting-notes-2024" }
  ]
}
```

## 安全最佳实践

- **缩短令牌有效期。** 将 `exp` 设置为 30 分钟或更短。为每个会话或连接生成新的令牌。
- **遵循最小权限原则。** 只包含令牌实际需要的权限和受众。仅用于 Convert 导出的令牌不应在受众中包含 `"Documents"` 或 `"AI"`。
- **切勿在客户端暴露私钥。** 必须在服务器上生成令牌。将签署后的 JWT 发送给客户端，绝不要发送签名密钥。
- **定期轮换密钥。** 创建新的密钥对，更新服务器以使用新密钥签署令牌，然后停用旧密钥。Tiptap 支持每个环境同时启用多个密钥对，以便在轮换密钥时实现零停机。
- **设置 `sub` 以便审计。** 在 `sub` 中包含用户标识符，有助于在日志和审计记录中追踪操作对应的用户。
