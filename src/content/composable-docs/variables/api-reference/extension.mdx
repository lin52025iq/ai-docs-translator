从 `@tiptap-pro/extension-variable` 导入扩展和取值函数：

```ts
import { Variable, getVariable } from '@tiptap-pro/extension-variable'
```

以下所有 Variable 专属类型都从同一软件包导出。`Editor` 和 `JSONContent` 来自 `@tiptap/core`。

## 变量值

### VariableValue

```ts
type VariableValue = string | number | boolean | bigint | symbol | null | undefined | object
```

`object` 包括数组、Tiptap JSON 和其他 JavaScript 对象。运行时仍会进行验证：不接受 Promise，对象必须能够在不抛出异常的情况下通过 `JSON.stringify()` 序列化。

| 值                                               | 显示方式                                                           |
| ----------------------------------------------- | ----------------------------------------------------------------- |
| `string`                                        | 原样文本。不会解析 HTML 字符串。                                  |
| `number`、`boolean`、`bigint`、`symbol`         | `String(value)`。数字包括 `NaN` 和无穷大。                         |
| `null`、`undefined`                             | 空文本。                                                          |
| 有效的 Tiptap JSON 节点、文档或节点数组          | 使用编辑器 schema 的富文本内容。                                   |
| 其他对象或数组                                   | `JSON.stringify(value)`；如果返回 `undefined`，则显示为空文本。     |

Tiptap JSON 使用 `@tiptap/core` 中的 `JSONContent` 类型。其节点和标记类型必须存在于编辑器的 schema 中。不符合该 schema 的对象会显示为 JSON 文本。

```ts
import type { JSONContent } from '@tiptap/core'

const label: JSONContent = {
  type: 'text',
  text: 'Ada',
  marks: [{ type: 'bold' }],
}
```

变量引用中的富文本值仍为只读，且不会与引用一起保存。[绑定槽位](/composable-docs/variables/guides/bind-slots)会照常保存其填入的内容。

### VariableResolver 和 VariableResolverContext

```ts
type VariableResolver = (context: VariableResolverContext) => VariableValue

interface VariableResolverContext {
  editor: Editor
  get: (name: string) => VariableValue
  getText: (name: string) => string
}
```

| 属性      | 类型                              | 行为                                                                                                                  |
| --------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `editor`  | `Editor`                          | 当前的 Tiptap 编辑器，包括其 schema。                                                                                 |
| `get`     | `(name: string) => VariableValue` | 读取原始值并跟踪依赖项。名称未知或存在循环依赖时会抛出错误。                                                          |
| `getText` | `(name: string) => string`        | 以文本形式读取变量，并跟踪与 `get` 相同的依赖项。名称未知或存在循环依赖时会抛出错误。                                 |

解析器会同步返回。使用 `get()` 或 `getText()` 读取其他变量后，该变量更新时解析器会重新运行。使用 `editor` 进行读取；在解析器内派发事务可能导致递归更新。通过 `editor` 读取不会注册变量依赖项。

`getText()` 会从符合 schema 的 Tiptap JSON 节点、文档和节点数组中提取文本。它使用 schema 的文本序列化器，保留硬换行，并以两个换行符分隔块。对于 `null` 和 `undefined`，它返回 `''`；对于所有其他值（包括普通对象和数组），则返回 `String(value)`。例如，`{ name: 'Ada' }` 会变成 `'[object Object]'`。此转换与变量引用将普通对象显示为 JSON 的方式不同。

如果绑定源不可读取，`getText()` 会像 `get()` 一样终止解析器并隐藏其值。

```ts
import type { VariableResolver } from '@tiptap-pro/extension-variable'

const greeting: VariableResolver = ({ getText }) => `Hello, ${getText('customer')}!`
```

直接赋给 `variables` 的函数会被视为解析器。若要将函数本身用作值，请从解析器中返回该函数，或将其传给 `setVariable`；它会显示为 `String(value)`。

## 配置

### VariableOptions

```ts
interface VariableOptions {
  HTMLAttributes: Record<string, string>
  variables: Record<string, VariableValue | VariableResolver>
  slots: Record<string, string>
  shortcuts: false | VariableShortcut
  resolveInputRuleVariable: VariableInputRuleResolver
  onUpdate: (options: VariableUpdateOptions) => void
  onError: (options: VariableErrorOptions) => void
}
```

调用 `Variable.configure()` 时，每个选项都是可选的。扩展提供以下默认值：

样式和自定义视图请参阅[样式](/composable-docs/variables/api-reference/rendering)。

| 选项                       | 类型                                                | 默认值                       | 说明                                                                                              |
| -------------------------- | --------------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------- |
| `HTMLAttributes`           | `Record<string, string>`                            | `{}`                        | 默认 NodeView 和导出 HTML 的属性。                                                                |
| `variables`                | `Record<string, VariableValue \| VariableResolver>` | `{}`                        | 键为变量名；值为初始值或解析器。                                                                  |
| `slots`                    | `Record<string, string>`                            | `{}`                        | 初始的槽位 ID 到变量的绑定。需要 `Slot`。建议使用槽位属性或绑定命令。                              |
| `shortcuts`                | `false \| VariableShortcut`                         | `{ open: '{', close: '}' }` | 输入分隔符。请参阅[输入快捷方式](#typed-shortcuts)。                                               |
| `resolveInputRuleVariable` | `VariableInputRuleResolver`                         | 返回 `undefined`            | 自定义或取消输入的引用。                                                                          |
| `onUpdate`                 | `(options: VariableUpdateOptions) => void`          | 空操作函数                  | 接受变量值更改后调用。                                                                            |
| `onError`                  | `(options: VariableErrorOptions) => void`           | 空操作函数                  | 求值、渲染、槽位同步或输入规则回调失败时调用。                                                     |

```ts
Variable.configure({
  variables: { customer: 'Ada', greeting },
  slots: { customerField: 'customer', signatureField: 'customer' },
  onUpdate: ({ values }) => console.log(values.customer),
  onError: ({ error }) => console.error(error.message),
})
```

槽位绑定以 `variable: 'customer'` 的形式存储在槽位节点上。`variable: null` 表示明确解除槽位绑定。HTML 使用 `data-slot-variable="customer"`；空属性表示未绑定。省略该属性时，初始绑定由 `slots` 配置提供；创建编辑器时，扩展会将这些初始绑定写入文档。后续更改建议使用[绑定命令](#bindslotvariable)。

### VariableUpdateOptions

`onUpdate` 和 `variablesUpdate` 事件都会接收此负载：

```ts
interface VariableUpdateOptions {
  editor: Editor
  values: Readonly<Record<string, VariableValue>>
}
```

| 属性      | 类型                                      | 说明                                                                                       |
| --------- | ----------------------------------------- | ------------------------------------------------------------------------------------------ |
| `editor`  | `Editor`                                  | 变量发生更改的编辑器。                                                                     |
| `values`  | `Readonly<Record<string, VariableValue>>` | 所有当前值，包括重新计算的依赖项。键是变量名，而非槽位 ID。                                  |

`values` 记录会被冻结。其中的对象值不会被克隆或深度冻结。更改对象后，请调用 `setVariable`，或刷新提供该对象的解析器；仅修改对象不会触发更新。

变量值不会根据其配置名称缩窄类型。将值用作特定对象或原始类型之前，请先检查类型：

```ts
import type { VariableUpdateOptions } from '@tiptap-pro/extension-variable'

const onVariablesUpdate = ({ values }: VariableUpdateOptions): void => {
  if (typeof values.customer === 'string') {
    console.log(values.customer.toUpperCase())
  }
}
```

### VariableErrorOptions

```ts
interface VariableErrorOptions {
  editor: Editor
  error: Error
}
```

| 属性      | 类型       | 说明                                                                                     |
| --------- | ---------- | ---------------------------------------------------------------------------------------- |
| `editor`  | `Editor`   | 更新失败的编辑器。                                                                       |
| `error`   | `Error`    | 失败信息，包含易读的 `message`。抛出的非 Error 值会转换为 `Error`。                       |

两个回调都返回 `void`；返回值会被忽略。

无效的初始配置或初始解析器失败会在创建编辑器时抛出异常。后续本地编辑或变量命令中的求值或槽位同步失败，会保留之前的运行时值并调用 `onError`。

如果默认 NodeView 无法渲染某个值，它会清除渲染失败的内容，并通过 `onError` 报告错误。编辑仍可继续；设置有效值后即可恢复显示。

即使解析器失败，传入的协同编辑和保护策略更改仍会生效。该解析器的值会变为 `null`，其依赖项会重新计算，并且 `onError` 会收到错误。

引入重复绑定槽位 ID 的远程编辑仍会保留在文档中。槽位结构无效期间，由槽位驱动的值及其依赖项不可用，槽位同步也会暂停。修复结构后，会从槽位恢复值。

## 命令

通过 `editor.commands` 直接调用时，命令返回 `boolean`。在链式调用中，相同命令返回链对象；`.run()` 返回 `boolean`。

### addVariable

在创建编辑器后注册新值或同步解析器。

```ts
interface AddVariableOptions {
  name: string
  value: VariableValue | VariableResolver
}

editor.commands.addVariable({ name: 'company', value: 'Acme' })
editor.commands.addVariable({
  name: 'greeting',
  value: ({ getText }) => `Hello, ${getText('customer')}!`,
})
```

两个属性都是必填项；显式传入 `undefined` 是有效值。函数会被视为解析器并立即运行。它所依赖的变量必须已经注册。若要同时注册多个变量及其依赖项，请使用 `setVariables()`。

名称为空，或已通过配置、运行时命令或槽位绑定注册时，返回 `false`。这些检查不会调用 `onError`。要更新现有值，请使用 `setVariable()`；要替换解析器，请使用 `setVariables()`。

求值或同步失败时会返回 `false`、调用 `onError`，并保持之前的定义和值不变。添加变量会更新文档中已有的同名引用，但不会插入新引用。若要同时执行这两项操作，请将它与 `insertVariable()` 链式调用：

```ts
editor
  .chain()
  .addVariable({ name: 'company', value: 'Acme' })
  .insertVariable({ name: 'company' })
  .run()
```

定义属于此编辑器实例。它们不会保存在文档中，也不会因文档撤销操作而回退。

### insertVariable

在选区处插入不可编辑的行内引用。

| 参数属性 | 类型     | 必填 | 说明                                                                                  |
| -------- | -------- | ---- | ------------------------------------------------------------------------------------- |
| `name`   | `string` | 是   | 通过配置、运行时命令或槽位绑定注册的变量。                                             |

参数类型为 `{ name: string }`。没有单独导出的 `InsertVariableOptions` 类型。

```ts
const inserted: boolean = editor.commands.insertVariable({ name: 'greeting' })
```

名称未知或无法插入引用时，返回 `false`。

### setVariable

设置一个值并重新计算其依赖项。

```ts
interface SetVariableOptions {
  name: string
  value: VariableValue
}
```

| 参数属性 | 类型            | 必填 | 说明                         |
| -------- | --------------- | ---- | ---------------------------- |
| `name`   | `string`        | 是   | 已注册的变量名。             |
| `value`  | `VariableValue` | 是   | 新值。允许显式传入 `undefined`。 |

```ts
const updated: boolean = editor.commands.setVariable({ name: 'customer', value: 'Grace' })
```

名称未知或更新失败时返回 `false`。名称未知不会调用 `onError`。

此命令会用提供的值替换任何解析器。绑定槽位会采用新值并变为只读。

### setVariables

在运行时添加变量，或替换其值和解析器。记录中省略的名称保持不变。

```ts
interface SetVariablesOptions {
  variables: Record<string, VariableValue | VariableResolver>
}
```

`variables` 属性为必填项。每个键都是变量名；每个值都是普通值或同步解析器。

```ts
editor.commands.setVariables({
  variables: {
    customer: 'Ada',
    greeting: ({ getText }) => `Hello, ${getText('customer')}!`,
  },
})
```

解析器会立即运行，依赖值和绑定槽位也会更新。可以在同一次调用中注册解析器及其依赖项。

将解析器替换为值即可停止重新计算。若要保留其当前值：

```ts
editor.commands.setVariables({
  variables: { greeting: getVariable({ editor, name: 'greeting' }) },
})
```

求值或槽位同步失败时，返回 `false` 并调用 `onError`。整个更新都会被拒绝，之前的定义和值保持不变。

定义属于此编辑器实例。它们不会保存在文档中，也不会因文档撤销操作而回退。

### removeVariable

按照与 `removeVariables()` 相同的规则移除一个运行时定义：

```ts
interface RemoveVariableOptions {
  name: string
}

editor.commands.removeVariable({ name: 'greeting' })
```

`name` 属性为必填项。名称未知，或移除未绑定变量会导致仍然存在的解析器失去依赖项时，返回 `false`。这些检查不会调用 `onError`。请先移除依赖解析器，或使用 `removeVariables()` 一次移除整组变量。

对于绑定变量，此命令会移除其显式值或解析器，并使槽位内容恢复可编辑。已移除的未绑定变量所对应的引用会保留在文档中并显示为空值。再次添加同名变量即可恢复其显示。

求值或同步失败时会返回 `false`、调用 `onError`，并保持之前的运行时状态不变。

### removeVariables

同时移除多个变量及其解析器。

```ts
interface RemoveVariablesOptions {
  names: string[]
}
```

`names` 属性为必填项。传入空数组时不执行任何操作。

```ts
editor.commands.removeVariables({ names: ['greeting'] })
```

对于绑定变量，此命令会移除其显式值或解析器。其槽位会恢复可编辑，并改为提供变量值。

对于未绑定变量，此命令会将其移除。名称未知，或移除变量会导致仍然存在的解析器失去依赖项时，返回 `false`。这些检查不会调用 `onError`。

现有文档引用会保留。已移除的未绑定变量所对应的引用会显示为空值。

### bindSlotVariable

将槽位绑定到变量，或替换其当前绑定。绑定会保存在槽位的 `variable` 属性中。

```ts
interface BindSlotVariableOptions {
  id: string
  name: string
}

editor.commands.bindSlotVariable({ id: 'customerField', name: 'customer' })
```

两个属性都是必填项。`id` 必须唯一标识一个槽位；`name` 不能为空。若名称未知，则会创建一个值来自该槽位的变量。

显式值或解析器的优先级更高，并会使槽位变为只读。否则，第一个绑定槽位会提供变量值，所有绑定槽位均保持可编辑。添加另一个槽位时，会将变量的当前值复制到该槽位。

另一个绑定槽位内部的绑定会被保存，但在嵌套期间会被忽略。只有外层绑定生效。移除外层绑定或将内层槽位移至其外部后，内层绑定才会生效。

如果槽位缺失或不唯一、名称为空，或同步或 Content Protection 拒绝更改，则返回 `false` 并调用 `onError`。整个更改都会被拒绝。

### unbindSlotVariable

解除绑定并保留槽位当前内容。

```ts
interface UnbindSlotVariableOptions {
  id: string
}

editor.commands.unbindSlotVariable({ id: 'customerField' })
```

`id` 属性为必填项，且必须唯一标识一个槽位。此命令会在该槽位上保存 `variable: null`。如果无法唯一找到槽位，或更改被拒绝，则返回 `false` 并调用 `onError`。

由槽位驱动的变量失去最后一个绑定槽位时，其值会变为 `undefined`。显式值和解析器不受影响。绑定和解除绑定均支持文档撤销与重做。

两个绑定命令都支持通过 `editor.can()` 检查，且不会求值解析器或更改绑定。试运行会检查槽位、名称和更改绑定的权限，但无法预测同步是否会失败。

### refreshVariables

刷新解析器及其依赖值。

```ts
interface RefreshVariablesOptions {
  names?: string[]
}
```

选项对象及其 `names` 属性均为可选项。

| `names`                | 行为                                                                      |
| ---------------------- | ------------------------------------------------------------------------- |
| 省略或为 `undefined`   | 刷新所有已注册的解析器，包括运行时添加的解析器。                            |
| `string[]`             | 刷新指定变量及其依赖项。名称必须已注册。                                    |
| `[]`                   | 不运行任何解析器；使用当前值同步绑定槽位。                                  |

```ts
const refreshed: boolean = editor.commands.refreshVariables({ names: ['customer'] })
editor.commands.refreshVariables()
```

名称未知或更新失败时返回 `false`。名称未知不会调用 `onError`。刷新普通值时，该值保持不变，但其依赖项会重新计算。

`editor.can().setVariable({ name, value })` 和 `editor.can().refreshVariables()` 会检查变量名称，但不会运行解析器。其 `boolean` 返回值无法预测求值或槽位写入是否会失败。

`editor.can().setVariables({ variables })` 同样会跳过求值。`editor.can().removeVariables({ names })` 会检查名称是否存在，以及剩余解析器是否会因此失去依赖项。这两种检查都不会更改运行时定义。

`editor.can().addVariable({ name, value })` 会检查名称是否非空且尚未注册，但不会运行解析器。`editor.can().removeVariable({ name })` 会按照批量移除的相同规则进行检查。这两种试运行都不会更改定义，也无法预测求值或槽位写入是否会失败。

## 读取值

### getVariable 和 GetVariableOptions

```ts
interface GetVariableOptions {
  editor: Editor
  name: string
}
```

| 参数属性 | 类型     | 必填 | 说明                     |
| -------- | -------- | ---- | ------------------------ |
| `editor` | `Editor` | 是   | 要从中读取值的编辑器实例。 |
| `name`   | `string` | 是   | 要读取的变量名。         |

**返回类型：** `VariableValue | undefined`。`VariableValue` 本身也包含 `undefined`。

```ts
const customer = getVariable({ editor, name: 'customer' })
if (typeof customer === 'string') console.log(customer.toUpperCase())
```

此函数直接返回值本身，包括对象值和 Tiptap JSON。它不会运行解析器。

| 结果                      | 说明                                                                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `undefined`               | 配置值为 `undefined`、名称未知，或未安装此扩展。                                                                         |
| `null`                    | 配置值为 `null`、绑定源被隐藏，或解析器在远程编辑或策略更改期间失败。                                                      |
| 任何其他 `VariableValue`  | 当前运行时值。                                                                                                           |

隐藏绑定槽位时，其依赖值也会被隐藏。恢复访问权限后，这些值会重新计算。

## 输入快捷方式

输入 `{foo}` 会创建名为 `foo` 的行内引用，即使 `foo` 未在 `variables` 中定义。未知名称会显示为空值。这会创建文档引用，而不是新的运行时值或解析器。

默认启用此规则。可以使用 `Variable.configure({ shortcuts: false })` 禁用，或更改分隔符：

```ts
Variable.configure({
  shortcuts: { open: '[[', close: ']]' },
})
```

```ts
interface VariableShortcut {
  open: string
  close: string
}
```

`shortcuts` 的类型为 `false | VariableShortcut`，默认值为 `{ open: '{', close: '}' }`。两个分隔符都必须是非空且互不相同的字符串。捕获的名称区分大小写，且不会去除首尾空格。空匹配、嵌套的起始分隔符和代码块都会被跳过。粘贴或加载内容不会触发转换。`undoInputRule()` 会恢复输入的文本。

### resolveInputRuleVariable

在插入引用之前自定义或取消该引用。默认回调返回 `undefined`，保留捕获的名称。

```ts
Variable.configure({
  resolveInputRuleVariable({ text }) {
    if (text === 'private') return false
    if (text === 'name') return { name: 'customer' }
    return undefined
  },
})
```

```ts
interface VariableInputRuleContext {
  editor: Editor
  text: string
  delimiters: Readonly<VariableShortcut>
  range: Readonly<{ from: number; to: number }>
  defaults: Readonly<{ name: string }>
}

interface VariableInputRuleResult {
  name?: string
}

type VariableInputRuleResolver = (
  context: VariableInputRuleContext,
) => VariableInputRuleResult | false | undefined
```

| 上下文属性 | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| `editor`   | 接收输入的编辑器。                                           |
| `text`     | 两个分隔符之间的文本，不包括分隔符。                         |
| `delimiters` | 已配置的起始和结束字符串。                                  |
| `range`    | 待替换的文档位置，不包括即将插入的输入内容。                 |
| `defaults` | 默认引用属性：`{ name: text }`。                             |

返回 `false` 可将输入保留为文本。返回 `{ name: 'customer' }` 可覆盖名称；返回 `{}` 或 `undefined` 则使用默认名称。覆盖名称必须是非空字符串，但不必是已配置的变量名。回调会同步执行。抛出错误或返回无效结果都会取消转换并调用 `onError`。

## renderVariableValue

在文档外部使用编辑器的 schema 和自定义 NodeView 渲染值。

```ts
interface RenderVariableValueOptions {
  editor: Editor
  value: VariableValue
}

interface RenderedVariableValue {
  dom: DocumentFragment
  destroy: () => void
}

function renderVariableValue(options: RenderVariableValueOptions): RenderedVariableValue
```

两个选项属性都是必填项。`editor` 提供 schema 和 NodeView；`value` 是要显示的当前值。这些接口和函数均从 `@tiptap-pro/extension-variable` 导出。

`dom` 包含渲染后的快照。Tiptap JSON 会保留格式和自定义 NodeView；其他对象会显示为 JSON 文本。替换或移除结果前，请调用 `destroy()`。它会释放嵌套的 NodeView，且可以安全地重复调用。

此辅助函数不会订阅更新。嵌套 NodeView 没有文档位置，因此其 `getPos()` 会返回 `undefined`。渲染错误会在清理已创建的 NodeView 后抛出。

## 监听更改

事件名称为 **`variablesUpdate`**。其监听器类型为 **`(options: VariableUpdateOptions) => void`**。`onVariablesUpdate` 只是这些示例中使用的处理函数名称。

使用同一个函数订阅和取消订阅：

```ts
editor.on('variablesUpdate', onVariablesUpdate)
editor.off('variablesUpdate', onVariablesUpdate)
```

`editor.on()` 和 `editor.off()` 都会返回编辑器实例。监听器接收的 `{ editor, values }` 负载与扩展的 `onUpdate` 回调相同。

命令、已刷新的解析器和槽位编辑都可能触发此事件。添加或移除变量也会触发事件，即使其值为 `undefined`。已移除的名称不会出现在 `values` 中。替换解析器但不更改其值时不会触发事件。被拒绝的更新和未更改的值不会触发事件。注册监听器不会发送初始值；请使用 `getVariable` 读取。

## 文档引用

变量引用只存储名称：

```json
{ "type": "variable", "attrs": { "name": "customer" } }
```

| 属性         | 类型             | 说明                                                                                   |
| ------------ | ---------------- | -------------------------------------------------------------------------------------- |
| `type`       | `'variable'`     | 扩展的节点名称。                                                                       |
| `attrs.name` | `string \| null` | 变量名。schema 默认值为 `null`；`insertVariable` 要求名称已注册。                       |

名称缺失或未知时会显示为空值。运行时值不会出现在文档 JSON、导出的 HTML 或纯文本中。
