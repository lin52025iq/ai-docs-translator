将一个或多个[插槽](/composable-docs/slots/getting-started/overview)绑定到变量，使插槽内容与变量保持同步。

## 配置绑定

安装 `@tiptap-pro/extension-slot` 和 `@tiptap-pro/extension-variable`。

首先，为两个插槽添加同名的 `variable` 属性：

```ts
const content = {
  type: 'doc',
  content: [
    {
      type: 'paragraph',
      content: [
        {
          type: 'inlineSlot',
          attrs: { id: 'customerField', variable: 'customer' },
          content: [{ type: 'text', text: 'Ada' }],
        },
        { type: 'text', text: ' / ' },
        {
          type: 'inlineSlot',
          attrs: { id: 'signatureField', variable: 'customer' },
          content: [{ type: 'text', text: 'Ada' }],
        },
      ],
    },
  ],
}
```

然后，使用这两个扩展创建编辑器：

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Slot } from '@tiptap-pro/extension-slot'
import { Variable } from '@tiptap-pro/extension-variable'

const editor = new Editor({
  extensions: [StarterKit, Slot, Variable],
  content,
})
```

变量值会直接显示在每个插槽中，无需额外的变量节点。

## 让插槽提供变量值

如果没有为 `customer` 显式指定值或解析器，第一个绑定的插槽会提供变量值。编辑任一插槽，或使用命令填充它，变量和另一个插槽都会同步更新：

```ts
editor.commands.fillSlot({
  id: 'customerField',
  content: [{ type: 'text', text: 'Grace' }],
})
```

填充成功时，命令返回 `true`。仅绑定变量不会使插槽变为只读。

如果依赖项解析器执行失败、新内容无法放入另一个绑定的插槽，或内容保护阻止了同步更新，命令会返回 `false`，并保留之前的文档和变量值。`Variable.onError` 会接收到错误，`slotCommandRejected` 会报告 `code: 'variableSyncFailed'`。试运行不会执行解析器，也不会预测同步失败。

## 让变量控制插槽

显式设置的值或解析器优先于插槽内容。设置变量后，两个插槽都会重新填充并变为只读：

```ts
editor.commands.setVariable({ name: 'customer', value: 'Lin' })
```

也可以使用解析器：

```ts
const currentCustomer = { name: 'Lin' }
editor.commands.setVariables({ variables: { customer: () => currentCustomer.name } })
```

变量控制插槽时，`fillSlot()`、`fillSlots()` 和 `clearSlot()` 会返回 `false`，且不会更改插槽内容，即使替换内容与当前值相同也是如此。对于这些写入操作，`editor.can()` 也会返回 `false`：

```ts
const filled = editor.commands.fillSlot({
  id: 'customerField',
  content: [{ type: 'text', text: 'Grace' }],
})
// filled === false; both slots still display "Lin".
```

批量操作或命令链被拒绝时，其中的写入操作都不会执行。插槽命令也会拒绝通过父级插槽或嵌套插槽写入内容。若要更改受控内容，请改为更新变量。

如需调试或向应用提供反馈，可以监听 Slot 扩展的 `slotCommandRejected` 事件：

```ts
editor.on('slotCommandRejected', ({ command, code, slotIds }) => {
  if (code === 'variableControlled') {
    console.log(`${command} refused: a variable controls the slot`, slotIds)
  }
})
```

此类拒绝通过 `slotCommandRejected` 报告，而不是通过 `Variable.onError`。试运行不会触发事件。Variable 插件拒绝的其他编辑操作仍会通过 `Variable.onError` 报告。

移除显式定义后，插槽会恢复可编辑状态，其当前内容将成为变量值：

```ts
editor.commands.removeVariables({ names: ['customer'] })
```

显式设置为 `null` 或 `undefined` 也会使插槽变为只读；插槽会显示为空内容。

## 更改绑定

将现有插槽绑定到变量，或更改其当前绑定：

```ts
editor.commands.bindSlotVariable({ id: 'customerField', name: 'customer' })
```

如果指定的变量名不存在，就会创建一个由插槽驱动的变量。如果该变量已有绑定的插槽，新绑定的插槽会采用该变量值。

移除绑定，同时保留插槽内容：

```ts
editor.commands.unbindSlotVariable({ id: 'customerField' })
```

## 富文本内容

纯文本插槽提供字符串。格式化插槽提供 Tiptap JSON，并保留标记、换行和结构：

```ts
editor.commands.setVariable({
  name: 'customer',
  value: { type: 'text', text: 'Ada', marks: [{ type: 'bold' }] },
})
```

- 内容必须适用于所有绑定的插槽。需要多个段落时，请使用块级插槽。
- 另一个已绑定插槽中的绑定会被忽略，但仍会保留；移除外层绑定或将内层插槽移到外层插槽之外后，这些绑定才会生效。
- 其他对象会显示为 JSON 文本。`null` 和 `undefined` 会清空插槽。

如果需要获取插槽的纯文本，即使用户添加了格式，也请在依赖项解析器中使用 `getText()`：

```ts
editor.commands.addVariable({
  name: 'greeting',
  value: ({ getText }) => `Hello, ${getText('customer')}!`,
})
```

编辑 customer 插槽时，问候语会自动更新。如果需要保留 Tiptap JSON，请改用 `get()`。

## 保存与保护

插槽内容和绑定会与文档一同保存。绑定支持撤销和重做。运行时变量值和解析器则保留在编辑器配置中。

在协同编辑器中，即使客户端的本地变量值不同，收到的插槽内容也会保留。移动光标和进行无关编辑都不会恢复该本地值。显式更新本地变量可以将其值写入共享插槽。如果希望各客户端显示相同的变量值，请确保它们的运行时定义一致。

启用[内容保护](/composable-docs/content-protection/getting-started/overview)时：

- 本地编辑需要拥有更新每个绑定插槽的权限。
- 无法读取源插槽时，由其驱动的变量及其依赖值会被隐藏，直到恢复访问权限。
- 收到的协同编辑仍会应用。额外的本地插槽写入操作需要编辑权限。

同步在客户端编辑器中运行。加载文档时，请再次提供显式值和解析器。
