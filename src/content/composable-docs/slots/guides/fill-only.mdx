若要防止用户编辑插槽之外的内容，请使用 [`ContentProtection`](/composable-docs/content-protection/getting-started/overview) 扩展。

<CodeDemo isPro path="/Examples/SlotFilling" />

`ContentProtection` 扩展接受一个[内容保护策略](/composable-docs/content-protection/api-reference/policy)。使用 [`createSlotFillingPolicy` 工具](/composable-docs/slots/api-reference/utilities#createslotfillingpolicy)，即可允许用户编辑插槽内的内容，同时保护插槽配置及其周围的文档内容。

对于[值插槽](/composable-docs/slots/guides/value-slots)，同一策略只允许更改已分配字段的 `value` 属性。标识、配置、其他属性以及节点结构仍受保护。对象或数组值作为整体编辑。

```ts
import { Slot, createSlotFillingPolicy } from '@tiptap-pro/extension-slot'
import { ContentProtection } from '@tiptap-pro/extension-content-protection'

const extensions = [
  StarterKit,
  Slot,
  ContentProtection.configure({
    policy: createSlotFillingPolicy(),
  }),
]
```

若要允许用户编辑指定的插槽，请将其 ID 传给策略创建函数。这样也会允许编辑这些插槽中嵌套插槽的内容。若要限制嵌套内容，请使用[优先级更高的规则](/composable-docs/content-protection/guides/example-policies#protect-nested-content)。

```ts
editor.commands.setContentProtectionPolicy({
  policy: createSlotFillingPolicy({
    editableSlotIds: ['summary', 'justification'],
  }),
})
```

## 按角色分配插槽

角色由你的应用定义。若要根据 ID 前缀分配插槽，请读取当前 ID，在宿主应用中进行筛选，然后将确切的 ID 传给 `createSlotFillingPolicy`：

```ts
import { getSlots } from '@tiptap-pro/extension-slot'

function applyRole(role: 'Auditor' | 'Reviewer') {
  const prefix = role === 'Auditor' ? 'audit-' : 'review-'
  const editableSlotIds = getSlots({ document: editor.state.doc }).flatMap(({ id }) =>
    id && (id.startsWith(prefix) || id.startsWith('all-')) ? [id] : [],
  )
  editor.commands.setContentProtectionPolicy({
    policy: createSlotFillingPolicy({ editableSlotIds }),
  })
}
```

当角色或插槽 ID 集合发生变化时，调用 `applyRole`。策略中保存的是确切 ID，不会持续根据前缀进行匹配。可编辑的父级插槽也允许编辑其嵌套内容，因此，如果嵌套插槽需要不同的分配规则，请使用优先级更高的规则。

## 协作

插槽可与 [Tiptap Collaboration](/editor/extensions/functionality/collaboration) 配合使用。将 `Slot` 与 `Collaboration` 和 `ContentProtection` 一同加入，并通过 `StarterKit.configure({ undoRedo: false })` 禁用 StarterKit 的本地撤销/重做功能。

插槽内容、ID 和配置会通过共享文档同步。每位协作者都可以使用自己的 `editableSlotIds`：这些 ID 会限制本地编辑，但不会拒绝其他协作者的更新。协作撤销/重做也会同步，且不会经过本地策略检查。共享内容发生变化时，插槽快照和验证结果会刷新；验证结果和策略仍保留在本地。
