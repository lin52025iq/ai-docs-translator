使用 `editor.on(name, listener)` 或相应的 `Slot.configure()` 回调进行订阅。使用 `editor.off(name, listener)` 移除监听器。

```ts
const onValidation = ({ state }: SlotValidationUpdateEvent) => showValidation(state)
editor.on('slotValidationUpdate', onValidation)
// When disposing the UI:
editor.off('slotValidationUpdate', onValidation)
```

从 `@tiptap-pro/extension-slot` 导入负载类型。`Editor` 来自 `@tiptap/core`。

## `slotsUpdate`

初始索引以及每次应用文档更改时都会触发。选项：`onSlotsUpdate`。

### 负载（`SlotsUpdateEvent`）

- `editor`（`Editor`）：源编辑器。
- `snapshot`（`SlotSnapshot`）：更新后的文档和索引。

## `activeSlotChange`

首次初始化以及活动条目发生变化时都会触发。选项：`onActiveSlotChange`。

### 负载（`ActiveSlotChangeEvent`）

- `editor`（`Editor`）：源编辑器。
- `slot`（`SlotEntry | null`）：活动 Slot；不在 Slots 范围内时为 `null`。

## `slotValidationUpdate`

验证状态变为待处理、当前有效或未经验证时触发，也包括显式使上下文失效的情况。选项：`onValidationUpdate`。

### 负载（`SlotValidationUpdateEvent`）

- `editor`（`Editor`）：源编辑器。
- `state`（`SlotValidationState`）：更新后的验证存储状态。

## `slotValidationError`

绑定到编辑器的验证器抛出异常、拒绝请求或返回格式错误的验证结果时触发。选项：`onValidationError`。

### 负载（`SlotValidationErrorEvent`）

在 [`SlotValidationError`](/composable-docs/slots/api-reference/validation#slotvalidationerror) 的基础上增加：

- `editor`（`Editor`）：源编辑器。

缺少验证器或请求已中止时，不会触发此事件。

## `slotCommandRejected`

实际的 Slot 命令被拒绝时触发，包括预检阶段的拒绝。选项：`onCommandRejected`。

### 负载（`SlotCommandRejectedEvent`）

在 [`SlotCommandRejection`](/composable-docs/slots/api-reference/types#slotcommandrejection) 的基础上增加：

- `editor`（`Editor`）：源编辑器。

## 事件派发

- 选项回调和编辑器监听器会收到相同的负载。两者都注册会创建两个订阅。
- 初始索引和活动 Slot 事件会在编辑器创建后触发。较晚订阅的监听器应读取存储；事件不会重放。
- 更新事件在存储更新后触发。拒绝事件在做出决定后触发；监听器的返回值不会改变决定。
- 负载数据为只读。应用界面在显示数据前必须遵守读取权限。
- `editor.can()` 和纯验证函数不会触发编辑器事件。
- `validateEditorSlots` 会触发验证事件。验证器错误会先于最终验证状态更新发生。
- 后续写入应由应用安排。
- 编辑器销毁时，会清理扩展所拥有的监听器和待处理的验证。

有关策略更新和保护拒绝，请参阅[内容保护事件](/composable-docs/content-protection/api-reference/extension#editor-events)。
