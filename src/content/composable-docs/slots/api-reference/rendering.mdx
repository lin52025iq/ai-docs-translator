将 `BlockSlot` 和 `InlineSlot` 按普通的 Tiptap Node 扩展进行自定义。将它们传给 `Slot`；它会保留命令、索引和验证行为。

## HTML 属性

```ts
Slot.configure({
  blockSlot: BlockSlot.configure({ HTMLAttributes: { class: 'block-field' } }),
  inlineSlot: InlineSlot.configure({ HTMLAttributes: { class: 'inline-field' } }),
})
```

- `HTMLAttributes`（`Record<string, string>`）：外层元素的属性。默认值：`{}`。
- 必需的 `data-slot-*` 属性优先于自定义属性。
- 此软件包不提供工具栏、边框或颜色。请在应用中为包装元素添加样式。

### 序列化属性

| 属性               | 值                      | 用途                     |
| ------------------ | ----------------------- | ------------------------ |
| `data-slot-kind`   | `'block'` 或 `'inline'` | 标识 Node 类型。         |
| `data-slot-id`     | Slot ID                 | 保留身份标识。           |
| `data-slot-config` | 转义后的 JSON           | 保留嵌入的配置。         |

块级 Slot 的默认包装元素为 `div`，行内 Slot 的默认包装元素为 `span`。无障碍名称使用 `config.label`；若未设置，则回退为 ID。

### 仅视图属性

| 属性                    | 值                     | 用途                   |
| ----------------------- | ---------------------- | ---------------------- |
| `data-slot-empty`       | `'true'` 或 `'false'`  | 为字段为空时设置样式。 |
| `data-slot-active`      | `'true'` 或 `'false'`  | 为活动字段设置样式。   |
| `data-slot-placeholder` | 配置的占位文本         | 字段为空时提供文本。   |

这些属性和占位文本的呈现不会持久化到 JSON、序列化后的 HTML 或剪贴板内容中。

## 自定义 NodeView

```ts
const CustomBlockSlot = BlockSlot.extend({
  addNodeView() {
    return ReactNodeViewRenderer(MySlotView)
  },
})

Slot.configure({ blockSlot: CustomBlockSlot })
```

`ReactNodeViewRenderer` 来自 `@tiptap/react`。JavaScript 和 Vue 使用各自标准的 Tiptap NodeView API。

### 约定

- 保留规范的 Node 名称、`id`/`config` 属性、内容表达式以及 defining/isolating 行为。
- 仅通过 `Slot` 注册自定义实例。实例在编辑器创建时确定。
- 提供一个可编辑的 `contentDOM`，或框架中对应的 `NodeViewContent`。
- 让 Tiptap 渲染文档内容。不要从 `node.content` 再渲染一份。
- 将控件和标签设为不可编辑。通过命令进行编辑。
- 行内包装元素和内容容器必须使用兼容行内布局的元素，例如 `span`。
- 自定义视图负责显示标签和占位文本。默认占位文本不会添加到自定义视图中。
- 保留选区、嵌套编辑、IME 和光标行为。不要拦截必需的内容事件或变更。

有关各框架的 API，请参阅 [Tiptap NodeView](/editor/extensions/custom-extensions/node-views)。

## 验证和权限更新

当仅靠属性变化无法触发更新时，使用 [`subscribeSlotViewUpdates`](/composable-docs/slots/api-reference/utilities#subscribeslotviewupdates) 刷新 UI。

```ts
const unsubscribe = subscribeSlotViewUpdates({ editor, onUpdate: refresh })
// 视图销毁时：
unsubscribe()
```

- 从 `editor.storage.slot` 读取快照、活动字段和验证状态。
- 导入的 ID 存在歧义时，使用 `getPos()` 和条目位置。
- 使用 `editor.can()` 检查命令是否可用，并通过 Content Protection 查询了解原因。
- 仅呈现当前的验证结果。显示消息或内容前，先应用读取权限。
- 挂载视图不会启动验证。

## HTML 序列化

- `addNodeView` 控制编辑器 UI；`renderHTML` 控制导出的 HTML。
- 对于内容槽位节点（`BlockSlot` 和 `InlineSlot`），自定义 `renderHTML` 必须保留三个序列化属性和一个内容孔位。
- 根据当前 Node 生成属性，并正确转义。
- 自定义 `parseHTML` 必须保留 ID 和完整配置。保留默认解析器作为后备方案。
- HTML 中格式错误的配置 JSON 会变为 `config: null`，并产生一条验证问题。
- UI 控件、占位文本和验证消息应放在 NodeView 中，而非导出的内容中。

## 值槽位 NodeView

通过 `addNodeView` 自定义 `BlockValueSlot` 或 `InlineValueSlot`。这些叶节点没有 `contentDOM` 或 `NodeViewContent`。其包装元素应保持不可编辑，并在其中使用原生控件或框架组件。完整示例请参阅[值槽位指南](/composable-docs/slots/guides/value-slots#mix-custom-and-default-nodeviews)。

### `createSlotValueController`

```ts
const slot = createSlotValueController({ editor, getPos })
```

接受一个 `Editor` 和 NodeView 的实时 `getPos: () => number | undefined` 回调。不需要依赖任何框架。

- `getState(): SlotValueState`：稳定的不可变快照，包含 `value: JsonValue`、`config: SlotConfig | null`、`editable: boolean` 和 `available: boolean`。
- `getValue(): JsonValue`：最新的可读值；不可用时为 `null`。
- `setValue(value: JsonValue): boolean`：受保护的命令；字段不可用、受保护、有歧义或由变量控制时返回 false。
- `subscribe(listener: () => void): () => void`：状态变化时通知；返回一个取消订阅函数。请显式读取初始状态。最后一个订阅者取消订阅后，编辑器监听器会被移除。
- `focus(): void`：控件获得焦点时选中可读的值节点。此操作不会移动 DOM 焦点。
- `destroy(): void`：释放订阅并阻止后续写入。

只有快照属性发生变化时，快照引用才会变化，因此适用于 React 的 `useSyncExternalStore`。其他使用者仍在使用控制器时，不要销毁它。字段缺失或不可读时，`available: false`，且不会暴露其值或配置。

### `createDefaultSlotValueView`

接受标准的 `NodeViewRendererProps`，并返回完整的 ProseMirror `NodeView`。对于需要保留内置控件的字段，请在 `addNodeView` 中调用它。它不会再次调用你的渲染器。

默认视图负责管理事件、组合输入、值更新、权限变更和销毁。输入类型发生变化时，它会重新创建。如果配置变化要求使用不同的渲染器，自定义视图也必须在 `update` 中返回 false。

### 值槽位 HTML

值节点会序列化 `data-slot-kind`、`data-slot-mode="value"`、`data-slot-id`、`data-slot-config` 和 `data-slot-value`。配置和值均使用转义后的 JSON。导出的 HTML 包含静态值表示，不包含内容孔位或交互控件。自定义值槽位序列化必须保留这些属性，且不得添加内容孔位。

## 已遮蔽内容

Content Protection 会使用自己的[脱敏渲染器](/composable-docs/content-protection/api-reference/rendering)替换被遮蔽的 Node。其原有 Slot NodeView 不会继续挂载。

可读的父节点可能包含被遮蔽的子节点。其自定义控件不得在其他位置显示这些子节点的文本、属性或 JSON。完整的源文档仍保留在客户端内存中。
