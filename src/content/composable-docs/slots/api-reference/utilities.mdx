从 `@tiptap-pro/extension-slot` 导入这些函数。每个函数都接受一个选项对象；`createSlotFillingPolicy` 也可以不传参数。

`Editor` 来自 `@tiptap/core`；`Schema` 来自 `@tiptap/pm/model`。请参阅[共享类型](/composable-docs/slots/api-reference/types)。

## `createSlotSnapshot`

无需编辑器即可捕获不可变文档及其插槽索引。

### 参数

- `document`（`SlotDocument`）：完整文档。
- `schema?`（`Schema`）：用于检查 JSON 的 Schema。对于 ProseMirror Node，会自动使用其 Schema。

### 返回值（`SlotSnapshot`）

文档、条目和不透明的快照 ID。两个版本号均为 `null`。输入格式错误时会抛出 `SlotInputError`。

如果未提供 Schema，JSON 检查仅涵盖结构和插槽数据；无法据此确认其与编辑器 Schema 兼容。

## `getSlots`

按文档顺序读取所有插槽，包括嵌套插槽。

### 参数

传入 `{ document, schema? }` 或 `{ snapshot }`。

- `document`（`SlotDocument`）：完整文档。
- `schema?`（`Schema`）：用于检查 JSON 的可选 Schema；对于 ProseMirror Node，会自动使用其 Schema。
- `snapshot`（`SlotSnapshot`）：要读取的现有快照，而不是新建快照。

### 返回值（`SlotEntry[]`）

只读条目。输入格式错误时会抛出 `SlotInputError`。

## `getSlot`

按 ID 读取一个插槽。

### 参数

传入 `{ document, schema?, id }` 或 `{ snapshot, id }`。

- `document`（`SlotDocument`）：完整文档。
- `id`（`string`）：完全匹配的插槽 ID。
- `schema?`（`Schema`）：用于检查 JSON 的可选 Schema；对于 ProseMirror Node，会自动使用其 Schema。
- `snapshot`（`SlotSnapshot`）：要搜索的现有快照，而不是新建快照。

### 返回值（`SlotEntry | null`）

匹配的条目；如果不存在，则返回 `null`。存在重复匹配或输入格式错误时会抛出 `SlotInputError`。

## `subscribeSlotViewUpdates`

订阅编辑器状态变更，以便应用 UI 或 NodeView 响应更新。需要 `Slot`。

### 参数

- `editor`（`Editor`）：要观察的编辑器。
- `onUpdate`（`() => void`）：读取刷新的公共存储。该函数会立即调用，之后在文档、选区、验证和事务更新时调用。

### 返回值（`() => void`）

可重复调用且安全的取消订阅函数。销毁视图时调用。此订阅不会编辑内容或启动验证。

## `createSlotFillingPolicy`

创建一项策略，允许用户填充现有插槽，同时保护周围的文档和字段定义。要强制执行该策略，需要使用[内容保护](/composable-docs/content-protection/getting-started/overview)。

```ts
const policy = createSlotFillingPolicy({ editableSlotIds: ['summary', 'decision'] })
```

### 参数（`SlotFillingPolicyOptions`）

- `editableSlotIds?`（`string[]`）：可填充的 ID 及其后代内容。省略时：所有插槽均可填充，包括未来新增的字段。`[]`：没有可编辑字段。
- `documentType?`（`string`）：根 Node 的名称。默认值：`'doc'`。
- `ruleIdPrefix?`（`string`）：生成的规则 ID 前缀。默认值：`'slotFilling'`。

### 返回值（`SlotFillingPolicy`）

普通策略 JSON，可赋值给 `ContentProtectionPolicy`。不会检查或更改文档。参数无效时会抛出 `SlotInputError`；重复 ID 会去重并排序。未知 ID 不会匹配任何内容。

### 生成的规则

ID 使用 `<ruleIdPrefix>.<suffix>` 格式。

| 后缀                 | 优先级 | 效果                                           |
| -------------------- | ------ | ---------------------------------------------- |
| `documentContent`    | `0`    | 禁止编辑根内容。                               |
| `documentAttributes` | `0`    | 禁止编辑所有根属性。                           |
| `fillableContent`    | `10`   | 允许编辑所选插槽及其后代中的内容。             |
| `slotStructure`      | `20`   | 禁止插入、移除、重新设置类型或移动插槽节点。   |
| `slotAttributes`     | `20`   | 禁止更改所有插槽属性。                         |
| `fillableValue`      | `30`   | 仅允许更改所选值插槽的 value 属性。            |

### 行为

- 允许编辑父插槽，也会允许编辑其中未列出的嵌套插槽内容。若要限制某个后代，可添加优先级高于 `10` 的内容拒绝规则。即使父插槽未列出，已列出的子插槽仍可编辑。
- 如果清空或替换父插槽会移除嵌套插槽，则操作会被拒绝。
- 在允许编辑的插槽中，普通文本和格式仍可编辑。插槽验证不会阻止编辑。
- 不会生成读取规则。现有读取限制仍然有效。
- ID 会匹配所有符合条件的实例。分配字段之前，请先验证导入数据中的身份问题。
- 使用 `setContentProtectionPolicy({ policy })` 替换策略赋值；修改已安装的对象不会生效。
- 更高优先级的应用规则可以覆盖这些规则。组合策略时，请使用唯一前缀。

## `SlotFillingPolicy`

### 属性

- `version`（`1`）：策略格式版本。
- `rules`（`SlotFillingRule[]`）：六条生成的规则，包括 `fillableValue`。

## `SlotFillingRule`

### 属性

- `id`（`string`）：生成的唯一规则 ID。
- `priority`（`number`）：规则优先级。
- `selector`（`{ target: 'nodeType'; node: SlotFillingNodeMatch } | { target: 'nodeContent'; node: SlotFillingNodeMatch } | { target: 'attribute'; node: SlotFillingNodeMatch; names?: string[] }`）：目标和匹配条件。
- `permissions`（`{ edit: boolean }`）：是否允许编辑。
- `reason?`（`string`）：可选的诊断说明。

### 选择器属性

- `target`（`'nodeType' | 'nodeContent' | 'attribute'`）：受保护的操作类别。
- `node`（`SlotFillingNodeMatch`）：要匹配的节点。
- `names?`（`string[]`）：`attribute` 规则的属性名称。省略时：匹配所有属性。

## `SlotFillingNodeMatch`

### 属性

- `types`（`string[]`）：精确匹配的 Node 类型名称。
- `attributes?`（`{ name: 'id'; operator: 'in'; values: string[] }[]`）：ID 筛选条件。省略时：匹配所选类型的所有 Node。

### 属性筛选条件

- `name`（`'id'`）：插槽身份属性。
- `operator`（`'in'`）：成员关系比较。
- `values`（`string[]`）：可接受的 ID，必须完全匹配且区分大小写。

有关优先级和选择器行为，请参阅[策略语言](/composable-docs/content-protection/api-reference/policy)。验证函数另见[验证](/composable-docs/slots/api-reference/validation)。
