策略是定义读取和编辑权限的 JSON 对象。除非匹配的规则拒绝访问，否则允许访问所有内容。

## `ContentProtectionPolicy`

### 属性

- `version` (`1`)：策略格式版本。目前仅支持 `1`。
- `rules` (`ProtectionRule[]`)：权限规则。空数组表示允许读取和编辑所有内容。

```ts
const policy: ContentProtectionPolicy = {
  version: 1,
  rules: [
    {
      selector: { target: 'node', node: { types: ['heading'] } },
      permissions: { edit: false },
    },
  ],
}
```

## `ProtectionRule`

一个选择器，以及它授予或拒绝的权限。

### 属性

- `id?` (`string`)：可选的诊断标识符。在同一策略中必须非空且唯一。匿名规则通过其数组索引标识。
- `selector` (`ProtectionSelector`)：规则的适用对象。
- `permissions` (`{ read?: boolean; edit?: boolean }`)：至少指定一项权限。`true` 表示允许；`false` 表示拒绝。未指定权限的规则不起作用，会被忽略。
- `priority?` (`number`)：整数优先级。未指定时为 `0`。数值越大优先级越高；允许负数。优先级相同时，无论规则顺序如何，拒绝都优先于允许。两条规则都省略 `priority` 时也适用此规则。
- `reason?` (`string`)：在诊断信息中返回的纯文本说明。不影响权限。不得包含隐藏内容。

## `ProtectionSelector`

使用字符串 `target` 选择一个方面，或使用非空目标数组选择多个方面。Node 目标使用 `node`，Mark 目标使用 `mark`。`SingleProtectionSelector` 是此类型中以字符串指定目标的形式。

### 多个目标

当同一批匹配的 Node 或 Mark 具有相同权限时，可以组合其多个方面：

```ts
const rule = {
  selector: {
    target: ['nodeType', 'attribute'],
    node: { types: ['heading'] },
    names: ['level'],
  },
  permissions: { edit: false },
} satisfies ProtectionRule
```

此规则保护标题结构和级别，同时允许编辑文本。其效果等同于具有相同权限和优先级的独立 `nodeType` 和 `attribute` 规则。

- 将 Node 目标（`node`、`nodeType`、`nodeContent`、`children`、`attribute`）与 `node` 组合，或将 Mark 目标（`mark`、`markType`、`markContent`、`markAttribute`）与 `mark` 组合。混用这两类目标无效。
- 只要任一所选方面适用，该规则就会生效。所有方面共用其 ID、原因和优先级。匹配多个方面不会提高优先级，也不会在诊断元数据中重复记录该规则。重复的目标不会产生额外效果。
- 只有选择 `attribute` 或 `markAttribute` 时，才可以使用 `names`，且它只应用于该方面。对于 Node 属性，省略 `names` 表示选择所有属性。Mark 属性必须指定 `names`。空 `names` 数组表示不选择任何属性；其他目标仍然适用。
- 如果目标中包含 `children`，该规则只支持 `edit`。无论 `read` 的值为何，都无效。
- 目标数组不能为空。仍然支持原有的字符串目标和策略版本 `1`。

`within` 中的祖先条件适用于每个所选方面。它们只用于定位匹配的 Node 或 Mark，不会保护祖先。参见[嵌套祖先匹配](#嵌套祖先匹配)。

### `target: 'node'`

- `node` (`NodeMatch`)：要匹配的 Node。
- `edit: false`：保护 Node 的存在、类型、属性和全部内容，包括后代和 Mark。
- `read: false`：隐藏该 Node 及其子树。

使用此目标锁定整个 Node。更改其类型或匹配的属性无法解除锁定。优先级更高的规则可以允许在其中进行特定编辑。

### `target: 'nodeType'`

- `node` (`NodeMatch`)：要匹配的 Node。
- `edit: false`：禁止插入、移除、重设类型、拆分、合并或移动该 Node。
- `read: false`：隐藏该 Node 及其子树。

仅保护编辑时，内容和属性仍可编辑。被隐藏的 Node 完全不可编辑。由更早的编辑导致的位置偏移不视为移动。

### `target: 'nodeContent'`

- `node` (`NodeMatch`)：其内容受规则控制的 Node。
- `edit: false`：禁止更改文本、后代 Node、后代属性和 Mark。
- `read: false`：隐藏该 Node 的子项。

仅保护编辑时，不会保护所属 Node 的类型、属性和存在状态。更改其类型或匹配的属性可能会允许后续编辑。使用 `node` 保护整个 Node，或添加 `nodeType` 和适当的 `attribute` 规则。即使所属 Node 的内容受到保护，删除它仍需要获得删除这些内容的权限。

设为 `read: false` 时，所属 Node 也不可编辑：即使其内容为空，也无法更改其类型、属性或存在状态。这样可以防止通过更改所属 Node 来显示被隐藏的内容。

### 嵌套内容规则

内容规则会递归应用，包括嵌套 Slot。如果优先级高于祖先的编辑规则，单独的规则可以授予或拒绝子树内的**编辑权限**。使用 `within` 或属性匹配嵌套区域。选择器的嵌套深度不影响优先级，覆盖规则也会应用于其后代。

这不会覆盖读取限制：被隐藏祖先中的内容仍然处于隐藏状态，且无法编辑。参见[读取限制](#读取限制)。

```ts
const rules = [
  {
    selector: { target: 'nodeContent', node: { types: ['blockquote'] } },
    permissions: { edit: false },
  },
  {
    selector: {
      target: 'nodeContent',
      node: { types: ['paragraph'], within: { types: ['blockquote'] } },
    },
    permissions: { edit: true },
    priority: 10,
  },
] satisfies ProtectionRule[]
```

允许编辑受保护引用块中的段落文本和格式。引用块中的其他内容仍受保护。允许规则的优先级必须高于拒绝规则的默认值 `0`。

### `target: 'children'`

- `node` (`NodeMatch`)：要匹配的父级 Node。
- `edit: false`：只要父级仍然存在，就保留其直接非文本子项的顺序序列。
- `read`：不支持；请改用 `nodeContent`。

子项中的文本和格式仍可编辑。使用 `nodeType` 可在不冻结父级内容的情况下保护其存在状态。此目标适用于固定表格列、可编辑单元格以及可删除的表体行。

### `target: 'attribute'`

- `node` (`NodeMatch`)：要匹配的 Node。
- `names?` (`string[]`)：要控制的属性。省略表示所有属性；`[]` 表示无属性。
- `edit: false`：禁止更改所选属性。
- `read: false`：隐藏整个所属 Node 及其子树。

### `target: 'mark'`

- `mark` (`MarkMatch`)：要匹配的 Mark。
- `edit: false`：保护 Mark 的存在、类型、属性和标记内容，包括其他格式。
- `read: false`：隐藏被标记的内容。

使用此目标锁定一段已标记的内容及其元数据。

### `target: 'markType'`

- `mark` (`MarkMatch`)：要匹配的 Mark。
- `edit: false`：禁止添加、移除或将 Mark 替换为其他类型。
- `read: false`：隐藏被标记的内容。

文字、Mark 属性和其他格式仍可编辑。删除最后一段带有此 Mark 的内容会导致 Mark 被移除，因此需要相应权限。使用 `markAttribute` 还可以保护元数据，同时允许更改文字。

### `target: 'markContent'`

- `mark` (`MarkMatch`)：用于标识受保护内容的 Mark。
- `edit: false`：禁止更改被标记的内容，包括其 Mark 和后代内容。
- `read: false`：隐藏被标记的内容。

移除或更改用于选择内容的 Mark 也受此规则控制。对于编辑保护，`markContent` 和 `mark` 覆盖相同的标记范围。优先级更高的 `markType` 规则可以允许移除 Mark；解锁后的内容需在单独的事务中编辑。

### `target: 'markAttribute'`

- `mark` (`MarkMatch`)：要匹配的 Mark。
- `names` (`string[]`)：要控制的属性。必填；`[]` 表示不选择任何属性。
- `edit: false`：禁止更改所选 Mark 属性。
- `read: false`：隐藏被标记的内容。

## `NodeMatch`

匹配文档中的 Node，与 DOM 结构或 CSS 无关。

### 属性

- `types?` (`string[]`)：区分大小写的精确 schema 名称。省略表示所有 Node 类型；`[]` 表示无类型。多个条目按 OR 组合。
- `attributes?` (`AttributePredicate[]`)：属性测试按 AND 组合。省略或设为 `[]` 表示不限制属性。
- `within?` (`NodeMatch`)：要求存在匹配的严格祖先。嵌套的 `within` 值表示更上层的祖先。

`{}` 匹配所有 Node。使用根节点的 schema 名称（通常为 `doc`）来选择根节点；在根节点上使用 `nodeContent` 可覆盖整个文档。

### 嵌套祖先匹配

```ts
const rule = {
  selector: {
    target: ['nodeType', 'attribute'],
    node: {
      types: ['heading'],
      within: {
        types: ['blockquote'],
        within: {
          types: ['blockSlot'],
          attributes: [{ name: 'id', operator: 'eq', value: 'legal-notice' }],
        },
      },
    },
    names: ['level'],
  },
  permissions: { edit: false },
} satisfies ProtectionRule
```

当标题位于引用块中，且该引用块位于 `legal-notice` Slot 中时，此规则会保护标题结构和级别。文本仍可编辑。每个 `within` 都要求在任意深度上存在祖先，不一定是直接父级；各条件必须构成这条祖先链。

引用块和 Slot 是匹配条件，不是额外的保护目标。`within` 只接受匹配器属性；在其中放入 `target` 或 `permissions` 无效。使用单独的规则来保护祖先本身。

### 使用 UniqueID 指定单个 Node

为相关 Node 类型配置 [UniqueID](/editor/extensions/functionality/uniqueid)：

```ts
import { UniqueID } from '@tiptap/extension-unique-id'

UniqueID.configure({ types: ['paragraph'] })
```

匹配 Node 存储的 `id` 属性。将 `'paragraph-id'` 替换为文档中的 ID：

```ts
const rule = {
  selector: {
    target: 'nodeContent',
    node: {
      types: ['paragraph'],
      attributes: [{ name: 'id', operator: 'eq', value: 'paragraph-id' }],
    },
  },
  permissions: { edit: false },
} satisfies ProtectionRule
```

此规则保护该段落的内容。若要同时保护其类型、存在状态和属性（包括其 ID），请改用 `target: 'node'`。如果 UniqueID 使用自定义的 `attributeName`，请在谓词中使用该名称，而不是 `id`。

## `MarkMatch`

匹配行内 Node 上的 Mark。

### 属性

- `types?` (`string[]`)：区分大小写的精确 Mark 名称。省略表示所有 Mark 类型；`[]` 表示无类型。多个条目按 OR 组合。
- `attributes?` (`AttributePredicate[]`)：属性测试按 AND 组合。省略或设为 `[]` 表示不限制属性。
- `within?` (`NodeMatch`)：要求被标记的行内 Node 存在匹配的祖先。

不同 Mark 类型会分别评估，包括彼此重叠的情况。

## `AttributePredicate`

这些谓词专用于 Content Protection；它们不实现任何外部查询标准。`operator` 用于选择以下测试之一。属性名称指完整属性；不支持点分路径。

属性值必须是 JSON：字符串、有限数值、布尔值、`null`，或包含这些值的数组和普通对象。TypeScript API 将此类型称为 `JsonValue`。

### `operator: 'exists'`

- `name` (`string`)：必须存在其键的属性。值为 `null` 仍视为存在。

### `operator: 'eq'`

- `name` (`string`)：要比较的属性。
- `value` (`JsonValue`)：必需值。使用结构相等比较，不进行类型强制转换；对象键顺序不影响结果，数组顺序则会保留。

### `operator: 'in'`

- `name` (`string`)：要比较的属性。
- `values` (`JsonValue[]`)：可接受的值，使用 `eq` 进行比较。`[]` 不匹配任何值。

Schema 默认值也视为属性值。属性缺失与属性值为 `null` 是不同的。

## 规则优先级

针对每项受影响的操作，分别解析 `read` 和 `edit`：

1. 选择声明了相应权限且匹配的规则。
2. 如果没有匹配规则，则允许。
3. 将省略的优先级视为 `0`，然后只保留 `priority` 最高的规则。
4. 在该优先级下，只要有任一规则拒绝，就拒绝；否则允许。因此，两条都未指定优先级的规则发生冲突时，结果为拒绝。

规则列表顺序和选择器的具体程度不影响权限。只有事务中的每项受影响操作都获准时，才允许该事务。

| 匹配规则 | 结果 |
| --- | --- |
| 内容拒绝，优先级为 `0`；内容允许，优先级为 `10` | 在允许区域内允许。 |
| 优先级均为 `10` 的允许和拒绝 | 拒绝。 |
| 属性拒绝，优先级为 `20`；外围内容允许，优先级为 `10` | 拒绝属性更改。 |
| 读取允许，优先级为 `50`；编辑拒绝，优先级为 `0` | 可读取，不可编辑。 |

## 读取限制

- 读取规则针对每个所选目标按优先级解析。读取被拒绝的目标会隐藏其整个子树。
- 针对子项的单独 `read: true` 规则不会使其显示，即使其优先级高于祖先的读取拒绝规则也是如此。
- 若要显示子项，请缩小祖先拒绝规则的范围，或使用优先级更高、以该祖先本身为目标的读取允许规则。
- 被隐藏的 Node 不可编辑，包括其类型、属性、存在状态和内容。无需额外添加 `edit: false` 规则。重设类型、删除或更改匹配属性都无法显示或移除被隐藏的内容。
- 被隐藏的已标记内容无法更改，也无法移除用于选择它的 Mark。无论优先级如何，编辑允许规则都无法覆盖读取拒绝规则。
- 拒绝访问某个属性会隐藏其所属 Node；它不会对 NodeView 进行选择性净化。

有关渲染、剪贴板和导出行为，请参见[隐藏内容](/composable-docs/content-protection/api-reference/rendering)。

## 验证

将策略直接传递给 `ContentProtection.configure({ policy })` 或 `setContentProtectionPolicy({ policy })`。扩展会自动验证策略并存储不可变副本。

独立工具也可以直接接受策略 JSON，并根据文档或事务的 schema 进行验证。使用 [`validateContentProtectionPolicy`](/composable-docs/content-protection/api-reference/utilities#validatecontentprotectionpolicy) 可在不应用策略的情况下检查它。

以下策略无效：

- 不支持的版本、未知属性、目标或运算符。
- 空目标数组、混用 Node/Mark 目标，或未选择属性目标却指定了 `names`。
- 任一目标为 `markAttribute` 时未指定 `names`。
- 权限为空、ID 重复或为空、优先级不是整数。
- JSON 值无效，或明确指定的类型/属性不存在于 schema 中。
- 在 `children` 上使用 `read`，包括与其他目标组合时。

## 如何检查编辑

输入、粘贴内容、运行编辑器命令（包括 `setContent`）以及使用本地撤销/重做时，都会检查本地更改。[Tiptap 协作更新](/composable-docs/content-protection/getting-started/overview#collaboration)（包括初始同步和协作式撤销/重做）会绕过本地权限检查，以便使用不同策略的协作者保持同步。

如果事务中的任何部分造成了被禁止的更改，整个事务都会被拒绝。例如，同时覆盖可编辑文本和受保护文本的粘贴操作不会更改文档。

若仅编辑 Slot，请使用 [`createSlotFillingPolicy`](/composable-docs/slots/api-reference/utilities#createslotfillingpolicy)。它会生成此策略语言中的普通规则。
