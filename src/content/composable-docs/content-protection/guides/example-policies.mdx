将这些策略中的任意一个传递给 `ContentProtection.configure({ policy })`。指定的节点、标记和属性必须存在于编辑器的 schema 中。

```ts
import type { ContentProtectionPolicy } from '@tiptap-pro/extension-content-protection'
```

## 保护标题

```ts
const policy = {
  version: 1,
  rules: [
    {
      selector: { target: 'node', node: { types: ['heading'] } },
      permissions: { edit: false },
    },
  ],
} satisfies ContentProtectionPolicy
```

保护标题，包括其类型、文本、格式和属性。也可以使用 `target: 'nodeType'`，固定标题结构，同时允许编辑文本和属性。

## 固定标题级别

```ts
const policy = {
  version: 1,
  rules: [
    {
      selector: {
        target: 'attribute',
        node: { types: ['heading'] },
        names: ['level'],
      },
      permissions: { edit: false },
    },
  ],
} satisfies ContentProtectionPolicy
```

禁止更改标题的 `level` 属性。标题文本仍可编辑，标题本身也仍可删除。

## 保留标题，同时允许编辑文本

```ts
const policy = {
  version: 1,
  rules: [
    {
      selector: {
        target: ['nodeType', 'attribute'],
        node: { types: ['heading'] },
        names: ['level'],
      },
      permissions: { edit: false },
    },
  ],
} satisfies ContentProtectionPolicy
```

保留标题并禁止更改级别，同时允许修改其文本和格式。与 `target: 'node'` 不同，此策略不会锁定整个标题。

## 保留标题中的链接目标

```ts
const policy = {
  version: 1,
  rules: [
    {
      selector: {
        target: ['markType', 'markAttribute'],
        mark: {
          types: ['link'],
          within: { types: ['heading'] },
        },
        names: ['href'],
      },
      permissions: { edit: false },
    },
  ],
} satisfies ContentProtectionPolicy
```

禁止在标题中添加或移除链接，也禁止更改链接目标。链接文本和其他属性仍可编辑。标题之外的链接不受影响。标题在此处仅作为祖先条件；此规则不会保护标题本身。

有关受多个祖先约束的目标数组，请参阅[嵌套祖先匹配](/composable-docs/content-protection/api-reference/policy#nested-ancestor-matching)。

## 隐藏引用块

```ts
const policy = {
  version: 1,
  rules: [
    {
      selector: { target: 'node', node: { types: ['blockquote'] } },
      permissions: { read: false },
    },
  ],
} satisfies ContentProtectionPolicy
```

将引用块替换为[已隐藏内容](/composable-docs/content-protection/api-reference/rendering)，并禁止编辑。原始内容仍保留在客户端文档中。

## 仅允许编辑引用块内部内容

```ts
const policy = {
  version: 1,
  rules: [
    {
      selector: { target: 'nodeContent', node: { types: ['doc'] } },
      permissions: { edit: false },
    },
    {
      priority: 10,
      selector: { target: 'nodeContent', node: { types: ['blockquote'] } },
      permissions: { edit: true },
    },
    {
      priority: 20,
      selector: { target: 'nodeType', node: { types: ['blockquote'] } },
      permissions: { edit: false },
    },
  ],
} satisfies ContentProtectionPolicy
```

先锁定文档，再允许修改现有引用块内部的内容。最后一条规则保护引用块本身，包括嵌套的引用块；其属性则由适用于整个文档的规则保护。

## 保护嵌套内容

```ts
const policy = {
  version: 1,
  rules: [
    {
      selector: { target: 'nodeContent', node: { types: ['doc'] } },
      permissions: { edit: false },
    },
    {
      priority: 10,
      selector: { target: 'nodeContent', node: { types: ['blockquote'] } },
      permissions: { edit: true },
    },
    {
      priority: 20,
      selector: {
        target: 'nodeContent',
        node: { types: ['blockquote'], within: { types: ['blockquote'] } },
      },
      permissions: { edit: false },
    },
  ],
} satisfies ContentProtectionPolicy
```

允许编辑外层引用块内部的内容，同时保护任意嵌套深度的引用块内容。嵌套规则的拒绝权限生效，是因为它的优先级更高，而不是因为选择器深度更深。若还要保护嵌套节点的类型、是否存在及其属性，请在嵌套拒绝规则中使用 `target: 'node'`。

## 保护表格列和表头

```ts
const policy = {
  version: 1,
  rules: [
    {
      selector: { target: 'children', node: { types: ['tableRow'] } },
      permissions: { edit: false },
    },
    {
      selector: { target: 'node', node: { types: ['tableHeader'] } },
      permissions: { edit: false },
    },
    {
      selector: {
        target: 'attribute',
        node: { types: ['tableCell', 'tableHeader'] },
        names: ['colspan', 'rowspan'],
      },
      permissions: { edit: false },
    },
  ],
} satisfies ContentProtectionPolicy
```

保护现有行中的单元格顺序、表头文本和表头单元格，并禁止更改单元格跨度。表体单元格中的内容仍可编辑，整个表体行也可以添加或移除。

有关选择器类型和规则优先级，请参阅[策略语言](/composable-docs/content-protection/api-reference/policy)；若只需编辑 Slot，也可以使用 [Slot 填充辅助工具](/composable-docs/slots/api-reference/utilities#createslotfillingpolicy)。
