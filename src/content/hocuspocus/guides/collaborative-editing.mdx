## 简介
实时协作、在不同设备间同步以及离线工作曾经都很困难。借助 [Y.js](https://github.com/yjs/yjs) 的强大功能，我们提供了让所有内容保持同步所需的一切。以下指南将帮助你开始使用 Hocuspocus 在 Tiptap 中进行协同编辑。别担心，搭建可用于生产环境的方案并不需要编写很多代码。

## 配置编辑器
Tiptap 使用的底层 schema 是同步文档的绝佳基础。借助 [`Collaboration`](https://tiptap.dev/docs/editor/api/extensions/collaboration) 扩展，你可以让 Tiptap 使用 [Y.js](https://github.com/yjs/yjs) 跟踪文档变更。

Y.js 是一种无冲突复制数据类型（CRDT）的实现，换句话说：它非常擅长合并变更。为此，变更甚至不需要按顺序到达。离线时修改文档完全没问题，设备重新上线后再与其他变更合并即可。

所有客户端最终都需要以某种方式交换文档变更。最常用的技术是 [WebRTC](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API) 和 [WebSockets](https://developer.mozilla.org/de/docs/Web/API/WebSocket)，下面我们来仔细了解一下：

### WebRTC
WebRTC 只使用服务器来连接客户端。实际数据随后在客户端之间传输，服务器并不了解数据内容。这非常适合用来初步体验协同编辑。

首先，安装依赖：

```bash
npm install @tiptap/extension-collaboration yjs y-webrtc y-prosemirror
```

接着，创建一个新的 Y 文档，并将其注册到 Tiptap：

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import Collaboration from '@tiptap/extension-collaboration'
import * as Y from 'yjs'
import { WebrtcProvider } from 'y-webrtc'

// A new Y document
const ydoc = new Y.Doc()
// Registered with a WebRTC provider
const provider = new WebrtcProvider('example-document', ydoc)

const editor = new Editor({
  extensions: [
    StarterKit.configure({
      // The Collaboration extension comes with its own history/undoRedo handling
      undoRedo: false,
    }),
    // Register the document with Tiptap
    Collaboration.configure({
      document: ydoc,
    }),
  ],
})
```

这样就足以创建一个 Tiptap 协作实例。很神奇吧？试试看，在两个不同的浏览器中打开编辑器，两个窗口中的变更应该会同步。

那么，这种魔法是如何实现的呢？所有客户端都需要彼此连接，这正是 *provider* 的职责。[WebRTC provider](https://github.com/yjs/y-webrtc) 是最容易上手的方式，因为它使用公共服务器让客户端直接彼此连接，但不会通过服务器同步实际变更。不过，它有两个缺点：

1. 浏览器不允许连接过多客户端。使用 Y.js 时，所有客户端间接连接也足够了，但即便如此，客户端数量达到一定程度后也无法实现。换句话说，同一文档中有 100 多个客户端同时在线时，扩展性并不好。
2. 你很可能无论如何都需要服务器来持久化变更。但 WebRTC 信令服务器（负责将所有客户端连接起来）不会收到这些变更，因此也不知道文档中的内容。

无论如何，如果你想深入了解，可以访问 GitHub 上的 [Y WebRTC 仓库](https://github.com/yjs/y-webrtc)。

### WebSocket（推荐）
对于大多数使用场景，我们推荐使用 WebSocket provider。它非常灵活，扩展性也很好。为了让这一切更加简单，我们推出了 [Hocuspocus](/hocuspocus/introduction)，这是一个面向 Tiptap 的开源后端。

根据你的应用选择合适的客户端接入方式：

- **React 应用** → 使用 [`@hocuspocus/provider-react`](/hocuspocus/provider/react)。它通过组件（`HocuspocusProviderWebsocketComponent`、`HocuspocusRoom`）和 hooks 封装 provider，让 React 为你管理生命周期，包括 StrictMode 下的双重挂载。
- **原生 JS 或其他框架** → 直接使用基础的 `HocuspocusProvider`，并自行管理其生命周期。

#### React

安装 React 绑定包以及协作扩展：

```bash
npm install @tiptap/extension-collaboration @hocuspocus/provider @hocuspocus/provider-react y-prosemirror yjs
```

使用 `HocuspocusProviderWebsocketComponent` 和 `HocuspocusRoom` 包裹协作子树，然后在编辑器组件中通过 `useHocuspocusProvider` hook 获取 provider：

```tsx
import {
  HocuspocusProviderWebsocketComponent,
  HocuspocusRoom,
  useHocuspocusProvider,
} from '@hocuspocus/provider-react'
import { EditorContent, useEditor } from '@tiptap/react'
import Collaboration from '@tiptap/extension-collaboration'
import StarterKit from '@tiptap/starter-kit'

function Editor() {
  const provider = useHocuspocusProvider()

  const editor = useEditor({
    extensions: [
      StarterKit.configure({
        // The Collaboration extension comes with its own history handling
        undoRedo: false,
      }),
      Collaboration.configure({ document: provider.document }),
    ],
  })

  return <EditorContent editor={editor} />
}

export function App() {
  return (
    <HocuspocusProviderWebsocketComponent url="ws://127.0.0.1:1234">
      <HocuspocusRoom name="example-document">
        <Editor />
      </HocuspocusRoom>
    </HocuspocusProviderWebsocketComponent>
  )
}
```

WebSocket 组件负责管理共享 socket。多个 `HocuspocusRoom` 可以共用它，这对于用户同时打开多个文档很方便。有关连接/同步状态、awareness 和事件 hooks，请参阅 [React 绑定参考](/hocuspocus/provider/react)。

#### 原生 JS

安装依赖：

```bash
npm install @tiptap/extension-collaboration @hocuspocus/provider y-prosemirror yjs
```

然后直接将 WebSocket provider 注册到 Tiptap：

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import Collaboration from '@tiptap/extension-collaboration'
import { HocuspocusProvider } from '@hocuspocus/provider'

// Set up the Hocuspocus WebSocket provider
const provider = new HocuspocusProvider({
  url: 'ws://127.0.0.1:1234',
  name: 'example-document',
})

const editor = new Editor({
  extensions: [
    StarterKit.configure({
      // The Collaboration extension comes with its own history handling
      undoRedo: false,
    }),
    // Register the document with Tiptap
    Collaboration.configure({
      document: provider.document,
    }),
  ],
})
```

以上两个示例都需要一个位于 `ws://127.0.0.1:1234` 的 WebSocket 服务器——接下来我们来启动它。

#### WebSocket 后端
为了尽可能简化服务器端的配置，我们提供了一个名为 [Hocuspocus](/hocuspocus/introduction) 的约定式服务器包。它是一个灵活的 Node.js 包，可用于构建自定义后端。

本指南中，我们直接使用命令行界面，只需几秒钟就能启动一个最简服务器：

```bash
npx @hocuspocus/cli --port 1234 --sqlite
```

此命令会下载 Hocuspocus 命令行界面，启动一个监听 1234 端口的服务器，并将变更持久化到本地 SQLite 文件中（移除 `--sqlite` 标志即可仅在内存中保存变更）。输出应如下所示：

```
Hocuspocus running at:

> HTTP: http://127.0.0.1:1234
> WebSocket: ws://127.0.0.1:1234

Ready.
```

尝试在浏览器中打开 http://127.0.0.1:1234。如果一切正常，你应该会看到纯文本 `OK`。

回到 Tiptap 编辑器并重新加载页面。此时编辑器应该会连接到 Hocuspocus WebSocket 服务器，并与所有其他客户端同步变更。很棒吧？


### 多个网络 provider
你甚至可以组合使用多个 provider。虽然通常不需要这么做，但这样即使某个连接（例如 WebSocket 服务器）暂时中断，客户端仍可能保持连接。示例如下：

```js
new WebrtcProvider('example-document', ydoc)
new HocuspocusProvider({
  url: 'ws://127.0.0.1:1234',
  name: 'example-document',
  document: ydoc,
})
```

没错，就这么简单。

请注意，WebRTC 需要信令服务器来连接客户端。信令服务器不会收到同步的数据，但会帮助客户端彼此发现。如果愿意，你可以[运行自己的信令服务器](https://github.com/yjs/y-webrtc#signaling)。否则，它会使用包中内置的默认 URL。

### 显示其他用户的光标
要让用户看到彼此的光标和文本选区，请添加 [`CollaborationCaret`](https://tiptap.dev/docs/editor/api/extensions/collaboration-caret) 扩展。

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import Collaboration from '@tiptap/extension-collaboration'
import CollaborationCaret from '@tiptap/extension-collaboration-caret'
import { HocuspocusProvider } from '@hocuspocus/provider'

// Set up the Hocuspocus WebSocket provider
const provider = new HocuspocusProvider({
  url: 'ws://127.0.0.1:1234',
  name: 'example-document',
})

const editor = new Editor({
  extensions: [
    StarterKit.configure({
      // The Collaboration extension comes with its own history handling
      undoRedo: false,
    }),
    Collaboration.configure({
      document: provider.document,
    }),
    // Register the collaboration cursor extension
    CollaborationCaret.configure({
      provider: provider,
      user: {
        name: 'Cyndi Lauper',
        color: '#f783ac',
      },
    }),
  ],
})
```

如你所见，可以为每位用户指定姓名和颜色。请参阅[协同编辑示例](https://tiptap.dev/docs/editor/examples/collaborative-editing)，了解更高级的用法。

该扩展不提供默认样式。将以下选择器添加到样式表中，即可显示远程光标、选区和姓名标签。颜色通过 `currentColor` 从 `user.color` 获取，因此每位用户都会自动使用自己的色调：

```css
.collaboration-carets__caret {
  position: relative;
  margin-left: -1px;
  margin-right: -1px;
  border-left: 1px solid currentColor;
  border-right: 1px solid currentColor;
  word-break: normal;
  pointer-events: none;
}

.collaboration-carets__label {
  position: absolute;
  top: -1.35em;
  left: -1px;
  font-size: 12px;
  font-weight: 600;
  line-height: 1;
  user-select: none;
  color: #fff;
  padding: 2px 6px;
  border-radius: 3px 3px 3px 0;
  white-space: nowrap;
  background: currentColor;
}

.collaboration-carets__selection {
  background-color: currentColor;
  opacity: 0.25;
  pointer-events: none;
}
```

### 离线支持
多亏了出色的 [Y IndexedDB 适配器](https://github.com/yjs/y-indexeddb)，为协作编辑器添加离线支持基本上只需一行代码。先安装它：

```bash
npm install y-indexeddb
```

然后将它与 Y 文档连接：

```js
import { Editor } from '@tiptap/core'
import Collaboration from '@tiptap/extension-collaboration'
import * as Y from 'yjs'
import { IndexeddbPersistence } from 'y-indexeddb'

const ydoc = new Y.Doc()

// Store the Y document in the browser
new IndexeddbPersistence('example-document', ydoc)

const editor = new Editor({
  extensions: [
    // …
    Collaboration.configure({
      document: ydoc,
    }),
  ],
})
```

这样，所有变更都会存储在浏览器中，即使你关闭标签页、断开网络，或在离线时进行修改也不例外。下次联网时，WebSocket provider 会尝试建立连接，并最终同步这些变更。

没错，这就是魔法。如前所述，这一切都基于出色的 Y.js 框架。如果你正在使用它或我们的集成，强烈建议你在 GitHub 上[赞助 Kevin Jahns](https://github.com/dmonad)，他是 Y.js 背后的核心开发者。

## 我们即插即用的协作后端
我们的协同编辑后端 Hocuspocus 负责同步、授权、持久化和扩展。下面来看看几个常见用例！

### 文档名称
这里所有示例中的文档名称都是 `'example-document'`，但它可以是任意字符串。在实际应用中，你可能会使用实体名称和实体 ID。示例如下：

```js
const documentName = 'page.140'
```

在后端，你可以拆分这个字符串，判断用户正在编辑 ID 为 140 的页面，并据此管理授权等事项。新文档会按需自动创建；除了向 provider 传递一个字符串之外，无需专门告知后端。

如果你想在一个 Y.js 文档中同步多个字段，只需向协作扩展传入不同的 fragment 名称：

```js
// a Tiptap instance for the field
Collaboration.configure({
  document: ydoc,
  field: 'title',
})

// and another instance for the summary, both in the same Y.js document
Collaboration.configure({
  document: ydoc,
  field: 'summary',
})
```

如果你的配置更复杂，例如涉及嵌套 fragment，也可以直接传入原始 Y.js fragment。此时会忽略 `document` 和 `field`。

```js
// a raw Y.js fragment
Collaboration.configure({
  fragment: ydoc.getXmlFragment('custom'),
})
```

### 身份验证与授权
使用 `onAuthenticate` hook，你可以检查客户端是否通过身份验证，并且是否有权查看当前文档。在实际应用中，这通常会涉及调用 API、查询数据库或其他操作。

如果抛出错误（或返回被拒绝的 Promise），与客户端的连接就会终止。如果客户端通过身份验证且获得授权，你还可以返回上下文数据，供其他 hooks 使用，但这并非必需。

```js
import { Server } from '@hocuspocus/server'

const server = Server.configure({
  async onAuthenticate({ token }) {
    // Example test if a user is authenticated
    if (token !== 'super-secret-token') {
      throw new Error('Not authorized!')
    }

    // You can set contextual data to use it in other hooks
    return {
      user: {
        id: 1234,
        name: 'John',
      },
    }
  },
})

server.listen()
```

## 注意事项

### Schema 更新
Tiptap 对 [schema](https://tiptap.dev/docs/editor/api/schema) 的要求非常严格：如果添加了配置的 schema 不允许的内容，该内容就会被丢弃。当多个 schema 不同的客户端共享文档变更时，这可能会导致异常行为。

假设你在应用中添加了编辑器，并且已经有用户开始使用。他们都加载了包含所有默认扩展的 Tiptap 实例，因此 schema 也只允许这些扩展所定义的内容。但你想在下次更新中添加任务列表，于是添加了相应扩展并重新部署。

新用户打开应用时使用的是更新后的 schema（包含任务列表），而其他用户仍在使用旧 schema（不包含任务列表）。新用户看到新添加的任务列表功能后，在文档中添加了一个任务列表，想让其他用户也看看这个功能。但任务列表刚添加进去就神奇地消失了。发生了什么？

当一位用户添加新的节点（或标记）时，该变更会同步给所有其他已连接的客户端。其他客户端将变更应用到编辑器中，而严格的 Tiptap 会根据它们的旧 schema 移除不允许的新节点。这个移除操作也会同步给其他已连接的客户端，于是新节点就从所有地方消失了。为避免这种情况，你有几个选择：

1. 永远不要更改 schema（不太现实）。
2. 部署新 schema 时强制客户端更新（不太容易）。
3. 跟踪 schema 版本，并对使用旧版 schema 的客户端禁用编辑器（取决于你的配置）。

我们计划提供一些功能，让这件事变得更容易。如果你有改进建议，欢迎告诉我们！
