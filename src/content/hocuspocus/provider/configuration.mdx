## 设置

### HocuspocusProvider

| 设置 | 描述 | 默认值 |
|---------------------|-------------------------------------------------------------------------------------------------------------------|-------------------------------------|
| `url` | Hocuspocus/WebSocket 服务器的 URL。 | `''` |
| `websocketProvider` | HocuspocusProviderWebsocket 实例，可用于在多个 provider 之间共享一个 socket。 | `new HocuspocusProviderWebsocket()` |
| `name` | 文档的名称。 | `''` |
| `document` | 实际的 Y.js 文档。此项为可选；默认会创建一个新文档，并可通过 provider.document 访问。 | `new Y.Doc()` |
| `token` | 将传递给服务器的身份验证令牌（支持字符串、函数和 Promise）。 | `''` |
| `awareness` | Awareness 对象，默认附加到传入的 Y.js 文档。 | `new Awareness()` |
| `forceSyncInterval` | 每隔 x 毫秒向服务器请求更新。 | `false` |
| `sessionAwareness` | 在每条消息的文档名称中嵌入唯一的 `sessionId`，以便多个文档名称相同的 provider 共用一个 WebSocket。连接到 v3 服务器时请保持为 `false`。此选项需要 v4 服务器。 | `false` |
| `flushDelay` | 在一个短时间窗口内批量发送文档和 awareness 更新（单位：毫秒），而不是每次更改都发送一条消息。在大量编辑时可减少 WebSocket 流量。增加的延迟最多为 `flushDelay`，因此请将其设为较小的值（例如 `500`）。设为 `false` 可立即发送每次更改。参见[批量发送更新](#batching-outgoing-updates)。 | `false` |

### HocuspocusProviderWebsocket

| 设置 | 描述 | 默认值 |
|---------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------|
| `url` | Hocuspocus/WebSocket 服务器的 URL。 | `''` |
| `WebSocketPolyfill` | 在 Node.js 中运行时：传入一个 WebSocket polyfill，例如 ws。 | `WebSocket` |
| `timeout` | 超时时间，单位为毫秒。如果 timeout 非零，则会使用 setTimeout 设置计时器。超时触发后，后续尝试将被中止。 | `0` |
| `factor` | 用于让延迟按指数增长的系数。 | `2` |
| `maxAttempts` | 最大尝试次数；设为 0 表示尝试次数不受限制。 | `0` |
| `minDelay` | 启用 jitter 时，minDelay 用于设置延迟下限。禁用 jitter 时，此属性无效。 | `1000` |
| `maxDelay` | 启用 factor 时，maxDelay 用于设置延迟上限。如果计算延迟时不需要上限，可将其设为 0。 | `30000` |
| `jitter` | 如果 jitter 为 true，则计算出的延迟将是一个随机整数，范围为 minDelay 到当前轮次计算出的延迟。 | `true` |
| `messageReconnectTimeout` | 配置的 messageReconnectTimeout 时间内未收到消息时关闭连接。 | `30000` |
| `delay` | 每次尝试之间的延迟，单位为毫秒。可提供一个系数，让延迟按指数增长。 | `1000` |
| `initialDelay` | initialDelay 是首次尝试前的等待时间。此选项通常应设为 0，因为一般希望立即进行首次尝试。 | `0` |
| `onMaxAttemptsFailed` | 当 `maxAttempts` 指定的所有重连尝试均失败且 provider 停止重试时，调用此回调并传入 `{ error }`。默认 `maxAttempts: 0` 时不会触发，因为 provider 会无限重试。参见[处理重连失败](#reacting-to-failed-reconnects)。 | `() => null` |


## 用法

设置 provider 无需太多操作，简单示例请参见[入门指南](/hocuspocus/provider/install)

## 批量发送更新

默认情况下，provider 每次更改都会发送一条 WebSocket 消息。在大量编辑时——例如快速输入、大段粘贴或光标快速移动——可能会产生许多小消息。将 `flushDelay` 设为毫秒数，即可在一个短时间窗口内批量发送文档和 awareness 更新：

```js
import { HocuspocusProvider } from '@hocuspocus/provider'

const provider = new HocuspocusProvider({
  url: 'ws://127.0.0.1:1234',
  name: 'example-document',
  flushDelay: 500,
})
```

在每个窗口内，缓冲的 Yjs 更新会通过 `Y.mergeUpdates` 合并为一条消息，而 awareness 则会合并为每个发生变化的客户端的最新状态。该窗口采用固定批处理，而不是会重置的防抖，因此即使用户持续输入，增加的延迟也不会超过 `flushDelay`。请将其设为较小的值（例如 `500`），以免其他客户端看到更新的时间延后。

调用 `provider.flushPendingUpdates()` 可以强制立即发送当前窗口中所有缓冲的内容。

## 处理重连失败

默认情况下，`maxAttempts: 0` 会让 provider 无限重连，因此连接失败不会成为最终状态。如果将 `maxAttempts` 设为一个数字，provider 会在用尽这些尝试次数后停止重试，并通过 `onMaxAttemptsFailed` 通知你。你可以在此处显示“你已离线”状态或“重试”按钮：

```js
import { HocuspocusProvider } from '@hocuspocus/provider'

const provider = new HocuspocusProvider({
  url: 'ws://127.0.0.1:1234',
  name: 'example-document',
  maxAttempts: 5,
  onMaxAttemptsFailed: ({ error }) => {
    console.error('Could not connect to the server:', error)
  },
})
```

`error` 表示导致最后一次尝试失败的原因：可能是 WebSocket 错误；如果 socket 关闭前从未触发错误，则会是一个包含关闭代码和原因的 `Error`。

这是 `HocuspocusProviderWebsocket` 的事件，特意不会转发给 `HocuspocusProvider`，因为一个 socket 可能由多个文档共享。将 `onMaxAttemptsFailed` 传给 `HocuspocusProvider` 是可行的（该选项会传递给它为你创建的 socket），但如果之后再绑定监听器，则必须在 socket 上进行：

```js
import { HocuspocusProvider, HocuspocusProviderWebsocket } from '@hocuspocus/provider'

const socket = new HocuspocusProviderWebsocket({
  url: 'ws://127.0.0.1:1234',
  maxAttempts: 5,
})

socket.on('maxAttemptsFailed', ({ error }) => {
  // …
})

const provider = new HocuspocusProvider({
  websocketProvider: socket,
  name: 'example-document',
})
```

停止重试并非永久状态。调用 websocket provider 的 `connect()` 即可重新开始一轮尝试，例如可在“重试”按钮的处理逻辑中调用：

```js
provider.configuration.websocketProvider.connect()
```
