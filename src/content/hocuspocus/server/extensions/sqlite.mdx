## 简介

对于本地开发，只需几行代码就能快速准备好一个数据库，非常方便。这正是 SQLite 扩展的用途。

## 安装

按如下方式安装 SQLite 扩展：

```bash
npm install @hocuspocus/extension-sqlite better-sqlite3
npm install -D @types/better-sqlite3
```

从 v4 开始，该扩展使用 [`better-sqlite3`](https://github.com/WiseLibs/better-sqlite3) 替代已停止维护的 `sqlite3` 包。如果你要从 v3 升级，请运行 `npm uninstall sqlite3` 卸载旧依赖。现有 SQLite 数据库文件完全兼容，无需迁移数据。

## 配置

**database**

有效值包括文件名、表示匿名内存数据库的 `":memory:"`，以及表示匿名磁盘数据库的空字符串。匿名数据库不会持久化，关闭数据库句柄时其中的内容会丢失。

https://github.com/mapbox/node-sqlite3/wiki/API#new-sqlite3databasefilename-mode-callback

默认值：`:memory:`

**schema**

为你创建的 SQLite 架构。

默认值：

```sql
CREATE TABLE IF NOT EXISTS "documents" (
  "name" varchar(255) NOT NULL,
  "data" blob NOT NULL,
  UNIQUE(name)
)
```

如果你在 v3 中编写了**自定义架构**，请注意，v4 的 `better-sqlite3` 使用不带 `$` 前缀的命名参数——请在查询中将 `$name` 改为 `name`，将 `$data` 改为 `data`。

**fetch**

用于从 SQLite 获取数据的异步函数。如果你更改了架构，可能需要覆盖查询语句。

**store**

用于将数据存储到 SQLite 的异步函数。如果你更改了架构，可能需要覆盖查询语句。

**用法**

默认情况下，数据只会“存储”在 `:memory:` 中，因此停止服务器时数据就会被清除。你可以传入文件名，将数据持久化到磁盘。

```js
import { Server } from "@hocuspocus/server";
import { SQLite } from "@hocuspocus/extension-sqlite";

const server = new Server({
  extensions: [
    new SQLite({
      database: "db.sqlite",
    }),
  ],
});

server.listen();
```

## 故障排除

### `Could not locate the bindings file`

`better-sqlite3` 附带预编译的原生绑定，但它们未必能立即适配最新版本的 Node.js。如果服务器启动时抛出错误 `Error: Could not locate the bindings file`，请在服务器项目中从源代码重新构建绑定：

```bash
npm rebuild better-sqlite3 --build-from-source
```

此命令会针对你使用的 Node.js、操作系统和处理器架构组合编译原生插件。你需要准备可用的 C++ 工具链（macOS 上的 Xcode Command Line Tools、Debian/Ubuntu 上的 `build-essential`，或 Windows 上的 Visual Studio Build Tools）。
