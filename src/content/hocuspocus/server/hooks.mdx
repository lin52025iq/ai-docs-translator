## 简介

Hocuspocus 提供钩子，用于扩展其功能并将其集成到现有应用中。钩子的配置方式与[其他配置选项](/hocuspocus/server/configuration)相同，只需将其配置为简单的方法即可。

钩子会将钩子负载作为第一个参数。负载是一个对象，其中包含可供你使用和修改的数据。借助这一简单机制，你可以构建复杂的功能，例如[扩展](/hocuspocus/guides/custom-extensions)。

钩子必须返回一个 [Promise](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise)；最简单的做法是将函数标记为 `async`（从 v4 开始要求使用 Node.js 22+）。这样，你就可以执行 API 请求、运行数据库查询、触发 Webhook，或执行其他任何集成应用所需的操作。

从 v4 开始，钩子负载使用符合 Web 标准的 `Request` 和 `Headers` 对象，取代 Node.js 的 `IncomingMessage` 和 `IncomingHttpHeaders`。请使用 `requestHeaders.get('authorization')` 读取标头，而不是 `requestHeaders['authorization']`。`onUpgrade` 和 `onRequest` 钩子是例外——它们仍使用 Node.js 类型，因为它们在 WebSocket 升级前的 HTTP 层运行。

## 生命周期

钩子会在 Hocuspocus 生命周期的不同阶段调用。例如，当你在服务器实例上调用 `listen()` 方法时，就会调用 `onListen` 钩子。

某些钩子不仅允许你响应事件，还允许你拦截事件。例如，底层 WebSocket 服务器建立新连接时会触发 `onConnect` 钩子。你可以在钩子中拒绝 Promise（或在使用 async 时抛出空异常），以终止连接并停止钩子链。

## 钩子链

扩展通过钩子为 Hocuspocus 添加功能。它们会按照在配置中的注册顺序依次调用，而你的配置则位于钩子链的最后。

如果钩子中的 Promise 被拒绝，后续扩展或你的配置就不会再被调用。这类似于请求必须依次经过的一系列中间件。使用钩子时请牢记这一点。

举例来说，如果用户无权连接，只需在 `onAuthenticate()` 钩子中抛出错误即可。是不是很简单？

## 用法

```js
import { Server } from "@hocuspocus/server";

const server = new Server({
  async onAuthenticate({ documentName, token }) {
    // Could be an API call, DB query or whatever …
    // The endpoint should return 200 OK in case the user is authenticated, and an http error
    // in case the user is not.
    return axios.get("/user", {
      headers: {
        Authorization: `Bearer ${token}`,
      },
    });
  },
});

server.listen();
```

## 钩子

### beforeHandleMessage

服务器收到消息后、处理或应用消息之前，会调用 `beforeHandleMessage` 钩子。此钩子可用于拒绝消息（例如，身份验证令牌已过期时），也可以检查更新消息，并根据自定义规则决定是否接受。若在钩子中抛出错误，连接将关闭。你可以抛出一个实现了 CloseEvent 的错误，以返回自定义代码或原因（参见下方示例）。

**钩子负载**

传递给 `beforeHandleMessage` 钩子的 `data` 包含以下属性：

```js
import { URLSearchParams } from "url";
import { Doc } from "yjs";
import { CloseEvent } from "@hocuspocus/common";

const data = {
  clientsCount: number,
  context: any,
  document: Doc,
  documentName: string,
  instance: Hocuspocus,
  requestHeaders: Headers,
  requestParameters: URLSearchParams,
  update: Uint8Array,
  socketId: string,
};
```

`context` 包含之前 `onConnect` 钩子提供的数据。

**示例**

```js
import { debounce } from "debounce";
import { Server } from "@hocuspocus/server";
import { TiptapTransformer } from "@hocuspocus/transformer";
import { writeFile } from "fs";

let debounced;

const server = new Server({
  beforeHandleMessage(data) {
    if (data.context.tokenExpiresAt <= new Date()) {
      const error: CloseEvent = {
        reason: "Token expired",
      };

      throw error;
    }
  },
});

server.listen();
```

### afterHandleMessage

处理完入站消息后（也就是将 Yjs 更新应用到文档后），会调用 `afterHandleMessage` 钩子。它与 `beforeHandleMessage` 相对应。无论应用更新成功还是抛出错误，都会触发此钩子；但如果 `beforeHandleMessage` 拒绝了消息，则不会触发此钩子（此时消息根本不会被应用）。

你可以使用此钩子响应已应用的更新，例如记录指标、写入日志，或在文档状态发生变化后触发副作用。

**钩子负载**

传递给 `afterHandleMessage` 钩子的 `data` 包含以下属性：

```js
import { URLSearchParams } from "url";
import { Doc } from "yjs";
import type { Connection } from "@hocuspocus/server";

const data = {
  clientsCount: number,
  context: any,
  document: Doc,
  documentName: string,
  instance: Hocuspocus,
  requestHeaders: Headers,
  requestParameters: URLSearchParams,
  update: Uint8Array,
  socketId: string,
  connection: Connection,
};
```

`context` 包含之前 `onConnect` 钩子提供的数据。

**示例**

```js
import { Server } from "@hocuspocus/server";

const server = new Server({
  async afterHandleMessage({ documentName, context }) {
    console.log(`Applied an update to "${documentName}" for ${context.user?.name}`);
  },
});

server.listen();
```

### onAuthenticate

当服务器收到客户端 provider 发来的身份验证请求时，会调用 `onAuthenticate` 钩子。此钩子应返回一个 Promise。抛出异常或拒绝 Promise 都会终止连接。请注意，如果未指定令牌，调用此钩子时传入的令牌将是空字符串。

**钩子负载**

传递给 `onAuthenticate` 钩子的 `data` 包含以下属性：

```js
import { URLSearchParams } from "url";
import { Doc } from "yjs";

const data = {
  documentName: string,
  instance: Hocuspocus,
  requestHeaders: Headers,
  requestParameters: URLSearchParams,
  request: Request,
  socketId: string,
  token: string,
  providerVersion: string | undefined,
  connection: {
    readOnly: boolean,
  },
};
```

**示例**

```js
import { Server } from "@hocuspocus/server";

const server = new Server({
  async onAuthenticate(data) {
    const { token } = data;

    // Example test if a user is authenticated using a
    // request parameter
    if (token !== "super-secret-token") {
      throw new Error("Not authorized!");
    }

    // Example to set a document to read only for the current user
    // thus changes will not be accepted and synced to other clients
    if (someCondition === true) {
      data.connection.readOnly = true;
    }

    // You can set contextual data to use it in other hooks
    return {
      user: {
        id: 1234,
        name: "John",
      },
    };
  },
});

server.listen();
```

### onTokenSync

当服务器收到已连接 provider 发来的令牌同步请求时，会调用 `onTokenSync` 钩子。借助此钩子，服务器可以在活动会话期间验证用户令牌，而无需完全重新建立连接。

**钩子负载**

传递给 `onTokenSync` 钩子的 `data` 包含以下属性：

```js
const data = {
  context: any,
  document: Doc,
  documentName: string,
  instance: Hocuspocus,
  requestHeaders: Headers,
  requestParameters: URLSearchParams,
  socketId: string,
  token: string,
  connectionConfig: {
    readOnly: boolean,
  },
  connection: Connection,
};
```

**示例**

```js
import { Server } from "@hocuspocus/server";

const server = new Server({
  async onTokenSync({ token, context, connection }) {
    // Validate the current token
    const isValid = await validateToken(token);

    if (!isValid) {
      throw new Error("Token has expired or is invalid");
    }

    // Update permissions if changed
    const permissions = await getUserPermissions(context.userId);
    if (permissions.readOnly !== connection.readOnly) {
      connection.readOnly = permissions.readOnly;
    }

    return { lastTokenSync: new Date() };
  },
});

server.listen();
```

**Provider 用法**

```js
// Provider sends token to server
provider.sendToken();
```

**服务器用法**

```js
// Server requests token from provider
const connection = document.connections.values().next().value?.connection;
connection.requestToken();
```

### beforeHandleAwareness

服务器解码入站 awareness 消息后、将其应用到文档的 awareness 状态之前，会调用 `beforeHandleAwareness` 钩子。与观察已应用的 awareness 变化的 `onAwarenessUpdate` 不同，`beforeHandleAwareness` 可以让你在更新写入文档的 awareness 状态或广播给其他节点之前检查并重写该更新。

此钩子接收解码后的、按客户端区分的 `states`。它是一个可变 `Map`，以 Yjs `clientId` 为键。你可以就地修改这个 Map 及其中的状态对象，以便：

- 更改状态对象中的字段（例如，用已验证的 `user` 覆盖客户端提供的值）。
- 使用 `states.delete(clientId)` 从广播中移除某个对等端。
- 使用 `states.set(clientId, ...)` 添加或替换一个合成状态。

钩子链中的所有钩子运行完毕后，发送给对等端的编码更新将反映 Map 的最终内容。抛出错误即可拒绝整个更新——既不会应用，也不会广播。

多个扩展可以自然地串联运行：每个扩展都会看到前一个扩展修改后的 Map，并可继续修改。扩展会先于配置级钩子运行。

**钩子负载**

传递给 `beforeHandleAwareness` 钩子的 `data` 包含以下属性：

```js
import { Awareness } from 'y-protocols/awareness'
import type { Connection, TransactionOrigin } from '@hocuspocus/server'

const data = {
  awareness: Awareness,
  clientsCount: number,
  // Connection context populated by `onAuthenticate`. `undefined` when the
  // update did not originate from a client connection (e.g. server-internal
  // writes via DirectConnection).
  context: any | undefined,
  document: Document,
  documentName: string,
  instance: Hocuspocus,
  requestHeaders: Headers,
  requestParameters: URLSearchParams,
  socketId: string,
  // Per-client awareness states decoded from the inbound update, keyed by
  // Yjs clientId. Mutate this map in place to rewrite the update.
  states: Map<number, Record<string, any>>,
  // The TransactionOrigin that will be passed to applyAwarenessUpdate.
  // Use isTransactionOrigin() to discriminate sources.
  transactionOrigin: TransactionOrigin,
  // Convenience shortcut: `origin.connection` when transactionOrigin is a
  // ConnectionTransactionOrigin, otherwise undefined.
  connection?: Connection,
}
```

**示例：用服务器验证过的字段覆盖客户端的值**

```js
import { Server } from '@hocuspocus/server'

const server = new Server({
  async beforeHandleAwareness({ states, context }) {
    for (const state of states.values()) {
      // Overwrite whatever the client claimed with what the server knows.
      state.user = context?.user ?? null
    }
  },
})

server.listen()
```

**示例：完全拒绝更新**

```js
import { Server } from '@hocuspocus/server'

const server = new Server({
  async beforeHandleAwareness({ context }) {
    if (context?.readOnly) {
      throw new Error('Awareness updates not allowed for read-only sessions')
    }
  },
})

server.listen()
```

### onAwarenessUpdate

awareness 发生变化时，会调用 `onAwarenessUpdate` 钩子（参见 [Provider Awareness API](/hocuspocus/provider/events)）。

**钩子负载**

传递给 `onAwarenessUpdate` 钩子的 `data` 包含以下属性：

```js
import { Awareness } from 'y-protocols/awareness'
import type { Connection, TransactionOrigin } from '@hocuspocus/server'

const data = {
  document: Document,
  documentName: string,
  instance: Hocuspocus,
  update: Uint8Array,
  added: number[],
  updated: number[],
  removed: number[],
  awareness: Awareness,
  states: { clientId: number, [key: string | number]: any }[],
  // Structured origin of the awareness update (since v4)
  transactionOrigin: TransactionOrigin,
  // Optional: the connection that triggered this update (since v4)
  connection?: Connection,
}
```

从 v4 开始，负载已简化。特定于连接的字段（`context`、`requestHeaders`、`requestParameters`、`socketId`）已被移除。如需访问这些字段，请使用可选的 `connection`（例如 `connection?.context`）。

**示例**

```js
const provider = new HocuspocusProvider({
  url: "ws://127.0.0.1:1234",
  name: "example-document",
  document: ydoc,
  onAwarenessUpdate: ({ states }) => {
    currentStates = states;
  },
});
```

### onChange

文档本身发生变化时，会调用 `onChange` 钩子。此钩子应返回一个 Promise。

需要注意的是，每个文档只会调用一次此钩子。由于负载中包含 `context` 和 `update`（见下文），你可以据此响应特定连接产生的更改。

强烈建议对开销较大的操作进行防抖，因为此钩子每秒可能触发多次。

**钩子负载**

传递给 `onChange` 钩子的 `data` 包含以下属性：

```js
import { URLSearchParams } from "url";
import { Doc } from "yjs";
import type { TransactionOrigin } from "@hocuspocus/server";

const data = {
  clientsCount: number,
  context: any,
  document: Doc,
  documentName: string,
  instance: Hocuspocus,
  requestHeaders: Headers,
  requestParameters: URLSearchParams,
  update: Uint8Array,
  socketId: string,
  // Structured origin (since v4) — use isTransactionOrigin() and switch on .source
  transactionOrigin: TransactionOrigin,
};
```

`context` 包含之前 `onConnect` 钩子提供的数据。

**示例**

:::warning 使用主存储
以下示例不适合作为主存储，因为将内容序列化为 JSON 再反序列化，不会保存协作历史步骤，只会保存最终文档。此示例仅用于保存应用视图所需的最终文档。有关主存储，请参阅 [Database 扩展](/hocuspocus/server/extensions/database)。
:::

```js
import { debounce } from "debounce";
import { Server } from "@hocuspocus/server";
import { TiptapTransformer } from "@hocuspocus/transformer";
import { writeFile } from "fs";

let debounced;

const server = new Server({
  async onChange(data) {
    const save = () => {
      // Convert the y-doc to something you can actually use in your views.
      // In this example we use the TiptapTransformer to get JSON from the given
      // ydoc.
      const prosemirrorJSON = TiptapTransformer.fromYdoc(data.document);

      // Save your document. In a real-world app this could be a database query
      // a webhook or something else
      writeFile(`/path/to/your/documents/${data.documentName}.json`, prosemirrorJSON);

      // Maybe you want to store the user who changed the document?
      // Guess what, you have access to your custom context from the
      // onConnect hook here. See authorization & authentication for more
      // details
      console.log(`Document ${data.documentName} changed by ${data.context.user.name}`);
    };

    debounced?.clear();
    debounced = debounce(save, 4000);
    debounced();
  },
});

server.listen();
```

### onLoadDocument

调用 `onLoadDocument` 钩子是为了从存储中获取现有数据。你可能习惯在应用中加载 JSON/HTML 文档，但这并不是 Y.js 的工作方式。要让 Y.js 正常运行，我们需要保存更改历史。只有这样，才能合并来自多个来源的更改。

你仍然可以存储 JSON/HTML 文档，但应将其视为数据的“视图”，而不是数据源。

**从 JSON/HTML 创建 Y.js 文档（一次性操作）**

你可以根据现有数据（例如 JSON）创建 Y.js 文档。此方法仅用于迁移数据，不应作为永久的数据存储方式。

为此，你可以使用 Transformer 包。对于兼容 Tiptap 的 JSON，代码如下：

```js
import { TiptapTransformer } from "@hocuspocus/transformer";
import Document from "@tiptap/extension-document";
import Paragraph from "@tiptap/extension-paragraph";
import Text from "@tiptap/extension-text";

const ydoc = TiptapTransformer.toYdoc(
  // the actual JSON
  json,
  // the `field` you’re using in Tiptap. If you don’t know what that is, use 'default'.
  "default",
  // The Tiptap extensions you’re using. Those are important to create a valid schema.
  [Document, Paragraph, Text]
);
```

如果要导入 HTML，必须先[将其转换为兼容 Tiptap 的 JSON](/editor/api/utilities/html#generating-json-from-html)。

不过，无论数据来自何处，我们都要求你从 `onLoadDocument` 钩子返回一个 Y.js 文档（或从 v4 开始支持的原始 `Uint8Array` Yjs 更新）。

```js
import { Server } from '@hocuspocus/server'

const server = new Server({
  async onLoadDocument(data) {
    // fetch the Y.js document from somewhere
    const ydoc = …

    return ydoc
  },
})

server.listen()
```

从 v4 开始，你也可以直接返回原始的 Yjs 更新 `Uint8Array`，这对存储扩展很方便：

```js
const server = new Server({
  async onLoadDocument({ documentName }) {
    const update = await loadUpdateFromStorage(documentName)
    return update // Uint8Array
  },
})
```

**获取 Y.js 文档（推荐）**

你可以通过多种方式将 Y.js 文档及其历史记录存储在任意位置。通常，你应使用 `onStoreDocument` 钩子。对于发生变化的文档，该钩子会经过防抖处理，并每隔几秒执行一次。它会提供当前的 Y.js 文档，由你决定将其存储在哪里。不用担心，我们提供了一些方便的方式。

如果你只想快速运行起来，可以查看用于本地开发的 [`SQLite`](/hocuspocus/server/extensions/sqlite) 扩展，以及便于获取和存储文档的通用 [`Database`](/hocuspocus/server/extensions/database) 扩展。

**钩子负载**

传递给 `onLoadDocument` 钩子的 `data` 包含以下属性：

```js
import { Doc } from "yjs";

const data = {
  context: any,
  document: Doc,
  documentName: string,
  instance: Hocuspocus,
  requestHeaders: Headers,
  requestParameters: URLSearchParams,
  socketId: string,
};
```

`context` 包含之前 `onConnect` 钩子提供的数据。

### afterLoadDocument

文档成功加载后，会调用 `afterLoadDocument` 钩子。这与 `onLoadDocument` 钩子不同，后者属于文档创建流程的一部分；例如，数据库中找不到文档时，创建流程可能会失败。

由于 `afterLoadDocument` 只会在所有 `onLoadDocument` 钩子都成功后运行，此时你可以确定服务器已将该文档视为打开状态。

**钩子负载**

传递给 `afterLoadDocument` 钩子的 `data` 包含以下属性：

```js
import { Doc } from "yjs";

const data = {
  context: any,
  document: Doc,
  documentName: string,
  instance: Hocuspocus,
  requestHeaders: Headers,
  requestParameters: URLSearchParams,
  socketId: string,
};
```

### onRequest

Hocuspocus 内部的 HTTP 服务器收到新请求时，会调用 `onRequest` 钩子。此钩子应返回一个 Promise。如果你抛出空异常或拒绝返回的 Promise，钩子链中的后续钩子将不会运行，因此你可以自行响应请求。这类似于请求中间件的概念。

如果你想在 Hocuspocus 使用的同一端口上创建自定义路由，这个钩子就很有用。

**钩子负载**

传递给 `onRequest` 钩子的 `data` 包含以下属性：

```js
import { IncomingMessage, ServerResponse } from "http";

const data = {
  request: IncomingMessage,
  response: ServerResponse,
  instance: Hocuspocus,
};
```

**示例**

```js
import { Server } from "@hocuspocus/server";

const server = new Server({
  onRequest(data) {
    return new Promise((resolve, reject) => {
      const { request, response } = data;

      // Check if the request hits your custom route
      if (request.url?.split("/")[1] === "custom-route") {
        // Respond with your custom content
        response.writeHead(200, { "Content-Type": "text/plain" });
        response.end("This is my custom response, yay!");

        // Rejecting the promise will stop the chain and no further
        // onRequest hooks are run
        return reject();
      }

      resolve();
    });
  },
});

server.listen();
```

### onStoreDocument

文档发生变化后（即 `onChange` 钩子执行后），会调用 `onStoreDocument` 钩子，可用于将已更改的文档存储到持久化存储中。默认情况下，对 `onStoreDocument` 的调用会经过防抖处理（参见 `debounce` 和 `maxDebounce` 配置选项）。

实现此功能最简单的方式是扩展 `extension-database` 并实现 `fetch()` 和 `store()` 方法，正如我们在 `extension-sqlite` 中所做的那样。你也可以直接通过钩子实现 `onStoreDocument`，只需确保像 `extension-database` 中那样应用或编码 yDoc 的状态即可。

从 v4 开始，任何文档更改都会触发 `onStoreDocument`，而不仅仅是由 WebSocket 引起的更改。由于此钩子现在也可能由与特定连接无关的来源触发（例如直接连接、Redis 复制），其负载结构也进行了调整。如果钩子抛出错误，文档会保留在内存中并重试，以避免数据丢失；服务器关闭时，`Server.destroy()` 会刷新所有待处理的防抖存储操作。

如果想针对某次本地变更跳过存储钩子，可以在打开直接连接时，在 `LocalTransactionOrigin` 上设置 `skipStoreHooks`。扩展也可以抛出 `SkipFurtherHooksError`（来自 `@hocuspocus/common`），表示持久化工作已处理完毕，应跳过剩余钩子。

**钩子负载**

传递给 `onStoreDocument` 钩子的 `data` 包含以下属性：

```js
import { Doc } from "yjs";
import type { TransactionOrigin } from "@hocuspocus/server";

const data = {
  clientsCount: number,
  document: Doc,
  documentName: string,
  instance: Hocuspocus,
  // Context of the last connection that triggered the hook (was `context` in v3)
  lastContext: any,
  // Structured origin of the last transaction (was `transactionOrigin` in v3)
  lastTransactionOrigin: TransactionOrigin,
};
```

在 v3 中，此负载还包含 `context`、`requestHeaders`、`requestParameters`、`socketId` 和 `transactionOrigin`。在 v4 中，这些字段已被移除或重命名——如需访问特定于连接的数据，请使用 `lastContext`。

### onUpgrade

Hocuspocus 内部的 HTTP 服务器收到新的升级请求时，会调用 `onUpgrade` 钩子。此钩子应返回一个 Promise。如果你抛出空异常或拒绝返回的 Promise，钩子链中的后续钩子将不会运行，因此你可以自行响应请求并完成升级。这类似于请求中间件的概念。

如果你想在 Hocuspocus 使用的同一端口上创建自定义 WebSocket 路由，这个钩子就很有用。

**钩子负载**

传递给 `onUpgrade` 钩子的 `data` 包含以下属性：

```js
import { IncomingMessage } from "http";
import { Socket } from "net";

const data = {
  head: any,
  request: IncomingMessage,
  socket: Socket,
  instance: Hocuspocus,
};
```

**示例**

```js
import { Server } from "@hocuspocus/server";
import WebSocket, { WebSocketServer } from "ws";

const server = new Server({
  onUpgrade(data) {
    return new Promise((resolve, reject) => {
      const { request, socket, head } = data;

      // Check if the request hits your custom route
      if (request.url?.split("/")[1] === "custom-route") {
        // Create your own websocket server to upgrade the request, make
        // sure noServer is set to true, because we're handling the upgrade
        // ourselves
        const websocketServer = new WebSocketServer({ noServer: true });
        websocketServer.on("connection", (connection: WebSocket, request: IncomingMessage) => {
          // Put your application logic here to respond to new connections
          // and subscribe to incoming messages
          console.log("A new connection to our websocket server!");
        });

        // Handle the upgrade request within your own websocket server
        websocketServer.handleUpgrade(request, socket, head, (ws) => {
          websocketServer.emit("connection", ws, request);
        });

        // Rejecting the promise will stop the chain and no further
        // onUpgrade hooks are run
        return reject();
      }

      resolve();
    });
  },
});

server.listen();
```

### onStateless

服务器收到无状态消息后，会调用 `onStateless` 钩子。此钩子应返回一个 Promise。

**钩子负载**

传递给 `onListen` 钩子的 `data` 包含以下属性：

```js
const data = {
  connection: Connection,
  documentName: string,
  document: Document,
  payload: string,
}
```

**示例**

```js
import { Server } from '@hocuspocus/server'

const server = new Server({
  async onStateless({ payload, document, connection }) {
    // Output some information
    console.log(`Server has received a stateless message "${payload}"!`)
    // Broadcast a stateless message to all connections based on document
    document.broadcastStateless('This is a broadcast message.')
    // Send a stateless message to a specific connection
    connection.sendStateless('This is a specific message.')
  },
})

server.listen()
```

### beforeSync

处理同步消息之前会调用 `beforeSync` 钩子。如果你想检查即将应用到文档的同步消息，此钩子会很有用。
请注意，此钩子不是异步的。

**钩子负载**

```js
const data = {
  documentName: string,
  document: Document,
  // The y-protocols/sync message type
  type: number,
  // The payload of the y-protocols/sync message
  payload: Uint8Array,
}
```

**示例**

```js
import { Server } from '@hocuspocus/server'

const server = new Server({
  beforeSync({ payload, document, documentName, type }) {
    console.log(`Server will handle a sync message: "${payload}"!`)
  },
})

server.listen()
```

### afterUnloadDocument

服务器关闭文档后，会调用 `afterUnloadDocument` 钩子。此时文档已被销毁，你无法再访问它，但可以通知任何订阅了该文档的对象。

**钩子负载**

传递给 `onDestroy` 钩子的 `data` 包含以下属性：

```js
const data = {
  instance: Hocuspocus,
  documentName: string,
};
```

**示例**

```js
import { Server } from "@hocuspocus/server";

const server = new Server({
  async afterUnloadDocument(data) {
    // Output some information
    console.log(`Document ${data.documentName} was closed`);
  },
});

server.listen();
```
