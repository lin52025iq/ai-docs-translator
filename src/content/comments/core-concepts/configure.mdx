评论嵌入在 Collaboration Cloud 中的文档内。要启用评论，请集成 TiptapCollabProvider 并配置设置，以支持评论功能。

## Provider

`TiptapCollabProvider` 实例

默认值：`null`

```js
const tiptapCollabProvider = new TiptapCollabProvider({
  // your provider options
})

Comments.configure({
  provider: tiptapCollabProvider,
})
```

## Classes

用于线程的类名。

默认值：

```js
{
  thread: 'tiptap-thread',
  threadInline: 'tiptap-thread--inline',
  threadBlock: 'tiptap-thread--block',
  threadHovered: 'tiptap-thread--hovered',
  threadSelected: 'tiptap-thread--selected',
  threadResolved: 'tiptap-thread--resolved',
  threadUnresolved: 'tiptap-thread--unresolved',
}
```

```js
Comments.configure({
  classes: {
    thread: 'my-thread',
    threadInline: 'my-thread-inline',
    threadBlock: 'my-thread-block',
    threadHovered: 'my-thread-hovered',
    threadSelected: 'my-thread-selected',
    threadResolved: 'my-thread-resolved',
    threadUnresolved: 'my-thread-unresolved',
  },
})
```

## onClickThread

点击线程时调用的回调。如果点击了线程，线程 ID 会传递给回调；如果没有点击线程，则传递 `null`。

默认值：`undefined`

```js
Comments.configure({
  // ID can be a string or null
  onClickThread: (id) => console.log('Thread clicked', id),
})
```

## deleteUnreferencedThreads

用于控制是否删除文档中没有引用的线程的布尔选项。默认情况下，当线程不再被文档引用时，会将其标记为已删除。这有助于清理不再需要的线程。

不过，如果希望即使线程未被文档引用也保留它们，可以将此选项设为 `false`。

**默认值：** `true`

```js
Comments.configure({
  // keep threads even if they are not referenced in the document
  deleteUnreferencedThreads: false,
})
```

如果配置了 `onThreadAnchorRemoved`，该选项会取代自动清理。其 `defaultHandler()` 仍会遵循 `deleteUnreferencedThreads` 的设置。

## onThreadAnchorRemoved

当本地编辑移除线程在文档中的最后一个锚点时运行的回调。锚点可以是行内线程标记或块级线程节点。编辑完成后、清理操作更改线程数据之前，会运行此回调。它只会在执行编辑的客户端上运行，不会在远程接收更改的客户端上运行。

**默认值：** `undefined`，此时自动清理由 `deleteUnreferencedThreads` 控制。

将此选项设为 `false` 可在锚点消失时禁用自动清理。除非回调调用 `defaultHandler()`，否则它会取代清理操作。当 `deleteUnreferencedThreads` 为 `true` 时，默认处理程序会软删除未被引用的线程。

例如，当线程的锚点消失时，将线程标记为已解决并保留其评论：

```js
CommentsKit.configure({
  onThreadAnchorRemoved: ({ editor, threadId }) => {
    editor.commands.resolveThread({ id: threadId })
  },
})
```

回调会接收以下参数：

| 参数              | 说明                                                   |
| ----------------- | ------------------------------------------------------ |
| `editor`          | 线程的最后一个锚点被移除的编辑器。                     |
| `threadId`        | 线程 ID。                                              |
| `thread`          | 当前线程数据，包括其评论。                             |
| `field`           | 包含该线程的协作字段。                                 |
| `removedBy`       | `'edit'`、`'command'` 或 `'undoRedo'`。                |
| `defaultHandler`  | 运行已配置的默认清理操作。                             |

使用 `removeThread({ id })` 显式移除锚点时，`removedBy` 的值为 `'command'`。调用 `removeThread({ id, deleteThread: true })` 会直接删除线程并跳过此回调。为修订建议创建的线程由该集成处理，也会跳过此回调。

请在回调中同步调用 `defaultHandler()`。它最多运行一次；回调返回后再调用将不起作用。例如，记录锚点移除事件并保留默认清理行为：

```js
CommentsKit.configure({
  onThreadAnchorRemoved: ({ threadId, removedBy, defaultHandler }) => {
    console.log('Thread anchor removed', threadId, removedBy)
    defaultHandler()
  },
})
```

## onThreadStateChanged

当 Yjs 事务更改编辑器协作字段中现有线程的状态后运行的回调。它会处理本地和远程更改。创建线程、添加评论或更新线程元数据都不会触发此回调。

**默认值：** `undefined`，此时使用默认文档处理行为。永久删除线程会移除其锚点并保留锚点处的文本。解决、重新打开、软删除或恢复线程都会保留其锚点。

将此选项设为 `false` 可禁用针对线程状态更改的自动文档处理。除非回调调用 `defaultHandler()`，否则它会取代该处理行为。

```js
CommentsKit.configure({
  onThreadStateChanged: ({ event, threadId, origin, defaultHandler }) => {
    console.log('Thread state changed', event, threadId, origin)
    defaultHandler()
  },
})
```

回调会接收以下参数：

| 参数                | 说明                                                                                  |
| ------------------- | ------------------------------------------------------------------------------------- |
| `editor`            | 处理状态更改的编辑器。                                                                |
| `threadId`          | 线程 ID。                                                                             |
| `event`             | `'resolved'`、`'unresolved'`、`'deleted'` 或 `'restored'`。                           |
| `previousThread`    | 更改前的线程数据。                                                                    |
| `thread`            | 更改后的线程数据。永久删除后，此值为 `undefined`。                                    |
| `field`             | 包含该线程的协作字段。                                                                |
| `origin`            | 根据 Yjs 事务确定的 `'local'` 或 `'remote'`。                                         |
| `defaultHandler`    | 执行默认文档处理。请在回调中同步调用，且最多调用一次。回调返回后再调用将不起作用。     |

`'deleted'` 事件涵盖软删除和永久删除。`'restored'` 事件表示软删除的线程已恢复，并不表示其文档锚点已恢复。

例如，在线程被解决时移除锚点，同时保留线程及其评论：

```js
CommentsKit.configure({
  onThreadStateChanged: ({ editor, threadId, event, defaultHandler }) => {
    if (event === 'resolved') {
      editor.commands.removeThread({ id: threadId, deleteThread: false })
    }
    defaultHandler()
  },
})
```

在此回调中移除锚点不会触发 `onThreadAnchorRemoved`，也不会自动删除已脱离锚点的线程。在此回调中进行的线程状态更改不会再次触发本地状态回调。重新打开线程不会重新创建由自定义处理移除的锚点。

## trackedChangesIntegration

用于控制是否启用自动[修订](/editor/extensions/functionality/tracked-changes)集成的布尔选项。启用后，系统会根据修订建议的生命周期事件自动创建、更新、解决或删除线程。

如果未使用修订扩展，并且希望阻止注册相关事件监听器和 ProseMirror 插件，请将此选项设为 `false`。

**默认值：** `true`

```js
Comments.configure({
  // disable Track Changes integration if you don't use that extension
  trackedChangesIntegration: false,
})
```

## respectParentSchema

启用 `respectParentSchema: true` 后，块级线程中的本地编辑必须遵循父节点的内容规则。例如，如果某个分区允许段落但不允许列表，那么其中的块级线程就不能包含列表。如果能够保留文本，扩展会将单个无效文本块转换为有效内容；无法修复的编辑则会被拒绝。

现有的无效块级线程不会迁移。只要其子块类型未发生变化，其中的文本仍可编辑。请在每个协作客户端上启用此选项。

**默认值：** `false`

```js
CommentsKit.configure({
  respectParentSchema: true,
})
```

## useLegacyWrapping

<Callout title="警告" variant="warning">
  新的包裹机制为块节点上的线程使用了不同的 schema，与旧版包裹行为不兼容。如果将此选项设为 `false`，却未将现有线程节点映射到新的 schema，文档中的线程内容将被移除。
</Callout>

用于控制多行评论是否使用旧版包裹机制的布尔选项。对于新的实现，我们建议将此选项设为 `false`；现有集成则可以继续使用旧版行为。此选项仅用于兼容现有评论，未来将被移除。

新的包裹机制更加灵活，可以更精确地包裹内容，并支持混合包裹行内节点和块节点。

**默认值：** `true`

```js
Comments.configure({
  // enable new flexible block wrapping
  useLegacyWrapping: false,
})
```
