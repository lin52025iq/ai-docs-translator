使用本指南将评论直接集成到编辑器中。要查看所有 Comments 编辑器命令的完整列表，请参阅[编辑器命令](/comments/integrate/editor-commands)页面。

若要自定义锚点消失或线程状态发生变化时的行为，请配置 [`onThreadAnchorRemoved`](/comments/core-concepts/configure#onthreadanchorremoved) 和 [`onThreadStateChanged`](/comments/core-concepts/configure#onthreadstatechanged)。

## 了解线程

Tiptap 的 Comments 功能会将讨论整理成线程，通过区分线程和单条评论，实现清晰且与上下文相关的协作。

线程用于容纳与文档特定部分相关的讨论，而评论则代表线程中的单条贡献。

## 创建新线程

假设你有一个用于创建新线程的按钮。你可以使用 `setThread` 命令，在当前选区创建新线程。

```js
const createThread = () => {
  editor
    .chain()
    .setThread({
      content: 'This is a new thread', // the content of the threads first inital comment
    })
    .run()
}
```

这会在当前选区创建一个新线程，并添加一条包含给定内容的评论。默认情况下，评论和线程都不会关联用户或任何其他元数据。假设你想将作者同时添加到线程**和**评论中，可以将 `data` 和 `commentData` 属性传给 `setThread` 命令。

```js
const createThread = () => {
  const user = {
    id: '123', // the user id of the author
    name: 'John Doe', // the name of the author
    avatarUrl: 'https://example.com/avatar.jpg', // the avatar of the author
  }

  editor
    .chain()
    .setThread({
      content: 'This is a new thread', // the content of the threads first inital comment
      data: {
        user,
      },
      commentData: {
        user,
      },
    })
    .run()
}
```

现在，线程和评论都会关联一个用户。

## 接收并监听线程和评论

使用 `@tiptap-pro/extension-comments` 中的 `subscribeToThreads`，使线程列表保持最新。传入 `editor`，即可包含每个线程在文档中的当前范围。

回调会立即收到初始列表。传入编辑器后，线程数据或范围发生变化时，后续更新会合并到一个微任务中处理。本地编辑、协同编辑以及撤销或重做后，范围都会更新。仅更改选区不会触发回调。

```js
import { subscribeToThreads } from '@tiptap-pro/extension-comments'

const unsubscribe = subscribeToThreads({
  editor,
  provider: yourTiptapCollabProvider,
  callback: (threads) => {
    console.log(threads.map((thread) => ({ id: thread.id, ranges: thread.ranges })))
  },
  getThreadsOptions: {
    types: ['archived', 'unarchived'],
  },
})
```

默认情况下，只会返回未归档的线程。使用 `getThreadsOptions.types` 可包含已归档的线程，也就是软删除的线程。

传入 `editor` 后，订阅默认使用编辑器的协作字段。可以通过 `getThreadsOptions.field` 指定其他字段。字段筛选也会包含未分配字段的旧版线程。

不再需要更新时，请调用 `unsubscribe()`。提供的编辑器销毁时，订阅也会自动清理。

不传入 `editor` 时，`subscribeToThreads` 会返回不含 `ranges` 的提供方线程记录，并且只监听提供方的变化。

## 读取当前线程范围

使用 `@tiptap-pro/extension-comments` 中的 `getThreads`，读取带有编辑器中当前锚点的线程记录。编辑器必须安装 `Comments` 或 `CommentsKit`。

```js
import { getThreads } from '@tiptap-pro/extension-comments'

const threads = getThreads({
  editor,
  provider: yourTiptapCollabProvider,
})
```

每个结果都会保留提供方的线程数据，并添加一个只读的 `ranges` 数组。该包导出了 `ThreadWithPositions<Data, CommentData>` 和 `ThreadRange` 类型。

每个范围包含以下字段：

| 字段   | 说明                                              |
| ------ | ------------------------------------------------- |
| `from` | 当前 ProseMirror 文档中的起始位置。               |
| `to`   | 当前 ProseMirror 文档中的结束位置（不包含该位置）。 |
| `type` | 标记范围为 `'inline'`，块级线程包装节点为 `'block'`。 |

块级范围包含包装节点。一个线程可以有多个独立锚点，因此 `ranges` 可能包含多个条目，并按文档位置排序。在所提供的编辑器中没有锚点的线程，其 `ranges` 为 `[]`。

这些位置描述的是当前文档中的位置，而不是永久锚点。编辑后请重新读取，或者传入 `editor` 使用 `subscribeToThreads` 接收更新后的范围。

`getThreads` 接受与订阅相同的 `getThreadsOptions` 筛选条件，并默认使用编辑器的协作字段。它会保留提供方中的顺序，而不会按文档位置对线程排序。

若要按文档顺序显示线程，请根据第一个范围进行排序。以下示例会将没有锚点的线程排在最后，并使用线程 ID 打破并列：

```js
const firstPosition = (thread) => thread.ranges[0]?.from ?? Infinity

const orderedThreads = [...threads].sort(
  (left, right) => firstPosition(left) - firstPosition(right) || left.id.localeCompare(right.id),
)
```

## 手动接收并渲染线程

若要手动获取当前文档中的线程列表，只需调用 `provider.getThreads()`。它会返回与提供方连接的文档中的线程数组。

这是一个静态数组，不会自行更新。若要让线程列表保持最新，可以通过 `provider.watchThreads` 和 `provider.unwatchThreads` 函数监听变化。

```js
// let's save threads in a variable
let threads = []

// this function is called whenever the threads change
const getThreads = () => {
  threads = provider.getThreads()
}

// initial call to get the threads
getThreads()

// watch for changes
provider.watchThreads(getThreads)
```

若要停止监听线程，可以调用 `provider.unwatchThreads(getThreads)`。

```js
provider.unwatchThreads(getThreads)
```

监听器回调还会接收 Yjs 事件和事务。使用 `transaction.local` 区分本地和远程更改；取消订阅时，将同一个回调传给 `unwatchThreads`：

```js
const handleThreadChanges = (events, transaction) => {
  console.log('Thread changes', events, transaction.local ? 'local' : 'remote')
}

provider.watchThreads(handleThreadChanges)

// Unsubscribe when the watcher is no longer needed.
provider.unwatchThreads(handleThreadChanges)
```

## 在 React 状态中维护线程范围

在 React Hook 中使用感知编辑器的订阅，以同时接收线程数据和范围更新：

不传入 `editor` 时，该 Hook 也能正常工作。在这种情况下，它会接收不含 `ranges` 的提供方线程记录。

```jsx
import { subscribeToThreads } from '@tiptap-pro/extension-comments'
import { useEffect, useState } from 'react'

const useThreads = (provider, editor) => {
  const [threads, setThreads] = useState([])

  useEffect(() => {
    if (!provider) {
      return
    }

    return subscribeToThreads({
      editor,
      provider,
      callback: setThreads,
    })
  }, [provider, editor])

  return threads
}
```

使用返回的线程来渲染 UI。当依赖项发生变化或组件卸载时，React 会调用取消订阅函数。

## 更新线程

若要更新线程，可以使用 `updateThread` 命令。此命令会更新指定 ID 的线程，并更新线程内容。

```js
editor.commands.updateThread({
  id: '123',
  {
    data: {
      seen: true,
    }
  }
})
```

这会更新 ID 为 `123` 的线程，并将 `seen` 属性设为 `true`。

## 删除线程

若要删除线程，可以使用 `removeThread` 命令。此命令会删除指定 ID 的线程。

<Callout title="如何删除线程" variant="default">
  默认情况下，移除的线程不会从 yjs 文档中删除。若要将其从文档中删除，可以将
  `deleteThread` 选项传给 `removeThread` 命令。
</Callout>

```js
editor.commands.removeThread({
  id: '123',
  deleteThread: true,
})
```

## 创建、更新和删除评论

可以在线程中添加、编辑和删除评论，但不能将评论标记为已解决，因为评论被视为线程讨论的一部分。

若要在线程中创建评论，可以使用 `createComment` 命令。此命令会在指定 ID 的线程中创建一条新评论。

```js
editor.commands.createComment({
  threadId: '123',
  content: 'This is a new comment', // this could also be Tiptap JSON or any other type of content
  data: {
    user, // pass through any meta data you want - in this case the user
  },
})
```

这会在 ID 为 `123` 的线程中创建一条新评论，并将内容设为 `This is a new comment`。你也可以为评论传入任何所需的元数据。

若要更新评论，可以使用 `updateComment` 命令。此命令会更新指定 ID 的评论及其内容。

```js
editor.commands.updateComment({
  threadId: '123', // the thread ID
  id: '456', // the comment ID
  content: 'Now this is the new content', // the new content of the comment
  data: {
    edited: true, // set the edited property to true
  },
})
```

这会更新 ID 为 `123` 的线程中 ID 为 `456` 的评论，并将内容设为 `Now this is the new content`。你也可以为评论传入任何所需的元数据。

最后，你可以使用 `deleteComment` 命令删除评论。此命令会删除指定 ID 的评论。

```js
editor.commands.deleteComment({
  threadId: '123',
  id: '456',
})
```

## 解决和取消解决线程

若要解决线程，可以使用 `resolveThread` 命令。此命令会解决指定 ID 的线程。

```js
editor.commands.resolveThread({
  id: '123',
})
```

这会解决 ID 为 `123` 的线程。若要取消解决线程，可以使用 `unresolveThread` 命令。此命令会取消解决指定 ID 的线程。

若要解决线程并记录解决线程的用户，可以在该线程的数据中加入解决线程的用户信息。取消解决线程时，请务必清除这些数据。

```js
editor.commands.unresolveThread({
  id: '123',
})
```

## 查找文档中的所有线程

若要查找编辑器文档中的所有线程，可以使用 `findThreadsInDocument` 实用函数。此函数会返回所有线程节点和标记的数组，其中包括它们在文档中的位置。

```js
const threads = findThreadsInDocument(editor, {
  blockTypeName: 'blockThread',
  markTypeName: 'inlineThread',
})
```

它会返回一个线程对象数组，每个对象都包含线程标识符、节点、位置，以及可选的关联标记。

## 选中线程

若要选中线程，可以使用 `selectThread` 命令。此命令会选中指定 ID 的线程。

```js
editor.commands.selectThread({
  id: '123',
})
```

这会将光标移动到 ID 为 `123` 的线程。

若要取消选中线程，可以使用 `unselectThread` 命令。此命令会取消选中指定 ID 的线程。

```js
editor.commands.unselectThread({
  id: '123',
})
```

也可以不指定 ID 来选中或取消选中线程。在这种情况下，编辑器会选中或取消选中当前选区中的线程。
