跟踪更改扩展提供的所有编辑器命令。

## enableTrackedChanges()

启用跟踪更改模式。之后的所有编辑都会成为建议。

```js
editor.commands.enableTrackedChanges()
```

## disableTrackedChanges()

禁用跟踪更改模式。编辑将直接应用到文档中。

```js
editor.commands.disableTrackedChanges()
```

## toggleTrackedChanges()

切换跟踪更改模式的启用或禁用状态。

```js
editor.commands.toggleTrackedChanges()
```

## setTrackedChangesUser()

更改新建议所使用的当前用户。

| 参数            | 类型                              | 说明                   |
| --------------- | --------------------------------- | ---------------------- |
| `userId`        | `string`                          | 新用户 ID              |
| `userMetadata`  | `Record<string, unknown> \| null` | 关于用户的可选任意元数据 |

```js
editor.commands.setTrackedChangesUser({
  userId: 'user-789',
  userMetadata: { name: 'Alice Johnson' },
})
```

## acceptSuggestion()

接受一条建议并应用其提出的更改。对于插入操作，会移除建议标记并保留文本。对于删除操作，会移除带标记的文本。对于替换操作，会移除旧文本并保留新文本。

| 参数 | 类型     | 说明                                       |
| ---- | -------- | ------------------------------------------ |
| `id` | `string` | 可选的建议 ID。若省略，则使用当前选区中的建议。 |

```js
// Accept suggestion at selection
editor.commands.acceptSuggestion()

// Accept specific suggestion
editor.commands.acceptSuggestion({ id: 'suggestion-123' })
```

## rejectSuggestion()

拒绝一条建议并撤销其提出的更改。对于插入操作，会移除带标记的文本。对于删除操作，会移除建议标记并保留文本。对于替换操作，会移除新文本并保留旧文本。

| 参数 | 类型     | 说明                                       |
| ---- | -------- | ------------------------------------------ |
| `id` | `string` | 可选的建议 ID。若省略，则使用当前选区中的建议。 |

```js
// Reject suggestion at selection
editor.commands.rejectSuggestion()

// Reject specific suggestion
editor.commands.rejectSuggestion({ id: 'suggestion-123' })
```

## acceptAllSuggestions()

接受文档中的所有建议。

```js
editor.commands.acceptAllSuggestions()
```

## rejectAllSuggestions()

拒绝文档中的所有建议。

```js
editor.commands.rejectAllSuggestions()
```

## acceptSuggestionsInRange()

接受指定文档位置范围内的所有建议。

| 参数   | 类型     | 说明         |
| ------ | -------- | ------------ |
| `from` | `number` | 范围的起始位置 |
| `to`   | `number` | 范围的结束位置 |

```js
editor.commands.acceptSuggestionsInRange({ from: 0, to: 100 })
```

## rejectSuggestionsInRange()

拒绝指定文档位置范围内的所有建议。

| 参数   | 类型     | 说明         |
| ------ | -------- | ------------ |
| `from` | `number` | 范围的起始位置 |
| `to`   | `number` | 范围的结束位置 |

```js
editor.commands.rejectSuggestionsInRange({ from: 0, to: 100 })
```

## acceptSuggestionsByUser()

接受特定用户创建的所有建议。

| 参数     | 类型     | 说明               |
| -------- | -------- | ------------------ |
| `userId` | `string` | 要接受其建议的用户 ID |

```js
editor.commands.acceptSuggestionsByUser({ userId: 'user-123' })
```

## rejectSuggestionsByUser()

拒绝特定用户创建的所有建议。

| 参数     | 类型     | 说明               |
| -------- | -------- | ------------------ |
| `userId` | `string` | 要拒绝其建议的用户 ID |

```js
editor.commands.rejectSuggestionsByUser({ userId: 'user-123' })
```

## addTrackedInsertion()

将内容作为跟踪建议插入，而不为整个编辑器启用跟踪更改模式。当你需要以编程方式创建建议，并希望结果与正常的跟踪输入事务一致时，此命令很有用。`content` 参数接受任何 Tiptap `Content` 值，包括文本、HTML 或 JSON 节点内容（例如图像节点）。当 `skipTrailingNode` 为 `true` 时，发出的事务也会设置 `skipTrailingNode: true`；此选项与 [TrailingNode](/editor/extensions/functionality/trailing-node) 扩展配合使用时很有用。

| 参数               | 类型      | 说明                                                                      |
| ------------------ | --------- | ------------------------------------------------------------------------- |
| `from`             | `number`  | 添加跟踪插入内容的文档位置                                                |
| `content`          | `Content` | 作为建议插入的内容                                                        |
| `reason`           | `string`  | 可选说明，会包含在 `trackedChanges:suggestionCreated` 事件载荷中           |
| `skipTrailingNode` | `boolean` | 可选标志，用于在发出的跟踪事务中设置 `skipTrailingNode: true`              |

```js
editor.commands.addTrackedInsertion({
  from: 7,
  content: 'big ',
  reason: 'Applied AI rewrite',
  skipTrailingNode: true,
})
```

```js
editor.commands.addTrackedInsertion({
  from: 7,
  content: {
    type: 'image',
    attrs: {
      src: '/example.png',
      alt: 'Example image',
    },
  },
  reason: 'Inserted approved image asset',
})
```

## addTrackedDeletion()

将现有文档范围转换为跟踪删除建议。这与启用跟踪更改模式时用户删除内容的效果相同。

| 参数     | 类型     | 说明                                           |
| -------- | -------- | ---------------------------------------------- |
| `from`   | `number` | 要标记为已删除范围的起始位置                   |
| `to`     | `number` | 要标记为已删除范围的结束位置                   |
| `reason` | `string` | 可选说明，会包含在 `trackedChanges:suggestionCreated` 事件载荷中 |

```js
editor.commands.addTrackedDeletion({
  from: 7,
  to: 12,
  reason: 'Removed outdated wording',
})
```

## addTrackedReplacement()

将现有范围替换为跟踪替换建议。被替换的内容会成为建议中的删除部分，新内容则成为插入部分。`content` 参数接受任何 Tiptap `Content` 值，因此你可以传入 JSON 内容，以不同节点替换文本。当 `skipTrailingNode` 为 `true` 时，发出的事务也会设置 `skipTrailingNode: true`；此选项与 [TrailingNode](/editor/extensions/functionality/trailing-node) 扩展配合使用时很有用。

| 参数               | 类型      | 说明                                                                      |
| ------------------ | --------- | ------------------------------------------------------------------------- |
| `from`             | `number`  | 要替换范围的起始位置                                                      |
| `to`               | `number`  | 要替换范围的结束位置                                                      |
| `content`          | `Content` | 作为跟踪建议插入的替换内容                                                |
| `reason`           | `string`  | 可选说明，会包含在 `trackedChanges:suggestionCreated` 事件载荷中           |
| `skipTrailingNode` | `boolean` | 可选标志，用于在发出的跟踪事务中设置 `skipTrailingNode: true`              |

```js
editor.commands.addTrackedReplacement({
  from: 7,
  to: 12,
  content: 'earth',
  reason: 'Replaced with approved terminology',
  skipTrailingNode: true,
})
```

```js
editor.commands.addTrackedReplacement({
  from: 7,
  to: 8,
  content: {
    type: 'image',
    attrs: {
      src: '/updated-diagram.png',
      alt: 'Updated diagram',
    },
  },
  reason: 'Replaced placeholder with final diagram',
})
```

## addTrackedMark()

将标记应用到现有范围，并将其作为跟踪的 `markChange` 建议。如果你想以编程方式建议格式更改或其他标记级别的更改，而不全局启用跟踪更改模式，请使用此命令。

| 参数        | 类型                              | 说明                                           |
| ----------- | --------------------------------- | ---------------------------------------------- |
| `from`      | `number`                          | 要添加标记的范围起始位置                       |
| `to`        | `number`                          | 要添加标记的范围结束位置                       |
| `markName`  | `string`                          | 要添加的 schema 标记名称                       |
| `markAttrs` | `Record<string, unknown> \| null` | 要跟踪标记的可选属性                           |
| `reason`    | `string`                          | 可选说明，会包含在 `trackedChanges:suggestionCreated` 事件载荷中 |

```js
editor.commands.addTrackedMark({
  from: 7,
  to: 12,
  markName: 'bold',
  reason: 'Emphasized the approved term',
})
```

```js
editor.commands.addTrackedMark({
  from: 7,
  to: 12,
  markName: 'link',
  markAttrs: {
    href: 'https://tiptap.dev',
    target: '_blank',
  },
  reason: 'Linked to the canonical reference',
})
```

## removeTrackedMark()

从现有范围移除标记，并将其作为跟踪的 `markChange` 建议。这与启用跟踪更改模式时用户移除格式的效果相同。

| 参数        | 类型                              | 说明                                           |
| ----------- | --------------------------------- | ---------------------------------------------- |
| `from`      | `number`                          | 要移除标记范围的起始位置                       |
| `to`        | `number`                          | 要移除标记范围的结束位置                       |
| `markName`  | `string`                          | 要移除的 schema 标记名称                       |
| `markAttrs` | `Record<string, unknown> \| null` | 用于识别标记变体的可选属性                     |
| `reason`    | `string`                          | 可选说明，会包含在 `trackedChanges:suggestionCreated` 事件载荷中 |

```js
editor.commands.removeTrackedMark({
  from: 7,
  to: 12,
  markName: 'bold',
  reason: 'Removed emphasis from the label',
})
```

## toggleTrackedMark()

通过跟踪标记建议切换现有范围上的标记。对于混合选区，带标记的片段会成为跟踪移除项，未带标记的片段则会成为跟踪添加项；这些操作在同一命令中完成。

| 参数        | 类型                              | 说明                                           |
| ----------- | --------------------------------- | ---------------------------------------------- |
| `from`      | `number`                          | 要切换标记的范围起始位置                       |
| `to`        | `number`                          | 要切换标记的范围结束位置                       |
| `markName`  | `string`                          | 要切换的 schema 标记名称                       |
| `markAttrs` | `Record<string, unknown> \| null` | 用于识别或创建标记变体的可选属性               |
| `reason`    | `string`                          | 可选说明，会包含在 `trackedChanges:suggestionCreated` 事件载荷中 |

```js
editor.commands.toggleTrackedMark({
  from: 7,
  to: 12,
  markName: 'bold',
  reason: 'Toggled emphasis based on editorial review',
})
```
