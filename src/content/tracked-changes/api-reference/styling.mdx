建议标记和节点级建议会渲染可通过 CSS 定位的数据属性。

## CSS 选择器

```css
/* All suggestions */
[data-suggestion] {
  /* Base styles for all suggestions */
}

/* Insertions */
[data-suggestion-type='add'] {
  background-color: rgba(0, 255, 0, 0.2);
  text-decoration: underline;
}

/* Deletions */
[data-suggestion-type='delete'] {
  background-color: rgba(255, 0, 0, 0.2);
  text-decoration: line-through;
}

/* Replacement deletions (old text being replaced) */
[data-suggestion-type='replaceDeletion'] {
  background-color: rgba(255, 0, 0, 0.2);
  text-decoration: line-through;
}

/* Replacement insertions (new text replacing old) */
[data-suggestion-type='replaceInsertion'] {
  background-color: rgba(0, 255, 0, 0.2);
  text-decoration: underline;
}

/* Mark changes (formatting added or removed) */
[data-suggestion-type='markChange'] {
  background-color: rgba(255, 200, 0, 0.2);
}

/* Node attribute changes */
[data-suggestion-type='attributeChange'] {
  outline: 2px solid rgb(59, 130, 246);
  outline-offset: 2px;
}

/* Suggested block splits (the block created by a tracked Enter) */
[data-suggestion-type='blockSplit'] {
  box-shadow: inset 2px 0 0 rgb(59, 130, 246);
}

/* Style suggestions by user */
[data-suggestion-user='user-123'] {
  border-bottom: 2px solid blue;
}
```

## 可用的数据属性

| 属性                                 | 说明                                                                                                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data-suggestion`                   | 始终出现在建议标记元素和节点级建议元素上                                                                                 |
| `data-suggestion-id`                | 唯一的建议 ID                                                                                                                                      |
| `data-suggestion-type`              | 内部类型：`'add'`、`'delete'`、`'replaceDeletion'`、`'replaceInsertion'`、`'markChange'`、`'attributeChange'`、`'sink'`、`'lift'` 或 `'blockSplit'` |
| `data-suggestion-user`              | 创建该建议的用户 ID                                                                                                                 |
| `data-suggestion-created`           | 创建建议时的 ISO 时间戳                                                                                                                 |
| `data-suggestion-user-metadata`     | JSON 序列化的用户元数据对象（仅在设置了 `userMetadata` 时存在）                                                                                |
| `data-suggestion-attribute-changes` | JSON 序列化的属性更改（仅对 `attributeChange` 建议存在）                                                                            |

`data-suggestion-type` 保存的是内部的 [SuggestionNodeType](/tracked-changes/api-reference/types#suggestionnodetype)，而非公开类型。这里的[块拆分](/tracked-changes/usage/advanced-usage#block-splits)值为 `blockSplit`，尽管查询 API 将其报告为 `split`。

节点类型提案还会提供 `data-suggestion-node-type-change`，其中包含 JSON 序列化的原始类型、提议类型和原始属性。当删除或拆分与该提案位于同一块时，此属性还会包含格式提案的标识信息。可通过 `[data-suggestion-node-type-change]` 定位这些提案，使其样式独立于块的主要建议类型。

## 块拆分标记

建议的块拆分还会在拆分**之前**的块末尾渲染一个标记，用于显示换行符的添加位置。默认标记是一个类名为 `tiptap-tracked-change-split-marker` 的 `<span>`：

```css
.tiptap-tracked-change-split-marker {
  color: rgb(59, 130, 246);
  opacity: 0.7;
  margin-left: 0.15em;
  user-select: none;
}
```

每个标记还带有 `data-tracked-change-split="true"`，因此也可以定位自定义标记：

```css
[data-tracked-change-split] {
  color: rgb(59, 130, 246);
}
```

该标记是一个 widget，而非文档内容。扩展始终会将其设为 `contenteditable="false"`，并禁用其选择和指针事件，因此无法在其中输入、选中或点击。使用 [`blockSplitMarker`](/tracked-changes/getting-started/install#blocksplitmarker) 更改字符或元素，也可以将其设为 `null`，不渲染任何内容。

## 已知限制

此扩展仍在积极开发中，未来几个月会有较大变化。目前已知以下限制，后续版本将予以解决：

- 仅支持内联建议的嵌套。不支持跨越整个块的嵌套建议。
- 将[节点类型更改](/tracked-changes/usage/advanced-usage#node-type-changes)作为 `attributeChange` 建议进行跟踪，需要启用 `nodeTypeChangeTypes` 设置；此设置仅适用于本地编辑器。使用 Tiptap Collaboration（Y.js 文档）时，请将此设置保留为 `[]`，以便将类型转换作为替换进行跟踪。
- 没有显式的建议模式可在跟踪版本旁边渲染单独的“干净”文档。
