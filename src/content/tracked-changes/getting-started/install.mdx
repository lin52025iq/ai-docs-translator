## 安装

修订跟踪是付费附加组件，不包含在任何套餐中。你可以在[免费试用](https://cloud.tiptap.dev/v2?trial=true)期间进行测试，也可以在[控制台](https://cloud.tiptap.dev/v2/billing)中购买。

然后按照[私有注册表指南](/guides/pro-extensions)配置包管理器。

接着安装该包：

```bash
npm install @tiptap-pro/extension-tracked-changes
```

## 基本设置

```js
import { Editor } from '@tiptap/core'
import { TrackedChanges } from '@tiptap-pro/extension-tracked-changes'

const editor = new Editor({
  extensions: [
    TrackedChanges.configure({
      enabled: true,
      userId: 'user-123',
      userMetadata: { name: 'John Doe' },
    }),
  ],
})
```

## 设置项

### enabled

启用或禁用修订模式。启用后，所有编辑都会变成建议，而不是直接修改内容。

默认值：`false`

```js
TrackedChanges.configure({
  enabled: true,
})
```

### userId

提交建议的当前用户 ID。该值应来自你的身份验证系统。

默认值：`'anonymous'`

```js
TrackedChanges.configure({
  userId: 'user-123',
})
```

### userMetadata

当前用户的任意元数据，以可序列化为 JSON 的对象形式存储在每条建议中。适合在建议中存储显示名称、头像或其他自定义数据，无需单独维护用户存储。

默认值：`null`

```js
TrackedChanges.configure({
  userId: 'user-123',
  userMetadata: {
    name: 'John Doe',
    avatar: 'https://example.com/avatar.jpg',
    role: 'editor',
  },
})
```

### nodeTypeChangeTypes

可创建节点类型建议的文本块 schema 名称。请同时包含源类型和目标类型。将段落转换为标题时，会创建一条 `attributeChange` 建议，同时保留一份文本。对于配置类型对之外的转换，则继续采用现有的替换行为。

默认值：`[]`

```js
TrackedChanges.configure({
  nodeTypeChangeTypes: ['paragraph', 'heading'],
})
```

`nodeTypeChangeTypes` 是供本地编辑器使用的可选设置。使用 Tiptap Collaboration（Y.js 文档）时，请保留默认值 `[]`，以便继续将类型转换跟踪为替换操作。在使用 Tiptap Collaboration（Y.js 文档）时配置非空列表，会在编辑器初始化期间抛出错误。支持的转换方式和审阅行为请参阅[节点类型变更](/tracked-changes/usage/advanced-usage#node-type-changes)。

### onSuggestionCreate

创建新建议时触发的回调。接收包含 id、type、userId、createdAt、from、to 和 text 的建议对象。

默认值：`undefined`

```js
TrackedChanges.configure({
  onSuggestionCreate: (suggestion) => {
    console.log('New suggestion created:', suggestion)
    // Update your UI, notify other users, etc.
  },
})
```

### onSuggestionAccept

接受建议时触发的回调。接收建议 ID。

默认值：`undefined`

```js
TrackedChanges.configure({
  onSuggestionAccept: (id) => {
    console.log('Suggestion accepted:', id)
  },
})
```

### onSuggestionReject

拒绝建议时触发的回调。接收建议 ID。

默认值：`undefined`

```js
TrackedChanges.configure({
  onSuggestionReject: (id) => {
    console.log('Suggestion rejected:', id)
  },
})
```

### blockSplitMarker

在建议进行[块拆分](/tracked-changes/usage/advanced-usage#block-splits)的位置显示的标记。标记会渲染在拆分前的块末尾。

默认值：`'¶'`

传入字符串即可更改标记字符：

```js
TrackedChanges.configure({
  blockSplitMarker: '↵',
})
```

传入元素或返回元素的函数，即可完全控制标记的标记语言：

```js
TrackedChanges.configure({
  // A function is called once per marker and must return a new element each time
  blockSplitMarker: () => {
    const marker = document.createElement('span')

    marker.className = 'my-split-marker'
    marker.textContent = '¶'

    return marker
  },
})
```

传入 `null` 可完全隐藏标记：

```js
TrackedChanges.configure({
  blockSplitMarker: null,
})
```

也可以传入单个 `HTMLElement`，该元素会为每个标记克隆一份。无论返回什么，扩展都会为其设置 `data-tracked-change-split="true"` 和 `contenteditable="false"`，并禁用选择和指针事件，因此标记不会成为可编辑内容。默认 CSS 请参阅[样式](/tracked-changes/api-reference/styling#block-split-marker)。
