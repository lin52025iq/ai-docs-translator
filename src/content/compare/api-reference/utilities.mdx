`@tiptap-pro/compare` 软件包导出的类和函数列表。

## `Compare`

Compare Tiptap 编辑器扩展。将其添加到用于渲染差异的编辑器中。此扩展不接受任何配置选项。

## `compareDocuments`

比较两个 Tiptap JSON 文档。

### 参数 (`CompareDocumentsOptions`)

- `schema` (`Schema`)：用于解析两个文档的 ProseMirror schema。
- `docA` (`JSONContent`)：原始文档。
- `docB` (`JSONContent`)：修改后的文档。
- `diffOptions?` (`DiffOptions`)：控制比较方式的选项。请参阅 [DiffOptions](/compare/api-reference/types#diffoptions)。

### 返回值 (`Changeset`)

返回一个包含两个文档及其变更的变更集。请参阅 [Changeset](/compare/api-reference/utilities#changeset)。

## `compareFragments`

比较两个 Tiptap JSON 片段。

### 参数 (`CompareFragmentsOptions`)

- `schema` (`Schema`)：用于解析两个片段的 ProseMirror schema。
- `fragmentA` (`JSONContent[] | null`)：原始片段。
- `fragmentB` (`JSONContent[] | null`)：修改后的片段。
- `diffOptions?` (`DiffOptions`)：控制比较方式的选项。

### 返回值 (`Changeset`)

返回一个包含两个片段及其变更的变更集。请参阅 [Changeset](/compare/api-reference/utilities#changeset)。

## `compareSteps`

将 `StepSequence` 转换为互不重叠的变更。

### 参数 (`CompareStepsOptions`)

- `stepSequence` (`StepSequence`)：要比较的文档状态转换序列。
- `compareMetadata?` (`(a: ChangeMetadata, b: ChangeMetadata) => boolean`)：决定是否可以将相邻步骤分组。
- `diffOptions?` (`DiffOptions`)：控制比较方式的选项。

### 返回值 (`Changeset`)

返回一个包含初始文档、最终文档及其变更的变更集。变更中包含生成这些变更的步骤所关联的元数据。请参阅 [Changeset](/compare/api-reference/utilities#changeset)。

## `compareVersions`

比较两个完整的 Yjs v2 更新，并在可用时恢复协作元数据。

### 参数 (`CompareVersionsOptions`)

- `versionA` (`Uint8Array`)：较早的 Yjs v2 更新。
- `versionB` (`Uint8Array`)：较新的 Yjs v2 更新。
- `schema` (`Schema`)：用于还原两个版本的 schema。
- `diffOptions?` (`DiffOptions`)：控制比较方式的选项。
- `compareMetadata?` (`(a: ChangeMetadata, b: ChangeMetadata) => boolean`)：决定是否可以将相邻变更分组。默认情况下，具有相同 `userId` 的变更会被分组。
- `field?` (`string`)：Yjs 文档字段。默认值：`'default'`。
- `permanentUserDataMapField?` (`string`)：共享用户数据映射字段。默认值：`'__tiptapcollab__users'`。
- `enableDebugging?` (`boolean`)：启用提取日志记录。默认值：`false`。

### 返回值 (`Changeset`)

返回一个包含两个版本及其变更的变更集。变更中包含变更历史的元数据，例如在可用时包含 `userId`。请参阅 [Changeset](/compare/api-reference/utilities#changeset)。

## `Changeset`

表示比较两个文档、片段、步骤或版本的结果。

### 属性

- `fragmentA` (`JSONFragment`)：原始片段。
- `fragmentB` (`JSONFragment`)：修改后的片段。
- `changes` (`Change[]`)：两个片段之间的变更。
- `docA` (`JSONContent`)：以 Tiptap JSON 文档表示的原始文档。
- `docB` (`JSONContent`)：以 Tiptap JSON 文档表示的修改后文档。

### `changeset.reverse`

创建一个方向相反的变更集，其中文档 A 变为文档 B，反之亦然。

#### 参数

此方法不接受参数。

#### 返回值 (`Changeset`)

- `Changeset`：原始文档和修改后文档已互换的变更集。

### `changeset.toJSON`

序列化变更集。

#### 参数

此方法不接受参数。

#### 返回值 (`ChangesetJSON`)

- `fragmentA` (`JSONFragment`)：原始片段。
- `fragmentB` (`JSONFragment`)：修改后的片段。
- `changes` (`Change[]`)：两个片段之间的变更。

### `Changeset.fromJSON`

从序列化的 JSON 还原变更集。

#### 参数

- `json` (`ChangesetJSON`)：序列化后的变更集。

#### 返回值 (`Changeset`)

- `Changeset`：还原后的变更集。

## `findDiffSuggestions`

返回编辑器中当前显示的差异建议。

### 参数

- `editor` (`Editor`)：已配置 `Compare` 的编辑器。

### 返回值 (`DiffSuggestion[]`)

每个 `DiffSuggestion` 包含：

- `id` (`string`)：建议 ID。
- `range` (`Range`)：编辑器中受影响的范围。
- `content` (`Slice`)：替换内容。
- `metadata?` (`Record<string, any>`)：可选的自定义元数据。
- `displayOptions?` (`DisplayOptions`)：用于渲染建议的选项。
- `isInlineGroup?` (`boolean`)：是否对行内变更进行了分组。
- `mappableRange?` (`MappableRange`)：可通过事务映射的范围。
- `nestedChanges?` (`DiffSuggestionNestedChange[]`)：此建议中嵌套的信息性变更。接受和拒绝操作针对父级建议。

## `getSuggestionNodeViewContext`

确定 [Tiptap Node View](/editor/extensions/custom-extensions/node-views) 是否位于差异建议中，并返回该建议的上下文。

### 参数

- `decorations` (`Decoration[]`)：传递给自定义 Node View 的装饰。

### 返回值 (`SuggestionNodeViewContext`)

- `suggestion` (`DiffSuggestion | null`)：Node View 所在的建议；如果 Node View 不属于差异建议，则为 `null`。
- `isSelected` (`boolean`)：建议是否已选中。当光标位于建议内时，建议即为选中状态。
- `isReplacement` (`boolean`)：Node View 是否位于替换内容中。对于当前文档中的内容，此值为 `false`。

## `renderSlice`

将 [ProseMirror 片段](https://prosemirror.net/docs/ref/#model.Slice)渲染为文档片段，以便在差异中显示。

### 参数 (`RenderSliceToHtmlOptions`)

- `slice` ([`Slice`](https://prosemirror.net/docs/ref/#model.Slice))：要渲染的片段。
- `editor` (`Editor`)：用于渲染片段的编辑器。
- `suggestionNodeViewContext` (`SuggestionNodeViewContext`)：渲染期间提供给自定义 Node View 的上下文数据。

### 返回值 ([`DocumentFragment`](https://developer.mozilla.org/en-US/docs/Web/API/DocumentFragment))

返回一个包含已渲染片段的[文档片段](https://developer.mozilla.org/en-US/docs/Web/API/DocumentFragment)。

## `generateSuggestionId`

为差异建议创建唯一 ID。

### 参数

此实用工具不接受参数。

### 返回值 (`string`)

- `string`：唯一的建议 ID。

## `getVersions`

从协作提供程序请求两个快照。

### 参数

- `provider` (`TiptapCollabProvider`)：具有版本列表和无状态消息方法的提供程序。
- `fromVersion` (`number`)：第一个版本 ID。
- `toVersion?` (`number`)：第二个版本 ID。默认为最新版本。

### 返回值 (`Promise<{ snapshot: Uint8Array; prevSnapshot: Uint8Array }>`)

Promise 解析后会返回：

- `snapshot` (`Uint8Array`)：较新版本的更新。
- `prevSnapshot` (`Uint8Array`)：较早版本的更新。

## `getDocumentFromVersion`

根据完整的 Yjs v2 更新还原 Tiptap JSON 文档。

### 参数 (`GetDocumentFromVersionOptions`)

- `version` (`Uint8Array`)：完整的 Yjs v2 更新。
- `schema` (`Schema`)：用于还原文档的 schema。
- `field?` (`string`)：Yjs 文档字段。默认值：`'default'`。

### 返回值 (`JSONContent`)

返回的 JSON 文档包含：

- `type` (`string`)：Tiptap 节点类型；完整文档通常为 `'doc'`。
- `content?` (`JSONContent[]`)：文档的子节点。
- `attrs?` (`Record<string, any>`)：文档节点上的属性。
- `marks?` (`Mark[]`)：节点上的标记（如适用）。
- `text?` (`string`)：文本内容（如适用）。

## `TrackedChangesDocumentFactory`

创建一个 Tiptap JSON 文档，其中的 `Changeset` 以[跟踪更改](/tracked-changes/getting-started/overview)形式编码。可在服务器端或任何无法使用编辑器实例的场景中使用。

### `fromChangeset`

将变更集转换为包含跟踪更改的文档。

#### 参数 (`TrackedChangesDocumentFactoryOptions`)

- `changeset` (`Changeset`)：要编码的比较结果。
- `schema` (`Schema`)：包含跟踪更改扩展的 ProseMirror schema。

#### 返回值 (`TrackedChangesDocumentFactoryResult`)

- `doc` (`JSONContent`)：包含跟踪更改标记和节点属性的文档。
- `trackedChanges` (`TrackedChangeData[]`)：编码后的跟踪更改及其在 `doc` 中的范围。

## `serializeSchema`

将 ProseMirror schema 序列化为可安全用于 JSON 的数据。

### 参数

- `schema` (`Schema`)：要序列化的 schema。

### 返回值 (`SerializedSchema`)

Tiptap 编辑器 schema 编码后的 JSON 对象，可通过网络发送。

## `deserializeSchema`

根据序列化的 schema 数据创建 ProseMirror schema。

### 参数

- `jsonSchema` (`SerializedSchema`)：要反序列化的 JSON 安全格式 schema 数据。

### 返回值 (`Schema`)

- `Schema`：还原后的 ProseMirror schema。

## `StepSequence`

存储一系列文档状态以及每次状态转换的元数据。

### `StepSequence.fromInitialDocument`

创建一个空序列。

#### 参数

- `before` (`Node`)：初始文档。

#### 返回值 (`StepSequence`)

- `before` (`Node`)：初始文档。
- `after` (`Node`)：最新文档，初始时与 `before` 相同。
- `stepCount` (`number`)：已记录步骤的数量，初始值为 `0`。

### `StepSequence.fromJSON`

从 JSON 还原序列。

#### 参数 (`StepSequenceFromJSONOptions`)

- `json` (`StepSequenceJSON`)：序列化后的序列。
- `schema` (`Schema`)：用于还原其中文档的 schema。

#### 返回值 (`StepSequence`)

- `before` (`Node`)：初始文档。
- `after` (`Node`)：最新文档。
- `stepCount` (`number`)：已记录步骤的数量。

### `sequence.addStep`

追加一次文档状态转换。

#### 参数 (`AddStepOptions`)

- `doc` (`Node`)：步骤执行后的文档。
- `metadata` (`ChangeMetadata`)：此步骤的元数据。
- `changes?` (`Change[] | null`)：缓存的变更。`null` 表示没有缓存的变更，因此会计算差异。空数组表示步骤之间没有变更。
- `changedArea?` (`Change | null`)：可用时提供的缓存变更区域。

#### 返回值 (`void`)

此方法不返回值。

### `sequence.copy` 和 `sequence.reverse`

`copy` 会复制一个序列。`reverse` 会返回一个从最终文档回溯至初始文档的序列。

#### 参数

这些方法不接受参数。

#### 返回值 (`StepSequence`)

- `before` (`Node`)：返回序列的初始文档。
- `after` (`Node`)：返回序列的最终文档。
- `stepCount` (`number`)：已记录步骤的数量。

### `sequence.getSteps`

返回每次已记录的文档状态转换。

#### 参数

此方法不接受参数。

#### 返回值 (`Step[]`)

每个 `Step` 包含：

- `before` (`Node`)：转换前的文档。
- `after` (`Node`)：转换后的文档。
- `metadata` (`ChangeMetadata`)：此转换的元数据。
- `changes` (`Change[] | null`)：可用时提供的缓存变更。
- `changedArea` (`Change | null`)：可用时提供的缓存变更区域。

### `sequence.toJSON`

序列化序列。

#### 参数

此方法不接受参数。

#### 返回值 (`StepSequenceJSON`)

- `before` (`JSONContent`)：初始文档。
- `docs` (`JSONContent[]`)：每次转换后的文档。
- `metadata` (`ChangeMetadata[]`)：每次转换的元数据。
- `changes` (`Array<Change[] | null>`)：每次转换的缓存变更。
- `changedAreas` (`Array<Change | null>`)：每次转换的缓存变更区域。
