装饰是附加到文档中某个位置或范围的仅用于视图的标记。它们由扩展声明，不会修改或序列化文档。有关装饰的概念、示例以及适用场景，请阅读[装饰指南](/editor/core-concepts/decorations)。本页是 API 参考。

## `addDecorations`

每个扩展（包括节点和标记）都有的生命周期钩子。它会返回一个 `DecorationSpec`，用于描述扩展提供的装饰；如果没有，则返回 `null`。Tiptap 的内部装饰管理器会将所有扩展的声明汇总到一个 ProseMirror 插件中。

与其他扩展钩子一样，`addDecorations()` 绑定到 `this`（`{ name, options, storage, editor, type, parent }`）。

```ts
import { Decoration, Extension } from '@tiptap/core'

const MyExtension = Extension.create({
  name: 'myExtension',

  addDecorations() {
    return {
      create: ({ editor, state, view }) => [Decoration.Inline(1, 5, { class: 'highlight' })],
    }
  },
})
```

### `DecorationSpec`

`DecorationSpec` 是一个判别联合类型，由其 `update` 策略决定。每种策略都会在初始化和强制更新时使用 `create`。

| 属性 | 类型 | 说明 |
| --------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `update` | `'document' \| 'changedRanges' \| 'manual'` | 控制装饰的更新方式。默认值为 `'document'`。 |
| `create` | `(props: { editor; state; view }) => Decoration[]` | **必填。** 构建完整集合。用于初始化和 `updateDecorations()`。 |
| `shouldUpdate` | `(props: { editor; tr; oldState; newState }) => boolean` | `document` 和 `changedRanges` 策略可选。返回 `false` 时只映射而不重新构建。默认值为 `tr.docChanged`。 |
| `createInRange` | `(props: { editor; state; view; from; to }) => Decoration[]` | 仅 `changedRanges` 策略必填。返回锚定在提供的、与块对齐的范围内的装饰。 |

<Callout title="从 state 参数读取状态，而非 editor.state" variant="warning">
  在 `create()` 和 `createInRange()` 中，始终从 `state` 参数读取文档，而不是从
  `editor.state` 读取。在事务处理期间，编辑器的视图状态尚未更新，因此
  `editor.state` 指向事务处理前的文档。`state` 参数才是当前正在构建的正确状态。如果 Tiptap 检测到在
  `create()` 中读取了 `editor.state`，就会在开发环境中记录警告。
</Callout>

<Callout title="create 和 createInRange 不得抛出异常" variant="warning">
  `create()` 和 `createInRange()` 会在 ProseMirror 的状态更新周期中运行。如果它们抛出异常，
  编辑器可能会进入不一致状态。请将任何可能失败的逻辑（正则表达式编译、外部数据访问）放入 try/catch 中，并在失败时返回空数组。
</Callout>

### `DecorationUpdateStrategy`

```ts
type DecorationUpdateStrategy = 'document' | 'changedRanges' | 'manual'
```

- `document` 会在文档更改后使用 `create` 重新构建完整集合。这是默认策略，始终能确保正确性。
- `changedRanges` 会映射现有装饰，并仅对发生变化且与块对齐的范围调用 `createInRange`。仅当装饰局限于块内时才使用此策略。
- `manual` 会保留当前装饰，直到你调用 `updateDecorations()`。

你可以将 `shouldUpdate` 与 `document` 和 `changedRanges` 搭配使用。不能与 `manual` 搭配使用，因为手动装饰只会在你主动要求时更新。

<Callout title="createInRange 的约定" variant="warning">
  `createInRange` 必须**仅**返回起始位置位于 `[from, to)` 内的装饰。
  对于行内和节点装饰，使用 `from`；对于 widget 装饰，使用 `pos`。`to` 不包含在范围内：
  它是下一个块的起始位置，而该块会自行重新构建，因此锚定在 `to` 的装饰会被忽略。最后一个块是例外，因为它包含文档末尾。如果装饰依赖所提供范围之外的内容，请改用 `document` 策略。
</Callout>

有关策略选择和变更范围正确性约束，请参阅[性能](/editor/core-concepts/decorations#performance)。

## `Decoration`

从 `@tiptap/core` 导入 `Decoration`。它的静态方法会构建描述 Tiptap 应显示内容的装饰实例。在 `create` 和 `createInRange` 中返回这些实例。

这三种方法都会返回一个 `Decoration`（类型为 `InlineDecoration`、`NodeDecoration` 或 `WidgetDecoration` 之一）。

| 方法 | 返回值 | 说明 |
| ------------------- | ------------------- | ---------------------------------------------------------------------- |
| `Decoration.Node` | `NodeDecoration` | 为单个节点的 DOM 包装元素添加属性。 |
| `Decoration.Inline` | `InlineDecoration` | 将一段行内内容包裹在带样式的 span 中。 |
| `Decoration.Widget` | `WidgetDecoration` | 在单个位置插入一个 widget（DOM 节点）。必须提供 `key`。 |

### 装饰类

`Decoration` 是抽象基类。`InlineDecoration`、`NodeDecoration` 和 `WidgetDecoration` 都继承自它。每个实例都有一个 `kind`（`'inline' | 'node' | 'widget'`）、一个 `anchor`（起始位置），以及一个 `toPMDecoration(extensionName?)` 方法，可将其转换为 ProseMirror 装饰。

Tiptap 会为你将这些实例转换为 ProseMirror 装饰。

### `Decoration.Node`

```ts
Decoration.Node(
  pos: number,
  to: number,
  attrs?: DecorationAttrs,
  spec?: Record<string, any>,
)
```

**参数**

- `pos` – 节点的起始位置。
- `to` – 节点的结束位置。
- `attrs` – 可选。`DecorationAttrs`：`class`、`style`、`nodeName` 以及其他任意 HTML 属性。
- `spec` – 可选的 ProseMirror 装饰规范。

```ts
Decoration.Node(pos, pos + node.nodeSize, { class: 'is-heading' })
```

### `Decoration.Inline`

```ts
Decoration.Inline(
  from: number,
  to: number,
  attrs?: DecorationAttrs,
  spec?: Record<string, any>,
)
```

**参数**

- `from` – 行内范围的起始位置。
- `to` – 行内范围的结束位置。
- `attrs` – 可选。`DecorationAttrs`：`class`、`style`、`nodeName` 以及其他任意 HTML 属性。
- `spec` – 可选的 ProseMirror 装饰规范。

```ts
Decoration.Inline(matchFrom, matchTo, { class: 'is-match' })
```

### `Decoration.Widget`

```ts
Decoration.Widget(
  pos: number,
  render: (view: EditorView, getPos: () => number | undefined) => HTMLElement,
  options: {
    key: string
    side?: number
    relaxedSide?: boolean
    marks?: readonly Mark[]
    stopEvent?: (e: Event) => boolean
    ignoreSelection?: boolean
    destroy?: (node: Node) => void
    [k: string]: any
  },
)
```

**参数**

- `pos` – 渲染 widget 的位置。
- `render` – 接收 `view` 和 `getPos` 访问器并返回 `HTMLElement` 的回调。
- `options.key` – **必填。** 稳定、不依赖位置且全局唯一的键。请参阅 [Widget 键](/editor/core-concepts/decorations#widget-keys)。如果 Tiptap 检测到单次构建中有两个 widget 装饰使用相同的键，就会在开发环境中记录警告。
- `options.side` – 可选。指定 widget 相对于该位置偏向哪一侧（请参阅 ProseMirror 的 [`Decoration.widget`](https://prosemirror.net/docs/ref/#view.Decoration%5Ewidget)）。
- `options.relaxedSide` – 可选。允许 DOM 选区保留在 widget 的任意一侧。
- `options.marks` – 可选。应用于 widget 的标记。
- `options.stopEvent` – 可选。返回 `true` 可阻止 ProseMirror 处理源自 widget 的事件。
- `options.ignoreSelection` – 可选。阻止 ProseMirror 同步 widget 内部的选区变化。
- `options.destroy` – 可选。当 ProseMirror 移除 widget 或销毁编辑器时，会传入 widget DOM 节点并调用此回调。对于使用 `ReactWidgetRenderer` 或 `VueWidgetRenderer` 创建的 widget，不会调用此回调，因为框架渲染器会自行清理。

```ts
Decoration.Widget(
  matchFrom,
  () => {
    const el = document.createElement('span')
    el.textContent = '★'
    return el
  },
  // A position-based key is fine here because this widget has no state.
  { key: `marker-${matchFrom}`, side: -1 },
)
```

<Callout title="Widget 键必须稳定且唯一" variant="warning">
  只有当键与上次渲染的键相同时，ProseMirror 才会在重绘时重用 widget 的 DOM；键还必须全局唯一。重复键或基于位置的键会导致闪烁、状态丢失或崩溃。完整规则请参阅 [Widget 键](/editor/core-concepts/decorations#widget-keys)。
</Callout>

## `updateDecorations`

此命令会重新构建整个文档的装饰。本次更新会忽略扩展的更新策略和 `shouldUpdate`。当文档以外的值发生变化时（例如搜索词），请使用此命令。

```ts
editor.commands.updateDecorations() // Update every extension.
editor.commands.updateDecorations('myExtension') // Update one extension.
```

**参数**

- `extensionName` 为可选参数。传入扩展名称可仅更新该扩展。不传入则更新所有扩展。

常见用法请参阅[通过 storage 管理运行时参数](/editor/core-concepts/decorations#runtime-parameters-via-storage)模式。

## `ReactWidgetRenderer`

导入：`import { ReactWidgetRenderer } from '@tiptap/react'`。它会返回一个 `WidgetDecoration`，供你从 `create` 或 `createInRange` 中返回。它会复用 Tiptap 的 `ReactRenderer` portal 基础设施，因此组件位于编辑器的 React 树中（上下文和 hooks 均可照常使用）。组件还会通过 props 接收 `editor` 和 `getPos`。

```tsx
import { Extension } from '@tiptap/core'
import { ReactWidgetRenderer } from '@tiptap/react'

function CommentMarker({ editor, getPos, label }: { editor: Editor; getPos: () => number | undefined; label: string }) {
  return <button onClick={() => console.log(getPos())}>{label}</button>
}

const Comments = Extension.create({
  name: 'comments',

  addDecorations() {
    return {
      create: ({ editor, state }) =>
        findComments(state.doc).map(c =>
          ReactWidgetRenderer(CommentMarker, {
            editor,
            pos: c.pos,
            key: `comment-${c.id}`, // stable domain key → component state preserved
            props: { label: c.label },
          }),
        ),
    }
  },
})
```

| 选项 | 类型 | 说明 |
| ----------------- | --------------------------- | ------------------------------------------------------------------------------------- |
| `editor` | `Editor` | 编辑器实例。 |
| `pos` | `number` | 要渲染的位置。 |
| `key` | `string` | 稳定且唯一的键。请参阅 [Widget 键](/editor/core-concepts/decorations#widget-keys)。 |
| `props` | `P` | 传递给组件的 props。 |
| `as` | `string` | 包装标签，默认为 `'span'`。 |
| `className` | `string` | 应用于包装元素的类名。 |
| `side` | `number` | ProseMirror widget 的侧向偏置。 |
| `relaxedSide` | `boolean` | 允许 DOM 选区位于 widget 的任意一侧。 |
| `marks` | `readonly Mark[]` | 应用于 widget 的标记。 |
| `stopEvent` | `(event: Event) => boolean` | 阻止选定的 widget 事件传递给 ProseMirror。 |
| `ignoreSelection` | `boolean` | 阻止同步 widget 内部的选区变化。 |
| `destroy` | `(node: Node) => void` | 框架渲染器移除后执行自定义清理。 |

<Callout title="Props 与渲染器缓存" variant="info">
  每次重新运行 `create`/`createInRange` 时都会传入最新的 `props`（ProseMirror 重用 DOM 时会跳过 `toDOM`，因此无法通过这种方式传递 props）。每个键对应的渲染器都会被缓存并重用，因此组件状态会在编辑过程中保留。编辑器销毁时会清除缓存。
</Callout>

完整示例请参阅 [React 装饰教程](/guides/decorations-react)。

## `VueWidgetRenderer`

导入：`import { VueWidgetRenderer } from '@tiptap/vue-3'`（或 `'@tiptap/vue-2'`）。它与 React 渲染器的思路相同；它会复用 Tiptap 的 `VueRenderer`，因此组件共享编辑器的应用上下文（`provide`/`inject` 可正常使用）。除了你提供的 `props`，组件还会接收 `editor` 和 `getPos`。

```ts
import { Extension } from '@tiptap/core'
import { VueWidgetRenderer } from '@tiptap/vue-3'
import CommentMarker from './CommentMarker.vue'

const Comments = Extension.create({
  name: 'comments',

  addDecorations() {
    return {
      create: ({ editor, state }) =>
        findComments(state.doc).map(c =>
          VueWidgetRenderer(CommentMarker, {
            editor,
            pos: c.pos,
            key: `comment-${c.id}`,
            props: { label: c.label },
          }),
        ),
    }
  },
})
```

| 选项 | 类型 | 说明 |
| ----------------- | --------------------------- | ------------------------------------------------------------------------------------- |
| `editor` | `Editor` | 编辑器实例。 |
| `pos` | `number` | 要渲染的位置。 |
| `key` | `string` | 稳定且唯一的键。请参阅 [Widget 键](/editor/core-concepts/decorations#widget-keys)。 |
| `props` | `Record<string, any>` | 传递给组件的 props。 |
| `side` | `number` | ProseMirror widget 的侧向偏置。 |
| `relaxedSide` | `boolean` | 允许 DOM 选区位于 widget 的任意一侧。 |
| `marks` | `readonly Mark[]` | 应用于 widget 的标记。 |
| `stopEvent` | `(event: Event) => boolean` | 阻止选定的 widget 事件传递给 ProseMirror。 |
| `ignoreSelection` | `boolean` | 阻止同步 widget 内部的选区变化。 |
| `destroy` | `(node: Node) => void` | 框架渲染器移除后执行自定义清理。 |

<Callout title="Vue 特定要求" variant="warning">
  组件**必须只渲染一个根元素**。有意将 `editor` 原样传入（使用 `markRaw`）。不要将其包装为响应式对象。
</Callout>

完整示例请参阅 [Vue 3 装饰教程](/guides/decorations-vue)。

## `liveWidgetKeys`

导入：`import { liveWidgetKeys } from '@tiptap/core'`。

```ts
import { liveWidgetKeys } from '@tiptap/core'

const keys = liveWidgetKeys(editor)
```

返回当前所有存活 widget 装饰的键。框架 widget 渲染器会在内部使用它来判断即将卸载的 widget 是确实已被移除，还是仅被重新分配到新位置（从而避免销毁键仍然存活的渲染器）。

<Callout title="仅供高级用途" variant="hint">
  大多数用户不需要使用 `liveWidgetKeys`。它面向构建自定义 widget 渲染器的高级开发者。
</Callout>

## `createWidgetDecoration`

导入：`import { createWidgetDecoration } from '@tiptap/core'`。

这是一个与框架无关的辅助函数，`ReactWidgetRenderer` 和 `VueWidgetRenderer` 都基于它构建。它负责管理每个编辑器的渲染器缓存、props 差异比较、延迟刷新 props、键重新分配保护，以及传递 ProseMirror 选项。如果你需要由 React 或 Vue 以外的自定义渲染器支持的 widget，请使用它。

```ts
import { createWidgetDecoration } from '@tiptap/core'
import type { WidgetRenderer } from '@tiptap/core'

// A minimal renderer. WidgetRenderer requires updateProps and destroy;
// element is what materialize hands to ProseMirror.
class MyRenderer implements WidgetRenderer {
  element: HTMLElement

  constructor(renderProps: Record<string, any>) {
    // renderProps already merges props with context ({ editor, getPos })
    this.element = document.createElement('span')
    this.element.textContent = renderProps.label
  }

  updateProps(props: Record<string, any>) { /* ... */ }
  destroy() { /* ... */ }
}

const WIDGET_CACHE = Symbol('myWidgetCache')

// Inside addDecorations create():
createWidgetDecoration<MyRenderer>({
  editor,
  pos,
  key: `my-widget-${id}`,
  props: { label: 'hello' },
  cacheKey: WIDGET_CACHE,
  context: getPos => ({ editor, getPos }),
  create: renderProps => new MyRenderer(renderProps),
  materialize: renderer => renderer.element,
})
```

| 选项 | 类型 | 说明 |
| -------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `editor` | `Editor` | 编辑器实例。渲染器缓存保存在该实例上。 |
| `pos` | `number` | 要渲染的位置。 |
| `key` | `string` | 稳定且唯一的键。请参阅 [Widget 键](/editor/core-concepts/decorations#widget-keys)。 |
| `props` | `Record<string, any>` | 传递给渲染器的 props，每次渲染时都会与 `context` 合并。 |
| `cacheKey` | `symbol` | 用于存储渲染器缓存的 symbol。每个框架使用一个，避免缓存混用。 |
| `context` | `(getPos) => Record<string, any>` | 合并到每次渲染中的额外 props，例如 `editor` 和 `getPos`。每次实例化时都会调用。 |
| `create` | `(props) => WidgetRenderer` | 首次挂载时创建渲染器。接收已合并 `props` 和 `context` 的参数。 |
| `materialize` | `(renderer) => HTMLElement` | 返回由 ProseMirror 插入的元素。 |
| `side` | `number` | ProseMirror widget 的侧向偏置。 |
| `relaxedSide` | `boolean` | 允许 DOM 选区位于 widget 的任意一侧。 |
| `marks` | `readonly Mark[]` | 应用于 widget 的标记。 |
| `stopEvent` | `(event: Event) => boolean` | 阻止选定的 widget 事件传递给 ProseMirror。 |
| `ignoreSelection` | `boolean` | 阻止同步 widget 内部的选区变化。 |
| `destroy` | `(node: Node) => void` | 渲染器移除后执行自定义清理。 |

<Callout title="仅供高级用途" variant="hint">
  大多数用户应改用 `ReactWidgetRenderer` 或 `VueWidgetRenderer`。`createWidgetDecoration`
  面向构建自定义框架渲染器（Solid、Svelte 等）的开发者。
</Callout>
