本指南将介绍如何为一个简单的内联 `highlight` 标记添加 Markdown 支持。该标记使用 `==text==` 简写形式（常见于某些 Markdown 方言），并在 HTML 中生成 `mark` 元素。

我们将分四个步骤进行，每个步骤都会提供完整示例，确保你始终掌握完整的上下文：

1. 创建基础的 Tiptap `Mark` 扩展（不含 Markdown 支持）。
2. 添加自定义 Markdown 分词器，从原始 Markdown 中生成 token。
3. 添加解析器，将这些 token 转换为 Tiptap JSON（并应用标记）。
4. 添加渲染器（序列化器），将 Tiptap 内容转换回 Markdown。

我们要支持的简写形式：

```js
This is ==highlighted== text.
```

---

## 步骤 1：创建基础的 `highlight` Mark

首先定义一个最简的 `Mark`，描述标记名称、HTML 解析/渲染行为以及相关选项。暂时不加入 Markdown 集成，以便先专注于 schema 和 HTML 输入/输出。

```js
import { Mark } from '@tiptap/core'

export const Highlight = Mark.create({
  name: 'highlight',

  addOptions() {
    return {
      HTMLAttributes: {},
    }
  },

  parseHTML() {
    return [{ tag: 'mark' }]
  },

  renderHTML({ HTMLAttributes }) {
    return ['mark', HTMLAttributes, 0]
  },

  addCommands() {
    return {
      toggleHighlight:
        () =>
        ({ commands }) => {
          return commands.toggleMark(this.name)
        },
    }
  },
})
```

**注意：**
- 此标记仅映射到 HTML `<mark>` 标签。
- `toggleHighlight` 命令可用于以编程方式切换该标记。

## 步骤 2：添加自定义 Markdown 分词器

分词器负责识别原始 Markdown 中的 `==text==`，并返回包含内部文本及任何嵌套内联 token 的 token。本步骤只关注分词器，以便你能独立测试识别效果。

```js
import { Mark } from '@tiptap/core'

export const Highlight = Mark.create({
  name: 'highlight',

  addOptions() {
    return {
      HTMLAttributes: {},
    }
  },

  parseHTML() {
    return [{ tag: 'mark' }]
  },

  renderHTML({ HTMLAttributes }) {
    return ['mark', HTMLAttributes, 0]
  },

  // 定义自定义 Markdown 分词器，以识别 ==text==
  markdownTokenizer: {
    name: 'highlight',
    level: 'inline', // 内联元素
    // 提示词法分析器快速查找候选位置
    start: (src) => src.indexOf('=='),
    tokenize: (src, tokens, lexer) => {
      // 匹配剩余源文本开头的 ==text==
      const match = /^==([^=]+)==/.exec(src)
      if (!match) return undefined

      return {
        type: 'highlight',       // token 类型（必须与 name 相同）
        raw: match[0],           // 完整匹配的字符串：==text==
        text: match[1],          // 内部内容：text
        // 让 Markdown 词法分析器处理嵌套的内联格式
        tokens: lexer.inlineTokens(match[1]),
      }
    },
  },

  addCommands() {
    return {
      toggleHighlight:
        () =>
        ({ commands }) => {
          return commands.toggleMark(this.name)
        },
    }
  },
})
```

**实现说明：**
- `start` 是词法分析器用于快速定位潜在匹配项的优化方法。
- 分词器返回 `tokens: lexer.inlineTokens(match[1])`，因此可以保留嵌套的内联格式（粗体、斜体、链接等）。

## 步骤 3：添加解析器

`parseMarkdown` 函数会将分词器生成的 token 转换为 Tiptap 表示形式。对于标记，通常需要先将内部 token 解析为内联节点，再将标记应用到这些内容上。

```js
import { Mark } from '@tiptap/core'

export const Highlight = Mark.create({
  name: 'highlight',

  addOptions() {
    return {
      HTMLAttributes: {},
    }
  },

  parseHTML() {
    return [{ tag: 'mark' }]
  },

  renderHTML({ HTMLAttributes }) {
    return ['mark', HTMLAttributes, 0]
  },

  // 定义自定义 Markdown 分词器，以识别 ==text==
  markdownTokenizer: {
    name: 'highlight',
    level: 'inline', // 内联元素
    // 提示词法分析器快速查找候选位置
    start: (src) => src.indexOf('=='),
    tokenize: (src, tokens, lexer) => {
      // 匹配剩余源文本开头的 ==text==
      const match = /^==([^=]+)==/.exec(src)
      if (!match) return undefined

      return {
        type: 'highlight',       // token 类型（必须与 name 相同）
        raw: match[0],           // 完整匹配的字符串：==text==
        text: match[1],          // 内部内容：text
        // 让 Markdown 词法分析器处理嵌套的内联格式
        tokens: lexer.inlineTokens(match[1]),
      }
    },
  },

  // 将 Markdown token 解析为 Tiptap JSON
  parseMarkdown: (token, helpers) => {
    // 将嵌套的内联 token 解析为 Tiptap 兼容的内容数组
    const content = helpers.parseInline(token.tokens || [])
    // 将 'highlight' 标记应用到解析后的内容
    return helpers.applyMark('highlight', content)
  },

  addCommands() {
    return {
      toggleHighlight:
        () =>
        ({ commands }) => {
          return commands.toggleMark(this.name)
        },
    }
  },
})
```

**注意：**
- `helpers.parseInline` 会将嵌套的内联 token 转换为 Tiptap 兼容的 `content` 数组。
- `helpers.applyMark('highlight', content)` 会将 `highlight` 标记应用到解析后的内联内容，并返回 Markdown 解析器所需的结构。

## 步骤 4：添加渲染器

要支持将编辑器状态序列化回 Markdown，需要实现 `renderMarkdown` 函数。该函数接收一个 Tiptap 节点（或标记节点结构），并应返回 Markdown 字符串。使用 `helpers.renderChildren` 序列化嵌套内容。

```js
import { Mark } from '@tiptap/core'

export const Highlight = Mark.create({
  name: 'highlight',

  addOptions() {
    return {
      HTMLAttributes: {},
    }
  },

  parseHTML() {
    return [{ tag: 'mark' }]
  },

  renderHTML({ HTMLAttributes }) {
    return ['mark', HTMLAttributes, 0]
  },

  // 定义自定义 Markdown 分词器，以识别 ==text==
  markdownTokenizer: {
    name: 'highlight',
    level: 'inline', // 内联元素
    // 提示词法分析器快速查找候选位置
    start: (src) => src.indexOf('=='),
    tokenize: (src, tokens, lexer) => {
      // 匹配剩余源文本开头的 ==text==
      const match = /^==([^=]+)==/.exec(src)
      if (!match) return undefined

      return {
        type: 'highlight',       // token 类型（必须与 name 相同）
        raw: match[0],           // 完整匹配的字符串：==text==
        text: match[1],          // 内部内容：text
        // 让 Markdown 词法分析器处理嵌套的内联格式
        tokens: lexer.inlineTokens(match[1]),
      }
    },
  },

  // 将 Markdown token 解析为 Tiptap JSON
  parseMarkdown: (token, helpers) => {
    // 将嵌套的内联 token 解析为 Tiptap 兼容的内容数组
    const content = helpers.parseInline(token.tokens || [])
    // 将 'highlight' 标记应用到解析后的内容
    return helpers.applyMark('highlight', content)
  },

  // 将 Tiptap 节点渲染回 Markdown
  renderMarkdown: (node, helpers) => {
    const content = helpers.renderChildren(node.content || [])
    // 用 == 分隔符包裹序列化后的子内容
    return `==${content}==`
  },

  addCommands() {
    return {
      toggleHighlight:
        () =>
        ({ commands }) => {
          return commands.toggleMark(this.name)
        },
    }
  },
})
```

**注意：**
- `helpers.renderChildren` 会将节点/标记的子内容序列化回 Markdown，并保留嵌套格式。
- 确保 `renderMarkdown` 的输出符合分词器的预期（空格/换行）。对于此类内联标记，简单的 `==content==` 形式即可。

## 用法

将扩展添加到编辑器，并从 Markdown 设置内容：

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import Markdown from 'some-markdown-integration' // 替换为你的 Markdown 集成
import { Highlight } from './highlight'

const editor = new Editor({
  extensions: [StarterKit, Markdown, Highlight],
})

// 设置 Markdown 内容（Markdown 集成必须支持 'contentType' 或类似选项）
editor.commands.setContent('This is ==highlighted== text', { contentType: 'markdown' })

// 以编程方式切换高亮
editor.commands.toggleHighlight()
```

## 测试与边缘情况

- **嵌套的内联格式：** 分词器使用了 `lexer.inlineTokens(match[1])`，因此嵌套的内联 token（粗体、斜体、链接）应能正确解析和渲染。
- **贪婪匹配：** 分词器使用简单的 `^==([^=]+)==` 正则表达式，因此无法匹配内部包含 `==` 的内容。如果需要支持嵌套的 `==` 或多行高亮，请相应扩展正则表达式。
- **空白处理：** 某些 Markdown 方言允许分隔符内有空格（例如 `== text ==`）。如果需要支持这种形式，请更新分词器和 `renderMarkdown` 的输出，以保留所选格式。
- **与其他分词器冲突：** `start` 优化有助于词法分析器选取候选位置，但请确保你的正则表达式不会与 Markdown 工具链中的其他内联分词器冲突。
