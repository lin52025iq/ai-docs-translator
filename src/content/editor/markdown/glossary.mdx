在深入了解细节之前，先来看看本指南中会用到的一些关键术语：

## Token（标记）

表示一段已解析 Markdown 内容的普通 JavaScript 对象。例如，标题 token 可能如下所示：`{ type: "heading", depth: 2, text: "Hello" }`。Token 就像描述文档结构的“乐高积木”。

- Token 是 [MarkedJS](https://marked.js.org) 解析器生成的 Markdown 语法片段的结构化表示。
- 每个 Token 都有一个 `type`（例如 `heading`、`paragraph`、`list` 等）。
- 每个 Token 还可能包含与其类型相关的其他属性（例如标题的 `depth`、列表的 `ordered` 等）。
- Token 也可以在 `tokens` 或 `items` 等属性中包含嵌套的 Token，以表示 Markdown 内容的层级结构。
- Token 不能直接用于 Tiptap；必须先将其转换为 Tiptap 的 JSON 格式。
- Token 由[分词器](#tokenizer)创建。
- 我们可以通过实现[自定义分词器](./advanced-usage/custom-tokenizer)来创建自己的 Token。

> **注意**：MarkedJS 内置了用于标准 Markdown 语法的分词器，但你可以通过向 MarkdownManager 提供自定义分词器来扩展或替换这些分词器。
>
> 你可以在 [MarkedJS 类型定义](https://github.com/markedjs/marked/blob/master/src/Tokens.ts)中查看默认 Token 列表。

## Tiptap JSON

- Tiptap JSON 与 Markdown 无关，是 Tiptap 和 ProseMirror 用来表示文档结构的 JSON 格式。
- Tiptap JSON 由节点和标记组成，每个节点和标记都有一个 `type`，以及可选的 `attrs`、`content` 或 `text`。
- 节点表示块级元素（如段落、标题和列表），而标记表示行内格式（如粗体、斜体和链接）。
- Tiptap JSON 具有层级结构，节点中可以包含其他节点或文本，以反映文档结构。
- 我们可以使用 **Token** 创建编辑器能够理解的 **Tiptap JSON**。

现在我们已经了解了 Token 和 Tiptap JSON 之间的区别，接下来看看如何解析 Token，以及如何序列化 Tiptap 内容。

## 分词器

分词器是一组函数（或规则），用于扫描原始 Markdown 文本，并决定如何将其中的片段转换为 Token。例如，它会识别 `## Heading` 并生成一个 `heading` Token。你可以自定义或覆盖分词器，以改变 Markdown 的解析方式。

你可以参阅[自定义分词器](./advanced-usage/custom-tokenizer)指南，了解如何创建自定义分词器。

## 词法分析器

词法分析器负责遍历整个 Markdown 字符串，依次应用[分词器](#tokenizer)，并生成完整的 Token 列表。可以把它想象成一台机器：它会反复将文本交给分词器处理，直到整个输入都被转换为 Token。

你无需直接操作词法分析器，因为 Tiptap 已经在 MarkedJS 实例中创建了一个词法分析器实例，并会在编辑器的整个生命周期内重复使用它。

此词法分析器实例会自动注册你各个扩展中的所有[分词器](#tokenizer)。
