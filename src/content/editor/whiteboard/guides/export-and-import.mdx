将白板保存为 JSON 文件，然后在同一应用或其他应用中重新打开；也可以打开 Excalidraw 和 tldraw 保存的白板。将整个白板或其中的一些图形导出为 SVG、PNG 或 JPEG 图片。这些函数会生成文件，之后由你的应用保存，例如将其作为下载文件。

## 将白板保存为文件

`exportBoard` 返回一个白板文件，其中包含白板的 JSON 数据，以及文档框所显示的文档。使用 `JSON.stringify` 将其转换为文件：

```js
import { exportBoard } from '@tiptap-pro/extension-whiteboard'

const json = JSON.stringify(exportBoard({ editor }))
const file = new Blob([json], { type: 'application/json' })
```

## 打开白板文件

`importBoard` 会打开经过解析的白板文件 JSON。默认情况下，文件中的白板会替换当前白板中的图形。使用 `mode: 'insert'` 时，则会像粘贴一样，将文件中的图形副本添加到其他图形前面，并选中这些副本：

```js
import { importBoard, scrollShapesIntoView } from '@tiptap-pro/extension-whiteboard'

const text = await file.text()
const { ids } = importBoard({ editor, file: JSON.parse(text), mode: 'insert' })
scrollShapesIntoView({ stage, editor, ids, updateCamera: setCamera })
```

与粘贴的图形一样，这些副本会保留文件中的位置；如果第一个副本原本会与白板上的某个图形位于同一点，它们就会整体向右下方移动 24 个白板单位。`scrollShapesIntoView` 会移动摄像机，使其显示这些图形。执行一次撤销即可撤销导入。

`importBoard` 会返回它添加的图形 ID。在 `skipped` 中，它会返回被省略的图形，因为编辑器无法显示它们：例如，编辑器没有相应扩展的自定义图形，或属性类型错误的图形（如位置不是数字）。对于图形内部的内容，编辑器不支持的标记会被移除，不支持的节点会转换为段落或被移除。没有 ID，或 ID 与文件中其他图形重复的图形会获得新 ID。

`skipped` 中的每个图形都会在 `reason` 中说明被省略的原因。如果文件中包含相关信息，还会提供 `detail`（例如文档框名称、链接或文本）以及 `box`（图形在白板上的位置）。这样，应用就可以列出缺失内容，并使用 [`fitCameraToRect`](/editor/whiteboard/api-reference/utilities#fitcameratorect) 将摄像机移动到对应位置。

### 无法打开的文件

如果 JSON 不属于它支持的文件类型，或者白板或 tldraw 文件格式版本过新，`importBoard` 就会抛出 `BoardFileError`。其 `code` 会指出具体原因，且白板会保持原样：

```js
import { BoardFileError, importBoard } from '@tiptap-pro/extension-whiteboard'

try {
  importBoard({ editor, file: JSON.parse(text) })
} catch (error) {
  if (error instanceof BoardFileError && error.code === 'version-too-new') {
    showMessage('请更新应用以打开此白板。')
  } else {
    showMessage('此文件不是白板文件。')
  }
}
```

## 打开 Excalidraw 和 tldraw 文件

`importBoard` 也可以打开 Excalidraw（`.excalidraw`）和 tldraw（`.tldr`）保存的文件。像传入白板文件一样传入解析后的 JSON，并在文件输入框中指定这些扩展名，例如 `accept=".json,.excalidraw,.tldr"`。

文件中的图形会转换为白板图形：

- 矩形、椭圆、菱形和三角形会转换为带文本的几何图形。星形等其他几何图形会转换为矩形。
- 便笺会转换为便利贴，文本会转换为自由文本。如果文件中包含数据 URL 或 `http`、`https` URL，图片就会显示。
- 箭头会保留其连接的图形、标签、箭头端和虚线样式，以及直线、曲线或折线形状。
- 绘图和由三个或更多点组成的线条会转换为画笔线条；由两个点组成的线条会转换为没有箭头端的箭头。
- 颜色会转换为最接近的白板颜色，字号会转换为最接近的白板字号。

白板不支持的内容会被省略或改变：

- 图形会失去旋转效果，组会被拆分。文档框、嵌入内容、书签、视频以及基于 tldraw 构建的应用添加的图形会被省略，但其中的图形不会被省略。`skipped` 会列出这些内容及其名称、链接或文本，以及它们原本所在的位置。
- 对于 tldraw 文件，会打开页面列表中的第一页，而不是上次打开的页面。`skipped` 会列出其他页面中的图形，并标明其所属页面名称。
- 箭头只能在两端之间呈直线、单段曲线或折线，因此 Excalidraw 箭头中两端之间的点会丢失。
- 图片会失去裁剪和翻转效果，并填满其边界框。
- 白板图形不支持垂直对齐，因此位于图形顶部或底部的文本会转换为相应位置的自由文本。
- 应用通常会填充白板图形，而其他应用默认不会这样做，因此较大的图形会置于较小图形的后方。

Excalidraw 库（`.excalidrawlib`）和 tldraw 1 的文件无法打开，并会抛出 `code` 为 `not-a-board-file` 的 `BoardFileError`。较新版本的 tldraw 文件会尽可能打开白板所支持的图形。tldraw 仍会写入版本 1 的文件格式，只有文件版本更高时，`importBoard` 才会抛出 `version-too-new`。

## 文档框

白板文件包含其文档框中的文档。`importBoard` 添加的每个文档框都会获得一个新的文档 ID，因此不会与其他白板上的文档框共用文档。使用 [`docs`](/editor/whiteboard/guides/doc-frames#provide-the-documents) 的 `load` 成员填充新文档：

```js
load: ({ docId, content }) => documents.set(docId, content),
```

`load` 会在文档框显示之前、`start` 运行之前执行。如果没有 `load`，导入的文档框将从空文档开始。

## 图片

白板文件会保存每张[图片](/editor/whiteboard/guides/images)的 URL，与白板本身的行为相同，但不会保存图片文件。因此，只有在 URL 有效时，导入的图片才会显示。

## 导出图片

`exportBoardImage` 会将白板图形绘制为 PNG 或 JPEG 文件，`exportBoardSvg` 则会生成带有尺寸的 SVG 标记。它们会按照页面上的显示效果绘制图形，使用应用的 CSS 和字体，但不包含选区、控制柄和光标：

```js
import { exportBoardImage, exportBoardSvg } from '@tiptap-pro/extension-whiteboard'

const png = await exportBoardImage({ editor, background: '#fff' })
const image = await exportBoardSvg({ editor, ids: ['note-1'] })
```

- 如果未指定 `ids`，就会绘制所有图形。如果没有可绘制的图形，则返回 `null`。
- `padding` 指图形周围的留白，默认值为 16 个白板单位。如果没有指定 `background`，留白区域会透明；但 JPEG 图片的留白区域会是白色。
- PNG 或 JPEG 默认每个白板单位对应 2 个像素，可通过 `pixelRatio` 设置。对于较大的图片，由于浏览器无法绘制超过特定尺寸的画布，每个白板单位对应的像素会减少。

图片取自页面中的白板，因此白板编辑器必须已挂载，否则这些函数会抛出错误。

- 页面 `@font-face` 规则中的字体也会一并导出，包括导入的样式表和其他来源（例如 Google Fonts）的样式表中的字体。无法加载字体文件时，会回退到其他字体。通过 `FontFace` API 添加的字体不会一并导出。
- 如果图形中的图片文件是图片格式，就会一并导出。页面无法获取的图片（例如来自没有 CORS 标头的其他来源的图片）不会显示。
- 10 秒内未加载的文件会被省略。
- 文本是 `foreignObject` 中的 HTML。浏览器可以显示它，但某些矢量编辑器不支持。
- CSS 背景图片、`canvas` 元素和 `::before` 等伪元素不会显示。
- 在 Safari 中，PNG 和 JPEG 图片没有阴影，因为 Safari 会将阴影绘制为灰色方框。
- 导出时会读取每个元素的样式，因此大型白板需要一些时间：导出 1,000 条便笺约需一秒。

## 复制图片

Safari 仅会在处理触发复制操作的点击或按键时写入剪贴板。因此，请立即调用 `write`，并将图片的 Promise 传给 `ClipboardItem`：

```js
const png = exportBoardImage({ editor }).then(
  (image) => image ?? Promise.reject(new Error('No shapes to copy')),
)

await navigator.clipboard.write([new ClipboardItem({ 'image/png': png })])
```
