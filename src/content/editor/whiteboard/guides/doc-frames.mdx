文档框是一种形状，用于在独立的编辑器中显示富文本。白板会存储文档框及其文档 ID。文档由你的应用管理，因此白板无需承担任何存储工作。

## 提供文档

通过 `WhiteboardKit` 的 `docs` 选项告知白板文档存放的位置。未设置此选项时，文档框不会显示文档。以下示例将文档保存在内存中：

```js
import { Editor } from '@tiptap/core'
import { StarterKit } from '@tiptap/starter-kit'
import { WhiteboardKit } from '@tiptap-pro/extension-whiteboard'

// Document JSON by document id
const documents = new Map()

const editor = new Editor({
  element: viewport,
  extensions: [
    WhiteboardKit.configure({
      docs: {
        createEditor: ({ element, docId }) =>
          new Editor({
            element,
            extensions: [StarterKit],
            content: documents.get(docId),
            onUpdate: ({ editor: docEditor }) => documents.set(docId, docEditor.getJSON()),
          }),
        copy: ({ fromDocId, toDocId }) => {
          const document = documents.get(fromDocId)

          if (document) {
            documents.set(toDocId, structuredClone(document))
          }
        },
        load: ({ docId, content }) => documents.set(docId, content),
      },
    }),
  ],
})
```

在 React 中，请在组件外部或使用 `useMemo` 创建一次配置好的 kit。请参阅[在 React 中设置白板](/editor/whiteboard/guides/react)。

`docs` 对象包含以下成员：

- `createEditor({ element, docId })` 在 `element` 中创建文档的编辑器。`element` 是文档框的内容元素 `[data-shape-content]`。白板会在销毁文档框时销毁编辑器。编辑器可以使用任意扩展，例如 `StarterKit`。
- `copy({ fromDocId, toDocId })` 为文档框副本复制文档；用户复制或粘贴文档框时会调用此方法。副本显示前会运行此方法。
- 可选的 `load({ docId, content })` 用于填充新文档，该文档属于通过 [`importBoard`](/editor/whiteboard/guides/export-and-import#doc-frames) 从白板文件导入的文档框。文档框显示前会运行此方法。未提供此方法时，导入的文档框内容为空。
- 可选的 `start(docId)` 用于初始化由当前编辑器中的更改添加到白板上的每个文档框的文档：包括新建的文档框、副本，以及通过 `setContent` 或使用 `UndoRedo` 撤销操作恢复的文档框。文档框显示前会运行此方法。通过 Yjs 从其他编辑器同步而来，或由其撤销操作恢复的文档框，不会在此处初始化文档。

因此，即使文档已经存在，`start` 也会运行，例如在 `copy` 之后为副本运行。请保留文档框已有的文档：

```js
start: (docId) => {
  if (!documents.has(docId)) {
    documents.set(docId, { type: 'doc', content: [{ type: 'paragraph' }] })
  }
},
```

## 添加文档框

`doc` 工具（快捷键 <kbd>W</kbd>）会添加一个带有新文档的文档框，并开始编辑该文档。未设置 `docs` 时，白板不会提供 `doc` 工具。在代码中，添加文档框的方式与添加其他形状相同：

```js
import { createShapeId } from '@tiptap-pro/extension-whiteboard'

editor.commands.insertShape({ type: 'docFrame', docId: createShapeId(), x: 0, y: 0, width: 420 })
```

文档框会显示 `docId` 指定 ID 对应的文档。没有 `docId` 的文档框会使用自身的形状 ID，因此仍会拥有自己的文档。`docIdOf` 会从文档框的节点或节点 JSON 中返回其文档 ID。

## 编辑文档

白板可以像选择、移动和调整其他形状一样操作文档框。文档框的高度会随文档内容变化。在开始编辑前，文档的编辑器处于只读状态。你可以点击已选中的文档框、按 <kbd>Enter</kbd>，或调用 `editShapeText` 开始编辑：

```js
editor.commands.editShapeText({ id: 'frame' })
```

编辑文档时，在文档框内的点击和按键操作都由其编辑器处理。按 <kbd>Escape</kbd> 会停止编辑并重新选中文档框。点击其他形状也会停止编辑；将[白板设为只读](/editor/whiteboard/guides/shapes-and-tools#read-only-boards)同样如此。

### 设置编辑中文档的格式

工具栏可以同时操作正在编辑的文档和形状中的文本。`getEditedDocEditor` 会返回文档框当前正在编辑的文档所对应的编辑器；如果没有正在编辑的文档，则返回 `null`：

```js
import { getEditedDocEditor } from '@tiptap-pro/extension-whiteboard'

// A bold button that works in documents too
const textEditor = getEditedDocEditor(editor) ?? editor
textEditor.commands.toggleBold()
```

文档编辑器的每次事务都会使白板编辑器触发 `docChange`，包括仅移动光标的事务。此外，开始或停止编辑，以及创建或销毁文档编辑器时，也会触发此事件。你可以用它更新工具栏，但不要用它保存文档：

```js
editor.on('docChange', ({ docId }) => {
  console.log(`The document ${docId} changed`)
})
```

## 读取所有文档

`getDocEditors` 会返回白板上各文档框所显示文档的编辑器：

```js
import { getDocEditors } from '@tiptap-pro/extension-whiteboard'

const contents = getDocEditors(editor).map((docEditor) => docEditor.getJSON())
```

白板编辑器销毁后，此方法不会返回任何编辑器。

## 延迟到达的文档

当前编辑器中的每次更改后，文档框都会调整高度以适应文档。其他用户的编辑器会测量其所做更改的尺寸。如果文档在文档框之后才到达，例如 AI 添加文档框后才写入文档，可以使用 `keepShapeHeights` 保留为文档框设置的高度：

```js
import { keepShapeHeights } from '@tiptap-pro/extension-whiteboard'

const { tr } = editor.state
// … add a doc frame whose document arrives later
editor.view.dispatch(keepShapeHeights(tr))
```
