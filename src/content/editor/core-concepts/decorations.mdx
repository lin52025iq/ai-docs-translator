装饰会改变内容在编辑器中的显示方式，但不会改变文档本身。将编辑器保存为 JSON 或 HTML 时，装饰不会包含在内。

扩展通过 `addDecorations()` 添加装饰。使用 `Decoration` 类创建装饰，Tiptap 会负责将它们添加到编辑器中。

<CodeDemo path="/Examples/Decorations?inline=false&hideSource=false" />

## 何时使用装饰，何时使用节点视图

当标记纯粹用于视觉呈现，且位于文档之外时，使用装饰。如果内容本身属于文档，请使用[节点视图](/editor/extensions/custom-extensions/node-views)。

<Callout title="装饰与节点视图" variant="info">
  对于不会更改文档的高亮、搜索结果、评论、注释和临时 UI 标记，请使用**装饰**。如果需要持久化的自定义文档内容、可编辑的自定义块，或拥有文档结构的复杂嵌入式 UI，请使用**[节点视图](/editor/extensions/custom-extensions/node-views)**。
</Callout>

## 三种装饰

装饰共有三种，均通过 `Decoration` 类创建：

- **node** 为单个节点添加属性，例如 CSS 类。
- **inline** 为一段文本或其他行内内容添加样式。
- **widget** 在文档中的某个位置添加 DOM 元素或框架组件。

## 声明装饰

扩展通过生命周期钩子 `addDecorations()` 声明装饰，该钩子返回一个 `DecorationSpec`（没有装饰时返回 `null`）。使用从 `@tiptap/core` 导入的 `Decoration` 类来创建装饰：

```ts
import { Decoration, Extension } from '@tiptap/core'

const MyExtension = Extension.create({
  name: 'myExtension',

  addDecorations() {
    return {
      create: ({ editor, state, view }) => [Decoration.Inline(1, 5, { class: 'highlight' })],
    }
  },
})
```

与其他扩展钩子一样，`addDecorations()` 绑定到 `this`（`{ name, options, storage, editor, type, parent }`），因此声明装饰时可以读取选项和存储。

<Callout title="从 state 参数读取状态，而不是 editor.state" variant="warning">
  在 `create()` 和 `createInRange()` 中，始终从 `state` 参数读取文档，而不要使用
  `editor.state`。事务执行期间，编辑器的视图状态尚未更新，因此
  `editor.state` 指向事务处理前的文档。`state` 参数才是当前正在构建的正确状态。
</Callout>

### `Decoration` 类

`Decoration` 类包含一些静态方法，它们会返回描述 Tiptap 应显示内容的装饰实例。请从 `@tiptap/core` 导入：

```ts
import { Decoration } from '@tiptap/core'

// 为单个节点添加装饰（属性会添加到节点的 DOM 外层）
Decoration.Node(from, to, attrs, spec)

// 为一段行内内容添加装饰（将其包裹在带样式的 span 中）
Decoration.Inline(from, to, attrs, spec)

// 在某个位置插入小部件（DOM 节点）；`key` 为必填项
Decoration.Widget(pos, render, options)
```

`attrs` 接受 `class`、`style`、`nodeName` 以及其他任意 HTML 属性（ProseMirror 的 `DecorationAttrs`）。

### 节点装饰

节点装饰会为单个节点的 DOM 外层添加属性。例如，为每个标题添加轮廓类，这是最轻量的做法：

```ts
addDecorations() {
  return {
    create: ({ state }) => {
      const decorations = []
      state.doc.descendants((node, pos) => {
        if (node.type.name === 'heading') {
          decorations.push(Decoration.Node(pos, pos + node.nodeSize, { class: 'is-heading' }))
        }
      })
      return decorations
    },
  }
}
```

### 行内装饰

行内装饰会将一段行内内容包裹在带样式的 span 中，非常适合用于高亮和搜索结果：

```ts
Decoration.Inline(matchFrom, matchTo, { class: 'is-match' })
```

### 小部件装饰

小部件装饰会在某个位置插入一个 DOM 节点。与节点装饰和行内装饰不同，小部件需要 `render` 回调和一个**必填且稳定的 `key`**：

```ts
Decoration.Widget(
  pos,
  (view, getPos) => {
    const el = document.createElement('span')
    el.textContent = '★'
    return el
  },
  { key: `marker-${pos}`, side: -1 },
)
```

`side` 用于控制小部件位于该位置的哪一侧。请参阅 ProseMirror 的 [`Decoration.widget`](https://prosemirror.net/docs/ref/#view.Decoration%5Ewidget)。每个小部件都必须有 `key`。

## 小部件的 key

每个小部件装饰都需要一个稳定且与位置无关的 `key`。这是使用小部件时最常见的问题来源。

<Callout title="选择稳定且全局唯一的 key" variant="warning">
  只有当小部件的 key 与上次渲染时相同时，ProseMirror 才会在重绘时复用其 DOM。如果没有稳定的 key，小部件会在每次更新时被销毁并重新创建，导致闪烁和组件状态丢失。所有编辑器中的小部件装饰，其 key 还必须**全局唯一**。重复的 key 会导致 ProseMirror 错误放置小部件 DOM 并崩溃。

  如果 Tiptap 在一次构建中检测到两个小部件装饰具有相同的 key，就会在开发环境中发出警告，并指出有问题的扩展：
  
  `[tiptap warn]: Duplicate widget decoration key "<key>" in extension "<name>". Widget decoration keys must
    be globally unique…`
  
  该警告有助于你发现问题，但仍须确保每个 key 都是唯一的。否则，ProseMirror 会错误放置小部件 DOM。

</Callout>

**好的 key** 使用属于该项的 ID：`comment-${id}`、`paragraph-${node.attrs.id}`、`suggestion-${id}`。

**不好的 key** 不稳定或依赖位置，例如循环或段落索引、文档位置（`marker-${from}`）或任何基于位置的值。

如果同一实体需要两个小部件，请添加后缀：`comment-${id}-start` 和 `comment-${id}-end`。

<Callout title="无状态小部件的例外情况" variant="hint">
  对于演示和简单示例中的无状态小部件（例如静态标记），可以使用基于索引或位置的 key。有状态的小部件则必须使用稳定的项目 ID。
</Callout>

## 默认行为

- 编辑器初始化时，每个扩展的 `create` 都会运行一次，以构建初始装饰。
- 默认情况下，文档更改时，Tiptap 会重新构建装饰。
- 仅选区更改时，Tiptap 会保留当前装饰并更新其位置。

## 性能

默认情况下，装饰使用 `document` 更新策略。每次文档更改后都会重新构建装饰。对于大型文档，可以选择其他策略来减少工作量。

### 使用 `shouldUpdate` 跳过更新

如果一次编辑不会影响装饰，请让 `shouldUpdate` 返回 `false`。Tiptap 会保留装饰并更新其位置，而不是重新构建。

```ts
addDecorations() {
  return {
    create: ({ state }) => buildHeadingOutline(state),
    shouldUpdate: ({ tr, oldState, newState }) => {
      // 仅当标题数量发生变化时才重新构建
      return countHeadings(oldState.doc) !== countHeadings(newState.doc)
    },
  }
}
```

默认情况下，每次文档更改后都会运行 `shouldUpdate`。

### 使用 `changedRanges` 更新已编辑的块

使用 `update: 'changedRanges'` 和 `createInRange` 回调时，文档更改后，管理器会：

1. 更新现有装饰的位置。
2. 计算事务中的更改范围，并将其扩展到**外围顶层块的边界**，这样即使匹配内容与原始编辑范围重叠（例如在单词中间输入），也仍会完整包含在内。
3. 移除锚定在这些块中的过时装饰，并通过调用 `createInRange({ state, from, to })` **仅重新构建这些块**。

正常编辑期间，Tiptap 不会调用 `create`。只有编辑器启动时或调用 [`updateDecorations()`](#重新构建装饰) 时才会调用 `create`。这样可以避免每次按键后都扫描整个文档。

`createInRange` 接收与块边界对齐的 `from`/`to`，且只能返回该范围内的装饰。它通常会与 `create` 共用一个扫描辅助函数：

```ts
addDecorations() {
  const scan = (editor, state, from, to) => {
    const decorations = []
    state.doc.nodesBetween(from, to, (node, pos) => {
      // …为 [from, to] 范围内的节点/文本构建装饰…
    })
    return decorations
  }

  return {
    update: 'changedRanges',
    create: ({ editor, state }) => scan(editor, state, 0, state.doc.content.size),
    createInRange: ({ editor, state, from, to }) => scan(editor, state, from, to),
  }
}
```

<Callout title="createInRange 的约定" variant="warning">
  `createInRange` 只能返回起始位置位于 `[from, to)` 内的装饰。对于行内装饰和节点装饰，起始位置是 `from`；对于小部件装饰，起始位置是 `pos`。`to` 不包含在范围内：它是下一个块的起始位置，该块会自行重新构建，因此会忽略锚定在 `to` 的装饰。最后一个块是例外，因为它包含文档末尾。锚定在 `from` 之前的装饰属于相邻块，而管理器不会移除该相邻块，因此返回这些装饰会造成重复，并且永远不会被清理。如果装饰依赖给定范围之外的内容，请改用 `document` 策略。
</Callout>

TypeScript 会强制检查两者的搭配：`update: 'changedRanges'` 必须搭配 `createInRange`，而其他策略不接受 `createInRange`。

<Callout title="增量模式仅适用于块内装饰" variant="warning">
  只有当每个装饰**仅依赖其所在块或范围内的内容时**，增量模式才是正确的。Tiptap 只会重新扫描已编辑的块，不会检查其他块中的装饰。

**安全（局部）：**“高亮某个单词的每次出现”“为每个标题添加轮廓”“给拼写错误的单词加下划线”。每个装饰都只依赖所在块。

**不安全（依赖整个文档）：**使用默认的 `document` 策略和 `create`，或调用 `updateDecorations()` 强制完整重建：

- 序数/计数逻辑：“只高亮第一次匹配”“每第 3 次出现时更改颜色”。
- 跨文档关系：“标记文档中的重复单词”。
- 结构关系：“为第一个标题添加特殊类”。
- 任何依赖选区或外部状态的内容。更改范围更新只响应_内容_变化；选区或状态变化时，请改为触发 `updateDecorations()`。

</Callout>

### 使用 `manual` 处理外部状态

当文档事务只应将现有装饰映射到新位置时，请使用 `update: 'manual'`。手动装饰只会在初始化时以及调用 `updateDecorations()` 时重新构建。

如果装饰依赖文档之外的值（例如搜索查询或筛选条件），请使用手动策略。该策略不能与 `shouldUpdate` 或 `createInRange` 搭配使用。

## 重新构建装饰

有时装饰会依赖文档之外的内容，例如搜索词或筛选条件。该值发生变化时，请调用 `updateDecorations`：

```ts
editor.commands.updateDecorations() // 更新每个扩展。
editor.commands.updateDecorations('myExtension') // 更新一个扩展。
```

`updateDecorations` 始终会针对整个文档调用 `create`。本次更新会忽略更新策略和 `shouldUpdate`。

### 通过 storage 设置运行时参数

将变化的值存储在扩展的 [`storage`](/editor/extensions/custom-extensions/create-new/extension#addstorage) 中。在 `create` 中读取这些值，更改后调用 `updateDecorations`：

```ts
editor.storage.myExtension.term = 'foo'
editor.commands.updateDecorations('myExtension')
```

## 将框架组件渲染为小部件

小部件装饰可以渲染 React 或 Vue 组件。组件会保留在编辑器的 React 或 Vue 应用中，因此 hooks、上下文以及 `provide`/`inject` 仍可正常工作。

<CodeDemo path="/Examples/DecorationComponents?inline=false&hideSource=false" />

### React：`ReactWidgetRenderer`

从 `@tiptap/react` 导入 `ReactWidgetRenderer`。它会返回一个 `WidgetDecoration`，可与 `Decoration.Node` 和 `Decoration.Inline` 一起从 `create` 或 `createInRange` 返回。组件还会通过 props 接收 `editor` 和 `getPos`。

```tsx
import { Extension } from '@tiptap/core'
import { ReactWidgetRenderer } from '@tiptap/react'
import type { Editor } from '@tiptap/core'

function CommentMarker({
  editor,
  getPos,
  label,
}: {
  editor: Editor
  getPos: () => number | undefined
  label: string
}) {
  return <button onClick={() => console.log(getPos())}>{label}</button>
}

const Comments = Extension.create({
  name: 'comments',

  addDecorations() {
    return {
      create: ({ editor, state }) =>
        findComments(state.doc).map((c) =>
          ReactWidgetRenderer(CommentMarker, {
            editor,
            pos: c.pos,
            key: `comment-${c.id}`, // 稳定的领域 key → 保留组件状态
            props: { label: c.label },
          }),
        ),
    }
  },
})
```

需要了解以下几点：

- 再次运行 `create` 或 `createInRange` 时，Tiptap 会传入新的 `props`。它会复用 key 相同的渲染器，因此组件会保留其状态。
- 编辑器销毁时会清理缓存。

### Vue：`VueWidgetRenderer`

从 `@tiptap/vue-3`（或 `@tiptap/vue-2`）导入 `VueWidgetRenderer`。它复用了 Tiptap 的 `VueRenderer`，因此组件与编辑器共享应用上下文（`provide`/`inject` 可正常工作）。除你的 `props` 外，组件还会接收 `editor` 和 `getPos`。

```ts
import { Extension } from '@tiptap/core'
import { VueWidgetRenderer } from '@tiptap/vue-3'
import CommentMarker from './CommentMarker.vue'

const Comments = Extension.create({
  name: 'comments',

  addDecorations() {
    return {
      create: ({ editor, state }) =>
        findComments(state.doc).map((c) =>
          VueWidgetRenderer(CommentMarker, {
            editor,
            pos: c.pos,
            key: `comment-${c.id}`,
            props: { label: c.label },
          }),
        ),
    }
  },
})
```

<Callout title="Vue 专属说明" variant="warning">
  组件**必须渲染单个根元素**。`editor` 会以原始形式传入（使用 `markRaw`），这是有意为之。请勿将其包装为响应式对象。
</Callout>

## 完整示例：搜索词高亮器

本示例使用了全部三种装饰和增量模式。它会高亮搜索词的每次出现（行内装饰）、在每个匹配项前渲染星形标记（小部件装饰），并为每个标题添加轮廓（节点装饰）。搜索词保存在 storage 中，并通过 `updateDecorations` 在运行时更改。

每个匹配项和标题都只依赖其所在块，因此这里使用 `update: 'changedRanges'` 是安全的。

```ts
import { Decoration, Extension } from '@tiptap/core'
import type { Editor } from '@tiptap/core'
import type { EditorState } from '@tiptap/pm/state'

export interface HighlightOptions {
  term: string
}
export interface HighlightStorage {
  term: string
}

declare module '@tiptap/core' {
  interface Storage {
    highlight: HighlightStorage
  }
}

export const Highlight = Extension.create<HighlightOptions, HighlightStorage>({
  name: 'highlight',

  addOptions: () => ({ term: 'tiptap' }),

  addStorage() {
    return { term: this.options.term }
  },

  addDecorations() {
    const scan = (editor: Editor, state: EditorState, from: number, to: number) => {
      const decorations: Decoration[] = []
      const term = editor.storage.highlight.term.trim().toLowerCase()

      state.doc.nodesBetween(from, to, (node, pos) => {
        if (node.type.name === 'heading') {
          decorations.push(Decoration.Node(pos, pos + node.nodeSize, { class: 'is-heading' }))
        }
        if (!term || !node.isText || !node.text) return

        const text = node.text.toLowerCase()
        let index = text.indexOf(term)
        while (index !== -1) {
          const matchFrom = pos + index
          const matchTo = matchFrom + term.length
          decorations.push(Decoration.Inline(matchFrom, matchTo, { class: 'is-match' }))
          decorations.push(
            Decoration.Widget(
              matchFrom,
              () => {
                const el = document.createElement('span')
                el.textContent = '★'
                return el
              },
              { key: `marker-${matchFrom}`, side: -1 }, // 无状态 → 可以使用位置作为 key
            ),
          )
          index = text.indexOf(term, index + term.length)
        }
      })
      return decorations
    }

    return {
      update: 'changedRanges', // 每个匹配项/标题都只依赖所在块 → 安全
      create: ({ editor, state }) => scan(editor, state, 0, state.doc.content.size),
      createInRange: ({ editor, state, from, to }) => scan(editor, state, from, to),
    }
  },
})
```

通过更新 storage 并重新构建装饰来更改搜索词：

```ts
editor.storage.highlight.term = 'editor'
editor.commands.updateDecorations('highlight')
```
