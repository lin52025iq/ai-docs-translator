与许多其他编辑器不同，Tiptap 基于[结构规范（schema）](https://prosemirror.net/docs/guide/#schema)构建，用于定义内容的组织方式。借助它，你可以定义文档中允许出现的节点类型、节点属性以及节点的嵌套方式。

这个 schema 的限制_非常_严格。你不能使用 schema 中未定义的 HTML 元素或属性。

举个例子：如果你在 Tiptap 中粘贴 `This is <strong>important</strong>` 这样的内容，但没有任何扩展处理 `strong` 标签，你只会看到 `This is important`，而不会看到粗体标签。

如果你想知道何时发生这种情况，可以启用 `enableContentCheck` 选项，然后监听 [`contentError`](/editor/api/events#list-of-available-events) 事件。

## Schema 的样子

如果你只使用提供的扩展，就不必太在意 schema。如果要构建自己的扩展，了解 schema 的工作方式可能会很有帮助。来看一个典型 ProseMirror 编辑器中最简单的 schema：

```js
// the underlying ProseMirror schema
{
  nodes: {
    doc: {
      content: 'block+',
    },
    paragraph: {
      content: 'inline*',
      group: 'block',
      parseDOM: [{ tag: 'p' }],
      toDOM: () => ['p', 0],
    },
    text: {
      group: 'inline',
    },
  },
}
```

这里注册了三个节点：`doc`、`paragraph` 和 `text`。`doc` 是根节点，允许一个或多个块节点作为子节点（`content: 'block+'`）。由于 `paragraph` 属于块节点组（`group: 'block'`），我们的文档只能包含段落。段落允许零个或多个内联节点作为子节点（`content: 'inline*'`），因此其中只能包含 `text`。`parseDOM` 定义如何从粘贴的 HTML 中解析节点。`toDOM` 定义节点如何渲染到 DOM 中。

在 Tiptap 中，每个节点、标记和扩展都各自位于一个文件中。这样可以将逻辑拆分开来。在底层，整个 schema 会合并在一起：

```js
// the Tiptap schema API
import { Node } from '@tiptap/core'

const Document = Node.create({
  name: 'doc',
  topNode: true,
  content: 'block+',
})

const Paragraph = Node.create({
  name: 'paragraph',
  group: 'block',
  content: 'inline*',
  parseHTML() {
    return [{ tag: 'p' }]
  },
  renderHTML({ HTMLAttributes }) {
    return ['p', HTMLAttributes, 0]
  },
})

const Text = Node.create({
  name: 'text',
  group: 'inline',
})
```

## 使用外部 schema 规范

将完整的 ProseMirror `SchemaSpec` 传给编辑器的 [`schemaSpec`](/editor/api/editor#schemaspec) 选项，即可在本地扩展行为之外单独定义文档结构。当多个编辑器需要共享相同结构，但具有不同的渲染或交互代码时，可以使用这种方式。

规范控制节点和标记的结构。本地扩展仍负责提供 HTML 解析和渲染、文本序列化、命令、键盘快捷键、节点视图和插件。

```ts
import { Editor } from '@tiptap/core'
import Bold from '@tiptap/extension-bold'
import Document from '@tiptap/extension-document'
import Paragraph from '@tiptap/extension-paragraph'
import Text from '@tiptap/extension-text'
import type { SchemaSpec } from '@tiptap/pm/model'

const schemaSpec: SchemaSpec = {
  nodes: {
    doc: { content: 'block+' },
    paragraph: {
      group: 'block',
      content: 'inline*',
      marks: 'bold',
      attrs: {
        tone: { default: 'newsletter', validate: 'string' },
      },
    },
    text: { group: 'inline' },
  },
  marks: {
    bold: {},
  },
}

const LocalParagraph = Paragraph.extend({
  addAttributes() {
    return {
      tone: {
        parseHTML: (element) => element.getAttribute('data-tone'),
        renderHTML: (attributes) => ({ 'data-tone': attributes.tone }),
      },
    }
  },
})

const editor = new Editor({
  element: document.querySelector('.editor'),
  extensions: [Document, LocalParagraph, Text, Bold],
  schemaSpec,
  content: '<p>Hello <strong>world</strong>.</p>',
})

editor.getHTML()
// '<p data-tone="newsletter">Hello <strong>world</strong>.</p>'
```

这里，`schemaSpec` 允许粗体文本，并设置了 `tone` 属性的默认值。`LocalParagraph` 继承段落的渲染方式，并将 `tone` 映射为 HTML 属性 `data-tone`。`Bold` 扩展提供 `<strong>` 的解析和渲染，以及 `toggleBold` 命令。

### 匹配扩展

规范和解析后的扩展必须包含完全相同的节点名称和标记名称。规范中的每个节点都需要对应的本地节点扩展，每个标记都需要对应的本地标记扩展。本地节点或标记名称重复时会被拒绝。

未定义节点或标记的扩展可以在规范中没有对应条目的情况下添加。例如，只添加键盘快捷键的扩展就不需要对应条目。

如果使用 `StarterKit`，请在规范中包含它启用的所有节点和标记，或者禁用未包含的类型。仅包含段落的规范不能与默认的 `StarterKit` 配置一起使用。

本地节点和标记扩展可以只定义行为。它们的结构字段和属性都可以完全由 `schemaSpec` 提供。

### 结构规则

外部规范会替换本地结构字段，而不是补充缺失字段。如果省略某个字段，ProseMirror 会使用其默认值，而不是本地扩展中的值。

- 对于节点，规范控制 `content`、`marks`、`group`、`inline`、`atom`、`selectable`、`draggable`、`code`、`whitespace`、`definingAsContext`、`definingForContent`、`defining`、`isolating` 和 `linebreakReplacement`。
- 对于标记，规范控制 `inclusive`、`excludes`、`group`、`spanning` 和 `code`。
- 无论本地扩展的优先级如何，规范都决定顶层节点以及节点和标记的顺序。

DOM 行为应保留在本地扩展中。外部规范中的 `parseDOM` 和 `toDOM` 字段会被忽略。自定义 schema 元数据（例如 `tableRole` 和 `allowGapCursor`）也来自本地扩展。

### 属性规则

对于节点和标记，规范控制属性名称、默认值、是否必需以及验证规则。

- 规范中不存在的本地属性会被移除，包括通过 `addGlobalAttributes()` 添加的属性。
- 匹配的本地属性会保留其 `parseHTML`、`renderHTML`、`rendered` 和 `keepOnSplit` 行为。它们的默认值和验证规则由规范决定。
- 仅存在于规范中的属性使用 Tiptap 默认的属性解析和渲染方式。如果需要自定义 HTML 表示形式，请定义本地属性钩子。
- 没有 `default` 的属性是必需属性。创建使用该属性的内容时，请提供相应的值。

### 验证和更新

创建编辑器时，如果 schema 结构无效、结构字段类型无效、缺少本地实现、存在额外的本地节点或标记类型，或本地类型名称重复，Tiptap 都会拒绝创建。

规范仅在创建编辑器时应用。`editor.setOptions({ schemaSpec })` 不会重建 schema。要更改结构，请创建一个新编辑器，并迁移现有内容，使其符合新规范。

如果省略 `schemaSpec`，Tiptap 会继续根据本地扩展构建 schema。

## 节点和标记

### 区别

节点类似内容块，例如段落、标题、代码块、引用块等。

标记可以应用于节点的特定部分。例如**粗体**、_斜体_或~~删除线~~文本。[链接](#)也是标记。

### 节点 schema

#### 内容

`content` 属性准确地定义了节点可以包含哪些内容。ProseMirror 对此要求非常严格，也就是说，不符合 schema 的内容会被丢弃。它要求值为名称或组名字符串。下面是一些示例：

```js
Node.create({
  // must have one or more blocks
  content: 'block+',

  // must have zero or more blocks
  content: 'block*',

  // allows all kinds of 'inline' content (text or hard breaks)
  content: 'inline*',

  // must not have anything else than 'text'
  content: 'text*',

  // can have one or more paragraphs, or lists (if lists are used)
  content: '(paragraph|list?)+',

  // must have exact one heading at the top, and one or more blocks below
  content: 'heading block+',
})
```

#### 标记

你可以通过 schema 的 `marks` 设置，定义节点中允许使用哪些标记。可以添加一个或多个标记名称或组名，也可以像下面这样允许或禁止所有标记：

```js
Node.create({
  // allows only the 'bold' mark
  marks: 'bold',

  // allows only the 'bold' and 'italic' marks
  marks: 'bold italic',

  // allows all marks
  marks: '_',

  // disallows all marks
  marks: '',
})
```

#### 组

将此节点添加到扩展组中，然后就可以在 schema 的 [`content`](#content) 属性中引用该组。

```js
Node.create({
  // add to 'block' group
  group: 'block',

  // add to 'inline' group
  group: 'inline',

  // add to 'block' and 'list' group
  group: 'block list',
})
```

#### 内联

节点也可以以内联方式渲染。设置 `inline: true` 后，节点会与文本一起显示。例如，提及就是如此。它的结果更像标记，但具备节点的功能。两者的一个区别在于生成的 JSON 文档：多个标记可以同时应用，而内联节点会形成嵌套结构。

```js
Node.create({
  // renders nodes in line with the text, for example
  inline: true,
})
```

如果你需要标记不具备的功能（例如节点视图），可以尝试使用内联节点：

```js
Node.create({
  name: 'customInlineNode',
  group: 'inline',
  inline: true,
  content: 'text*',
})
```

内联节点可能不容易选中，尤其是位于行首或行尾时。一个快速解决方法是使用 CSS 在元素后添加零宽空格：

```css
.customInlineNode::after {
  content: "\200B";
}
```

#### 原子节点

`atom: true` 的节点不能直接编辑，应视为一个整体。在编辑器场景中，这种用法并不常见，但配置如下：

```js
Node.create({
  atom: true,
})
```

[`Mention`](/editor/extensions/nodes/mention) 扩展就是一个例子：它看起来有点像文本，但行为更像一个整体。由于它不包含可编辑文本，复制此类节点时内容为空。不过，你可以控制这一行为。下面是 [`Mention`](/editor/extensions/nodes/mention) 扩展中的示例：

```js
// Used to convert an atom node to plain text
renderText({ node }) {
  return `@${node.attrs.id}`
},
```

#### 可选择

除了常见的文本选择，还有一种不可见的节点选择。要让节点可以被选中，可以这样配置：

```js
Node.create({
  selectable: true,
})
```

#### 可拖动

可以使用此设置让所有节点都可拖动（默认不可拖动）：

```js
Node.create({
  draggable: true,
})
```

#### 代码

用户期望代码的行为与普通内容截然不同。对于包含代码的各类节点，可以设置 `code: true` 来体现这一点。

```js
Node.create({
  code: true,
})
```

#### 空白字符

控制如何解析此节点中的空白字符。

```js
Node.create({
  whitespace: 'pre',
})
```

#### 定义节点

默认情况下，当节点的全部内容被替换时（例如粘贴新内容时），该节点会被移除。如果希望此类替换操作保留节点，请将其配置为 `defining`。

这通常适用于 [`Blockquote`](/editor/extensions/nodes/blockquote)、[`CodeBlock`](/editor/extensions/nodes/code-block)、[`Heading`](/editor/extensions/nodes/heading) 和 [`ListItem`](/editor/extensions/nodes/list-item)。

```js
Node.create({
  defining: true,
})
```

#### 隔离

对于在退格等常规编辑操作中需要阻止光标越界的节点（例如表格单元格），请设置 `isolating: true`。

```js
Node.create({
  isolating: true,
})
```

#### 允许间隙光标

[`Gapcursor`](/editor/extensions/functionality/gapcursor) 扩展会注册一个新的 schema 属性，用于控制是否允许光标出现在该节点的任意位置。

```js
Node.create({
  allowGapCursor: false,
})
```

#### 表格角色

[`Table`](/editor/extensions/nodes/table) 扩展会注册一个新的 schema 属性，用于配置节点的角色。允许的值为 `table`、`row`、`cell` 和 `header_cell`。

```js
Node.create({
  tableRole: 'cell',
})
```

### 标记 schema

#### 包含性

如果不希望光标位于标记末尾时仍激活该标记，请将 `inclusive` 设为 `false`。例如，[`Link`](/editor/extensions/marks/link) 标记就是这样配置的：

```js
Mark.create({
  inclusive: false,
})
```

#### 排除项

默认情况下，所有标记都可以同时应用。通过 `excludes` 属性，你可以定义哪些标记不能与此标记共存。例如，行内代码标记会排除其他所有标记（粗体、斜体等）。

```js
Mark.create({
  // must not coexist with the bold mark
  excludes: 'bold'
  // exclude any other mark
  excludes: '_',
})
```

#### 可退出

默认情况下，标记会“困住”光标：除非将光标从左向右移入没有标记的文本，否则光标无法离开标记。
如果将此项设为 `true`，当标记位于节点末尾时，光标就可以退出该标记。例如，代码标记就适合使用此设置。

```js
Mark.create({
  // make this mark exitable - default is false
  exitable: true,
})
```

#### 组

将此标记添加到扩展组中，然后就可以在 schema 的 `content` 属性中引用该组。

```js
Mark.create({
  // add this mark to the 'basic' group
  group: 'basic',
  // add this mark to the 'basic' and the 'foobar' group
  group: 'basic foobar',
})
```

#### 代码

用户期望代码的行为与普通内容截然不同。对于包含代码的各类标记，可以设置 `code: true` 来体现这一点。

```js
Mark.create({
  code: true,
})
```

#### 跨节点

默认情况下，标记渲染为 HTML 时可以跨越多个节点。设置 `spanning: false` 表示标记不能跨越多个节点。

```js
Mark.create({
  spanning: false,
})
```

## 获取底层 ProseMirror schema

有些场景需要使用底层 schema。例如，使用 Tiptap 协同文本编辑功能，或想要手动将内容渲染为 HTML 时，就需要用到它。

### 方式一：使用编辑器

如果你需要在客户端获取 schema，而且本来就需要一个编辑器实例，可以通过编辑器获取：

```js
import { Editor } from '@tiptap/core'
import Document from '@tiptap/extension-document'
import Paragraph from '@tiptap/extension-paragraph'
import Text from '@tiptap/extension-text'

const editor = new Editor({
  extensions: [
    Document,
    Paragraph,
    Text,
    // add more extensions here
  ])
})

const schema = editor.schema
```

### 方式二：不使用编辑器

如果只想获取 schema，而不初始化实际的编辑器，可以使用辅助函数 `getSchema`。它需要一个可用扩展数组，并会便捷地为你生成 ProseMirror schema：

```js
import { getSchema } from '@tiptap/core'
import Document from '@tiptap/extension-document'
import Paragraph from '@tiptap/extension-paragraph'
import Text from '@tiptap/extension-text'

const schema = getSchema([
  Document,
  Paragraph,
  Text,
  // add more extensions here
])
```

## 无效 Schema 处理

为了跟踪并响应内容错误，Tiptap 支持检查所提供的内容是否符合根据已注册扩展生成的 schema。
要启用此功能，请将 `enableContentCheck` 选项设为 `true`，以检查内容并触发 `contentError` 事件。
可以通过 `onContentError` 回调监听这些事件。
此标志默认设为 `false`，以保持与旧版本的兼容性。

<Callout title="注意" variant="warning">
  Tiptap 对 JSON 类型内容的检查 100% 准确。但如果你提供的是 HTML，我们会尽力提示缺失的节点；在某些情况下可能无法检测到标记，因此仍会按默认行为丢弃无法识别的内容。
</Callout>

### contentError 事件

在编辑器初始化时，如果提供的初始 `content` 与 schema 不兼容，就会触发 `contentError` 事件。

使用 3.33.0 版 [Collaboration 扩展](/editor/extensions/functionality/collaboration)以及 3.2.0 版或更高版本的 `@tiptap/y-tiptap` 时，如果共享文档包含不符合 schema 的内容，也会触发该事件。此时，编辑器会保留共享文档中的内容、暂停编辑并且不发送任何更改。详情请参阅[无效 Schema 处理](/guides/invalid-schema#for-collaborative-editing)。

错误上下文中会提供一个 `disableCollaboration` 函数。调用该函数会销毁传递给 Collaboration 扩展的 Y.Doc，使编辑器停止与其他用户同步。使用同一 Y.Doc 的其他编辑器也会停止同步。

可以通过 `onContentError` 选项直接处理此事件，例如：

```jsx
new Editor({
  enableContentCheck: true,
  content: invalidContent,
  onContentError({ editor, error, disableCollaboration }) {
    // your handler here
  },
  ...options,
})
```

也可以在编辑器实例上为 `contentError` 事件添加监听器：

```jsx
const editor = new Editor({
  enableContentCheck: true,
  content: invalidContent,
  ...options,
})

editor.on('contentError', ({ editor, error, disableCollaboration }) => {
  // your handler here
})
```

有关更多实现示例，请参阅[事件](/editor/api/events)部分。

### 不启用内容检查也监听 contentError 事件

如果想在不启用内容检查的情况下监听 `contentError` 事件，请在初始化 Tiptap 编辑器时将 `emitContentError` 设为 `true`：

```jsx
new Editor({
  enableContentCheck: false,
  emitContentError: true,
  ...options,
})
```

此设置允许编辑器中存在无效内容，同时仍会在内容无效时通知你。

### 建议的处理方式

如何处理 schema 错误取决于你的应用和需求，以下是我们的建议：

#### 不使用协同编辑

根据具体使用场景，默认的未知内容剥离行为可以确保内容处于已知的有效状态，以便后续编辑。

#### 使用协同编辑

根据具体使用场景，你可能需要设置 `enableContentCheck` 标志并监听 `contentError` 事件。收到此事件后，可以参考以下示例进行处理：

```tsx
onContentError({ editor, error, disableCollaboration }) {
  // Removes the collaboration extension.
  disableCollaboration()

  // Since the content is invalid, we don't want to emit an update
  // Preventing synchronization with other editors or to a server
  const emitUpdate = false

  // Disable the editor to prevent further user input
  editor.setEditable(false, emitUpdate)

  // Maybe show a notification to the user that they need to refresh the app
}
```
