Tiptap 的强大之处在于灵活性。你可以从头开始创建自己的扩展，打造符合需求的独特编辑器体验。

无论是创建节点、标记还是功能变更，所有扩展的基本结构都相同。而且，Tiptap 中的一切都基于扩展。

## 创建扩展

扩展为 Tiptap 增添新功能。在文档中，你会经常看到“扩展”这个词，包括介绍节点和标记的内容。不过也有真正的扩展。它们无法像标记和节点那样修改 schema，但可以添加功能或改变编辑器的行为。

一个很好的例子是监听编辑器事件并对其进行处理，例如：

```typescript
import { Extension } from '@tiptap/core'

const CustomExtension = Extension.create({
  name: 'customExtension',

  onUpdate() {
    console.log(this.editor.getJSON())
  },
})
```

你也可以使用回调函数创建扩展。如果你想封装扩展逻辑，例如定义事件处理程序或其他自定义逻辑，这种方式会很有用。

```js
import { Extension } from '@tiptap/core'

const CustomExtension = Extension.create(() => {
  // Define variables or functions to use inside your extension
  const customVariable = 'foo'

  function onCreate() {}
  function onUpdate() {}

  return {
    name: 'customExtension',
    onCreate,
    onUpdate,

    // Your code goes here.
  }
})
```

此扩展会监听编辑器的 `update` 事件，并将编辑器当前的 JSON 表示形式输出到控制台。

可以这样将它安装到编辑器中：

```typescript
import { Editor } from '@tiptap/core'

const editor = new Editor({
  extensions: [CustomExtension],
})

// Or if using React or Vue

const editor = useEditor({
  extensions: [CustomExtension],
})
```

扩展数组中可以包含任意数量的扩展。它们会按照列出的顺序安装，也可以按 `priority` 属性排序。

了解扩展的基本结构后，接下来我们深入看看创建自定义扩展时可以使用的所有选项。

## 扩展选项

创建扩展时，你可以定义一组选项，供用户配置。这些选项可用于自定义扩展的行为，或提供其他功能。

### `name`

扩展的名称。编辑器的扩展管理器会使用此名称来识别扩展。

```typescript
const CustomExtension = Extension.create({
  name: 'customExtension',
})
```

如果扩展是节点或标记，此名称用于在编辑器的 schema 中识别该节点或标记，因此也会保存在编辑器内容的 JSON 表示形式中。详情请参阅[将内容存储为 JSON](/guides/output-json-html#option-1-json)。

### `priority`

优先级决定扩展的注册顺序。默认优先级为 `100`，大多数扩展都使用此值。优先级较高的扩展会先加载。

```js
import Link from '@tiptap/extension-link'

const CustomLink = Link.extend({
  priority: 1000,
})
```

扩展的加载顺序会影响以下两点：

1. 插件顺序（优先级较高的扩展所含的 ProseMirror 插件会先运行。）
2. Schema 顺序

例如，[`Link`](/editor/extensions/marks/link) 标记的优先级较高，因此它会被渲染为 `<a href="…"><strong>Example</strong></a>`，而不是 `<strong><a href="…">Example</a></strong>`。

### `addOptions`

`addOptions` 方法用于定义扩展选项。此方法应返回一个对象，其中包含可由用户配置的选项。

```typescript
type CustomExtensionOptions = {
  customOption: string
}

declare module '@tiptap/core' {
  interface ExtensionOptions {
    customOption: CustomExtensionOptions
  }
}

const CustomExtension = Extension.create<CustomExtensionOptions>({
  name: 'customExtension',

  addOptions() {
    return {
      customOption: 'default value',
    }
  },
})
```

这样便可以在安装扩展时设置配置：

```typescript
const editor = new Editor({
  extensions: [CustomExtension.configure({ customOption: 'new value' })],
})
```

### `addStorage`

`addStorage` 方法用于定义扩展的存储（本质上是一个简单的状态管理器）。此方法应返回一个对象，其中包含扩展可使用的存储。

```typescript
type CustomExtensionStorage = {
  customValue: string
}

declare module '@tiptap/core' {
  interface ExtensionStorage {
    customExtension: CustomExtensionStorage
  }
}

const CustomExtension = Extension.create<any, CustomExtensionStorage>({
  name: 'customExtension',

  addStorage() {
    return {
      customValue: 'default value',
    }
  },
})
```

这样便可以在扩展内部访问存储：

```typescript
const CustomExtension = Extension.create<any, CustomExtensionStorage>({
  name: 'customExtension',

  addStorage() {
    return {
      customValue: 'default value',
    }
  },

  onUpdate() {
    console.log(this.storage.customValue) // 'default value'
  },
})
```

也可以通过编辑器访问：

```typescript
const editor = new Editor({
  extensions: [CustomExtension],
})

editor.storage.customExtension.customValue // 'default value'
```

<Callout title="注意" variant="info">
  `editor.storage` 使用扩展的名称作为命名空间。
</Callout>

### `addCommands`

`addCommands` 方法用于定义扩展命令。此方法应返回一个对象，其中包含用户可以执行的命令。

```typescript
declare module '@tiptap/core' {
  interface Commands<ReturnType> {
    customExtension: {
      customCommand: () => ReturnType
    }
  }
}

const CustomExtension = Extension.create({
  name: 'customExtension',

  addCommands() {
    return {
      customCommand:
        () =>
        ({ commands }) => {
          return commands.setContent('Custom command executed')
        },
    }
  },
})
```

<Callout title="在 addCommands 中使用 commands 参数" variant="warning">
  如需在 `addCommands` 中访问其他命令，请使用传入的 `commands` 参数。
</Callout>

这样便可以让用户执行这些命令：

```typescript
const editor = new Editor({
  extensions: [CustomExtension],
})

editor.commands.customCommand() // 'Custom command executed'
editor.chain().customCommand().run() // 'Custom command executed'
```

### `addKeyboardShortcuts`

`addKeyboardShortcuts` 方法用于定义键盘快捷键。此方法应返回一个对象，其中包含用户可以使用的键盘快捷键。

```typescript
const CustomExtension = Extension.create({
  name: 'customExtension',

  addKeyboardShortcuts() {
    return {
      'Mod-k': () => {
        console.log('Keyboard shortcut executed')
      },
    }
  },
})
```

这样便可以让用户使用这些键盘快捷键。

### `addInputRules`

使用输入规则可以定义正则表达式来监听用户输入。它们可用于 Markdown 快捷输入；例如，[`Typography`](/editor/extensions/functionality/typography) 扩展可以将 `(c)` 等文本转换为 `©`（以及许多其他内容）。标记请使用 `markInputRule` 辅助函数，节点请使用 `nodeInputRule`。

默认情况下，两侧各有一个波浪号的文本会转换为 ~~删除线文本~~。如果你希望每侧一个波浪号就足够，可以像这样覆盖输入规则：

```typescript
import { Extension } from '@tiptap/core'
import { markInputRule } from '@tiptap/core'

const CustomExtension = Extension.create({
  name: 'customExtension',

  addInputRules() {
    return [
      markInputRule({
        find: /(?:~)((?:[^~]+))(?:~)$/,
        type: this.editor.schema.marks.strike,
      }),
    ]
  },
})
```

现在，输入 `~striked text~` 后，它就会转换为 ~~删除线文本~~。

想进一步了解输入规则？请参阅[输入规则](/editor/api/input-rules)文档。

### `addPasteRules`

粘贴规则的工作方式与输入规则（见上文）类似。不过，它们不是监听用户输入，而是应用于粘贴的内容。

正则表达式有一个小区别。输入规则通常以 `$` 美元符号结尾（表示“断言位置在行尾”），粘贴规则通常会检查全部内容，不带这个 `$` 美元符号。

将上面的示例用于粘贴规则，代码如下：

```typescript
import { Extension } from '@tiptap/core'
import { markPasteRule } from '@tiptap/core'

const CustomExtension = Extension.create({
  name: 'customExtension',

  addPasteRules() {
    return [
      markPasteRule({
        find: /(?:~)((?:[^~]+))(?:~)/g,
        type: this.editor.schema.marks.strike,
      }),
    ]
  },
})
```

想进一步了解粘贴规则？请参阅[粘贴规则](/editor/api/paste-rules)文档。

### `transformPastedHTML`

`transformPastedHTML` 方法允许你在粘贴的 HTML 内容被解析并插入编辑器之前对其进行转换。它适用于清理样式、移除危险内容，或修改粘贴的 HTML 以满足编辑器的要求。

#### 工作原理

用户将内容粘贴到编辑器时：

1. 扩展按优先级排序（优先级越高，执行越早）
2. 按顺序调用每个扩展的 `transformPastedHTML`
3. 每次转换都会接收上一次转换的输出
4. 最终转换后的 HTML 会被解析并插入编辑器

#### 基本示例

```typescript
import { Extension } from '@tiptap/core'

const CleanStylesExtension = Extension.create({
  name: 'cleanStyles',

  transformPastedHTML(html) {
    // Remove all inline style attributes
    return html.replace(/\s+style="[^"]*"/gi, '')
  },
})
```

#### 转换链示例

多个扩展可以转换同一份粘贴内容。使用 `priority` 选项控制顺序：

```typescript
// Extension 1: Remove scripts (runs first, priority: 110)
const SecurityExtension = Extension.create({
  name: 'security',
  priority: 110,

  transformPastedHTML(html) {
    let cleanHtml = html

    // Remove script tags
    cleanHtml = cleanHtml.replace(/<script\b[^<]*(?:(?!<\/script>)<[^<]*)*<\/script>/gi, '')

    // Remove event handler attributes (onclick, onerror, etc.)
    cleanHtml = cleanHtml.replace(/\s+on\w+\s*=\s*(?:"[^"]*"|'[^']*'|[^\s>]*)/gi, '')

    // Remove javascript: protocol from href (handles double-quoted, single-quoted, and unquoted attributes)
    cleanHtml = cleanHtml.replace(
      /href\s*=\s*(?:"javascript:[^"]*"|'javascript:[^']*'|javascript:[^\s>]*)/gi,
      'href="#"',
    )

    return cleanHtml
  },
})

// Extension 2: Remove styles (runs second, priority: 100)
const CleanStylesExtension = Extension.create({
  name: 'cleanStyles',
  priority: 100,

  transformPastedHTML(html) {
    return html.replace(/\s+style="[^"]*"/gi, '')
  },
})
```

在此示例中：

1. `SecurityExtension` 先运行（优先级为 110），移除危险内容
2. `CleanStylesExtension` 接收 `SecurityExtension` 的输出并移除样式
3. 最终清理后的 HTML 会插入编辑器

#### 使用扩展上下文

此方法可以通过 `this` 访问扩展上下文：

```typescript
const ConditionalCleanup = Extension.create({
  name: 'conditionalCleanup',

  addOptions() {
    return {
      removeStyles: true,
      removeClasses: false,
    }
  },

  transformPastedHTML(html) {
    let cleanHtml = html

    // Access extension options
    if (this.options.removeStyles) {
      cleanHtml = cleanHtml.replace(/\s+style="[^"]*"/gi, '')
    }

    if (this.options.removeClasses) {
      cleanHtml = cleanHtml.replace(/\s+class="[^"]*"/gi, '')
    }

    // Access editor instance
    this.editor.emit('htmlTransformed', { original: html, transformed: cleanHtml })

    return cleanHtml
  },
})
```

#### 常见用例

移除 Google Docs 格式：

```typescript
const GoogleDocsCleanup = Extension.create({
  name: 'googleDocsCleanup',

  transformPastedHTML(html) {
    return (
      html
        // Remove Google Docs spans with inline styles
        .replace(/<span[^>]*style="[^"]*"[^>]*>(.*?)<\/span>/gi, '$1')
        // Remove Google Docs IDs
        .replace(/\s+id="docs-internal-[^"]*"/gi, '')
        // Remove empty spans
        .replace(/<span>(.*?)<\/span>/gi, '$1')
    )
  },
})
```

移除 Microsoft Word 格式：

```typescript
const WordCleanup = Extension.create({
  name: 'wordCleanup',

  transformPastedHTML(html) {
    return (
      html
        // Remove Word-specific classes
        .replace(/\s+class="Mso[^"]*"/gi, '')
        // Remove Word-specific tags
        .replace(/<o:p>.*?<\/o:p>/gi, '')
        // Remove conditional comments
        .replace(/<!--\[if.*?<!\[endif\]-->/gs, '')
    )
  },
})
```

### 事件

你也可以将[事件监听器](/editor/api/events)移至单独的扩展中。下面是一个监听所有事件的示例：

```typescript
import { Extension } from '@tiptap/core'

const CustomExtension = Extension.create({
  onBeforeCreate() {
    // The editor is about to be created.
  },
  onCreate() {
    // The editor is ready.
  },
  onUpdate() {
    // The content has changed.
  },
  onSelectionUpdate({ editor }) {
    // The selection has changed.
  },
  onTransaction({ transaction }) {
    // The editor state has changed.
  },
  onFocus({ event }) {
    // The editor is focused.
  },
  onBlur({ event }) {
    // The editor isn’t focused anymore.
  },
  onDestroy() {
    // The editor is being destroyed.
  },
})
```

### `dispatchTransaction`

此钩子允许你在事务分派前拦截并修改事务。它采用类似 Koa 或 Express 的**中间件模式**，每个扩展都会接收 `transaction` 和 `next` 函数。

#### 工作原理

1. **中间件链**：分派事务时，Tiptap 会将所有定义了 `dispatchTransaction` 钩子的扩展串联起来。
2. **按优先级排序**：此链按[扩展优先级](#priority)排序。优先级**较高**（例如 `1000`）的扩展会在链中**较早**调用，并包装优先级较低的扩展。
3. **传递事务**：你必须调用 `next(transaction)`，将事务传递给链中的下一个扩展。最终，最后一次 `next()` 调用会将事务传递给编辑器的基础分派函数（或你定义的自定义 `editorProps.dispatchTransaction`）。
4. **阻止事务**：如果不调用 `next(transaction)`，事务就会被阻止，无法到达编辑器。

```typescript
import { Extension } from '@tiptap/core'

const LoggingExtension = Extension.create({
  name: 'loggingExtension',
  priority: 1000, // Runs early

  dispatchTransaction({ transaction, next }) {
    console.log('Intercepting transaction before others...')

    // You can modify the transaction here if needed
    // transaction.setMeta('customMeta', true)

    // Call next to pass it to the next extension
    next(transaction)

    console.log('Transaction has been processed by the rest of the chain.')
  },
})
```

#### 中间件生命周期

每个扩展都会“包装”下一个扩展，因此你可以在事务由链中其余部分（以及编辑器本身）处理前后执行代码。

```typescript
dispatchTransaction({ transaction, next }) {
  // 1. Pre-processing: Code before next()
  const start = performance.now()

  next(transaction)

  // 2. Post-processing: Code after next()
  const end = performance.now()
  console.log(`Dispatch took ${end - start}ms`)
}
```

### `addProseMirrorPlugins`

你可以向扩展添加 ProseMirror 插件。如果想通过 ProseMirror 插件扩展编辑器，这会很有用。

#### 使用现有的 ProseMirror 插件

如下例所示，你可以将现有的 ProseMirror 插件封装在 Tiptap 扩展中。

```typescript
import { history } from '@tiptap/pm/history'

const History = Extension.create({
  addProseMirrorPlugins() {
    return [
      history(),
      // …
    ]
  },
})
```

#### 创建 ProseMirror 插件

你也可以创建自定义 ProseMirror 插件。下面是一个自定义插件示例，它会向控制台输出一条消息。

```typescript
import { Plugin, PluginKey } from '@tiptap/pm/state'
import { Extension } from '@tiptap/core'

const CustomExtension = Extension.create({
  name: 'customExtension',

  addProseMirrorPlugins() {
    return [
      new Plugin({
        key: new PluginKey('customPlugin'),
        view() {
          return {
            update() {
              console.log('Custom plugin updated')
            },
          }
        },
      }),
    ]
  },
})
```

想进一步了解 ProseMirror 插件，请参阅 [ProseMirror 文档](https://prosemirror.net/docs/ref/#state.Plugin)。

### `addDecorations`

`addDecorations` 方法会向编辑器添加[装饰](/editor/core-concepts/decorations)。装饰可用于高亮、搜索结果和小型控件。它们会改变用户看到的内容，但不会更改已保存的文档。

使用从 `@tiptap/core` 导入的 `Decoration` 类来创建装饰：

```ts
import { Decoration, Extension } from '@tiptap/core'

const MyExtension = Extension.create({
  name: 'myExtension',

  addDecorations() {
    return {
      create: ({ editor, state, view }) => [Decoration.Inline(1, 5, { class: 'highlight' })],
    }
  },
})
```

`Decoration` 类有三个静态方法：`Decoration.Node`（节点 DOM 包装器上的属性）、`Decoration.Inline`（覆盖某个范围的样式化 span）和 `Decoration.Widget`（位于某个位置的 DOM 节点或框架组件）。对于大型文档，你可以使用 `shouldUpdate` 控制是否重新计算，或通过 `update: 'changedRanges'` 仅重建已编辑的块。你也可以随时使用 `editor.commands.updateDecorations()` 强制完整重建。

<Callout title="装饰适用于仅影响视图的标记" variant="info">
  标记纯粹用于视觉展示时，请使用 `addDecorations`。如果需要持久化的自定义文档内容或可编辑的自定义块，请改用[节点视图](/editor/extensions/custom-extensions/node-views)。
</Callout>

阅读[装饰指南](/editor/core-concepts/decorations)，了解三种装饰及性能优化策略；参阅 [Vanilla JS](/guides/decorations-vanilla)、[React](/guides/decorations-react) 或 [Vue 3](/guides/decorations-vue) 教程；并使用[装饰 API 参考](/editor/api/decorations)查看所有签名。

### `addGlobalAttributes`

`addGlobalAttributes` 方法用于添加可同时应用于多个扩展的属性。它适用于文本对齐、行高或其他样式相关属性，这些属性通常需要在多种节点和标记类型中使用。

你可以指定 `types` 属性，控制哪些扩展会接收该属性：

- `types: ['heading', 'paragraph']` - 应用于指定的类型名称
- `types: '*'` - 应用于所有节点类型（内置 text 节点除外）和所有标记类型
- `types: 'nodes'` - 应用于所有节点类型（内置 text 节点除外）
- `types: 'marks'` - 应用于所有标记类型

下面的示例将属性应用于特定类型：

```typescript
const TextAlign = Extension.create({
  name: 'textAlign',

  addGlobalAttributes() {
    return [
      {
        types: ['heading', 'paragraph'],
        attributes: {
          textAlign: {
            default: 'left',
            renderHTML: (attributes) => ({
              style: `text-align: ${attributes.textAlign}`,
            }),
            parseHTML: (element) => element.style.textAlign || 'left',
          },
        },
      },
    ]
  },
})
```

如需了解所有选项（包括字符串简写语法），请参阅[应用全局属性](/editor/extensions/custom-extensions/extend-existing#apply-global-attributes-to-all-extensions)指南。

### `addExtensions`

你可以向扩展中添加更多扩展。如果想创建一组相互关联的扩展，这会很有用。

```typescript
import { Extension } from '@tiptap/core'
import CustomExtension1 from './CustomExtension1'

const CustomExtension = Extension.create({
  name: 'customExtension',

  addExtensions() {
    return [
      CustomExtension1.configure({
        name: 'customExtension1',
      }),
    ]
  },
})
```

### `extendNodeSchema`

你可以使用 `extendNodeSchema` 方法扩展编辑器的 NodeConfig。如果想向节点 schema 添加额外属性，这会很有用。

```typescript
import { Extension } from '@tiptap/core'

declare module '@tiptap/core' {
  // This adds a new configuration option to the NodeConfig

const CustomExtension = Extension.create({
  name: 'customExtension',
```

## 这里有哪些可用内容？

这些扩展不是类，但在扩展的任何位置，你都可以通过 `this` 访问一些重要内容。

```js
// Name of the extension, for example 'bulletList'
this.name

// Editor instance
this.editor

// ProseMirror type (if a node or mark)
this.type

// Object with all settings
this.options

// Everything that’s in the extended extension
this.parent

// Storage object
this.storage
```
