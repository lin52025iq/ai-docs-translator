## 设置

### document

已初始化的 Y.js 文档。

默认值：`null`

```js
Collaboration.configure({
  document: new Y.Doc(),
})
```

### field

Y.js 片段的名称，可更改此项以使用一个 Y.js 文档同步多个字段。

默认值：`'default'`

```js
Collaboration.configure({
  document: new Y.Doc(),
  field: 'title',
})
```

### fragment

原始 Y.js 片段，可替代 `document` 和 `field` 使用。

默认值：`null`

```js
Collaboration.configure({
  fragment: new Y.Doc().getXmlFragment('body'),
})
```

## 命令

`Collaboration` 扩展自带历史记录扩展。如果你使用 `StarterKit`，请务必禁用 `UndoRedo` 扩展。

### undo()

撤销上一次更改。

```js
editor.commands.undo()
```

### redo()

重做上一次更改。

```js
editor.commands.redo()
```

## 不符合 Schema 的内容

共享文档可能包含编辑器 Schema 无法显示的内容，例如来自未注册扩展的节点。该扩展有以下两种处理方式：

- 默认情况下，编辑器会移除此类内容，并补全缺失的必需节点。这些更改会同步，因此其他用户也会丢失这些内容。
- 将编辑器选项 `enableContentCheck: true` 启用后，编辑器会在共享文档中保留这些内容。它会尽可能显示内容、暂停编辑且不发送任何更改。编辑器会触发 `contentError` 事件，并在内容再次符合 Schema 后恢复。请通过 `onContentError` 处理该事件，因为默认处理程序会抛出错误。此功能需要 `@tiptap/extension-collaboration` 3.33.0 和 `@tiptap/y-tiptap` 3.2.0 或更高版本。

更多信息请参阅[无效 Schema 的处理](/guides/invalid-schema#for-collaborative-editing)。

## 与 UniqueID 搭配使用

如果你将 [UniqueID 扩展](/editor/extensions/functionality/uniqueid) 与 Collaboration 一起使用，请确保仅在协作提供程序完成同步后挂载编辑器。初始化顺序不正确可能导致文档中持续出现空段落。详情请参阅 [UniqueID：与 Collaboration 搭配使用](/editor/extensions/functionality/uniqueid#usage-with-collaboration)。
