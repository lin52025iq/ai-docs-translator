你是否曾想在编辑器中拖动节点？我们也想过，所以为此推出了这个扩展。

`DragHandle` 扩展让你可以轻松地在编辑器中拖动节点。你可以自定义渲染函数、位置等。

<CodeDemo path="/Extensions/DragHandle" />

## 安装

```bash
npm install @tiptap/extension-drag-handle
```

## 设置

### render

使用 floating-ui/dom 包渲染一个定位元素。拖动节点时，该元素会显示为拖拽手柄。

```js
DragHandle.configure({
  render: () => {
    const element = document.createElement('div')

    // Use as a hook for CSS to insert an icon
    element.classList.add('custom-drag-handle')

    return element
  },
})
```

### computePositionConfig

使用 floating-ui/dom 包计算拖拽手柄位置的配置。你可以传入 [floating-ui 文档](https://floating-ui.com/docs/computePosition)中提供的任意选项。

默认值：`{ placement: 'left-start', strategy: 'absolute' }`

```js
DragHandle.configure({
  computePositionConfig: {
    placement: 'left',
    strategy: 'fixed',
  },
})
```

### getReferencedVirtualElement

返回拖拽手柄虚拟元素的函数。如果需要相对于特定 DOM 元素定位菜单，这个函数会很有用。

默认值：`undefined`

```js
DragHandle.configure({
  getReferencedVirtualElement: () => {
    // Return a virtual element for custom positioning
    return null
  },
})
```

### locked

锁定拖拽手柄的位置和可见状态。如果拖拽手柄当前可见，它会一直保持可见，直到解除锁定；如果当前隐藏，则会一直保持隐藏，直到解除锁定。

默认值：`false`

```js
DragHandle.configure({
  locked: true,
})
```

### onNodeChange

当鼠标悬停在节点上时，返回该节点或 `null`。你可以用它高亮当前悬停的节点。

默认值：`undefined`

```js
DragHandle.configure({
  onNodeChange: ({ node, editor, pos }) => {
    if (!node) {
      selectedNode = null
      return
    }
    // Do something with the node
    selectedNode = node
  },
})
```

### onElementDragStart

元素开始被拖动时调用的函数。你可以在拖动开始时添加自定义逻辑。

签名：`(event: DragEvent) => void`

默认值：`undefined`

```js
DragHandle.configure({
  onElementDragStart: (event) => {
    // do something when dragging starts
  },
})
```

### onElementDragEnd

元素停止被拖动时调用的函数。你可以在拖动结束时添加自定义逻辑。

签名：`(event: DragEvent) => void`

默认值：`undefined`

```js
DragHandle.configure({
  onElementDragEnd: (event) => {
    // do something when dragging ends
  },
})
```

### nested

为列表项、引用块和其他嵌套结构等内容启用拖拽手柄。

启用后，拖拽手柄不仅会出现在顶层区块，也会显示在嵌套区块上。系统会根据光标位置和配置的规则，通过基于规则的评分来确定目标节点。

默认值：`false`

```js
// Enable with defaults
DragHandle.configure({
  nested: true,
})

// Enable with custom edge detection
DragHandle.configure({
  nested: {
    edgeDetection: {
      threshold: 20,
    },
  },
})
```

详细配置选项请参阅下文的[嵌套拖拽手柄](#nested-drag-handle)部分。

## 命令

### lockDragHandle()

锁定拖拽手柄的位置和可见状态。如果拖拽手柄当前可见，它会一直保持可见，直到解除锁定；如果当前隐藏，则会一直保持隐藏，直到解除锁定。

如果你想在拖拽手柄中放置菜单，并希望无论鼠标是否悬停在拖拽手柄上，菜单都保持可见，此命令会很有用。

```js
editor.commands.lockDragHandle()
```

### unlockDragHandle()

解除拖拽手柄的锁定，并将其恢复为默认的可见状态和行为。

```js
editor.commands.unlockDragHandle()
```

### toggleDragHandle()

切换拖拽手柄的锁定状态。如果拖拽手柄已锁定，则解除锁定；反之亦然。

```js
editor.commands.toggleDragHandle()
```

## 嵌套拖拽手柄

默认情况下，拖拽手柄只会出现在顶层区块上。启用 `nested` 后，它也会应用于列表项、引用块段落和其他嵌套结构等内容。

### 基本用法

```js
// Enable with all defaults
DragHandle.configure({
  nested: true,
})
```

### 配置选项

如需更精细地控制，可以传入一个选项对象：

```js
DragHandle.configure({
  nested: {
    // Edge detection configuration
    edgeDetection: 'left', // or 'right', 'both', 'none', or custom config

    // Custom rules for node selection
    rules: [],

    // Whether to use default rules
    defaultRules: true,

    // Restrict to specific container types
    allowedContainers: ['bulletList', 'orderedList'],
  },
})
```

### 边缘检测

边缘检测控制何时优先选择父节点而不是嵌套节点。当光标靠近内容区域边缘时，通常希望选中父容器，而不是其中的嵌套内容。

#### 预设

```js
DragHandle.configure({
  nested: {
    // 'left' (default) - Prefer parent near left/top edges
    edgeDetection: 'left',

    // 'right' - Prefer parent near right/top edges (for RTL layouts)
    edgeDetection: 'right',

    // 'both' - Prefer parent near any horizontal edge
    edgeDetection: 'both',

    // 'none' - Disable edge detection entirely
    edgeDetection: 'none',
  },
})
```

#### 自定义配置

如需精细控制，可以传入一个配置对象：

```js
DragHandle.configure({
  nested: {
    edgeDetection: {
      // Which edges trigger parent preference
      edges: ['left', 'top'],

      // Distance in pixels from edge to trigger (default: 12)
      threshold: 20,

      // How strongly to prefer parent (default: 500)
      strength: 500,
    },
  },
})
```

你也可以传入部分配置，只覆盖指定值并保留其他默认值：

```js
DragHandle.configure({
  nested: {
    // Only override threshold, keep default edges and strength
    edgeDetection: { threshold: -16 },
  },
})
```

#### strength 的作用方式

`strength` 值控制光标靠近边缘时系统优先选择父节点的程度。它与评分系统配合使用：

1. 每个候选节点的初始基础分为 **1000**。
2. 光标靠近已配置的边缘时，扣分值按以下公式计算：`strength × depth`。
3. 选择剩余分数最高的节点。

默认 `strength` 值为 **500**：

| 节点深度 | 扣分 | 剩余分数 | 效果 |
|------------|-----------|-----------------|--------|
| 1（较浅） | 500 | 500 | 仍可选中，但优先级降低 |
| 2 | 1000 | 0 | 几乎无法选中，会输给不在边缘的节点 |
| 3+（较深） | 1500+ | 负数 | 实际上会被排除 |

这意味着，光标靠近边缘时，越深层的嵌套节点优先级降低得越明显，因此更容易选中其父容器。

**示例：**
- `strength: 250` - 优先级调整较温和；即使光标靠近边缘，深度为 3 的节点仍有一定机会被选中。
- `strength: 500` - 默认值；光标靠近边缘时，深度为 2 或更深的节点优先级会大幅降低。
- `strength: 1000` - 调整较强；光标靠近边缘时，任何嵌套节点实际上都会被排除。

<Callout title="负阈值" variant="info">
  使用负阈值（例如 `-16`）会有效缩小触发边缘检测的区域，因此即使光标靠近边缘，也更容易选中嵌套项。光标需要进一步移入元素内部，边缘检测才会触发。
</Callout>

### 允许的容器

将嵌套拖拽手柄限制在特定容器类型中：

```js
DragHandle.configure({
  nested: {
    // Only enable nested dragging inside lists
    allowedContainers: ['bulletList', 'orderedList'],
  },
})
```

设置此项后，拖拽手柄只会出现在指定容器类型内部的嵌套内容上。无论此设置如何，顶层区块始终可以拖动。

### 自定义规则

拖拽手柄使用评分系统来确定要选中的节点。每个候选节点的初始分数为 1000，规则会修改该分数。最终分数最高的节点将被选中。

#### 创建自定义规则

```js
DragHandle.configure({
  nested: {
    rules: [
      {
        id: 'preferParagraphs',
        evaluate: ({ node, parent, depth }) => {
          // Return a score modifier:
          // - Negative: Boost the node's score (more likely to be selected)
          // - 0: No change, node remains at current score
          // - 1-999: Deduction, node is less preferred
          // - >= 1000: Node is effectively excluded

          if (node.type.name === 'paragraph') {
            return -200 // Boost paragraphs by 200 points
          }
          return 100 // Small penalty for other nodes
        },
      },
    ],
  },
})
```

#### 评分调整值说明

| 返回值 | 效果 | 示例用途 |
|--------------|--------|------------------|
| `-500` | 加 500 分 | 强烈优先选择此节点类型 |
| `-100` | 加 100 分 | 略微优先选择此节点 |
| `0` | 不变 | 节点保持中立 |
| `100` | 减 100 分 | 略微降低优先级 |
| `500` | 减 500 分 | 大幅降低优先级 |
| `1000+` | 实际上排除 | 永不选择此节点 |

所有节点的初始分数都是 1000，因此加 200 分的节点最终得分为 1200，而扣 100 分的节点最终得分为 900。得分为 1200 的节点胜出。

#### 规则上下文

每条规则都会接收一个上下文对象，其中包含以下属性：

| 属性 | 类型 | 说明 |
|----------|------|-------------|
| `node` | `Node` | 正在评估的节点 |
| `pos` | `number` | 节点在文档中的绝对位置 |
| `depth` | `number` | 节点在文档树中的深度（0 = doc 根节点） |
| `parent` | `Node \| null` | 父节点（如果是 doc，则为 null） |
| `index` | `number` | 节点在同级节点中的索引（从 0 开始） |
| `isFirst` | `boolean` | 是否为第一个子节点 |
| `isLast` | `boolean` | 是否为最后一个子节点 |
| `$pos` | `ResolvedPos` | 供高级查询使用的解析后位置 |
| `view` | `EditorView` | 用于访问 DOM 的编辑器视图 |

#### 示例：自定义问题区块

如果你有一个包含选项的自定义问题区块，可能只希望选项可以拖动：

```js
DragHandle.configure({
  nested: {
    rules: [
      {
        id: 'onlyAlternatives',
        evaluate: ({ node, parent }) => {
          // Inside a question, only alternatives should be draggable
          if (parent?.type.name === 'question') {
            return node.type.name === 'alternative' ? 0 : 1000
          }
          return 0
        },
      },
    ],
  },
})
```

#### 构建自定义列表类节点

如果你创建的自定义节点行为类似列表（即容器中包含可拖动的子项），拖拽手柄需要相应指引，以便优先选择子项而不是容器。否则，用户可能难以选中单个子项。

默认规则会自动降低首个子节点为 `listItem` 或 `taskItem` 的节点的优先级。对于节点名称不同的自定义列表结构，你有两个选择：

**选项 1：将子项节点命名为 `listItem` 或 `taskItem`**

如果你的自定义子项扩展了标准列表项，或行为与标准列表项相同，可以考虑使用相同的类型名称。默认规则会自动处理。

**选项 2：添加自定义规则以降低容器的优先级**

对于使用自定义节点名称的情况，可以添加一条规则来扣减容器的分数：

```js
DragHandle.configure({
  nested: {
    rules: [
      {
        id: 'deprioritizeCustomListWrapper',
        evaluate: ({ node }) => {
          // Deprioritize the wrapper so child items are easier to select
          if (node.type.name === 'myCustomList') {
            return 900
          }
          return 0
        },
      },
    ],
  },
})
```

**自定义列表类节点的样式注意事项：**

为自定义列表容器设置足够的内边距或外边距，有利于边缘检测正常工作。这样，用户既可以在需要时（将光标移到边缘）选中容器本身，也可以轻松选中主要内容区域中的单个子项。

```css
.my-custom-list {
  /* Provide space for edge detection to distinguish wrapper from items */
  padding: 0.5rem;
}

.my-custom-list-item {
  /* Space between items for easier targeting */
  margin: 0.25rem 0;
  padding-left: 0.5rem;
}
```

#### 禁用默认规则

如果你想完全控制节点选择，可以禁用默认规则：

```js
DragHandle.configure({
  nested: {
    defaultRules: false,
    rules: [
      // Your custom rules here
    ],
  },
})
```

<Callout title="默认规则" variant="warning">
  默认规则会处理常见情况，例如排除行内内容并正确处理列表项。只有在有特定需求且了解其影响时，才应禁用默认规则。
</Callout>

### 样式注意事项

为了让嵌套拖拽手柄正常工作，可能需要调整编辑器样式。拖拽手柄需要一定的实际空间才能显示，边缘检测阈值也需要有足够的空间才能生效。

#### 增加左侧外边距或内边距

拖拽手柄位于内容左侧。如果外边距不足，它可能会与文本重叠，或显示在可视区域之外：

```css
.ProseMirror {
  /* Leave space for the drag handle on the left */
  padding-left: 2rem;
}

/* Or use margin on direct children */
.ProseMirror > * {
  margin-left: 2rem;
}
```

#### 嵌套内容间距

对于列表项等嵌套元素，请确保缩进足够，使拖拽手柄能在每个嵌套层级显示：

```css
.ProseMirror ul,
.ProseMirror ol {
  /* Provide space for nested drag handles */
  padding-left: 1.5rem;
}

.ProseMirror li {
  /* Additional spacing if needed */
  margin-left: 0.5rem;
}
```

#### 边缘检测与阈值

边缘检测中的 `threshold` 值以像素为单位，从元素边缘开始计算。如果内容没有内边距，阈值为 12px 就意味着光标必须位于距离实际文本 12px 的范围内。在内容区域添加内边距，能让边缘检测更加自然：

```css
.ProseMirror blockquote {
  /* Padding gives the edge detection room to breathe */
  padding: 0.5rem 1rem;
}

.ProseMirror li > p {
  /* Even small padding helps with edge detection */
  padding-left: 0.25rem;
}
```

#### 示例：完整的嵌套拖拽手柄样式

```css
.ProseMirror {
  /* Base padding for drag handle space */
  padding: 1rem 1rem 1rem 3rem;
}

.ProseMirror > * {
  /* Consistent left margin for top-level blocks */
  margin-left: 0;
}

.ProseMirror ul,
.ProseMirror ol {
  /* List indentation */
  padding-left: 1.5rem;
}

.ProseMirror li {
  /* Space between list marker and content */
  padding-left: 0.25rem;
}

.ProseMirror blockquote {
  /* Blockquote padding for comfortable dragging */
  padding: 0.5rem 1rem;
  margin-left: 0;
  border-left: 3px solid #ccc;
}

/* Selection highlight for dragged nodes */
.ProseMirror-selectednode,
.ProseMirror-selectednoderange {
  position: relative;
}

.ProseMirror-selectednode::before,
.ProseMirror-selectednoderange::before {
  content: '';
  position: absolute;
  inset: -0.25rem;
  background-color: rgba(112, 207, 248, 0.3);
  border-radius: 0.2rem;
  pointer-events: none;
  z-index: -1;
}
```

<Callout title="负阈值" variant="info">
  如果无法添加内边距，可以使用负的 `threshold` 值（例如 `-16`）来缩小边缘检测区域。这样系统就不容易优先选择父节点，即使光标靠近边缘，也能选中嵌套项。
</Callout>
