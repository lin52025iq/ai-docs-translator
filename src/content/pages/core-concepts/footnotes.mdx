脚注可以让读者为文本添加编号注释，并像 Microsoft Word 一样将其显示在页面底部、页脚上方。每条脚注都通过正文中的上标引用标记锚定。脚注区域会占用页面的部分可用空间，因此页面上的脚注越多，正文可用空间就越少。

脚注始终与其引用标记保持在一起：如果编辑导致引用文本移至另一页，脚注也会自动移至该页的脚注区域。

<Callout title="想了解尾注？" variant="hint">
  汇集在文档末尾单个列表中的注释称为[尾注](/pages/core-concepts/endnotes)。脚注和尾注彼此独立，可以在同一文档中同时使用。
</Callout>

<Callout title="从 DOCX 导入" variant="hint">
  使用 [DOCX 导入扩展](/conversion/import/docx/editor-extension#footnotes--endnotes)导入 `.docx` 文件时，文档中的脚注会自动应用到 Pages：包括引用标记、内容和编号。无需额外配置。
</Callout>

## 启用脚注

脚注默认处于禁用状态。通过 `footnotes` 选项组启用：

```js
import { Pages } from '@tiptap-pro/extension-pages'

Pages.configure({
  pageFormat: 'A4',
  footer: 'Page {page} of {total}',
  footnotes: {
    enabled: true,
  },
})
```

这样就可以了：脚注引用节点会自动注册，只要文档中包含脚注，每页的脚注区域就会随之显示。

## 脚注的行为方式

其工作方式与 Microsoft Word 一致：

- **一个标记对应一条脚注。** 每条脚注都是正文中的一个上标数字，并与包含该标记的页面脚注区域中的编号条目相对应。
- **脚注位于页脚上方。** 每页都会显示自己的脚注区域，正文内容与页脚之间有一条短分隔线。
- **脚注会占用页面空间。** 脚注区域会随内容增多而扩展，正文区域则相应缩小。因此，在已排满内容的页面中添加脚注，会将正文推至下一页。
- **脚注跟随其引用标记。** 每页的脚注区域只显示标记位于该页的脚注。文本在页面间重新排版时，脚注也会随之移动；无需手动管理脚注位置。
- **编号自动连续。** 脚注按文档顺序编号为 `1, 2, 3…`。在现有两条脚注之间插入新脚注后，后续脚注会全部重新编号；删除脚注后，编号间的空缺会自动补齐。编号是动态计算的，不会存储，因此始终准确。

## 插入脚注

调用 `insertFootnote()` 可在当前选区插入脚注：

```js
editor.commands.insertFootnote()
```

此命令会在选区**之后**插入引用标记（与 Word 一样，选中的文本会保留），创建一条空脚注，并打开脚注编辑器，将光标置于新脚注内，方便用户立即输入内容。

```jsx
<button onClick={() => editor.commands.insertFootnote()}>插入脚注</button>
```

## 编辑脚注

用户可以直接双击页面的脚注区域来编辑脚注。这会打开一个功能完整、作用范围限定在该页面的 Tiptap 编辑器：编辑器按编号顺序显示属于该页的脚注，每条脚注都可以像普通富文本一样编辑。双击某条脚注即可将光标置于其中。

按 <kbd>Escape</kbd>、点击关闭按钮或双击编辑器外部即可关闭编辑器。脚注编辑器打开时，主文档编辑器会暂时变为不可编辑，行为与页眉和页脚编辑器相同。

### 自定义扩展

脚注编辑器默认使用 `ConvertKit`。通过 `footnotes.extensions` 传入自己的扩展集合，以确保其 schema 与主编辑器一致：

```ts
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'

Pages.configure({
  footnotes: {
    enabled: true,
    extensions: [ConvertKit.configure({ table: false })],
  },
})
```

<Callout title="协作功能需使用回调形式" variant="info">
  `footnotes.extensions` 也接受 `(ctx) => Extensions` 回调，并会接收脚注编辑器应绑定的 Y 字段名称和 Y.Doc。配置协作功能时请使用此形式。请参阅下文的[脚注与协作](#脚注与协作)。
</Callout>

### 活动编辑器状态

脚注编辑器打开时，扩展会通过 storage 暴露该编辑器，方式与页眉和页脚相同，因此统一工具栏可以同时适用于三者：

- `activeEditor` – 已打开的脚注编辑器的 Tiptap Editor 实例（或 `null`）
- `activeEditorType` – 编辑脚注时为 `'footnotes'`（以及现有的 `'header'`、`'footer'` 和 `null` 值）
- `activePageNumber` – 当前正在编辑脚注的页面
- `footnotesEditorOn` / `footnotesEditorOff` – 订阅或取消订阅脚注编辑器上的事件

```tsx
useEffect(() => {
  if (!editor) return

  const syncActiveEditorState = () => {
    const { activeEditor, activeEditorType } = editor.storage.pages
    // 脚注编辑器打开时，activeEditorType === 'footnotes'
  }

  editor.on('update', syncActiveEditorState)
  return () => {
    editor.off('update', syncActiveEditorState)
  }
}, [editor])
```

如需查看会跟随当前焦点编辑器的完整自定义工具栏示例，请参阅[页眉和页脚 → 构建自定义工具栏](/pages/core-concepts/page-header-footer#building-a-custom-toolbar)。要为其添加脚注支持，只需处理 `activeEditorType` 的额外值 `'footnotes'`。

脚注浮层标签及其关闭按钮可以通过 `overlayLabels` 翻译。请参阅[翻译浮层标签](/pages/core-concepts/page-header-footer#translating-overlay-labels)。

### 锁定脚注

将 `footnotes.editable` 设为 `false`，即可显示脚注但禁用双击编辑；也可以在运行时切换：

```js
Pages.configure({
  footnotes: { enabled: true, editable: false },
})

// 运行时
editor.commands.setFootnotesEditable(false) // 锁定
editor.commands.setFootnotesEditable(true) // 解锁
```

锁定后，脚注仍会正常显示，只是无法编辑。`openFootnoteEditor` 会返回 `false`，双击不会产生作用，已打开的脚注编辑器也会关闭。

### 防止双击时关闭

与页眉和页脚编辑器一样，可以在用户双击其外部时保持脚注编辑器打开。如果工具栏位于编辑器之外，这会很有用：

```js
Pages.configure({
  footnotes: { enabled: true },
  onDblClickFootnotesPreventClose: (event) => {
    const toolbar = document.querySelector('.my-toolbar')
    return toolbar?.contains(event.target)
  },
})
```

如果未提供脚注专用回调，通用回调 `onDblClickHeaderFooterPreventClose` 会作为备用回调。

### 以编程方式打开和关闭

```js
// 打开第 2 页的脚注编辑器
editor.commands.openFootnoteEditor({ pageNumber: 2 })

// 打开编辑器，并将光标置于指定脚注中
editor.commands.openFootnoteEditor({ pageNumber: 2, focusNoteId: '3' })

// 关闭编辑器
editor.commands.closeFootnoteEditor()
```

如果脚注已禁用、已锁定或页面上没有脚注，`openFootnoteEditor` 会返回 `false`。

## 删除脚注和清理

从正文中删除引用标记后，相应脚注会立即从页面移除，其余脚注也会重新编号。脚注的**内容会在后台保留**，因此执行普通撤销操作时，引用标记及其文本会一起恢复。这是为了确保可以安全撤销，特意采用了不同于 Word 的行为（Word 会立即删除脚注内容）。

如果需要永久丢弃已没有引用标记的内容，请调用：

```js
editor.commands.cleanupOrphanFootnotes()
```

至少移除一条孤立脚注时，此命令会返回 `true`。

## 复制和粘贴

复制包含脚注标记的文本并粘贴到其他位置时，会像 Word 一样复制脚注：粘贴后的标记会拥有自己的脚注，内容是原脚注的副本，整个文档中的编号也会更新。从此以后，两条脚注互相独立。

## 没有内容的引用标记

引用标记始终会生成可见脚注，即使它暂时没有对应内容（例如，通过包含标记但尚未提供脚注内容的文档调用 `setContent()` 后）。此类脚注会显示为空的编号条目；打开脚注编辑器后即可立即编辑。

## 从标记跳转

点击正文中的脚注标记会滚动页面，使对应脚注显示出来，这在较长的文档中很方便。

## 屏幕阅读器名称

Pages 会为正文中的每个脚注标记提供屏幕阅读器名称，例如“脚注 3”。页面上的标记仍只显示数字。设置 `noteReferenceLabel` 可以更改名称，例如将其翻译：

```ts
Pages.configure({
  footnotes: { enabled: true },
  noteReferenceLabel: ({ type, number }) =>
    type === 'footnote'
      ? t('pages.footnoteReference', { number })
      : t('pages.endnoteReference', { number }),
})
```

`noteReferenceLabel` 是顶层选项，也可以为[尾注标记](/pages/core-concepts/endnotes#screen-reader-names)命名。该函数会接收一个对象，其中包含：

- `type`：`'footnote'` 或 `'endnote'`。
- `number`：注释的编号，从 1 开始，按文档顺序计数。
- `marker`：读者看到的标记文本。脚注使用数字，尾注使用罗马数字。

添加、删除或重新排序注释时，Pages 会更新这些名称。这些名称只存在于编辑器视图中，因此 `getHTML()`、`getJSON()` 和 DOCX 导出内容中都不包含它们。

Pages 会将名称作为标记的 CSS 替代文本传递给屏幕阅读器。如果自定义 CSS 替换了 `.tiptap-footnote-ref::after` 的 `content`，请使用 `content: attr(data-footnote-number) / attr(data-footnote-label)` 保留名称。

脚注浮层标签有单独的选项。请参阅[翻译浮层标签](/pages/core-concepts/page-header-footer#translating-overlay-labels)。

## 配置

所有脚注设置都位于 `footnotes` 选项组中：

```ts
Pages.configure({
  footnotes: {
    enabled: true, // 总开关（默认值：false）
    extensions: [ConvertKit], // 编辑器扩展（或支持协作的回调）
    initialContent: undefined, // 初始内容，以注释 ID 为键
    separator: true, // 区域上方的短分隔线（默认值：true）
    maxHeightRatio: 0.5, // 页面内容高度的最大占比（默认值：0.5）
    editable: true, // 双击编辑（默认值：true）
    accentColor: '#6366f1', // 脚注编辑器强调色（默认使用 accentColor）
  },
})
```

### 设置初始内容

`initialContent` 接受以注释 ID 为键的脚注内容。每个 ID 都应与文档内容中 `footnoteReference` 节点的 `noteId` 属性相匹配。值为 Tiptap `JSONContent` 文档：

```js
Pages.configure({
  footnotes: {
    enabled: true,
    initialContent: {
      1: {
        type: 'doc',
        content: [
          {
            type: 'paragraph',
            content: [{ type: 'text', text: '第一条脚注。' }],
          },
        ],
      },
    },
  },
})
```

这与 [DOCX 导入 REST API](/conversion/import/docx/rest-api) 在 `footnotes` 字段中返回的数据结构完全相同，因此可以直接使用服务器导入的文档来设置初始内容。

<Callout title="协作" variant="info">
  `initialContent` 仅在**未启用**协作时生效。在协作文档中，脚注内容由共享文档管理。如需通过明确的用户操作将脚注载入协作文档（例如 DOCX 导入后），请改用 `setFootnotes` 命令。
</Callout>

### 分隔线

Word 会在正文与脚注之间绘制一条短水平线。该选项默认启用；设置 `separator: false` 即可将其关闭。

### 区域最大高度

`maxHeightRatio` 限制脚注区域最多可占页面内容高度的比例（默认值为 `0.5`，即页面的一半）。脚注超出此上限时，区域内容会被裁切。关于这一点与 Word 的差异，请参阅[不支持的行为](#what-not-to-expect)。

### 强调色

脚注编辑器默认使用共享的 `accentColor`；可以通过 `footnotes.accentColor` 覆盖，或在运行时设置：

```js
editor.commands.setFootnotesAccentColor('#10b981')
```

强调色会应用于正文中的标记颜色、光标、编辑器工具栏边框以及“脚注 – 第 N 页”标签。

## 访问脚注内容

脚注内容会以注释 ID 为键，存放在 `editor.storage.pages` 中：

```js
// 每条脚注对应的 Tiptap JSON，可用于持久化和 DOCX 导出
const footnotesJSON = editor.storage.pages.footnotesJSON
// { '1': { type: 'doc', content: [...] }, 'fn-abc123': { ... } }

// 每条脚注对应的渲染后 HTML，与页面预览一致
const footnotesHTML = editor.storage.pages.footnotesHTML

// 当前编号（注释 ID → 从 1 开始的编号）
const numbers = editor.storage.pages.footnoteNumbers
```

### 保存和恢复

与页眉和页脚一样，脚注内容需要由你负责持久化。将 `footnotesJSON` 与文档一同保存，并在加载内容后使用 `setFootnotes` 命令恢复：

```js
// 保存
await saveDocument({
  content: editor.getJSON(),
  footnotes: editor.storage.pages.footnotesJSON,
})

// 恢复
editor.commands.setContent(savedDocument.content)
editor.commands.setFootnotes(savedDocument.footnotes)
```

`setFootnotes` 会根据 ID → 文档映射替换所有脚注内容。正文中的引用标记会根据 ID 匹配，因此仍可正常工作。

## DOCX 导入和导出

脚注开箱即支持与 Word 文档往返转换：

- **导入**：使用 [DOCX 导入编辑器扩展](/conversion/import/docx/editor-extension#footnotes--endnotes)时，导入文件中的脚注会自动应用：标记出现在正文中，内容放入页面区域，编号与源文档一致。导入上下文还会提供原始的 `footnotes` / `endnotes` 数据，方便你自行处理。
- **导出**：使用 [DOCX 导出编辑器扩展](/conversion/export/docx/editor-extension)时，脚注内容会从 Pages 自动提取，并作为真正的 Word 脚注写入：标记会成为有效的脚注引用，Word 会原生渲染并重新编号。

导入和导出两端都无需额外配置。在 Pages 旁安装导入/导出扩展，即可包含脚注。

## 脚注与协作

脚注会与主文档一起参与协作：多个用户可以实时看到彼此对脚注的修改，插入或删除脚注的操作也会在各客户端间保持一致，包括编号。

要启用此功能，请将 `footnotes.extensions` 设为一个**回调**，以便为脚注编辑器附加 `Collaboration` 扩展。其方式与页眉和页脚相同：

```ts
Pages.configure({
  footnotes: {
    enabled: true,
    extensions: (ctx) => {
      const base = [ConvertKit.configure({ undoRedo: false })]
      if (!ctx.isCollaborative || !ctx.ydoc) {
        return base
      }
      return [...base, Collaboration.configure({ document: ctx.ydoc, field: ctx.field })]
    },
  },
})
```

回调会接收预先计算出的 Y 字段名称（`ctx.field`）和父编辑器的 Y.Doc（`ctx.ydoc`）。有关完整的协作设置（包括页眉和页脚的相应配置方式），请参阅[为 Pages 添加协作功能](/pages/guides/collaboration-with-pages)。

## 支持的功能

- 类似 Word 的位置：脚注显示在包含其标记的页面底部、页脚上方，并带有分隔线。
- 自动连续编号，并会在每次插入、删除、粘贴和重新排版后更新。
- 脚注增多时，页面正文区域会缩小，因此分页会将脚注占用的空间计算在内。
- 支持使用你配置的扩展来编辑富文本脚注内容。
- 渲染后的脚注与编辑视图外观一致：字体排版、编号和间距均相同，包括用于垂直间距的空段落。
- DOCX 往返转换无需额外配置。

## 不支持的行为

- **脚注不会跨页续排。** 当页面脚注超出 `maxHeightRatio` 限制时，区域内容会被裁切，而不会像 Word 一样将溢出内容续排到下一页。
- **仅支持十进制编号。** 脚注会在整个文档中按 `1, 2, 3…` 连续编号。目前不支持每页重新编号以及其他格式（罗马数字、字母、符号）。
- **脚注中的表格不会导出。** 表格会在编辑器中渲染，但 Word 的脚注格式只接受段落，因此导出 DOCX 时会丢弃表格。

## 完整选项参考

除非另有说明，所有选项都位于 `Pages.configure()` 的 `footnotes` 键下。

| 选项                              | 类型                                                | 默认值              | 说明                                                                        |
| --------------------------------- | --------------------------------------------------- | ------------------- | --------------------------------------------------------------------------- |
| `enabled`                         | `boolean`                                           | `false`             | 脚注功能的总开关                                                            |
| `extensions`                      | `Extensions \| (ctx) => Extensions`                 | `ConvertKit`        | 脚注编辑器的扩展。协作功能请使用回调形式。                                  |
| `initialContent`                  | `Record<string, JSONContent>`                       | `undefined`         | 按注释 ID 设置的初始脚注内容（仅适用于非协作文档）                          |
| `separator`                       | `boolean`                                           | `true`              | 在区域上方渲染类似 Word 的分隔线                                            |
| `maxHeightRatio`                  | `number`                                            | `0.5`               | 脚注区域最多可占页面内容高度的比例                                          |
| `editable`                        | `boolean`                                           | `true`              | 双击区域是否打开脚注编辑器                                                  |
| `accentColor`                     | `string`                                            | `accentColor` 值    | 标记和脚注编辑器的强调色                                                    |
| `onDblClickFootnotesPreventClose` | `(event: MouseEvent) => boolean`（顶层选项）        | `undefined`         | 防止在外部双击时关闭脚注编辑器                                              |
| `noteReferenceLabel`              | `NoteReferenceLabel`（顶层选项）                    | `undefined`         | 每个脚注和尾注标记的屏幕阅读器名称                                          |

| `footnoteNumbers`    | `Record<string, number>`                      | 当前编号（注释 ID → 从 1 开始的编号）                              |

| `editableFootnotes`  | `boolean`                                     | 是否已解锁编辑（只读；请使用 `setFootnotesEditable`）              |
| `activeEditorType`   | `'header' \| 'footer' \| 'footnotes' \| null` | 脚注编辑器打开时为 `'footnotes'`                                    |
| `footnotesEditorOn`  | `Editor['on'] \| null`                        | 预先绑定的脚注编辑器事件订阅函数                                   |
| `footnotesEditorOff` | `Editor['off'] \| null`                       | 预先绑定的脚注编辑器事件取消订阅函数                               |
