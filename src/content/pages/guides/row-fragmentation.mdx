如果表格行无法放入本页剩余空间，它就会整行移到下一页，导致页面底部留下空白。高于整页的行则完全无法放置。

Word 不会这样处理。它会拆分表格行，并在下一页继续显示。行拆分可以实现同样的效果。从 DOCX 导入的文档通常包含这样的表格行，因此实际内容中也会出现页面空白。

<Callout title="实验性功能" variant="warning">
  行拆分目前是实验性功能，默认关闭。选项名以 `experimental` 开头，
  是因为其行为和选项本身仍可能发生变化。
</Callout>

## 启用

```ts
import { TableKit } from '@tiptap-pro/extension-pages-tablekit'

TableKit.configure({ experimentalRowFragmentation: true })
```

关闭此选项时，不会有任何变化，也不会加载该插件。

如果你自行构建表格套件而不使用 `TableKit`，请直接配置 `TableRow`。它包含了此功能的全部内容：

```ts
import { TableRow } from '@tiptap-pro/extension-pages-tablekit'

TableRow.configure({ experimentalRowFragmentation: true })
```

你也可以通过 [PageKit](/pages/guides/pagekit-usage) 传入此选项：

```ts
PageKit.configure({
  table: { experimentalRowFragmentation: true },
})
```

## 文档不会改变

表格行仍然是一行。拆分只会改变表格行的绘制方式。

- 拆分前后，`editor.getJSON()` 返回的都是同一行。
- 不会创建 ProseMirror 步骤，因此协作功能不会感知到任何变化。
- DOCX 导出和打印得到的仍是普通表格行。

你可以在拆分后的表格行中输入内容、跨页选择内容，也可以调整列宽。编辑过程中，表格行会随之拆分和合并。

## 哪些表格行可以拆分

拆分位置必须在两行文字之间。是否可以拆分，取决于单元格内容的实际渲染方式，而不是节点类型列表，因此你自己的自定义节点无需在任何地方注册也能正常使用。

实际使用中，如果单元格包含段落、标题、项目符号列表或有序列表、嵌套列表、引用块、代码块或图片等行内内容，表格行就可以拆分。编号会在分页后继续，图片则会完整移到下一页，而不会被截断。

含有合并单元格的表格行也可以按相同方式拆分，包括被合并单元格覆盖的那些行。合并单元格会延续到下一页。

嵌套表格会在其行之间拆分。能放入一页的嵌套行会整行移到下一页。高于一页的嵌套行，只要自身可以拆分，就会在与外层行相同的位置拆分。如果不能拆分，外层行也会保持完整，具体如下文所述。

在以下情况下，Pages 不会拆分表格行：

- 表格行的 `heightRule: "exact"`
- 单元格中的文本位于具有独立布局的盒子中，但嵌套表格行除外

这包括设置了 `display: flex`、`grid` 或 `flow-root` 的盒子、溢出内容被裁剪的盒子、多栏布局、设置了 `contain: layout` 的盒子或绝对定位的盒子。还包括高于一页且无法拆分的嵌套行，例如设置了 `heightRule: "exact"` 的行。

无法拆分的表格行会像现在一样处理：整行移到下一页。

<Callout title="任务列表是个意外情况" variant="hint">
  任务列表项在文档中看起来像普通列表项，但实际渲染为 flex 容器，分页符无法穿过它。包含任务列表项的表格行不会被拆分。这就是为什么要根据渲染出的盒子，而不是节点类型来判断：仅看节点类型会得出错误结果。
</Callout>

## 拆分行的样式

PagesTableKit 只负责绘制布局，不会绘制边框，因此表格行跨页拆分处也不会出现分隔线。

如果表格带有边框，并且希望边框在分页处延续，可以在表格上设置一个自定义属性：

```css
.my-document table {
  --pages-tablekit-border-color: #d5d5d5;
}
```

单元格内边距来自 ConvertKit，它会通过 `--cell-margin-left` 和 `--cell-margin-right` 提供每个单元格的实际内边距。如果单元格内边距由其他方式设置，可以设置 `--pages-tablekit-cell-padding-x` 来覆盖两侧的值。

## 行元素由扩展负责管理

表格行拆分时，其 NodeView 会管理 `<tr>` 元素上的以下属性：

- `style`
- `data-height-rule`
- `data-pages-row-fragmentation`

不要在自己的代码中设置这些属性。NodeView 会在下一轮布局时再次写入它们，双方的写入会相互冲突。在指针下，这会表现为闪烁。

你可以读取这些属性。拆分后的表格行会带有 `data-pages-row-fragmentation="fragmented"`，其中的每个单元格会带有 `data-row-fragmentation-cell="fragmented"`，因此你可以在 CSS 中选取它们。

## 限制

- 表格行只能在文字行之间或嵌套表格行之间拆分。单元格中的任务列表项或类似盒子会使整行保持完整。
- 能放入一页的嵌套行不会拆分，而是整行移到下一页。
- 如果表格列宽保存为收缩状态，例如宽度为一个像素，表格可能会渲染到行的右边缘之外，此时该行不会拆分。这是列宽调整导致的，与行拆分无关。关闭此选项时也会发生这种情况。
- 此功能依赖 Pages 的[布局参与者](/pages/core-concepts/layout-participants)周期，因此需要使用提供该功能的 Pages 版本。

## 工作原理

表格行会注册为[布局参与者](/pages/core-concepts/layout-participants)。每次分页更新后，它会测量页面边缘的位置，然后在自己的单元格中相应位置插入空白块。浏览器自身的换行机制会将文本排布到这些空白块周围，从而实现拆分。

所有写入内容都存在于编辑器视图中，而非文档中。因此协作和导出不会受到影响。
