Pages 开箱即支持对**主文档正文**、**每个页眉/页脚子编辑器**以及**文档级页面几何设置**（页面格式、页面间距、页眉/页脚边距覆盖值）进行实时协作。每种页眉/页脚子类型（默认、首页、奇数页、偶数页）都有各自的 Y 字段，因此多位用户可以同时编辑，并实时看到远程更改同步到打开的编辑器以及每一页上渲染的页面预览中。一位用户切换页面格式或拖动边距滑块，所有已连接用户的布局都会随之更新。

## 工作原理

在父编辑器上接入 `@tiptap/extension-collaboration` 后，Pages 扩展会通过 `headerFooterExtensions` 回调提供 `Y.Doc`，以便你为每个页眉/页脚子编辑器添加 `Collaboration` 扩展。此软件包不包含 `yjs` 或 `@tiptap/extension-collaboration`；这些依赖由你的应用负责，并通过该回调接入。

每种页眉/页脚子类型（默认、首页、奇数页、偶数页；页眉和页脚均适用）都独立协作。配置开关 `differentFirstPage` / `differentOddEven` 以及文档级页面几何设置（`pageFormat`、`pageGap`、`headerTopMargin`、`footerBottomMargin`）都会自动在各客户端之间同步：一位用户切换开关或更改页面格式，其他用户的设置会在一帧内同步更新。即使没有打开任何覆盖层，远程编辑也会同步到每个客户端的页面预览中。

如果你还在父编辑器上接入了 `@tiptap/extension-collaboration-caret`（Tiptap v2 中为 `CollaborationCursor`），主文档正文中就会显示远程光标和用户标签。回调上下文会通过 `ctx.cursor` 暴露 provider 和本地用户；但请留意下文的注意事项：推荐的设置只在主编辑器上启用协同感知，不在子编辑器上启用。

## 1. 前提条件

- 支持协作功能的 Tiptap Pro 计划
- Tiptap Cloud 访问权限或你自己的协作后端
- Pages 扩展栈：`@tiptap-pro/extension-convert-kit`、`@tiptap-pro/extension-pages-tablekit`、`@tiptap-pro/extension-pages`
- 协作 provider：`@tiptap-pro/provider`（或你自己的 provider），以及 `@tiptap/extension-collaboration` 和 `yjs`

## 2. 安装所需软件包

```bash
npm install @tiptap-pro/extension-convert-kit \\
            @tiptap-pro/extension-pages-tablekit \\
            @tiptap-pro/extension-pages \\
            @tiptap-pro/provider \\
            @tiptap/extension-collaboration \\
            yjs
```

## 3. 设置协作 provider

```ts
import { TiptapCollabProvider } from '@tiptap-pro/provider'
import * as Y from 'yjs'

const doc = new Y.Doc()

const provider = new TiptapCollabProvider({
  name: 'document.name', // Unique document identifier for syncing
  appId: 'your-app-id', // From the Cloud dashboard, or use `baseURL` for on-premises
  token: 'your-jwt', // JWT generated by your server
  document: doc,
})
```

## 4. 使用 Pages 扩展栈和协作配置编辑器

使用 `headerFooterExtensions` 的**回调形式**。Pages 会针对每个子类型（`default`、`first`、`odd`、`even` × `header`、`footer`）各调用一次回调，并提供上下文，说明协作是否已启用，以及子编辑器应绑定到哪个 Y 字段。返回该子类型所需的扩展；当 `ctx.isCollaborative` 为 `true` 时，包含 `Collaboration` 扩展。

```ts
import { Editor } from '@tiptap/core'
import Collaboration from '@tiptap/extension-collaboration'
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'
import { TableKit } from '@tiptap-pro/extension-pages-tablekit'
import { Pages } from '@tiptap-pro/extension-pages'

const editor = new Editor({
  extensions: [
    ConvertKit.configure({ table: false }),
    TableKit,
    Pages.configure({
      pageFormat: 'A4',
      // ⚠️ Do NOT pass `header` / `footer` defaults here; see "What to expect"
      // below. With collaboration on, Y is the source of truth for header/footer
      // content; defaults compete with that and can re-appear after a remote clear.
      headerFooterExtensions: ctx => {
        // Mirror the main editor's stack inside each sub-editor so the schema,
        // marks, and tables behave identically there.
        const base = [ConvertKit.configure({ table: false }), TableKit]

        if (!ctx.isCollaborative || !ctx.ydoc) {
          // No collaboration on the parent editor, so return your base stack.
          return base
        }

        return [
          ...base,
          Collaboration.configure({
            document: ctx.ydoc,
            field: ctx.field,
          }),
        ]
      },
    }),
    Collaboration.configure({
      document: doc,
      // Pages waits for this provider to sync before it writes the page setup.
      provider,
    }),
  ],
})
```

如上例所示，将 `provider` 传给 `Collaboration`，这样 Pages 就会先等待 provider 完成首次同步，再根据 `Pages.configure()` 写入页面设置，并且只填入文档中尚未设置的选项。

<Callout title="一个回调，八个子编辑器" variant="info">
  对每个 `(editorType, subType)` 组合都会调用一次回调，总共调用八次。每次调用都会收到一个独立的 `ctx.field`，确保对应的子编辑器与文档中各自的片段保持同步。当前未编辑的子类型仍会在后台接收远程更新，因此每位用户的页面预览都会立即反映更改。
</Callout>

### 使用 `CollaborationCaret` 添加协同感知

安装 `@tiptap/extension-collaboration-caret`（Tiptap v2 中为 `@tiptap/extension-collaboration-cursor`），并将其接入**主编辑器**。这样，主文档正文中就会显示远程光标和用户标签：

```ts
import Collaboration from '@tiptap/extension-collaboration'
import CollaborationCaret from '@tiptap/extension-collaboration-caret'

const localUser = { name: 'Alice', color: '#3b82f6' }

const editor = new Editor({
  extensions: [
    ConvertKit.configure({ table: false }),
    TableKit,
    Pages.configure({
      headerFooterExtensions: ctx => {
        const base = [ConvertKit.configure({ table: false }), TableKit]
        if (!ctx.isCollaborative || !ctx.ydoc) return base
        // Content sync only; see the callout below for why
        // CollaborationCaret is intentionally not forwarded here.
        return [...base, Collaboration.configure({ document: ctx.ydoc, field: ctx.field })]
      },
    }),
    Collaboration.configure({ document: doc }),
    // Awareness on the main document body.
    CollaborationCaret.configure({ provider, user: localUser }),
  ],
})
```

<Callout title="为什么不在每个子编辑器上都添加 CollaborationCaret" variant="warning">
  `y-prosemirror` 的 awareness 对每个客户端只有一个**光标槽位**。当一个 provider 同时服务主编辑器和 8 个页眉/页脚子编辑器时，每个 `yCursorPlugin` 实例都会写入同一个槽位，而每个编辑器又会尝试根据不同的 Y 字段解析其他编辑器的位置。渲染回退机制会在整个页眉/页脚内容上绘制一条宽大的“选区”条，而不是纤细的光标。

  只在主编辑器上保留 `CollaborationCaret`。所有页眉/页脚子编辑器中的内容仍会正常同步；只是你在覆盖层中编辑时看不到远程光标。如果你想进行实验，回调仍会收到 `ctx.cursor`，你可以将其转发给一个指定的子编辑器，但不要转发给全部八个子编辑器。
</Callout>

## 哪些内容会同步

### 内容

- **全部八个页眉/页脚子编辑器。** 默认 / 首页 / 奇数页 / 偶数页 × 页眉 / 页脚：所有子类型都会保持同步。
- **每位用户都会看到实时预览，即使覆盖层处于关闭状态。** 用户 A 在页眉中输入内容后，用户 B 渲染的页面页眉会在一帧内更新。B 不需要打开覆盖层也能看到更改。
- **已清空的内容会保持为空。** 一位用户删除所有页眉内容后，其他用户渲染的页眉也会留空。
- **远程内容增加时会自动调整高度。** 如果远程用户添加了足够多的行，使页眉超出当前预留空间，每位用户的页面布局都会相应调整，避免正文与页眉重叠。

### 子类型开关

- 一位用户切换 **`differentFirstPage`**（以及对应的 `differentFirstPageFooter`）后，其他用户的开关也会同时切换，符合 Microsoft Word “两者同时切换”的行为。
- **`differentOddEven`**（以及对应的 `differentOddEvenFooter`）也一样。

### 文档级页面几何设置

- **`pageFormat`**：内置格式（`A4`、`Letter`、`Legal` 等）和自定义 `PageFormat` 对象。
- **`pageGap`**：页面之间的垂直间距。
- **`headerTopMargin`**：显式覆盖页面顶部到页眉内容之间的距离。
- **`footerBottomMargin`**：显式覆盖页脚到页面底部之间的距离。

以下是几个实际示例：

```ts
// Triggering any of these on one client propagates to every connected client.
editor.commands.setPageFormat('Letter')
editor.commands.setPageGap(80)
editor.commands.setHeaderTopMargin(40)
editor.commands.setFooterBottomMargin(40)
```

`reset*` 边距命令会同步**重置操作**，而不是格式默认值：`resetHeaderTopMargin()` 会在每位用户的客户端上清除覆盖值，让所有客户端恢复使用格式本身的默认值（格式顶部边距的 50%）：

```ts
editor.commands.resetHeaderTopMargin()
editor.commands.resetFooterBottomMargin()
```

### 可选：协同感知

如果你在父编辑器上接入了 `@tiptap/extension-collaboration-cursor`，页眉/页脚覆盖层中也会显示远程光标和标签。请参阅下文的[添加 `CollaborationCursor`](#adding-collaborationcursor)。

## 哪些内容不会同步

这些设置按设计仅对当前客户端生效，因为它们描述的是*你*如何查看文档，而不是文档本身：

- **`zoom`**：不同屏幕尺寸需要不同的缩放比例。一位用户使用 80%，另一位使用 100%，完全合理，也很实用。
- **`accentColor` / `headerAccentColor` / `footerAccentColor`**：覆盖层界面元素（光标、工具栏边框、标签背景）只会显示在*你自己*编辑时。按用户单独设置，能让每个人选择适合无障碍需求的高对比度选项。
- **`pageGapBackground`**：页面区域之外的界面装饰，原因与强调色相同。
- **`editableHeader` / `editableFooter`**：这些是权限控制项。它们应由应用的身份验证/角色模型决定（管理员可以编辑，查看者不可以），而不是存储在文档级 Y 状态中，否则任何用户都可能让所有人无法编辑。

如果你需要共享这些设置中的任何一项（例如，希望所有客户端使用相同的强调色），请通过自己的应用状态进行同步。

## 注意事项

- **如果 provider 不报告同步状态，Pages 就会立即写入页面设置。** 新加入的客户端随后可能会替换所有人的文档页面设置。不带 `synced` 标志的自定义 provider 在此处会被视为没有 provider。Pages 会先从 `Collaboration`、再从 `CollaborationCaret` 读取 provider；在开发环境中，如果找不到会报告同步状态的 provider，就会记录一条警告。
- **启用协作时，不要在 `Pages.configure()` 中传入 `header` / `footer` 默认值。** 启用协作后，页眉/页脚内容由 Y 管理；配置的默认值可能会在另一位用户清空内容后重新出现。请不要设置这些默认值；如果需要初始内容，请在 provider 完成同步后，通过 `editor.commands.setHeader(...)` 设置一次。
- **此软件包不包含 `yjs` 或 `@tiptap/extension-collaboration`。** 它们是对等依赖项：请在应用中安装，并通过 `headerFooterExtensions` 回调接入 `Collaboration`。
- **切换 `differentOddEven` 不会通过网络复制内容。** 启用该选项时，其他用户的奇数页区域不会预先填入默认页眉的内容。每位用户看到的都是各子类型中实际编辑过的内容。

## 回调上下文

回调会收到一个上下文，其中包含为某个子类型接入协作所需的全部信息：

```ts
import type { HeaderFooterExtensionsContext } from '@tiptap-pro/extension-pages'

interface HeaderFooterExtensionsContext {
  /** Which sub-editor this invocation is for. */
  editorType: 'header' | 'footer'
  /** Which subtype (default / first / odd / even). */
  subType: 'default' | 'first' | 'odd' | 'even'
  /** True when the parent editor has Collaboration installed. */
  isCollaborative: boolean
  /** Y.Doc instance from the parent's Collaboration extension, or null. */
  ydoc: import('yjs').Doc | null
  /** Y field name to bind the sub-editor's Collaboration extension to. */
  field: string
  /** Awareness info from the parent's CollaborationCursor, or null. */
  cursor: { provider: unknown; user: unknown } | null
}
```

将 `ctx.field` 直接传给 `Collaboration.configure({ document: ctx.ydoc, field: ctx.field })`，扩展就会自动将每个子类型路由到 `Y.Doc` 中各自的片段。

## 提升使用体验的建议

- **允许编辑前，先等待 provider 完成同步。** 一种常见做法是使用 `connected` 标志控制 `<EditorContent>` 的显示，并在 provider 的 `onSynced` 回调触发后更新该标志。
- **在回调的 `base` 中镜像主编辑器使用的扩展。** 传入相同的 `ConvertKit` / `TableKit` 配置，确保子编辑器支持相同的标记和节点。
- **持久化由你负责。** Tiptap Cloud / 你的 provider 会持久化 `Y.Doc`，自动涵盖页眉/页脚内容、已同步的开关以及文档级页面几何设置（格式、间距、边距覆盖值）。只有在还需要非协作回退快照时，才需要单独持久化主文档正文。
- **在两个浏览器窗口中进行测试。** 在两个标签页中打开同一文档，全面测试同步功能：在一个标签页的页眉中输入内容，确认另一个标签页的页面预览会在覆盖层未打开时更新；切换首页设置，确认两个标签页的按钮会一起切换；更改一个标签页的页面格式，确认另一个标签页的页面会重新排版；拖动一个标签页中的边距滑块，确认另一个标签页的页面 CSS 会重新计算。
