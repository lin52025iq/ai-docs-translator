Tiptap 重视您的隐私。因此，在使用 Tiptap 基础 AI 生成时，您可能会有一些疑问，下面我们将详细解答。

## 云端集成

Tiptap AI Server 在您的客户端（Tiptap Editor）与 OpenAI 之间**充当代理**。这样可以保护您的 OpenAI 密钥不被客户端获取，因为公开分享面向用户的密钥是一种反模式。

使用我们的云服务时，您需要在 AI 设置页面中输入 OpenAI 密钥。该密钥会经过加密并存储在我们的数据库中。我们会使用此密钥代表您向 OpenAI API 发送请求。

### 数据流

数据的一般流转过程如下：

1. 您的客户端（编辑器）执行 AI 命令，例如 `translate`
2. AI 扩展向我们的后端服务发送请求
3. 后端验证签名令牌及其权限，然后继续处理请求，或返回错误代码并中止请求
4. 授权完成后，后端会根据所需命令构建提示词，并使用您的 OpenAI API 密钥向 OpenAI API 发送请求
5. 请求处理完成后，响应会发送回客户端

### 我们记录哪些信息

在上述过程中，我们会定期记录以下数据，以确保服务正常、可靠地运行：

- HTTP 日志，包括时间戳、关联 ID、引荐来源、用户代理和 IP，以及相关请求标头和部分请求正文，以确保服务正常运行并防止滥用
- 与您的团队关联的已执行操作，包括时间戳、关联 ID、命令（例如“translate”）和时间戳，以跟踪套餐限额的使用情况

为了在出现异常时为您提供帮助，我们实现了一种称为“增强日志记录”的机制。

**只有在您提出要求（例如，为了调试）并征得您的许可后**，我们才可能启用增强日志记录。请注意：这并非默认设置。不过，启用后会额外记录以下字段：

- 输入文本和选项、后端构建的提示词以及 OpenAI 的响应

这些数据有助于我们追踪双方的错误，并协助您解决可能遇到的问题。调试完成后，我们会立即停用增强日志记录。

### 加密

如上所述，我们会在数据库中加密存储以下信息：

- 您的 OpenAI API 密钥
- 您的 JWT 密钥（适用于仍在使用旧版身份验证的集成）

只有在授权或处理请求时，才会解密这些密钥。

客户端、后端和 OpenAI 之间的所有流量均使用最新的 SSL 标准进行加密。

## 本地部署

本地部署版本在技术上与云端版本的工作方式相同，同样充当客户端与 OpenAI 之间的代理。

出于显而易见的原因，两者也有一些不同之处：

- OpenAI API 密钥存储在您指定的位置，绝不会发送给我们
- 我们**不会**获取已执行请求的任何使用信息
- 日志会发送到 stdout，您可以按自己的需要和偏好使用这些日志

因此，本地部署版本让您能够全面掌控所收集的数据和指标。
