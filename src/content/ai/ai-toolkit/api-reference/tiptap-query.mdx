Tiptap Query 使用 JSON 操作读取、搜索和编辑 Tiptap 文档。AI 代理通过 `tiptapQuery` 工具使用它。每个操作都会选取内容（例如所有标题或某个词的每次出现），并对其执行操作。该工具可以独立工作：AI 代理无需使用 `tiptapRead` 或 `tiptapEdit`，即可查找并编辑内容。

```json
{
  "operations": [
    {
      "selector": [{ "type": "heading" }, { "text": "Old title" }],
      "action": { "type": "replace", "content": "New title" },
      "expect": 1
    }
  ]
}
```

## 启用工具

在[获取工具定义](/ai/ai-toolkit/api-reference/rest-api#fetch-tool-definitions)时启用 `tiptapQuery`：

```json
{
  "editorContext": {
    /* editor context data */
  },
  "tools": {
    "tiptapQuery": true
  }
}
```

若要让 AI 说明所做的更改，请传入 `meta` 指令，而不是 `true`，例如 `{ "meta": "Briefly explain the change." }`。之后，每个会更改文档的操作都必须包含 `meta`。读取操作无需包含。

使用 [`execute-tool`](/ai/ai-toolkit/api-reference/rest-api#execute-a-tool) 端点运行 AI 生成的工具调用：

```json
{
  "editorContext": {
    /* editor context data */
  },
  "document": { "type": "cloud", "id": "your-document-id" },
  "tool": {
    "name": "tiptapQuery",
    "input": {
      "operations": [
        { "selector": [{ "type": "heading" }], "action": { "type": "read", "view": "summary" } }
      ]
    }
  }
}
```

`tiptapQuery` 支持 `json`、`shorthand` 和 `shorthandV2` 格式，并支持[审阅选项](/ai/ai-toolkit/api-reference/review-options)。它不能通过 `stream-tool` 端点使用。

工具配置（`tool.config`）：

- `chunkSize`（`number`，可选，默认值：`32000`）：一次调用中所有读取操作合计返回的最大字符数。该值会限制在 `512` 到 `32000` 之间。
- `threadData`（`object`，可选）：添加到所创建线程的元数据。
- `commentData`（`object`，可选）：添加到所创建评论的元数据。

## 输入

工具输入（`tool.input`）：

- `operations`（`array`，必需）：按顺序运行 1 到 50 个操作。每个操作包含：
  - `selector`（`array`，必需）：最多 12 个步骤，用于选取要读取或编辑的内容。空数组表示选取整个文档。请参阅[选择器](#selectors)。
  - `action`（`object`，必需）：对选取的内容执行的操作。请参阅[操作](#actions)。
  - `expect`（`number`，可选）：选择器必须找到的确切匹配数。如果找到的数量不同，操作会以 `unexpected_matches` 失败。使用 `expect: 1` 可保护单个目标的编辑。
  - `meta`（`string`，可选）：更改原因，最多 4,000 个字符。在跟踪更改模式下，如果支持评论，该内容会成为建议上的评论。请参阅[跟踪更改和评论](#tracked-changes-and-comments)。如果 `fetch-tools` 为 `tiptapQuery` 收到 `meta` 指令，则更改操作必须包含此字段。

不接受未知字段。

## 选择器

选择器是由多个步骤组成的数组。它从文档开始，每个步骤都会在上一步选取的内容中搜索。空选择器（`[]`）表示选取整个文档。

| 选择器                                                    | 选取的内容                                               |
| --------------------------------------------------------- | -------------------------------------------------------- |
| `[{ "type": "heading" }]`                              | 每个标题，包括嵌套标题                                   |
| `[{ "hash": "HASH" }]`                                 | `_hash` 值为该值的节点                                   |
| `[{ "type": "paragraph", "contains": "beta" }]`     | 每个包含文本 `beta` 的段落                               |
| `[{ "text": "beta", "wholeWord": true }]`             | 单词 `beta` 的每次出现                                   |
| `[{ "type": "bulletList" }, { "text": "late" }]`    | 项目符号列表中的 `late` 的每次出现                       |
| `[{ "hash": "HASH" }, { "content": true }]`          | `_hash` 值为该值的节点内部内容，不包含节点本身           |
| `[{ "range": { "from": "START_HASH", "to": "END_HASH" } }]` | 两个同级节点及其间的所有节点                      |

### 节点步骤

节点步骤会在上一步选取的内容中选择节点。一个步骤中的所有筛选条件都必须匹配。

- `type`（`string`，可选）：节点类型，例如 `"heading"`。如果编辑器架构中未定义该类型，则会以 `invalid_selector` 失败。
- `hash`（`string`，可选）：节点 `_hash` 属性的值。读取操作会返回找到节点的哈希值。
- `id`（`string`，可选）：节点 `id` 属性的值，例如 [Unique ID](/editor/extensions/functionality/uniqueid) 扩展添加的 ID。多个节点可以匹配同一个 ID。
- `attrs`（`object`，可选）：节点必须具有的属性值，例如 `{ "level": 2 }`。
- `contains`（`string`，可选）：节点必须包含的文本。按字面匹配，区分大小写。
- `scope`（`'descendants' | 'children'`，可选，默认值：`'descendants'`）：搜索所有后代节点，或仅搜索直接子节点。
- `pick`（`'all' | 'first' | 'last'`，可选，默认值：`'all'`）：保留所有匹配项，或仅保留文档顺序中的第一个或最后一个匹配项。如果没有 `type`，且匹配项互相嵌套，则不能选取第一个或最后一个匹配项。

串联两个节点步骤时，会在第一个步骤找到的节点内部搜索。它不会选取这些节点之间的节点；要实现此目的，请使用范围步骤。

### 文本步骤

文本步骤会在上一步选取的内容中选择某个文本的所有非重叠匹配项。

- `text`（`string`，必需）：要查找的文本，最多 10,000 个字符。按字面匹配文本。不支持正则表达式。
- `caseSensitive`（`boolean`，可选，默认值：`true`）：设为 `false` 可忽略大小写。
- `wholeWord`（`boolean`，可选，默认值：`false`）：设为 `true` 仅匹配完整单词。
- `pick`（`'all' | 'first' | 'last'`，可选，默认值：`'all'`）：保留所有匹配项，或仅保留文档顺序中的第一个或最后一个匹配项。

匹配项可以跨越格式不同的文本，但不会跨越块、硬换行或行内节点。文本步骤之后只能跟另一个文本步骤。

### 内容步骤

`{ "content": true }` 会选取每个已选节点内部的内容，不包括节点本身。可用它读取或替换节点的子内容，同时保留该节点及其属性。

### 范围步骤

`{ "range": { "from": "START_HASH", "to": "END_HASH" } }` 会选取两个同级节点及它们之间的所有节点。两个哈希都必须对应上一步选取范围内恰好一个节点，并且 `from` 必须位于 `to` 之前。省略 `to` 可选取直到父节点末尾的内容；如果外层范围先结束，则选取至外层范围末尾。

编辑范围之前，请先读取端点的哈希，并在一个操作中编辑整个范围。

## 操作

### `read`

返回选取的内容，不更改文档。

- `view`（`'content' | 'text' | 'summary'`，可选，默认值：`'content'`）：每个匹配项的返回形式：
  - `'content'`：使用请求中的 `format` 返回内容：Tiptap JSON 节点或 Tiptap Shorthand 字符串。
  - `'text'`：纯文本。
  - `'summary'`：每个节点的哈希、类型、属性和纯文本。
- `maxChars`（`number`，可选，默认值：`32000`）：返回页面的最大大小，范围为 512 到 32,000 个字符。
- `cursor`（`string`，可选）：继续先前的读取操作。不要创建或更改它；请发送读取操作返回的整个 `next` 操作。请参阅[读取较长内容](#read-long-content)。

### `replace`

替换选取的内容。

- `content`（`JSONContent[] | string`，必需）：新内容。
  - 对于文本匹配项，在所有格式中，`content` 始终是纯字符串。使用 `""` 删除文本。新文本会保留匹配项起始位置的格式；如果父节点允许，`\n` 会转换为硬换行。
  - 对于节点、内容步骤、范围和整个文档，当 `format` 为 `json` 时，`content` 是 Tiptap JSON 节点数组；当 `format` 为 `shorthand` 或 `shorthandV2` 时，则是 [Tiptap Shorthand](/ai/ai-toolkit/advanced-guides/tiptap-shorthand) 字符串。空内容（`[]`，或 Tiptap Shorthand 中的 `""`）会删除选取的节点，前提是架构允许删除。

### `insertBefore` 和 `insertAfter`

在每个选中的节点或内容范围前后插入同级节点。

- `content`（`JSONContent[] | string`，必需）：要插入的节点，格式与 `replace` 的节点内容相同。

不能对文本匹配项使用此操作。若要在段落内添加文本，请用更长的文本替换某个文本匹配项。若要在文档开头或结尾添加节点，请选择 `[{ "content": true }]`。不能对整个文档（`[]`）执行插入操作。

### `setAttrs`

将属性合并到每个选中的节点中。

- `attrs`（`object`，必需）：要设置的属性。编辑器架构必须定义这些属性。不能设置保留属性，例如 `_hash` 和跟踪更改属性。

### `addMark` 和 `removeMark`

为选中的文本或所选节点内的所有文本添加或移除标记。

- `mark`（`string`，必需）：编辑器架构中的标记类型，例如 `"bold"`。不能使用跟踪更改标记和评论标记。
- `attrs`（`object`，可选）：`addMark` 的标记属性，例如用于链接的 `{ "href": "https://tiptap.dev" }`。

`removeMark` 会移除该类型的所有标记，不论其属性为何。

### 新内容中的哈希

工具会为每个新节点添加 `_hash`。你发送的内容中的哈希会被忽略。使用 `replace` 将节点替换为一个相同类型的节点时，新节点会保留旧哈希。如果新内容中包含跟踪更改标记和属性，则会以 `invalid_content` 拒绝。

## 输出

工具输出（`tool.output`）：

- `success`（`boolean`）：所有操作是否均已成功。
- `operationResults`（`array`）：每个已运行操作对应一个结果，按运行顺序排列。见下文。
- `skipped`（`number`）：因先前操作失败而未运行的操作数量。

`operationResults` 中的每个结果都采用以下某种结构。

读取结果：

- `index`（`number`）：该操作在 `operations` 中的位置。
- `success`（`true`）
- `complete`（`boolean`）：读取操作是否返回了所有选取内容。如果为 `false`，请使用 `next` 再次调用工具。
- `totalMatches`（`number`）：选择器的匹配项数量。选择器为空时，每个顶层节点都计为一个匹配项。
- `items`（`array`）：返回的匹配项。每项包含：
  - `hash`（`string`，可选）：节点的哈希。对于文本匹配项，这是包含该匹配项的节点哈希；对于内容步骤，这是内容被选取的节点哈希。范围项没有哈希。
  - `type`（`string`）：节点类型；文本匹配项为 `"text"`，内容步骤或范围为 `"content"`。
  - `attrs`（`object`，可选）：在 `summary` 视图中返回的节点属性。不包括 `_hash` 和跟踪更改属性。文本匹配项、内容步骤和范围没有 `attrs`。
  - `text`（`string`）：在 `text` 和 `summary` 视图中的纯文本。硬换行会转换为 `\n`，其他行内节点会转换为 U+FFFC 字符。
  - `content`（`JSONContent[] | string`）：在 `content` 视图中的内容。
  - `excerpt`（`true`，可选）：当节点内容无法全部放入页面时，此项为该节点的文本摘录。此时使用 `text`，而非 `content`。
- `next`（`object | null`）：用于继续读取的操作；读取完成时为 `null`。

编辑结果：

- `index`（`number`）：该操作在 `operations` 中的位置。
- `success`（`true`）
- `matched`（`number`）：该操作编辑的匹配项数量。
- `changed`（`boolean`）：文档是否发生更改。如果编辑没有效果（例如将粗体文本再次设为粗体），则为 `false`。

失败结果：

- `index`（`number`）：该操作在 `operations` 中的位置。
- `success`（`false`）
- `code`（`string`）：错误代码。请参阅[错误代码](#error-codes)。
- `error`（`string`）：提供给 AI 的错误消息，最多 2,000 个字符。消息通常会建议如何修复操作。

如果输入本身无效，输出为 `{ "success": false, "code": "invalid_input", "error": "..." }`，且不会运行任何操作。

失败的操作和无效输入会在 `tool.output` 中报告，而 `execute-tool` 请求仍会返回 HTTP 状态码 `200`。其他失败（例如身份验证、文档访问和服务器错误）会返回 [REST API 参考](/ai/ai-toolkit/api-reference/rest-api#execute-a-tool)中所述的 HTTP 错误。

## 操作的运行方式

- 操作按顺序运行。每个操作都会看到之前操作所做的更改。
- 编辑操作会先查找所有匹配项，然后一次性更改全部匹配项；如果编辑失败，则一个也不会更改。
- 没有匹配项的编辑操作会以 `no_matches` 失败。没有匹配项的读取操作会成功返回空项。
- 第一个失败的操作会终止调用。先前操作所做的更改会保留，后续操作会跳过。调用不会回滚。
- 即使调用只执行读取操作，没有 `_hash` 的节点也会获得哈希。重复的哈希会被替换。已有哈希不会更改。

## 读取较长内容

读取操作最多返回 `maxChars` 个字符。如果内容更多，`complete` 会为 `false`，并且 `next` 会包含用于继续读取的操作。将 `next` 作为新调用中的操作发送，并重复此过程，直到 `next` 为 `null`：

```json
{
  "operations": [
    /* the `next` value of the previous read */
  ]
}
```

如果某个节点无法完整放入页面，则会以文本摘录形式返回，并带有 `excerpt: true`；`next` 会继续读取该节点内部的内容。因此，读取所需的页面数可能多于匹配项数；`totalMatches: 1` 并不表示该节点已完整读取。若要查看大型节点的结构，请读取其子节点或使用更大的页面。

当文档的其他部分发生更改，且已读取的节点仍保留其哈希时，`next` 中的游标仍然有效。如果已读取的内容以其他方式发生更改，读取操作会以 `stale_cursor` 失败。请在不使用游标的情况下重新读取，或从上次读取的哈希处开始一个范围。

同一次调用中的所有读取操作共享 `chunkSize` 预算。预算用尽后，剩余读取操作不会返回任何项，而是返回 `complete: false` 及其 `next` 操作。后续操作仍会运行。

## 跟踪更改和评论

使用 `reviewOptions: { mode: 'trackedChanges' }` 时，每个编辑都会成为一条建议，供用户接受或拒绝，而不会直接更改文档。

- 读取操作会返回仿佛所有待处理建议均已接受的文档。
- AI 编辑其他内容时，先前调用创建的建议会保留。
- `meta` 会成为该操作生成的建议上的评论。评论要求文档位于 Tiptap Cloud，且编辑器架构支持评论。内联文档会收到建议，但不会有评论。
- 如果 `setAttrs` 设置了建议无法记录的属性，则会以 `invalid_attributes` 失败。默认情况下，这些属性为 `id` 和 `data-thread-id`（请参阅[审阅选项](/ai/ai-toolkit/api-reference/review-options)中的 `ignoreAttributes`）。
- 如果编辑只更改被忽略的属性或标记，则会返回 `changed: false`，且不会更改文档。

## 错误代码

| 代码                  | 原因                                                                                                                                          |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `invalid_input`       | 输入不符合架构，例如包含未知字段或操作数量超过 50 个。不会运行任何操作。                                                                        |
| `invalid_selector`    | 节点类型不在架构中；文本步骤后跟随节点、范围或内容步骤；内容步骤选取了叶节点；或者 `pick` 存在歧义。                                              |
| `invalid_range`       | 范围端点在所选范围内没有且仅有一个对应节点，或端点不是顺序正确的同级节点。                                                                         |
| `no_matches`          | 编辑操作没有选中任何内容。                                                                                                                      |
| `unexpected_matches`  | 匹配数量与 `expect` 不同。                                                                                                                      |
| `too_many_matches`    | 编辑操作选中了超过 10,000 个匹配项。                                                                                                            |
| `overlapping_matches` | 编辑操作的匹配项相互重叠。                                                                                                                      |
| `selection_limit`     | 调用中的选择器检查了超过 2,000,000 个节点和文本匹配项。                                                                                           |
| `invalid_target`      | 该操作无法应用于所选内容，例如在文本匹配项旁插入内容，或为文本设置属性。                                                                          |
| `invalid_content`     | 内容的形式与所选内容或格式不符，或者包含跟踪更改。                                                                                                |
| `invalid_operation`   | 编辑器架构拒绝该内容，或无法解析 Tiptap Shorthand。消息会列出相关问题。                                                                           |
| `invalid_attributes`  | 属性未知或为保留属性，或者在跟踪更改模式下建议无法记录该属性。                                                                                    |
| `invalid_mark`        | 该标记不是架构中的普通标记，或父节点不允许使用该标记。                                                                                            |
| `invalid_cursor`      | 游标不是由工具返回的，或已被更改。                                                                                                               |
| `stale_cursor`        | 读取操作已返回的内容发生了更改。                                                                                                                 |
| `output_limit`        | 单个项及其后续内容无法放入 `maxChars`。                                                                                                           |
| `unsupported_content` | Tiptap Shorthand 无法表示该内容。请使用 `text` 或 `summary` 视图读取。                                                                            |

## 限制

| 限制                                                       | 值                       |
| ---------------------------------------------------------- | ------------------------ |
| 每次调用的操作数                                           | 50                       |
| 每个选择器的步骤数                                         | 12                       |
| `text` 和 `contains` 的长度                                | 10,000 个字符            |
| `meta` 的长度                                              | 4,000 个字符             |
| 每次编辑的匹配项数                                         | 10,000                   |
| 调用中的选择器检查的节点和文本匹配项数                     | 2,000,000                |
| 读取页面大小（`maxChars`）                                 | 512 到 32,000 个字符     |
| 调用中所有读取操作返回的字符数（`chunkSize`）              | 512 到 32,000 个字符     |
| 游标长度                                                   | 2,048 个字符             |

以下示例使用的文档包含这些节点：

| 哈希     | 节点                                    | 文本                                                        |
| -------- | --------------------------------------- | ----------------------------------------------------------- |
| `k8Tq2m` | 标题，级别 1                            | Launch plan                                                 |
| `p3Lx7a` | 段落                                    | This plan covers the beta and the public launch.            |
| `Q9wE4r` | 标题，级别 2                            | Timeline                                                    |
| `Z2nB6c` | 段落                                    | The beta starts in March. The public launch follows in May. |
| `m5Ht8v` | 标题，级别 2                            | Risks                                                       |
| `J7sD1k` | 项目符号列表                            |                                                             |
| `x4Pq9w` | `J7sD1k` 中的列表项，包含一个段落       | Hiring takes longer than planned.                           |
| `R1yU5e` | `J7sD1k` 中的列表项，包含一个段落       | The scope changes late.                                     |
| `W3gN7h` | 标题，级别 2                            | Contacts                                                    |
| `t5Mz1q` | 段落                                    | Product: Ana. Engineering: Ben.                             |

### 读取大纲

使用 `summary` 视图读取所有标题，而不加载正文：

```json
{
  "operations": [
    { "selector": [{ "type": "heading" }], "action": { "type": "read", "view": "summary" } }
  ]
}
```

输出：

```json
{
  "success": true,
  "operationResults": [
    {
      "index": 0,
      "success": true,
      "complete": true,
      "totalMatches": 4,
      "items": [
        { "hash": "k8Tq2m", "type": "heading", "attrs": { "level": 1 }, "text": "Launch plan" },
        { "hash": "Q9wE4r", "type": "heading", "attrs": { "level": 2 }, "text": "Timeline" },
        { "hash": "m5Ht8v", "type": "heading", "attrs": { "level": 2 }, "text": "Risks" },
        { "hash": "W3gN7h", "type": "heading", "attrs": { "level": 2 }, "text": "Contacts" }
      ],
      "next": null
    }
  ],
  "skipped": 0
}
```

### 从某个标题开始向后读取

从标题哈希处开始一个范围，并省略 `to`，即可读取至文档末尾。添加 `{ "scope": "children" }` 可将范围内的每个节点分别作为一项返回：

```json
{
  "operations": [
    {
      "selector": [{ "range": { "from": "m5Ht8v" } }, { "scope": "children" }],
      "action": { "type": "read", "view": "summary", "maxChars": 8000 }
    }
  ]
}
```

结果包含四项：`Risks` 标题、项目符号列表、`Contacts` 标题及其段落。范围不会在遇到下一个标题时停止。若只读取某个章节，请将 `to` 设为该章节的最后一个节点。

### 查找并编辑段落

搜索包含某段文本的段落：

```json
{
  "operations": [
    {
      "selector": [{ "type": "paragraph", "contains": "March" }],
      "action": { "type": "read", "view": "summary" }
    }
  ]
}
```

读取操作会返回一项：哈希为 `Z2nB6c` 的段落。

接着使用该段落的哈希编辑其中的文本：

```json
{
  "operations": [
    {
      "selector": [{ "hash": "Z2nB6c" }, { "text": "March" }],
      "action": { "type": "replace", "content": "April" },
      "expect": 1
    }
  ]
}
```

编辑操作会返回 `matched: 1` 和 `changed: true`。此时段落内容为 "The beta starts in April. The public launch follows in May."。

### 更改节点类型

若要更改节点类型，请选中节点本身，而不是其中的文本，然后替换它。以下操作会将联系人段落转换为项目符号列表：

```json
{
  "operations": [
    {
      "selector": [{ "type": "paragraph", "contains": "Product:" }],
      "action": {
        "type": "replace",
        "content": [
          {
            "type": "bulletList",
            "content": [
              {
                "type": "listItem",
                "content": [
                  { "type": "paragraph", "content": [{ "type": "text", "text": "Product: Ana" }] }
                ]
              },
              {
                "type": "listItem",
                "content": [
                  {
                    "type": "paragraph",
                    "content": [{ "type": "text", "text": "Engineering: Ben" }]
                  }
                ]
              }
            ]
          }
        ]
      },
      "expect": 1
    }
  ]
}
```

### 插入节点

在一个段落后插入另一个段落：

```json
{
  "operations": [
    {
      "selector": [{ "hash": "Z2nB6c" }],
      "action": {
        "type": "insertAfter",
        "content": [
          {
            "type": "paragraph",
            "content": [{ "type": "text", "text": "Feedback closes two weeks after launch." }]
          }
        ]
      }
    }
  ]
}
```

编辑操作会返回 `matched: 1` 和 `changed: true`。

### 处理失败的操作

第二个操作要求找到一个包含文本 "launch" 的段落，但有两个段落包含该文本：

```json
{
  "operations": [
    { "selector": [{ "text": "March" }], "action": { "type": "replace", "content": "April" } },
    {
      "selector": [{ "type": "paragraph", "contains": "launch" }],
      "action": { "type": "addMark", "mark": "italic" },
      "expect": 1
    },
    { "selector": [{ "text": "May" }], "action": { "type": "replace", "content": "June" } }
  ]
}
```

输出：

```json
{
  "success": false,
  "operationResults": [
    { "index": 0, "success": true, "matched": 1, "changed": true },
    {
      "index": 1,
      "success": false,
      "code": "unexpected_matches",
      "error": "Expected 1 matches, found 2. Narrow the selector or read first."
    }
  ],
  "skipped": 1
}
```

第一个操作会保留，因此文档现在写着 "April"。第三个操作不会运行。
