Server AI Toolkit REST API 包含用于获取可用工具和执行工具调用的端点。

<Callout title="旧版端点" variant="info">
  V4 是 Server AI Toolkit 端点的当前 API 版本。V3 端点已弃用；新项目请使用
  v4。v4 还将工具定义端点更名为 `/v4/ai/toolkit/fetch-tools`；`/v3/ai/toolkit/tools` 等旧名称属于 v3 API。有关旧版端点，请参阅 [v3 REST API
  参考](/ai/ai-toolkit/api-reference/rest-api-v3)。
</Callout>

## 基础 URL

Tiptap Cloud 的基础 URL 为：

```sh
BASE_URL=https://api.tiptap.dev
```

在本地部署中，基础 URL 可能有所不同。

下文示例中的请求使用 `BASE_URL/v4/ai/toolkit/...` 格式。

## 身份验证

所有请求都必须包含以下身份验证标头：

- `Authorization: Bearer JWT`，其中 `JWT` 是 Tiptap Access Control JWT。

请在服务器端使用以下设置对令牌进行签名：

- 受众：`AI`
- 权限：`AI:Toolkit`

如需自动获取和保存 Tiptap Cloud 文档，请添加 `Documents` 受众和 `Documents:Write` 权限。`Documents:Write` 包含读取和评论权限。

有关如何创建密钥对并对令牌签名，请参阅[身份验证](/authentication)；完整设置方法请参阅[授权指南](/ai/ai-toolkit/install#set-up-authorization)。

```ts
import { SignJWT, importPKCS8 } from 'jose'

const privateKey = await importPKCS8(process.env.TIPTAP_PRIVATE_KEY, 'ES256')

const JWT_TOKEN = await new SignJWT({
  permissions: [
    { action: 'AI:Toolkit', resource: '*' },
    { action: 'Documents:Write', resource: 'your-document-id' },
  ],
})
  .setProtectedHeader({ alg: 'ES256' })
  .setIssuer(process.env.TIPTAP_ENVIRONMENT_ID)
  .setAudience(['AI', 'Documents'])
  .setExpirationTime('30m')
  .sign(privateKey)
```

之前使用 App ID + secret 的身份验证流程请参阅[旧版身份验证](/authentication/legacy)。

## 可选字段

可选字段可以省略、设为 `null` 或 `undefined`。

## 端点

### 获取工具定义

```txt
POST /v4/ai/toolkit/fetch-tools
```

返回要传递给 AI 提供商的提示词和工具定义。

请求正文：

- `editorContext`（`object`，必填）：由 `getEditorContext` 返回的编辑器上下文。
- `tools`（`Record<string, boolean | ToolConfig>`，可选，默认值：`{}`）：启用、禁用或配置工具。默认情况下，工具处于禁用状态。
- `format`（`'json' | 'shorthand' | 'shorthandV2'`，可选，默认值：`'json'`）：工具定义和模型输出所使用的文档格式。请参阅 [Tiptap
  Shorthand](/ai/ai-toolkit/advanced-guides/tiptap-shorthand)。

`tools` 可以包含以下键：

- `tiptapRead`（`boolean`，可选）
- `tiptapEdit`（`boolean | { meta?: string }`，可选）：如果希望 AI 在每个编辑操作中都包含额外的元数据字段（例如简短说明），请设置 `meta`。
- `tiptapQuery`（`boolean | { meta?: string }`，可选）：如果希望 AI 在每个会更改文档的操作中都包含额外的元数据字段，请设置 `meta`。请参阅
  [`tiptapQuery`](/ai/ai-toolkit/api-reference/tiptap-query)。
- `getThreads`（`boolean`，可选）
- `editThreads`（`boolean`，可选）
- `readDocument`（`boolean`，可选）
- `replaceDocument`（`boolean`，可选）
- `createDocument`（`boolean`，可选）：`replaceDocument` 的别名。
- `readSelection`（`boolean`，可选）
- `proofread`（`boolean | { meta?: string }`，可选）：如果希望 AI 在每个校对编辑中都包含额外的元数据字段（例如简短说明），请设置 `meta`。
- `readBoard`、`createShapes`、`arrangeShapes`、`createDiagram`、`updateShapes`、`deleteShapes`、
  `connectShapes` 和 `createDocFrame`（`boolean`，可选）：用于白板的[画板工具](#board-tools)。

响应：

- `systemPrompt`（`string`）：将其添加到 AI 请求的系统提示词中。它会向 AI 介绍 Tiptap 文档的工作方式、编辑器支持的元素，以及应使用的文档格式。
- `tools`（`array`）：AI 或开发者可以调用的工具定义。数组中的每个元素包含：
  - `name`（`string`）：工具名称。
  - `description`（`string`）：工具说明。
  - `inputSchema`（`object`）：AI 生成的工具输入所使用的 JSON Schema。

示例：

```curl
curl --location 'BASE_URL/v4/ai/toolkit/fetch-tools' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer YOUR_JWT' \
  --data '{
    "editorContext": { /* editor context data */ },
    "tools": {
      "tiptapRead": true,
      "tiptapEdit": {
        "meta": "Briefly explain the edit."
      }
    },
    "format": "shorthandV2"
  }'
```

#### 错误响应

HTTP 错误会返回：

- `error`（`object`）：包含以下属性的对象：
  - `message`（`string`）：便于人理解的错误消息。
  - `status`（`number`）：HTTP 状态码。
  - `code`（`string`）：稳定的错误代码。
  - `data`（`object`，可选）：经过清理的结构化上下文。

此端点可能返回：

- `401`，错误代码为 `access_control_auth_required` 或 `missing_token`：请求未包含 Tiptap Access Control JWT。
- `401`，错误代码为 `token_expired` 或 `signature_invalid` 等 Access Control 错误代码：Access Control 拒绝了 JWT。
- `403`，错误代码为 `feature_not_available`：当前环境未启用 Server AI Toolkit。
- `403`，错误代码为 `insufficient_permissions`：JWT 未授予 `AI:Toolkit` 权限。
- `403`，错误代码为 `origin_not_allowed`：当前环境不允许请求中的 `Origin`。
- `422`，错误代码为 `validation_failed`：请求正文与端点 Schema 不匹配。响应包含 `error.issues`，其中列出了验证问题。
- `422`，错误代码为 `tool_config_validation_failed`：请求正文中提供的工具配置无效。响应包含 `error.data.issues`，其中列出了验证问题。
- `429`，错误代码为 `rate_limited`：Access Control 对身份验证进行了速率限制。
- `429`：服务器端速率限制器阻止了请求。此响应使用不同的顶层结构：
  - `error`（`string`）：速率限制错误消息。
  - `retryAfter`（`number`，可选）：重试前需要等待的秒数。
  - `limit`（`number`，可选）：当前时间窗口内的请求上限。
  - `window`（`number`，可选）：速率限制窗口的秒数。
- `500`，错误代码为 `internal_server_error`：发生意外的服务器错误。
- `500`，错误代码为 `missing_cloud_api_token`：云服务缺少内部身份验证配置。
- `503`，错误代码为 `service_unavailable`：Access Control 暂时不可用。

### 执行工具

```txt
POST /v4/ai/toolkit/execute-tool
```

执行工具。AI 模型生成工具调用后，使用此端点。

请求正文：

- `editorContext`（`object`，必填）：由 `getEditorContext` 返回的编辑器上下文。
- `document`（`object`，必填）：要对其执行工具的文档。如果 API 应从 Tiptap Cloud 文档读取并写入，请使用
  `{ "type": "cloud", "id": "your-document-id" }`。如果要在请求正文中提供 Tiptap JSON 文档，请使用
  `{ "type": "inline", "content": { /* Tiptap JSON document */ } }`。
- `user`（`string`，可选）：版本历史中编辑操作的作者。它也会设置与 AI 生成的评论、讨论串和修订建议关联的用户。
  对于修订作者，请使用 `reviewOptions.trackedChangesOptions.userId`。
- `field`（`string`，可选，默认值：`"default"`）：要在云文档中操作的协作字段。当文档包含多个可编辑字段（如标题和正文）时，请使用此字段。
- `tool`（`object`，必填）：要执行的工具调用。
  - `name`（`string`，必填）：工具名称，例如 `"tiptapRead"`。
  - `input`（`object`，必填）：AI 生成的工具输入。该对象符合相应工具的 Schema 和工具定义。各工具的 Schema 和定义可从 `/v4/ai/toolkit/fetch-tools` 端点获取。
  - `config`（`unknown`，可选）：开发者提供的特定工具配置。
- `format`（`'json' | 'shorthand' | 'shorthandV2'`，可选，默认值：`'json'`）：工具输入和输出的文档格式。请参阅 [Tiptap Shorthand](/ai/ai-toolkit/advanced-guides/tiptap-shorthand)。
- `reviewOptions`（[`ReviewOptions`](/ai/ai-toolkit/api-reference/review-options)，可选，默认值：`{ mode: 'disabled' }`）：控制直接应用编辑，还是将其作为可审阅的更改应用。

响应：

- `tool`（`object`）：已执行的工具及其输出。
  - `name`（`string`）：工具名称。
  - `output`（`object`）：供 AI 使用的工具输出。
- `docChanged`（`boolean`）：文档是否发生更改。
- `before`（`JSONContent`）：执行工具之前的 Tiptap JSON 文档。
- `document`（`JSONContent | null`）：执行工具之后的 Tiptap JSON 文档；如果文档未更改，则为 `null`。更改可能涉及文档内容，也可能涉及节点的 `_hash` 属性。`_hash` 属性用作唯一标识符，并允许 AI 选择文档节点。

示例：

```curl
curl --location 'BASE_URL/v4/ai/toolkit/execute-tool' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer YOUR_JWT' \
  --data '{
    "editorContext": { /* editor context data */ },
    "document": {
      "type": "cloud",
      "id": "your-document-id"
    },
    "user": "ai-assistant",
    "tool": {
      "name": "tiptapRead",
      "input": {
        "from": 0
      }
    },
    "format": "shorthandV2"
  }'
```

#### 错误响应

HTTP 错误会返回：

- `error`（`object`）：包含以下属性的对象：
  - `message`（`string`）：便于人理解的错误消息。
  - `status`（`number`）：HTTP 状态码。
  - `code`（`string`）：稳定的错误代码。
  - `data`（`object`，可选）：经过清理的结构化上下文。文档和讨论串的上游故障会包含 `operation`、`upstreamStatus`、`upstreamUrl` 和 `upstreamMethod` 等字段。

此端点可能返回：

- `400`，错误代码为 `missing_document_credentials`：请求使用了云文档，但 JWT 不包含文档服务器凭据。
- `400`，错误代码为 `missing_document_options`：对内联文档执行了 `getThreads` 或 `editThreads`。这些工具需要云文档。
- `400`，错误代码为 `thread_not_found` 或 `comment_not_found` 等讨论串存储错误代码：讨论串或评论操作引用了不存在的数据。
- `401`，错误代码为 `access_control_auth_required` 或 `missing_token`：请求未包含 Tiptap Access Control JWT。
- `401`，错误代码为 `token_expired` 或 `signature_invalid` 等 Access Control 错误代码：Access Control 拒绝了 JWT。
- `403`，错误代码为 `feature_not_available`：当前环境未启用 Server AI Toolkit。
- `403`，错误代码为 `insufficient_permissions`：JWT 未授予 `AI:Toolkit` 权限，或未授予对所请求云文档的访问权限。
- `403`，错误代码为 `origin_not_allowed`：当前环境不允许请求中的 `Origin`。
- `403`，错误代码为 `unsupported_tool_format`：所选工具不支持请求的 `format`。
- `403`，错误代码为 `tracked_changes_unsupported_schema`：`reviewOptions.mode` 为 `trackedChanges`，但编辑器 Schema 不支持修订。
- `403`，错误代码为 `thread_schema_not_supported`：编辑器 Schema 不支持评论或讨论串。
- `403`，错误代码为 `board_schema_not_supported`：某个[画板工具](#board-tools)收到的文档或编辑器 Schema 不是其可操作的白板。
- `409`，错误代码为 `concurrent_edit_conflict`：工具执行期间云文档发生了更改。请使用最新文档状态重试请求。
- `422`，错误代码为 `validation_failed`：请求正文与端点 Schema 不匹配。响应包含 `error.issues`，其中列出了验证问题。
- `429`，错误代码为 `rate_limited`：Access Control 对身份验证进行了速率限制。
- `429`：服务器端速率限制器阻止了请求。此响应使用不同的顶层结构：
  - `error`（`string`）：速率限制错误消息。
  - `retryAfter`（`number`，可选）：重试前需要等待的秒数。
  - `limit`（`number`，可选）：当前时间窗口内的请求上限。
  - `window`（`number`，可选）：速率限制窗口的秒数。
- `500`，错误代码为 `document_save_failed`：服务器加载云文档后无法保存，或者在加载文档前调用了保存流程。
- `500`，错误代码为 `diff_worker_failed` 或 `diff_worker_invalid_result`：准备可审阅的更改时，内部差异工作器发生故障。
- `500`，错误代码为 `internal_server_error` 或 `unknown_error`：发生意外的服务器错误。
- `500`，错误代码为 `missing_cloud_api_token`：云服务缺少内部身份验证配置。
- `502`，错误代码为 `document_load_failed` 或 `document_save_failed`：从上游加载或保存云文档失败。请检查 `error.data.upstreamStatus` 中的上游 HTTP 状态码。
- `502`，错误代码为 `thread_list_failed`、`thread_create_failed`、`thread_update_failed`、`thread_delete_failed`、`thread_resolve_failed`、`thread_unresolve_failed`、`comment_create_failed`、`comment_update_failed` 或 `comment_delete_failed` 等讨论串或评论错误代码：上游评论 API 操作失败。
- `503`，错误代码为 `diff_worker_queue_timeout`：差异工作器队列已满或超时。
- `503`，错误代码为 `service_unavailable`：Access Control 暂时不可用。

### 流式执行工具

```txt
POST /v4/ai/toolkit/stream-tool
```

以流式方式执行工具。`tiptapEdit` 可以逐步应用编辑，呈现打字效果。其他工具会在收到完整输入后运行，并返回一个最终事件，与 `execute-tool` 类似。

请求分段发送。第一部分包含：

- `editorContext`（`object`，必填）：由 `getEditorContext` 返回的编辑器上下文。
- `document`（`object`，必填）：要将流式编辑写入的云文档：
  `{ "type": "cloud", "id": "your-document-id" }`。流式处理不支持内联文档。
- `user`（`string`，可选）：版本历史、评论和讨论串中的编辑作者（例如使用 `editThreads` 时）。它不会设置修订建议的作者；对于修订作者，请使用 `reviewOptions.trackedChangesOptions.userId`。
- `field`（`string`，可选，默认值：`"default"`）：要在云文档中操作的协作字段。流式处理仅支持 `default` 字段；其他值都会被拒绝。
- `tool`（`object`，必填）：要执行的工具调用，不含 `tool.input`。
  - `name`（`string`，必填）：工具名称，例如 `"tiptapEdit"`。
  - `config`（`unknown`，可选）：开发者提供的特定工具配置。
- `format`（`'json' | 'shorthand' | 'shorthandV2'`，可选，默认值：`'json'`）：工具输入和输出的文档格式。请参阅 [Tiptap Shorthand](/ai/ai-toolkit/advanced-guides/tiptap-shorthand)。
- `reviewOptions`（[`ReviewOptions`](/ai/ai-toolkit/api-reference/review-options)，可选，默认值：`{ mode: 'disabled' }`）：控制直接应用编辑，还是将其作为可审阅的更改应用。
- `delayMs`（`number`，可选，默认值：`5`）：逐步输出 `tiptapEdit` 时每个字符之间的延迟（毫秒）。必须介于 `0` 和 `1000` 之间。设为 `0` 可尽可能快速地应用编辑。

然后发送：

- 后续部分：AI 生成 `tool.input` 时，以流的形式发送其值。

响应：

- `tiptapEdit`：应用编辑期间返回增量事件，随后返回包含更新后 `document` 的最终事件。
- 其他工具：返回一个最终事件，其结果结构与 `execute-tool` 相同。

#### 错误响应

开始流式处理前，HTTP 错误使用与 `execute-tool` 相同的 JSON 结构：

- `error`（`object`）：包含以下属性的对象：
  - `message`（`string`）：便于人理解的错误消息。
  - `status`（`number`）：HTTP 状态码。
  - `code`（`string`）：稳定的错误代码。
  - `data`（`object`，可选）：经过清理的结构化上下文。

开始流式处理后，错误会以 NDJSON 事件的形式发送：

- `version`（`number`）：流协议版本。
- `type`（`'error'`）：事件类型。
- `code`（`string`）：稳定的错误代码。
- `status`（`number`）：类似 HTTP 的状态码。
- `message`（`string`）：便于人理解的错误消息。

此端点可能返回或发送：

- `400`，错误代码为 `invalid_request`：请求没有正文。
- `400`，错误代码为 `missing_document_credentials`：JWT 不包含文档服务器凭据。
- `400`，错误代码为 `invalid_stream_message`：流消息不是有效的 JSON、未通过 Schema 验证、使用了不受支持的协议版本，或流以未终止的 NDJSON 行结束。
- `400`，错误代码为 `duplicate_start`：发送了多个 `start` 消息。
- `400`，错误代码为 `delta_before_start`：在 `start` 之前收到了 `delta` 消息。
- `400`，错误代码为 `end_before_start`：在 `start` 之前收到了 `end` 消息。
- `400`，错误代码为 `incomplete_stream`：请求结束时尚未收到 `end` 消息。
- `400`，错误代码为 `thread_not_found` 或 `comment_not_found` 等讨论串存储错误代码：缓冲的讨论串或评论操作引用了不存在的数据。
- `401`，错误代码为 `access_control_auth_required` 或 `missing_token`：请求未包含 Tiptap Access Control JWT。
- `401`，错误代码为 `token_expired` 或 `signature_invalid` 等 Access Control 错误代码：Access Control 拒绝了 JWT。
- `403`，错误代码为 `feature_not_available`：当前环境未启用 Server AI Toolkit。
- `403`，错误代码为 `insufficient_permissions`：JWT 未授予 `AI:Toolkit` 权限。
- `403`，错误代码为 `origin_not_allowed`：当前环境不允许请求中的 `Origin`。
- `403`，错误代码为 `tracked_changes_unsupported_schema`：`reviewOptions.mode` 为 `trackedChanges`，但编辑器 Schema 不支持修订。
- `403`，错误代码为 `thread_schema_not_supported`：编辑器 Schema 不支持评论或讨论串。
- `413`，错误代码为 `ndjson_line_too_long`：单个 NDJSON 行超过了最大长度。
- `429`，错误代码为 `stream_rate_limit_exceeded`：同一客户端打开的并发流过多。
- `429`，错误代码为 `rate_limited`：Access Control 对身份验证进行了速率限制。
- `429`：流式处理开始前，服务器端速率限制器阻止了请求。此响应使用不同的顶层结构：
  - `error`（`string`）：速率限制错误消息。
  - `retryAfter`（`number`，可选）：重试前需要等待的秒数。
  - `limit`（`number`，可选）：当前时间窗口内的请求上限。
  - `window`（`number`，可选）：速率限制窗口的秒数。
- `500`，错误代码为 `diff_worker_failed`、`diff_worker_invalid_result`、`stream_internal_error` 或 `unknown_error`：流处理期间发生意外的服务器错误。
- `500`，错误代码为 `missing_cloud_api_token`：云服务缺少内部身份验证配置。
- `502`，错误代码为 `document_load_failed`、`document_save_failed`、`thread_list_failed` 或 `comment_create_failed` 等文档、讨论串或评论上游故障代码：云文档或评论 API 操作发生上游故障。
- `503`，错误代码为 `diff_worker_queue_timeout`：差异工作器队列已满或超时。
- `503`，错误代码为 `service_unavailable`：Access Control 暂时不可用。
- `504`，错误代码为 `stream_request_timeout`：流处理超出服务器请求超时时间。

## 画板工具

<Callout title="Alpha 功能" variant="hint">
  画板工具目前处于 alpha 阶段
</Callout>

这些工具可以读取和更改[白板](/editor/whiteboard/getting-started/overview)。请在画板编辑器的编辑器上下文中，对画板文档执行这些工具。设置方法请参阅[与白板配合使用](/ai/ai-toolkit/agents/whiteboard)。

画板工具处理的是纯文本，而不是文档内容，因此在所有 `format` 下的工作方式都相同。这些工具无法通过 `stream-tool` 使用。

无法运行的画板工具不会更改任何内容。如果模型能够修正调用问题（例如输入与 Schema 不匹配，或使用了不在画板上的 ID），工具会返回 HTTP 状态 `200`，并在工具输出中返回 `success: false` 和 `error`。

如果请求本身无法执行，`execute-tool` 会像执行其他工具时一样失败：

- `403`，错误代码为 `board_schema_not_supported`：文档或编辑器上下文不是工具可操作的白板，例如在 `createDocFrame` 中使用了不包含文档框架的画板。
- `403`，错误代码为 `tracked_changes_unsupported_schema`：对于会更改画板的工具，`reviewOptions.mode` 为 `'trackedChanges'`，但编辑器上下文不支持修订。`readBoard` 不会检查此项。

### 画板工具配置

`readBoard`、`createShapes`、`createDiagram` 和 `createDocFrame` 接受以下工具配置（`tool.config`）：

- `selectedIds`（`string[]`，可选）：用户选中的形状 ID，按选择顺序排列。
- `viewport`（`{ x: number, y: number, width: number, height: number }`，可选）：用户当前看到的画板部分，以画板单位表示。`width` 和 `height` 必须大于 `0`。

每个缺失、为 `null` 或无效的字段都会分别回退为默认值：无选择或无视口。

### 画板元素的放置

`createShapes`、`createDiagram` 和 `createDocFrame` 的输入（`tool.input`）接受以下字段，AI 可据此指定新内容的位置：

- `near`（`string[]`，可选）：最多 100 个形状 ID；新内容将放在这些形状旁边，例如摘要所涉及的图表旁边。默认为选中的形状。
- `side`（`'right' | 'below' | 'left' | 'above'`，可选）：新内容相对于这些形状的位置。默认为 `'right'`；如果下方的空位更近，则默认为 `'below'`。

新形状会放在画板上 `near` 指定的形状旁边；如果这些形状不在画板上，则放在选中形状旁边。如果没有此类形状，则放在视口中央；如果没有视口，则放在画板所有形状的右侧；如果画板为空，则放在原点。若其他形状挡路，新形状会移动到最近的空位。

### 画板建议

当 `reviewOptions.mode: 'trackedChanges'` 时，画板工具会将更改作为[修订](/tracked-changes/getting-started/overview)建议写入：

- 一次调用添加或删除的形状共用一个建议，因此一次 `acceptSuggestion` 或 `rejectSuggestion` 即可审阅全部形状。
- 每个已更改的形状和每段新文本都会获得各自的建议。同一用户尚待审阅的形状后续更改会并入该建议。
- 对于等待其他用户审阅的形状，或等待审阅其删除操作的形状，工具不会进行更改；对于等待审阅更改的形状，工具也不会删除。工具会在 `skipped` 或 `skippedArrows` 中说明原因。

`suggestionIds`（`string[]`）列出本次调用创建或沿用的建议。沿用的建议还包含之前的更改；对先前建议所添加形状的更改也属于该添加操作，因此不会单独列出。审阅这些 ID 时，其他建议保持不变。如果不进行审阅，`suggestionIds` 为空，工具不会更改任何等待审阅的形状。

  - `color`（`'black' | 'gray' | 'red' | 'orange' | 'yellow' | 'green' | 'blue' | 'violet'`，可选）：便利贴颜色。默认值：`'yellow'`
- `near` 和 `side`（可选）：便利贴的放置位置。请参阅[画板元素的放置](#board-placement)。

工具配置（`tool.config`）：

[画板工具配置](#board-tool-config)。

工具输出（`tool.output`）：

成功响应：

- `success`（`true`）：表示便利贴已添加。
- `createdIds`（`string[]`）：新便利贴的 ID，顺序与输入相同。
- `suggestionIds`（`string[]`）：请参阅[画板建议](#board-suggestions)。

错误响应：

- `success`（`false`）：表示未添加便利贴。
- `error`（`string`）：错误消息。

### `arrangeShapes`

将形状从左到右分组成若干列，每列顶部都有一个自由文本标题。各列从形状所在位置开始；如果会遮挡其他形状，则从最近的空位开始。形状只会移动，因此与其相连的箭头也会随之移动。

工具输入（`tool.input`）：

- `groups`（`array`，必填）：从左到右排列的 1 至 12 个组，ID 总数最多为 300。
  - `title`（`string`，必填）：组标题，最多 60 个字符。
  - `ids`（`string[]`，必填）：组中形状的 ID，按阅读顺序排列。一个形状会加入第一个列出它的组。

工具配置（`tool.config`）：

`null`

工具输出（`tool.output`）：

成功响应：

- `success`（`true`）：表示形状已整理。
- `movedIds`（`string[]`）：已移动形状的 ID。
- `titleIds`（`string[]`）：新标题的 ID。
- `skipped`（`array`）：保持原位的形状，每项包含 `id` 和 `reason`。原因可能是该 ID 不对应画板上的形状、它是箭头、先前的组已列出该 ID，或该形状正在等待其他用户审阅。
- `suggestionIds`（`string[]`）：请参阅[画板建议](#board-suggestions)。

错误响应：

- `success`（`false`）：表示未整理任何形状。错误中会列出原因。
- `error`（`string`）：错误消息。

### `createDiagram`

绘制带文本的形状，用箭头连接，并将它们排布成图表。箭头会连接各个形状，因此用户移动形状时，箭头也会随之移动。

工具输入（`tool.input`）：

- `title`（`string`，可选）：图表上方的标题，最多 80 个字符。
- `direction`（`'down' | 'right'`，可选）：箭头主要指向的方向。默认值：`'down'`
- `nodes`（`array`，必填）：1 至 40 个形状。
  - `key`（`string`，必填）：AI 为形状指定的名称，在图表中最多 40 个字符且必须唯一。箭头会引用此名称。
  - `text`（`string`，必填）：形状中的文本，最多 60 个字符。
  - `shape`（`'rectangle' | 'ellipse' | 'diamond'`，可选）：形状类型。其他类型会转换为矩形。默认值：`'rectangle'`
  - `color`（`string`，可选）：`createShapes` 支持的颜色之一。默认值：`'black'`
- `arrows`（`array`，可选）：最多 60 个箭头。
  - `from`（`string`，必填）：箭头起始形状的键。
  - `to`（`string`，必填）：箭头所指向形状的键。
  - `label`（`string`，可选）：箭头旁的标签，最多 24 个字符。
- `near` 和 `side`（可选）：图表的放置位置。请参阅[画板元素的放置](#board-placement)。

工具配置（`tool.config`）：

[画板工具配置](#board-tool-config)。

工具输出（`tool.output`）：

成功响应：

- `success`（`true`）：表示图表已绘制。
- `createdIds`（`string[]`）：所有新形状的 ID，包括标题、形状、箭头及其标签。
- `nodeIds`（`Record<string, string>`）：按键映射的每个新形状的 ID。
- `skippedArrows`（`array`）：未添加的箭头，每项包含 `from`、`to` 和 `reason`。如果箭头使用了未知键、从某个形状指向自身，或与先前的箭头重复，则会被省略。
- `suggestionIds`（`string[]`）：请参阅[画板建议](#board-suggestions)。

错误响应：

- `success`（`false`）：表示未绘制图表。
- `error`（`string`）：错误消息。

### `updateShapes`

更改形状的文本、颜色或类型。形状的位置和大小保持不变。

工具输入（`tool.input`）：

- `shapes`（`array`，必填）：1 至 40 个形状，每个形状仅出现一次，并且只包含需要更改的内容。
  - `id`（`string`，必填）：形状的 ID。
  - `text`（`string`，可选）：新文本，最多 500 个字符，换行规则与 `createShapes` 相同。文本会替换形状文本，但不保留其格式。若 `readBoard` 返回的形状文本与此相同，则不会进行更改。只有便利贴、几何形状和自由文本可以包含文本。
  - `color`（`string`，可选）：新颜色，必须是 `createShapes` 支持的颜色之一。
  - `kind`（`'rectangle' | 'ellipse' | 'diamond' | 'triangle'`，可选）：几何形状的新类型。

工具配置（`tool.config`）：

`null`

工具输出（`tool.output`）：

成功响应：

- `success`（`true`）：表示至少一个形状已更改。
- `updatedIds`（`string[]`）：已更改形状的 ID。
- `skipped`（`array`）：保持原样的形状，每项包含 `id` 和 `reason`。原因可能是该形状正在等待其他用户审阅，或该形状不包含文本但请求为其设置了文本。
- `suggestionIds`（`string[]`）：请参阅[画板建议](#board-suggestions)。

错误响应：

- `success`（`false`）：表示未更改任何形状。错误中会列出原因。
- `error`（`string`）：错误消息。
