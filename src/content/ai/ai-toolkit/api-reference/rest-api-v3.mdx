Server AI Toolkit 提供用于 AI 代理工具的 REST API 端点。

<Callout title="已弃用的端点" variant="warning">
  这些 API 端点已弃用，请参阅[新版 API 端点](/ai/ai-toolkit/api-reference/rest-api)。
</Callout>

<Callout title="向后兼容性" variant="warning">
  旧版 API 名称（例如 `schemaAwarenessData`、`getSchemaAwarenessData`、
  `/v3/ai/toolkit/tools` 和 `/v3/ai/toolkit/schema-awareness-prompt`）仍可使用以保持向后兼容，但已弃用。新集成请使用 `editorContext`、`getEditorContext` 和
  `/v3/ai/toolkit/tools`。
</Callout>

## 身份验证

所有请求都必须包含：

- `Authorization: Bearer <JWT>`
- `X-App-Id: <APP_ID>`

在服务器端使用 AI 密钥生成 JWT。请前往 [Server AI Toolkit 设置](https://cloud.tiptap.dev/v2/cloud/ai)页面获取 App ID 和密钥。

```ts
import jwt from 'jsonwebtoken'

const JWT_TOKEN = jwt.sign(
  {
    experimental_document_server_id: 'your-document-server-id',
    experimental_document_server_management_api_secret:
      'your-document-server-management-api-secret',
  },
  'your-ai-secret-key',
  { expiresIn: '1h' },
)
```

如需了解详情，请参阅[授权指南](/ai/ai-toolkit/install#set-up-authorization)。

这些端点也接受新版[身份验证](/authentication)。例外情况是 `stream-tool`：它要求使用新版身份验证，不接受旧版令牌。

### Document Server 凭据

如果希望 Server AI Toolkit 自动获取并保存 Tiptap Cloud 文档，请在 JWT 中包含以下声明：

- `experimental_document_server_id`
- `experimental_document_server_management_api_secret`

## 基础 URL

托管服务的基础 URL 为：

```txt
https://api.tiptap.dev
```

以下示例中的请求使用 `BASE_URL/v3/ai/...` 格式。

## 如何提供文档

工具端点只接受以下一种文档来源：

- `document`：内联 Tiptap JSON
- `experimental_documentOptions`：Tiptap Cloud 文档引用

`experimental_documentOptions` 的结构如下：

- `documentId`（`string`，必填）：Tiptap Cloud 文档标识符。
- `userId?`（`string | null`，可选）：用于标记 AI 所做编辑的标识符。
- `field?`（`string | null`，可选，默认值：`"default"`）：省略或设为 `null` 时，将定位到文档中的特定协作字段（Y.js XML 片段）。如果你的文档在同一 `documentId` 下存储了多个可编辑字段（例如标题和正文分别存储），请使用此字段。

使用 Tiptap Cloud 文档的示例：

```json
{
  "experimental_documentOptions": {
    "documentId": "your-document-id",
    "userId": "ai-assistant"
  }
}
```

指定非默认协作字段的示例：

```json
{
  "experimental_documentOptions": {
    "documentId": "your-document-id",
    "userId": "ai-assistant",
    "field": "title"
  }
}
```

使用内联文档的示例：

```json
{
  "document": {
    "type": "doc",
    "content": []
  }
}
```

<Callout title="线程需要云文档" variant="info">
  线程和评论端点始终需要 `experimental_documentOptions.documentId`。
</Callout>

## 格式

大多数端点都接受 `format` 字段：

- `"json"`：标准 JSON 表示形式
- `"shorthand"`：Tiptap Shorthand，一种适用于提示词和模型输出的高效令牌格式
- `"shorthandV2"`：Tiptap Shorthand V2，一种适用于提示词和模型输出的高效令牌格式

## 工具端点

### 获取工具定义

```txt
POST /v3/ai/toolkit/tools
```

返回 AI 代理可用的[工具定义](#available-tools)。

请求正文：

- `editorContext`（`EditorContext`，必填）。通过 `getEditorContext` 函数获取的编辑器上下文。请参阅[安装指南](/ai/ai-toolkit/install)。
- `tools?`（`Record<string, boolean>`，可选）：启用或禁用单个工具。支持的键请参阅[工具参考](#available-tools)。
- `operationMeta?`（`string`，可选，默认值：`""`）
- `format?`（`'json' | 'shorthand' | 'shorthandV2'`，可选，默认值：`'json'`）
- `schemaAwarenessData?`（`SchemaAwarenessData`，可选，已弃用）：请改用 `editorContext`。为保持向后兼容，仍支持此字段。

响应：

- `prompt`（`string`）：将此内容添加到 AI 请求的系统提示词中。它会向 AI 说明 Tiptap 文档的工作方式、文档可能包含的元素，以及文档格式的工作方式。
- `tools`（`array`）
  - `name`（`string`）
  - `description`（`string`）
  - `inputSchema`（`object`）：AI 生成的工具 `input` 的 JSON Schema。

### 执行工具

```txt
POST /v3/ai/toolkit/execute-tool
```

执行一个 Server AI Toolkit 工具，例如 `tiptapRead`、`tiptapEdit`、`getThreads` 或
`editThreads`。所有支持的工具及其类型结构请参阅[工具参考](#available-tools)。

请求正文：

- `toolName`（`string`，必填）
- `input`（必填）：AI 模型生成的工具输入。其结构取决于 `toolName`；请参阅[工具参考](#available-tools)。
- `editorContext`（`EditorContext`，必填；提供 `schemaAwarenessData` 时除外）
- `schemaAwarenessData?`（`SchemaAwarenessData`，可选，已弃用）：请改用 `editorContext`。为保持向后兼容，仍支持此字段。
- `toolConfig?`（可选）：由开发者提供的工具专用参数，而不是由 AI 模型提供。请参阅[工具参考](#available-tools)。
- `format?`（`'json' | 'shorthand' | 'shorthandV2'`，可选，默认值：`'json'`）
- `reviewOptions?`（[`ReviewOptions`](/ai/ai-toolkit/api-reference/review-options)，可选，默认值：`{ mode: 'disabled' }`）
- `experimental_commentsOptions?`（`{ threadData?: Record<string, unknown>, commentData?: Record<string, unknown> }`，可选）：在线程相关的工具执行期间，为新建的线程和评论附加的元数据。
- 以下两项中必须且只能提供一项：
  - `document`
  - `experimental_documentOptions`

响应：

- `output`：供 AI 模型读取的工具响应。请参阅[工具参考](#available-tools)。
- `toolResult`：面向开发者解析的工具响应格式。AI 不应读取此字段。请参阅[工具参考](#available-tools)。
- `docChanged`（`boolean`）：工具调用是否导致文档发生变化
- `before`（`object`）：工具运行前的文档；始终返回
- `document`（`object | null`）：工具运行后的文档；如果文档没有变化，则为 `null`

### 流式执行工具

```txt
POST /v3/ai/toolkit/stream-tool
```

以流式方式执行工具。请求结构与 `POST /v3/ai/toolkit/execute-tool` 相同。流式响应格式仍在最终确定中。

此端点通过实时连接处理文档，因此可能返回 REST 端点不会返回的连接和并发错误。这些错误会作为响应流中的 `error` 事件发送，详见[流式传输和会话错误](#streaming-and-session-errors)。

## 错误处理

REST 端点返回的错误结构如下：

```json
{
  "error": {
    "message": "Human-readable description of what went wrong.",
    "status": 502,
    "code": "document_load_failed"
  }
}
```

- `message`（`string`）：人类可读的说明。不要根据此字段进行匹配，因为措辞可能会更改。
- `status`（`number`）：HTTP 状态码，响应中也会设置此值。
- `code`（`string`）：可用于分支处理的稳定标识符。验证失败时使用 `code: "validation_failed"`，并附带 `issues` 数组。

API 使用标准 HTTP 错误码：

- `400 Bad Request`：正文无效、格式无效、缺少文档来源或缺少 Document Server 凭据
- `401 Unauthorized`：缺少或无效的 JWT 或 App ID
- `404 Not Found`：端点或工具未知
- `422 Unprocessable Entity`：验证失败
- `429 Too Many Requests`：重复请求或触发速率限制保护
- `500 Internal Server Error`：意外的服务器错误
- `502 Bad Gateway`：加载或保存 Tiptap Cloud 文档失败

### 流式传输和会话错误

[`POST /v3/ai/toolkit/stream-tool`](#stream-a-tool) 通过实时连接处理 Tiptap Cloud 文档：它会实时加入文档，使 AI 能与其他协作者一起编辑最新内容。建立或使用连接时发生的错误会以内嵌方式作为响应流中的 `error` 事件发送，而不是作为 HTTP 状态返回：

```json
{ "type": "error", "code": "concurrent_edit_conflict", "status": 409, "message": "..." }
```

`status` 字段与对应的 HTTP 状态码一致。可能的 `code` 值如下：

| `code`                        | `status` | 发生时机                                                                                                                             | 处理方式                                                                                                                                                  |
| ----------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `concurrent_edit_conflict`    | 409      | 工具运行期间文档发生了更改（例如用户进行了编辑），因此无法在过时内容上应用更改。 | 重新运行请求。AI 会在下次尝试时读取最新内容。可以安全地自动重试。请参阅[处理并发编辑](#handle-concurrent-edits)。 |
| `schema_mismatch`             | 409      | 请求中的编辑器 Schema 与此文档当前使用的 Schema 不匹配，或者无法使用该 Schema 解析存储的文档。 | 为同一文档发送一致的 `editorContext` Schema。不要使用相同的 Schema 重试。                                                              |
| `websocket_auth_failed`       | 401      | 打开连接时，Tiptap Cloud 拒绝了文档凭据。                                                                 | 刷新 Document Server JWT 声明，然后重试。不要使用相同的令牌重试。                                                                           |
| `websocket_connection_failed` | 502      | 初始同步完成前，与 Tiptap Cloud 的连接已关闭。                                                                    | 采用退避策略重试。检查网络连接和 Tiptap Cloud 状态。                                                                                                |
| `websocket_sync_timeout`      | 504      | 文档未能在时限内完成初始同步。                                                                          | 采用退避策略重试。大型文档和网络连接质量下降会增加此情况发生的可能性。                                                                           |
| `session_limit_reached`       | 503      | 服务器正在处理的并发文档会话已达上限。                                                                  | 采用退避策略重试。会话空闲后会释放。                                                                                                     |
| `session_creation_cancelled`  | 503      | 会话在连接完成前被终止，通常发生在服务器重启期间。                                                   | 重试。                                                                                                                                                         |

<Callout title="仅适用于 Tiptap Cloud 文档" variant="info">
  这些错误只会出现在 `stream-tool` 使用的实时连接路径中。发送内联 `document` 的请求不会打开连接，因此不会返回会话或 WebSocket 错误。
</Callout>

### 处理并发编辑

在协作文档中，`concurrent_edit_conflict` 是预期会发生的情况。AI 读取文档、调用模型并写入更改期间，用户可能会编辑同一文档。工具包不会覆盖用户的编辑，而是拒绝写入，以免丢失任何内容。

请将其视为可安全重试的信号：收到 `code: "concurrent_edit_conflict"` 的 `error` 事件时，请再次运行相同的工具调用。工具包会重新读取文档，因此 AI 将基于用户的最新更改进行操作。请限制重试次数，避免在频繁编辑的文档上陷入长时间循环。

```ts
// `runStream` 发送 start/delta/end 消息，并解析为流中的最终
// `error` 事件；如果流成功完成，则解析为 `null`。
async function streamToolWithRetry(body: unknown, maxRetries = 3) {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    const error = await runStream(body)

    if (!error) {
      return // completed successfully
    }
    if (error.code !== 'concurrent_edit_conflict') {
      throw new Error(`stream-tool failed: ${error.code}`)
    }
    // Document changed mid-flight — retry with the latest content.
  }

  throw new Error('Tool call kept conflicting with concurrent edits.')
}
```

`null`

#### 工具配置（`toolConfig`）

`null`

`null`

### `getThreads`

读取已持久化的评论线程、线程中的评论及其在文档中的位置。

<Callout title="需要 Tiptap Cloud 文档" variant="warning">
  由于线程存储在 Tiptap Document Server 上，此工具需要在请求正文中提供 `experimental_documentOptions`。请传入指向 Tiptap Cloud 文档的 `documentId`。

#### 工具配置（`toolConfig`）

`null`

#### 工具输入（`toolInput`）

- `from`（`number`）：要读取的第一个线程的从零开始的索引。

#### 工具输出（`toolOutput`）

成功响应：

- `success`（`true`）：表示读取请求成功。
- `totalThreadCount`（`number`）：文档中的线程总数。
- `threadRange`（`[number, number]`）：读取的线程范围，格式为 `[from, to)`。
- `threads`（`array`）：返回的线程对象。
  - `id`（`string`）：唯一线程标识符。

    - `content`（`string`）：评论文本。

    - `createdAt`（`string`）：评论创建时间的 ISO 时间戳。
    - `updatedAt`（`string`）：评论最后更新时间的 ISO 时间戳。
  - `resolvedAt?`（`string | null`）：线程解决时间的 ISO 时间戳；如果尚未解决，则为 `null`。
  - `createdAt`（`string`）：线程创建时间的 ISO 时间戳。
  - `updatedAt`（`string`）：线程最后更新时间的 ISO 时间戳。
  - `data?`（`Record<string, unknown>`）：公开线程元数据。

- `success`（`false`）：表示读取请求失败。
- `error`（`string`）：错误消息。
- `totalThreadCount?`（`number`）：已持久化线程的总数（如果已知）。

`null`
