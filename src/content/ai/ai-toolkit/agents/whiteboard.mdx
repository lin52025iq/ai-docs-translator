让 AI 代理在[白板](/editor/whiteboard/getting-started/overview)上工作。Server AI Toolkit 的白板工具可以添加便笺、绘制图表、将便笺分组到列中、连接、修改和删除形状，还可以添加用于容纳较长文本的文档框。它们会修改白板的 Tiptap Cloud 文档，因此白板上的所有用户都能实时看到更改。

<Callout title="独立产品" variant="info">
  [Whiteboard](/editor/whiteboard/getting-started/overview) 是与 Server AI Toolkit 分开销售的 Tiptap 产品。
</Callout>

<Callout title="实验性功能" variant="warning">
  [Whiteboard](/editor/whiteboard/getting-started/overview) 扩展目前处于 Alpha 阶段。
</Callout>

<Callout title="接续 AI 代理聊天机器人指南" variant="info">

</Callout>

## 工作原理

1. AI 使用 `readBoard` 读取白板内容：包括形状、形状之间的箭头，以及用户选中的形状。
2. AI 使用其他白板工具（如 `createShapes` 和 `createDiagram`）修改白板。AI 不会提供坐标。工具会调整新形状的大小，并将它们放在 AI 指定的形状或选区旁边；如果没有指定，则放在用户视图中央的空白处，不会遮挡其他形状。
3. 每个文档框都显示一个独立文档，并对应自己的 Tiptap Cloud 文档。AI 使用 `tiptapRead` 和 `tiptapEdit` 读写该文档。
4. 使用 `reviewOptions` 后，更改会成为 [Tracked Changes](/tracked-changes/getting-started/overview) 建议，用户可以在白板上接受或拒绝这些建议。

## 设置白板

白板工具会操作白板的 Tiptap Cloud 文档。为白板的编辑器启用协作功能，详见[白板协作](/editor/whiteboard/guides/collaboration)。然后从该编辑器获取编辑器上下文，并像 AI 代理聊天机器人指南中那样，随每条聊天消息一起发送：

```ts
import { getEditorContext } from '@tiptap/ai-toolkit'

// The board's editor, with WhiteboardKit and BoardCollaboration
const boardEditorContext = getEditorContext(editor)
```

白板工具不会根据节点的哈希值定位节点，因此白板编辑器不需要 `ServerAiToolkit` 扩展。

## 启用白板工具

获取工具定义时，使用白板的编辑器上下文来启用白板工具：

```ts
import { getAuthHeaders } from '@/lib/server-ai-toolkit/get-auth-headers'

const response = await fetch(`${apiBaseUrl}/v4/ai/toolkit/fetch-tools`, {
  method: 'POST',
  headers: await getAuthHeaders(),
  body: JSON.stringify({
    editorContext: boardEditorContext,
    tools: {
      readBoard: true,
      createShapes: true,
      arrangeShapes: true,
      createDiagram: true,
      updateShapes: true,
      deleteShapes: true,
      connectShapes: true,
      createDocFrame: true,
    },
  }),
})
```

只启用代理所需的工具。例如，没有 `deleteShapes`，AI 就无法删除形状。

白板工具接收纯文本，而非文档内容，因此在所有 `format` 中的工作方式都相同。工具描述会告诉 AI 如何使用这些工具，因此本次请求不需要 `systemPrompt`。白板工具无法通过 `stream-tool` 使用。

## 执行白板工具

在白板的文档上执行白板工具。`tool.config` 会告知工具用户选中了什么以及看到了什么：

```ts
const result = await fetch(`${apiBaseUrl}/v4/ai/toolkit/execute-tool`, {
  method: 'POST',
  headers: await getAuthHeaders(documentId),
  body: JSON.stringify({
    editorContext: boardEditorContext,
    document: { type: 'cloud', id: documentId },
    user: 'ai-assistant',
    tool: {
      name: toolName,
      input,
      // What the user selected and saw when they sent the message
      config: { selectedIds, viewport },
    },
  }),
})
```

- `selectedIds` 是用户选中的形状。`readBoard` 会首先列出这些形状及其完整文本，因此 AI 知道“这些便笺”指的是哪些形状。新形状会放在它们右侧；如果下方更近，则放在下方。
- `viewport` 是用户当前看到的白板区域，以白板单位表示。如果没有选区，新形状会放在该区域中央。

如果两者都未提供，新形状会放在白板上所有形状的右侧；如果白板为空，则放在原点。缺失、为 `null` 或无效的值会分别独立回退。AI 也可以在 `near` 中指定形状，让摘要放在对应图表旁边。请参阅[白板元素的放置](/ai/ai-toolkit/api-reference/rest-api#board-placement)。

用户发送消息时，在浏览器中读取这两个值并一并发送：

```ts
import { getSelectedShapeIds, visibleBoardRect } from '@tiptap-pro/extension-whiteboard'

sendMessage(
  { text: input },
  {
    body: {
      editorContext: boardEditorContext,
      selectedIds: getSelectedShapeIds(editor.state),
      viewport: visibleBoardRect({
        // Your app's camera, and the stage element around the board
        camera,
        viewport: { width: stage.clientWidth, height: stage.clientHeight },
      }),
    },
  },
)
```

用户在聊天中输入时，白板会保留当前选区，因此无需再次聚焦白板。

如果用户在工具运行期间修改白板，`execute-tool` 可能会返回 `409` 和 `concurrent_edit_conflict`，且不做任何更改。请重新运行该工具。服务器会在 Tiptap Cloud 文档的 `default` 字段中执行此检查。在其他 `field` 中，服务器会直接保存，不执行检查。如果文档或编辑器上下文不是白板，服务器会返回 `403` 和 `board_schema_not_supported`。

## 编写文档框中的文档

每个文档框都显示一个独立文档。`createDocFrame` 会添加一个包含新空文档的文档框，并返回其 `docId`；`readBoard` 会列出每个文档框的 `docId`。随后，AI 使用 `tiptapRead` 和 `tiptapEdit` 读写文档。

### 将文档保存在 Tiptap Cloud 中

AI 服务器会在 Tiptap Cloud 中写入这些文档。请将文档框所用的扩展放在浏览器和服务器共享的模块中，因为服务器需要使用相同的 schema。添加 `ServerAiToolkit` 扩展，因为文档工具会根据节点的哈希值定位节点：

```ts
// lib/whiteboard-docs.ts, shared by the browser and the server
import { ServerAiToolkit } from '@tiptap/ai-toolkit'
import StarterKit from '@tiptap/starter-kit'

export const docExtensions = [StarterKit.configure({ undoRedo: false }), ServerAiToolkit]

// The name of the Tiptap Cloud document of a frame, on the board `documentId`
export const frameDocumentName = (documentId: string, docId: string) => `${documentId}/doc/${docId}`
```

在浏览器中，将每个文档框的编辑器连接到其 `docId` 对应的 Tiptap Cloud 文档：

```ts
import { Editor } from '@tiptap/core'
import { Collaboration } from '@tiptap/extension-collaboration'
import type { CreateDocEditorOptions } from '@tiptap-pro/extension-whiteboard'
import { TiptapCollabProvider } from '@tiptap-pro/provider'
import * as Y from 'yjs'
import { docExtensions, frameDocumentName } from '@/lib/whiteboard-docs'

function createEditor({ element, docId }: CreateDocEditorOptions) {
  const document = new Y.Doc()
  const provider = new TiptapCollabProvider({
    name: frameDocumentName(documentId, docId),
    appId,
    token,
    document,
  })

  return new Editor({
    element,
    extensions: [...docExtensions, Collaboration.configure({ document })],
    onDestroy: () => provider.destroy(),
  })
}
```

在 `WhiteboardKit` 的 `docs` 选项中使用 `createEditor`。有关 `copy` 和 `start`，请参阅[文档框](/editor/whiteboard/guides/doc-frames)。AI 添加的文档框会通过 Yjs 创建，因此不会运行 `start`。`createEditor` 会根据文档框的 `docId` 打开其文档，并显示 AI 写入的内容。

浏览器的 `token` 必须同时允许访问文档框中的文档，而不只是白板文档。使用[前缀约束](/authentication#constraints)，允许名称以 `${documentId}/doc/` 开头的文档：

```ts
permissions: [
  { action: 'Documents:Write', resource: documentId },
  { action: 'Documents:Write', resource: '*', constraints: { prefix: `${documentId}/doc/` } },
],
```

每个 provider 都会单独建立连接。如需通过一个连接打开所有文档框中的文档，请参阅[多路复用](/hocuspocus/provider/examples#multiplexing)。

### 为文档工具提供 `docId`

文档工具一次只处理一个文档。在服务器上，使用包含 `docExtensions` 的编辑器获取文档框中文档的编辑器上下文。请提供 JSON 内容，因为默认内容是需要浏览器的 HTML：

```ts
import { getEditorContext } from '@tiptap/ai-toolkit'
import { Editor } from '@tiptap/core'
import { docExtensions } from '@/lib/whiteboard-docs'

// Only for the schema of the frames' documents
const docEditor = new Editor({
  extensions: docExtensions,
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
})
const docEditorContext = getEditorContext(docEditor)
docEditor.destroy()
```

然后使用该编辑器上下文获取 `tiptapRead` 和 `tiptapEdit`。在它们的输入中添加 `docId`，并在该 `docId` 对应的文档上执行工具：

```ts
import { tool } from 'ai'
import z from 'zod'
import { executeTool } from '@/lib/server-ai-toolkit/execute-tool'
import { getToolDefinitions } from '@/lib/server-ai-toolkit/get-tool-definitions'
import { frameDocumentName } from '@/lib/whiteboard-docs'

// tiptapRead and tiptapEdit, and the prompt about the format of the documents
const { prompt: docsPrompt, tools: docToolDefinitions } = await getToolDefinitions(docEditorContext)

const docTools = Object.fromEntries(
  docToolDefinitions.map((definition) => [
    definition.name,
    tool({
      description: definition.description,
      inputSchema: z.fromJSONSchema({
        ...definition.inputSchema,
        properties: {
          docId: {
            type: 'string',
            description: 'The docId of the doc frame, from readBoard or createDocFrame.',
          },
          ...definition.inputSchema.properties,
        },
        required: ['docId', ...(definition.inputSchema.required ?? [])],
      }),
      strict: false,
      execute: async (toolInput) => {
        const { docId, ...input } = toolInput as Record<string, unknown>

        // The docId comes from the AI, and becomes part of a document name
        if (typeof docId !== 'string' || !/^[\w-]+$/.test(docId)) {
          return { success: false, error: 'Use the docId of a doc frame, from readBoard.' }
        }

        try {
          const result = await executeTool(
            definition.name,
            input,
            frameDocumentName(documentId, docId),
            docEditorContext,
          )
          return result.tool.output
        } catch (error) {
          console.error(`Failed to execute tool ${definition.name}:`, error)
          return { error: error instanceof Error ? error.message : 'Unknown error' }
        }
      },
    }),
  ]),
)
```

将这些工具与白板工具一并提供给 AI，并将 `docsPrompt` 添加到代理的指令中，让 AI 了解这些文档的格式。

白板会根据文档内容绘制相应高度的文档框，但存储的高度仍是 `createDocFrame` 根据其 `lines` 输入设定的高度。箭头、选区和元素放置都会使用存储的高度。白板只会在自身用户进行更改后更新该高度，因此只有用户编辑文档后，高度才会改变。

## 审核 AI 的更改

按照[白板上的 Tracked Changes](/editor/whiteboard/guides/tracked-changes)中的说明，将 Tracked Changes 添加到白板编辑器，并发送该编辑器的编辑器上下文。然后在执行白板工具时传入 `reviewOptions`：

```ts
reviewOptions: {
  mode: 'trackedChanges',
  trackedChangesOptions: {
    userId: 'ai-assistant',
    userMetadata: { name: 'AI Assistant' },
  },
},
```

这样，白板工具会将更改作为建议提出，而不是直接应用：

- 新形状会成为 `add` 建议。移动、颜色和类型会成为包含旧值和新值的 `attributeChange` 建议；新文本则会作为建议替换旧段落。
- 被删除的形状会保留在白板上，并带有 `delete` 建议，直到用户接受该建议。待处理建议添加的形状会立即显示。
- 一次调用添加或删除的形状会共用一个建议，因此一次 `acceptSuggestion` 或 `rejectSuggestion` 操作即可审核它们。
- 每个被更改的形状和每段新文本都会各自生成一条建议。`suggestionIds` 会列出本次调用创建或沿用的建议；要审核整次调用的更改，请审核所有这些建议。本次调用沿用的建议还包含对同一形状先前所做的更改。
- 如果某个形状正在等待其他用户审核，工具会保持该形状不变，并在 `skipped` 中说明原因。
- 如果建议新增、删除或更改了某个形状，`readBoard` 会为该形状标记 `suggestion`；即使只有文本在等待审核，也会如此。

如果编辑器上下文中没有 Tracked Changes，`execute-tool` 会像文档工具那样返回 `403` 和 `tracked_changes_unsupported_schema`，且不做任何更改，而不是直接修改白板。如果没有 `reviewOptions`，工具会直接修改白板，并保持所有正在等待审核的形状不变。

对于文档框中的文档，请将 `TrackedChanges` 添加到 `docExtensions`，确保文档框的编辑器和 `docEditorContext` 都包含该扩展。否则，`execute-tool` 会返回 `403` 和 `tracked_changes_unsupported_schema`。然后，通过将相同的 `reviewOptions` 添加到 `executeTool` helper 的请求正文中，将其传递给文档工具。请参阅[与 Tracked Changes 配合使用](/ai/ai-toolkit/agents/tracked-changes)。AI 在同一响应中创建的文档可以跳过审核，因为其文档框本身已经处于等待审核状态。

## 限制

- 工具只会添加白板自身支持的形状：便笺、几何形状、自由文本、箭头和文档框。`readBoard` 会列出所有具有 id 和边界框的形状。
- 服务器无法测量浏览器中的字体，因此工具会估算标题、标签和文档框的高度。白板只会测量自身用户所做的更改，因此这些高度会保持不变，直到用户编辑文本。
- 箭头是连接其两端形状中心的直线，因此较长的箭头可能会穿过其他形状。箭头的标签是自由文本形状；用户移动箭头两端的形状时，标签会留在原处。
- `readBoard` 最多列出 300 个形状和箭头，并将选中的形状列在最前面。其他形状的文本超过 280 个字符时会被截断。
- 服务器会通过比较整个白板，将一次调用写入白板的 Yjs 文档。当一次调用删除某个形状并更改后续形状时（例如 `deleteShapes` 清除箭头端点），如果用户同时编辑了中间的形状，这些用户编辑可能会丢失或应用到其他形状上。
