工作流是指 AI 模型执行单一且定义明确的任务的场景。AI Toolkit 内置了以下工作流：

- [插入内容](/ai/ai-toolkit/client/workflows/insert-content)。
- [校对](/ai/ai-toolkit/client/workflows/proofreader)。
- [Tiptap Edit](/ai/ai-toolkit/client/workflows/tiptap-edit)。
- [评论](/ai/ai-toolkit/client/workflows/comments)。
- [模板](/ai/ai-toolkit/client/workflows/template)。

以下是支持这些内置工作流的方法的 API 参考。

## `createProofreaderWorkflow`（服务端工具）

创建现成的校对工作流配置。返回系统提示词以及用于验证 AI 输出的 schema。

该工作流要求用户提示词为 JSON 对象，包含以下字段：

- `content`：要校对的文档内容（如何获取，请参阅客户端设置部分）
- `task`：描述要完成任务的字符串
- `context`：（可选）与任务相关的其他上下文或背景信息

### 返回值

- `systemPrompt`（`string`）：可直接使用的系统提示词，用于指示 AI 模型如何生成校对操作
- `zodOutputSchema`（`ZodObject`）：用于验证 AI 输出的 Zod schema
- `jsonOutputSchema`（`object`）：用于验证 AI 输出的 JSON schema

`systemPrompt` 字段包含一个可直接使用的示例提示词，其中设置了合理的默认值。建议阅读并根据需要进行修改。

### 示例

```ts
import { createProofreaderWorkflow } from '@tiptap-pro/client-ai-toolkit-tool-definitions'
import { Output, streamText } from 'ai'
import { openai } from '@ai-sdk/openai'

// Get the content from the API endpoint request
const { content } = apiEndpointRequest

// Create and configure the workflow
const workflow = createProofreaderWorkflow()

const result = streamText({
  model: openai('gpt-5.6-luna'),
  // System prompt
  instructions: workflow.systemPrompt,
  // User message with the content and the task
  prompt: JSON.stringify({
    content,
    task: 'Correct all grammar and spelling mistakes',
    context: 'This is a formal business document',
  }),
  output: Output.object({ schema: workflow.zodOutputSchema }),
})
```

## `createInsertContentWorkflow`（服务端工具）

创建用于插入或替换内容的现成工作流配置。返回供 AI 模型使用的系统提示词。

该工作流要求用户提示词为包含以下属性的 JSON 对象：

- `task`：要完成的任务
- `replace`：要替换的 HTML 内容（可选）
- `before`：前面的 HTML 内容（可选）
- `after`：后面的 HTML 内容（可选）

### 返回值

- `systemPrompt`（`string`）：可直接使用的系统提示词，用于指示 AI 模型如何生成 HTML 内容

`systemPrompt` 字段包含一个可直接使用的示例提示词，其中设置了合理的默认值。建议阅读并根据需要进行修改。

### 示例

```ts
import { createInsertContentWorkflow } from '@tiptap-pro/client-ai-toolkit-tool-definitions'
import { createTextStreamResponse, streamText, toTextStream } from 'ai'
import { openai } from '@ai-sdk/openai'

// Get the task and selection from the API endpoint request
const { task, replace } = apiEndpointRequest

// Create and configure the workflow
const workflow = createInsertContentWorkflow()

const result = streamText({
  model: openai('gpt-5.6-luna'),
  // System prompt
  instructions: workflow.systemPrompt,
  // User message with the task and content in a JSON object
  prompt: JSON.stringify({
    task,
    replace,
  }),
})

return createTextStreamResponse({ stream: toTextStream({ stream: result.stream }) })
```

## `proofreaderWorkflow`

将一组校对操作应用于文档。

### 参数

- `options`（`ProofreaderWorkflowOptions`）：配置选项
  - `hasFinished`（`boolean`）：流式传输是否已完成。操作仍在流式传输时传入 `false`，最后一次调用时传入 `true`。
  - `operations`（`PartialProofreaderOperation[]`）：校对操作数组。
  - `workflowId`（`unknown`）：本次工作流运行的唯一 ID
  - `reviewOptions?`（[`ReviewOptions`](/ai/ai-toolkit/client/api-reference/review-options)）：控制预览/审阅行为。[查看可用选项](/ai/ai-toolkit/client/api-reference/review-options)。
    - 在此方法中，`diffUtilityOptions.groupInlineChanges` 默认值为 `2`，而不是 `1`，因此默认以内联变更的形式显示编辑内容。
    - 安装了 [Tracked Changes](/tracked-changes/getting-started/overview) 扩展时，支持 `mode: 'trackedChanges'`。
  - `range?`（`Range`）：要对其应用校对操作的范围
    - `from`（`number`）：起始位置
    - `to`（`number`）：结束位置

### 返回值（`ProofreaderWorkflowResult`）

- `doc`（`Node`）：应用操作后修改的文档
- `operationResults`（`OperationResult[]`）：操作结果数组，顺序与输入操作相同。每个结果包含：
  - `target`（`string`）：与操作结果关联的目标哈希
  - `success`（`boolean`）：操作是否成功
  - `error`（`string | null`）：操作失败时的错误消息，否则为 `null`

### 示例

```ts
const toolkit = getAiToolkit(editor)

// Get the document in a format that allows the AI to make fast, efficient edits
const readResult = toolkit.tiptapRead()

const operations = await callApiEndpoint({ content: readResult.content })

// Apply proofreading corrections
const result = toolkit.proofreaderWorkflow({
  hasFinished: true,
  operations,
  workflowId: 'proofread-123',
  reviewOptions: {
    mode: 'preview',
  },
})
```

## `createTiptapEditWorkflow`（服务端工具）

创建用于编辑文档的现成工作流配置。返回系统提示词以及用于验证 AI 输出的 schema。

该工作流要求用户提示词为 JSON 对象，包含以下字段：

- `content`：要编辑的文档内容（通过 `tiptapRead` 获取）
- `task`：描述要完成的编辑任务的字符串
- `context`：（可选）与任务相关的其他上下文或背景信息

### 返回值

- `systemPrompt`（`string`）：可直接使用的系统提示词，用于指示 AI 模型如何生成编辑操作
- `zodOutputSchema`（`ZodObject`）：用于验证 AI 输出的 Zod schema。此 schema 会验证模型返回的流式 `operations` 对象。
- `jsonOutputSchema`（`object`）：用于验证 AI 输出的 JSON schema

### 示例

```ts
import { createTiptapEditWorkflow } from '@tiptap-pro/client-ai-toolkit-tool-definitions'
import { Output, streamText } from 'ai'
import { openai } from '@ai-sdk/openai'

// Get the content and task from the API endpoint request
const { content, task } = apiEndpointRequest

// Create and configure the workflow
const workflow = createTiptapEditWorkflow()

const result = streamText({
  model: openai('gpt-5.6-luna'),
  instructions: workflow.systemPrompt,
  prompt: JSON.stringify({ content, task, context }),
  output: Output.object({ schema: workflow.zodOutputSchema }),
})
```

## `tiptapEditWorkflow`

将一组编辑操作应用于文档。

### 参数

- `options`（`TiptapEditWorkflowOptions`）：配置选项
  - `hasFinished`（`boolean`）：流式传输是否已完成。操作仍在流式传输时传入 `false`，最后一次调用时传入 `true`。
  - `operations`（`PartialTiptapEditOperation[]`）：编辑操作数组。每个操作都是包含以下属性的对象：
    - `type`：`'replace'` | `'insertBefore'` | `'insertAfter'`
    - `target`：节点的 6 字符哈希（来自 `tiptapRead`），或表示整个文档的 `'doc'`
    - `content`：包含要插入内容的 HTML 字符串
  - `workflowId`（`unknown`）：本次工作流运行的唯一 ID
  - `tiptapReadResult`（`TiptapReadResult`）：`tiptapRead` 返回的结果，应用编辑操作时用于检测读取内容是否过期。
  - `reviewOptions?`（[`ReviewOptions`](/ai/ai-toolkit/client/api-reference/review-options)）：控制预览/审阅行为。
    - 安装了 [Tracked Changes](/tracked-changes/getting-started/overview) 扩展时，支持 `mode: 'trackedChanges'`。
  - `streamingOptions?`（`StreamingOptions`）：控制如何应用流式传输的操作。
    - `disableTypingEffect?`（`boolean`）：应用流式传输的操作时禁用打字效果。
  - `tiptapEditHooks?`（`TiptapEditHooks`）：用于拦截和修改操作的钩子。详情请参阅 [Tiptap Edit 钩子指南](/ai/ai-toolkit/client/advanced-guides/tiptap-edit-hooks)。
    - `beforeOperation?`（`(context: BeforeOperationContext) => BeforeOperationResult`）：在应用每个操作前调用。返回 `{ action: 'accept' }` 以应用操作（可选覆盖 `fragment` 或 `operationType`），或返回 `{ action: 'reject', error }` 以跳过操作。

### 返回值（`TiptapEditWorkflowResult`）

- `doc`（`Node`）：应用操作后修改的文档
- `operationResults`（`OperationResult[]`）：操作结果数组，顺序与执行顺序相同。每个结果包含：
  - `target`（`string`）：与操作结果关联的目标哈希
  - `success`（`boolean`）：操作是否成功完成
  - `error`（`string | null`）：操作失败时的错误消息，否则为 `null`

### 示例

```ts
const toolkit = getAiToolkit(editor)

// Get the document content
const readResult = toolkit.tiptapRead()

const operations = await callApiEndpoint({
  content: readResult.content,
  task: 'Make the text more formal',
})

// Apply edit operations
const result = toolkit.tiptapEditWorkflow({
  hasFinished: true,
  operations,
  workflowId: 'edit-123',
  tiptapReadResult: readResult,
  reviewOptions: {
    mode: 'preview',
  },
})
```

## `createEditThreadsWorkflow`（服务端工具）

创建用于管理评论和讨论串的现成工作流配置。返回系统提示词以及用于验证 AI 输出的 schema。

该工作流要求用户提示词为 JSON 对象，包含以下字段：

- `content`：文档内容（通过 `tiptapRead` 获取）
- `threads`：文档中现有的讨论串（通过 `getThreads` 获取）
- `task`：描述要完成的评论管理任务的字符串

### 返回值

- `systemPrompt`（`string`）：可直接使用的系统提示词，用于指示 AI 模型如何管理评论
- `zodOutputSchema`（`ZodObject`）：用于验证 AI 输出的 Zod schema
- `jsonOutputSchema`（`object`）：用于验证 AI 输出的 JSON schema

### 示例

```ts
import { createEditThreadsWorkflow } from '@tiptap-pro/client-ai-toolkit-tool-definitions'
import { Output, streamText } from 'ai'
import { openai } from '@ai-sdk/openai'

// Get the content, threads, and task from the API endpoint request
const { content, threads, task } = apiEndpointRequest

// Create and configure the workflow
const workflow = createEditThreadsWorkflow()

const result = streamText({
  model: openai('gpt-5.6-luna'),
  instructions: workflow.systemPrompt,
  prompt: JSON.stringify({ content, threads, task }),
  output: Output.object({ schema: workflow.zodOutputSchema }),
})
```

## `getThreads`

获取文档中的所有讨论串及其评论和位置信息。

### 返回值（`GetThreadsResult`）

- `threadCount`（`number`）：文档中的讨论串数量
- `threads`（`ThreadInfo[]`）：讨论串信息数组，每项包含：
  - `id`（`string`）：讨论串的唯一标识符
  - `comments`（`{ id: string; content: string }[]`）：讨论串中的评论数组
  - `nodeRange?`（`string`）：讨论串所在的节点范围
  - `documentContent?`（`string`）：应用讨论串的位置所包含的 HTML 内容

### 示例

```ts
const toolkit = getAiToolkit(editor)

// Get all threads in the document
const result = toolkit.getThreads()

console.log(`Found ${result.threadCount} threads`)

result.threads.forEach((thread) => {
  console.log(`Thread ${thread.id}: ${thread.comments.length} comments`)
})
```

## `editThreadsWorkflow`

将评论和讨论串操作应用于文档。

### 参数

- `options`（`EditThreadsWorkflowOptions`）：配置选项
  - `operations`（`string[][]`）：以元组形式表示的评论操作数组。
  - `commentsOptions?`（`CommentsOptions`）：评论操作选项
    - `threadData?`（`Record<string, any>`）：为创建的讨论串添加的额外元数据
    - `commentData?`（`Record<string, any>`）：为创建的评论添加的额外元数据

### 返回值（`EditThreadsWorkflowResult`）

- `operations`（`EditThreadsOperationResult[]`）：操作结果数组
- `success`（`boolean`）：所有操作是否均成功

### 示例

```ts
const toolkit = getAiToolkit(editor)

// Get document and threads
const { content } = toolkit.tiptapRead()
const { threads } = toolkit.getThreads()

const operations = await callApiEndpoint({ content, threads, task: 'Add review comments' })

// Apply comment operations
const result = toolkit.editThreadsWorkflow({
  operations,
})

if (result.success) {
  console.log('All comment operations completed successfully')
}
```

## `createTemplateWorkflow`（服务端工具）

创建用于填充模板的现成工作流配置。该方法接收 HTML 模板字符串（由客户端的 `createHtmlTemplate` 方法生成），自动提取所有模板键，并返回系统提示词以及用于验证 AI 输出的 schema。

该工作流要求用户提示词为 JSON 对象，包含以下字段：

- `task`：描述要为模板生成什么内容的字符串
- `context`：（可选）与任务相关的其他上下文或背景信息

### 参数

- `options`（`CreateTemplateWorkflowOptions`）：配置选项
  - `htmlTemplate`（`string`）：以 HTML 字符串表示的模板，由客户端的 `createHtmlTemplate` 方法生成
  - `requiredSlots?`（`string[]`）：AI 必须填充的插槽名称。未列出的插槽均为可选项。省略时，所有插槽均为必填项。传入空数组则所有插槽均为可选项。
  - `requiredConditions?`（`string[]`）：AI 必须评估的条件名称。未列出的条件均为可选项。省略时，所有条件均为必填项。传入空数组则所有条件均为可选项。
  - `requiredAttributes?`（`string[]`）：AI 必须设置的属性键名称。未列出的属性均为可选项。省略时，所有属性均为必填项。传入空数组则所有属性均为可选项。

### 返回值

- `systemPrompt`（`string`）：可直接使用的系统提示词，用于指示 AI 模型如何填充模板
- `zodOutputSchema`（`ZodObject`）：用于验证 AI 输出的 Zod schema
- `jsonOutputSchema`（`object`）：用于验证 AI 输出的 JSON schema

### 示例

```ts
import { createTemplateWorkflow } from '@tiptap-pro/client-ai-toolkit-tool-definitions'
import { createTextStreamResponse, Output, streamText, toTextStream } from 'ai'
import { openai } from '@ai-sdk/openai'

const { htmlTemplate, task } = apiEndpointRequest

const workflow = createTemplateWorkflow({ htmlTemplate })

const result = streamText({
  model: openai('gpt-5.6-luna'),
  instructions: workflow.systemPrompt,
  prompt: JSON.stringify({ task, context }),
  output: Output.object({ schema: workflow.zodOutputSchema }),
})

return createTextStreamResponse({ stream: toTextStream({ stream: result.stream }) })
```

## `templateWorkflow`

使用 AI 生成的值填充 Tiptap JSON 模板，并将结果插入编辑器。模板使用特殊属性（`_templateSlot`、`_templateIf`、`_templateAttributes`、`_templateFieldMetadata`）标记动态部分。

### 参数

- `options`（`TemplateWorkflowOptions`）：配置选项
  - `template`（`Record<string, any>`）：Tiptap JSON 格式的模板（doc 节点或片段数组）
  - `values`（`TemplateValues`）：用于填充模板的 AI 生成值。键对应模板属性值。
  - `position?`（`Range | number`）：插入已填充模板的位置。默认值：整个文档范围。
  - `hasFinished?`（`boolean`）：流式传输是否已完成。省略时，方法以非流式模式运行。默认值：`true`
  - `workflowId?`（`unknown`）：本次工作流运行的唯一 ID。提供此值后会启用流式模式，方法会在多次调用间跟踪插入范围并逐步替换内容。
  - `preserveSlotAttr?`（`boolean`）：为 `true` 时，填充后保留节点上的 `_templateSlot` 属性。这样便可识别 AI 填充的内容，并在之后重新填充模板字段。默认值：`false`
  - `reviewOptions?`（[`ReviewOptions`](/ai/ai-toolkit/client/api-reference/review-options)）：控制预览/审阅行为

### 示例

```ts
import { useEffect } from 'react'
import { useObject } from '@ai-sdk/react'
import { getAiToolkit } from '@tiptap-pro/client-ai-toolkit'
import { z } from 'zod'

const templateSchema = z.object({}).passthrough()

const { submit, isLoading, object } = useObject({
  api: '/api/template-workflow',
  schema: templateSchema,
})

// Stream partial results in a useEffect
useEffect(() => {
  if (!editor || !object) return

  const toolkit = getAiToolkit(editor)
  toolkit.templateWorkflow({
    template: templateJson,
    values: object as Record<string, unknown>,
    hasFinished: !isLoading,
    workflowId,
  })
}, [object, workflowId, editor, isLoading])
```

## `createHtmlTemplate`

将 Tiptap JSON 模板转换为 HTML 字符串，同时保留模板属性。生成的 HTML 可发送到服务器，由服务器上的 `createTemplateWorkflow` 解析模板键。

由于这是 AI Toolkit 的方法，编辑器 schema 会自动提供，因此只需传入模板。

### 参数

- `template`（`Record<string, unknown>`）：Tiptap JSON 格式的模板（doc 节点或片段数组）

### 返回值

- HTML `string`，其中模板属性名称已转换为小写（`_templateslot`、`_templateif`、`_templateattributes`、`_templatefieldmetadata`）

### 示例

```ts
const toolkit = getAiToolkit(editor)
const htmlTemplate = toolkit.createHtmlTemplate(templateJson)
```

## `TemplateField`

一种 Tiptap 扩展，可将模板字段属性添加到编辑器 schema 中的所有节点类型。注册此扩展后，即可在编辑器 DOM 中支持模板字段（渲染、解析和 CSS 样式）。

该扩展添加了四个全局属性：

- `_templateSlot`（`string | null`）：将节点标记为内容占位符。填充模板时，该节点会被 AI 生成的 HTML 替换。
- `_templateIf`（`string | null`）：将节点标记为条件包含项。当值为 `false` 时，输出中将排除该节点。
- `_templateAttributes`（`TemplateAttributeEntry[] | null`）：将模板键映射到特定节点属性。
- `_templateFieldMetadata`（`Record<string, unknown> | null`）：存储由开发者定义的可选字段实例元数据。

### 命令

- `setTemplateSlot(name: string)`：为当前选区中的节点设置 `_templateSlot` 属性。
- `unsetTemplateSlot()`：移除当前选区中节点的 `_templateSlot` 属性。
- `setTemplateIf(name: string)`：为当前选区中的节点设置 `_templateIf` 属性。
- `unsetTemplateIf()`：移除当前选区中节点的 `_templateIf` 属性。
- `setTemplateAttributes(entries: TemplateAttributeEntry[])`：为当前选区中的节点设置 `_templateAttributes` 属性。
- `unsetTemplateAttributes()`：移除当前选区中节点的 `_templateAttributes` 属性。

### 示例

```ts
import { TemplateField } from '@tiptap-pro/client-ai-toolkit'

const editor = new Editor({
  extensions: [StarterKit, TemplateField],
})

// Mark the selected node as a template slot
editor.commands.setTemplateSlot('intro')

// Remove the template slot
editor.commands.unsetTemplateSlot()
```

## `getTemplateFieldMatches`

从 Tiptap JSON 文档中返回与指定字段名称匹配的所有模板字段实例。

搜索范围包括 `_templateSlot`、`_templateIf` 和 `_templateAttributes`。每个匹配项都包含节点内容，以及存储在该字段实例上的可选 `_templateFieldMetadata` 对象。

### 参数

- `options`（`GetTemplateFieldMatchesOptions`）：搜索选项
  - `document`（`JSONContent | JSONContent[]`）：Tiptap JSON 文档节点或片段数组
  - `fieldName`（`string`）：要搜索的字段名称

### 返回值

- `TemplateFieldMatch[]`
  - `fieldName`（`string`）：匹配的字段名称
  - `fieldType`（`'slot' | 'condition' | 'attribute'`）：匹配的模板字段类型
  - `metadata`（`Record<string, unknown> | null`）：该字段实例的 `_templateFieldMetadata` 对象
  - `content`（`JSONContent[] | null`）：匹配的节点内容，采用 Tiptap JSON 格式

### 示例

```ts
import { getTemplateFieldMatches } from '@tiptap-pro/client-ai-toolkit'

const matches = getTemplateFieldMatches({
  document: editor.getJSON(),
  fieldName: 'intro',
})

matches.forEach((match) => {
  console.log(match.fieldType)
  console.log(match.metadata)
  console.log(match.content)
})
```
