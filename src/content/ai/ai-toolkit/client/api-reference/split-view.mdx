本页介绍 `createSplitView` 和 `SplitView` 实例的 API。

如果你是第一次使用分屏视图，请先阅读[分屏视图指南](/ai/ai-toolkit/client/advanced-guides/split-view)。

## `createSplitView`

创建一个分屏视图实例，将三个编辑器连接起来，以便并排审阅更改。

在 AI Toolkit 实例上调用：

```ts
const toolkit = getAiToolkit(mainEditor)
const splitView = toolkit.createSplitView(options)
```

### 参数

- `options` (`CreateSplitViewOptions`)：分屏视图配置
  - `leftEditor` (`Editor`)：左侧面板的编辑器（显示原始文档）。必须已安装 `AiToolkit`。
  - `rightEditor` (`Editor`)：右侧面板的编辑器（显示修改后的文档）。必须已安装 `AiToolkit`。
  - `leftContainer?` (`HTMLElement`)：左侧面板的滚动容器。与 `rightContainer` 一起提供时，将启用自动滚动同步。
  - `rightContainer?` (`HTMLElement`)：右侧面板的滚动容器。与 `leftContainer` 一起提供时，将启用自动滚动同步。
  - `diffOptions?` (`SplitViewDiffOptions`)：内部差异算法的选项
    - `mode?` (`'smart' | 'inline' | 'block'`)：差异算法模式。默认为 `'smart'`。
    - `groupInlineChanges?` (`number`)：将行内更改合并为块级更改的阈值。默认为 `0`。

### 返回值（`SplitView`）

返回一个 `SplitView` 实例。请参阅下文的 [SplitView 方法](#splitview-methods)部分。

### 示例

```ts
import { getAiToolkit } from '@tiptap-pro/client-ai-toolkit'

const splitView = getAiToolkit(mainEditor).createSplitView({
  leftEditor,
  rightEditor,
  leftContainer: leftScrollRef.current,
  rightContainer: rightScrollRef.current,
})
```

## `SplitView` 方法

### `sync`

根据主编辑器中跟踪的更改重新计算差异，并更新两个面板。将更改前后的快照加载到左右编辑器中，然后渲染高亮装饰和间隔元素。

每当主编辑器中跟踪的更改发生变化时，都应调用此方法（例如，应用新的 AI 建议后）。

```ts
splitView.sync()
```

### `getEntries`

返回上次调用 `sync()` 时计算出的当前差异条目列表。

```ts
const entries = splitView.getEntries()
// SplitDiffEntry[]
```

每个条目的结构请参阅 [`SplitDiffEntry`](#splitdiffentry)。

### `acceptEntry`

通过将某个差异条目对应的跟踪更改应用到主编辑器来接受该条目，然后重新同步。

```ts
const accepted = splitView.acceptEntry('diff-tc-abc123')
// Returns false if the entry was not found
```

### `rejectEntry`

通过还原主编辑器中某个差异条目对应的跟踪更改来拒绝该条目，然后重新同步。

```ts
const rejected = splitView.rejectEntry('diff-tc-abc123')
// Returns false if the entry was not found
```

### `acceptAll`

一次性接受所有剩余的跟踪更改，然后重新同步。

```ts
splitView.acceptAll()
```

### `rejectAll`

一次性拒绝所有剩余的跟踪更改，然后重新同步。

```ts
splitView.rejectAll()
```

### `setHighlight`

设置高亮显示的差异条目 ID，以便在编辑器之间同步悬停高亮。内置悬停监听器在鼠标悬停于带有 `data-diff-id` 的元素时会自动调用此方法。仅在实现自定义悬停逻辑时使用此方法。

```ts
splitView.setHighlight('diff-tc-abc123') // highlight an entry
splitView.setHighlight(null)             // clear highlight
```

### `on` / `off`

注册或移除事件监听器。

```ts
const handler = (entries) => {
  // entries: SplitDiffEntry[]
  console.log(`${entries.length} diff entries remaining`)
}

splitView.on('sync', handler)
splitView.off('sync', handler)
```

当前支持的事件：

| 事件 | 负载 | 说明 |
|---|---|---|
| `sync` | `SplitDiffEntry[]` | 每次同步后触发，并传入更新后的条目列表 |

### `destroy`

销毁实例：取消所有待处理的动画帧、清除两个编辑器中的所有装饰，并移除所有事件监听器。

```ts
splitView.destroy()
```

不再需要分屏视图时（例如组件卸载时），务必调用 `destroy()`。

## `SplitDiffEntry`

`getEntries()` 返回的列表中，每个条目的结构如下：

```ts
interface SplitDiffEntry {
  /** Unique identifier, e.g. "diff-tc-abc123" */
  id: string

  /** Range of this change in the left (original) document */
  rangeInBefore: { from: number; to: number }

  /** Range of this change in the right (modified) document */
  rangeInAfter: { from: number; to: number }

  /** IDs of the tracked changes that make up this diff entry */
  trackedChangeIds: string[]

  /** Change type */
  type?: 'add' | 'delete' | 'replace'
}
```

## CSS 装饰类

分屏视图会向编辑器 DOM 应用以下 CSS 类。你必须在自己的样式表中为这些类定义样式。

| 类 | 应用对象 | 说明 |
|---|---|---|
| `split-diff-deletion` | 左侧编辑器 | 高亮显示已删除或已修改的块 |
| `split-diff-insertion` | 右侧编辑器 | 高亮显示已添加或已修改的块 |
| `split-diff-highlight` | 两个编辑器 | 添加到当前悬停条目的删除/插入类旁边 |
| `split-diff-spacer` | 两个编辑器 | 用于保持两个面板垂直对齐的部件元素 |

所有添加了装饰的元素都包含一个 `data-diff-id` 属性，其值为条目 ID，可用于自定义点击和悬停处理。

<Callout title="请勿覆盖间隔元素的外边距">
  分屏视图会通过内联样式将每个间隔元素的 `margin` 设为 `0`。在 CSS 中覆盖此设置会破坏垂直对齐，因为间隔元素的高度已计入周围块级元素外边距在内的全部视觉间距。
</Callout>
