默认情况下，AI Suggestion 扩展使用 Tiptap Content AI Cloud 为内容生成建议。这样只需进行少量设置，即可使用其功能。不过，你也可以集成自己的后端和 LLM 来生成建议。

<Callout title="自定义 LLM 演示" variant="info">

  定价](https://tiptap.dev/pricing)。
</Callout>

AI Suggestion 扩展支持不同程度的自定义。你可以：

1. 使用 Tiptap Content AI Cloud，同时自定义 OpenAI 模型。
2. 将获取建议数据的 API 端点替换为自己的 LLM 和后端，同时让扩展负责显示和应用建议。这是大多数使用场景的推荐做法，因为我们会为你处理大部分复杂工作：比较编辑器的新旧内容、以清晰易读的方式显示差异，以及处理冲突。
3. 完全自行实现 resolver 函数。这样你就能完全自主决定如何在编辑器中显示建议。仅建议在高级场景中使用此方式。

## 在 Tiptap Cloud 中自定义 OpenAI 模型

你可以通过 `model` 选项配置用于生成建议的 OpenAI 模型。默认模型为 `gpt-4o-mini`，在速度、成本和准确性之间取得了良好平衡。

如果想提高建议质量，可以使用 `gpt-4o` 等更大型的模型。请注意，大型模型通常成本更高、速度更慢，延迟也更高。

```ts
AiSuggestion.configure({
  // The model to use for generating suggestions. Defaults to "gpt-4o-mini"
  model: 'gpt-4o',
})
```

## 替换 API 端点（推荐）

如果想使用自己的后端和 LLM 生成建议，可以提供自定义的 `apiResolver` 函数。此函数应调用你的后端，并根据编辑器内容和规则返回建议数组。

```tsx
AiSuggestion.configure({
  async resolver({ defaultResolver, ...options }) {
    const suggestions = defaultResolver({
      ...options,
      apiResolver: async ({ html, htmlChunks, rules }) => {
        // Generate the response by calling your custom backend and LLMs
        const response = await claudeSonnetApi({ html, htmlChunks, rules })

        // Return the response in the correct format (see details below)
        return { format: 'replacements', content: response }
      },
    })

    return suggestions
  },
})
```

为了提供最大的灵活性，`apiResolver` 支持两种响应格式：

### `replacements` 格式（推荐）

响应是一个替换项数组，这些替换项将应用于编辑器内容。当建议只修改文档的特定部分时，这种格式很有用。Tiptap Content AI Cloud 内部也使用此格式，目前为止效果最好。
响应包含以下属性：

- `items`：建议列表。每条建议包含以下属性：
  - `ruleId`：生成此建议的规则 ID。
  - `deleteHtml`：要从编辑器中删除的 HTML 内容。
  - `insertHtml`：要插入编辑器的 HTML 内容。
  - `chunkId`：要应用此建议的分块 ID。
- `htmlChunks`：编辑器内容中所有 HTML 代码块的列表。每个代码块包含以下属性：
  - `id`：代码块的唯一标识符。
  - `html`：代码块的 HTML 内容。
  - `generateSuggestions`：AI 模型是否为此代码块生成了建议。如果设为 `false`，则会从扩展的内部缓存中获取建议。

请确保 `htmlChunks` 属性包含编辑器内容中的所有 HTML 代码块，否则缓存机制将无法正常工作。

你可以通过读取 `apiResolver` 函数的 `htmlChunks` 参数，轻松获取 `htmlChunks` 属性的值。

以下是 `replacements` 格式的响应示例。

### `fullHtml` 格式

响应是一个完整的 HTML 字符串，用于替换编辑器内容。当你想用建议替换整个内容时，这种格式很有用。我们发现，当只需应用一条规则时，此格式效果很好；但规则较多时，效果不那么理想。此格式不支持分块和缓存。

```json
{
  "format": "fullHtml",
  "content": {
    "items": [
      {
        "ruleId": "1",
        "fullHtml": "<p>Hello, welcome to our awesome app! We hope you guys will love it. Our aplication offers unique features that enhance your cooking experience. You can explore various cuisines and share your food momentts.</p><p>Hello, we are excited to have you here. Our app is not just about recipes but also about building a community. We believe this will transform how you cook.</p><p>Please check out our cool fetures and enjoy cooking with us. If you have doubts, do not hesitate to ask.</p>"
      },
      {
        "ruleId": "2",
        "fullHtml": "<p>Hello, welcome to our awesome app! We hope you guys will love it. Our application offers unique features that enhance your cooking experience. You can explore various cuisines and share your food moments.</p><p>Hola, estamos emocionados de tenerte aquí. Our app is not just about recipes but also about building a community. We believe this will transform how you cook.</p><p>Please check out our cool features and enjoy cooking with us. Si tienes dudas, no dudes en preguntar.</p>"
      }
    ]
  }
}
```

### 提高准确性

LLM 可能会出错，因此很难确保其响应符合所需格式。为了提高自定义模型的准确性，我们建议采用以下最佳实践和提示词工程技巧。

- 在实施改进之前，评估自定义端点的响应，并衡量其性能和准确性。可以使用 [Evalite](https://www.evalite.dev/) 等评估框架。这有助于你优化并比较提示词，从而获得更好的效果。
- 如果使用 `replacements` 格式，可以利用 [OpenAI 结构化输出](https://platform.openai.com/docs/guides/structured-outputs)（或其他 LLM 提供商的同类功能），确保响应是符合特定架构的 JSON 对象。
- 如果使用 `fullHtml` 格式，可以利用 [OpenAI 预测输出](https://platform.openai.com/docs/guides/predicted-outputs)（或其他 LLM 提供商的同类功能），确保响应不会与编辑器的原始内容偏离太多。
- 调整 `temperature` 或 `top_p` [参数](https://platform.openai.com/docs/api-reference/completions/create)，以控制模型输出的随机性。
- LLM 提供商提供了关于[最佳实践](https://platform.openai.com/docs/guides/prompt-engineering)、优化[延迟](https://platform.openai.com/docs/guides/latency-optimization)和提高[准确性](https://platform.openai.com/docs/guides/optimizing-llm-accuracy)的官方指南。
- 不同的校对规则适合不同的提示方式和响应格式。你不必在 `replacements` 和 `fullHtml` 格式之间二选一，可以同时使用！定义一个以 `replacements` 格式返回建议的 API 端点，再定义另一个以 `fullHtml` 格式生成建议的端点。示例如下：

  ```tsx
  AiSuggestion.configure({
    async resolver({ defaultResolver, rules, ...options }) {
     // Split the rules into two groups
     const {
     rulesForFirstApi,
     rulesForSecondApi,
    } = splitRules(rules)

    // Send the first group of rules to the first api endpoint
      const suggestions1 = await defaultResolver({
        ...options,
        rules: rulesForFirstApiEndpoint
        apiResolver: async ({ html, htmlChunks, rules }) => {
          const response = await firstApi({ html, htmlChunks, rules });
          return { format: "replacements", content: response };
        },
      });

      // Send the second group of rules to the second api endpoint
      const suggestions2 = await defaultResolver({
        ...options,
        rules: rulesForSecondApiEndpoint
        apiResolver: async ({ html, htmlChunks, rules }) => {
          const response = await secondApi({ html, htmlChunks, rules });
          return { format: "fullHtml", content: response };
        },
      });

    // Merge both lists of suggestions
      return [...suggestions1, ...suggestions2]
    },
  ```

### 提高性能

要提升 API 和自定义 LLM 模型生成建议时的性能，可以考虑以下策略：

- 选择在准确性、速度和低延迟之间取得平衡的模型。可以使用 [Artificial Analysis](https://artificialanalysis.ai/#intelligence-vs-output-speed) 等排行榜，从不同指标比较模型。
- 在实施性能改进之前，先测量 API 的响应时间。如果处理流程包含多个步骤或模型调用，请分析每个步骤以找出瓶颈。可以使用 [Evalite](https://www.evalite.dev/) 等评估框架来迭代提示词并比较效果。
- 利用 [OpenAI 预测输出](https://platform.openai.com/docs/guides/predicted-outputs)（或其他 LLM 提供商的同类功能）来降低延迟并提升处理速度。
- 将编辑器内容分成多个小节并行处理，以缩短整体处理时间，尤其是处理大型文档时。利用扩展内置的分块和缓存机制，只重新加载有变化的内容块的建议。
- 设计提示词时，利用完整或[部分缓存](https://platform.openai.com/docs/guides/prompt-caching)。请注意，不同 LLM 提供商的缓存实现各不相同，有些可能不支持缓存。如有需要，可以自行实现缓存机制，以便重复利用相同或相似提示词对应的 LLM 响应。
- 流式响应可以提升用户对 API 性能的感知，尤其是在处理大型文档时，因为这样可以在完整响应生成之前显示建议。AI Suggestion 扩展目前尚不支持流式响应，但我们正在考虑在未来版本中添加此功能。如果你认为应用会因此受益，请通过 humans@tiptap.dev 联系我们。

## 完全替换 Resolver 函数（高级）

如果你想完全控制编辑器建议的生成方式（包括其在文档中的确切位置），可以提供自定义的 `resolver` 函数。此函数应根据编辑器内容和规则返回建议数组。

为了生成有效的建议对象，代码需要计算[建议在编辑器中的位置](https://prosemirror.net/docs/guide/#doc.indexing)。这通常需要比较编辑器当前内容与 LLM 生成的内容。有关如何实现的示例，请查看扩展源代码中的默认 resolver 函数。

如需了解每个建议对象应包含的数据，请参阅 [API 参考](/ai/deprecated/suggestion/api-reference#proofreading-suggestions)。

```tsx
AiSuggestion.configure({
  async resolver({ defaultResolver, ...options }) {
    const suggestions = await customResolver(options)
    return suggestions
  },
})
```

总体而言，实现自定义 resolver 需要更多工作，但能带来更大的灵活性。我们只建议在高级使用场景中采用此方式。

## 将 Tiptap Content AI Cloud 与自有后端结合使用

你不必在 Tiptap Content AI Cloud 和自有后端之间二选一。你可以将两者结合起来，兼得两者的优势。

```tsx
AiSuggestion.configure({
  async resolver({ defaultResolver, rules, ...options }) {
    // Split the rules into two groups
    const { rulesForDefaultSuggestions, rulesForCustomSuggestions } = splitRules(rules)

    // Get suggestions from Tiptap Content AI Cloud
    const defaultSuggestions = await defaultResolver({
      ...options,
      rules: rulesForDefaultSuggestions,
    })
    // Get suggestions from your own backend
    const customSuggestions = await customResolver({
      ...options,
      rules: rulesForCustomSuggestions,
    })

    // merge both lists of suggestions
    return [...defaultSuggestions, ...customSuggestions]
  },
})
```

## 不使用 AI 生成校对建议

生成校对建议不一定要使用 AI。你可以将 AI 模型与传统校对技术结合起来。例如，可以检查特定词语并将其替换。以下示例展示了一个 resolver，它会生成将单词 “hello” 替换为 “goodbye” 的建议。

```tsx
AiSuggestion.configure({
  rules: [
    {
      id: '1',
      title: 'Replace hello with goodbye',
      // The prompt will not be used because we do not use an LLM to generate suggestions for this rule
      prompt: 'Replace hello with goodbye',
      color: '#DC143C',
      backgroundColor: 'FFE6E6',
    },
  ],
  async resolver({ defaultResolver, ...options }) {
    const suggestions = await defaultResolver({
      ...options,
      apiResolver: async ({ html, rules }) => {
        // Generate the response without needing to call an LLM
        return {
          format: 'fullHtml',
          content: {
            items: [
              {
                ruleId: '1',
                // return the new document html after replacing "hello" with "goodbye"
                fullHtml: html.replaceAll('hello', 'goodbye'),
              },
            ],
          },
        }
      },
    })

    return suggestions
  },
})
```
