没有活跃的社区，Tiptap 就不会有今天的样子。我们一直欢迎贡献，也将一如既往地欢迎大家参与。在提交贡献之前，以下几点值得了解：

## 欢迎提交的内容

- 作为错误报告提交未通过的回归测试
- 改进文档，例如修正错别字或添加章节
- 为现有扩展添加新功能，例如新增可配置选项
- 对核心代码进行说明充分且不会造成破坏的修改

## 不会合并的内容

- 我们需要负责支持和维护的新扩展

## 提交想法

请先创建一个 issue，简要说明你的想法。我们会尽快回复，并告知你的贡献是否有机会被合并。

## 搭建开发环境

在官方仓库中进行试验并不难。你需要安装 [Git](https://github.com/git-guides/install-git)、[Node](https://nodejs.org/en/download/) 和 [pnpm](https://pnpm.io/installation)。接下来，请按以下步骤操作：

1. 将代码克隆到本地：`$ git clone git@github.com:ueberdosis/tiptap.git`
2. 安装依赖：`$ pnpm install`
3. 启动开发环境：`$ pnpm run start`
4. 在你常用的浏览器中打开 http://localhost:3000。
5. 开始动手探索吧！

## 代码风格

我们使用 eslint 配置来确保代码风格一致。运行 `$ pnpm run lint` 检查错误。提交拉取请求时也会进行检查。请确保检查通过后再提交拉取请求。

## 检查错误

你的拉取请求会自动运行所有现有测试。请在提交拉取请求前确认测试全部通过。使用 `$ pnpm run test` 在本地运行所有测试；也可以使用 `$ pnpm run test:open` 运行单个测试（例如编写新测试时）。

## 创建自己的扩展

如果你想创建并维护自己的扩展，可以使用 `create-tiptap-extension` CLI 工具。它会生成一个包含所有必要文件和构建流程的新扩展模板。只需运行：

```bash
pnpm init tiptap-extension
```

如果想让我们了解你的扩展，可以在 [X](https://x.com/tiptap_editor) 或 [Discord](https://tiptap.dev/discord) 上告诉我们。

## 记录你的贡献

为 Tiptap 做贡献时，请注意：Tiptap 的代码库和文档分别由两个独立的仓库管理。如果你对 Tiptap 进行了修改或改进，记录这些变更有助于他人理解和使用。请务必根据代码中的改动更新相应的文档仓库。

1. Tiptap 仓库：[Tiptap 代码仓库](https://github.com/ueberdosis/tiptap)——在此修改代码。
2. 文档仓库：[Tiptap 文档仓库](https://github.com/ueberdosis/tiptap-docs)——在此更新或添加文档，以反映 Tiptap 仓库中的改动。

在提交到 Tiptap 代码仓库的 PR 中，请附上你在文档仓库中所做相应更新的链接。反之，如果向文档仓库提交 PR，请在相关时附上 Tiptap 仓库中对应代码改动的链接。

## 还有其他问题？

如有其他问题，请在仓库中创建一个[新 issue](https://github.com/ueberdosis/tiptap/issues)或发起[讨论](https://github.com/ueberdosis/tiptap/discussions)。我们会尽快回复。
