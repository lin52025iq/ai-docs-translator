Collaboration 为编辑器添加实时协作编辑功能。在线状态指示器会显示当前活跃的用户，感知功能会突出显示每位用户的光标和选区，内置的[版本历史](/collaboration/documents/snapshot)和[评论](/comments/getting-started/overview)则会记录每一项更改。

它基于我们的开源后端 [Hocuspocus](https://github.com/ueberdosis/hocuspocus) 运行，使用 Yjs CRDT 同步内容，既能满足单个演示项目的需求，也能扩展到数千个并发连接。

## 管理文档
每项更改都会存储为 Yjs 更新。使用 [REST API](/collaboration/documents/rest-api) 获取 JSON 或以编程方式推送编辑内容。添加 [webhook](/collaboration/core-concepts/webhooks)，即可即时接收通知并获取所有文档。

使用我们的[文档管理 API](/collaboration/documents/rest-api)为所有文档及相关信息创建自己的备份。

## 启用高级功能
- [版本历史](/collaboration/documents/snapshot) – 安装 Collaboration Snapshot 扩展，让用户恢复到任意先前状态。
- [快照比较](/collaboration/documents/snapshot-compare) – 使用 Snapshot Compare 突出显示不同版本之间的差异。

## 从 Hocuspocus 或 Collaboration Cloud 迁移

将应用从 Hocuspocus 迁移到本地部署方案或 Tiptap Collaboration Cloud，只需将 `HocuspocusProvider` 切换为 `TiptapCollabProvider`，反之亦然。

无需对现有设置进行其他更改，与 API 交互的方式也不会改变。`TiptapCollabProvider` 充当中间层，负责管理应用连接服务器的方式以及登录信息。

从 Tiptap Collaboration Cloud 迁移到本地部署配置时，同样适用这种迁移方式。

查看 [Batch Import 端点](/collaboration/documents/rest-api#batch-import-documents)，了解如何迁移文档。

## Schema 管理

Tiptap 会严格执行 Schema 规则，并丢弃当前 Schema 中未定义的任何元素。当使用不同 Schema 版本的客户端同时编辑同一文档时，这可能会引发问题。

例如，假设某次更新添加了任务列表功能。使用旧版 Schema 的用户看不到这些任务列表，而新版 Schema 用户添加的任务列表也会因 Schema 不一致而从他们的视图中消失。这是因为 Tiptap 会在客户端之间同步更改，并根据旧版 Schema 移除无法识别的元素。

为减少这些问题，请考虑按照 Tiptap Editor 文档中的说明实现[无效 Schema 处理](/editor/core-concepts/schema#invalid-schema-handling)。
