Collaboration 通过 Documents 服务进行身份验证。你可以在服务器上签发 JWT，并在客户端连接时将其传递给 provider。令牌会指定用户可以访问哪些文档，以及可以对这些文档执行哪些操作。

<Callout title="刚开始使用 Tiptap 身份验证？" variant="hint">
  本页介绍 Documents 专用的声明。要创建密钥对并签发令牌，请参阅[身份验证](/authentication)。如需了解旧版 `allowedDocumentNames` 模型，请参阅[旧版身份验证](/authentication/legacy)。
</Callout>

## 受众和操作

将 `aud` 声明设置为 `"Documents"`。Collaboration 支持以下操作：

| 操作 | 授予的权限 |
| --- | --- |
| `Documents:Read` | 打开并读取文档 |
| `Documents:Write` | 编辑文档。隐含 `Documents:Read` 和 `Documents:Comment` 权限 |
| `Documents:Comment` | 添加评论，但不能编辑 |
| `Documents:Api:All` | 完全访问 Document Server 的所有 API 端点，包括设置。请将此令牌保留在服务器端。请参阅 [REST API](/collaboration/documents/rest-api) |

由于 `Documents:Write` 隐含读取和评论权限，因此仅授予写入权限即可获得完整的编辑权限。

## 按文档授权

`resource` 字段用于指定权限适用的文档。使用 `"*"` 表示所有文档，使用确切的文档名称表示单个文档，或将 `"*"` 与约束条件结合使用以匹配一组文档。

### 访问所有文档

```json
{
  "aud": "Documents",
  "permissions": [{ "action": "Documents:Write", "resource": "*" }]
}
```

<Callout title="注意" variant="warning">
  如果权限中的 `"resource": "*"` 没有约束条件，就会匹配你所在环境中的所有文档。若用户只能访问特定文档，请限定资源范围。
</Callout>

### 指定文档

```json
{
  "permissions": [
    { "action": "Documents:Write", "resource": "user-specific-document-1" },
    { "action": "Documents:Write", "resource": "user-specific-document-2" }
  ]
}
```

### 只读访问

授予 `Documents:Read`，但不授予 `Documents:Write`：

```json
{
  "permissions": [{ "action": "Documents:Read", "resource": "annual-report-2024" }]
}
```

### 允许评论但不能编辑

```json
{
  "permissions": [
    { "action": "Documents:Read", "resource": "policy-document-v3" },
    { "action": "Documents:Comment", "resource": "policy-document-v3" }
  ]
}
```

### 一组文档

使用 `prefix` 约束，而不是逐一列出文档名称：

```json
{
  "permissions": [
    {
      "action": "Documents:Write",
      "resource": "*",
      "constraints": { "prefix": "project-alpha/" }
    }
  ]
}
```

这将授予对所有名称以 `project-alpha/` 开头的文档的访问权限。约束条件的完整参考（包括 `suffix` 和 `in`），请参阅[权限](/authentication#permissions)。

## 连接 provider

将签名后的令牌作为 `token` 传递给 `TiptapCollabProvider`，并同时提供 `appId`。在服务器上生成令牌，然后发送给客户端。切勿在客户端代码中暴露签名密钥。

```ts
const doc = new Y.Doc()

const provider = new TiptapCollabProvider({
  name: note.id, // Document identifier
  appId: 'YOUR_APP_ID', // Document server ID from the Cloud dashboard
  token: 'YOUR_JWT', // Signed Documents token
  document: doc,
  user: userId,
})
```

## 处理令牌过期

设置 `exp`，让令牌保持较短的有效期。令牌每隔几秒就会验证一次，因此过期后不久便会被拒绝，且无法重新连接。

- 如果连接或重新连接时令牌无效，`onAuthenticationFailed` 回调会以 `permission-denied` 为原因触发。
- 如果令牌在连接建立后过期，`onClose` 回调会以 `JWT verification failed` 为原因触发。

这两种情况下，都应创建新令牌并重新创建 provider。用户可能长时间不关闭标签页，因此请在重新连接时处理令牌过期，以免丢失[未同步的更改](/collaboration/provider/integration#unsynced-changes)。

如需在令牌过期前将其失效，Collaboration 提供了 [Revoke JWT API](https://www.postman.com/tiptap-platform/workspace/tiptap-workspace/request/33042171-63ed5bbe-f54d-4a85-b2d0-5c1bc215d2fc)。由于支持撤销令牌，你无需将令牌的有效期设得极短。
