## 访问 Pro 注册表
Version History 扩展发布在 Tiptap 的私有 npm 注册表中。请按照[私有注册表指南](/guides/pro-extensions)集成此扩展。如果你已验证 Tiptap 账户身份，可以直接跳转到 [#安装](#install)。

## 安装

```bash

npm install @tiptap-pro/extension-snapshot @hocuspocus/transformer

```

**注意**：
`@hocuspocus/transformer` 包用于将 Y.js 二进制数据转换为 Tiptap JSON。协作功能还需要安装 Y.js。
如果尚未安装，请在项目中运行 `npm install yjs`。如果使用 NPM，这通常会自动完成（因为 NPM 会自动解析对等依赖）。

## 设置

| 设置     | 类型                   | 默认值     |
| -------- | ---------------------- | ---------- |
| provider | `TiptapCollabProvider` | `null`     |
| onUpdate | `function`             | `() => {}` |

## 自动版本管理

自动版本管理功能会定期为文档创建新版本，无需手动操作，即可保留完整的更改历史记录。

你可以使用 `enableAutoVersioning` 命令启用此功能（默认禁用）。

启用自动版本管理后，Tiptap 会定期创建新版本（默认每 30 秒一次，且仅在文档发生更改时创建）。这可能会产生大量版本，因此你可能需要延长时间间隔。
若要自定义时间间隔，可以这样操作：

```typescript
// 设置自动创建版本的时间间隔（秒）
provider.setAutoVersioningInterval(900)
provider.enableAutoVersioning()
provider.disableAutoVersioning()
```

## 恢复到某个版本

恢复到之前的版本时：

1. 如果存在未保存的更改，Tiptap 会自动创建一个版本来保留这些更改。
2. Tiptap 会在历史记录顶部创建一个新版本，其中包含所选版本的内容。
3. 所有用户都可以继续基于这个新版本进行编辑。

请注意，恢复操作只会影响 ydoc 中的 `default` 片段。恢复 Tiptap 内容时，评论不会更改（除非你在 TiptapCollabProvider 中指定了其他 `field`）。

你可以集成 [compare snapshots](/collaboration/documents/snapshot-compare) 扩展来突出显示不同版本之间的差异，确保选择正确的版本进行恢复。

## 存储

| 键                | 类型                   | 说明                                                                     |
| ----------------- | ---------------------- | ------------------------------------------------------------------------ |
| currentVersion    | `number`               | 当前版本。                                                               |
| lastSaved         | `Date`                 | 上次保存的时间戳。                                                       |
| latestVersion     | `number`               | 最新版本。                                                               |
| provider          | `TiptapCollabProvider` | Collaboration 提供程序实例。                                            |
| status            | `string`               | 提供程序的状态，可以是 `connecting`、`connected` 或 `disconnected`。     |
| synced            | `boolean`              | 版本历史记录是否已与服务器同步。                                         |
| versioningEnabled | `boolean`              | 是否已启用版本管理。                                                     |
| versions          | `array<Version>`       | 存储在历史记录中的版本数组。每个版本包含 `version`（数字）、`date`（数字）、`name`（可选字符串）和 `meta`（可选对象）。有关 `meta` 字段的详情，请参阅[自动版本元数据](#automatic-version-metadata)。 |

## 命令

| 命令              | 说明                                                                       |
| ----------------- | -------------------------------------------------------------------------- |
| saveVersion       | 创建一个新版本，可选名称、强制标志和元数据                                 |
| fetchVersions     | 从服务器获取版本列表并更新存储                                             |
| enableVersioning  | 为此文档启用自动版本管理                                                   |
| disableVersioning | 为此文档禁用自动版本管理                                                   |
| revertToVersion   | 恢复到指定版本；可选择创建带有自定义标题的新恢复版本                       |

## 示例

### 基本设置

```js
const provider = new TiptapCollabProvider({
  // ...
})

const editor = new Editor({
  // ...
  extensions: [
    // ...
    Snapshot.configure({
      provider,
    }),
  ],
})
```

### 保存版本更新

本例中，我们获取版本更新的数据并将其保存到变量中。

```js
let currentVersion = 0
let latestVersion = 0
let autoversioningEnabled = false
let versions = []

const provider = new TiptapCollabProvider({
  // ...
})

const editor = new Editor({
  // ...
  extensions: [
    // ...
    Snapshot.configure({
      provider,
      onUpdate(payload) {
        currentVersion = payload.currentVersion
        latestVersion = payload.version
        versions = payload.versions
        autoversioningEnabled = payload.versioningEnabled
      },
    }),
  ],
})
```

### 直接从存储中访问版本数据

```js
const provider = new TiptapCollabProvider({
  // ...
})

const editor = new Editor({
  // ...
  extensions: [
    // ...
    Snapshot.configure({
      provider,
    }),
  ],
})

const latestVersion = editor.storage.snapshot.latestVersion
const currentVersion = editor.storage.snapshot.currentVersion
const versions = editor.storage.snapshot.versions
const autoversioningEnabled = editor.storage.snapshot.versioningEnabled
```

### 手动创建新版本

```js
editor.commands.saveVersion('My new custom version')
```

### 创建带有元数据的版本

你可以为版本附加任意元数据。这对于存储作者、标签或自定义数据等额外信息很有用。

```js
editor.commands.saveVersion('Release v1.0', false, {
  author: 'Jane Doe',
  tags: ['release', 'stable'],
})
```

`saveVersion` 命令接受三个参数：

| 参数  | 类型                      | 默认值      | 说明                             |
| ----- | ------------------------- | ----------- | -------------------------------- |
| name  | `string`                  | `undefined` | 版本的可选名称                   |
| force | `boolean`                 | `false`     | 即使未检测到更改，也创建版本     |
| meta  | `Record<string, unknown>` | `undefined` | 要附加到版本的任意元数据         |

### 自动版本元数据

每个版本的 `meta` 对象中都会自动包含一个 `__tiptap` 键。此元数据由服务器添加，用于说明版本的创建方式以及参与创建的人员。

版本的 `meta` 字段如下所示：

```json
{
  "__tiptap": {
    "trigger": "websocket",
    "changesBy": ["#user1"],
    "triggeredBy": "user1"
  },
  "wordCount": 81624434
}
```

`__tiptap` 对象包含以下字段：

| 字段        | 类型       | 说明                                                                                                                                                                                                                      |
| ----------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| trigger     | `string`   | 版本的创建方式。可能的值：`"websocket"`（通过编辑器/提供程序）、`"api"`（通过 REST API）、`"autoVersioning"`（由自动版本管理功能创建）或 `"revert"`（恢复到之前的版本时创建）。 |
| changesBy   | `string[]` | 对此版本所包含的更改作出贡献的用户标识符列表。这些标识符是参与编辑的客户端在 `TiptapCollabProvider` 上设置的 `user` 值。                                                                                                    |
| triggeredBy | `string`   | 触发版本创建的用户标识符。对于 `"websocket"` 版本，这是经过身份验证的 JWT `sub`；对于 `"api"` 版本，这是后端提供的 `user` 查询参数。                                                                                      |

通过 `saveVersion` 或 REST API 传入的任何自定义元数据，都会与 `__tiptap` 键一起存储在 `meta` 顶层。`__tiptap` 键为保留键，不能被自定义元数据覆盖。

<Callout title="确保编辑归属信息可信" variant="warning">
  默认情况下，`changesBy` 会反映各客户端在其 `TiptapCollabProvider` 上设置的 `user` 值。此值由客户端提供，**不会**与经过身份验证的 JWT 核对，因此客户端可能会将更改记录在其他用户的身份名下。

  若要确保归属信息可信，请启用 [`user_mapping_authenticator`](/collaboration/operations/configure) 设置。启用后，服务器会拒绝任何注册、覆盖或删除与连接 JWT `sub` 不匹配的用户身份的尝试。启用此设置后，**每个客户端都必须将 `TiptapCollabProvider.user` 设置为与其 JWT `sub` 相同的值**，否则连接会被拒绝。此功能要求启用 JWT 身份验证。
</Callout>

### 从服务器获取版本

你可以使用 `fetchVersions` 命令手动刷新服务器上的版本列表。此操作会用最新版本数据更新扩展存储。

```js
editor.commands.fetchVersions()
```

### 为文档启用自动版本管理

```js
editor.commands.enableVersioning()
```

### 为文档禁用自动版本管理

```js
editor.commands.disableVersioning()
```

### 使用版本 ID 恢复

```js
editor.commands.revertToVersion(4)
```

### 使用版本 ID 和自定义名称恢复

在本例中，编辑器命令会帮助你返回到版本 4。使用此命令后，文档会恢复到版本 4 的状态，同时将这个旧版本保存为一个名为“Revert to version”的新版本。这样，你就可以继续基于版本 4 进行编辑，而它现在已保存为最新版本。

```js
editor.commands.revertToVersion(4, 'Revert to version')
```

### 恢复、命名并备份

在本例中，将文档恢复到版本 4 时，编辑器会自动创建两个新版本。第一个新版本会捕获并保存恢复前文档的状态，作为备份。第二个新版本会将文档恢复到版本 4，让你可以从此处继续工作，并将其作为新的起点。

```js
editor.commands.revertToVersion(4, 'Revert to version', 'Unversioned changes before revert')
```

### 使用提供程序级别的版本方法

`TiptapCollabProvider` 提供了直接操作版本的方法，无需使用 Snapshot 扩展。

#### 列出版本

从服务器获取完整的版本列表：

```js
const versions = await provider.listVersions()
// versions: Array<{ version: number, date: number, name?: string, meta?: Record<string, unknown> }>
```

#### 获取缓存的版本

获取本地缓存的版本列表（不会向服务器发送请求）：

```js
const versions = provider.getVersions()
```

#### 监听版本更改

使用回调订阅版本列表更新：

```js
const onVersionsChange = (versions) => {
  console.log('Versions updated:', versions)
}

// 开始监听
provider.watchVersions(onVersionsChange)

// 停止监听
provider.unwatchVersions(onVersionsChange)
```

#### 创建带有元数据的版本

```js
provider.createVersion('My version', false, {
  author: 'Jane Doe',
  tags: ['draft'],
})
```

### 为编辑器实现版本预览

以上示例会直接修改文档，不会提供仅在本地显示的版本预览。因此，你需要自行实现前端方案。你可以使用 `TiptapCollabProvider` 上的 `previewVersion` 方法，从服务器请求指定版本。

首先，为提供程序添加监听器：

```js
// 导入 getPreviewContentFromVersionPayload 辅助函数（详情见下文）
import { watchPreviewContent } from '@tiptap-pro/extension-snapshot'

// 配置提供程序
const provider = new TiptapCollabProvider({ ... })

// 使用 watchPreviewContent 工具函数监听提供程序的内容更改
const unbindWatchContent = watchPreviewContent(provider, content => {
  // 设置编辑器内容
  editor.commands.setContent(content)
})
```

如果要解除监听，可以像这样调用返回的 `unbindWatchContent` 函数：

```js
const unbindWatchContent = watchPreviewContent(provider, (content) => {
  // 设置编辑器内容
  editor.commands.setContent(content)
})

// 停止监听
unbindWatchContent()
```

完成上述设置后，可以像这样发送 `version.preview` 请求：

```js
// 从服务器请求指定版本的预览
provider.previewVersion(1)

// 你可以将此操作绑定到按钮点击或其他 UI 元素上，以触发请求。
```

若要进一步可视化比较不同版本，[compare snapshots](/collaboration/documents/snapshot-compare) 扩展可让你轻松查看编辑器中任意两个版本之间的差异。

## 实用函数

### getPreviewContentFromVersionPayload

此函数会将 Collaboration 提供程序的载荷转换为 Tiptap JSON 内容。

| 参数    | 说明                                      |
| ------- | ----------------------------------------- |
| payload | 版本预览事件的 Hocuspocus 载荷            |
| field   | 要解析的字段。默认值：`default`           |

```js
const myContent = getPreviewContentFromVersionPayload(payload, 'default')
```

### watchPreviewContent

此函数会在提供程序上设置监听器，监听必要事件，以便在版本内容更改时作出响应。它还会返回一个新函数，供你取消监听这些事件。

| 参数     | 说明                                           |
| -------- | ---------------------------------------------- |
| provider | Collaboration 提供程序                         |
| callback | 被调用的回调函数，参数为 Tiptap JSON 内容       |
| field    | 要监听的字段，默认值为 `default`               |

```js
const unwatchContent = watchPreviewContent(provider, editor.commands.setContent, 'default')

// 停止监听版本预览内容
unwatchContent()
```

## 提供程序可能的载荷

以下是提供程序可能发送或接收的载荷列表：

### 传出

#### `document.revert`

请求将文档恢复到指定版本，并可选择设置标题。

```js
provider.revertToVersion(1, {
  currentVersionName: 'Before reverting to version 1',
  newVersionName: 'Revert to version 1',
})
```

#### `version.create`

创建一个新版本，可选择指定名称和元数据。

```js
provider.createVersion('My custom version', false, { author: 'Jane Doe' })
```

#### `versions.list`

请求从服务器获取完整的版本列表。

```js
const versions = await provider.listVersions()
```

### 传入

#### `version.created`

这条无状态消息包含新创建版本的信息，包括附加的任何元数据。

```js
provider.on('stateless', (data) => {
  const payload = JSON.parse(data.payload)

  if (payload.event === 'version.created') {
    const latestVersion = payload.version
    const name = payload.name // 可选的版本名称
    const date = payload.date // 创建时间戳
    const meta = payload.meta // 可选的元数据对象
  }
})
```

#### `versions.list`

`listVersions` 方法会返回完整的版本列表。每个版本都包含 `version`、`date`，以及可选的 `name` 和 `meta` 字段。

```js
const versions = await provider.listVersions()
// versions 是由 { version: number, date: number, name?: string, meta?: object } 组成的数组
```

#### `document.reverted`

这条无状态消息包含文档恢复操作的信息。

```js
provider.on('stateless', (data) => {
  const payload = JSON.parse(data.payload)

  if (payload.event === 'document.reverted') {
    const currentVersion = payload.version
  }
})
```
