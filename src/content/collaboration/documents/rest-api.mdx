Collaboration Management API 提供了一系列用于管理文档的 RESTful 端点。此 API 可用于创建、列出、检索、更新、删除和复制文档。

你可以访问我们的 [Postman Collection](https://www.postman.com/tiptap-platform/workspace/tiptap-workspace/collection/33042171-cc186a66-df41-4df8-9c6e-e91b20deffe5) 来试用 REST API。

## 速率限制

为维护系统完整性并防止客户端配置错误，我们的基础设施（包括管理 API，以及通过 `TiptapCollabProvider` 建立的 WebSocket 连接）均受速率限制。

### 默认速率限制（按源 IP 计算）：

  - **请求数：** 100
  - **时间窗口：** 5 秒
  - **突发容量：** 最多 200 个请求

如果在正常运行期间遇到这些限制，请[发送邮件联系我们](mailto:humans@tiptap.dev)。

## 访问 API

REST API 可通过自定义 URL 直接从文档服务器访问：

```bash
https://YOUR_APP_ID.collab.tiptap.cloud/
```

请将 `YOUR_APP_ID` 替换为你的文档服务器 ID。该 ID 在 [Cloud 控制台](https://cloud.tiptap.dev/v2/configuration/document-server)中标记为“Document server ID”。

### 身份验证

使用携带 `Documents:Api:All` 权限的签名令牌对 API 请求进行身份验证，并通过 `Authorization: Bearer <jwt>` 发送。有关如何签署令牌，请参阅[身份验证](/authentication)。

<Callout title="请在服务器端保管此令牌" variant="warning">
  `Documents:Api:All` 授予对文档服务器所有 API 端点（包括托管设置）的访问权限。请将携带此权限的令牌视为管理员凭据。在服务器上签署令牌，设置较短的有效期，且绝不要将其暴露给客户端。
</Callout>

之前使用的 API 密钥仍然有效，相关说明请参阅[旧版身份验证](/authentication/legacy)。

### 文档标识符
如果文档标识符包含斜杠 (`/`)，请将其编码为 `%2F`，例如使用 `encodeURIComponent`。

## API 端点概览

使用 Collaboration Management API 高效管理文档。如需查看 Tiptap 各产品的所有端点，请参阅我们的 [Postman Collection](https://www.postman.com/tiptap-platform/workspace/tiptap-workspace/collection/33042171-cc186a66-df41-4df8-9c6e-e91b20deffe5)，其中包含详细示例和配置。

| 操作 | 方法 | 端点 | 说明 |
| ------------------ | ---------- | -------------------------------------------- |----------------------------------------------------------------------------------------------|
| 创建文档 | POST | `/api/documents/:identifier` | 使用 `yjs` 或 `json` 更新消息创建文档。 |
| 批量导入文档 | PUT | `/api/admin/batch-import` | 批量导入多个文档。 |
| 获取文档 | GET | `/api/documents/:identifier` | 以 `json` 或 `yjs` 格式获取文档。 |
| 列出文档 | GET | `/api/documents` | 获取所有文档的列表，并支持分页选项。 |
| 复制文档 | POST + GET | `/api/documents/:identifier` (先 GET 再 POST) | 先检索文档，再使用新的标识符创建文档，以此复制文档。 |
| 加密文档 | POST | `/api/documents/:identifier/encrypt` | 使用 Base64 加密文档。 |
| 列出版本 | GET | `/api/documents/:identifier/versions` | 获取文档的所有版本。 |
| 获取版本 | GET | `/api/documents/:identifier/versions/:versionId` | 获取指定版本。 |
| 创建版本 | POST | `/api/documents/:identifier/versions` | 创建版本，可选设置名称和元数据。 |
| 更新版本 | PATCH | `/api/documents/:identifier/versions/:versionId` | 更新版本名称或元数据。 |
| 恢复到指定版本 | POST | `/api/documents/:identifier/versions/:versionId/revertTo` | 将文档恢复到较早的版本。 |
| 更新文档 | PATCH | `/api/documents/:identifier` | 将 Yjs 更新消息应用到现有文档。 |
| 更新文档（PUT 别名） | PUT | `/api/documents/:identifier` | `PATCH` 端点的别名，应用 Yjs 更新消息，行为完全相同。 |
| 检查文档是否存在 | HEAD | `/api/documents/:identifier` | 检查文档是否存在（不返回响应正文）。 |
| 删除文档 | DELETE | `/api/documents/:identifier` | 从服务器删除文档。 |
| 删除版本 | DELETE | `/api/documents/:identifier/versions/:versionId` | 删除文档的指定版本。 |
| 导出文档 | GET | `/api/documents/:identifier/export` | 将文档及其所有版本导出为 `.zip` 归档文件。 |
| 导入文档 | POST | `/api/documents/:identifier/import` | 从导出的 `.zip` 归档文件导入文档及其版本。 |
| 发送无状态消息 | POST | `/api/documents/:identifier/stateless` | 向文档的所有已连接客户端广播无状态消息。 |

也可以查看[指标和统计信息端点](/collaboration/operations/metrics)！

## 创建文档

```bash
POST /api/documents/:identifier
```

此调用允许你使用 [Yjs 二进制格式](/collaboration/getting-started/overview#about-yjs)或 JSON 格式（默认：`yjs`）创建文档。可在用户连接到 Tiptap Collaboration 服务器之前，用它预先创建文档。

成功创建文档时，端点返回 HTTP 状态码 `204`；如果文档已存在，则返回 `409`。要覆盖现有文档，必须先[删除该文档](/collaboration/documents/rest-api#delete-a-document)。

- **Yjs 格式**：若要使用 Yjs 二进制更新消息创建文档，请先使用 `Y.encodeStateAsUpdate` 对 Yjs 文档进行编码。

```bash
curl --location 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME' \
--header 'Authorization: Bearer YOUR_JWT' \
--data '@yjsUpdate.binary'
```

- **JSON 格式**：若要使用 JSON 创建文档，请传入查询参数 `format=json`，并以 Tiptap JSON 格式提供文档内容。

```bash
curl --location 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME?format=json' \
--header 'Authorization: Bearer YOUR_JWT' \
--header 'Content-Type: application/json' \
--data '{
    "type": "doc",
    "content": [
      {
        "type": "paragraph",
        "content": [
          {
            "type": "text",
            "text": "This is your content."
          }
        ]
      }
    ]
}'

```

## 批量导入文档

```bash
PUT /api/admin/batch-import
```

此调用允许你使用预定义的 JSON 结构批量导入多个文档。每个文档都必须包含元数据（例如 created_at、name 和 version）以及 Tiptap JSON 格式的内容。

成功导入文档时，端点返回 HTTP 状态码 `204`；如果请求包含无效数据，则返回 `400`。

```bash
curl --location --request PUT 'https://YOUR_APP_ID.collab.tiptap.cloud/api/admin/batch-import' \
--header 'Content-Type: application/json' \
--data '[
    [
        {
            "created_at": "2024-05-01T10:00:00Z",
            "version": 0,
            "name": "document-1",
            "tiptap_json": {"type": "doc", "content": [{"type": "paragraph", "content": [{"type": "text", "text": "Text of document-1: v0"}]}]}
        },
        {
            "created_at": "2024-05-01T11:00:00Z",
            "version": 1,
            "name": "document-1",
            "tiptap_json": {"type": "doc", "content": [{"type": "paragraph", "content": [{"type": "text", "text": "Text of document-1: v1"}]}]}
        }
    ],
    [
        {
            "created_at": "2024-06-01T10:00:00Z",
            "version": 0,
            "name": "document-2",
            "tiptap_json": {"type": "doc", "content": [{"type": "paragraph", "content": [{"type": "text", "text": "Text of document-2: v0"}]}]}
        },
        {
            "created_at": "2024-06-01T11:00:00Z",
            "version": 1,
            "name": "document-2",
            "tiptap_json": {"type": "doc", "content": [{"type": "paragraph", "content": [{"type": "text", "text": "Text of document-2: v1"}]}]}
        }
    ]
]'

```

## 获取文档

```bash
GET /api/documents/:identifier?format=:format&fragment=:fragment&version=:version
```

此调用允许你以 JSON 或 Yjs 格式导出指定文档的所有片段。如果文档当前已在服务器上打开，我们将返回内存中的版本；否则，将从数据库读取。

- `format` 支持 `yjs`、`base64`、`text` 或 `json`（默认：`json`）。如果选择 `yjs` 格式，你将获得通过 `Y.encodeStateAsUpdate` 创建的 Yjs 二进制更新消息。

- `fragment` 可以是数组（例如 `fragment=a&fragment=b`），也可以是你要导出的单个片段。默认情况下，我们仅导出 `default` 片段。此参数仅适用于 `json` 或 `text` 格式；使用 `yjs` 时，始终会返回整个 Yjs 文档。

- `version`（`string`，可选）：要检索的 Y.js 文档版本。默认为最新版本。

```bash
curl --location 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME' \
--header 'Authorization: Bearer YOUR_JWT'
```

  使用 `axios` 时，需要在请求选项中指定 `responseType: arraybuffer`。

```typescript
import * as Y from 'yjs'

const ydoc = new Y.Doc()

const axiosResult = await axios.get(
  'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME?format=yjs',
  {
    headers: {
      Authorization: 'Bearer YOUR_JWT',
    },
    responseType: 'arraybuffer',
  },
)

Y.applyUpdate(ydoc, axiosResult.data)
```

使用 `node-fetch` 时，需要调用 `.arrayBuffer()`，并据此创建 Buffer：

```typescript
import * as Y from 'yjs'

const ydoc = new Y.Doc()

const fetchResult = await fetch(
  'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME?format=yjs',
  {
    headers: {
      Authorization: 'Bearer YOUR_JWT',
    },
  },
)

Y.applyUpdate(ydoc, Buffer.from(await docUpdateAsBinaryResponse.arrayBuffer()))
```

## 列出文档

```bash
GET /api/documents?take=100&skip=0
```

此调用会返回存储中所有文档的分页列表。默认情况下，我们会返回前 100 个文档。传入 `take` 和 `skip` 参数可调整分页。

```bash
curl --location 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents' \
--header 'Authorization: Bearer YOUR_JWT'
```


## 复制文档

此调用允许你复制文档。首先使用 `GET` 端点检索文档，然后使用 `POST` 调用创建一个新文档。以下是一个 TypeScript 示例：

```typescript
const docUpdateAsBinaryResponse = await axios.get(
  'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME?format=yjs',
  {
    headers: {
      Authorization: 'Bearer YOUR_JWT',
    },
    responseType: 'arraybuffer',
  },
)

await axios.post(
  'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME-duplicated',
  docUpdateAsBinaryResponse.data,
  {
    headers: {
      Authorization: 'Bearer YOUR_JWT',
    },
  },
)
```

请注意，新文档不会包含源文档的版本。如果要保留版本，可以使用导入/导出端点（请参阅 Postman Collection）。

## 加密文档

```bash
POST /api/documents/:identifier/encrypt
```

此调用允许你使用 Base64 加密指定标识符的文档。

成功加密文档时，端点返回 HTTP 状态码 `204`；如果文档不存在，则返回 `404`。

```bash
curl --location 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME/encrypt' \
--header 'Content-Type: application/json' \
--header 'Authorization: Bearer YOUR_JWT' \
--data '{
    "type": "doc",
    "content": [
      {
        "type": "paragraph",
        "attrs": {
          "indent": 0,
          "textAlign": "left"
        },
        "content": [
          {
            "text": "the entire document is replaced by this (except if you changed the mode parameter to '\''append'\'')",
            "type": "text"
          }
        ]
      }
    ]
  }'
```

## 版本管理

版本记录文档在某个时间点的状态。每个版本都有一个 `version` 编号和 `date`，还可以选择添加 `name` 和 `meta`（任意元数据对象）。

每个版本的 `meta` 对象都会自动包含一个 `__tiptap` 键，其中包含服务器生成的元数据，记录由谁贡献了更改以及该版本的创建方式。详情请参阅[自动版本元数据](/collaboration/documents/snapshot#automatic-version-metadata)。

如需查看所有版本端点的完整交互式参考，请参阅 [Postman Collection](https://www.postman.com/tiptap-platform/workspace/tiptap-workspace/folder/33042171-a6e8aa7e-c077-46ee-a2a3-241f8efd5d25?action=share&creator=33042171&active-environment=33042171-378cfb31-9c16-40f0-95b8-b9f0d3c7d2ab)。

### 恢复到指定版本

```bash
POST /api/documents/:identifier/versions/:versionId/revertTo
```

此调用通过应用与文档先前状态相对应的更新，将文档恢复到指定的历史版本。

成功恢复文档时，端点返回 HTTP 状态码 `200`；如果找不到文档或版本，则返回 `404`。

```bash
curl --location --request POST 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME/versions/VERSION_ID/revertTo' \
--header 'Content-Type: application/json' \
--header 'Authorization: Bearer YOUR_JWT'
```

### 更新版本

```bash
PATCH /api/documents/:identifier/versions/:versionId
```

此调用允许你更新版本名称或元数据。你可以在创建版本后重命名版本或添加更多上下文信息。

有关可用的请求正文参数和示例，请参阅 [Postman Collection](https://www.postman.com/tiptap-platform/workspace/tiptap-workspace/folder/33042171-a6e8aa7e-c077-46ee-a2a3-241f8efd5d25?action=share&creator=33042171&active-environment=33042171-378cfb31-9c16-40f0-95b8-b9f0d3c7d2ab)。

### 删除版本

```bash
DELETE /api/documents/:identifier/versions/:versionId
```

此调用会删除文档的单个版本。`:versionId` 是列出版本或获取版本的端点所返回的版本编号。

成功删除版本时，端点返回 HTTP 状态码 `204`；如果找不到文档或版本，则返回 `404`。

```bash
curl --location --request DELETE 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME/versions/VERSION_ID' \
--header 'Authorization: YOUR_SECRET_FROM_SETTINGS_AREA'
```


## 更新文档

```bash
PATCH /api/documents/:identifier
```

此调用接受 Yjs 更新消息，并将其应用到服务器上的现有文档。

同一端点也可通过 `PUT /api/documents/:identifier` 访问，其行为与 `PATCH` 完全相同（请求正文和查询参数相同）。

文档成功更新时，端点返回 HTTP 状态码 `204`；如果文档不存在，则返回 `404`；如果负载无效或无法应用更新，则返回 `422`。

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME' \
--header 'Authorization: Bearer YOUR_JWT' \
--data '@yjsUpdate.binary'
```

此 API 端点还支持 JSON 文档更新、用于跟踪更改而不替换整个文档的文档历史记录，以及针对特定节点的更新。

如需详细了解如何使用 JSON 而不是 Yjs 操作文档，请参阅[内容注入](/collaboration/documents/content-injection)页面。

## 删除文档

```bash
DELETE /api/documents/:identifier
```

此调用会在关闭文档的所有开放连接后，从服务器删除文档。

成功删除文档时，返回 HTTP 状态码 `204`；如果找不到文档，则返回 `404`。

```bash
curl --location --request DELETE 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME' \
--header 'Authorization: Bearer YOUR_JWT'
```

<Callout title="删除后文档仍然存在" variant="hint">
  如果端点返回 `204`，但文档仍然存在，请确认没有用户通过 provider 重新创建该文档。删除文档前，我们会关闭所有连接，但你的错误处理逻辑可能会重新创建 provider，进而再次创建文档。
</Callout>

## 检查文档是否存在

```bash
HEAD /api/documents/:identifier
```

此调用会检查指定标识符的文档是否存在，而不会传输文档内容。响应不包含正文。

如果文档存在，则返回 HTTP 状态码 `200`；如果不存在，则返回 `404`。文档是否存在与其处于活动还是非活动状态无关。

```bash
curl --location --head 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME' \
--header 'Authorization: YOUR_SECRET_FROM_SETTINGS_AREA'
```

## 导出和导入文档

使用这些端点可在服务器之间迁移文档及其所有版本，或创建可移植的备份。与[复制文档](#duplicate-a-document)不同，导出归档会保留文档的版本历史记录。

### 导出文档

```bash
GET /api/documents/:identifier/export
```

此调用会将当前文档及其所有版本导出为 `.zip` 归档文件（`Content-Type: application/zip`）。之后可以使用导入端点再次导入该归档文件。

成功时，端点返回 HTTP 状态码 `200`，并在响应正文中提供归档文件；如果文档不存在，则返回 `404`。

```bash
curl --location 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME/export' \
--header 'Authorization: YOUR_SECRET_FROM_SETTINGS_AREA' \
--output export.zip
```

### 导入文档

```bash
POST /api/documents/:identifier/import
```

此调用会从之前通过导出端点创建的归档文件中导入文档及其版本。请将归档文件作为原始请求正文发送；服务器会读取原始字节，因此不要求使用特定的 `Content-Type` 标头。目标 `:identifier` 必须尚不存在。

验证失败的请求会在导入开始前通过常规 HTTP 状态码拒绝：如果目标标识符对应的文档已存在，则返回 `409`；如果归档文件超过允许的最大正文大小，则返回 `413`；如果归档文件格式错误，则返回 `400`。

导入开始后，端点会返回 HTTP 状态码 `200`（`Content-Type: application/x-ndjson`），并在处理过程中以流的形式发送以换行符分隔的 JSON（NDJSON）进度事件。流以 `done` 事件结束，其 `status` 字段报告最终结果：成功时为 `201`；如果导入期间创建了标识符冲突的文档，则为 `409`。如果导入中途失败，流将以携带状态码 `422` 的 `error` 事件结束。

```bash
curl --location 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME/import' \
--header 'Authorization: YOUR_SECRET_FROM_SETTINGS_AREA' \
--header 'Content-Type: application/zip' \
--data-binary '@export.zip'
```

## 发送无状态消息

```bash
POST /api/documents/:identifier/stateless
```

此调用会向当前连接到文档的所有客户端广播自定义负载。客户端会将其作为[无状态消息](/collaboration/provider/events)接收；你可以通过 provider 的 `onStateless` 回调处理该消息，也可以监听 `stateless` 事件。

请求正文会原样作为无状态负载发送。消息广播后，端点返回 HTTP 状态码 `204`。

```bash
curl --location 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME/stateless' \
--header 'Authorization: YOUR_SECRET_FROM_SETTINGS_AREA' \
--header 'Content-Type: application/json' \
--data '{ "type": "ping", "payload": "hello" }'
