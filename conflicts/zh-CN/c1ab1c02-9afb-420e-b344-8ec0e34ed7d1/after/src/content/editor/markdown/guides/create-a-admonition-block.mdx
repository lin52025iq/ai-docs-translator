本指南将带你了解如何为 Tiptap 中的自定义“提示块”添加 Markdown 支持。我们会将整个过程分为四个清晰的步骤，并在每个步骤中提供完整示例，其中包含前面步骤的代码，让你始终掌握完整上下文。

**步骤**：
1. 创建基础的 Tiptap `Node` 扩展（不支持 Markdown）。
2. 添加自定义 Markdown 分词器，从原始 Markdown 中生成 token。
3. 添加解析器，将这些 token 转换为 Tiptap JSON。
4. 添加渲染器（序列化器），将 Tiptap 节点转换回 Markdown。

我们将使用 `:::type` 格式表示提示块，例如：

```javascript
:::warning
This is a warning with **bold** text.
:::
```

---

## 第 1 步：创建基础扩展

先定义一个精简的 `Node`，描述其结构、HTML 解析与渲染方式以及属性。暂时不集成 Markdown，这样你可以先专注于 schema 和 HTML 输入输出。

```javascript
import { Node } from '@tiptap/core'

export const Admonition = Node.create({
  name: 'admonition',

  group: 'block',
  content: 'block+',

  addAttributes() {
    return {
      type: {
        default: 'note',
        parseHTML: (element) => element.getAttribute('data-type'),
        renderHTML: (attributes) => ({
          'data-type': attributes.type,
        }),
      },
    }
  },

  parseHTML() {
    return [{ tag: 'div[data-admonition]' }]
  },

  renderHTML({ node, HTMLAttributes }) {
    return ['div', { 'data-admonition': '', ...HTMLAttributes }, 0]
  },
})
```

**说明：**
- `content: 'block+'` 允许提示块中包含嵌套块级内容。
- 我们将提示块的 `type` 存储为节点属性（在 HTML 中对应 `data-type`）。

## 第 2 步：添加自定义 Markdown 分词器

Tiptap 的 Markdown 集成可以接收一个分词器，将 Markdown 源文本转换为 Markdown 解析器能够识别的 token。分词器负责识别 `:::type` ... `:::` 块，并返回一个包含相关元数据和嵌套 token（用于表示内容）的 token 对象。

下面是一个完整示例，其中包含基础 Node 和新增的 `markdownTokenizer`。通过它可以完整了解分词器如何与 Node 集成。

```javascript
import { Node } from '@tiptap/core'

export const Admonition = Node.create({
  name: 'admonition',

  group: 'block',
  content: 'block+',

  addAttributes() {
    return {
      type: {
        default: 'note',
        parseHTML: (element) => element.getAttribute('data-type'),
        renderHTML: (attributes) => ({
          'data-type': attributes.type,
        }),
      },
    }
  },

  parseHTML() {
    return [{ tag: 'div[data-admonition]' }]
  },

  renderHTML({ node, HTMLAttributes }) {
    return ['div', { 'data-admonition': '', ...HTMLAttributes }, 0]
  },

  markdownTokenizer: {
    name: 'admonition',
    level: 'block', // block-level element

    // A fast start check: returns -1 if not found.
    // and is used by the lexer to optimize scanning.
    start: (src) => src.indexOf(':::'),

    // the actual tokenize function that builds
    // the token
    tokenize: (src, tokens, lexer) => {
      // This regex matches:
      // :::type\n
      // (anything, including newlines)\n
      // :::
      const match = /^:::(\w+)\n([\s\S]*?)\n:::\n?/.exec(src)
      if (!match) return undefined

      return {
        type: 'admonition',
        raw: match[0], // the full matched Markdown
        admonitionType: match[1], // e.g. 'warning'
        text: match[2], // inner Markdown text

        // Let the Markdown lexer parse the inner content into block tokens.
        tokens: lexer.blockTokens(match[2]),
      }
    },
  },
})
```

**实现细节：**
- `start` 是一种优化方式，供词法分析器查找候选位置。
- 如果 `markdownTokenizer.tokenize` 未匹配到内容，则返回 `undefined`；否则必须返回包含 `raw` 字符串以及 `parseMarkdown` 函数所需字段的 token 对象。
- 使用 `lexer.blockTokens()`（或 Markdown 工具链中的类似辅助函数）将内部内容解析为嵌套 token，以便解析器复用现有的块级解析逻辑。

## 第 3 步：添加解析器

`parseMarkdown` 函数接收分词器生成的 token，并必须返回与 Tiptap 兼容的 JSON 节点（或节点数组）。使用提供的 `helpers` 将嵌套 token 解析为子内容。

下面是包含基础 Node、分词器以及新增 `parseMarkdown` 函数的完整示例，展示了各部分如何协同工作。

```javascript
import { Node } from '@tiptap/core'

export const Admonition = Node.create({
  name: 'admonition',

  group: 'block',
  content: 'block+',

  addAttributes() {
    return {
      type: {
        default: 'note',
        parseHTML: (element) => element.getAttribute('data-type'),
        renderHTML: (attributes) => ({
          'data-type': attributes.type,
        }),
      },
    }
  },

  parseHTML() {
    return [{ tag: 'div[data-admonition]' }]
  },

  renderHTML({ node, HTMLAttributes }) {
    return ['div', { 'data-admonition': '', ...HTMLAttributes }, 0]
  },

  markdownTokenizer: {
    name: 'admonition',
    level: 'block', // block-level element

    // A fast start check: returns -1 if not found.
    // and is used by the lexer to optimize scanning.
    start: (src) => src.indexOf(':::'),

    // the actual tokenize function that builds
    // the token
    tokenize: (src, tokens, lexer) => {
      // This regex matches:
      // :::type\n
      // (anything, including newlines)\n
      // :::
      const match = /^:::(\w+)\n([\s\S]*?)\n:::\n?/.exec(src)
      if (!match) return undefined

      return {
        type: 'admonition',
        raw: match[0], // the full matched Markdown
        admonitionType: match[1], // e.g. 'warning'
        text: match[2], // inner Markdown text

        // Let the Markdown lexer parse the inner content into block tokens.
        tokens: lexer.blockTokens(match[2]),
      }
    },
  },

  // Parse Markdown token to Tiptap JSON
  parseMarkdown: (token, helpers) => {
    return {
      type: 'admonition',
      attrs: { type: token.admonitionType || 'note' },
      // Parse nested tokens into Tiptap content using the helpers
      content: helpers.parseChildren(token.tokens || []),
    }
  },
})
```

**说明：**
- `helpers.parseChildren` 会将内部 token 转换为 Tiptap 所需的节点 `content` 数组。
- 确保这里的 `type` 与 Node 的 `name` 一致。

## 第 4 步：添加渲染器

要将内容序列化回 Markdown，请实现 `renderMarkdown` 函数。此函数接收一个 Tiptap 节点，并应返回对应的 Markdown 字符串。使用 `helpers.renderChildren` 序列化节点内容。

下面是包含分词器、解析器和渲染器的完整示例。至此，你将获得一个支持 Markdown 输入输出以及 HTML 渲染的完整扩展。

```javascript
import { Node } from '@tiptap/core'

export const Admonition = Node.create({
  name: 'admonition',
  group: 'block',
  content: 'block+',

  addAttributes() {
    return {
      type: {
        default: 'note',
        parseHTML: (element) => element.getAttribute('data-type'),
        renderHTML: (attributes) => ({
          'data-type': attributes.type,
        }),
      },
    }
  },

  parseHTML() {
    return [{ tag: 'div[data-admonition]' }]
  },

  renderHTML({ node, HTMLAttributes }) {
    return ['div', { 'data-admonition': '', ...HTMLAttributes }, 0]
  },

  markdownTokenizer: {
    name: 'admonition',
    level: 'block', // block-level element

    // A fast start check: returns -1 if not found.
    // and is used by the lexer to optimize scanning.
    start: (src) => src.indexOf(':::'),

    // the actual tokenize function that builds
    // the token
    tokenize: (src, tokens, lexer) => {
      // This regex matches:
      // :::type\n
      // (anything, including newlines)\n
      // :::
      const match = /^:::(\w+)\n([\s\S]*?)\n:::\n?/.exec(src)
      if (!match) return undefined

      return {
        type: 'admonition',
        raw: match[0], // the full matched Markdown
        admonitionType: match[1], // e.g. 'warning'
        text: match[2], // inner Markdown text

        // Let the Markdown lexer parse the inner content into block tokens.
        tokens: lexer.blockTokens(match[2]),
      }
    },
  },

  // Parse Markdown token to Tiptap JSON
  parseMarkdown: (token, helpers) => {
    return {
      type: 'admonition',
      attrs: { type: token.admonitionType || 'note' },
      // Parse nested tokens into Tiptap content using the helpers
      content: helpers.parseChildren(token.tokens || []),
    }
  },

  renderMarkdown: (node, helpers) => {
    const type = node.attrs?.type || 'note'
    const content = helpers.renderChildren(node.content || [])
    // Reconstruct the :::type ... ::: block. Ensure spacing/newlines match what your Markdown parser expects.
    return `:::${type}\n${content}:::\n\n`
  },
})
```

## 用法

要将使用提示块语法的 Markdown 设置为编辑器内容，请传入 Markdown 字符串，并确保设置 `contentType: 'markdown'`（具体取决于你的编辑器集成方式）：

```javascript
const markdown = `
:::warning
This is a warning message with **bold** text.
:::
`

editor.commands.setContent(markdown, { contentType: 'markdown' })
```

这将创建一个 `type: 'warning'` 的 `admonition` 节点，并将其中的嵌套内容解析为 Markdown。

---

## 测试与边缘情况

- **嵌套块：**分词器会对内部内容调用 `lexer.blockTokens()`，因此内部 Markdown（列表、段落、标题）会被解析为常规块级 token，并转换为 Tiptap 内容。
- **行内格式：**如果 `helpers.renderChildren` 和 `helpers.parseChildren` 使用相同的 token 集合，提示块内容中的粗体、斜体和链接应由 Markdown 解析器处理。
- **尾随换行符：**注意分词器正则表达式会消耗哪些尾随换行符。请调整正则表达式或 `renderMarkdown` 输出，以符合 Markdown 工具链的预期。
- **类型校验：**如果只允许特定类型（例如 `note | warning | tip | danger`），可以在 `markdownTokenizer.tokenize` 或 `parseMarkdown` 中校验 `admonitionType`，并在需要时回退到默认值。
