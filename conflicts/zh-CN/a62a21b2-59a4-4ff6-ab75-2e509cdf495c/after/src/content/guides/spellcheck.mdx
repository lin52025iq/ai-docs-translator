使用浏览器拼写检查为拼错的单词添加下划线，并在浏览器的上下文菜单中提供更正建议。设置两个编辑器属性即可，无需额外扩展。

如果你需要自己的建议菜单、自定义词典，或希望在不同浏览器中获得一致的结果，可以[集成自定义拼写检查器](#integrate-a-custom-spell-checker)。

以下示例假设你已[安装 Tiptap](/editor/getting-started/install/vanilla-javascript)。

## 启用浏览器拼写检查

在现有编辑器中，将 `spellcheck` 和 `lang` 添加到 [`editorProps.attributes`](/editor/api/editor#editorprops) 中。请使用字符串 `'true'`，因为这些 DOM 属性的值是字符串。

对于新的 JavaScript 编辑器，先在 HTML 中添加容器：

```html
<div id="editor"></div>
```

然后创建编辑器：

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [StarterKit],
  content: '<p>This sentense has a spelling mistake.</p>',
  editorProps: {
    // Apply these attributes to the editable element.
    attributes: {
      // Ask the browser to check spelling.
      spellcheck: 'true',
      // Declare the text's language. Browser dictionary settings still apply.
      lang: 'en-US',
    },
  },
})
```

在 React 或 Vue 中，将相同的 `editorProps` 选项传给 `useEditor`。这些属性会设置在 `EditorContent` 内部的可编辑元素上。

在编辑器中单击，输入 `sentense`，然后按空格键。如果启用了拼写检查，浏览器可能会为该单词添加下划线。打开该单词的上下文菜单即可查看建议。

HTML [`spellcheck` 属性](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/spellcheck)会请求浏览器检查拼写。用户仍然可以关闭拼写检查。将 [`lang`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/lang) 设置为文本所用的语言，例如德语使用 `de-DE`。浏览器还需要有匹配的词典。

### 在运行时更改拼写检查设置

使用 [`setOptions()`](/editor/api/editor#setoptions) 开启或关闭浏览器拼写检查。复制现有的 props 和 attributes，以保留事件处理程序和设置。

在上面的编辑器设置代码后添加此函数：

```js
function setSpellcheck(enabled) {
  const editorProps = editor.options.editorProps

  editor.setOptions({
    editorProps: {
      // Keep existing event handlers and other editor props.
      ...editorProps,
      attributes: {
        // Keep attributes such as class, role, and lang.
        ...editorProps.attributes,
        // DOM attribute values are strings.
        spellcheck: enabled ? 'true' : 'false',
      },
    },
  })
}

setSpellcheck(false)
```

如果你使用的是 `attributes` 函数，请修改该函数，而不要像对象一样展开它。

### 在纯 ProseMirror 中启用拼写检查

在 ProseMirror 中，将属性直接传给 [`EditorView`](https://prosemirror.net/docs/ref/#view.EditorProps.attributes)：

```js
import { EditorView } from 'prosemirror-view'

// state is your existing EditorState, including its schema and plugins.
const view = new EditorView(document.querySelector('#editor'), {
  state,
  // ProseMirror applies these attributes to its editable element.
  attributes: {
    // Request native spelling checks for English text.
    spellcheck: 'true',
    lang: 'en-US',
  },
})
```

### 排查拼写建议未显示的问题

如果没有看到拼写错误下划线，请检查以下设置：

1. 检查可编辑的 `.tiptap` 或 `.ProseMirror` 元素，确认它具有 `contenteditable="true"` 和 `spellcheck="true"`。
2. 在浏览器或操作系统中启用拼写检查，并安装或选择与文本语言对应的词典。
3. 在编辑器中单击，输入一个拼错的单词，然后按空格键。有些浏览器在你编辑之前不会检查已有文本。
4. 检查自定义节点视图和嵌套元素，查看是否有 `spellcheck="false"` 或 `contenteditable="false"`。这些设置可能会让文本不参与拼写检查。
5. 如果出现下划线但没有建议，请检查应用是否替换了浏览器的上下文菜单，或阻止了 `contextmenu` 事件。

请在应用支持的浏览器和设备上进行测试。下划线和建议菜单由浏览器控制。如需在应用中读取错误或设置下划线样式，请使用自定义检查器。

## 集成自定义拼写检查器

下面的示例使用 nspell 检查英文文本。它会在扩展中存储错误，并使用 [`addDecorations()`](/editor/api/decorations#adddecorations) 为这些错误添加下划线。装饰只改变文本的显示方式，不会更改保存的文档。

如需查看更多示例，请阅读[装饰指南](/editor/core-concepts/decorations)。请参阅[装饰 API 参考](/editor/api/decorations)查询方法和更新设置。

### 选择检查引擎

- [`nspell`](https://github.com/wooorm/nspell) 根据词典检查单词。`correct(word)` 用于检查拼写，`suggest(word)` 返回可能的更正建议。以下示例展示了如何将它用于本地拼写检查。
- [LanguageTool](https://dev.languagetool.org/http-server) 通过 HTTP 服务检查拼写和语法。如需在用户输入时进行检查，请使用自己的服务器，或使用允许自动请求的 API 方案。其[免费公共端点](https://dev.languagetool.org/public-http-api.html)禁止自动请求。

请按所示顺序，将以下 JavaScript 代码片段放在同一个浏览器模块中。这是与浏览器拼写检查示例相互独立的编辑器设置，并使用相同的 `<div id="editor"></div>` 容器。

### 1. 存储错误并添加下划线

创建一个 `Spellcheck` 扩展。它的 storage 会保存错误和 `checkedDoc`，即检查器读取的文档版本。如果文档发生变化，扩展会隐藏旧的下划线。

```js
import { Decoration, Extension } from '@tiptap/core'

const Spellcheck = Extension.create({
  name: 'spellcheck',

  addStorage() {
    // Keep checker results outside the saved document.
    return { checkedDoc: null, errors: [] }
  },

  addDecorations() {
    return {
      // Rebuild after edits so results for the old document disappear.
      update: 'document',
      create: ({ state }) => {
        // Show results only for the document snapshot the checker used.
        if (this.storage.checkedDoc !== state.doc) return []

        // Underline each error's document range without changing its text.
        return this.storage.errors.map(({ from, to }) =>
          Decoration.Inline(from, to, { class: 'spellcheck-error' }),
        )
      },
    }
  },
})
```

### 2. 创建编辑器

将 `Spellcheck` 和 `StarterKit` 一同注册。关闭浏览器拼写检查，以便只显示自定义检查器添加的下划线：

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [StarterKit, Spellcheck],
  content: '<p>This sentense has a spelling mistake.</p>',
  editorProps: {
    attributes: { spellcheck: 'false', lang: 'en-US' },
  },
})
```

添加一个用于保存检查结果并刷新下划线的函数。每个错误都需要 `from` 和 `to`，分别表示单词在文档中的起始位置和结束位置：

```js
function showSpellcheckResults(checkedDoc, errors) {
  // Ignore results if the editor closed or the document changed during the check.
  if (editor.isDestroyed || editor.state.doc !== checkedDoc) return

  // Store the checked snapshot and the errors that belong to it.
  editor.storage.spellcheck.checkedDoc = checkedDoc
  editor.storage.spellcheck.errors = errors
  // Storage changes need an explicit decoration refresh.
  editor.commands.updateDecorations('spellcheck')
}
```

在应用的样式表中添加此规则：

```css
.spellcheck-error {
  /* Draw a red, wavy underline beneath each error. */
  text-decoration-line: underline;
  text-decoration-style: wavy;
  text-decoration-color: #c62828;
}
```

仅更改 storage 不会重新绘制下划线。[`updateDecorations()`](/editor/api/decorations#updatedecorations) 会通知 Tiptap 根据已存储的错误重新构建装饰。

### 3. 加载英文词典

安装 nspell 和 [Hunspell 英文词典](https://github.com/wooorm/dictionaries/tree/main/dictionaries/en)：

```sh
npm install nspell dictionary-en
```

`dictionary-en` 使用 Node.js 读取文件。若要在浏览器中使用该词典，请将文件复制到应用的公共静态资源目录中。在应用根目录下运行以下命令：

```sh
mkdir -p public/dictionaries
cp node_modules/dictionary-en/index.aff public/dictionaries/en.aff
cp node_modules/dictionary-en/index.dic public/dictionaries/en.dic
```

此处假设应用将 `public/dictionaries/en.aff` 提供在 `/dictionaries/en.aff` 路径下。请根据所用框架或基础 URL 调整路径。

在应用启动时加载一次这些文件。将此代码放在与编辑器相同的浏览器模块中：

```js
import nspell from 'nspell'

async function createEnglishSpellchecker() {
  // Fetch the affix rules and word list from your app's static assets.
  const [aff, dic] = await Promise.all(
    ['/dictionaries/en.aff', '/dictionaries/en.dic'].map(async (url) => {
      const response = await fetch(url)
      if (!response.ok) throw new Error(`Failed to load dictionary: ${url}`)
      return response.text()
    }),
  )

  // nspell accepts dictionary data as strings.
  return nspell({ aff, dic })
}

const spell = await createEnglishSpellchecker()
```

### 4. 查找错误并保存

分别检查每个段落或标题。跨格式标记拼接文本，使 `sen<strong>ten</strong>se` 仍被视为一个单词。跳过代码和非文本的行内节点，例如图片。

文档位置会计算文本和节点边界，与 `editor.getText()` 返回的偏移量不同。下面的函数会用等长空格替换跳过的内容，以保持位置对齐：

```js
function findSpellingErrors(doc, spell) {
  const errors = []

  doc.descendants((block, blockPos) => {
    // Skip code blocks, including their descendants.
    if (block.type.spec.code) return false
    if (!block.isTextblock) return

    let text = ''

    block.forEach((child) => {
      const isCode = child.marks.some((mark) => mark.type.spec.code)

      // Text node sizes equal their JavaScript string lengths.
      // Spaces keep offsets aligned for code, hard breaks, and inline nodes.
      text += child.isText && !isCode ? child.text : ' '.repeat(child.nodeSize)
    })

    // nspell checks words. This tokenizer includes letters and contractions.
    for (const match of text.matchAll(/[\p{L}\p{M}]+(?:['’][\p{L}\p{M}]+)*/gu)) {
      const checkedWord = match[0]
      // Normalize curly apostrophes only for the dictionary lookup.
      const word = checkedWord.replaceAll('’', "'")
      if (spell.correct(word)) continue

      // Add one for the text block's opening token.
      const from = blockPos + 1 + match.index
      errors.push({
        from,
        to: from + checkedWord.length,
        checkedWord,
        suggestions: spell.suggest(word),
      })
    }

    // We already checked this block. Don't visit its children again.
    return false
  })

  return errors
}

function checkEnglishDocument() {
  if (editor.isDestroyed) return

  // Check one snapshot, then save results and refresh its decorations.
  const checkedDoc = editor.state.doc
  const errors = findSpellingErrors(checkedDoc, spell)
  showSpellcheckResults(checkedDoc, errors)
}

checkEnglishDocument()
```

对于示例文档，`editor.storage.spellcheck.errors` 中会包含 `sentense` 的错误，位置为 `from: 6`、`to: 14`。该单词应显示红色波浪下划线。使用错误的 `suggestions` 数组构建更正菜单。

如需在用户输入时重新检查，请在停止输入 300 毫秒后执行检查。在首次检查后添加以下代码：

```js
let spellcheckTimer

editor.on('update', () => {
  // Restart the timer on each document change.
  clearTimeout(spellcheckTimer)
  spellcheckTimer = setTimeout(checkEnglishDocument, 300)
})

editor.on('destroy', () => {
  // Cancel a scheduled check when the editor closes.
  clearTimeout(spellcheckTimer)
})
```

此示例会在主线程中检查整个文档。对于较大的文档，请使用 Web Worker，或只检查已更改的区块。单词匹配模式可以处理字母和缩写中的撇号。请根据应用对数字和 URL 的处理规则进行调整。

### 5. 应用更正

用户选择建议时，将已存储的错误和替换文本传给此函数：

```js
function applySpellingSuggestion(error, replacement) {
  if (editor.isDestroyed) return
  const { state, view } = editor
  const { from, to, checkedWord } = error

  // Ignore suggestions from an older version of the document.
  if (editor.storage.spellcheck.checkedDoc !== state.doc) return

  // Confirm that the range still contains the checked word.
  if (state.doc.textBetween(from, to, '') === checkedWord) {
    // A transaction lets history and collaboration track the replacement.
    view.dispatch(state.tr.insertText(replacement, from, to))
  }
}
```

使用 [`insertText()`](https://prosemirror.net/docs/ref/#state.Transaction.insertText) 进行替换，以便配置的历史记录和协作插件能够追踪更改。不要替换 `innerHTML`，也不要编辑 DOM 文本节点。

确保建议菜单支持键盘操作。添加接受更正、忽略单词或将单词加入应用词典的控件。如果一个单词跨越了粗体或斜体文本，请决定替换内容应保留哪种格式。

### 使用其他检查器

若要使用 LanguageTool 或其他服务，请将 `findSpellingErrors()` 替换为对该检查器的调用。保留相同的错误字段，并将结果传给 `showSpellcheckResults()`。

对于异步检查，请在发送请求前捕获 `editor.state.doc`。将该文档版本与检查结果一同传回。如果请求期间文档发生变化（包括协作者所做的更改），`showSpellcheckResults()` 会丢弃这些结果。每次文档更改后都应安排一次新的检查。

如果服务返回的是纯文本中的偏移量，请在保存错误前将其转换为文档位置。如果发送的文本中添加了分隔符或移除了内容，请保留位置映射。

如需查看更多装饰示例，请参阅 [Vanilla JavaScript](/guides/decorations-vanilla)、[React](/guides/decorations-react) 和 [Vue](/guides/decorations-vue) 教程。

### 处理文档隐私

如果使用远程检查服务，请仅发送你打算检查的文本，并将服务凭据保存在自己的服务器上。对于必须留在设备上的内容，请使用本地检查引擎。

根据用户的浏览器设置，浏览器拼写检查也可能将文本发送到远程服务。在对敏感内容启用拼写检查前，请参阅 MDN 的[拼写检查隐私说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/spellcheck#security_and_privacy_concerns)。
