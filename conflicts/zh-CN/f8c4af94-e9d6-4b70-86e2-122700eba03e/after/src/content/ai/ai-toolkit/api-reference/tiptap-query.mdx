Tiptap Query 使用 JSON 操作读取、搜索和编辑 Tiptap 文档。AI 代理通过 `tiptapQuery` 工具使用它。每个操作都会选取内容（例如所有标题或某个词的每处出现位置），并对其执行操作。该工具可以独立工作：AI 代理无需使用 `tiptapRead` 或 `tiptapEdit`，即可查找并编辑内容。

```json
{
  "operations": [
    {
      "selector": [{ "type": "heading" }, { "text": "Old title" }],
      "action": { "type": "replace", "content": "New title" },
      "expect": 1
    }
  ]
}
```

## 启用工具

在[获取工具定义](/ai/ai-toolkit/api-reference/rest-api#fetch-tool-definitions)时启用 `tiptapQuery`：

```json
{
  "editorContext": {
    /* editor context data */
  },
  "tools": {
    "tiptapQuery": true
  }
}
```

若要让 AI 说明所做的更改，请传入 `meta` 指令，而不是 `true`，例如 `{ "meta": "Briefly explain the change." }`。之后，每个会更改文档的操作都必须包含 `meta`。读取操作无需包含此字段。

使用 [`execute-tool`](/ai/ai-toolkit/api-reference/rest-api#execute-a-tool) 端点运行 AI 生成的工具调用：

```json
{
  "editorContext": {
    /* editor context data */
  },
  "document": { "type": "cloud", "id": "your-document-id" },
  "tool": {
    "name": "tiptapQuery",
    "input": {
      "operations": [
        { "selector": [{ "type": "heading" }], "action": { "type": "read", "view": "summary" } }
      ]
    }
  }
}
```

`tiptapQuery` 支持 `json`、`shorthand` 和 `shorthandV2` 格式，也适用于[审阅选项](/ai/ai-toolkit/api-reference/review-options)。`stream-tool` 端点不提供此工具。

工具配置（`tool.config`）：

- `chunkSize`（`number`，可选，默认值：`32000`）：单次调用中所有读取操作返回的字符总数上限。该值会限制在 `512` 到 `32000` 之间。
- `threadData`（`object`，可选）：添加到新建讨论串的元数据。
- `commentData`（`object`，可选）：添加到新建评论的元数据。

## 输入

工具输入（`tool.input`）：

- `operations`（`array`，必填）：1 到 50 个按顺序运行的操作。每个操作包含：
  - `selector`（`array`，必填）：最多 12 个步骤，用于选择要读取或编辑的内容。空数组表示选择整个文档。请参阅[选择器](#selectors)。
  - `action`（`object`，必填）：对选中内容执行的操作。请参阅[操作](#actions)。
  - `expect`（`number`，可选）：选择器必须匹配的确切数量。如果匹配数量不同，操作将以 `unexpected_matches` 失败。使用 `expect: 1` 可确保只编辑单个目标。
  - `meta`（`string`，可选）：更改原因，最多 4,000 个字符。在跟踪更改模式下，如果评论可用，该字段会成为建议上的评论。请参阅[跟踪更改和评论](#tracked-changes-and-comments)。如果 `fetch-tools` 为 `tiptapQuery` 收到 `meta` 指令，则更改操作必须提供此字段。

不接受未知字段。

## 选择器

选择器是由多个步骤组成的数组。选择器从文档开始，每个步骤都会在上一步选中的内容中进行搜索。空选择器（`[]`）表示选择整个文档。

| 选择器                                                     | 选取的内容                                                |
| ---------------------------------------------------------- | --------------------------------------------------------- |
| `[{ "type": "heading" }]`                                   | 所有标题，包括嵌套标题                                    |
| `[{ "hash": "HASH" }]`                                      | `_hash` 为该值的节点                                      |
| `[{ "type": "paragraph", "contains": "beta" }]`             | 所有包含文本 `beta` 的段落                                |
| `[{ "text": "beta", "wholeWord": true }]`                   | 单词 `beta` 的每处出现位置                                |
| `[{ "type": "bulletList" }, { "text": "late" }]`            | 项目符号列表中 `late` 的每处出现位置                      |
| `[{ "hash": "HASH" }, { "content": true }]`                 | 具有此 `_hash` 的节点内部内容，不包括节点本身             |
| `[{ "range": { "from": "START_HASH", "to": "END_HASH" } }]` | 两个同级节点及其间的所有节点                              |

### 节点步骤

节点步骤会在上一步选中的内容中选择节点。该步骤中的所有筛选条件都必须匹配。

- `type`（`string`，可选）：节点类型，例如 `"heading"`。如果编辑器架构未定义该类型，则会以 `invalid_selector` 失败。
- `hash`（`string`，可选）：节点 `_hash` 属性的值。读取结果会返回找到的节点的哈希值。
- `id`（`string`，可选）：节点 `id` 属性的值，例如 [Unique ID](/editor/extensions/functionality/uniqueid) 扩展添加的 ID。多个节点可能匹配同一个 ID。
- `attrs`（`object`，可选）：节点必须具有的属性值，例如 `{ "level": 2 }`。
- `contains`（`string`，可选）：节点必须包含的文本。按字面内容匹配，并区分大小写。
- `scope`（`'descendants' | 'children'`，可选，默认值：`'descendants'`）：搜索所有后代节点，或仅搜索直接子节点。
- `pick`（`'all' | 'first' | 'last'`，可选，默认值：`'all'`）：保留所有匹配项，或仅保留文档顺序中的第一项或最后一项。如果匹配项彼此嵌套，则不带 `type` 的步骤无法选择第一项或最后一项。

串联两个节点步骤时，会在第一个步骤找到的节点内部搜索。它不会选择这些节点之间的节点；要实现此目的，请使用范围步骤。

### 文本步骤

文本步骤会在上一步选中的内容中选择文本的所有非重叠出现位置。

- `text`（`string`，必填）：要查找的文本，最多 10,000 个字符。按字面内容匹配。不支持正则表达式。
- `caseSensitive`（`boolean`，可选，默认值：`true`）：设为 `false` 可忽略大小写。
- `wholeWord`（`boolean`，可选，默认值：`false`）：设为 `true` 可仅匹配完整单词。
- `pick`（`'all' | 'first' | 'last'`，可选，默认值：`'all'`）：保留所有匹配项，或仅保留文档顺序中的第一项或最后一项。

匹配项可以跨越格式不同的文本，但不会跨越块、硬换行或行内节点。文本步骤之后只能接另一个文本步骤。

### 内容步骤

`{ "content": true }` 会选择每个已选节点的内部内容，但不包括节点本身。使用此步骤可读取或替换节点的子内容，同时保留节点及其属性。

### 范围步骤

`{ "range": { "from": "START_HASH", "to": "END_HASH" } }` 会选择两个同级节点及其间的所有节点。两个哈希值必须分别对应上一步所选内容中的唯一节点，并且 `from` 必须位于 `to` 之前。省略 `to` 可一直选到父节点的末尾；如果范围嵌套在另一个范围中，则以外层范围的末尾为准。

编辑范围之前，请先读取端点的哈希值，并在一个操作中编辑整个范围。

## 操作

### `read`

返回选中的内容，不更改文档。

- `view`（`'content' | 'text' | 'summary'`，可选，默认值：`'content'`）：每个匹配项的返回形式：
  - `'content'`：请求 `format` 指定格式的内容：Tiptap JSON 节点或 Tiptap Shorthand 字符串。
  - `'text'`：纯文本。
  - `'summary'`：每个节点的哈希值、类型、属性和纯文本。
- `maxChars`（`number`，可选，默认值：`32000`）：返回页面的最大字符数，范围为 512 到 32000 个字符。
- `cursor`（`string`，可选）：继续之前的读取。不要创建或修改此值；请发送读取结果返回的整个 `next` 操作。请参阅[读取长内容](#read-long-content)。

### `replace`

替换选中的内容。

- `content`（`JSONContent[] | string`，必填）：新内容。
  - 对于文本匹配项，无论采用何种格式，`content` 始终是纯字符串。使用 `""` 删除文本。新文本会保留匹配项起始位置的格式；如果父节点允许硬换行，`
` 会转换为硬换行。
  - 对于节点、内容步骤、范围和整个文档，如果 `format` 为 `json`，`content` 必须是 Tiptap JSON 节点数组；如果 `format` 为 `shorthand` 或 `shorthandV2`，则必须是 [Tiptap Shorthand](/ai/ai-toolkit/advanced-guides/tiptap-shorthand) 字符串。若架构允许，空内容（`[]`，或 Tiptap Shorthand 中的 `""`）会删除选中的节点。

### `insertBefore` 和 `insertAfter`

在每个选中的节点或内容范围之前或之后，以同级节点的形式插入节点。

- `content`（`JSONContent[] | string`，必填）：要插入的节点，格式与 `replace` 的节点内容相同。

不能用于文本匹配项。要在段落中添加文本，请改为将文本匹配项替换为更长的文本。要在文档开头或结尾添加节点，请选择 `[{ "content": true }]`。不能使用整个文档（`[]`）进行插入。

### `setAttrs`

将属性合并到每个选中的节点中。

- `attrs`（`object`，必填）：要设置的属性。编辑器架构必须定义这些属性。不能设置保留属性，例如 `_hash` 和跟踪更改属性。

### `addMark` 和 `removeMark`

为选中的文本或选中节点中的所有文本添加或移除标记。

- `mark`（`string`，必填）：编辑器架构中的标记类型，例如 `"bold"`。不能使用跟踪更改标记和评论标记。
- `attrs`（`object`，可选）：`addMark` 的标记属性，例如为链接设置 `{ "href": "https://tiptap.dev" }`。

`removeMark` 会移除该类型的所有标记，无论其属性为何。

### 新内容中的哈希值

工具会为每个新节点添加 `_hash`。你发送的内容中的哈希值会被忽略。使用 `replace` 将一个节点替换为一个相同类型的节点时，新节点会保留旧哈希值。新内容中的跟踪更改标记和属性会被拒绝，并返回 `invalid_content`。

## 输出

工具输出（`tool.output`）：

- `success`（`boolean`）：所有操作是否均成功。
- `operationResults`（`array`）：每个已运行操作各有一项结果，顺序与操作顺序一致。详见下文。
- `skipped`（`number`）：因先前操作失败而未运行的操作数。

`operationResults` 中的每项结果都符合以下某一种结构。

读取结果：

- `index`（`number`）：操作在 `operations` 中的位置。
- `success`（`true`）
- `complete`（`boolean`）：读取是否返回了所选内容的全部内容。若为 `false`，请使用 `next` 再次调用工具。
- `totalMatches`（`number`）：选择器的匹配项数。选择器为空时，每个顶层节点都计为一项匹配。
- `items`（`array`）：返回的匹配项。每项包含：
  - `hash`（`string`，可选）：节点的哈希值。对于文本匹配项，这是包含该匹配项的节点的哈希值；对于内容步骤，这是所选内容所属节点的哈希值。范围项没有哈希值。
  - `type`（`string`）：节点类型；文本匹配项的类型为 `"text"`；内容步骤或范围的类型为 `"content"`。
  - `attrs`（`object`，可选）：在 `summary` 视图中显示的节点属性。`_hash` 和跟踪更改属性不会显示。文本匹配项、内容步骤和范围没有 `attrs`。
  - `text`（`string`）：在 `text` 和 `summary` 视图中的纯文本。硬换行会转换为 `\n`，其他行内节点会转换为 U+FFFC 字符。
  - `content`（`JSONContent[] | string`）：在 `content` 视图中的内容。
  - `excerpt`（`true`，可选）：此项是未能完整放入页面的节点的文本摘录。此时包含 `text`，而非 `content`。
- `next`（`object | null`）：用于继续读取的操作；读取完成时为 `null`。

编辑结果：

- `index`（`number`）：操作在 `operations` 中的位置。
- `success`（`true`）
- `matched`（`number`）：该操作编辑的匹配项数。
- `changed`（`boolean`）：该操作是否更改了文档。如果编辑没有效果，则为 `false`，例如将已加粗的文本再次设为粗体。

失败结果：

- `index`（`number`）：操作在 `operations` 中的位置。
- `success`（`false`）
- `code`（`string`）：错误代码。请参阅[错误代码](#error-codes)。
- `error`（`string`）：面向 AI 的错误消息，最多 2,000 个字符。消息通常会说明如何修正操作。

如果输入本身无效，输出为 `{ "success": false, "code": "invalid_input", "error": "..." }`，且不会运行任何操作。

失败的操作和无效输入会在 `tool.output` 中报告，但 `execute-tool` 请求仍会返回 HTTP 状态码 `200`。其他错误（例如身份验证、文档访问和服务器错误）会返回 [REST API 参考](/ai/ai-toolkit/api-reference/rest-api#execute-a-tool)中所述的 HTTP 错误。

## 操作运行方式

- 操作按顺序运行。每个操作都能看到之前操作所做的更改。
- 编辑操作会先查找所有匹配项，再一次性更改全部匹配项；如果编辑失败，则不会更改任何匹配项。
- 没有匹配项的编辑操作会以 `no_matches` 失败。没有匹配项的读取操作仍会成功，但不返回任何项目。
- 首个失败的操作会终止此次调用。先前操作的更改会保留，之后的操作会跳过。调用不会回滚。
- 如果节点没有 `_hash`，即使调用只执行读取操作，也会为其添加一个哈希值。重复的哈希值会被替换。已有哈希值不会更改。

## 读取长内容

读取操作最多返回 `maxChars` 个字符。如果内容超出此限制，`complete` 为 `false`，且 `next` 中会包含用于继续读取的操作。将 `next` 作为新调用中的操作发送，并重复此过程，直到 `next` 为 `null`：

```json
{
  "operations": [
    /* the `next` value of the previous read */
  ]
}
```

无法完整放入页面的节点会以文本摘录的形式返回，并带有 `excerpt: true`；`next` 会继续读取同一节点。因此，读取所需的页面数可能多于匹配项数；`totalMatches: 1` 并不表示该节点已被完整读取。若要查看大型节点的结构，请读取其子节点或使用更大的页面。

如果文档其他部分发生更改，且已读取的节点仍保留其哈希值，`next` 中的游标仍然有效。如果已读取的内容以其他方式发生更改，读取操作会以 `stale_cursor` 失败。请在不使用游标的情况下重新读取，或从上次读取到的最后一个哈希值开始一个范围。

一次调用中的所有读取操作共用 `chunkSize` 预算。预算用尽后，其余读取操作不会返回任何项目，`complete` 为 `false`，并返回各自的 `next` 操作。之后的操作仍会继续运行。

## 跟踪更改和评论

使用 `reviewOptions: { mode: 'trackedChanges' }` 时，每项编辑都会变成建议，供用户接受或拒绝，而不是直接更改文档。

- 读取操作会将所有待处理建议视为已接受，来返回文档内容。
- AI 编辑其他内容时，先前调用生成的建议会保留。
- `meta` 会成为该操作所生成建议上的评论。评论需要 Tiptap Cloud 文档以及支持评论的编辑器架构。内联文档会收到建议，但不会收到评论。
- 如果 `setAttrs` 设置了建议无法记录的属性，则会以 `invalid_attributes` 失败。默认情况下，这些属性包括 `id` 和 `data-thread-id`（请参阅[审阅选项](/ai/ai-toolkit/api-reference/review-options)中的 `ignoreAttributes`）。
- 如果编辑仅更改了被忽略的属性或标记，则会返回 `changed: false`，且不会更改文档。

## 错误代码

| 代码                  | 原因                                                                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `invalid_input`       | 输入与架构不匹配，例如包含未知字段或操作数超过 50。不会运行任何操作。                                                                              |
| `invalid_selector`    | 节点类型未在架构中定义；文本步骤之后跟有节点、范围或内容步骤；内容步骤选择了叶节点；或 `pick` 存在歧义。                                           |
| `invalid_range`       | 范围端点在所选范围内不唯一，或端点不是按顺序排列的同级节点。                                                                                      |
| `no_matches`          | 编辑操作未选中任何内容。                                                                                                                          |
| `unexpected_matches`  | 匹配项数量与 `expect` 不同。                                                                                                                      |
| `too_many_matches`    | 编辑操作选中了超过 10,000 个匹配项。                                                                                                              |
| `overlapping_matches` | 编辑操作的匹配项相互重叠。                                                                                                                        |
| `selection_limit`     | 调用中的选择器检查了超过 2,000,000 个节点和文本匹配项。                                                                                           |
| `invalid_target`      | 操作无法应用于所选内容，例如在文本匹配项旁插入内容，或为文本设置属性。                                                                            |
| `invalid_content`     | 内容格式与所选内容或格式不匹配，或内容中包含跟踪更改。                                                                                            |
| `invalid_operation`   | 编辑器架构拒绝了内容，或无法解析 Tiptap Shorthand。消息会列出具体问题。                                                                            |
| `invalid_attributes`  | 属性未知或为保留属性，或建议在跟踪更改模式下无法记录该属性。                                                                                      |
| `invalid_mark`        | 该标记不是架构中的普通标记，或父节点不允许使用该标记。                                                                                            |
| `invalid_cursor`      | 游标不是由工具返回的，或游标已被修改。                                                                                                            |
| `stale_cursor`        | 读取操作已返回的内容发生了更改。                                                                                                                  |
| `output_limit`        | 单个项目及其后续内容无法同时放入 `maxChars`。                                                                                                     |
| `unsupported_content` | Tiptap Shorthand 无法表示该内容。请使用 `text` 或 `summary` 视图读取。                                                                             |

## 限制

| 限制                                       | 值                      |
| ------------------------------------------ | ----------------------- |
| 每次调用的操作数                           | 50                      |
| 每个选择器的步骤数                         | 12                      |
| `text` 和 `contains` 的长度                | 10,000 个字符            |
| `meta` 的长度                              | 4,000 个字符             |
| 每个编辑操作的匹配项数                     | 10,000                  |
| 调用中选择器检查的节点和文本匹配项数       | 2,000,000               |
| 读取页面大小（`maxChars`）                 | 512 到 32,000 个字符     |
| 单次调用中所有读取操作返回的字符数（`chunkSize`） | 512 到 32,000 个字符     |
| 游标长度                                   | 2,048 个字符             |

## 示例

以下示例使用包含这些节点的文档：

| 哈希     | 节点                                     | 文本                                                        |
| -------- | ---------------------------------------- | ----------------------------------------------------------- |
| `k8Tq2m` | 标题，级别 1                              | Launch plan                                                 |

### 读取大纲

使用 `summary` 视图读取所有标题，而不加载正文：

```json
{
  "operations": [
    { "selector": [{ "type": "heading" }], "action": { "type": "read", "view": "summary" } }
  ]
}
```

输出：

```json
{
  "success": true,
  "operationResults": [
    {
      "index": 0,
      "success": true,
      "complete": true,
      "totalMatches": 4,
      "items": [
        { "hash": "k8Tq2m", "type": "heading", "attrs": { "level": 1 }, "text": "Launch plan" },
        { "hash": "Q9wE4r", "type": "heading", "attrs": { "level": 2 }, "text": "Timeline" },
        { "hash": "m5Ht8v", "type": "heading", "attrs": { "level": 2 }, "text": "Risks" },
        { "hash": "W3gN7h", "type": "heading", "attrs": { "level": 2 }, "text": "Contacts" }
      ],
      "next": null
    }
  ],
  "skipped": 0
}
```

### 从某个标题开始向后读取

从标题哈希值开始一个范围，并省略 `to`，即可一直读取到文档末尾。添加 `{ "scope": "children" }` 可将范围中的每个节点作为单独项目返回：

```json
{
  "operations": [
    {
      "selector": [{ "range": { "from": "m5Ht8v" } }, { "scope": "children" }],
      "action": { "type": "read", "view": "summary", "maxChars": 8000 }
    }
  ]
}
```

结果包含四个项目：`Risks` 标题、项目符号列表、`Contacts` 标题及其段落。范围不会在遇到下一个标题时停止。若只读取一个章节，请将 `to` 设为该章节的最后一个节点。

### 查找并编辑段落

搜索包含指定文本的段落：

```json
{
  "operations": [
    {
      "selector": [{ "type": "paragraph", "contains": "March" }],
      "action": { "type": "read", "view": "summary" }
    }
  ]
}
```

读取操作会返回一个项目：哈希值为 `Z2nB6c` 的段落。

然后使用该段落的哈希值编辑段落中的文本：

```json
{
  "operations": [
    {
      "selector": [{ "hash": "Z2nB6c" }, { "text": "March" }],
      "action": { "type": "replace", "content": "April" },
      "expect": 1
    }
  ]
}
```

编辑操作返回 `matched: 1` 和 `changed: true`。此时段落文本为 "The beta starts in April. The public launch follows in May."。

### 更改节点类型

要更改节点类型，请选择并替换节点，而不是节点中的文本。以下示例会将联系人段落转换为项目符号列表：

```json
{
  "operations": [
    {
      "selector": [{ "type": "paragraph", "contains": "Product:" }],
      "action": {
        "type": "replace",
        "content": [
          {
            "type": "bulletList",
            "content": [
              {
                "type": "listItem",
                "content": [
                  { "type": "paragraph", "content": [{ "type": "text", "text": "Product: Ana" }] }
                ]
              },
              {
                "type": "listItem",
                "content": [
                  {
                    "type": "paragraph",
                    "content": [{ "type": "text", "text": "Engineering: Ben" }]
                  }
                ]
              }
            ]
          }
        ]
      },
      "expect": 1
    }
  ]
}
```

### 插入节点

在一个段落后插入另一个段落：

```json
{
  "operations": [
    {
      "selector": [{ "hash": "Z2nB6c" }],
      "action": {
        "type": "insertAfter",
        "content": [
          {
            "type": "paragraph",
            "content": [{ "type": "text", "text": "Feedback closes two weeks after launch." }]
          }
        ]
      }
    }
  ]
}
```

编辑操作返回 `matched: 1` 和 `changed: true`。

### 处理失败的操作

第二个操作要求找到一个包含文本 "launch" 的段落，但实际上有两个段落包含该文本：

```json
{
  "operations": [
    { "selector": [{ "text": "March" }], "action": { "type": "replace", "content": "April" } },
    {
      "selector": [{ "type": "paragraph", "contains": "launch" }],
      "action": { "type": "addMark", "mark": "italic" },
      "expect": 1
    },
    { "selector": [{ "text": "May" }], "action": { "type": "replace", "content": "June" } }
  ]
}
```

输出：

```json
{
  "success": false,
  "operationResults": [
    { "index": 0, "success": true, "matched": 1, "changed": true },
    {
      "index": 1,
      "success": false,
      "code": "unexpected_matches",
      "error": "Expected 1 matches, found 2. Narrow the selector or read first."
    }
  ],
  "skipped": 1
}
```

第一个操作的更改会保留，因此文档现在包含 "April"。第三个操作不会运行。
