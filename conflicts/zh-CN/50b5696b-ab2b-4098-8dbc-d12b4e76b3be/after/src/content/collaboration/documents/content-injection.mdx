更新文档端点还支持通过 JSON 更新来修改本地部署或云端协作服务器上的文档：

- 在服务器端向任意文档添加 `json`、`binary` 或 `base64` 内容。
- 使用 [UniqueID 扩展](/editor/extensions/functionality/uniqueid)向特定节点注入内容。
- 注入内容时，用户仍可实时协作。
- 跟踪用户所做的更改和注入的内容，并与[快照](/collaboration/documents/snapshot)完全兼容。

### 使用场景

内容注入 REST API 可用于一些实用而复杂的场景：

- 实时翻译文档内容。
- 以编程方式在服务器端标记或操作文档内容。
- 集成服务器端组件，例如执行 SQL 查询并显示结果。
- 集成版本历史记录，并无冲突地合并并发编辑。

## 创建文档

要在 Tiptap Collab 服务器上创建新文档，请使用 `POST` 方法和以下端点：

```bash
POST /api/documents/:identifier?format=:format
```

创建成功时，服务器会返回 HTTP 状态码 `204`；如果文档已存在，则返回 `409`（若要覆盖，必须先删除文档）；如果操作失败，则返回 `422`。

`format` 参数接受与更新端点相同的值（`binary`、`base64` 或 `json`）。


## 更新文档

要更新协作服务器上的现有文档，可以使用 `PATCH` 方法和以下 API 端点：

```bash
PATCH /api/documents/:identifier?format=:format
```

此端点接受 Yjs 更新消息，并将其应用到指定文档。

### 查询参数

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `format` | `string` | — | 更新格式：`json`、`binary`（Yjs 的 `Y.encodeStateAsUpdate`）或 `base64`（以 Base64 编码的二进制状态）。 |
| `mode` | `string` | `default` | 更新策略：`default` 合并节点，`append` 仅追加，`node` 使用负载替换匹配的节点，`attrs` 替换匹配节点的属性，`delete` 删除匹配的节点（无需负载）。请参阅[模式](#modes)。 |
| `nodeAttributeName` | `string` | — | 仅对具有指定名称属性的节点执行更新。需与 `nodeAttributeValue` 配合使用。 |
| `nodeAttributeValue` | `string` | — | 仅对具有指定值属性的节点执行更新。需与 `nodeAttributeName` 配合使用。可传入多个值：`?nodeAttributeValue=a&nodeAttributeValue=b`。 |
| `checksum` | `string` | — | 仅当文档当前状态与此校验和匹配时才应用更新（校验和会在获取文档的响应中作为 `x-FRAGMENTNAME-checksum` 返回）。否则返回 `409 Checksum mismatch`。 |
| `user` | `string` | — | 与此次更改关联的用户 ID。 |
| `skipVersioning` | `1` | — | 如果传入此参数，此次更改不会触发自动版本管理。 |
| `upsert` | `0` \| `1` | `0` | 设为 `1` 时，如果文档不存在，则创建文档，而不是返回 `404`。 |
| `fragment` | `string` | `default` | 要更新的 Yjs 片段。传入多个值时，可以用相同内容更新多个片段（当 `format=json` 时）：`?fragment=a&fragment=b`。 |
| `multi` | `0` \| `1` | `0` | 仅用于 `format=json`。设为 `1` 时，请求正文是一个以片段名称为键的 JSON 对象，可在单个请求中更新多个片段的不同内容。仅与默认模式兼容。请参阅[使用不同内容更新多个片段](#update-multiple-fragments-with-different-content)。 |
| `mergeAttributes` | `0` \| `1` | `0` | 仅用于 `mode=attrs`。设为 `1` 时，保留请求负载中未包含的属性。设为 `0`（默认值）时，删除缺失的属性。 |
| `multiUpdates` | `true` | — | 仅用于 `mode=attrs` 和 `format=json`。启用在单个请求中使用不同属性值更新多个节点。请求正文必须是由 `{ where, attrs }` 对象组成的 JSON 数组。请参阅[多项更新](#multi-updates)。 |

更新成功时，服务器会返回 HTTP 状态码 `204`。如果文档不存在，则返回 `404`（除非传入 `upsert=1`，此时会创建文档）；如果负载无效或无法应用更新，则返回 `422`。

**示例：**使用 `curl` 命令更新文档

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/DOCUMENT_NAME' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--data '@yjsUpdate.binary'
```

## 通过 JSON 更新

通过 JSON 更新时，服务器会计算当前文档状态与提供的 JSON 之间的差异，然后在内部计算出达到目标状态所需的 Yjs 更新。

为了确保精确更新，尤其是针对特定节点的更改，建议使用 `nodeAttributeName` 和 `nodeAttributeValue` 参数。这些参数可以由 Tiptap 的 [UniqueID 扩展](/editor/extensions/functionality/uniqueid)或自定义实现生成。
请注意，在使用 `mode=default` 时，这仅适用于顶层节点。

省略这些参数可能会覆盖获取文档和发起更新调用之间发生的任何更新。`get document` 调用会返回一个 `x-${fragmentName}-checksum` 标头，可将其作为 `?checksum=${checksum}` 传递给更新调用，以检测冲突。如果自上次获取文档后文档已更新，此次更新将失败，并返回 `409 Checksum mismatch.` 状态。
[`document.saved` 和 `content.changed` Webhook](/collaboration/core-concepts/webhooks#conflict-safe-updates-from-a-webhook) 的 `checksums` 对象中包含每个字段对应的相同校验和，因此可以在收到 Webhook 后立即更新文档，无需先获取文档。

### 模式

`mode` 参数控制如何将内容应用到文档：

#### 默认模式

将负载中的节点合并到文档中。未指定模式时，默认采用此行为。

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [{ "type": "text", "text": "Merged content" }]
    }
  ]
}'
```

#### 追加模式

将节点追加到文档的 JSON 表示中，不更改现有节点。

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&mode=append' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [{ "type": "text", "text": "This paragraph is appended at the end" }]
    }
  ]
}'
```

#### 节点模式

将与 `nodeAttributeName`/`nodeAttributeValue` 匹配的节点替换为负载中的节点。

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&mode=node&nodeAttributeName=id&nodeAttributeValue=abc-123' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "type": "paragraph",
  "attrs": { "id": "abc-123" },
  "content": [{ "type": "text", "text": "This replaces the entire matched node" }]
}'
```

#### 属性模式

使用请求负载替换所有匹配节点的属性（仅发送属性对象）。有关 `mergeAttributes` 的详情，请参阅[仅更新节点属性](#update-only-node-attrs)。

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&mode=attrs&nodeAttributeName=id&nodeAttributeValue=abc-123' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "textAlign": "center",
  "indent": 2
}'
```

#### 删除模式

删除与 `nodeAttributeName`/`nodeAttributeValue` 匹配的节点。无需提供负载。

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&mode=delete&nodeAttributeName=id&nodeAttributeValue=abc-123' \\
--header 'Authorization: Bearer YOUR_JWT'
```

### 实用参数组合

#### 跟踪更改者

将用户 ID 与注入的内容关联起来，便于审计和查看版本历史记录。

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&user=bot-user-1' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [{ "type": "text", "text": "Injected by bot" }]
    }
  ]
}'
```

#### 跳过自动版本管理

注入内容，但不创建新的版本快照。

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&skipVersioning=1' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [{ "type": "text", "text": "Silent update" }]
    }
  ]
}'
```

#### 更新特定片段

指定一个特定的 Yjs 片段，而不是默认片段；也可以一次更新多个片段。

```bash
# Update a single fragment
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&fragment=sidebar' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [{ "type": "text", "text": "Sidebar content" }]
    }
  ]
}'
```

```bash
# Update multiple fragments with the same content
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&fragment=header&fragment=footer' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [{ "type": "text", "text": "Shared content" }]
    }
  ]
}'
```

#### 使用不同内容更新多个片段

若要在单个请求中使用**不同**内容更新多个片段，请传入 `multi=1`（同时设置 `format=json`），并发送一个以片段名称为键的 JSON 对象。每个值都是该片段的完整 Tiptap JSON 内容，并使用默认模式合并到对应片段中。

与 `?fragment=a&fragment=b`（会将*相同*负载应用到列出的每个片段）不同，`multi=1` 允许为每个片段发送不同内容。

`multi=1` 仅适用于默认模式。不能将其与 `mode`、`nodeAttributeName`/`nodeAttributeValue`、`checksum` 或 `multiUpdates` 一起使用，否则会返回 `400`。它可以与 `user`、`skipVersioning` 和 `upsert` 一起使用。

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&multi=1' \\
--header 'Authorization: YOUR_SECRET' \\
--header 'Content-Type: application/json' \\
--data '{
  "default": {
    "type": "doc",
    "content": [
      { "type": "paragraph", "content": [{ "type": "text", "text": "Text in fragment default" }] }
    ]
  },
  "otherFragment": {
    "type": "doc",
    "content": [
      { "type": "paragraph", "content": [{ "type": "text", "text": "Text in fragment otherFragment" }] }
    ]
  }
}'
```

#### 使用校验和执行冲突安全更新

仅当文档自上次获取后未发生更改时，才应用更新。

```bash
# 1. Fetch the document and note the checksum header (x-default-checksum). The header is present when fetching the document with ?format=json. If you want to get the checksum for a different fragment, send &fragment=customfragmentname
# 2. Use the checksum in the update call
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&checksum=THE_CHECKSUM_VALUE' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [{ "type": "text", "text": "Only applied if document unchanged" }]
    }
  ]
}'
```

#### 合并属性而不删除现有属性

更新匹配节点的特定属性，同时保留所有其他现有属性。

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&mode=attrs&nodeAttributeName=id&nodeAttributeValue=abc-123&mergeAttributes=1' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "textAlign": "center"
}'
```

### 仅更新节点属性

如果只想更新节点的属性，可以使用 `?mode=attrs` 查询参数。此模式仅更新节点属性，不会修改节点内容。
在此模式下，`nodeAttributeName` 和 `nodeAttributeValue` 参数适用于任意节点（不只是顶层节点）。

默认情况下，所有匹配节点的属性都会被替换——负载中未包含的属性将被删除。若要保留现有属性，仅更新负载中指定的属性，请传入 `?mergeAttributes=1`。

如果不指定节点筛选条件（`nodeAttributeName`、`nodeAttributeValue`），则会更新所有节点。

```
curl --location --request PATCH '/api/documents/:identifier?format=json&nodeAttributeName=id&nodeAttributeValue=12&mode=attrs' \\
--data '{
  "indent": 12,
  "textAlign": "right"
}'
```

### 多项更新

使用 `mode=attrs` 时，可以传入 `multiUpdates=true`，在单个请求中使用不同属性值更新多个节点。无需通过 `nodeAttributeName`/`nodeAttributeValue` 查询参数指定目标节点，而是在请求正文中提供一个更新对象数组。每个对象都指定用于匹配节点的 `where` 条件以及要应用的 `attrs`。

`where` 条件中的所有条件均通过 AND 逻辑连接——节点必须匹配所有指定属性才会被更新。

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&mode=attrs&multiUpdates=true' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '[
  {
    "where": {
      "id": "id123"
    },
    "attrs": {
      "textAlign": "center"
    }
  },
  {
    "where": {
      "name": "customname"
    },
    "attrs": {
      "indent": 2
    }
  }
]'
```

`multiUpdates` 可以与 `user`、`skipVersioning`、`fragment` 和 `mergeAttributes` 等其他参数组合使用：

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc?format=json&mode=attrs&multiUpdates=true&user=bot-user-1&mergeAttributes=1' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '[
  {
    "where": {
      "id": "node-1",
      "type": "heading"
    },
    "attrs": {
      "level": 2
    }
  },
  {
    "where": {
      "id": "node-2"
    },
    "attrs": {
      "textAlign": "right"
    }
  }
]'
```

## 文档字段

这些端点允许你读取和更新文档中的自定义 Yjs 字段。使用自定义 Yjs 类型（例如 `Y.getMap('configuration')`）并希望通过 API 获取或更新值时，此功能非常有用。

### 获取文档字段

```bash
GET /api/documents/:identifier/fields?field=:field&type=:type
```

返回自定义 Yjs 字段的当前值。

#### 查询参数

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `field` | `string` | — | 自定义字段的名称。 |
| `type` | `string` | — | 自定义字段的 Yjs 类型。支持的值：`map`、`array`。传入错误的类型会导致返回结果不正确。请注意，如果文档中不存在该类型，调用此端点会在文档中创建该类型。对同一字段名称切换类型会产生意外的副作用。 |

```bash
curl --location 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc/fields?field=configuration&type=map' \\
--header 'Authorization: Bearer YOUR_JWT'
```

### 更新文档字段

```bash
PATCH /api/documents/:identifier/fields?field=:field&type=:type
PUT /api/documents/:identifier/fields?field=:field&type=:type
```

更新文档中的自定义 Yjs 字段。

- **`PATCH`** 会将请求正文合并到现有字段值中——仅更新传入的键，并保留现有键。
- **`PUT`** 会完整替换字段——请求正文中未包含的键将被移除。

#### 查询参数

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `field` | `string` | — | 自定义字段的名称。 |
| `type` | `string` | — | 自定义字段的 Yjs 类型。目前仅支持使用 `map` 更新。 |
| `user` | `string` | — | 与此次更改关联的用户 ID。 |
| `skipVersioning` | `1` | — | 如果传入此参数，此次更改不会触发自动版本管理。 |

#### 示例：使用 PATCH 合并值

```bash
curl --location --request PATCH 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc/fields?field=configuration&type=map' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "key": "newValue",
  "array": [1, 2, 3],
  "object": {
    "id": 62,
    "position": ""
  },
  "arrayOfObjects": [
    { "id": 61 }
  ]
}'
```

#### 示例：使用 PUT 替换所有值

```bash
curl --location --request PUT 'https://YOUR_APP_ID.collab.tiptap.cloud/api/documents/my-doc/fields?field=configuration&type=map' \\
--header 'Authorization: Bearer YOUR_JWT' \\
--header 'Content-Type: application/json' \\
--data '{
  "key": "newValue"
}'
```

`PUT` 正文中未包含的任何现有键都会从字段中移除。
