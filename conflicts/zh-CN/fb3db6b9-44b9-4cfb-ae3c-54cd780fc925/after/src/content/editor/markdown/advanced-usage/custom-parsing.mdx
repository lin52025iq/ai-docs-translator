本指南将带你了解如何在 Tiptap 编辑器中实现自定义 Markdown 解析。完成本教程后，你将能够从 [Token](../glossary#token) 中提取 [Tiptap JSON](../glossary#tiptap-json)。

扩展可以提供自定义解析逻辑，以处理特定的 Markdown Token。这通过 `markdown.parse` 处理器实现。

## 创建并了解解析处理器

解析处理器接收来自 MarkedJS 的 Markdown Token，并返回编辑器可以使用的 Tiptap JSON 内容。
除了 Token，解析函数还会接收一个 `helpers` 对象，其中包含用于辅助解析的实用函数。

这些函数可用于创建节点和标记，或解析 `token.tokens` 中的子级 `MarkedJS` Token。

```typescript
const MyHeading = Node.create({
  name: 'customHeading',
  // ...

  markdownTokenName: 'heading', // Token type to handle (optional, default is the extension name)
  parseMarkdown: (token, helpers) => {
    return {
      type: 'heading',
      attrs: { level: token.depth },
      content: helpers.parseInline(token.tokens || []),
    }
  },
})
```

在此示例中，解析处理器会处理 MarkedJS 传递给 Markdown 管理器的 `heading` Token。该 Token 在此示例中会被捕获，并转换为类型为 `heading` 的 Tiptap 节点。

处理器会从 Token 中提取相应的 `level` 属性，并使用 `helpers.parseInline()` 函数解析其行内内容（因为标题只能包含标记或行内文本）。

> **重要提示**：Token 的属性可能因 [Tokenizer](../glossary#tokenizer) 的配置方式而异。

## 解析辅助函数

如上一节所述，`helpers` 对象提供了用于解析子级 Token 或创建节点和标记的实用函数。
下面逐一介绍这些辅助函数及其用法。

### 使用 `helpers.parseInline(tokens)` 解析行内级子级 Token

此辅助函数接收一个 Token 列表，并**尝试**将其解析为行内内容（带有标记的文本节点）。
它不会验证这些 Token 是否确实为行内 Token，因此请确保只向此函数传入行内 Token。

该函数返回 `TiptapJSON[]`，可用作 Tiptap 节点的 `content`。

```typescript
parse: (token, helpers) => {
  const content = helpers.parseInline(token.tokens || [])

  return {
    type: 'paragraph',
    content,
  }
}
```

### 使用 `helpers.parseChildren(tokens)` 解析块级子级 Token

与 `parseInline()` 类似，但此函数会将 Token 解析为块级内容（例如列表项、引用块、代码块等）。
它不会验证这些 Token 是否确实为块级 Token，因此请确保只向此函数传入块级 Token。

该函数返回 `TiptapJSON[]`，可用作 Tiptap 节点的 `content`。

```typescript
parse: (token, helpers) => {
  // Parse nested block content (e.g., list items)
  const content = helpers.parseChildren(token.tokens || [])

  return {
    type: 'blockquote',
    content,
  }
}
```

### 使用 `helpers.parseInline()` 和 `helpers.applyMark()` 解析标记

使用 `helpers.applyMark()` 将标记应用于内容：

```typescript
const Bold = Mark.create({
  name: 'bold',

  markdownTokenName: 'strong',
  parseMarkdown: (token, helpers) => {
    const content = helpers.parseInline(token.tokens || []) // parse the inline content inside the mark
    return helpers.applyMark('bold', content) // apply the 'bold' mark to the parsed content
  },
})
```

## Markdown 中的 HTML 解析

Markdown 中包含 HTML 时，会使用扩展现有的 `parseHTML` 方法进行解析。

```markdown
# Regular Markdown

<custom-component data-foo="bar">
  <p>This HTML is parsed by your extensions</p>
</custom-component>

More **Markdown** here.
```

## 定义 Markdown Token 名称

将 Token 解析为节点或标记时，Token 名称可能与节点或标记名称并非一一对应。在这种情况下，你可以使用 `markdownTokenName` 指定要解析的 Token 名称，并将其映射到节点或标记的类型名称。

```typescript
const CustomBold = Mark.create({
  name: 'bold',
  // ...

  markdownTokenName: 'strong', // Match 'strong' tokens when parsing
  parseMarkdown: (token, helpers) => { /* ... */ },
  renderMarkdown: (node, helpers) => { /* ... */ },
})
```

以下情况适合使用此功能：

- Markdown Token 名称与节点名称不同
- 多个 Markdown Token 映射到同一节点类型
- 同一节点类型可以序列化为多种 Markdown 格式

## 回退解析

如果没有扩展处理某种特定类型的 Token，MarkdownManager 会为常见 Token 提供回退解析：

- `paragraph` → `{ type: 'paragraph' }`
- `heading` → `{ type: 'heading', attrs: { level } }`
- `text` → `{ type: 'text', text }`
- `html` → 使用扩展的 `parseHTML` 方法解析

你可以为这些 Token 类型提供自己的处理器来覆盖此行为。

## 调试解析

记录 Token，以了解 MarkedJS 生成的内容：

```typescript
const markdown = '# Hello **World**'
const tokens = editor.markdown.instance.lexer(markdown)
console.log(JSON.stringify(tokens, null, 2))
```

### 单独解析 Token

```typescript
const token = {
  type: 'heading',
  depth: 1,
  tokens: [{ type: 'text', text: 'Hello' }],
}

const helpers = {
  parseInline: tokens => [{ type: 'text', text: 'Hello' }],
  // ... other helpers
}

const result = myExtension.options.markdown.parse(token, helpers)
console.log(result)
```

## 性能注意事项

### 延迟解析

对于大型文档，可以考虑按需解析：

```typescript
let cachedJSON = null

function getJSON() {
  if (!cachedJSON) {
    cachedJSON = editor.markdown.parse(largeMarkdownString)
  }
  return cachedJSON
}
```

### 增量更新

与其在每次更改时重新解析整个文档，不如只更新特定部分：

```typescript
editor.commands.insertContentAt(position, newMarkdown, { contentType: 'markdown' })
```

## 示例

### 自定义标题解析器

下面为 `customHeading` 扩展构建一个自定义标题解析器，用于提取标题级别，并为每个标题生成唯一 ID。

```typescript
import { Node } from '@tiptap/core'

const CustomHeading = Node.create({
  name: 'customHeading',

  // ... other config

  parseMarkdown: (token, helpers) => {
    const level = token.depth || 1 // we can get the heading level from the token

    // Add custom attributes
    return {
      type: 'customHeading',
      attrs: {
        level,
        id: `heading-${Math.random()}`, // Generate ID
      },
      content: helpers.parseInline(token.tokens || []), // parse the inline content of the heading token
    }
  },
})
```

### 自定义 YouTube 嵌入解析器

下面为 `youtube` Token 创建一个自定义解析器，将其转换为带有相应嵌入属性的 `youtubeEmbed` 节点。

```typescript
import { Node } from '@tiptap/core'

const YoutubeEmbed = Node.create({
  name: 'youtubeEmbed',
  atom: true, // this is a self-contained node

  // ... other config

  parseMarkdown: (token) => {
    // Those attributes are extracted from the youtube token
    // we assume that a custom tokenizer is providing these tokens
    // from the Markdown syntax like: ![youtube](videoId?start=60&width=800&height=450)
    const videoId = token.videoId || ''
    const start = token.start || 0
    const width = token.width || 560
    const height = token.height || 315


    // Because this is an atom node, we don't require the helpers
    // to parse any children, as this node is self-contained.
    return {
      type: 'youtubeEmbed',
      attrs: {
        videoId,
        start,
        width,
        height,
      },
    }
  },
})
```
